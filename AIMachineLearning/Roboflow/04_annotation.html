06 · UI WORKFLOW

화면 조작 순서

  1. Annotate 클릭 업로드된 Image에 정답을 만드는 작업 영역으로 이동
  2. Label Myself 선택 사용자가 직접 Annotation하는 경로 선택
  3. Rectangle Tool 선택 사각형 Bounding Box Drawing Mode 활성화
  4. 탐지 객체 Drag 객체 위치와 범위를 사각 영역으로 지정
  5. 영문 Label 입력 교안 기준으로 객체 Category 이름 작성
  6. Create class 새 Class를 Dataset에 등록하고 Box에 연결
  7. 교안의 다음 UI 조작 상단 Paging 옆 원형 아이콘 클릭
  8. 다른 Image에서도 반복 같은 Annotation 기준을 전체 Image에 적용
  9. Unannotated = 0 확인 Annotation 작업이 남은 Image가 없는지 확인
  10. Versions 이동 완료된 Dataset을 Version으로 생성하는 다음 단계
교안에서 설명하지 않은 부분

교안은 Paging 옆 원형 아이콘을 클릭하도록 안내하지만, 해당 아이콘의 정확한 공식 기능명은 설명하지 않습니다. 따라서 기능을 임의로 확정하지 않습니다.

10 · BOUNDING BOX QUALITY

좋은 Bounding Box 기준

SUPPLEMENT · 교안 절차를 보완한 품질 기준

GOOD

객체 범위와 일치

탐지 대상 Object를 일관된 기준으로 포함합니다.

TOO LARGE

배경을 지나치게 포함

객체와 무관한 배경 특징까지 정답 범위에 포함될 수 있습니다.

TOO SMALL

객체 일부만 포함

객체의 전체 범위를 일관되게 학습하기 어려워집니다.

좋은 Box의 핵심 원칙

객체의 학습 대상 범위를 포함
불필요한 배경을 최소화
모든 Image에서 같은 기준 적용
잘린 객체와 가려진 객체의 정책 통일
가장 중요한 것은 Dataset 전체의 일관성입니다.

같은 객체를 어떤 Image에서는 얼굴 전체로, 다른 Image에서는 마스크 영역만으로 지정하면 Model이 무엇을 탐지해야 하는지 혼란스러워질 수 있습니다.

15 · COMMON MISTAKES

초보자가 자주 하는 실수

01

Class 이름 불일치

같은 객체를 with-mask, with_mask, With Mask처럼 여러 이름으로 만들지 않습니다.

02

Bounding Box가 지나치게 큼

객체보다 많은 배경을 포함하면 불필요한 특징이 정답 범위에 들어갈 수 있습니다.

03

Bounding Box가 지나치게 작음

객체 일부만 포함하면 Image마다 Object 정의가 달라질 수 있습니다.

04

객체 일부만 Annotation

학습 대상 객체가 여러 개인데 일부만 Box로 표시하지 않습니다.

05

Annotation 누락

Version으로 이동하기 전에 Unannotated 상태를 확인합니다.

06

잘못된 Class 선택

실제 with-mask 객체에 without-mask Label을 지정하지 않습니다.

07

Box만 만들고 Class를 지정하지 않음

Bounding Box와 Class가 모두 있어야 완전한 Object Detection Annotation이 됩니다.

08

Unannotated = 0을 품질 완료로 착각

작업 누락 여부와 Annotation 정확성은 별도로 확인합니다.

09

Train / Valid / Test 역할 혼동

이후 Dataset Split의 목적을 구분해야 합니다.

10

잘못된 Export Format

이후 사용할 Model Framework와 맞는 Format으로 Export합니다.

11

data.yaml 경로 오류

Export 후 train, val, test 경로와 실제 Folder 구조를 확인합니다.

18 · INTERVIEW / REVIEW

면접 포인트

Q01. Annotation이란 무엇입니까?

Image에 Model이 학습할 정답 정보를 입력하는 과정입니다. Object Detection에서는 Bounding Box와 Class를 작성합니다.

Q02. 이번 교안에서 Annotation을 시작하는 경로는 무엇입니까?

Annotate → Label Myself입니다.

Q03. Bounding Box란 무엇입니까?

Image 안에서 탐지 대상 객체의 위치와 범위를 나타내는 사각형입니다.

Q04. Class란 무엇입니까?

Dataset에서 정의한 객체 Category입니다.

Q05. Label과 Class의 차이는 무엇입니까?

Class는 가능한 Category 정의이고, Label은 특정 Bounding Box에 실제로 부여한 Class 값입니다.

Q06. Object Detection Annotation의 구성은 무엇입니까?

Bounding Box와 Class로 구성됩니다.

Q07. 교안에서는 Box를 어떻게 만듭니까?

오른쪽 Rectangle Tool을 선택하고 탐지할 객체를 마우스로 Drag합니다.

Q08. Label은 어떤 언어로 작성합니까?

교안에서는 영문으로 작성하도록 안내합니다.

Q09. 새 Class는 어떻게 만듭니까?

Label을 입력한 뒤 Create class를 클릭합니다.

Q10. Unannotated = 0은 무엇을 의미합니까?

Annotation 작업이 남은 Image가 없다는 의미입니다.

Q11. Unannotated = 0이면 품질도 완벽합니까?

아닙니다. Box 범위, Class 정확성, 객체 누락은 별도로 검수해야 합니다.

Q12. 좋은 Bounding Box의 기준은 무엇입니까?

객체의 학습 대상 범위를 일관되게 포함하고, 불필요한 배경을 최소화해야 합니다.

Q13. Image 안의 객체 일부를 누락하면 왜 문제입니까?

학습 대상 객체인데 Ground Truth로 표시되지 않아 Dataset 정답이 불완전해질 수 있습니다.

Q14. 같은 Class 이름을 일관되게 사용해야 하는 이유는 무엇입니까?

같은 의미의 객체가 여러 Class로 분리되는 것을 막고, 최종 data.yaml과 Label ID를 일관되게 유지하기 위해서입니다.

Q15. Annotation 완료 후 다음 단계는 무엇입니까?

Versions로 이동해 Dataset Version을 생성합니다.

Q16. 최종 YOLO Dataset에서 Annotation은 어디에 저장됩니까?

labels Folder의 YOLO Annotation .txt 파일로 연결됩니다.

Q17. Annotation과 Dataset Version은 같은 단계입니까?

아닙니다. Annotation은 정답 작성 단계이고, Version은 완료된 Dataset 상태를 학습용 Snapshot으로 만드는 후속 단계입니다.
