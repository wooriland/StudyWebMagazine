02 · WHY EVALUATE?

같은 Accuracy라도 오류의 방향과 실제 비용은 다를 수 있습니다

REASON 01

Prediction은 결과일 뿐

Class를 출력했다는 사실만으로 Model이 새로운 Data에서도 잘 작동하는지 알 수 없습니다.

REASON 02

FP와 FN의 비용이 다름

정상인을 환자로 판단하는 오류와 환자를 정상으로 놓치는 오류의 위험은 다를 수 있습니다.

REASON 03

Class 불균형

다수 Class만 Prediction해도 Accuracy가 높게 보일 수 있습니다.

REASON 04

운영 목적이 다름

의료, 보안, 스팸, 사기 탐지는 서로 다른 Metric과 Threshold를 요구합니다.

FALSE POSITIVE 없는 위험을 있다고 경고

정상 메일을 스팸으로 차단하거나 정상 거래를 사기로 판단하는 상황입니다.

FALSE NEGATIVE 실제 위험을 없다고 놓침

실제 암 환자, 화재, 침입 또는 사기 거래를 정상이라고 판단하는 상황입니다.

06 · ACCURACY & ERROR RATE

Accuracy는 전체 중 맞힌 비율, Error Rate는 전체 중 틀린 비율입니다

ACCURACY Accuracy = (TP + TN) / (TP + TN + FP + FN) (5 + 70) / 100 = 0.75

교안 예제 Accuracy는 75%입니다.

ERROR RATE Error Rate = (FP + FN) / Total (20 + 5) / 100 = 0.25

교안 예제 오분류율은 25%입니다.

Accuracy 75%
Error 25%
Accuracy가 답하는 질문

전체 Sample 중 Model이 정확하게 판단한 비율은 얼마인가?

07 · CLASS IMBALANCE

Accuracy가 높아도 중요한 Positive를 전혀 찾지 못할 수 있습니다

ACTUAL POSITIVE 1명

암 환자 1%

ACTUAL NEGATIVE 99명

정상인 99%

모두 Negative로 Prediction → 정상인 99명 정답 + 암 환자 1명 오답 → Accuracy 99%
높은 Accuracy가 숨긴 사실

실제 암 환자를 한 명도 찾아내지 못했으므로 Positive Class Recall은 0%입니다. 따라서 Class가 불균형한 문제에서는 Accuracy만으로 Model을 판단하지 않습니다.

08 · PRECISION

Positive라고 한 결과를 얼마나 믿을 수 있는지 평가합니다

PRECISION · 정밀도 · PPV
Model이 Positive라고 Prediction한 Sample 중 실제로 Positive인 비율
Precision = TP / (TP + FP) 5 / (5 + 20) = 0.20

교안 예제 Precision은 20%입니다.

분모 Predicted Positive TP + FP = 25명
그중
분자 True Positive TP = 5명
Precision 20%를 문장으로 읽기

Model이 암이라고 경고한 25명 중 실제 암 환자는 5명이었습니다. 나머지 20명은 실제 정상인인 False Positive입니다.

09 · RECALL

실제 Positive를 얼마나 놓치지 않고 찾아냈는지 평가합니다

RECALL · 재현율 · SENSITIVITY · TPR
실제로 Positive인 Sample 중 Model이 Positive로 정확하게 찾아낸 비율
Recall = TP / (TP + FN) 5 / (5 + 5) = 0.50

교안 예제 Recall은 50%입니다.

분모 Actual Positive TP + FN = 10명
그중
분자 True Positive TP = 5명
Recall 50%를 문장으로 읽기

실제 암 환자 10명 중 5명만 암으로 찾아냈고, 나머지 5명은 정상이라고 잘못 판단한 False Negative입니다.

10 · SPECIFICITY & FPR

실제 Negative를 지킨 비율과 잘못 경고한 비율을 함께 봅니다

SPECIFICITY · TNR

실제 Negative를 정확히 판단

Specificity = TN / (TN + FP) 70 / 90 ≈ 0.7778

교안 예제에서는 약 77.78%입니다.

FPR

실제 Negative를 Positive로 오판

FPR = FP / (FP + TN) 20 / 90 ≈ 0.2222

교안 예제에서는 약 22.22%입니다.

FPR = 1 - Specificity

실제 Negative를 잘 지킬수록 잘못된 Positive 경고 비율은 낮아집니다.

HARMONIC MEAN F1 = 2 × (Precision × Recall) / (Precision + Recall)

F1 Score의 한계 · 보완 이해

F1은 Precision과 Recall을 결합하지만 TN을 직접 사용하지 않습니다. Negative Class 성능이 중요하다면 Specificity와 Confusion Matrix도 함께 확인해야 합니다.

13 · THRESHOLD TRADE-OFF

같은 Probability도 Threshold에 따라 다른 Class가 됩니다

교안 확인 메모

교안의 Precision–Recall Trade-off 설명 중 한 문장은 정밀도가 높을 때와 낮을 때 모두 Recall이 낮아진다고 표현되어 있어 문맥상 재확인이 필요합니다. 아래 내용은 해당 원문을 조용히 교체한 것이 아니라, Threshold 변화의 일반적 경향을 설명하는 보완 이해입니다.

THRESHOLD ↓

TP 증가 가능 FP 증가 가능 FN 감소 가능
Recall 상승 가능
Precision 하락 가능
THRESHOLD ↑

Positive 기준 엄격

FP 감소 가능 TP 감소 가능 FN 증가 가능
Precision 상승 가능
Recall 하락 가능

더 많은 Positive를 찾을 것인지, 더 확실한 Sample만 Positive로 인정할 것인지에 따라 적절한 Threshold가 달라질 수 있습니다.

14 · ROC CURVE

여러 Threshold에서 FPR과 TPR의 관계를 확인합니다

X AXIS FPR FP / (FP + TN)

실제 Negative를 Positive로 잘못 판단한 비율

Y AXIS TPR TP / (TP + FN)

실제 Positive를 찾아낸 비율, 즉 Recall

Threshold 매우 높음 → Positive 거의 없음 → TPR·FPR 낮음 → Threshold를 낮춤 → TPR·FPR 변화 → ROC Curve
ROC에는 Probability 또는 Score가 필요합니다

여러 Threshold를 적용하려면 이미 0과 1로 잘라낸 y_pred보다 Positive Probability 또는 Decision Score인 y_score가 필요합니다.

18 · CODE EXAMPLE

교안 예제의 TP·FP·FN·TN을 Python으로 직접 계산합니다

보완 예제

아래 코드는 교안에 저장된 특정 Notebook 코드를 복사한 것이 아니라, 교안의 Confusion Matrix 수치를 실행 가능한 Python 구조로 옮긴 예제입니다. 

from __future__ import annotations


def safe_divide(
    numerator: float,
    denominator: float,
) -> float | None:
    """분모가 0이면 None을 반환합니다."""
    if denominator == 0:
        return None

    return numerator / denominator


# 교안의 암 진단 예제
tp = 5
fp = 20
fn = 5
tn = 70

total = tp + fp + fn + tn

accuracy = safe_divide(
    tp + tn,
    total,
)

error_rate = safe_divide(
    fp + fn,
    total,
)

precision = safe_divide(
    tp,
    tp + fp,
)

recall = safe_divide(
    tp,
    tp + fn,
)

specificity = safe_divide(
    tn,
    tn + fp,
)

fpr = safe_divide(
    fp,
    fp + tn,
)

if (
    precision is not None
    and recall is not None
    and precision + recall != 0
):
    f1 = (
        2
        * precision
        * recall
        / (precision + recall)
    )
else:
    f1 = None


print("Accuracy:", accuracy)
print("Error Rate:", error_rate)
print("Precision:", precision)
print("Recall:", recall)
print("Specificity:", specificity)
print("FPR:", fpr)
print("F1 Score:", f1)

Error Rate 0.25
Precision 0.20
Recall 0.50
Specificity 0.7778
FPR 0.2222
F1 0.2857
코드에서 가장 중요한 것은 분모입니다

Precision은 TP + FP, Recall은 TP + FN, Specificity는 TN + FP를 분모로 사용합니다.

    probabilities: Iterable[float],

    if not 0.0 <= threshold <= 1.0:
        raise ValueError(
            "threshold는 0.0 이상 1.0 이하여야 합니다."
        )

    return [
        1 if probability >= threshold else 0
        for probability in probabilities
    ]


probabilities = [
    0.92,
    0.62,
    0.58,
    0.45,
    0.41,
]

print(
    predict_labels(
        probabilities,
        threshold=0.5,
    )
)

# 출력:
# [1, 1, 1, 0, 0]

19 · COMMON MISTAKES

분류 Metric을 읽을 때 반드시 피해야 할 착각

01

Positive는 좋은 상태라는 뜻이다

Positive는 평가 대상으로 정한 Class입니다. 암·사기·스팸도 Positive가 될 수 있습니다.

02

True는 실제 Label이 Positive라는 뜻이다

True는 Model의 Prediction이 실제 정답과 일치했다는 뜻입니다.

03

FP와 FN의 방향을 반대로 기억한다

FP는 없는 Positive를 있다고 경고하고, FN은 실제 Positive를 Negative로 놓칩니다.

04

Confusion Matrix 위치만 외운다

도구마다 Actual·Predicted 축이 다를 수 있으므로 행과 열 Label을 먼저 확인합니다.

05

Accuracy가 높으면 무조건 좋은 Model이다

Class 불균형에서는 다수 Class만 Prediction해도 높은 Accuracy가 나올 수 있습니다.

06

Precision과 Recall의 분모가 같다

Precision은 Predicted Positive, Recall은 Actual Positive를 분모로 사용합니다.

07

Recall이 높으면 Precision도 반드시 높다

모든 Sample을 Positive로 판단하면 Recall은 높아져도 FP가 늘어 Precision은 낮아질 수 있습니다.

08

F1은 산술 평균이다

F1 Score는 Precision과 Recall의 조화 평균입니다.

09

F1이 높으면 TN도 잘 맞힌 것이다

F1은 TN을 직접 사용하지 않으므로 Specificity도 함께 확인해야 할 수 있습니다.

10

ROC의 x축이 Recall이다

ROC의 x축은 FPR, y축은 TPR, 즉 Recall입니다.

11

ROC에는 Class Label만 있으면 된다

여러 Threshold를 적용하려면 Probability 또는 Decision Score가 필요합니다.

12

AUC와 Accuracy는 같은 값이다

Accuracy는 특정 Threshold의 정답률, AUC는 여러 Threshold의 구분 능력입니다.

13

AUC가 높으면 현재 Threshold도 적절하다

Model의 구분 능력과 실제 운영 Threshold 선택은 별도 문제입니다.

14

Threshold는 언제나 0.5여야 한다

0.5는 기본값으로 자주 사용하지만 실제 목적과 FP·FN 비용에 따라 달라질 수 있습니다.

15

Training Metric만 보면 된다

일반화 성능은 학습에 직접 사용하지 않은 Validation/Test Data에서 확인합니다.

16

Multi-Class F1의 평균 방식을 확인하지 않는다

Macro·Micro·Weighted는 서로 다른 관점을 나타냅니다.

22 · INTERVIEW POINT

“Confusion Matrix → Metric → 업무 비용” 순서로 설명하면 평가 기준이 흔들리지 않습니다

Q1. Confusion Matrix란 무엇인가요?

Actual Label과 Prediction Label을 비교하여 TP, FP, FN, TN 네 가지 경우로 나눈 표입니다. Accuracy, Precision, Recall 등의 계산 기반입니다.

Q2. TP란 무엇인가요?

실제 Positive를 Model도 Positive로 정확하게 Prediction한 경우입니다.

Q3. FP란 무엇인가요?

실제 Negative인데 Model이 Positive로 잘못 Prediction한 경우입니다.

Q4. FN이란 무엇인가요?

실제 Positive인데 Model이 Negative로 잘못 Prediction하여 Positive를 놓친 경우입니다.

Q5. Accuracy란 무엇인가요?

전체 Sample 중 올바르게 Prediction한 비율이며 (TP+TN)/전체로 계산합니다.

Q6. Accuracy의 한계는 무엇인가요?

Class가 불균형하면 다수 Class만 Prediction해도 높은 Accuracy가 나올 수 있고, FP와 FN의 성격을 구분하지 못합니다.

Q7. Precision이란 무엇인가요?

Positive라고 Prediction한 것 중 실제로 Positive인 비율이며 TP/(TP+FP)입니다.

Q8. Recall이란 무엇인가요?

실제 Positive 중 Model이 찾아낸 비율이며 TP/(TP+FN)입니다.

Q9. Precision과 Recall의 차이는 무엇인가요?

Precision은 Predicted Positive를 기준으로 Positive Prediction의 신뢰도를 보고, Recall은 Actual Positive를 기준으로 발견률을 봅니다.

Q10. F1 Score란 무엇인가요?

Precision과 Recall의 조화 평균이며, 두 값 중 하나가 지나치게 낮으면 F1도 함께 낮아집니다.

Q11. Specificity란 무엇인가요?

실제 Negative 중 Model이 Negative로 정확하게 판단한 비율이며 TN/(TN+FP)입니다.

Q12. FPR이란 무엇인가요?

실제 Negative 중 Positive로 잘못 판단한 비율이며 FP/(FP+TN)입니다.

Q13. ROC Curve란 무엇인가요?

여러 Threshold에서 FPR을 x축, TPR을 y축으로 표시해 Model의 분류 성능을 시각화한 Curve입니다.

Q14. TPR은 무엇인가요?

True Positive Rate이며 Recall, Sensitivity와 같은 수식입니다.

Q15. AUC란 무엇인가요?

ROC Curve 아래의 면적으로, 여러 Threshold에서 Positive와 Negative를 구분하는 능력을 하나의 값으로 요약합니다.

Q16. Accuracy와 AUC는 무엇이 다른가요?

Accuracy는 특정 Threshold의 Class 정답률이고, AUC는 여러 Threshold에서의 전반적인 구분 능력입니다.

Q17. Threshold는 왜 조정하나요?

문제마다 FP와 FN의 비용이 다르기 때문에 Precision과 Recall의 균형을 업무 목적에 맞추기 위해 조정합니다.

Q18. Multi-Class F1은 어떻게 해석하나요?

Class별 F1을 계산한 뒤 Macro, Micro, Weighted 등의 평균 방식을 사용하므로 어떤 Average인지 함께 확인해야 합니다.

  8. ROC y축 = TPR
