04 · Train·Validation·Test

선택에 쓰는 데이터와 최종 평가 데이터를 분리합니다

교안 A의 검증 개념 / 전처리와 실제 분리 규칙 보완 [A] [D]

Train

Gradient와 Parameter Update에 사용합니다.

Validation

상태·구조·설정·선택 Epoch를 검토합니다.

Test

선택을 마친 모델을 별도 데이터에서 평가합니다.

평균·표준편차 등을 데이터에서 추정하는 전처리는 Train에서 기준을 구하고 Validation과 Test에는 같은 기준을 적용합니다. 전체 데이터로 전처리를 먼저 학습하면 평가 정보가 학습에 들어갈 수 있습니다.

validation_split과 shuffle은 다른 일입니다

NumPy 배열의 validation_split은 셔플 전에 뒤쪽 일부를 검증용으로 분리합니다. shuffle=True라고 검증 Sample이 매 Epoch 새로 선택되는 것은 아닙니다. 정렬 순서·Class 구성·같은 원본에서 나온 유사 Sample의 분리를 확인합니다.

검증 단계는 일반적으로 검증 Label로 학습용 Gradient Update를 하지 않습니다. 하지만 검증 결과로 설정을 반복 선택하므로 Validation 최선도 모든 새 데이터의 최고 성능을 보장하지 않습니다.

Regularization은 학습 목적에 제약을 더하는 규제화입니다. 입력 표준화는 전처리이고, BN·LN은 Layer 값의 통계적 변환입니다. Loss에 L2를 추가하는 일과 입력 평균을 빼기, BatchNormalization Layer 추가는 다릅니다.

06 · 가중치 초기화

학습 시작의 스케일을 입력·출력 크기와 연결합니다

교안 A 47~48쪽의 Xavier·He 설명 / Dense 기본값 보완 [A] [E]

교안의 기본 분산 척도
방법 대표 연결 분산 척도
Xavier·Glorot Sigmoid·tanh 계열 2 / (n_in + n_out)
He ReLU 계열 2 / n_in

Xavier 균등분포: U(−sqrt(6/(n_in+n_out)), +sqrt(6/(n_in+n_out)))

He 균등분포: U(−sqrt(6/n_in), +sqrt(6/n_in))

n_in은 입력 노드 수, n_out은 출력 노드 수입니다. 교안은 평균 0의 정규분포 방식과 위 균등분포 방식을 소개합니다. 숫자 암기보다 입력·출력 크기에 맞는 초기값 스케일을 이해합니다.

이는 초기 신호 전달을 돕는 방향이지 과적합이나 모든 기울기 문제의 해결 보장이 아닙니다. 교안의 “50층 이상” 예도 모든 모델의 절대 경계로 사용하지 않습니다.

현재 API와 교안의 일반 설명을 나눕니다

공식 Dense의 기본 kernel_initializer는 glorot_uniform입니다. glorot_normal·he_normal은 별도 설정입니다. 교안의 분포 설명과 Library의 구체적인 초기화 이름을 구분합니다. 초기화와 BN은 대체가 아니라 역할이 다른 보완 방법으로 읽습니다.

07 · Regularization 수식

Data Loss와 패널티를 함께 최소화합니다

교안 A 48~49쪽 / 적용 대상은 공식 API 보완 [A] [F]

L_total = L_data + λ R(W)

L1: R(W)=Σ_j |w_j|

L2: R(W)=Σ_j w_j²

L_data는 예측과 실제값의 차이, R(W)는 패널티, λ는 규제 강도인 Hyperparameter입니다. 규제는 학습 후 Weight를 임의로 잘라내는 것이 아니라 학습이 최소화하는 목적을 바꿉니다.

보완 미분 · L2: ∂L_total/∂w_j = ∂L_data/∂w_j + 2λw_j

Keras 규제의 적용 대상
설정 적용 대상
kernel_regularizer Weight
bias_regularizer Bias
activity_regularizer Layer 출력

kernel_regularizer만 지정했다고 Bias까지 같은 규제를 받는 것은 아닙니다. 위 식은 λΣw² 형태를 미분한 것이며 Optimizer는 합쳐진 Gradient를 사용합니다.

L1의 “노드 제거 효과”를 구분합니다

교안은 Weight가 0이 되면 입력 노드를 제거하는 효과로 설명합니다. 연결 하나의 기여가 0인 것과 그 노드의 전체 경로가 제거되는 것은 다릅니다. L1이 특정 상황에서 희소성을 유도한다는 설명을 모든 값의 정확한 0 보장으로 읽지 않습니다. Layer Shape이나 summary의 선언된 Parameter 수도 자동으로 줄어들지 않습니다.

08 · 패널티 손계산과 Loss 비교

숫자가 커진 이유가 오차인지 패널티인지 확인합니다

Step 1·2의 보완 손계산 · 실제 학습 결과가 아닙니다

W=[1,−2,0.5], λ=0.1

L1 penalty=0.1×(1+2+0.5)=0.35

L2 penalty=0.1×(1+4+0.25)=0.525

Data Loss를 0.2로 가정한 계산
구성 전체 Loss
규제 없음 0.2
L1 추가 0.55
L2 추가 0.725

고정 Weight에 대한 계산입니다. 패널티를 더했으므로 전체 Loss가 커진 것이며, 이 사실만으로 예측이 나빠졌다고 결론 내리지 않습니다.

규제가 다른 모델의 val_loss를 그대로 비교하지 않습니다

Keras의 규제 패널티는 모델 Loss에 포함됩니다. 이름이 같은 val_loss라도 포함 항이 다를 수 있습니다. 규제항 포함 여부와 공통 Accuracy 또는 데이터 손실 등 문제에 맞는 지표를 함께 봅니다. Accuracy 하나만으로 모든 문제의 목적이 결정되는 것도 아닙니다. [F] [C]

09 · BN의 통계와 수식

같은 Feature의 여러 Sample을 모아서 계산합니다

교안 A 49~51쪽 / 분모 표기와 공식 기본 동작을 분리 [A] [G]

Dense 출력 Z가 (B,F)이면 같은 열의 Sample 값을 모읍니다. 교안은 Batch별 중간값 분포 변화에 대응해 학습을 안정화하는 방법으로 설명합니다.

Feature 1의 통계

Sample들의 z11·z21·z31을 모아 계산

Feature 2의 통계

Sample들의 z12·z22·z32를 모아 계산

교안 수식은 σ에 ε를 더합니다

50쪽은 표준편차 σ_j를 구한 뒤 (z_ij−μ_j)/(σ_j+ε)로 적고 있습니다. 아래 공식 API 형태의 sqrt(v_j+ε)와 완전히 같은 계산은 아닙니다. 원문 표기를 숨겨서 바꾸지 않고 두 식을 나눕니다.

공식 API 보완 · μ_j=(1/B)Σ_i z_ij

v_j=(1/B)Σ_i(z_ij−μ_j)²

z_hat_ij=(z_ij−μ_j)/sqrt(v_j+ε)

a_ij=γ_j z_hat_ij+β_j

γ는 스케일, β는 이동을 조정합니다. 교안은 Sigmoid의 입력 범위와 연결해 설명하지만, 보완해서는 모델에 필요한 스케일과 위치를 학습할 자유도로 읽습니다. Sigmoid에서만 쓰이는 장치는 아닙니다.

평균·분산 변환은 분포 전체의 동일화나 Gaussian 분포 생성과 다릅니다. 서로 다른 값 두 종류만 있는 데이터도 이 변환 후 여전히 두 종류입니다. γ·β를 적용한 최종 출력의 평균과 스케일도 정규화 직후 값과 다를 수 있습니다.

값 처리 방식
현재 Batch 평균·분산 이번 입력에서 계산

학습: 현재 Batch 통계 사용 + 이동 통계 갱신

추론: 저장된 이동 통계 사용

moving_mean ← ρ×moving_mean + (1−ρ)×batch_mean

여기서 momentum은 이동평균 계수입니다. 앞 Optimizer 단원의 Momentum과 같은 계산이 아닙니다. Layer 동결이나 실행 모드를 바꾼 경우에는 기본 동작 조건을 다시 확인합니다.

설명용 Batch Z=[2,4,6]

μ=4, v=8/3, ε=1e−5

정규화: [−1.224743, 0, 1.224743]

γ=2, β=1 적용: [−1.449485, 1, 3.449485]

아래 NumPy 코드로 대조한 보완 계산입니다. ε는 손계산용 값이지 API 기본값이라고 제시한 값이 아닙니다. 현재 Batch 계산만 검증하며 BN의 이동 통계 학습 전체를 재현하지 않습니다.

12 · Dropout의 계산

일부 활성값을 임시로 제외하고 남은 값의 스케일을 조정합니다

교안 A 52쪽의 의존 완화 설명 / 확률·스케일 보완 [A] [I]

교안은 일부 연결을 사용하지 않아 특정 노드나 조합에 과도하게 의존하는 것을 완화한다고 설명합니다. 학습 중 무작위로 다른 부분을 사용하는 효과를 설명하지만, 여기서 별도 여러 모델을 학습해 합치는 절차를 추가하는 것은 아닙니다.

0≤p<1, m_j ~ Bernoulli(1−p)

학습: h_tilde_j = m_j h_j / (1−p)

E[h_tilde_j | h_j] = h_j

마지막 줄은 기대값의 관계입니다. 매번 전체 합이 정확히 같거나, Dropout(0.5)가 작은 입력마다 정확히 절반을 지우도록 강제하는 것은 아닙니다.

활성값 제외와 Weight 영구 삭제는 다릅니다

기본 Dropout 자체에는 학습 Weight가 없고 앞 Dense의 선언된 Parameter 수도 유지됩니다. 원문의 “학습되는 가중치 수를 줄인다”는 설명과 구조 삭제를 구분합니다. Dropout을 끄는 기준은 training 모드이며 trainable=False 자체가 마스크를 끄는 방법은 아닙니다.

설명용 H=[2,4,6,8], p=0.5, 고정 M=[1,0,1,0]

이번 학습 계산: [4,0,12,0]

일반적인 추론: [2,4,6,8]

마스크는 손계산을 위해 고정한 값입니다. 실제 무작위 실행에서 동일한 마스크가 나온다는 뜻이 아닙니다.

14 · Callback의 역할

Layer 계산 바깥에서 학습 이벤트에 반응합니다

교안 A 53쪽의 Callback 설명 [A]

Callback은 학습 중 특정 이벤트에서 상태를 관찰하거나 동작을 수행하는 기능입니다. 교안은 tf.keras.callbacks와 fit의 callbacks 리스트로 연결합니다.

  1. Epoch 종료 학습·검증 지표 기록
  2. Callback 실행 logs의 실제 지표 확인
  3. 저장 판단 ModelCheckpoint
  4. 종료 판단 EarlyStopping

이 흐름의 저장·종료는 같은 역할이 아닙니다. TensorBoard는 로그를 관찰하도록 돕습니다. 코드의 Callback 순서와 각 monitor를 확인하고, 모두 자동으로 같은 선택을 한다고 가정하지 않습니다.

15 · EarlyStopping 설정

개선이 없는 상태가 지속되면 학습을 종료합니다

교안의 조기 종료 + 공식 API의 실제 판단 구분 [A] [J]

2026-09-13 확인 · 이번 설명은 기본 모니터링 조건
설정 역할
monitor 관찰할 기록 이름
mode 작은 값이 좋으면 min, 큰 값이면 max

val_loss는 보통 min, val_accuracy는 max로 읽습니다. 이번 예제는 min_delta=0입니다. 현재까지의 최선 0.10 뒤에 0.15, 0.13이 나와도, 직전보다 낮아졌다는 이유만으로 최선 기록을 갱신하지 않습니다.

종료와 원인 진단은 다릅니다

교안은 과적합 제어로 연결하지만 실제 Callback은 지정 지표의 개선을 봅니다. 학습률 문제·과소적합·검증 변동 등으로도 개선이 멈출 수 있습니다. EarlyStopping 작동 자체가 과적합의 원인 증명은 아닙니다.

예정 Epoch는 최대 학습 범위입니다. 데이터와 조건에 따라 그 전에 끝날 수 있으며, patience 값 자체도 모든 실험의 정답은 아닙니다.

16 · ModelCheckpoint와 복원

저장·종료·복원·평가를 별개의 작업으로 연결합니다

교안 A의 저장·로드 설명 / 현재 파일 형식 보완 [A] [K]

선택 예: monitor="val_loss", mode="min", save_best_only=True

현재 ModelCheckpoint의 save_best_only 기본값은 False입니다. Callback을 만들었다는 사실만으로 최선 모델만 저장되는 것은 아닙니다. 지표·방향·저장 주기를 명시합니다.

서로 다른 역할
작업 담당·의미
언제 끝낼까? EarlyStopping
무엇을 남길까? ModelCheckpoint

restore_best_weights=True는 메모리의 가중치 복원입니다. 파일 저장이나 해당 시점의 모든 학습·Callback 상태 재현과 같다고 생각하지 않습니다.

가중치 중심 저장의 예는 best.weights.h5입니다. 저장된 모델·Optimizer 상태의 범위는 버전과 컴파일 등 조건에 따라 확인합니다. 이름에 weights가 있다고 모든 버전에서 저장 내용이 완전히 같다고 단정하지 않습니다.

22 · 독립 NumPy 검증

세 손계산을 고정 입력으로 대조합니다

Step 1·2의 보완 코드 · NumPy만 필요 · TensorFlow 학습과 별개 

import numpy as np

np.set_printoptions(precision=6, suppress=True)

# 고정 Weight의 패널티입니다. 학습 실험이 아닙니다.
W = np.array([1.0, -2.0, 0.5])
lam = 0.1
l1 = lam * np.abs(W).sum()
l2 = lam * np.square(W).sum()

# BN의 현재 Batch만 계산합니다. epsilon은 예제용입니다.
Z = np.array([2.0, 4.0, 6.0])
epsilon = 1e-5
normalized = (Z - Z.mean()) / np.sqrt(Z.var(ddof=0) + epsilon)
bn_output = 2.0 * normalized + 1.0

# 손계산을 위한 고정 마스크입니다.
H = np.array([2.0, 4.0, 6.0, 8.0])
mask = np.array([1.0, 0.0, 1.0, 0.0])
rate = 0.5
dropout_train = H * mask / (1.0 - rate)

print(f"L1 penalty: {l1:.3f}")
print(f"L2 penalty: {l2:.3f}")
print("BN normalized:", normalized)
print("BN scaled:", bn_output)
print("Dropout training:", dropout_train)
print("Dropout inference:", H)

assert np.isclose(l1, 0.35)
assert np.isclose(l2, 0.525)
assert np.allclose(normalized.mean(), 0.0)
assert np.allclose(bn_output, [-1.449485, 1.0, 3.449485], atol=1e-6)
assert np.allclose(dropout_train, [4.0, 0.0, 12.0, 0.0])

from uuid import uuid4

    loss="sparse_categorical_crossentropy",
    metrics=["accuracy"],

# 이전 실행 파일과 혼동하지 않도록 실행별 폴더를 사용합니다.

    save_weights_only=False,
    save_freq="epoch",
)

early_stopping = tf.keras.callbacks.EarlyStopping(

    mode="min",
    min_delta=0.0,

    batch_size=32,

    X_test,
    y_test,
    return_dict=True,
    verbose=0
)

print(report)

26 · 오류 메시지 읽기

처음 문제가 생긴 기록·경로·모드를 확인합니다

재실습용 보완 사례 · 원본 오류 로그가 아니며 버전별 문구가 달라질 수 있음

01. val_loss가 없음

검증이 설정되고 실행되었는지, monitor가 실제 기록 이름인지 확인합니다. history.history.keys()로 실제 항목을 봅니다.

02. val_acc와 val_accuracy

교안마다 acc 또는 accuracy를 사용합니다. 기억으로 추측하지 말고 컴파일 설정·History·Callback 이름을 맞춥니다.

03. 저장 파일이 없거나 다른 실행 파일

경로·저장 조건·기록 이름·실행 폴더를 확인합니다. 파일 존재만으로 이번 실행의 최선 파일임이 증명되지는 않습니다.

04. 확장자 오류

전체 모델 예는 best.keras, save_weights_only=True의 예는 best.weights.h5입니다. 실제 API 규칙과 맞춥니다.

05. float object is not iterable

max(logs["accuracy"])는 숫자 하나를 최댓값 목록처럼 다루는 문제입니다. 과거 최선값을 별도로 관리하거나 ModelCheckpoint를 사용합니다.

06. Dropout을 동결했는데 마스크가 적용됨

Dropout의 trainable=False와 training=False를 같은 제어로 보지 않습니다. 실제 호출 모드를 확인합니다.

07. BN 추가 후 평가가 이상함

현재 Batch 또는 이동 통계 중 무엇을 사용하는지, 동결·학습 모드·입력 분포·Batch 크기를 확인합니다.

08. 너무 빨리 종료되거나 저장 Epoch가 다름

patience·min_delta·검증 변동을 봅니다. EarlyStopping과 Checkpoint가 서로 다른 지표를 보거나 개선 기준이 다를 수 있습니다.

위 파일·모드·기록 규칙은 공식 문서로 확인합니다. [G] [I] [J] [K]

원본 사용자 정의 Callback 문제를 보완 재현

이 블록은 정상 학습 코드가 아니라 오류 설명입니다. 현재 Epoch의 숫자 하나에 max를 쓰는 것은 과거 최고값을 구하는 일이 아닙니다.

먼저 답을 말한 뒤 펼쳐서 비교하세요. 기법 이름보다 계산·선택·평가의 역할을 연결합니다.

Q1. 최적화와 일반화는 어떻게 다른가요?

학습 목적함수를 줄이는 문제와 새 데이터에서 그 관계가 유효한지의 문제입니다.

Q2. 학습 정확도가 가장 높으면 좋은 모델인가요?

그 사실만으로 고르지 않습니다. 검증·테스트와 실제 사용 목적의 기준을 봅니다.

Q3. Validation과 Test는 어떻게 다른가요?

Validation은 모델·설정·시점 선택에, Test는 선택 후의 최종 평가에 사용하도록 분리합니다.

Q4. Regularization은 무엇을 바꾸나요?

Data Loss에 패널티를 더해 Parameter의 성질도 함께 고려하는 학습 목적을 만듭니다.

Q5. L1의 Weight 하나가 0이면 노드가 없어지나요?

연결 하나의 기여와 노드 전체 경로를 구분합니다. 선언된 Layer Shape이 자동으로 줄지 않습니다.

Q6. 좋은 초기화와 BN은 대체 관계인가요?

시작값의 안정화와 학습 중 중간값 조절이라는 서로 다른 역할입니다. BN이 있다고 초기값을 아무렇게나 정해도 된다는 뜻은 아닙니다.

Q7. BN과 LN은 어디에서 통계를 구하나요?

기본 2차원 비교에서 같은 Feature의 여러 Sample과, 한 Sample 내부의 지정 Feature 축을 구분합니다.

Q8. BN의 평균·분산·γ·β는 모두 Gradient로 학습하나요?

γ·β와 이동 통계의 갱신 방식은 다릅니다. 현재 Batch 통계도 별도로 계산합니다.

Q9. Dropout은 Parameter 수를 줄이나요?

일반적인 Dropout은 활성값을 임시 제외합니다. Weight의 영구 삭제가 아닙니다.

Q10. Dropout 0.5는 항상 정확히 절반을 지우나요?

기본적으로 확률적 마스크입니다. 기대값 보존도 매 실행의 정확한 합 보존과 다릅니다.

Q11. EarlyStopping과 ModelCheckpoint는 어떻게 다른가요?

종료 판단과 파일 저장입니다. 실제 모델 복원·평가도 따로 확인합니다.

Q12. patience는 직전 Epoch보다 나빠진 횟수인가요?

이번 기본 설정은 현재까지의 최선과 비교합니다. 직전보다 조금 좋아져도 최선보다 나쁘면 미개선일 수 있습니다.

Q13. EarlyStopping이 작동하면 과적합인가요?

지표의 개선 정체를 판단한 것이므로 원인은 따로 진단합니다.

Q14. Checkpoint를 읽으면 Test도 반드시 좋아지나요?

아닙니다. 63번 저장 결과에서도 로드 후 테스트 정확도가 아주 조금 낮았습니다. 검증 기준과 Test 최고는 다릅니다.

Q15. 66번 결과로 L1·Dropout이 나쁘다고 말할 수 있나요?

특정 구성과 설정의 결과입니다. 마지막 모델은 입력 BN도 추가되어 단일 효과를 분리하지 못합니다.

Q16. 규제가 다른 모델의 Loss 비교는 왜 조심하나요?

목적함수에 포함된 패널티가 다를 수 있습니다. 공통 예측 지표와 데이터 손실도 함께 확인합니다.
