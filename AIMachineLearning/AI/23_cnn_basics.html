01 · CORE IDEA

CNN은 작은 Filter를 공유하며 위치별 특징을 기록합니다

교안 기준: CNN의 지역 연산·Filter 이동·Feature Map

작은 입력 Patch × 학습 가능한 Filter → 출력 Scalar → Feature Map

CNN은 이미지 전체를 한 번에 완전 연결하지 않습니다. 작은 영역을 보고, 같은 Filter Weight를 여러 위치에 반복 적용하여 같은 종류의 Pattern이 어디에 나타나는지 계산합니다.

Local Connectivity

한 번에 전체 이미지가 아니라 작은 가로·세로 영역을 봅니다.

Weight Sharing

같은 Filter를 여러 공간 위치에 재사용합니다.

Feature Hierarchy

단순한 경계에서 복합적인 형태까지 여러 Layer가 특징을 조합합니다.

Filter 하나는 입력 Channel 전체를 보고 Feature Map 하나를 만듭니다. Filter 수는 출력 Channel 수가 됩니다.

02 · WHY CNN?

이미지는 값뿐 아니라 위치와 이웃 관계가 중요합니다

같은 수의 밝은 Pixel을 갖더라도 서로 붙어 있는지, 떨어져 있는지에 따라 전혀 다른 모양이 됩니다.

표 데이터도 Feature 열의 의미와 순서는 일관되어야 합니다. 다만 이미지처럼 인접한 열이 가로·세로 공간의 이웃 관계를 가진다고 일반화할 수는 없습니다. CNN은 이미지의 국소적 공간 구조를 모델 구조에 반영합니다.

03 · DENSE VS CNN

Flatten은 값을 지우지 않지만 지역성과 Weight Sharing을 활용하지 못합니다

이미지를 Flatten하면 다차원 배열을 1차원으로 재배치합니다. 값 자체가 없어지는 것은 아니며, 원래 Shape과 순서를 알면 복원할 수 있습니다.

  1. 이미지 H × W × C
  2. Flatten 길이 H×W×C의 Vector
  3. Dense 각 입력 위치에 별도 Weight
Dense와 Convolution의 구조적 차이
구분 Dense Convolution
연결 범위 전체 입력과 연결 작은 Patch와 연결
Weight 사용 입력 위치별 별도 Weight 같은 Filter를 여러 위치에 공유
공간 구조 별도 구조로 사용하지 않음 Height·Width 위치를 유지
주요 출력 Vector Feature Map

Parameter 수 예

흑백 1024×1024 이미지를 5개 Dense 노드에 연결하면 Weight는 5,242,880개입니다. 2×2 Filter 5개의 Weight는 20개입니다. CNN의 핵심은 같은 Filter를 여러 위치에 공유한다는 점입니다.

Parameter 수와 연산량은 다릅니다. 적은 Filter Weight도 많은 공간 위치에 반복 적용됩니다.

04 · IMAGE TENSOR & PIXEL

이미지 한 장은 H×W×C, 여러 장은 B×H×W×C입니다

Channel-last 기준의 기본 Shape
축 의미
B 한 번에 묶어 처리하는 이미지 수
H 세로 방향 Pixel 수
W 가로 방향 Pixel 수
C 한 위치가 가진 Channel 수

이미지 한 장: (H, W, C)

Batch: (B, H, W, C)

예: (32, 128, 128, 3)

Grayscale Pixel

한 위치에 밝기값 하나가 있습니다.

RGB Pixel

한 위치에 R·G·B 값 세 개가 있습니다.

일반적인 8-bit 이미지가 0~255 범위를 사용할 수 있지만, 0과 255가 어떤 색을 뜻하는지는 Dataset의 표현을 확인해야 합니다. 교안의 흰색 0·검은색 255는 이해를 위한 가정입니다.

Pixel 정규화

MNIST 실습은 float32로 바꾸고 255로 나누어 값을 주로 0~1 범위로 조정합니다. 이 전처리는 값의 Scale을 바꾸지만 Height·Width의 위치 구조는 바꾸지 않습니다.

06 · FILTER & KERNEL

Kernel의 공간 크기와 실제 Weight Shape을 구분합니다

교안에서는 Filter와 Kernel을 같은 의미로 사용합니다. 코드의 kernel_size=(3,3)는 공간 크기이고, 실제 Filter Weight에는 입력 Channel 깊이가 포함됩니다.

3×3 Kernel의 실제 Shape
입력 Filter 하나 Filter 32개 전체
Grayscale C=1 (3,3,1) (3,3,1,32)
RGB C=3 (3,3,3) (3,3,3,32)
R Patch × R Weight 합산
G Patch × G Weight 합산
B Patch × B Weight 합산

세 Channel 결과 + Bias → 출력 위치 하나

사람이 만든 경계 Filter를 예제로 사용할 수 있지만, 실제 CNN의 Filter Weight는 Loss와 역전파를 통해 학습됩니다. 공간 위치를 이동할 때는 같은 Weight를 사용하고, Optimizer Step에서는 그 Weight가 바뀔 수 있습니다.

07 · CONVOLUTION

Patch와 Filter를 위치별로 곱하고 모두 더합니다

Z[i,j,f] = Σu Σv Σc X[i·S_h+u, j·S_w+v, c] K[u,v,c,f] + b[f]
보완 수식의 기호
기호 의미
i, j 출력 Feature Map의 위치
f Filter 번호·출력 Channel
u, v Filter 내부 공간 위치
c 입력 Channel
S Stride
b[f] Filter마다 하나의 Bias
  1. Patch 선택 Kernel과 같은 공간 영역
  2. Element-wise 곱 모든 입력 Channel 포함
  3. 합산 + Bias 출력 Scalar 하나
  4. Stride 이동 다음 위치에서 같은 Filter 사용

딥러닝 Library가 일반적으로 구현하는 연산은 수학적 Kernel 뒤집기를 생략한 Cross-correlation 형태인 경우가 많지만, 딥러닝 문맥에서는 관례적으로 Convolution이라고 부릅니다.

08 · FEATURE MAP

Filter가 찾으려는 Pattern의 위치별 반응입니다

Filter 1 세로 경계 반응 Feature Map 1
Filter 2 가로 경계 반응 Feature Map 2
Filter 3 다른 국소 Pattern Feature Map 3

Feature Map의 큰 값은 일반적으로 그 Filter가 반응하는 Pattern이 해당 위치에 강하게 나타났다는 뜻입니다. 그러나 학습된 Filter의 의미를 “Filter 7은 반드시 눈을 찾는다”처럼 자동 단정할 수는 없습니다.

원본 이미지와 Feature Map
원본 이미지 Feature Map
밝기·색 값 학습된 Filter의 반응값
입력 데이터 Layer의 중간 표현
RGB 등 원래 Channel 의미 학습된 특징별 Channel 의미

Feature Map 값은 음수가 될 수 있으며, 음수라는 이유만으로 잘못된 데이터가 아닙니다. ReLU는 음수를 0으로 만들고 비선형성을 추가합니다.

09 · THREE DESIGN PRINCIPLES

지역 연결·가중치 공유·특징 계층을 함께 이해합니다

01

Local Connectivity

작은 Patch를 보며 지역적인 선·경계·질감을 계산합니다.

02

Weight Sharing

같은 Filter를 여러 위치에 적용해 위치가 달라도 비슷한 Pattern을 찾습니다.

03

Hierarchical Features

초기 특징을 다음 Layer가 다시 조합하여 더 복잡한 표현을 만듭니다.

Pixel → 경계·방향 → 부분 형태 → 복합 표현 → Class Prediction

깊은 Layer일수록 항상 성능이 좋아지는 것은 아닙니다. 데이터·일반화·최적화와 앞 단원의 성능 개선 원칙을 함께 봅니다.

10 · OUTPUT SHAPE

Kernel·Stride·Padding으로 공간 크기를 계산합니다

Dilation이 1인 기본 Convolution의 보완 공식입니다.

H_out = floor((H_in + 2P_h − K_h) / S_h) + 1

W_out = floor((W_in + 2P_w − K_w) / S_w) + 1

C_out = Filter 수

입력 28×28×1

Kernel 3×3

Stride 1

Padding 0 · valid

출력 26×26×32

Stride가 커지면 적용 위치와 출력 공간 크기가 줄어듭니다. Padding은 가장자리 정보와 출력 크기를 조절합니다. 두 개념은 다음 단원에서 더 자세히 계산합니다.

11 · PARAMETER COUNT

입력 Height·Width가 아니라 Kernel·Channel·Filter로 계산합니다

Params = (K_h × K_w × C_in + 1) × C_out

Bias를 사용하는 기본 Conv2D의 식입니다. +1은 Filter마다 하나인 Bias입니다.

MNIST 3×3 Conv2D, Filter 32개
항목 개수
Filter 하나의 Weight 3×3×1 = 9
Filter 하나의 Bias 1
Filter 하나의 Parameter 10
Filter 수 32
전체 Parameter 10×32 = 320

Parameter

학습되고 모델에 저장되는 Filter Weight와 Bias입니다.

Activation

특정 입력으로 계산된 Feature Map 값입니다. 위 예에서는 26×26×32개입니다.

Parameter 수가 적더라도 큰 이미지의 많은 위치에 Filter를 적용하면 연산량과 Activation 메모리는 클 수 있습니다.

15 · KERAS CONV2D

Filter 수와 공간 설정을 코드 인수로 연결합니다

다음 코드는 통합교안의 Normal Convolution 설정을 독립적으로 읽기 좋은 형태로 정리한 보완 예제입니다. 

import tensorflow as tf

model = tf.keras.Sequential([
    tf.keras.Input(shape=(28, 28, 1)),

    tf.keras.layers.Conv2D(
        filters=32,
        kernel_size=(3, 3),
        strides=(1, 1),
        padding="valid",
        activation="relu",
        kernel_initializer="he_normal",
        use_bias=True,
    ),

    tf.keras.layers.MaxPooling2D(
        pool_size=(2, 2)
    ),
])

model.summary()
코드 인수와 개념의 연결
인수 의미
filters=32 Filter 32개·출력 Channel 32
kernel_size=(3,3) 공간적으로 보는 영역
strides=(1,1) 한 칸씩 이동
padding="valid" 추가 Padding 없이 계산
activation="relu" Convolution 결과에 ReLU 적용

Pooling은 기본적으로 학습 Filter Weight가 없으며 공간 크기를 줄입니다. 세부 계산은 24단원에서 다룹니다.

(28,28,1)의 1은 이미지 수 흑백 Channel 수입니다.
Input에 (60000,28,28,1)을 넣음 이미지 한 장의 (28,28,1)을 사용합니다.
RGB는 Filter를 3개만 사용 입력 Channel 3이 Filter의 깊이를 정합니다.
3×3 Kernel은 Weight 9개 입력 Channel 깊이를 포함해야 합니다.
Filter 수와 입력 Channel은 같아야 함 Normal Conv에서는 별도 설정입니다.
Feature Map은 원본 이미지 복사본 Filter에 대한 위치별 반응입니다.
Weight Sharing이면 Filter가 학습되지 않음 공간에서는 공유되고 학습 Step에서는 업데이트됩니다.
ReLU가 Shape을 줄임 값만 변환하고 Shape은 유지합니다.
Padding을 넣으면 Parameter가 증가 출력 공간은 바뀌지만 Filter Parameter는 그대로입니다.
Stride 2면 Parameter도 절반 적용 위치가 줄며 Weight 수는 그대로입니다.
Parameter가 적으면 연산량도 항상 작음 공간 위치와 Activation 크기도 확인합니다.
교안 주석이 항상 현재 Summary와 같음 현재 활성화된 Layer 구조에서 다시 계산합니다.

22 · INTERVIEW POINTS

Shape과 Parameter를 말로 설명하고 직접 계산합니다

Q1. CNN은 왜 이미지 처리에 적합한가요?

이미지의 공간적 지역성을 유지하고, 작은 Filter를 여러 위치에 공유해 같은 Pattern을 효율적으로 찾기 때문입니다.

Q2. Flatten하면 Pixel 값이 사라지나요?

값은 재배치됩니다. 일반 Dense가 국소 관계와 Weight Sharing을 구조적으로 이용하지 못하는 점이 핵심입니다.

Q3. 이미지와 Batch의 Shape은 무엇인가요?

Channel-last 기준으로 한 장은 H×W×C, 여러 장은 B×H×W×C입니다.

Q4. Filter Depth는 무엇으로 결정되나요?

현재 입력 이미지 또는 Feature Map의 Channel 수로 결정됩니다.

Q5. Filter 수는 무엇을 결정하나요?

출력 Feature Map 수, 즉 출력 Channel 수를 결정합니다.

Q6. 3×3 Kernel이면 Weight가 항상 9개인가요?

입력 Channel이 1일 때 Filter 하나의 Weight가 9개입니다. RGB라면 3×3×3=27개입니다.

Q7. Feature Map은 무엇인가요?

Filter가 찾으려는 Pattern에 대한 위치별 반응값입니다.

Q8. Weight Sharing은 무엇인가요?

같은 Filter Weight를 여러 공간 위치에 재사용하는 것입니다. Filter 자체는 학습 중 업데이트됩니다.

Q9. 한 위치의 Convolution은 무엇을 계산하나요?

Patch와 Filter를 곱하고, 모든 공간·입력 Channel 결과를 합한 뒤 Bias를 더합니다.

Q10. Conv2D Parameter 공식은 무엇인가요?

Bias를 사용할 때 (K_h×K_w×C_in+1)×C_out입니다.

Q11. 28×28×1에 3×3 Filter 32개를 valid·Stride 1로 적용하면?

출력은 26×26×32, Parameter는 320개입니다.

Q12. ReLU가 Feature Map Shape을 바꾸나요?

아닙니다. 각 값을 변환하며 Shape은 유지합니다.

Q13. Parameter 수와 연산량은 같은가요?

아닙니다. 적은 Filter Weight도 많은 공간 위치에 반복 적용될 수 있습니다.

Q14. 교안 주석과 Summary가 다르면 무엇을 하나요?

현재 활성화된 Layer와 입력 Shape에서 Shape·Parameter를 다시 계산한 뒤 Summary와 대조합니다.
