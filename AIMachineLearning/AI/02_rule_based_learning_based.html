01 · CORE CONCEPT

차이는 하나입니다. “판단 규칙을 누가 만드는가?”

Rule-Based와 Learning-Based를 여러 기술 이름으로 외우기보다 판단 규칙이 만들어지는 위치를 중심으로 이해합니다.

핵심 질문

컴퓨터가 어떤 결과를 판단할 때, 그 판단 기준을 사람이 직접 코드로 작성하는가? 아니면 데이터를 이용해 모델이 관계를 학습하는가?
APPROACH A
R

Rule-Based Approach

사람이 규칙을 직접 작성

사람이 문제의 판단 기준을 분석하고 IF / THEN과 같은 형태로 규칙을 프로그램에 명시합니다. 컴퓨터는 이미 만들어진 Rule을 검사하여 결과를 결정합니다.

Human → Rule → Program → Decision
VS
APPROACH B
L

Learning-Based Approach

데이터를 이용해 관계를 학습

사람이 모든 판단 규칙을 직접 작성하지 않고, Training Data와 학습 방법을 준비합니다. 모델은 데이터에서 패턴과 관계를 학습하고 학습된 Model을 이용해 새로운 입력을 판단합니다.

Data → Learning → Model → Prediction
RULE-BASED “사람이 답을 만드는 규칙을 알려준다.”
/
LEARNING-BASED “데이터를 주고 답을 만드는 관계를 학습시킨다.”

02 · WHY LEARNING-BASED?

현실의 모든 예외를 사람이 Rule로 작성하기 어려워졌습니다

보완 예시

주차요금처럼 규칙이 명확한 문제

아래 코드는 AI 교안 원문의 예제가 아니라 Rule-Based 사고방식을 이해하기 위한 보완 예시입니다. 

def calculate_fee(parking_minutes, is_discount_target):
    if parking_minutes <= 30:
        fee = 0
    else:
        extra_minutes = parking_minutes - 30
        fee = ((extra_minutes + 9) // 10) * 1000

    if is_discount_target:
        fee = int(fee * 0.5)

    return fee
RULE 1 30분까지 무료

사람이 정책을 코드로 명확하게 표현했습니다.

RULE 2 10분 단위 요금

계산 기준 역시 사람이 직접 정의합니다.

RULE 3 할인 대상 50%

할인 정책도 학습하지 않고 Rule로 적용합니다.

07 · RULE vs LEARNING

두 접근을 한 표로 비교합니다

비교 기준 Rule-Based Learning-Based
판단 기준 사람이 직접 작성 데이터에서 관계를 학습
핵심 자원 Rule · Domain Knowledge Data · Model · Learning Algorithm
대표 표현 IF / THEN Model / Parameter
Training 일반적으로 별도 학습 없음 Model Training 필요
새로운 예외 사람이 Rule 추가·수정 Data·Model·Training 개선 검토
복잡한 패턴 Rule 수가 급격히 늘 수 있음 데이터를 통해 관계 학습 가능
설명 방식 어떤 Rule이 실행됐는지 직접 추적하기 쉬움 Model 종류에 따라 해석이 복잡할 수 있음
대표 장점 명확성 · 통제 · 결정성 복잡한 패턴과 다양한 입력을 학습 가능
대표 한계 예외 증가 · Rule 유지보수 Data 품질 · 일반화 · 평가 문제
RULE-BASED

코드를 수정해서 판단 기준을 바꾼다

Wrong Result → Rule 수정
LEARNING-BASED

Data와 학습 과정을 검토해서 모델을 개선한다

Wrong Prediction → Data / Model / Training

09 · LIMITATION & COMPLEMENT

두 접근 모두 장점과 한계를 가지고 있습니다

RULE-BASED

명확하지만 Rule이 폭증할 수 있습니다

  • 예외가 늘어나면 Rule 수도 증가합니다.
  • Rule끼리 충돌할 수 있습니다.
  • 복잡한 이미지·언어 패턴을 사람이 조건으로 모두 표현하기 어렵습니다.
  • Rule 수가 많아지면 유지보수가 어려워질 수 있습니다.
잘 맞는 문제
접근 권한 상태 전이 정책 할인율 결제 조건
LEARNING-BASED

복잡한 패턴을 학습하지만 Data와 평가가 중요합니다

  • Data 품질이 나쁘면 잘못된 관계를 학습할 수 있습니다.
  • Data가 편향되면 Prediction도 편향될 수 있습니다.
  • Training Data에는 잘 맞지만 새로운 Data에는 성능이 떨어질 수 있습니다.
  • Model에 따라 판단 근거를 직접 설명하기 어려울 수 있습니다.

10 · COMMON MISTAKES

Rule-Based와 Learning-Based를 처음 공부할 때 생기는 대표적인 오해

01

“Rule-Based는 AI가 아니다.”

이번 교안은 AI를 Rule-Based와 Learning-Based 방식으로 구현할 수 있다고 설명합니다.

02

“Learning-Based는 컴퓨터가 아무 도움 없이 스스로 생각한다.”

Problem, Data, Model, 학습 방법, 평가 방법 등은 여전히 사람이 설계해야 합니다.

03

“Learning-Based에서 학습한 Rule도 반드시 IF / THEN으로 나온다.”

학습된 관계는 Weight, Bias, Tree Structure, Embedding 같은 다양한 형태로 Model 내부에 표현될 수 있습니다.

04

“Data가 많으면 무조건 좋은 Model이 된다.”

Data의 양뿐 아니라 정확성, 다양성, 대표성, Label 품질이 중요합니다.

05

“Learning-Based는 항상 Rule-Based보다 좋다.”

법적 제한, 접근 권한, 고정 할인율처럼 결정적이고 명확한 문제는 Rule-Based가 더 자연스러울 수 있습니다.

06

“두 접근을 함께 사용할 수 없다.”

Model이 복잡한 Pattern을 판단하고 이후 Business Rule로 결과를 제한하는 Hybrid 구조도 가능합니다.

07

“Learning-Based는 항상 정답 Label이 필요하다.”

지도학습에서는 Label을 사용하지만, 이후 배우게 될 비지도학습은 명시적인 정답 Label 없이 학습하고, 강화학습은 Reward를 학습 신호로 사용합니다.

13 · INTERVIEW POINT

두 접근의 차이를 정의 → 이유 → 실무 선택으로 설명합니다

Q1. Rule-Based Approach란 무엇인가요?

사람이 문제의 판단 규칙을 직접 정의하고 프로그램이 그 규칙을 검사하여 결과를 결정하도록 하는 접근입니다. 일반적으로 IF / THEN 같은 명시적인 조건으로 표현할 수 있습니다.

Q2. Learning-Based Approach란 무엇인가요?

사람이 모든 판단 Rule을 직접 작성하는 대신 데이터를 이용해 Model이 Pattern과 관계를 학습하게 하고, 학습된 Model로 새로운 입력을 Prediction하는 접근입니다.

Q3. 두 접근의 가장 중요한 차이는 무엇인가요?

판단 기준을 만드는 주체가 다릅니다. Rule-Based는 사람이 Rule을 직접 작성하고, Learning-Based는 Data를 이용하여 Model이 관계를 학습합니다.

Q4. Rule-Based의 대표적인 한계는 무엇인가요?

현실의 조건과 예외가 많아질수록 Rule의 수가 증가하고, 사람이 모든 상황을 미리 정의하기 어려워지며 유지보수도 복잡해질 수 있습니다.

Q5. Learning-Based가 발전한 배경은 무엇인가요?

교안에서는 Big Data, Computing Power, Machine Learning Algorithm의 발전을 Learning-Based 접근이 확대된 주요 배경으로 설명합니다.

Q6. Learning-Based에서 “학습한다”는 것은 무엇인가요?

교안의 기본적인 수학 모델 관점에서는 데이터를 가장 잘 설명하도록 Weight와 Bias 같은 Parameter의 적절한 값을 찾아가는 과정입니다. Prediction과 실제값의 차이를 줄이는 방향으로 Parameter를 조정합니다.

Q7. Rule-Based는 지금도 사용할 가치가 있나요?

있습니다. 접근 권한, 법적 제한, 할인율, 상태 전이처럼 판단 Rule이 명확하고 결과를 정확하게 통제해야 하는 문제에서는 Rule-Based가 매우 자연스러울 수 있습니다.

Q8. Learning-Based는 항상 Rule-Based보다 좋은가요?

아닙니다. 문제의 성격에 따라 적절한 접근이 달라집니다. 복잡한 Pattern 학습은 Learning-Based가 유리할 수 있지만, 명확한 정책을 확률적으로 예측할 이유는 없을 수 있습니다.

Q9. Rule-Based와 Learning-Based를 함께 사용할 수 있나요?

가능합니다. Model이 복잡한 Pattern을 이용해 후보나 Score를 만들고, 그 결과에 Business Rule을 적용해 최종 결과를 결정하는 Hybrid 구조를 사용할 수 있습니다.

Q10. Learning-Based에서는 항상 Label이 필요한가요?

아닙니다. 이후 배우는 지도학습은 정답 Label을 사용하지만, 비지도학습은 명시적인 정답 없이 학습하고, 강화학습은 Reward를 학습 신호로 사용합니다.

Q11. Machine Learning은 이번 구조에서 어디에 위치하나요?

이번 교안의 학습 흐름에서는 AI 안의 Learning-Based 접근을 구체적으로 구현하는 대표적인 방법으로 Machine Learning을 연결해서 이해할 수 있습니다. 다음 단원에서 Deep Learning과 함께 자세히 구분합니다.

MEMORY

오늘의 암기 포인트

  1. Rule-Based = 사람이 Rule을 작성
  2. Learning-Based = Data에서 관계를 학습
  3. Rule-Based 지식은 주로 Code / Rule에 명시됩니다.
  4. Learning-Based의 관계는 Model Parameter에 반영될 수 있습니다.
  5. Learning-Based는 Training과 Inference를 구분합니다.
  6. 중요한 것은 어느 방식이 “더 최신”인지가 아니라 문제에 더 적합한가입니다.
