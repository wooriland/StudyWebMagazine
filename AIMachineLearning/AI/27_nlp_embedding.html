27. 자연어 처리 문장을 Token으로 나누고,
의미를 가진 Vector로 바꾸다

컴퓨터는 문자열의 의미를 그대로 계산하지 못합니다. 자연어 처리는 문장을 Token으로 나누고, Vocabulary를 통해 정수 ID로 변환한 뒤, Embedding으로 학습 가능한 Dense Vector를 만듭니다. Word2Vec는 중심 단어와 주변 단어의 관계를 예측하며 단어의 문맥 정보를 Vector에 반영합니다.

01 · CORE IDEA

자연어 처리는 문자열을 학습 가능한 숫자 Tensor로 바꾸는 과정입니다

교안 기준 흐름: 텍스트 정제 → 토큰화 → 불용어 처리 → 정수 인코딩 → 워드 임베딩

문장 → Token → Token ID → Embedding Vector → Sequence Model

Tokenization

문장을 모델이 처리할 단어·형태소·Subword 단위로 나눕니다.

Vocabulary

Token과 정수 ID의 대응표를 만듭니다.

Embedding

정수 ID를 저차원의 학습 가능한 실수 Vector로 변환합니다.

Word2Vec

중심 단어와 주변 단어의 예측 관계로 의미 Vector를 학습합니다.

Tokenizer는 문자열을 ID Sequence로 바꾸고, Embedding Layer는 ID를 Dense Vector Sequence로 바꿉니다.

02 · WHY NLP?

컴퓨터는 Token의 정수 ID만으로 단어의 의미와 문맥을 알 수 없습니다

HUMAN LANGUAGE 오늘은 날씨가 좋습니다.

사람은 단어의 의미와 문장 전체의 관계를 함께 이해합니다.

→
COMPUTER INPUT [3, 8, 2]

컴퓨터는 숫자를 계산하지만 ID 자체에는 의미 관계가 없습니다.

TOKEN ID 좋다 → 3 단순한 식별 번호
TOKEN ID 나쁘다 → 4 3보다 의미가 크다는 뜻이 아님

정수 ID는 의미 좌표가 아닙니다

ID의 크기와 거리에는 단어의 유사성·감정·문법 관계가 없습니다. 그래서 정수 ID를 Embedding Vector로 변환해야 합니다.

10 · BOW · DTM · TF-IDF

빈도만 세는 방식에서 문서 전체를 고려한 상대적 중요도로 확장합니다

문서 1 오늘은 날씨가 좋습니다.
문서 2 오늘은 하늘이 맑습니다.
간단한 Document-Term Matrix
문서 오늘 날씨 하늘 좋습니다 맑습니다
문서 1 1 1 0 1 0
문서 2 1 0 1 0 1

TF-IDF(t, d) = TF(t, d) × IDF(t)

IDF(t) = log(N / (1 + DF(t)))

TF-IDF Library마다 Smoothing 수식이 달라질 수 있습니다

위 수식은 교안의 개념식입니다. 실제 Library에서는 0으로 나누는 문제와 음수 값을 피하기 위해 분자·분모에 1을 더하는 등 세부 구현이 달라질 수 있습니다.

14 · EMBEDDING TRAINING

초기 Random Vector는 Task Loss를 줄이는 방향으로 업데이트됩니다

Random Embedding → Model Prediction → Loss → Gradient → Embedding Update

학습 전

Embedding Vector는 의미를 충분히 반영하지 않는 작은 Random 값일 수 있습니다.

학습 중

분류·예측 Loss의 Gradient가 Embedding Matrix까지 전달됩니다.

학습 후

현재 Task에서 유용한 Token Feature가 Vector에 반영됩니다.

Embedding Dimension이 클수록 항상 좋은 것은 아닙니다

Dimension이 커지면 표현력은 증가할 수 있지만 Parameter·Memory·학습 시간·과적합 위험도 증가합니다.

16 · WORD2VEC FORMULA

입력 One-Hot에서 Embedding을 선택하고 Vocabulary 확률을 계산합니다

h = xW

z = hW′ + b

ŷ = softmax(z)

L = −Σ yᵢ log(ŷᵢ)

Word2Vec 기본 수식의 기호
기호 의미
x 입력 Token의 One-Hot Vector
W V × D Embedding Matrix
h 선택된 D차원 Embedding Vector
W′ D × V 출력 Weight Matrix
ŷ Vocabulary 전체의 예측 확률
y 정답 Token의 One-Hot Vector

Loss를 줄이도록 W를 업데이트하면 W의 각 행이 Corpus의 문맥 관계를 반영한 Token Vector가 됩니다.

18 · CBOW

주변 단어들의 Embedding을 모아 중심 단어를 예측합니다

CONTEXT 나는 · 공부한다
→
PREDICT 인공지능을

h = (1 / |C|) Σ E[c]

P(wₜ | C) = softmax(hW′ + b)

  1. Context IDs 주변 Token의 정수 ID
  2. Lookup 각 Context Embedding 선택
  3. Average 주변 Vector를 평균·결합
  4. Predict 중심 Token 확률 계산

CBOW 기억 문장: 주변을 보고 가운데를 맞힌다.

19 · SKIP-GRAM

중심 단어 하나로 여러 주변 단어를 예측합니다

CENTER 인공지능을
→
PREDICT 나는 · 공부한다

h = E[wₜ]

P(w_c | wₜ) = softmax(hW′ + b)

L = −Σ log P(w_c | wₜ)

  1. Center ID 중심 Token의 정수 ID
  2. Lookup 중심 Embedding 선택
  3. Predict Vocabulary Probability
  4. Loss 각 Context Token의 Loss 합산

Skip-gram 기억 문장: 가운데를 보고 주변을 맞힌다.

전통적인 Word2Vec는 Token마다 하나의 고정 Vector를 가집니다

“은행”처럼 문맥에 따라 뜻이 달라지는 다의어를 문장마다 다른 Vector로 표현하기 어렵습니다. 이 한계가 RNN·Attention·Transformer의 문맥 표현으로 이어집니다.

LIBRARY TensorFlow · Keras Tokenizer·Padding·Embedding

23 · KERAS EXAMPLE

Tokenizer·OOV·Padding·Embedding을 하나의 흐름으로 실행합니다 

import numpy as np

from tensorflow.keras.preprocessing.text import (
    Tokenizer,
)

from tensorflow.keras.preprocessing.sequence import (
    pad_sequences,
)

from tensorflow.keras.models import (
    Sequential,
)

from tensorflow.keras.layers import (
    Input,
    Embedding,
)


sentences = [
    "철수는 유튜브를 너무 좋아 합니다.",
    "철수는 태권도를 좋아해 하지만 너무 가기 싫어 합니다.",
    "태권도는 한국의 국기 종목이다.",
    "태권도를 좋아해 주세요.",
]


# 1. OOV Token을 포함한 Tokenizer 생성
tokenizer = Tokenizer(
    oov_token="<OOV>",
)


# 2. Training Corpus를 기준으로 Vocabulary 생성
tokenizer.fit_on_texts(
    sentences
)


# 3. 문장을 Integer Sequence로 변환
sequences = tokenizer.texts_to_sequences(
    sentences
)


# 4. 가장 긴 문장 길이 계산
maxlen = max(
    len(sequence)
    for sequence in sequences
)


# 5. 뒤쪽에 0을 추가해 길이 통일
padded_sequences = pad_sequences(
    sequences,
    maxlen=maxlen,
    padding="post",
    truncating="post",
)


# 6. Padding Index 0을 포함한 Vocabulary Size
vocab_size = (
    len(tokenizer.word_index)
    + 1
)


# 7. Embedding Dimension
embedding_dim = 10


# 8. Embedding Layer 구성
model = Sequential([
    Input(
        shape=(maxlen,)
    ),

    Embedding(
        input_dim=vocab_size,
        output_dim=embedding_dim,
    ),
])


# 9. Integer Sequence를 Embedding Tensor로 변환
embedded_sequences = model(
    np.array(
        padded_sequences
    )
)


print("Vocabulary")
print(
    tokenizer.word_index
)

print("\nInteger Sequences")
print(
    sequences
)

print("\nPadded Sequences")
print(
    padded_sequences
)

print("\nVocabulary Size")
print(
    vocab_size
)

print("\nEmbedding Shape")
print(
    embedded_sequences.shape
)

model.summary()

위 코드는 교안에서 사용하는 tensorflow.keras.preprocessing API를 기준으로 작성했습니다. 설치된 TensorFlow·Keras Version에 따라 경고나 권장 API가 달라질 수 있습니다.

25 · CBOW · SKIP-GRAM PAIRS

Sliding Window가 실제 학습 입력·정답 Pair를 어떻게 만드는지 확인합니다 

from typing import Sequence


def make_cbow_examples(
    tokens: Sequence[str],
    window_size: int = 1,
) -> list[
    tuple[
        list[str],
        str,
    ]
]:
    if window_size < 1:
        raise ValueError(
            "window_size는 1 이상이어야 합니다."
        )

    examples = []

    for center_index, center_word in enumerate(tokens):
        start = max(
            0,
            center_index - window_size,
        )

        end = min(
            len(tokens),
            center_index + window_size + 1,
        )

        context_words = [
            tokens[index]
            for index in range(start, end)
            if index != center_index
        ]

        examples.append(
            (
                context_words,
                center_word,
            )
        )

    return examples


def make_skipgram_examples(
    tokens: Sequence[str],
    window_size: int = 1,
) -> list[
    tuple[
        str,
        str,
    ]
]:
    if window_size < 1:
        raise ValueError(
            "window_size는 1 이상이어야 합니다."
        )

    examples = []

    for center_index, center_word in enumerate(tokens):
        start = max(
            0,
            center_index - window_size,
        )

        end = min(
            len(tokens),
            center_index + window_size + 1,
        )

        for context_index in range(start, end):
            if context_index == center_index:
                continue

            examples.append(
                (
                    center_word,
                    tokens[context_index],
                )
            )

    return examples


sentence = [
    "나는",
    "인공지능을",
    "공부한다",
]


print("CBOW")
print(
    make_cbow_examples(
        sentence,
        window_size=1,
    )
)


print("\nSkip-gram")
print(
    make_skipgram_examples(
        sentence,
        window_size=1,
    )
)

이 코드는 Pair 생성 원리를 보여줍니다

Embedding Weight를 실제로 학습하는 전체 Word2Vec 구현은 아니며, CBOW와 Skip-gram의 입력·정답 방향을 확인하는 예제입니다.

26 · COSINE SIMILARITY

Embedding Vector의 방향 유사성을 계산합니다

cos(u, v) = (u · v) / (||u|| ||v||) 
import numpy as np


def cosine_similarity(
    vector_a: np.ndarray,
    vector_b: np.ndarray,
) -> float:
    vector_a = np.asarray(
        vector_a,
        dtype=np.float64,
    )

    vector_b = np.asarray(
        vector_b,
        dtype=np.float64,
    )

    if vector_a.shape != vector_b.shape:
        raise ValueError(
            "두 Vector의 Shape이 같아야 합니다."
        )

    denominator = (
        np.linalg.norm(vector_a)
        * np.linalg.norm(vector_b)
    )

    if denominator == 0:
        return 0.0

    return float(
        np.dot(
            vector_a,
            vector_b,
        )
        / denominator
    )


cat = np.array([
    0.8,
    0.2,
    0.7,
])

dog = np.array([
    0.7,
    0.3,
    0.8,
])

car = np.array([
    -0.4,
    0.9,
    -0.2,
])


print(
    cosine_similarity(
        cat,
        dog,
    )
)

print(
    cosine_similarity(
        cat,
        car,
    )
)

높은 유사도가 반드시 동의어를 의미하지는 않습니다

“좋다”와 “나쁘다”처럼 반대 의미의 단어도 유사한 문장 구조에 자주 등장하면 문맥 Vector가 가까워질 수 있습니다.

28 · COMMON MISTAKES

Token·ID·Padding·Embedding·Word2Vec의 역할을 서로 바꾸어 읽지 않습니다

자주 하는 착각과 올바른 해석
착각 올바른 해석
Token은 항상 완전한 단어 형태소·문자·Subword도 Token입니다.
한국어는 공백으로만 나누면 됨 조사·어미·활용형을 고려해야 할 수 있습니다.
Vocabulary는 Corpus 전체 문장 Token과 ID의 대응표입니다.
ID가 가까우면 의미도 가까움 ID는 Embedding Row의 주소일 뿐입니다.
OOV와 Padding은 같음 OOV는 미등록 Token, Padding은 길이 보정 값입니다.
One-Hot은 의미를 표현 Token을 구분하지만 의미 유사성은 표현하지 못합니다.
Embedding은 처음부터 의미가 있음 초기에는 Random 값일 수 있으며 학습이 필요합니다.
Dimension이 클수록 항상 좋음 Parameter·Memory·Data Size·과적합을 함께 봅니다.
CBOW와 Skip-gram은 같음 입력과 정답의 방향이 반대입니다.
Word2Vec는 문장 전체 의미를 학습 주로 Local Context Window의 단어 관계를 학습합니다.
높은 Cosine Similarity는 동의어 비슷한 문맥에 등장한 Token일 수 있습니다.
Stopword는 항상 제거 Task에 중요한 부정어·조사·어미일 수 있습니다.

31 · INTERVIEW POINTS

문자열이 Tensor로 바뀌는 과정과 CBOW·Skip-gram의 방향을 설명합니다

Q1. NLP란 무엇인가요?

사람의 언어를 컴퓨터가 분석·검색·분류·생성할 수 있도록 처리하는 분야입니다.

Q2. Corpus란 무엇인가요?

Vocabulary와 언어 사용 패턴을 학습하기 위해 사용하는 문장·문서 집합입니다.

Q3. Token과 Tokenization은 무엇인가요?

Token은 텍스트를 나눈 처리 단위이고, Tokenization은 문장을 Token Sequence로 분리하는 과정입니다.

Q4. 한국어 Tokenization이 복잡한 이유는 무엇인가요?

조사·어미·활용형이 어근과 결합되어 공백만으로 의미 단위를 충분히 구분하기 어렵기 때문입니다.

Q5. Vocabulary란 무엇인가요?

Token과 고유한 정수 ID를 연결한 사전입니다.

Q6. Integer Encoding의 한계는 무엇인가요?

Token을 구분할 수 있지만 정수의 크기와 거리에는 의미 관계가 없습니다.

Q7. OOV와 Padding의 차이는 무엇인가요?

OOV는 Vocabulary에 없는 실제 Token을 대신하고, Padding은 Sequence 길이를 맞추기 위한 예약 값입니다.

Q8. One-Hot Encoding의 한계는 무엇인가요?

Vocabulary Size만큼 차원이 커지고 대부분 값이 0이며 Token 간 의미 유사성을 표현하지 못합니다.

Q9. TF-IDF란 무엇인가요?

현재 문서에서 자주 등장하면서 전체 문서에서는 드문 Token에 높은 중요도를 주는 표현입니다.

Q10. Embedding이란 무엇인가요?

Token ID를 학습 가능한 저차원 Dense Vector로 변환하는 과정입니다.

Q11. Embedding Layer의 Parameter 수는 어떻게 계산하나요?

Vocabulary Size × Embedding Dimension으로 계산합니다.

Q12. Embedding 출력 Shape은 무엇인가요?

일반적으로 (Batch, Time Steps, Embedding Dimension)입니다.

Q13. Lookup 연산이란 무엇인가요?

Token ID에 해당하는 Embedding Matrix의 행 Vector를 선택하는 연산입니다.

Q14. Keras Embedding과 Word2Vec의 차이는 무엇인가요?

Keras Embedding은 현재 Model Task Loss로 학습되고, Word2Vec는 주변 단어 예측을 통해 학습됩니다.

Q15. Word2Vec의 핵심 가정은 무엇인가요?

비슷한 문맥에 자주 등장하는 단어는 비슷한 의미를 가질 가능성이 높다는 것입니다.

Q16. CBOW란 무엇인가요?

주변 단어들을 입력으로 받아 중심 단어를 예측하는 방식입니다.

Q17. Skip-gram이란 무엇인가요?

중심 단어를 입력으로 받아 주변 단어들을 예측하는 방식입니다.

Q18. CBOW와 Skip-gram의 차이는 무엇인가요?

CBOW는 Context → Center이고, Skip-gram은 Center → Context입니다.

Q19. Window Size란 무엇인가요?

중심 단어 앞뒤에서 Context로 사용할 Token 범위입니다.

Q20. Cosine Similarity가 높으면 항상 동의어인가요?

아닙니다. 비슷한 문맥에 등장하는 반의어도 높은 유사도를 가질 수 있습니다.

Q21. Word2Vec의 한계는 무엇인가요?

Token마다 하나의 고정 Vector를 사용하고 문장 전체의 긴 문맥을 직접 모델링하기 어렵습니다.

Q22. FastText가 OOV에 상대적으로 유리한 이유는 무엇인가요?

단어 전체뿐 아니라 Character N-gram과 Subword 정보를 활용할 수 있기 때문입니다.

Q23. Stopword는 항상 제거해야 하나요?

아닙니다. 부정어·조사·어미처럼 Task에 중요한 정보가 될 수 있습니다.

Q24. Vocabulary는 어느 데이터로 만들어야 하나요?

일반적으로 Training Corpus를 기준으로 만들고, Validation·Test의 미등록 Token은 OOV로 처리합니다.

Q25. Embedding이 다음 RNN 단원에 왜 필요한가요?

RNN은 각 Time Step에서 Token의 Dense Vector를 입력받기 때문에 Integer Sequence를 (B, T, D) Tensor로 바꾸는 Embedding이 필요합니다.

MEMORY

오늘의 암기 포인트

  1. Tokenization은 문장을 처리 단위로 나눕니다.
  2. Vocabulary는 Token과 ID의 대응표입니다.
  3. OOV는 미등록 Token이고 Padding은 길이 맞춤 값입니다.
  4. Integer ID 자체에는 의미 관계가 없습니다.
  5. Embedding은 ID를 Dense Vector로 Lookup합니다.
  6. Parameter는 Vocabulary Size × Dimension입니다.
  7. CBOW는 주변 → 중심, Skip-gram은 중심 → 주변입니다.
