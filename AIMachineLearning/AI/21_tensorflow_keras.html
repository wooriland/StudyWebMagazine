01 · 전체 학습 흐름

모델 생성·학습 설정·학습·평가·예측은 다른 작업입니다

교안 A의 Keras 절차 + Step 1·2의 역할 구분 [A]

이번 단원은 새로운 학습 원리를 추가하기보다, 앞에서 배운 신경망 계산을 실제 Python 객체와 메서드에 연결합니다. 교안의 순서를 유지하되 구조와 초기 상태의 준비, 학습 규칙 연결, 실제 Parameter 학습 을 나누어 읽습니다.

각 메서드를 한 문장으로 읽기
단계 핵심 역할 구분할 결과
Model 생성 입력에서 출력까지 계산 구조를 정함 초기 모델과 학습된 모델은 다름
compile() Loss·Optimizer·Metric 설정을 연결 설정 완료가 학습 완료는 아님
fit() 데이터로 기존 모델을 학습 반환값은 History
evaluate() 현재 모델의 Loss·Metric 계산 Sample별 예측 배열이 아님
predict() 입력의 모델 출력 계산 정확도나 Class 이름 자체가 아님

모델이 실행된다는 사실과 유용한 예측을 한다는 사실을 구분합니다. 이 페이지에서 교안 코드·저장 출력·보완 계산·현재 공식 API는 각각 표시합니다.

02 · 왜 배우는가

직접 읽었던 계산을 Library의 구조로 표현합니다

교안 A의 모델 구성 요소 / 자동 미분·실행 기반 보완 [A] [C]

Z=XW+b → H=f(Z)

L=ℒ(Y, Ŷ) → Gradient → Parameter Update

직접 구현에서는 행렬곱·Bias·Activation·미분· 학습 반복문을 확인했습니다. Keras에서는 Layer·Model·Loss·Optimizer·fit으로 표현합니다. 원리가 사라지는 것이 아니라 반복적인 계산을 도구에 맡기는 것입니다.

도구가 제공하는 것

Tensor 연산, 자동 미분, Layer의 상태 관리, 학습·평가 인터페이스입니다.

개발자가 정할 것

X·y의 의미, Feature 순서와 단위, 출력 형태, Loss, 데이터 분할과 평가 기준입니다.

“회귀인가, 이진 분류인가, 다중 분류인가?”를 먼저 정해야 적절한 출력층과 Loss를 연결할 수 있습니다. Library를 사용한다고 문제 정의와 성능 검증까지 자동으로 해결되는 것은 아닙니다.

05 · Layer와 Model

계산 단위와 전체 계산 구조를 구분합니다

교안의 Fully Connected Layer와 모델 구성 / Dense 수식 보완 [A] [E]

Dense(64, activation="relu") → H=ReLU(XW+b)

Dense(64)는 Layer 64개가 아니라 현재 Layer의 출력 유닛 64개입니다. 교안은 이전 Layer와 다음 Layer의 뉴런을 연결하는 Dense를 Fully Connected Layer로 설명합니다.

Layer

입력을 받아 출력을 만드는 계산 단위입니다. Dense는 자신의 Weight와 Bias를 관리합니다.

Model

입력부터 최종 출력까지 여러 Layer와 상태를 묶은 객체입니다.

  1. 구조 정의 어떤 계산을 연결할지 결정
  2. 상태 준비 입력 크기에 맞는 초기 Parameter 생성
  3. 학습 데이터에 따라 Parameter 조정

초기 Parameter가 생겼거나 출력을 계산할 수 있다는 사실만으로 학습 성능이 검증되지는 않습니다. 상태가 준비된 모델과 학습된 모델을 구분합니다.

세 가지 모델 생성 방식
방식 구조 표현 핵심

인수 의미
x·y 입력과 정답

위 한 줄은 호출 형태를 설명하는 표현입니다. 실제 fit의 반환값은 History 객체입니다. 검증을 수행했다면 검증 기록도 history.history에 들어갑니다.

model = model.fit(...)으로 덮어쓰지 않습니다

그렇게 하면 model이라는 이름이 History를 가리킵니다. 학습된 Model 객체와 학습 기록 객체를 각각 유지합니다. 모델을 새로 만들지 않고 fit을 다시 호출하면 기존 학습 상태에서 이어질 수 있습니다.

11 · Train·Validation·Test

검증 분리와 셔플을 같은 작업으로 보지 않습니다

교안 A의 검증 개념 / 실제 배열 분리 규칙 보완 [A] [F]

Train

Gradient를 구하고 Parameter를 조정하는 데 사용합니다.

Validation

학습 중 현재 모델을 점검합니다. 기본 검증 단계는 검증 정답으로 학습 Update를 하지 않습니다.

최종 평가용으로 별도 관리합니다. 검증 결과로 구조나 Epoch를 선택하는 과정과 분리합니다.

import tensorflow as tf
import numpy as np

from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split
from tensorflow.keras import models, layers, optimizers

iris = load_iris()
X = iris.data
y = iris.target

X_train, X_test, y_train, y_test = train_test_split(
    X,
    y,
    test_size=0.2,
    stratify=y,
    random_state=42
)

model = models.Sequential()
model.add(tf.keras.Input(shape=(4,)))
model.add(layers.Dense(64, activation="relu", name="hidden-1"))
model.add(layers.Dense(16, activation="relu", name="hidden-2"))
model.add(layers.Dense(3, activation="softmax", name="output"))

model.summary()

adam = optimizers.Adam(learning_rate=0.001)
model.compile(
    optimizer=adam,
    loss="sparse_categorical_crossentropy",
    metrics=["accuracy"]
)

history = model.fit(
    X_train,
    y_train,
    epochs=8,
    validation_split=0.2,
    batch_size=1,
    verbose=1
)

model.evaluate(X_test, y_test)

원본은 Adam의 Learning Rate를 0.001, Epoch를 8, Batch Size를 1로 지정합니다. Batch Size 1은 데이터 단위이며 Update 규칙을 SGD로 바꾸는 설정이 아닙니다.

21 · fit 안의 손계산

단일 선형 모델에서도 순전파·Loss·Gradient·Update를 연결합니다

Step 1·2의 별도 보완 예제 · 붓꽃 모델과 다른 문제

ŷ=wx+b, X=[0,1], Y=[1,3]

w=0, b=0, η=0.1

학습 전 예측은 [0,0], 평균 제곱오차는 ((0−1)²+(0−3)²)/2=5입니다. 같은 Update 전 Parameter에서 두 Gradient를 계산합니다.

∂L/∂w=(2/N)Σ(ŷ_i−y_i)x_i=−3

∂L/∂b=(2/N)Σ(ŷ_i−y_i)=−4

w_new=0.3, b_new=0.4

보완 손계산 · Update 이후 Loss를 다시 계산
시점 w b 예측값 MSE
학습 전 0 0 [0,0] 5
한 번 Update 후 0.3 0.4 [0.4,0.7] 2.825

새 입력 x=2의 현재 예측은 0.3×2+0.4=1.0입니다. 설명용 관계 y=2x+1의 정답 5와 다릅니다. 한 번 학습했다고 충분히 학습된 것은 아닙니다.

0 초기화의 범위

단일 선형 모델의 손계산을 위한 설정입니다. 모든 깊은 신경망의 Weight를 0으로 초기화하라는 제안이 아닙니다.

22 · 독립 NumPy 검증

TensorFlow 학습 로그와 수식 검증 결과를 구분합니다

독립 실행용 보완 코드 · NumPy만 사용 · 작은 고정 입력 

import numpy as np

# 보완 예제: 단일 선형 모델입니다. 깊은 신경망의 0 초기화 권장이 아닙니다.
X = np.array([[0.0], [1.0]], dtype=np.float64)
y = np.array([[1.0], [3.0]], dtype=np.float64)
W = np.zeros((1, 1), dtype=np.float64)
b = np.zeros(1, dtype=np.float64)
learning_rate = 0.1

prediction_before = X @ W + b
error = prediction_before - y
loss_before = float(np.mean(error ** 2))

# 같은 Update 전 Parameter에서 두 Gradient를 구합니다.
n_samples = X.shape[0]
grad_W = (2.0 / n_samples) * (X.T @ error)
grad_b = 2.0 * np.mean(error, axis=0)

W -= learning_rate * grad_W
b -= learning_rate * grad_b

prediction_after = X @ W + b
loss_after = float(np.mean((prediction_after - y) ** 2))
new_prediction = np.array([[2.0]]) @ W + b

np.set_printoptions(precision=3, suppress=True)
print("학습 전 예측:", prediction_before.ravel())
print(f"학습 전 MSE: {loss_before:.3f}")
print("Weight Gradient:", grad_W.ravel())
print("Bias Gradient:", grad_b)
print("새 Weight:", W.ravel())
print("새 Bias:", b)
print("학습 후 예측:", prediction_after.ravel())
print(f"학습 후 MSE: {loss_after:.3f}")

assert np.allclose(W, [[0.3]])

assert np.allclose(prediction_after, [[0.4], [0.7]])

24 · 자주 하는 실수

객체와 메서드가 맡은 역할을 바꾸어 읽지 않습니다

앞 카드의 교안 내용과 보완 구분 복습

Step 1·2의 핵심 오해 점검
자주 하는 착각 올바른 해석
TensorFlow와 Keras는 완전히 같은 이름이다 역할과 버전별 관계를 구분합니다.
설치하면 이미 학습된 모델이 생긴다 이번에는 구조를 만들고 학습할 기반을 준비합니다.
Input(shape=(4,))는 Sample 네 개다 Sample 하나의 Feature 네 개입니다.
(None,64)의 None은 결측값이다 정의 시점에 고정하지 않은 축 크기입니다.
Dense(64)는 Layer 64개다 현재 Dense의 출력 유닛 수입니다.
모델 생성은 학습 완료다 구조·초기 상태·학습을 분리합니다.
build와 compile은 같은 일이다 상태 준비와 학습 설정 연결은 다릅니다.
compile하면 Weight가 좋아진다 실제 데이터 학습은 fit에서 수행합니다.
metrics에 accuracy를 넣으면 Accuracy를 미분한다 이번 학습 목적은 설정한 Loss입니다.
fit은 새 Model을 반환한다 기존 모델을 학습하고 History를 반환합니다.
evaluate는 언제나 숫자 두 개다 Loss·Metric 설정에 따라 달라집니다.
predict는 정확도를 반환한다 Sample별 출력이며 Label 비교는 별도입니다.
predict가 Class 이름을 반환한다 확률·인덱스·이름 매핑을 구분합니다.
shuffle=True면 검증 데이터도 매번 새로 뽑힌다 검증 분리와 학습 셔플은 다른 작업입니다.
batch_size=1이면 Adam이 SGD로 바뀐다 데이터 단위와 Update 규칙은 별개입니다.
학습 후에는 Feature 순서가 달라도 괜찮다 서비스에서도 동일한 의미·순서·전처리를 유지해야 합니다.

Loss를 백분율 Accuracy로 표시하거나, History를 Model로 사용하거나, 평가 숫자를 Sample별 예측값으로 사용하지 않습니다.

25 · 오류 메시지 읽기

실행 환경부터 출력 해석까지 첫 문제 위치를 찾습니다

재실습용 보완 사례 · 원본 오류 로그 아님 · 버전마다 문구가 다를 수 있음 [F] [J]

01. ModuleNotFoundError

패키지를 설치한 Python과 실행 중인 Interpreter·Notebook Kernel을 확인합니다. 현재 호환 조건은 공식 설치 안내로 확인합니다.

02. AttributeError · Sequantial

교안의 철자를 그대로 복사했는지 확인합니다. 실제 API는 Sequential입니다. 오타를 명시적으로 보완합니다.

03. SyntaxError · Dense 인수

45쪽 예처럼 쉼표·괄호·들여쓰기를 확인합니다. 모델 성능 전에 Python 문법을 점검합니다.

04. 입력 차원 불일치

X.shape와 model.input_shape를 비교하고 Sample축·Feature축을 구분합니다. 의미가 틀린 데이터를 reshape로 숨기지 않습니다.

05. Data cardinality

입력 (120,4)와 Label (119,)처럼 Sample 수가 다른지 확인합니다. X.shape[0]과 y.shape[0]의 대응을 봅니다.

06. Label 범위·Loss 형식 오류

이번 Class 3개의 정수 Label은 0·1·2입니다. 출력 Shape, Label 인코딩, Loss, from_logits 순서로 점검합니다.

07. History에 predict가 없음

model=model.fit(...)으로 Model 이름을 History로 덮어썼는지 확인합니다. history=model.fit(...)로 역할을 나눕니다.

08. KeyError: val_loss

검증을 수행했는지 확인하고 history.history.keys()를 봅니다. 없는 검증 기록이 항상 생긴다고 가정하지 않습니다.

09. Gradient가 None

숫자 0인 Gradient와 다릅니다. Loss와 변수가 연결되었는지, 연산이 추적되었는지, NumPy로 미분 경로가 끊기지 않았는지 확인합니다.

  1. 환경 Python·패키지·Kernel
  2. 데이터 의미·순서·Shape·Label
  3. 모델과 설정 출력 Shape·Loss·Optimizer
  4. 결과 History·평가값·예측값

학습이 안 된다고 무조건 Epoch나 Optimizer만 바꾸지 않습니다. 모델과 Loss가 연결되지 않았다면 학습 규칙보다 먼저 계산 경로를 확인해야 합니다.

일반 사용자 요청마다 fit을 호출하는 것과 학습된 모델을 사용하는 추론은 다릅니다. 일렬 구조는 Sequential, 분기·병합은 Functional, 클래스 안의 계산 제어는 Subclassing으로 역할을 구분하되 어떤 방식도 입력→Layer→출력→Loss→Gradient→Update의 원리를 바꾸지는 않습니다.

질문을 읽고 먼저 답한 뒤 펼쳐서 비교하세요. 이름을 외우기보다 계산 역할을 연결합니다.

Q1. TensorFlow와 Keras의 차이는 무엇인가요?

이번 흐름에서는 TensorFlow가 계산·자동 미분의 기반이고 Keras가 Layer·Model·학습 인터페이스입니다. 현재 Keras 3의 멀티 백엔드 관계는 교안 버전 설명과 구분합니다.

Q2. Shape·Rank·dtype은 무엇인가요?

각 축의 크기, 축의 개수, 원소의 자료형입니다.

Q3. Input(shape=(4,))는 Sample 네 개인가요?

아닙니다. Sample 하나의 Feature 수 네 개입니다.

Q4. (None,64)의 None은 결측값인가요?

아닙니다. 모델 정의에서 해당 축의 크기를 고정하지 않았다는 뜻입니다.

Q5. Layer와 Model은 어떻게 다른가요?

하나의 계산 단위와 입력부터 출력까지 연결한 구조·상태의 차이입니다.

Q6. 모델을 생성하면 학습된 것인가요?

아닙니다. 구조·초기 Parameter와 학습된 상태는 다릅니다.

Q7. build와 compile의 차이는 무엇인가요?

입력에 맞는 상태 준비와 Loss·Optimizer·Metric 등 학습 설정 연결을 구분합니다.

Q8. Accuracy Metric을 추가하면 Accuracy를 미분하나요?

기본 학습 목적은 설정한 Loss이고 Accuracy는 관찰 지표입니다.

Q9. fit은 무엇을 반환하나요?

History입니다. 기존 모델의 Parameter와 별도로 Epoch별 기록을 확인합니다.

Q10. evaluate는 언제나 두 값을 반환하나요?

아닙니다. Loss·Metric 설정에 따라 달라집니다. 이 원본은 Loss와 Accuracy를 설정했습니다.

Q11. predict는 정확도를 반환하나요?

아닙니다. Sample별 모델 출력입니다. 정확도는 실제 Label과 비교해야 합니다.

Q12. Softmax 출력은 어떻게 Class 이름이 되나요?

Class 축에서 argmax로 인덱스를 선택한 뒤 정의한 이름 순서에 연결합니다.

Q13. shuffle=True면 검증도 새로 뽑나요?

배열의 validation_split은 셔플 전에 검증 부분을 분리합니다. 학습 셔플과 다른 작업입니다.

Q14. Subclassing이면 미분 전체를 직접 구현하나요?

아닙니다. call에 순전파를 정의하고 내장 학습 인터페이스를 사용할 수 있습니다.

Q15. 통합교안의 붓꽃 예제는 이미지 분류인가요?

검토 메모와 실제 입력은 4개 수치 Feature의 표 데이터라고 명시합니다. 원본의 이미지 표현과 구분합니다.

Q16. 두 교안의 붓꽃 구조가 같은가요?

AI 기본 설계는 4→64→3, 통합교안 51번은 4→64→16→3입니다.

Q17. random_state=42가 모든 결과를 고정하나요?

이 코드에서는 데이터 분할 설정입니다. 모든 초기화·학습 실행 조건을 고정하는 선언은 아닙니다.

Q18. 다음 성능 개선 단원은 무엇을 묻나요?

학습 기록과 검증을 이용해 과적합을 살피고 구조·초기화·정규화·Dropout·조기 종료 등의 개선을 다룹니다.

오늘의 암기 포인트

  1. Tensor는 Shape·Rank·dtype으로 읽습니다.
  2. Layer는 계산 단위, Model은 전체 연결입니다.
  3. build와 compile은 다른 역할입니다.
  4. fit은 모델을 학습하고 History를 반환합니다.
  5. evaluate는 평가값, predict는 예측 배열입니다.
  6. Validation과 학습 Update를 구분합니다.
  7. 원본 결과·보완 계산·현재 API를 분리합니다.
