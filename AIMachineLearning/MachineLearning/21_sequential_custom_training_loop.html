B는 현재 Batch의 Sample 수다. Grayscale이지만 원문은 Channel 축을 추가하지 않는다. 입력을 (N,28,28,1)로 설명하지 않는다. 정답은 (B,), Logit은 (B,10)으로 서로 달라도 Sparse Loss에서는 정상이다.

Rank·Shape·행렬곱: (B,28,28)은 축 세 개, (B,784)는 축 두 개다. Shape는 각 축의 길이이고, (B,784) @ (784,128)에서는 안쪽 784가 일치해야 한다.

Model·행렬 계산

학습 변수 Tensor 네 개, 수치 Parameter 101,770개

Step 1·2의 구조 계산 · 원본 Summary 출력이 아님

H = ReLU(XflatW1 + b1)
Z = HW2 + b2

학습 변수와 수치 Parameter 수
변수 Shape 원소 수
W₁ · 은닉층 Kernel (784,128) 100,352
b₁ · 은닉층 Bias (128,) 128
W₂ · 출력층 Kernel (128,10) 1,280
b₂ · 출력층 Bias (10,) 10
합계 변수 Tensor 네 개 101,770

첫 Dense는 100,480개, 마지막 Dense는 1,290개다. InputLayer와 Flatten에는 학습 Parameter가 없다. Flatten은 784개 값을 버리지 않고 펼친다.

(B,784) @ (784,128) + (128,) → (B,128)
(B,128) @ (128,10) + (10,) → (B,10)

Batch가 64에서 32로 바뀌어도 Weight Shape와 Parameter 개수는 바뀌지 않는다. 변화하는 것은 처리하는 Sample의 수다.

Loss·Optimizer 준비

compile 대신 객체를 직접 생성하고 호출한다

교안 원문 · Cell 6

# 손실함수, 옵티마이저
loss_fn = tf.keras.losses.SparseCategoricalCrossentropy(from_logits=True)
optimizer = tf.keras.optimizers.Adam()
무엇을 하는가?
Cross-Entropy와 Adam 객체를 준비한다.
왜 필요한가?
직접 Loss를 계산하고 Gradient를 적용하기 위해서다.
입력 Shape
객체 생성 시 Dataset을 넣지 않는다.
출력·반환값
호출 가능한 loss_fn과 optimizer 객체.
실행 후 변화
학습 도구가 준비된다. W,b의 정답 기반 업데이트는 아직 없다.
설정의 의미
항목 이번 해석
Sparse 정답이 One-Hot이 아닌 0~9 정수 Class Index
from_logits=True 모델 출력을 Softmax 이전 점수로 해석
Loss 호출 loss_fn(y_batch, logits)
기본 집계 이 원본에서는 현재 Batch 평균 Cross-Entropy
Adam() 학습률 인자를 원문에 직접 쓰지 않음
공식 API 기본 학습률 0.001. 원본에서 출력한 실행값은 아님

정답 Class c의 손실: L = −zc + log(∑ exp(zj))
= −log(softmax(z)c)

위 식은 의미를 설명한 보완 수식이다. 직접 exp로 구현하는 대신 원문의 Loss 객체를 사용한다. 정답 (B,)와 Logits (B,10)을 입력받아 Loss 스칼라 ()를 계산한다.

Logit ≠ 확률: Logit은 음수·1보다 큰 값도 가능하고 합이 1일 필요가 없다. 이번 출력에 임의로 Softmax를 추가하면서 from_logits=True를 그대로 두지 않는다. 확률 입력과 Logit 입력을 구분한다.

Mini-Batch는 Sample을 나누는 방식이고 Adam은 업데이트 규칙이다. Adam()의 기본값 설명은 원본 코드에 learning_rate=0.001이 직접 쓰였다는 뜻이 아니다. 원본에 학습률 후보 비교나 Schedule은 없다.

주석 코드와 기존 출력을 함께 보존했다. 저장된 출력이 있다는 사실이 현재 활성 코드로 재현된다는 뜻은 아니다. 이 페이지에서 주석을 조용히 제거하지 않는다.

epochs = 1

무엇을 하는가?
X와 y를 Sample끼리 연결하고 최대 64개씩 묶는다.
왜 필요한가?
안쪽 학습 루프가 Batch를 꺼내도록 준비한다.
입력 Shape
X_train (60000,28,28), y_train (60000,).
출력·반환값

실행 후 변화
Dataset이 준비된다. 생성만으로 가중치를 학습하지 않는다.

from_tensor_slices((X_train, y_train))는 같은 위치의 이미지·Label을 연결한다. 반복 중 X_batch·y_batch는 TensorFlow Tensor로 사용된다. 원래 NumPy 배열을 Label과 무관하게 독립 셔플하는 코드가 아니다.

기본적으로 남은 Sample을 버리지 않는다. 마지막 작은 Batch도 반복문이 처리한다. 원문의 일반 Batch Shape 주석을 모든 Step의 고정 크기로 보지 않는다.

Epoch·Batch·Step

1 Epoch이지만 업데이트는 938회다

원본 설정에 대한 계산

60,000 = 64 × 937 + 32
ceil(60,000 / 64) = 938 Batch

학습 반복과 마지막 Batch
항목 원본 설정에서 계산한 값
일반 Batch Sample 64개씩 937개
마지막 Batch Sample 32개, X (32,28,28), y (32,)
전체 Batch 938개
enumerate Step Index 0~937
현재 epochs 1
끝까지 한 번 실행한 업데이트 938회
출력할 Index 0,100,200,…,900의 열 개

Index는 0부터 센다. Step 0은 첫 Batch이고, Step 900은 901번째 Batch다. 마지막은 Step 937이다. Step 900 이후에도 901~937의 37회 업데이트가 더 진행된다.

앞의 ML 20

Full-Batch 100 Epoch → 업데이트 100회.

이번 ML 21

Mini-Batch 1 Epoch → 업데이트 938회.

Epoch 숫자만으로 업데이트 양을 비교하지 않는다. 이 계산은 루프를 중단 없이 끝까지 한 번 실행하는 조건이며, Notebook의 과거 누적 학습 횟수를 증명하는 기록은 아니다.

#맞춤 학습 루프

for epoch in range(epochs):
    print(f"\nEpoch {epoch+1}/{epochs}")
    #배치 크기로 데이타를 꺼내와서 GradientTape 안에서
    #손실(loss)을 계산하고
    #옵티마이저로 업데이트하기

    #train_dataset:tf.data.Dataset으로 만든 (입력, 레이블) 배치 데이터셋
    #한 번 반복할 때마다
    # (64, 28, 28) shape의 학습 데이터를 X_batch에 저장
    # (64,) shape의 정답 레이블을  y_batch에 저장
    for step, (X_batch, y_batch) in enumerate(train_dataset):
        #GradientTape는 TensorFlow에서 자동 미분을 계산하는 도구이다
        #이 블록 안에서 실행되는 연산들은 모두 그래디언트 계산 대상으로 기록된다
        with tf.GradientTape() as tape:
            #model에 입력 배치(X_batch)를 넣어 예측값(logits)을 얻기

            logits = model(X_batch)
            #예측값(logits)과 정답(y_batch)을 비교해서 손실(loss)을 계산
            loss = loss_fn(y_batch, logits)
        #손실을 가중치에 대해 미분
        #grads는 각 파라미터에 대한 기울기(gradient) 리스트
        grads = tape.gradient(loss, model.trainable_weights)
        #옵티마이저(Adam)가 기울기(grads)를 이용해 모델 파라미터를 업데이트
        optimizer.apply_gradients(zip(grads, model.trainable_weights))

        if step % 100 == 0:
            print(f"Step {step}: loss = {loss.numpy():.4f}")

왜 필요한가?
fit 없이 학습 과정을 직접 제어한다.
입력 Shape
일반 Batch X (64,28,28), y (64,); 마지막은 32개.
출력·반환값
반복 중 Logits·Loss·Gradient와 콘솔 출력. History 반환 함수가 아니다.

W,b와 Adam 상태가 갱신된다. 출력 조건과 무관하게 모든 Batch에서 업데이트한다.

Step 1·2 보완 해석

Tape는 관련 TensorFlow 연산을 기록하고, 역방향으로 따라가며 미분한다. “모든 연산”이라는 원문 주석을 모든 Python 동작을 무조건 미분한다는 뜻으로 확대하지 않는다. 기본 설정에서는 접근한 학습 가능한 변수와 연결된 연산이 관찰된다.

Accuracy = 맞힌 Sample 수 / 전체 Sample 수
전체 평균 Loss = ∑(nbLb) / ∑nb

L_b는 Batch 평균, n_b는 그 Batch의 Sample 수다. 마지막 Batch가 작으면 평균들을 같은 비중으로 합치지 않는다. 또한 학습 중 변하는 모델의 Batch 손실 평균과, 종료 후 고정 모델로 다시 평가한 값은 다른 측정이다.

Loss ≠ Accuracy ≠ R². 0.2089는 정확도·오분류율 20.89%가 아니다. 숫자 0~9는 Class Index이며, Class 번호의 거리를 회귀 오차처럼 해석하지 않는다. 원본에 R² 계산도 없다.

Step 1·2 보완 예시 · 별도 Test 평가 

# 보완 예시: 원본 학습 이후 Test를 별도로 평가한다.
test_dataset = tf.data.Dataset.from_tensor_slices(
    (X_test, y_test)
).batch(256)

test_loss_metric = tf.keras.metrics.Mean()
test_accuracy_metric = tf.keras.metrics.SparseCategoricalAccuracy()

for X_eval, y_eval in test_dataset:
    test_logits = model(X_eval, training=False)
    batch_loss = loss_fn(y_eval, test_logits)

    # 현재 batch_loss는 Batch 평균이므로 Sample 수로 가중한다.
    current_batch_size = tf.cast(tf.shape(y_eval)[0], tf.float32)

    test_loss_metric.update_state(
        batch_loss,
        sample_weight=current_batch_size
    )
    test_accuracy_metric.update_state(y_eval, test_logits)

print("Test Loss:", float(test_loss_metric.result().numpy()))
print(
    "Test Accuracy:",
    float(test_accuracy_metric.result().numpy()) * 100,
    "%"
)
무엇을 하는가?
Test를 여러 Batch로 처리하여 Loss·Accuracy를 누적한다.
왜 필요한가?
원본에 없는 독립 평가를 어떻게 작성하는지 보여 준다.
입력 Shape
X_test (10000,28,28), y_test (10000,); 보완 예시의 평가 Batch는 최대 256.
출력·반환값
Test 평균 Loss와 Accuracy 스칼라.
실행 후 변화
Metric의 누적값만 바뀐다. apply_gradients가 없으므로 학습용 W,b를 갱신하지 않는다.

평가 Batch Size 256은 이 예시에서 선택한 값이며 원본의 64와 구분한다. Batch 평균 손실에 Sample 수를 가중하여 전체 평균을 만든다. Accuracy에는 Logits를 그대로 전달할 수 있다.

전체 예시는 Metric 객체를 새로 생성한다. 객체를 유지한 채 평가 반복문만 다시 실행하는 경우에는 reset_state()로 평가 구간을 분리해야 한다. 결과는 현재 모델 상태에 따라 달라지므로 예상 정확도 숫자를 고정하지 않는다.

보완 코드·predict에 해당하는 작업

Class는 Logit에서, 확률은 Softmax에서 읽는다

Step 1·2 보완 예시 · 단일 이미지 추론 

# 보완 예시: 이미 전처리된 Test 이미지 한 장을 사용한다.
single_x = X_test[:1]

if single_x.shape != (1, 28, 28):
    raise ValueError(f"입력 Shape를 확인하세요: {single_x.shape}")

if not np.isfinite(single_x).all():
    raise ValueError("입력에 NaN 또는 Inf가 있습니다.")

single_logits = model(single_x, training=False)

if tuple(single_logits.shape) != (1, 10):
    raise ValueError(f"출력 Shape를 확인하세요: {single_logits.shape}")

tf.debugging.assert_all_finite(
    single_logits,
    "Logit에 NaN 또는 Inf가 있습니다."
)

probabilities = tf.nn.softmax(single_logits, axis=-1)

predicted_class = int(
    tf.argmax(single_logits, axis=1, output_type=tf.int32)[0].numpy()
)
selected_probability = float(
    probabilities[0, predicted_class].numpy()
)

print("예측 숫자:", predicted_class)
print("선택한 Class의 확률:", selected_probability)
print("실제 정답:", int(y_test[0]))
무엇을 하는가?
전처리된 Test 한 장의 Logit·Class·확률을 계산한다.
왜 필요한가?
학습된 모델의 출력을 실제 숫자 판정으로 연결한다.
입력 Shape
X_test[:1]은 (1,28,28).
출력·반환값
Logits (1,10), 확률 (1,10), 선택한 Class는 정수 하나.
실행 후 변화
추론 결과만 생성한다. W,b를 업데이트하지 않는다.
한 장 (1,28,28)
→
Logits (1,10)
→
argmax → 숫자
Softmax → 확률

Softmax는 최대 점수의 Class 순서를 유지한다. 숫자만 고를 때는 Logits의 argmax로 충분하고, 확률 표시에 Softmax를 적용한다. Sample별 Class 선택은 axis=1이며 0.5 임계값 판정이 아니다.

추가 정규화 금지: X_test는 이미 전처리되었다. training=False는 추론 의도를 나타내는 보완 코드다. 원문 학습의 model(X_batch)를 변경한 것으로 표시하지 않는다. 결과 숫자는 새로 실행하여 얻은 기록이 없다.

# 보완 진단: 원문 코드가 아니며, grads 계산 이후에 추가한다.
weights = model.trainable_weights

if len(grads) != len(weights):
    raise ValueError("Gradient와 학습 변수 개수가 다릅니다.")

for grad, weight in zip(grads, weights):
    if grad is None:
        raise RuntimeError(
            f"Gradient가 없습니다: {weight.name}"
        )

    tf.debugging.assert_equal(
        tf.shape(grad),
        tf.shape(weight),
        message="Gradient와 변수 Shape가 다릅니다."
    )
    tf.debugging.assert_all_finite(
        grad,
        f"Gradient에 NaN 또는 Inf가 있습니다: {weight.name}"
    )

위 코드는 이미 만든 grads를 검사한다. 소모된 같은 Tape에서 gradient()를 다시 호출하는 코드가 아니다. 이번 Dense 모델의 Gradient·변수 대응을 점검하는 예시이며 새 학습 알고리즘이 아니다.

Data Leakage·성능 개선

측정하지 않은 성능을 추정값으로 채우지 않는다

Data Leakage와 평가 부재

원문은 Test를 Training Dataset에 넣지 않는다. /255.0은 데이터에서 통계를 적합하는 변환이 아니다. 그러나 Test를 불러왔다는 것만으로 독립 평가가 끝난 것도 아니다.

Step 1·2의 추가 실험 원칙

데이터에서 평균·표준편차 등을 학습하는 전처리는 Training에만 fit한다. 설정 선택에는 Validation을 사용하고 최종 Test와 역할을 구분한다. Test 결과를 반복해서 보며 모델·Epoch·학습률을 선택하면 평가 독립성이 약해진다.

Overfitting·Underfitting·Learning Rate 판단
주제 필요한 관찰·원본의 한계
Overfitting 독립 Validation 변화가 필요하지만 원본에 없음
Underfitting 충분한 학습 후 Train·Validation 성능 등을 봐야 하나 집계 없음
수렴·발산 다른 Batch의 열 개 Loss만으로 확정하지 않음
Learning Rate Adam 기본값 설명과 최적값을 찾은 실험은 다름
업데이트 수 Batch를 바꾸면 같은 Epoch의 Step 수가 달라짐
이전 모델과 비교 동일 기준의 평가가 없으므로 이번이 더 낫다고 단정하지 않음
입력·Label·Shape 확인
→
변수·Gradient 연결 확인
→
평가 범위·집계 정의
→
Validation으로 조건 비교
→
최종 Test 평가

Loss가 불안정하면 입력·Loss 설정을 먼저 살피고 학습률 영향을 점검한다. 감소가 느리면 업데이트 수·초기화 상태를 함께 확인한다. 이는 추가 실험의 점검 순서이지, 이 원본에서 오류가 발생했거나 개선에 성공했다는 기록이 아니다.

Q1. Custom Training Loop란?

Batch 반복, Forward, Loss, Gradient, 업데이트를 직접 작성하는 방식이다.

Q2. 이번 모델 구성 API는?

Sequential이다. 모델 구성 방식과 학습 진행 방식은 별개다.

Q3. 왜 compile이 없는가?

Loss·Optimizer 객체를 직접 생성하고 호출하기 때문이다.

Q4. 실제 학습용 Parameter를 바꾸는 줄은?

optimizer.apply_gradients(...)다.

Q5. model(X_batch)가 학습 완료 명령인가?

현재 Parameter의 순전파다. 정답 기반 업데이트는 뒤의 과정이 필요하다.

Q6. tape.gradient가 반환하는 것은?

미분 대상 변수별 Gradient 목록이다.

Q7. Gradient의 Shape는?

각각 대응하는 학습 변수와 같다.

Q8. trainable_weights에 Bias도 있는가?

이번 Dense 모델의 Bias도 포함한다.

Q9. 변수 Tensor 수와 Parameter 수는?

학습 변수 Tensor 네 개, 구조상 수치 Parameter 101,770개다.

Q10. 출력이 확률인가?

아니다. 활성화를 지정하지 않은 Dense10의 Logits다.

Q11. from_logits=True의 의미는?

Loss에 전달된 예측값을 확률 이전 점수로 해석한다.

Q12. Sparse Loss를 쓰는 이유는?

y가 One-Hot이 아니라 0~9 정수 Class Index이기 때문이다.

Q13. 실제 Training 수와 Validation은?

Training 60,000개 전체를 사용하고 Validation은 구성하지 않았다.

Q14. 1 Epoch의 업데이트 수는?

마지막 작은 Batch를 포함하면 계산상 938회다.

Q15. 마지막 Batch Shape는?

X (32,28,28), y (32,)다.

Q16. 왜 로그는 열 줄뿐인가?

모든 Step에서 업데이트하고 0,100,…,900에서만 Loss를 출력하기 때문이다.

Q17. 출력 Loss는 업데이트 후 재계산한 값인가?

아니다. 그 업데이트 전에 계산해 둔 현재 Batch Loss다.

Q18. Step 900의 0.2089는 최종 성능인가?

아니다. Step937까지 학습하고 최종 평균·Test 성능은 따로 집계하지 않았다.

Q19. 이번 원본의 정확도는?

계산·출력하지 않았으므로 저장 자료만으로 알 수 없다.

Q20. Class 선택에 Softmax가 반드시 필요한가?

Logit의 argmax로 Class를 고를 수 있다. 확률 표시에 Softmax를 적용한다.
