01핵심 개념 · 같은 정답, 다양한 모습

같은 고양이를 조금 회전하거나 좌우 반전해도 보통 정답은 고양이입니다. CNN이 사진의 고정된 배치만 외우지 않도록 정답을 유지할 수 있는 변환을 학습에 넣습니다.

왜 배우나요?

새 사진은 위치·방향·촬영 크기가 달라집니다. 이런 변화를 경험하게 하여 일반화에 도움을 주는 것이 목적입니다. 증강이 새로운 실제 개체와 환경을 모두 대신하지는 못합니다.

온라인 증강

원본을 배치로 읽을 때 변환합니다. 원본 파일 수와 train_datasets.n은 2,000으로 유지됩니다. 이번 원본에는 증강본을 따로 저장하는 코드가 없습니다. 

원본 (x, y) → 변환 (T(x), y)

x: 이미지
y: 정답 클래스
T: 회전·이동·반전 등의 변환

이미지 모습은 변경 → 정답은 유지

회전한 고양이
이동한 고양이
반전한 고양이
    ↓
모두 정답은 고양이

변환이 정답을 훼손하면 안 됩니다. 숫자·글자의 회전이나 반전, 동물이 거의 잘려 나가는 확대는 문제에 따라 부적절합니다. 증강은 강할수록 좋은 방법이 아닙니다.

클래스별 수는 교안의 폴더 설명입니다. 로딩 출력은 Train 2,000장·Validation 200장·Test 200장을 확인합니다. 테스트 정답 배열에서도 클래스별 100개가 확인됩니다. 이번 코드에는 새로 데이터를 나누는 train_test_split이 없습니다.

각 데이터의 역할
구분 파일 수 / 배치 역할 무작위 증강
Train 2,000 / 128 가중치 업데이트 적용
Validation 200 / 25 학습 중 성능 확인 미적용
Test 200 / 25 학습 종료 후 평가 미적용

X · 이미지

RGB 픽셀의 숫자 배열입니다. 이미지 한 장은 (128,128,3)입니다.

y · 정답

{'cats': 0, 'dogs': 1}

Sparse는 원-핫 벡터가 아닌 클래스 번호를 뜻합니다. 배치 정답은 (B,)입니다.

전체 X_train, y_train 배열을 미리 만드는 흐름이 아닙니다. DirectoryIterator가 (X_batch, y_batch)를 함께 공급합니다. 클래스 번호는 추측하지 말고 class_indices로 확인합니다.

04전처리 · 증강 규칙을 읽는 법

원문 활성 코드 · 설명 주석 생략

image_generator = keras.preprocessing.image.ImageDataGenerator(
    rescale=1./COLOR_NUMBER_MAX,
    rotation_range=20,
    width_shift_range=0.2,
    height_shift_range=0.2,
    shear_range=0.2,
    zoom_range=0.2,
    horizontal_flip=True
)

test_generator = keras.preprocessing.image.ImageDataGenerator(
    rescale=1./COLOR_NUMBER_MAX
)

val_generator = keras.preprocessing.image.ImageDataGenerator(
    rescale=1./COLOR_NUMBER_MAX
)
무엇을 하나요?
학습·검증·테스트의 변환 규칙을 생성합니다.
왜 필요한가요?
학습 입력의 다양성과 평가 조건을 구분하기 위해서입니다.
입력 Shape
생성 시 실제 이미지 배열을 전달하지 않습니다.
출력 Shape
이미지가 아니라 ImageDataGenerator 설정 객체입니다.
실행 후 변화
규칙이 준비됩니다. 원본 파일 수나 모델 가중치는 바뀌지 않습니다.
원문 증강 설정
설정 의미 주의
rescale=1./255. 픽셀 0~255 → 0~1 정규화이며 정답 y에는 적용하지 않음
rotation_range=20 −20°~+20° 무작위 회전 매번 정확히 20°가 아님
width_shift_range=0.2 너비의 최대 20% 이동 128×0.2=25.6픽셀 범위
height_shift_range=0.2 높이의 최대 20% 이동 보간 때문에 정수 이동만은 아님
shear_range=0.2 전단 각도 −0.2°~+0.2° 원문 11.5° 주석은 단위 오류
zoom_range=0.2 줌 계수 0.8~1.2 두 축의 계수가 다를 수 있음
horizontal_flip=True 무작위 좌우 반전 허용 항상 반전하는 것은 아님

추가 검토 원문은 shear 0.2를 약 11.5°로 설명하지만 이 API는 도 단위입니다. 0.2라디안으로 해석하지 않습니다. 원문 값 0.2는 유지하고 주석을 바로잡습니다. 

이미지 파일
→ 128×128 RGB
→ 무작위 변환
→ /255
→ 배치

Train: 증강 + 정규화
Val:   정규화만
Test:  정규화만

변환 후에도 Shape는 (128,128,3)입니다. 빈 영역은 기본 fill_mode='nearest'로 채워지며 항상 검은색이 아닙니다. 고정 크기로 맞추는 과정에서는 원래 종횡비가 달라질 수 있습니다.

정규화 / 증강 / Shuffle

정규화는 값의 범위, 증강은 이미지 모습, Shuffle은 공급 순서를 바꿉니다. 세 기능을 구별합니다.

두 종류의 fit

현재 설정에는 데이터 통계를 학습하는 전처리가 없어 별도의 image_generator.fit(...)이 필요하지 않습니다. 이것은 가중치를 학습하는 model.fit(...)과 다릅니다.

class_mode='sparse'는 번호 레이블입니다. Train과 Val은 shuffle을 생략했고, Test는 shuffle=False입니다. 테스트 예측과 .labels의 순서를 맞추기 위한 설정입니다.

추가 검토 원문 target_size=(IMAGE_WIDTH,IMAGE_HEIGHT)를 유지했습니다. API의 의미는 (높이, 너비)이며, 현재 둘 다 128이라 차이가 드러나지 않습니다. 비정사각형으로 변경할 때 주의합니다.

06Shape · 반복되는 128을 구분하세요

배치·정답·출력의 대응
구간 X y 모델 출력
학습 일반 배치 (128,128,128,3) (128,) (128,2)
학습 마지막 배치 (80,128,128,3) (80,) (80,2)
검증·테스트 배치 (25,128,128,3) (25,) (25,2)
테스트 전체 예측 배치로 입력 (200,) (200,2)
새 이미지 한 장 (1,128,128,3) 예측 시 없음 (1,2) 
(128, 128, 128, 3)
 배치  높이  너비 채널

2,000 = 128×15 + 80 → 16배치
200 = 25×8         → 8배치
20에폭 × 16배치    → 320회 학습 업데이트

그림을 생성합니다. 모델 학습은 하지 않습니다.

Generator가 정규화하므로 원본 배열을 먼저 /255하지 않습니다. 이미 증강·정규화한 학습 배치를 다시 넣는 예제가 아닙니다. 원본 Notebook에는 이 비교 그림이 저장되어 있지 않습니다.

08Model Architecture · 특징 추출에서 확률까지

원문 활성 코드 · 여러 셀 연결

from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import (
    Conv2D,

    Dense,
    Flatten,
    Input

model = Sequential()

model.add(
    Input(
        shape=(
            IMAGE_HEIGHT,

)

model.add(
    Conv2D(

        kernel_size=(3, 3),

)

model.add(

model.add(

        activation='relu',

model.add(

model.add(Flatten())

model.add(

    )

model.add(

    )
)
무엇을 하나요?
CNN과 분류층을 순서대로 연결합니다.
왜 필요한가요?
픽셀에서 특징을 추출해 클래스를 구분하기 위해서입니다.
입력 Shape
(B,128,128,3)
출력 Shape
(B,2)
실행 후 변화
층과 가중치가 준비됩니다. 아직 데이터로 학습하지 않습니다.
  1. Input(B,128,128,3)
  2. Conv32 + ReLU(B,126,126,32)
  3. MaxPool(B,63,63,32)
  4. Conv16 + ReLU(B,61,61,16)
  5. MaxPool(B,30,30,16)
  6. Flatten(B,14400)
  7. Dense128 + ReLU(B,128)
  8. Dense2 + Softmax(B,2)
  9. argmax(B,) 클래스 번호

Conv의 출력이 이미 Feature Map입니다. Pooling은 그 공간 크기를 줄입니다. ReLU는 Conv 층의 activation에 포함되어 있습니다. 증강은 이 모델 바깥의 iterator에서 수행합니다.

합계 모두 학습 가능 1,849,106

None은 고정되지 않은 배치 크기입니다. Dense128이 전체 파라미터의 약 99.69%를 차지합니다. He 초기화는 두 Conv에만 명시했고 Dense128에는 명시하지 않았습니다. 원문의 sigmoid 1개 출력은 주석 처리된 대안입니다.

왜 필요한가요?

입력 Shape
학습 시 y (B,), 모델 예측 (B,2)
출력 Shape
모델 출력 Shape는 유지됩니다.
실행 후 변화

정답 출력 Loss 클래스 선택
번호 (B,) — 원문 softmax 2개 sparse categorical crossentropy argmax
번호 — 대안 sigmoid 1개 binary crossentropy 임계값 비교
원-핫 (B,2) — 대안 softmax 2개 categorical crossentropy argmax

두 클래스여도 softmax 2개를 사용할 수 있습니다. Sparse는 3개 이상 클래스에만 쓰는 방식이 아닙니다. 정답은 클래스 번호, 출력은 클래스별 확률이라는 조합을 확인합니다. 

정답 클래스 확률 p → 손실 −log(p)

p = 0.9 → 약 0.105
p = 0.5 → 약 0.693
p = 0.1 → 약 2.303

Loss는 1보다 클 수 있고 오답률이 아닙니다. Adam의 0.001은 모든 가중치가 매번 정확히 0.001만큼 변한다는 뜻이 아닙니다. Optimizer는 모델 가중치를 학습하며 증강 범위 자체를 학습하지 않습니다.

15원문과 추가 검토를 구분하기

추가 검토 이 단원에는 별도의 공식 검토 메모가 없습니다. 아래는 원본 코드·저장 출력·API를 대조한 설명입니다. 원문 설정값은 유지하고, 주석의 오류와 보충 제안은 따로 표시합니다.

원문 표현과 정확한 해석
원문 표현·주석 확인할 내용
shear_range=0.2는 약 11.5° 해당 레거시 API는 도 단위입니다. 현재 범위는 약 −0.2°~+0.2°이며 0.2라디안으로 환산하지 않습니다.
target_size=(WIDTH, HEIGHT) API 순서는 (height, width)입니다. 지금은 둘 다 128이라 차이가 숨겨져 있습니다.
원본 이미지는 사용하지 않는다 원본 파일을 읽어 변환·정규화한 배열을 사용합니다. 원본 삭제나 무관한 새 이미지 생성이 아닙니다.

테스트 정확도 71% 저장된 evaluate와 수동 계산 결과는 모두 72%입니다.
100장의 테스트 데이터 예측 실제 테스트 iterator에는 200장이 들어 있습니다.
sparse는 다중 분류에 사용 두 클래스의 softmax 출력에서도 사용할 수 있습니다. 정답 표현·출력층·Loss를 함께 맞춥니다.
배치 조회·이미지 표시 예제 원본에서는 주석 처리되어 있습니다. X_train 변수가 이미 생성되었다고 가정하지 않습니다.

16자주 하는 실수와 성능 문제

Data Leakage · 데이터 누수

원본은 Train, 반전본은 Test에 넣으면 거의 같은 사진으로 평가하게 됩니다. 중복 이미지·같은 개체·연속 촬영 장면도 확인합니다.

원본 기준 분할 → Train에 증강 순서를 지킵니다. 테스트를 반복해서 보며 설정을 고르는 것도 피합니다. shuffle=False는 순서 설정이며 누수 방지 기능은 아닙니다.

평균·표준편차처럼 데이터에서 학습하는 전처리 통계는 Train에서 계산합니다. 고정 상수 /255는 통계를 학습하지 않으므로 분할 전에 적용했다고 자동으로 누수가 되는 것은 아닙니다.

Shape / Dimension · 축의 크기와 개수

모델은 (B,128,128,3)을 기대합니다. (128,128,3)은 배치 축이 없고, (B,128,128,1)은 채널이 다릅니다.

새 이미지에는 expand_dims(x, axis=0)으로 배치 축을 추가합니다. 크기 변경·채널 변환·축 이동을 무조건 reshape로 대신하지 않습니다.

dtype · 자료형과 값 범위

문자열·object 배열, NaN·Inf, 0~255와 0~1의 혼동을 구별합니다. uint8 입력이 자동 변환되어도 픽셀 스케일이 맞지 않으면 예측이 나빠질 수 있습니다.

정규화 대상은 이미지입니다. 레이블에 /255를 적용하지 않습니다. Sparse 배치 dtype은 실수형일 수도 있으므로 클래스 번호 값이 유효한지도 확인합니다.

Overfitting · 과적합

Train은 좋아지는데 Validation이 악화되는 추세를 확인합니다. 데이터 다양성·모델 크기·학습 기간을 점검합니다.

현재 마지막 Train 70.15%, Validation 69%라는 작은 차이만으로 과적합이 완전히 해결되었다고 단정하지 않습니다.

Underfitting · 과소적합

Train과 Validation이 모두 낮으면 학습 부족·표현력 부족·잘못된 전처리·레이블·과도한 증강을 살펴봅니다.

동물이 대부분 잘리는 변형처럼 정답을 훼손하는 증강은 줄여야 합니다. 증강을 강하게 하는 것이 항상 성능 개선은 아닙니다.

Learning Rate · 학습률

너무 크면 Loss가 흔들리거나 수치가 불안정해질 수 있고, 너무 작으면 개선이 느릴 수 있습니다.

NaN의 원인이 반드시 학습률인 것은 아닙니다. 입력·정답·Loss 조합·수치 범위를 먼저 확인합니다. 원문의 0.001이 최적값이라는 증거도 없습니다.

예외 없이 정확도가 틀릴 수 있다: 브로드캐스팅

보충 예제 예측 (N,)과 정답 (N,1)을 비교하면 (N,N)으로 확장될 수 있습니다. 오류가 없더라도 모든 이미지가 일대일로 비교된 것은 아닙니다. 

pred = np.array([0, 1, 0])       # (3,)
truth = np.array([0, 1, 1])      # (3,)

print(np.mean(pred == truth))
# 0.6666...

print((pred == truth[:, None]).shape)
# (3, 3)

print(np.mean(pred == truth[:, None]))
# 0.4444...

assert pred.shape == truth.shape

입력은 예측·정답 클래스 번호, 출력은 비교 배열과 비율입니다. 모델 가중치는 바뀌지 않습니다. 원본의 test_datasets.labels는 (200,)이므로 위 사례와 구분합니다.

argmax의 축도 확인: axis=1은 각 이미지의 클래스를 선택합니다. axis=0은 각 클래스 열에서 값이 가장 큰 이미지 위치를 고르므로 이번 정답 계산과 다릅니다.

print(X_batch.shape, X_batch.dtype)

dtype, Shape, 값 범위는 각각 확인합니다. 숫자형이라는 사실만으로 0~1 정규화가 되었다고 판단하지 않습니다.

전체 정확도 뒤의 오분류 확인

보충 코드 아래 코드는 실제 예측 후 실행합니다. 행은 실제 클래스, 열은 예측 클래스입니다. 저장된 72%만으로 네 칸의 숫자를 복원할 수는 없습니다. 

predicted_classes = np.argmax(y_pred, axis=1)
true_labels = test_datasets.labels

assert predicted_classes.shape == true_labels.shape

confusion = np.zeros((2, 2), dtype=int)

np.add.at(
    confusion,
    (true_labels, predicted_classes),
    1
)

print(confusion)

입력은 예측·정답 각각 (200,), 출력은 혼동행렬 (2,2)입니다. 실행 후 클래스별 오분류가 집계됩니다. 실제 오분류 사진과 필요에 따른 클래스별 Precision·Recall도 확인합니다.

Accuracy와 R²의 용도를 구분하기

Accuracy는 분류의 정답 비율입니다. R²는 회귀에서 평균값 예측 기준과 비교하는 지표입니다. 이번 레이블 0·1은 연속적인 수치 목표가 아니라 클래스를 나타내는 번호이므로 R²로 해석하지 않습니다. 

실제값에 변동이 있는 회귀 문제:

R² = 1 − 예측 오차 제곱합 / 평균 기준 오차 제곱합

1    → 완벽한 예측
0    → 평균값 예측 기준 수준
음수 → 그 기준보다 나쁨

성능 문제를 볼 때 먼저 확인할 것

  • Train·Val 모두 낮음: 전처리·레이블·학습 상태·증강 강도
  • Train만 높음: 과적합·데이터 다양성·모델 크기
  • 특정 클래스만 약함: 클래스별 수량·품질·오분류
  • 추론에서만 성능 저하: 학습과 추론의 전처리 차이
  • 실행마다 결과 차이가 큼: 데이터·난수·환경·평가 표본 수

원본에는 Dropout, EarlyStopping, 학습률 스케줄러가 활성 코드로 들어 있지 않습니다. 이런 방법을 추가한다면 원문과 구분한 실험으로 기록합니다.

배포할 때 함께 기록: 입력 128×128, RGB, /255 정규화, 클래스 매핑, softmax 2개, argmax 규칙, 데이터 분할·환경 버전. 모델 파일만 저장하면 추론 조건을 놓칠 수 있습니다.

19면접 포인트 · 스스로 설명해 보기

1. 데이터 증강의 목적은 무엇인가요?

정답을 유지하는 변형을 통해 다양한 입력 상황을 경험하게 하는 것입니다. 새로운 실제 개체나 모든 촬영 환경을 수집한 것과 같지는 않습니다.

2. 증강하면 이미지 파일 수가 늘어나나요?

이번 온라인 방식에서는 원본 2,000장과 iterator의 n이 그대로입니다. 배치를 읽을 때 변환 배열을 만들며 별도 저장 코드는 없습니다.

3. 두 데이터 객체의 역할은 어떻게 다른가요?

ImageDataGenerator는 변환 규칙을, DirectoryIterator는 이미지·정답 배치 공급을 담당합니다. 모델에는 후자가 전달됩니다.

4. 마지막 배치가 80장이어도 왜 가능한가요?

모델은 이미지 한 장의 크기를 고정했지만 배치 크기는 고정하지 않았습니다. 128장 15배치와 80장 1배치가 한 에폭입니다.

5. 두 클래스에서 softmax를 사용해도 되나요?

가능합니다. 클래스 번호 정답, softmax 2개, sparse categorical crossentropy를 일관되게 사용하면 됩니다.

6. predict 결과는 클래스 번호인가요?

이번 결과는 클래스별 확률 (N,2)입니다. argmax(axis=1)을 적용하면 클래스 번호 (N,)이 됩니다.

7. 테스트 shuffle=False는 왜 필요한가요?

예측 결과를 고정된 labels 배열과 같은 순서로 비교하기 위해서입니다. evaluate처럼 이미지·정답을 함께 처리하는 상황과 구별합니다.

8. Loss와 Accuracy는 무엇이 다른가요?

Accuracy는 최종 선택이 맞았는지, Crossentropy는 정답 클래스에 부여한 확률을 봅니다. 같은 정확도라도 손실은 달라질 수 있습니다.

9. 검증 정확도가 학습 정확도보다 높으면 오류인가요?

항상 그렇지는 않습니다. 학습 입력에만 증강이 적용되고 지표를 계산하는 시점도 다릅니다. 누수 여부는 별도로 확인합니다.

10. 파라미터가 가장 많은 부분은 어디인가요?

Flatten 뒤 Dense 128로 1,843,328개입니다. 전체의 약 99.69%이므로 Conv 필터 수만으로 모델 규모를 판단하면 부족합니다.

11. 증강은 과적합을 항상 해결하나요?

아닙니다. 지나친 변형은 정답을 훼손하거나 학습을 어렵게 만들 수 있습니다. 학습 곡선과 실제 변환 이미지를 함께 확인합니다.

12. 정확도 상승을 증강 효과라고 말할 수 있나요?

이전 단원과 데이터·모델·출력 조건도 달라졌으므로 단정할 수 없습니다. 같은 조건에서 증강 여부만 바꾼 비교가 필요합니다.
