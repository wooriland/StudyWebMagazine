from sklearn.model_selection import GroupShuffleSplit

split_frame = corpus[['Q', 'A']].copy()

# 분할용 그룹 키입니다. 모델의 한국어 전처리를 대체하지 않습니다.
question_groups = (
    split_frame['Q']
    .astype(str)
    .str.replace(r'\s+', ' ', regex=True)
    .str.strip()
)

first_split = GroupShuffleSplit(
    n_splits=1,
    test_size=0.2,
    random_state=42
)

train_idx, holdout_idx = next(
    first_split.split(split_frame, groups=question_groups)
)

train_df = split_frame.iloc[train_idx].copy()
holdout_df = split_frame.iloc[holdout_idx].copy()
holdout_groups = question_groups.iloc[holdout_idx]

second_split = GroupShuffleSplit(
    n_splits=1,
    test_size=0.5,
    random_state=42
)

val_idx, test_idx = next(
    second_split.split(holdout_df, groups=holdout_groups)
)

val_df = holdout_df.iloc[val_idx].copy()
test_df = holdout_df.iloc[test_idx].copy()

Attention — 질문의 어느 위치를 참고할까?

원본 Decoder는 LSTM 출력을 먼저 계산한 다음 Attention을 적용합니다. Context를 현재 LSTM 입력 앞에 추가하는 구조가 아니라, LSTM 출력과 결합해 Dense에 전달하는 구조입니다.

역할이번 TensorShape
QueryDecoder LSTM 출력 x(B,T,256)
KeyEncoder 전체 출력(B,S,256)
ValueEncoder 전체 출력(B,S,256)
CSV의 Q와 Attention의 Query는 다릅니다.

CSV의 Q는 사용자 질문 문자열이고, Attention Query는 Decoder가 계산한 상태 벡터입니다. Keras Attention의 입력 순서는 [query, value, optional_key]이며, Key를 생략하면 Value를 Key로도 사용합니다.

Score → Weight → Context

① Dot-Product Score e(t,i) = s(t) · H(i) (B,T,256) × (B,256,S) → (B,T,S)
② 질문 위치 축으로 Softmax α(t,i) = exp(e(t,i)) / Σⱼ exp(e(t,j)) 각 Decoder 시점에서 질문 위치별 비중을 계산합니다.
③ Value의 가중합 a(t) = Σᵢ α(t,i) × H(i) (B,T,S) × (B,S,256) → (B,T,256)
④ Decoder 출력과 이어 붙이기 z(t) = [s(t); a(t)] 256차원 + 256차원 → 512차원

원본 Attention 호출을 설명하기 위해 수식으로 풀어 쓴 내용입니다. 원본에 직접 구현된 별도 NumPy Attention 셀이 있는 것은 아닙니다. a(t)는 Attention Context를 뜻하며 LSTM Cell State c와 구분합니다.

class Encoder(tf.keras.Model):

    def __init__(self, units, vocab_size, embedding_dim):
        super(Encoder, self).__init__()

        self.embedding = keras.layers.Embedding(
            vocab_size, embedding_dim
        )
        self.dropout = keras.layers.Dropout(0.2)
        self.lstm = keras.layers.LSTM(
            units,
            return_state=True,
            return_sequences=True
        )

    def call(self, inputs, training=None):
        x = self.embedding(inputs)
        x = self.dropout(x, training=training)

        encoder_outputs, hidden_state, cell_state = self.lstm(x)

        return encoder_outputs, [hidden_state, cell_state]

DecoderCell 034 
class Decoder(tf.keras.Model):

    def __init__(self, units, voca_size, embedding_dim):
        super(Decoder, self).__init__()

        self.embedding = keras.layers.Embedding(
            voca_size, embedding_dim
        )
        self.dropout = keras.layers.Dropout(0.2)
        self.lstm = keras.layers.LSTM(
            units,
            return_state=True,
            return_sequences=True
        )
        self.attention = keras.layers.Attention()
        self.dense = keras.layers.Dense(
            voca_size,
            activation='softmax'
        )

    def call(self, inputs, initial_state, training=None):
        encoder_outputs, decoder_inputs = inputs

        x = self.embedding(decoder_inputs)
        x = self.dropout(x, training=training)

        x, hidden_state, cell_state = self.lstm(
            x,
            initial_state=initial_state
        )

        attention_vector = self.attention([x, encoder_outputs])
        x = tf.concat([x, attention_vector], axis=-1)
        x = self.dense(x)

        print(
            '디코더의 현재 타임 스텝의 분류층을 통과한 출력값:',
            x
        )

        return x, hidden_state, cell_state

입력
Encoder 출력, Decoder Token ID, h/c 초기 상태
출력
확률 (B,T,2300), 마지막 Decoder h/c

현재 응답 위치의 확률과 다음 시점에 전달할 상태가 계산됩니다.

Dropout(0.2)은 Embedding 뒤의 별도 계층입니다. 토큰 ID나 Vocabulary의 단어를 삭제하는 연산이 아닙니다. Concat도 원소별 덧셈과 달리 마지막 Feature 축을 이어 붙입니다.

Seq2SeqCell 035 
class Seq2Seq(tf.keras.Model):

    def __init__(
        self, units, voca_size, embedding_dim,
        time_steps, start_token, end_token
    ):
        super(Seq2Seq, self).__init__()

        self.start_token = start_token
        self.end_token = end_token
        self.time_steps = time_steps

        self.encoder = Encoder(units, voca_size, embedding_dim)
        self.decoder = Decoder(units, voca_size, embedding_dim)

    def call(self, inputs, training=None):
        if training:
            encoder_outputs, context_vector = self.encoder(
                inputs['enc_inputs']
            )

            decoder_outputs, _, _ = self.decoder(
                (encoder_outputs, inputs['dec_inputs']),
                initial_state=context_vector
            )

            return decoder_outputs

        else:
            x = inputs
            encoder_outputs, context_vector = self.encoder(x)

            target_seq = np.array(
                [[self.start_token]],
                dtype=np.float32
            )
            results = []

            for i in range(self.time_steps):
                decoder_output, decoder_hidden, decoder_cell = self.decoder(
                    (encoder_outputs, target_seq),
                    initial_state=context_vector
                )

                decoder_output = np.argmax(
                    decoder_output,
                    axis=-1
                ).astype(np.int32)

                decoder_output = decoder_output.reshape((1, 1))
                results.append(decoder_output)

                if decoder_output == self.end_token:
                    break

                target_seq = decoder_output
                context_vector = [decoder_hidden, decoder_cell]

                print(
                    'Seq2Seq+ Attention 디코더 출력(추론):',
                    np.array(results).reshape((1, i+1, 1))
                )

            return np.array(results).reshape((1, len(results), 1))
무엇·왜?
Encoder와 Decoder를 연결하고 학습·자유 생성을 선택합니다.
학습 입력·출력
입력 Dictionary → 확률 (B,20,2300)
추론 입력·출력
질문 (1,20) → 생성 Token ID (1,L,1)
실행 후 변화
학습은 확률을 계산하고, 추론은 토큰과 Decoder 상태를 반복 갱신합니다.
하나의 call()이 서로 다른 형식과 의미를 반환합니다.

학습에서는 확률 Tensor, 추론에서는 정수 Token ID를 반환합니다. 이 때문에 evaluate()나 validation_data를 단순히 추가하면 입력·출력 계약이 충돌할 수 있습니다.

값생성 중 처리
encoder_outputs같은 질문의 출력을 재사용
target_seq방금 선택한 토큰으로 갱신
context_vector방금 계산한 Decoder h/c로 갱신
attention_vector현재 Query를 사용해 매번 다시 계산
results생성 토큰을 누적

원본은 최대 20번 생성하고 EOS가 나오면 중단합니다. Encoder를 매 토큰마다 다시 실행하지 않습니다. 학습 분기에는 생성한 EOS를 검사해 반복문을 중단하는 코드가 없습니다.

def index_to_word(indexs, end_token, tokenizer):
    sentence = ' '.join(
        [
            tokenizer.index_word[index]
            for index in indexs
            if index != end_token and tokenizer.index_word.get(index)
        ]
    )
    return sentence


def predict_preprocessing(sentence, is_will_delete_stopword=False):
    if not is_will_delete_stopword:
        sentence = word_tokenizer.preprocess_korean(
            sentence,
            is_will_delete_stopword
        )

    encoding_vector = word_tokenizer.make_integer_encoding(sentence)
    return encoding_vector


def predict(model, question_inputs):
    results = model(inputs=question_inputs, training=False)
    return results.flatten()


def chatbot(question):

    results = predict(seq2seq, question_inputs)
    results = index_to_word(results, EOS_TOKEN, tokenizer)

97.89%가 말해 주지 않는 것

“새로운 질문의 97.89%에 적절히 응답한다”는 뜻이 아닙니다.

이 수치는 학습 중 토큰 위치의 정답 일치율입니다. 이전 정답을 입력받는 Teacher Forcing 결과이며, 독립 Test 성능이나 자유 생성의 응답 적절성 점수가 아닙니다.

PAD만 맞혀도 높아질 수 있는 가상 정확도

가상 예제 · 실제 PAD 비율을 측정한 것이 아님 20개 위치 중 유효 토큰 5개 + PAD 15개 전부 PAD로 예측하면 단순 정확도 = 15 / 20 = 75%

원본은 PAD 제외를 위한 Mask와 토큰별 가중치를 명시하지 않았습니다. 정확도가 얼마나 영향을 받았는지는 실제 PAD 비율과 예측을 확인해야 합니다. 이 가상 75%를 원본 모델의 실제 기준 성능으로 사용하면 안 됩니다.

유효 토큰 기준의 보충 평가식

non-PAD Accuracy = 유효 위치의 정답 일치 수 / 유효 토큰 수 non-PAD Loss = 유효 위치의 토큰 손실 합 / 유효 토큰 수

EOS는 응답 종료를 학습하는 유효 정답입니다. PAD와 구분하여 평가합니다. sample_weight를 Loss에 적용하는 것과 metrics=['acc']가 자동으로 가중 평가되는 것은 다릅니다. Keras의 weighted_metrics와 Loss Reduction 설정을 확인해야 합니다. 보충: 가중 Metric

R²가 적절하지 않은 이유

Token ID는 임의의 식별 번호입니다. ID 10과 11이 ID 10과 200보다 의미적으로 더 비슷하다는 근거는 없습니다. 사전 번호만 바꾸어도 숫자 오차가 달라지므로, ID를 연속적인 회귀값으로 보고 R²를 계산하는 것은 이 응답 생성 문제의 의미와 맞지 않습니다.

import tensorflow as tf


def evaluate_teacher_forced_tokens(
    model,
    eval_dataset,
    pad_id: int = 0
) -> dict:
    """Eager 실행용 진단. 가중치를 업데이트하지 않습니다."""
    loss_sum = 0.0
    correct_count = 0
    token_count = 0

    for inputs, targets in eval_dataset:
        targets = tf.convert_to_tensor(targets)

        if not targets.dtype.is_integer:
            raise TypeError("Target은 정수 Token ID여야 합니다.")

        tf.debugging.assert_rank(targets, 2)

        encoder_outputs, states = model.encoder(
            inputs['enc_inputs'],
            training=False
        )
        probabilities, _, _ = model.decoder(
            (encoder_outputs, inputs['dec_inputs']),
            initial_state=states,
            training=False
        )

        tf.debugging.assert_equal(
            tf.shape(targets),
            tf.shape(probabilities)[:2]
        )
        tf.debugging.assert_all_finite(
            probabilities,
            "예측 확률에 NaN 또는 Inf가 있습니다."
        )

        token_losses = tf.keras.losses.sparse_categorical_crossentropy(
            targets,
            probabilities,
            from_logits=False
        )

        valid = tf.not_equal(targets, pad_id)
        predictions = tf.argmax(
            probabilities,
            axis=-1,
            output_type=tf.int64
        )
        correct = tf.logical_and(
            valid,
            tf.equal(predictions, tf.cast(targets, tf.int64))
        )

        loss_sum += float(
            tf.reduce_sum(
                tf.where(valid, token_losses, tf.zeros_like(token_losses))
            ).numpy()
        )
        correct_count += int(
            tf.reduce_sum(tf.cast(correct, tf.int64)).numpy()
        )
        token_count += int(
            tf.reduce_sum(tf.cast(valid, tf.int64)).numpy()
        )

    if token_count == 0:
        raise ValueError("평가할 유효 응답 토큰이 없습니다.")

    return {
        "non_pad_loss": loss_sum / token_count,
        "non_pad_accuracy": correct_count / token_count,
        "valid_tokens": token_count
    }

print(report)

19 · INTERVIEW / REVIEW

면접 포인트와 복습 질문

답변을 접고 질문부터 설명해 보세요. 원본의 데이터, Shape, 학습 이유를 함께 말하는 것이 복습 기준입니다.

Q01. 이번 모델의 학습 문제는 무엇입니까?

한국어 질문·발화 Q를 입력받아 응답 A의 토큰 시퀀스를 생성하는 지도 학습입니다.

Q02. label을 삭제했는데 왜 지도 학습입니까?

정답은 label 컬럼이 아니라 A에서 만든 다음 응답 토큰 시퀀스이기 때문입니다.

Q03. Encoder가 반환하는 것은 무엇입니까?

전체 출력 (B,20,256)과 마지막 h/c 각각 (B,256)입니다. 전체 출력은 Attention에, 마지막 상태는 Decoder 초기화에 사용합니다.

Q04. return_sequences와 return_state는 어떻게 다릅니까?

전자는 모든 시점의 출력, 후자는 마지막 상태를 추가 반환합니다. 모든 시점의 Cell State를 반환하는 것은 아닙니다.

Q05. Query, Key, Value는 무엇입니까?

Decoder LSTM 출력이 Query이고 Encoder 전체 출력이 Key와 Value입니다. CSV의 Q는 Query 벡터 자체가 아닙니다.

Q06. Attention Weight와 Softmax 출력은 어떻게 다릅니까?

전자는 질문 위치의 비중, 후자는 출력 어휘의 확률입니다. 이번 학습 Shape은 각각 (B,20,20)과 (B,20,2300)입니다.

Q07. Concat 결과가 512차원이 되는 이유는 무엇입니까?

Decoder 출력 256차원과 Attention Context 256차원을 Feature 축으로 이어 붙이기 때문입니다.

Q08. Teacher Forcing은 답안 유출입니까?

정상적인 Shift에서는 이전 정답 토큰을 입력합니다. 현재 정답을 같은 위치에 복사하거나 미래 응답을 보는 잘못된 학습과 구분합니다.

Q09. 학습과 추론의 입력은 어떻게 다릅니까?

학습은 이전 정답, 추론은 이전 생성 토큰을 입력합니다. 자유 생성은 SOS에서 시작하여 EOS 또는 최대 길이에서 끝납니다.

Q10. Sparse Crossentropy를 사용하는 이유는 무엇입니까?

정답이 One-Hot이 아닌 정수 Token ID이며, 모델이 전체 어휘 확률을 출력하기 때문입니다.

Q11. 97.89%는 실제 응답 정확도입니까?

아닙니다. 원본의 Training Token Accuracy입니다. 독립 Test, PAD 처리, 자유 생성 품질은 별도로 평가해야 합니다.

Q12. PAD 처리는 어디에서 확인해야 합니까?

질문을 처리하는 Encoder, 질문 위치를 참조하는 Attention, 응답 Target의 Loss·Metric을 각각 확인합니다.

Q13. evaluate()를 바로 추가하면 왜 문제가 됩니까?

원본 call()은 학습에서 확률을, 추론에서 정수 시퀀스를 반환합니다. 평가에 필요한 입력·출력 계약과 충돌할 수 있습니다.

Q14. Go.가 전부 0이면 무엇을 알 수 있습니까?

유효한 비영 토큰이 남지 않았다는 사실입니다. 전처리 제거인지 OOV 누락인지는 외부 WordTokenizer를 확인해야 합니다.

Q15. 이 모델이 이전 대화를 기억합니까?

원본에는 대화 이력을 입력에 누적하는 기능이 없습니다. 현재 응답의 상태 유지와 여러 대화 턴의 기억은 다릅니다.

Q16. R²로 Token ID를 평가하면 왜 적절하지 않습니까?

ID는 임의의 번호라 숫자 차이가 의미적 거리를 뜻하지 않습니다. 사전 번호만 바꾸어도 수치 오차가 달라집니다.

Q17. 공통 사전이면 Embedding도 공유합니까?

원본은 두 Embedding 객체를 각각 생성합니다. 사전은 같아도 임베딩 가중치는 별도로 학습됩니다.

Q18. 다음 단원에서 특히 이어갈 개념은 무엇입니까?

Attention, 입력 위치 정보, PAD 처리, 미래 응답 차단, Shift 학습과 순차 생성입니다. 다음은 ML 62 Transformer 기계번역입니다.
