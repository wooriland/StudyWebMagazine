01핵심 개념 · 특징은 가져오고 판단은 새로 학습

사진 한 장을 고양이 또는 개로 분류합니다. 이번 구현은 원핫 정답 + Dense 2 Softmax + categorical cross-entropy를 사용합니다. 두 클래스 문제라고 해서 반드시 Dense 1 Sigmoid로 구성해야 하는 것은 아닙니다.

왜 전이학습을 하나요?

큰 데이터에서 배운 경계·질감·형태 등의 특징을 새 문제의 출발점으로 활용합니다. 모델 전체를 처음부터 학습하는 대신 학습 대상 파라미터를 줄일 수 있습니다.

무엇을 학습하나요?

MobileNet V1 기반 모델은 고정하고 새 Dense 두 층만 학습합니다. 기반 모델의 가중치까지 다시 학습하는 미세조정은 원문의 활성 코드에 없습니다.

역할이 다른 핵심 설정
용어·설정 역할 이번 적용
사전학습 다른 데이터로 이미 학습한 가중치 사용 ImageNet 가중치
include_top=False 기존 분류 부분 제외 ImageNet 분류 부분 제거
trainable=False 가중치 업데이트 대상에서 제외 기반 모델 모든 층 고정
전이학습 기존 특징을 새 과제에 활용 고양이·개 분류층 학습
미세조정 기반 층 일부·전체도 추가 학습 실행하지 않음
추론 현재 가중치로 예측 계산 학습 후 predict

MobileNet V1은 채널별 공간 패턴을 처리하는 Depthwise Convolution과 채널 정보를 결합하는 1×1 Pointwise Convolution을 활용하는 경량 CNN입니다. 이번에는 내부 연산을 직접 구현하지 않고 준비된 모델을 특징 추출기로 사용합니다.

동결은 계산 생략이 아닙니다. 고정된 MobileNet도 이미지의 특징을 계산합니다. 달라지는 것은 Optimizer가 그 가중치를 업데이트하지 않는다는 점입니다. ML 36의 기존 1,000클래스 추론과 달리, 이번에는 정답 y를 사용해 새 두 클래스 분류층을 학습합니다.

Dataset 한 원소는 이미 배치입니다.
X: (100,224,224,3), y: (100,2)
여기에 .batch(100)을 추가하면 중복 배치 축이 생길 수 있습니다.

원문의 lambda는 같은 iterator를 반환합니다. 매 호출마다 새 공급원을 만드는 코드가 아닙니다. 점검용 next(iter(train_dataset))도 반복 상태와 난수를 소비할 수 있습니다. 정확한 재현은 데이터 객체를 새로 만들고 순서대로 실행하여 확인합니다.

target_size의 API 의미는 (높이, 너비)입니다. 원문 Test·Validation은 (WIDTH, HEIGHT)이지만 두 값이 모두 224여서 현재 결과 차이가 없습니다. Keras의 evaluate는 이미지·정답 쌍으로 평가하므로 shuffle=True라는 이유만으로 항상 틀리는 것은 아닙니다. 외부 labels와 행별로 비교할 때 순서 일치가 중요합니다.

07Model Architecture · 고정된 기반 모델 + 새 Dense

def create_model():
    base_model = MobileNet(include_top=False,input_shape=(IMAGE_HEIGHT,IMAGE_WIDTH,IMAGE_CHANNEL))
    for layer in base_model.layers:
        layer.trainable=False
        print(f'레이어명:{layer.name}')
    input = Input(shape=(IMAGE_HEIGHT,IMAGE_WIDTH,IMAGE_CHANNEL))
    base_model_output=base_model(input)
    flattening_output=GlobalAveragePooling2D()(base_model_output)
    print('모바일넷의 추가한 새 분류층 직전의 출력 텐서:',flattening_output)
    hidden_output=Dense(units=64,activation='relu')(flattening_output)
    output = Dense(IMAGE_CLASS,activation='softmax')(hidden_output)
    return tf.keras.models.Model(inputs=input,outputs=output)

MobileNet 내부는 여러 합성곱·BatchNormalization·활성화 연산을 포함합니다. 위 흐름은 중요한 입출력을 요약한 것으로, 모든 내부 층을 하나씩 표시한 것은 아닙니다.

R²를 분류 번호에 적용하지 않기

R²는 연속값 회귀에서 1 − SSE/SST로 사용하는 지표입니다. SSE = Σ(y − ŷ)²는 예측 오차 제곱합이고, SST = Σ(y − ȳ)²는 정답과 정답 평균의 차이 제곱합입니다. 실제 정답에 변동이 있는 일반적인 경우 1은 완벽한 예측, 0은 평균값 예측 수준, 음수는 그보다 나쁜 결과를 뜻합니다. 클래스 번호는 수치적 크기·거리 의미를 가진 연속값이 아니므로 이번 분류의 주 평가 지표로 사용하지 않습니다. 원본에는 R² 계산이 없습니다.

Loss는 정답에 준 확률, Accuracy는 클래스 선택의 정답 비율, 개별 점수는 특정 이미지의 클래스 확률입니다. 같은 말로 바꾸어 읽지 않습니다. 99.5%만으로 클래스별 Recall이나 서비스 성능까지 확인한 것은 아닙니다.

원문이 tensorflow.keras.applications.mobilenet.MobileNet을 가져옵니다. MobileNetV2가 아닙니다.

Q5. weights를 생략했는데 왜 사전학습인가요?

MobileNet의 기본 가중치 설정이 ImageNet이기 때문입니다.

Q6. 입력이 왜 4차원인가요?

높이·너비·채널 앞에 이미지 수를 나타내는 배치 축이 필요합니다.

Q7. GAP와 Flatten은 어떻게 다른가요?

Flatten은 값을 펼치고 GAP는 채널별 공간 평균을 구합니다. 이번에는 (B,7,7,1024)가 (B,1024)가 됩니다.

Q8. 실제 학습 파라미터 수는?

새 Dense 두 층의 65,730개입니다. 기반 3,228,864개는 고정합니다.

Q9. 두 클래스에 categorical cross-entropy를 써도 되나요?

정답이 원핫(B,2)이고 출력이 Dense 2 Softmax이면 맞는 조합입니다.

Q10. 배치 y와 labels의 Shape가 다른 이유는?

학습에는 원핫(B,2), 수동 비교에는 전체 정수 정답(N,)을 사용하기 때문입니다.

Q11. from_generator가 배치를 새로 만드나요?

이번 원문에서는 이미 배치화된 DirectoryIterator를 감쌉니다. TensorSpec이 batch나 resize를 수행하지 않습니다.

Q12. steps_per_epoch=20은 무엇인가요?

한 epoch에서 배치 20개를 소비합니다. 전체 데이터를 20회 반복한다는 뜻이 아닙니다.

Q13. 데이터가 적으면 repeat가 필수인가요?

아닙니다. 공급원의 종료·반복 방식과 길이 인지 여부를 봐야 합니다.

Q14. 검증 성능이 훈련보다 좋을 수 있나요?

훈련 증강, 집계 시점, 데이터 난이도 차이가 원인일 수 있습니다. 지표 대소만으로 오류를 확정하지 않습니다.

Q15. Loss와 Accuracy의 차이는?

Accuracy는 클래스 선택의 정답 여부, Loss는 정답 클래스에 부여한 확률도 반영합니다.

Q16. 99.5%는 무엇을 뜻하나요?

해당 테스트 200장의 정확도로 199장 정답에 해당합니다. 한 이미지의 예측 확률이 아닙니다.

Q17. 테스트 shuffle=False가 중요한 이유는?

예측 행을 외부 정답 배열 labels와 순서대로 비교하기 위해서입니다.

Q18. decode_predictions를 사용하지 않는 이유는?

새 두 클래스는 ImageNet 출력 순서가 아니므로 class_indices로 이름을 연결합니다.

Q19. 동결 해제 후 바로 fit하면 되나요?

학습 대상을 바꿨다면 재컴파일해야 합니다. 학습률과 BatchNormalization 상태도 검토합니다. 원본은 미세조정을 수행하지 않습니다.

Q20. 클래스 번호에 R²를 적용하지 않는 이유는?

번호가 연속적인 크기·거리 의미를 갖지 않으며 현재 과제는 분류 성능을 평가해야 하기 때문입니다.

처리 규칙 ↔ 배치 공급원
ImageDataGenerator는 규칙, DirectoryIterator는 실제 배치 공급 객체입니다.
None ↔ 실제 배치 100
None은 가변 규격이고 100은 현재 설정의 일반 배치 크기입니다.
원핫 ↔ 정수 라벨
학습 y는 (B,2), 수동 비교용 labels는 (N,)입니다.
분류층 제거 ↔ 동결

동결 ↔ 추론 모드

Step ↔ Epoch
한 배치 처리와 정해진 여러 배치의 학습 구간입니다.
Loss ↔ Accuracy ↔ 예측 점수

마지막 모델 ↔ 최적 검증 모델
원본은 최적 가중치를 자동 복원하지 않습니다.
과거 summary ↔ 실제 학습 모델
주석 셀의 1,000클래스 출력과 새 2클래스 모델을 구분합니다.
