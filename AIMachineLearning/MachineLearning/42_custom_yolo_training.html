정답 객체 축

얼굴 3개 → 라벨 3행. 얼굴 1개 → 라벨 1행. 여러 이미지의 정답을 단순히 (B, 5)로 가정하지 않습니다.

dtype의 역할

파일명은 문자열, 클래스 ID는 정수 의미, 좌표는 실수입니다. 라벨 배열이 실수 dtype이어도 첫 열은 정수 값이어야 합니다.

height, width = image.shape[:2]처럼 배열의 첫째 축은 높이입니다. 단일 객체 TXT를 읽으면 객체 축이 사라질 수 있으므로 (1, 5)인지 확인합니다. 비어 있는 정답은 개념적으로 (0, 5)입니다.

COORDINATES · PIXELS

04. 전처리 — VOC xyxy → YOLO xywh

VOC는 왼쪽 위와 오른쪽 아래 모서리의 픽셀 좌표를 저장합니다. YOLO TXT는 중심과 크기를 원본 이미지 크기로 정규화하여 저장합니다. 

(xmin, ymin) ●──────────────┐
             │      ×       │  × = 중심 (cx, cy)
             │              │
             └──────────────● (xmax, ymax)

cx = (xmin + xmax) / (2 × W)
cy = (ymin + ymax) / (2 × H)
w  = (xmax - xmin) / W
h  = (ymax - ymin) / H

라벨 정규화

박스 좌표를 원본 W/H로 나눕니다. imgsz=640으로 나누지 않습니다. 클래스 ID는 정규화하지 않습니다.

이미지 전처리

로더가 이미지 읽기, 증강, 리사이즈·패딩, 채널·Tensor 정리, 픽셀 스케일 조정을 수행합니다. 기하학적 변환은 박스에도 함께 반영되어야 합니다.

박스 함수는 픽셀 밝기를 바꾸지 않습니다. OpenCV 이미지의 BGR/HWC와 모델의 RGB/BCHW도 구분합니다. 원문처럼 고수준 API에 이미지를 전달할 때는 내부 처리를 이해하고 이중 정규화·잘못된 채널 변환을 피합니다.

원문 좌표 함수에는 유효성 검사가 없습니다. W/H 양수, xmax>xmin, ymax>ymin, 이미지 범위를 확인합니다. 경계 포함 규약을 확인하지 않고 +1 또는 -1을 임의로 추가하지 않습니다.

전체의 10%를 Test로 떼고, 남은 데이터의 20%를 Validation으로 나누므로 약 72:18:10입니다. 80:10:10이 아닙니다. 원문에는 stratify가 없습니다.

객체 행을 나누면 안 되는 이유: 같은 사진의 얼굴 A는 Train, 얼굴 B는 Validation으로 들어갈 수 있습니다. 원문은 filename.unique()로 이미지 단위 분할을 합니다. 다만 이름이 다른 복제 이미지, 같은 영상의 인접 프레임까지 막아 주지는 않습니다.
  • 동일·유사 장면은 영상·촬영 그룹 단위 분할을 검토합니다.
  • 원문은 기존 출력 폴더를 비우지 않습니다. 분할을 바꿔 재실행하면 이전 파일이 남을 수 있습니다.
  • 파일명 집합뿐 아니라 디스크의 실제 파일 목록과 라벨 대응도 확인합니다.
  • 원문의 glob 목록은 정렬하지 않았습니다. seed가 같아도 입력 순서가 바뀌면 분할이 달라질 수 있습니다.
  • confidence·모델·증강 설정을 Test 결과를 보며 반복 선택하면 평가 정보가 새어 들어갑니다.

for annotation_path in annotation_paths:
    tree = ET.parse(annotation_path)
    root = tree.getroot()
    filename = root.find('filename').text

    for obj in root.findall("object"):
        label = obj.find("name").text
        bbox = []

        bndbox_tree = obj.find('bndbox')
        bbox.append(int(bndbox_tree.find('xmin').text))
        bbox.append(int(bndbox_tree.find('ymin').text))
        bbox.append(int(bndbox_tree.find('xmax').text))
        bbox.append(int(bndbox_tree.find('ymax').text))

        size = root.find('size')

        pascal_data['filename'].append(filename)
        pascal_data['width'].append(int(size.find('width').text))
        pascal_data['height'].append(int(size.find('height').text))
        pascal_data['label'].append(label)
        pascal_data['class_id'].append(classes[label])
        pascal_data['bboxes'].append(bbox)

def pascal_to_yolo_bbox(bbox, w, h):
    x_min, y_min, x_max, y_max = bbox
    x_center = ((x_max + x_min) / 2) / w
    y_center = ((y_max + y_min) / 2) / h
    width = (x_max - x_min) / w
    height = (y_max - y_min) / h
    return [x_center, y_center, width, height]

    for image in images:

from pathlib import Path
import numpy as np

def inspect_yolo_label(label_path, class_count=3, tolerance=1e-6):
    path = Path(label_path)

    if not path.is_file():
        raise FileNotFoundError(f"라벨 누락: {path}")

    rows = []

    for line_number, line in enumerate(
        path.read_text(encoding="utf-8-sig").splitlines(), start=1
    ):
        if not line.strip():
            continue

        tokens = line.split()

        if len(tokens) != 5:
            raise ValueError(f"{line_number}행: 값 5개가 필요합니다.")

        rows.append([float(token) for token in tokens])

    labels = np.asarray(rows, dtype=np.float64).reshape(-1, 5)

    if len(labels) == 0:
        print("빈 라벨: 실제 배경 이미지인지 별도 검수하세요.")
        return labels

    if not np.isfinite(labels).all():
        raise ValueError("NaN 또는 Inf가 있습니다.")

    ids, boxes = labels[:, 0], labels[:, 1:]

    if not np.equal(ids, np.floor(ids)).all():
        raise ValueError("클래스 ID는 정수여야 합니다.")

    if ((ids < 0) | (ids >= class_count)).any():
        raise ValueError("클래스 ID 범위 오류")

    if ((boxes < -tolerance) | (boxes > 1 + tolerance)).any():
        raise ValueError("정규화 좌표 범위 오류")

    cx, cy, w, h = boxes.T

    if ((w <= 0) | (h <= 0)).any():
        raise ValueError("너비와 높이는 양수여야 합니다.")

    corners = np.column_stack([
        cx - w / 2, cy - h / 2, cx + w / 2, cy + h / 2
    ])

    if ((corners < -tolerance) | (corners > 1 + tolerance)).any():
        raise ValueError("박스가 이미지 밖에 있습니다.")

    return labels

먼저 줄당 값 5개를 검사한 뒤 reshape합니다. 그렇지 않으면 한 줄의 값 10개가 두 객체로 조용히 바뀔 수 있습니다. 출력은 (N_i, 5), 한 객체는 (1, 5), 빈 파일은 (0, 5)입니다. 이 검사는 실제 얼굴 위치나 클래스 의미의 정답 여부까지 판정하지 않습니다.

REVIEW · Q&A

15. 면접 포인트 — 질문을 눌러 답 확인

Q1. 이번 입력 X와 정답 y는?

X는 이미지, y는 객체별 클래스와 박스입니다. 이미지마다 객체 수가 다릅니다.

Q2. VOC 형식이면 VOC 20클래스를 배우나요?

아닙니다. 저장 형식과 실제 데이터의 클래스는 별개입니다. 이번에는 마스크 3클래스입니다.

Q3. 853장인데 왜 4,072행인가요?

한 행은 이미지가 아니라 객체 하나입니다. 같은 이미지에 여러 행이 대응합니다.

Q4. X_train.shape=(613,)의 의미는?

이미지 파일명 613개입니다. 픽셀 Tensor도, Feature 613개도 아닙니다.

Q5. YOLO TXT 한 줄의 다섯 값은?

클래스 ID, 정규화된 중심 x·y, 너비, 높이입니다.

Q6. 왜 640으로 좌표를 나누면 안 되나요?

원본 픽셀 좌표이므로 원본 이미지 W/H로 정규화해야 합니다.

Q7. 왜 이미지 단위로 분할하나요?

같은 이미지의 객체들이 서로 다른 분할에 들어가는 누수를 피하기 위해서입니다.

Q8. 원문의 분할 비율은?

전체 Test 10%, 남은 자료의 Validation 20%이므로 약 72:18:10, 실제 613/154/86장입니다.

Q9. 파일명을 분리하면 누수는 완전히 없나요?

복제 이미지, 인접 프레임, 이전 분할 잔존 파일은 별도로 검사해야 합니다.

Q10. YAML과 TXT는 어떻게 다른가요?

YAML은 경로·클래스 안내서이고 TXT는 이미지별 실제 객체 정답입니다.

Q11. compile()과 fit()이 없는 이유는?

Ultralytics Trainer가 학습 준비와 반복을 담당하며 model.train()을 사용합니다.

Q12. 실제 Optimizer와 학습률은?

원본 auto 로그는 AdamW, 초기 LR 0.001429입니다. 덤프의 0.01과 구분합니다.

Q13. 세 Loss의 역할은?

box는 박스 일치, cls는 클래스 예측, dfl은 박스 경계 위치 분포 학습입니다.

Q14. Train Loss가 낮으면 일반화가 좋은가요?

보장되지 않습니다. 독립 Validation 추이·클래스별 오류·최종 Test를 확인합니다.

Q15. best.pt와 last.pt의 차이는?

best는 검증 기준 최적 체크포인트, last는 마지막 시점입니다. 최종 파일의 Optimizer 보존 여부도 확인합니다.

Q16. mAP50 약 0.912는 Test 성능인가요?

아닙니다. 원본 best 모델의 Validation 154장 결과입니다.

Q17. Precision과 Recall의 차이는?

Precision은 예측 중 맞춘 비율, Recall은 정답 중 찾아낸 비율입니다.

Q18. mAP50-95가 더 엄격한 이유는?

IoU 0.95까지의 더 높은 위치 일치 기준을 포함하기 때문입니다.

Q19. confidence 0.9는 Accuracy 90%인가요?

아닙니다. 개별 탐지 점수이며 전체 성능이나 보정된 정답 확률과 다릅니다.

Q20. 평가 IoU와 NMS IoU의 차이는?

전자는 예측과 정답을 비교하고 후자는 예측끼리 비교하여 중복을 줄입니다.

Q21. results 재사용의 위험은?

학습 DetMetrics가 추론 list[Results]로 바뀌므로 속성과 접근 방식이 달라집니다.

Q22. 원본은 Test 앞의 두 장을 추론하나요?

아닙니다. 조회는 [:2]이지만 실제 입력은 첫 번째와 마지막입니다.

Q23. image0.jpg는 Custom 학습의 특징인가요?

아닙니다. 이번 NumPy 입력에는 원본 파일 경로가 없어서 생성된 이름입니다.

Q24. 라벨 값이 0~1이면 충분한가요?

ID·양수 크기·모서리 범위와 실제 박스 위치·클래스 의미를 더 확인해야 합니다.

Q25. 다음 단원의 핵심은?

저장된 best.pt를 로드하여 검증·새 이미지 추론·표시·CSV/JSON 활용을 수행합니다.

CONFUSION

헷갈리기 쉬운 개념

이미지 수 ≠ 객체 수
한 장에 여러 객체가 있습니다.
파일명 배열 ≠ 이미지 Tensor
(613,)을 BCHW와 혼동하지 않습니다.
라벨 정규화 ≠ 픽셀 정규화
변환 대상과 분모가 다릅니다.
Validation ≠ Test
선택용 자료와 최종 평가용 자료를 구분합니다.
predict ≠ train
추론에서는 가중치를 학습하지 않습니다.
빈 라벨 ≠ 라벨 누락
검수된 배경인지 정답을 빠뜨렸는지 확인합니다.
탐지 ≠ 추적
같은 사람의 프레임 간 연결은 별도 문제입니다.
