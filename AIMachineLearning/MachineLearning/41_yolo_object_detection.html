PROBLEM · CORE CONCEPT

01. 실습 목표 — 사진 속 무엇이 어디에 있는가?

이전의 이미지 분류는 사진 전체에 하나의 이름을 붙였습니다. 객체 탐지는 한 사진 안의 여러 객체마다 클래스와 위치를 함께 구하는 문제입니다. 사무실 사진에서 사람·의자·화분·TV를 찾고, 도로 사진에서 자동차를 찾는 것이 이번 실습입니다.

분류 Classification

입력: 사진 한 장 → 출력: 이미지 전체의 클래스.

예: “이 사진은 개입니다.”

탐지 Object Detection

입력: 사진 한 장 → 출력: 객체별 박스 + 클래스 + 신뢰도.

예: “이 위치에 사람 2명, 저 위치에 의자 2개가 있습니다.”

YOLO = You Only Look Once. 이미지를 신경망에 통과시켜 여러 위치의 객체 후보를 예측하는 단일 단계 탐지 계열입니다. 전처리와 후처리까지 없어지는 것은 아닙니다.

  • YOLO('yolo11m.pt')로 사전학습 모델을 불러옵니다.
  • model.predict()로 두 사진을 추론하고, 이미지별 Results를 해석합니다.
  • boxes.cls / conf / xyxy / xywh의 의미와 Shape를 구분합니다.
  • 저장 그림과 수치 결과를 읽고, 신뢰도와 실제 평가 성능이 다른 이유를 설명합니다.
이 단원의 범위: 이미 학습된 가중치를 사용하는 추론 실습입니다. 학습 데이터 준비, 정답 라벨 작성, compile(), fit(), train(), evaluate(), val()은 실행하지 않습니다. 추론으로 모델 가중치가 학습되는 것도 아닙니다.

03. X / y와 Shape — 이미지 수와 객체 수는 다르다

images는 문자열을 담은 Python 리스트이므로 images.shape가 없습니다. len(images) == 2는 사진이 2장이라는 의미입니다. 기본 추론 결과도 리스트이며 len(results) == 2입니다.

원문에 저장된 Shape와 해석
대상 Shape / 길이 각 축의 의미
경로 목록 images len = 2 사진 경로 2개. 배열 Shape가 아닙니다.
사무실 orig_img (183, 275, 3) 높이 183, 너비 275, BGR 3채널. uint8.
도로 orig_img (168, 300, 3) 높이 168, 너비 300, BGR 3채널. uint8.
저장 로그의 모델 입력 (1, 3, 640, 640) batch, channel, height, width. 원본 사진 Shape와 다릅니다.
사무실 boxes.xyxy / xywh (6, 4) 저장 수치 결과: 탐지 6개 × 좌표 4개.
사무실 boxes.cls / conf (6,) 객체마다 클래스 1개, 신뢰도 1개.
도로 boxes.xyxy / xywh (11, 4) 저장 수치 결과: 탐지 11개 × 좌표 4개.
도로 boxes.cls / conf (11,) 객체별 11개 값.
객체 하나의 box.xyxy (1, 4) box.xyxy[0]을 선택하면 (4,).
정답 y 없음 y.shape도 정의하지 않습니다.
고정된 값과 실행 결과를 구분: 6개·11개는 저장된 수치 출력의 탐지 개수입니다. 모델 버전, 입력 파일, 임계값 등에 따라 다시 실행한 개수는 달라질 수 있습니다. 그림 파일의 픽셀 크기를 모델 입력 Shape로 읽으면 안 됩니다. (1,3,640,640)은 저장된 속도 요약의 표기이며, 두 사진 전체의 실제 내부 배치 크기를 직접 출력한 값은 아닙니다.

좌표 형식 4가지를 함께 읽기

Boxes 좌표 표기
속성 값의 순서 단위
xyxy x1, y1, x2, y2: 왼쪽 위와 오른쪽 아래 원본 이미지의 픽셀 좌표
xywh cx, cy, w, h: 중심점과 너비·높이 원본 이미지의 픽셀 좌표
xyxyn 정규화된 두 모서리 x는 원본 W, y는 원본 H로 나눔
xywhn 정규화된 중심과 크기 cx·w는 W, cy·h는 H로 나눔 
w = x2 - x1                 h = y2 - y1
cx = (x1 + x2) / 2           cy = (y1 + y2) / 2

정규화: cx/W, cy/H, w/W, h/H

첫 번째 사람 박스 원문 xyxy ≈ [192.5087, 67.7866, 236.9896, 164.1515]를 바꾸면 xywh ≈ [214.7491, 115.9691, 44.4809, 96.3649]입니다. 원본 W=275, H=183으로 나눈 값은 약 [0.7809, 0.6337, 0.1617, 0.5266]입니다. 640으로 나누지 않습니다.

PREPROCESS · COLOR · DTYPE

04. 전처리 — 경로를 모델 입력으로 바꾸는 과정

원문은 이미지 경로를 predict()에 전달하므로 라이브러리가 전처리를 처리합니다. 이미지 배열을 직접 임의로 펼치거나, 경로 입력에 별도 /255를 적용하는 코드가 필요하지 않습니다.

  1. 파일 읽기 NumPy HWC · BGR · uint8
  2. Letterbox 종횡비를 유지해 크기 조절, 필요한 여백 추가
  3. 채널·축 변환 BGR → RGB, HWC → CHW
  4. 배치 구성 사진 축을 붙여 BCHW
  5. 자료형·범위 변환 모델용 부동소수점, 일반적으로 0~1
  6. 장치로 전달 CPU 또는 사용 가능한 GPU

위 흐름은 이 Notebook처럼 경로를 전달한 경우의 설명입니다. 이미 준비한 Tensor를 직접 전달할 때는 요구되는 축·채널·범위를 사용자가 맞춰야 합니다. PIL 입력은 RGB, 일반 NumPy 이미지 입력은 BGR이라는 차이도 확인합니다.

imgsz의 일반적인 기본값은 640입니다. 원문 저장 로그에서는 두 이미지가 640×640으로 처리되었습니다. 실제 전처리 크기는 직사각형 패딩 옵션, 배치 구성, 모델 조건 등에 따라 달라질 수 있으므로 항상 정사각형이라고 단정하지 않습니다.

표시용과 모델용을 구분: result.orig_img와 기본 result.plot() 결과는 BGR 배열입니다. Matplotlib에 넣을 때 [:, :, ::-1]로 채널을 뒤집어 RGB로 표시합니다. 이 연산은 좌우 반전이 아니며 (H, W, 3) Shape도 변하지 않습니다. PIL.Image.open()으로 연 RGB 그림에는 같은 변환을 다시 적용하지 않습니다.

SPLIT · DATA LEAKAGE

05. Train / Validation / Test — 이번에는 분할하지 않는다

이번 사진 2장은 추론 결과를 확인하는 입력입니다. 정답이 있는 정식 Test Set이라고 부르기에는 평가 절차가 없습니다. 모델이 과거 학습한 COCO 자료와 현재 사진의 중복 여부도 이 Notebook만으로 확인할 수 없습니다.

학습 실험을 확장할 때의 세 역할
구분 사용 목적 이번 단원
Train 정답을 이용해 가중치를 갱신 구성하지 않음
Validation 모델·학습 설정·추론 임계값 선택 구성하지 않음
Test 선택을 끝낸 모델의 최종 성능 확인 정답 기반 평가는 하지 않음

Data Leakage를 막으려면

  • 같은 사진의 객체 행을 따로 분할하지 않습니다. 한 이미지의 사람은 Train, 같은 이미지의 의자는 Test에 들어가면 이미지 정보가 겹칩니다.
  • 동영상의 연속 프레임·복제 이미지·비슷한 촬영 장면은 묶어서 분할합니다. 배포 목적에 따라 영상·장면·카메라·촬영 시점을 분리 단위로 정합니다.
  • Test 성능을 보면서 conf와 iou를 반복 조정하면 Test에 맞춘 선택이 됩니다. 설정 선택은 Validation에서 합니다.
  • 증강한 복사본이 분할을 넘어 섞이지 않도록 원본을 먼저 나눕니다.
  • YOLO가 만든 예측 박스를 그대로 정답으로 삼아 같은 예측을 평가하지 않습니다. 정답 라벨은 별도 검수가 필요합니다.

MODEL · YOLO11

06. Model Architecture — 특징에서 객체별 박스로

yolo11m.pt에서 11은 모델 계열, m은 medium 크기 변형, .pt는 가중치 파일 확장자입니다. n / s / m / l / x는 크기 변형입니다. 크기가 커질 때 연산·메모리 요구가 늘어나는 경향이 있으나, 실제 속도와 정확도는 장치·입력·데이터에서 측정해야 합니다.

  1. Image 전처리한 BCHW 입력
  2. Backbone 윤곽·질감·형태 등의 특징 추출
  3. Neck 서로 다른 해상도의 특징 결합
  4. Detection Head 객체 위치와 클래스 후보 예측
  5. 후처리 신뢰도 필터 · NMS · 원본 좌표 복원
  6. Results 이미지별 Boxes와 부가 정보

위는 이해를 위한 기능별 흐름입니다. 이미지 분류기의 Flatten → Dense → 단일 클래스 구조를 그대로 적용한 도식이 아닙니다. 객체 탐지는 여러 위치와 크기의 객체를 함께 다룹니다.

모델의 작업 종류
파일 형태 예시 주요 작업 대표 결과
yolo11m.pt 객체 탐지 boxes
yolo11m-seg.pt 인스턴스 분할 boxes, masks
yolo11m-pose.pt 키포인트 추정 boxes, keypoints
yolo11m-obb.pt 회전 박스 탐지 obb
yolo11m-cls.pt 이미지 분류 probs

이번 결과의 probs / masks / keypoints / obb가 None인 것은 해당 작업의 출력이 없다는 뜻입니다. 탐지 신뢰도는 boxes.conf에서 읽습니다.

7-10. cpu → detach → numpy → tolist 읽는 법

원문 변환 체인
연산 의미 이번 실습에서의 주의
.cpu() 텐서를 CPU 메모리에서 다루도록 이동 GPU 텐서를 기본 .numpy()로 변환하려면 필요합니다.
.detach() 자동 미분 추적에서 분리한 텐서 반환 기울기가 필요한 텐서의 NumPy 변환에 사용합니다. 추론 출력에는 보통 기울기 추적이 없습니다.
.numpy() Tensor를 NumPy 배열로 변환 장치와 기울기 상태 등 변환 조건을 확인합니다.
.tolist() NumPy 배열을 Python 리스트로 변환 원문에서는 앞 단계가 NumPy이므로 NumPy의 메서드입니다.
원문 설명용 문자열 보완

‘모든 tolist는 CPU 변환을 직접 해야 한다’는 설명은 정확하지 않습니다. PyTorch의 Tensor.tolist()는 필요하면 내부적으로 CPU로 옮깁니다. 원문의 변환 체인은 유효하지만, 이 두 종류의 tolist()를 구별해야 합니다.

image_path.split('/')[-1]은 원문의 슬래시 경로에서 파일명을 구합니다. 다른 환경에서는 Path(image_path).name처럼 경로 도구를 쓰는 보완을 고려할 수 있습니다. 저장 폴더는 추정하지 말고 result.save_dir로 확인합니다.

타입·좌표·시각화: Results 문서. 변환의 구분: Tensor.numpy, Tensor.tolist.

10. Metric 해석 — conf, IoU, mAP는 서로 다르다

신뢰도 0.8357은 평가 정확도 83.57%가 아닙니다. 해당 탐지에 대한 모델의 점수입니다. 모든 탐지 점수의 합이 1일 필요도 없고, 그 수치가 그대로 실제 정답 확률로 보정되어 있다고 보장하지도 않습니다.

객체 탐지에서 결과를 평가하는 기준
지표 정의·의미 이번 실습에서 계산했나?
Confidence 객체별 예측 신뢰도 점수. 임계값 필터에 사용 저장 출력에 있음. 정답 비교 지표는 아님
IoU 박스 교집합 넓이 ÷ 합집합 넓이 원문은 NMS 설정에 사용. GT와의 매칭 평가는 하지 않음
Precision TP / (TP + FP): 탐지한 것 중 맞은 비율 계산하지 않음
Recall TP / (TP + FN): 실제 객체 중 찾은 비율 계산하지 않음
AP 클래스별 Precision–Recall 곡선을 요약하는 면적 기반 지표 계산하지 않음
mAP50 정답 매칭 IoU 0.50 기준 AP를 클래스별 평균 계산하지 않음
mAP50–95 IoU 0.50~0.95를 0.05 간격으로 바꿔 평균 계산하지 않음
Accuracy 이미지 분류에서는 전체 예측 중 정답 비율 객체 탐지를 단일 분류 Accuracy로 대신 평가하지 않음
R² 회귀에서 예측의 설명력을 비교하는 지표 임의의 클래스 ID나 매칭하지 않은 박스에 적용하지 않음

TP는 정답 클래스·위치 조건을 만족하며 정답 객체와 매칭된 탐지, FP는 틀렸거나 중복된 탐지, FN은 놓친 정답 객체입니다. 박스가 겹친다는 이유만으로 모두 TP가 되지는 않습니다. 정답과 예측의 일대일 매칭도 필요합니다.

IoU의 두 용도: NMS에서는 예측 박스끼리 겹침을 비교합니다. 평가에서는 예측 박스와 정답 박스를 비교합니다. predict(iou=0.5)가 곧 mAP50 계산이라는 뜻은 아닙니다.

Loss는 어떻게 읽는가?

이 단원에는 학습 Loss 출력이 없습니다. 1 - confidence를 Loss로 해석하지 않습니다. 향후 학습에서는 위치·클래스 관련 오차 항을 최적화하고, 학습·검증 추이와 탐지 Metric을 함께 봅니다. 낮은 학습 Loss 하나로 일반화 성능을 보장하지 않습니다.

속도는 어떻게 읽는가?

preprocess / inference / postprocess는 서로 다른 구간입니다. 1000 / inference_ms만으로 계산한 값은 전체 서비스의 FPS가 아닙니다. 파일 읽기·시각화·저장·통신·첫 실행 준비 시간 등을 포함하는지, 배치·장치·입력 크기가 같은지 확인합니다.

평가 지표 설명: YOLO 성능 지표, Validation 문서. 이 링크의 설명은 원문에 없는 실제 평가 점수를 만들어 주지 않습니다.

Overfitting / Underfitting

과적합은 학습 자료에는 잘 맞지만 새로운 자료로 일반화되지 않는 상태입니다. 과소적합은 학습 자료의 패턴부터 충분히 배우지 못한 상태입니다. 사진 2장, 높은 신뢰도, 객체 하나의 미탐만 보고 어느 쪽이라고 진단할 수 없습니다.

커스텀 학습에서는 Train·Validation의 Loss와 Precision·Recall·mAP 추이를 함께 봅니다. 도메인 차이, 잘못된 라벨, 전처리 오류도 낮은 성능의 원인이므로 먼저 구분합니다.

Learning Rate 문제

Learning Rate는 학습 시 가중치 갱신의 크기를 제어합니다. 너무 크면 불안정해질 수 있고, 너무 작으면 학습이 느리거나 충분히 진행되지 않을 수 있습니다. 이번 predict()의 conf / iou / line_width는 Learning Rate가 아닙니다. 추론에서 놓친 객체를 학습률 조절로 즉시 해결한다고 설명하지 않습니다.

12. NMS IoU와 평가 IoU의 차이는?

NMS는 예측 후보끼리, 평가는 예측과 정답 사이의 겹침을 사용합니다.

13. NMS가 필요한 이유는?

같은 객체를 설명하는 중복 후보를 줄이기 위해서입니다. 임계값에 따라 밀집 객체가 제거될 수도 있습니다.

14. probs가 None이면 탐지가 실패했는가?

아닙니다. 이 탐지 모델의 객체 신뢰도는 boxes.conf에 있습니다.

15. 클래스가 0.처럼 출력되는 이유는?

텐서의 자료형 표시입니다. 의미는 클래스 ID이며 이름 조회 때 정수로 변환합니다.

16. 객체 하나의 xyxy Shape가 왜 (1,4)인가?

객체 축이 남아 있기 때문입니다. [0]을 고르면 좌표 4개를 얻습니다.

17. [:, :, ::-1]은 무슨 역할인가?

3채널 이미지의 채널 순서를 BGR에서 RGB로 바꿉니다. 좌우 반전이 아닙니다.

18. cpu와 detach는 각각 무엇인가?

cpu는 장치 이동, detach는 자동 미분 추적에서 분리입니다. 둘은 같은 기능이 아닙니다.

19. Tensor.tolist 전에 항상 cpu가 필수인가?

PyTorch Tensor.tolist는 필요 시 내부적으로 CPU로 이동합니다. 원문의 numpy().tolist는 NumPy 메서드라는 점을 구분합니다.

20. save=True로 정답 라벨이 생기는가?

아닙니다. 탐지 표시 이미지를 저장합니다. 예측 TXT 저장과 GT 작성은 별개의 작업입니다.

21. 높은 신뢰도만으로 과적합을 알 수 있는가?

아닙니다. 학습·검증 데이터에 대한 성능과 학습 추이 등을 비교해야 합니다.

22. 객체가 안 보이면 Learning Rate부터 바꾸는가?

이번 추론에서는 학습률로 가중치를 갱신하지 않습니다. 입력·모델 클래스·전처리·임계값부터 확인합니다.

23. 이번 두 사진으로 mAP를 알 수 있는가?

검수한 정답 박스와 클래스 및 평가 절차가 없으므로 계산된 mAP는 없습니다.

24. 왜 영상 프레임을 무작위로 섞으면 안 되는가?

거의 같은 프레임이 Train과 Test에 들어가면 독립 평가가 훼손될 수 있습니다. 영상·장면 등으로 묶어 분할합니다.

25. 왜 추론 ms만으로 서비스 FPS를 말하기 어려운가?

전처리·후처리뿐 아니라 입력 읽기·저장·전송 등 전체 처리 비용과 배치 조건이 다를 수 있기 때문입니다.

26. 다음 단원에서는 무엇이 추가되는가?

사용자 클래스의 정답 라벨, 데이터 분할, YOLO 라벨 형식과 YAML, train(), 학습한 best.pt를 이용한 추론이 추가됩니다.

Confidence ≠ Accuracy
탐지 점수와 정답 비교 성능은 다릅니다.
NMS IoU ≠ mAP50
중복 후보 제거 설정과 정답 기반 평가 기준을 구분합니다.
xywh의 x,y는 중심

predict ≠ train
추론은 출력 계산, 학습은 정답으로 가중치 갱신입니다.
저장 그림 ≠ Ground Truth

탐지 ≠ 추적

None ≠ 무조건 실패
현재 작업에서 만들지 않는 속성일 수 있습니다.
