18 · Loss·Metric·출력 해석

Accuracy를 설정한 것과 수치를 확인한 것은 다르다

Step 1·2 보완 수식

BCE = −(1/N) Σ [y log(p) + (1−y) log(1−p)]

y는 0/1, p는 모델의 Sigmoid 출력이다. 정답 1에 가까운 출력을 내야 할 때 p가 0에 가까울수록 손실은 커진다. Accuracy는 판정 결과의 일치 여부를 보므로 같은 분류 결과라도 확신 정도에 따라 BCE는 달라질 수 있다.

확인된 사실

BCE·Adam·Accuracy 설정, 문장 네 개, 50 Epoch, verbose=0, History 객체 표시.

확인되지 않은 값

최종 Loss, 최종 Accuracy, Epoch별 곡선, 최적 Epoch, Validation/Test 성능.

성능 곡선과 Accuracy 100%를 만들어 넣지 않는다.

원본에는 수치가 없다. MSE·MAE·R²도 계산하지 않았다. 또한 Embedding-only 단계의 Vector 성분은 분류 확률이 아니다.

더미 Label에서 직접 계산한 비교 예시 · 원본 성능 아님

네 문장만 한 번 평가한다면 한 개의 정답 차이는 25%p다. labels=[1,0,1,1]에서 항상 1이라고 답해도 75%다. 이 계산은 작은 더미 Dataset의 한계를 설명하며, 학습된 모델의 Accuracy를 뜻하지 않는다.

Q1. fit_on_texts와 model.fit은 어떻게 다른가?

전자는 사전·통계 구성, 후자는 정답에 따른 신경망 가중치 학습이다.

Q2. OOV 설정 후 기존 Token ID도 왜 달라지는가?

새 사전에서 OOV가 1번을 차지한다. 기존 사전의 숫자 의미를 그대로 사용하면 안 된다.

Q3. Padding 0과 OOV 1은 같은가?

아니다. 길이 보충 위치와 사전에 없는 Token의 표시다.

Q4. num_words=5이면 word_index가 다섯 항목만 남는가?

아니다. 이 Legacy 구현의 변환 경계는 index >= num_words이며 사전 자체를 그 크기로 자르는 것과 다르다.

Q5. index_docs와 word_counts의 차이는?

등장 문서 수와 총 등장 횟수의 차이다. 후자는 원문에 출력하지 않은 보완 비교 속성이다.

Q6. 실제 maxlen과 Padding Shape는?

8과 (4,8)이다. 원문 주석 (4,5)와 구분한다.

Q7. Vocabulary 위치가 17개인 이유는?

실제 Token 15개, OOV 1개, Padding Index 0의 위치 1개를 포함한다.

Q8. (4,8,10)과 (17,10)은 어떻게 다른가?

문장별 출력 Tensor와 Token별 Embedding 가중치 Table이다.

Q9. Padding은 자동으로 0 Vector가 되는가?

아니다. 원본에서는 Table의 0번 행이 반환되고 0이 아닌 Vector가 출력된다.

Q10. 이번 분류 모델에 LSTM이 있는가?

없다. Embedding → Flatten → Dense(8) → Dense(1)이다.

Q11. Parameter 827개는 어떻게 계산하는가?

170 + 0 + 648 + 9 = 827이다.

Q12. 실제 Accuracy는 얼마인가?

자료에 수치가 없다. Metric으로 설정하고 50 Epoch 학습했다는 사실만 확인된다.

Q13. 가중치 저장 출력의 문제는?

Cell 36은 (16,8), 현재 설정과 Cell 37은 (17,10)이다. 정확한 불일치 원인은 확정하지 않는다.

Q14. nouns와 phrases는 같은가?

아니다. 우리 형 예제에서 명사 목록과 우리 형이라는 구가 포함된 목록이 다르게 나온다.

Q15. 새 문장 추론 시 사전을 다시 학습하는가?

기존 모델과 맞는 사전으로 변환한다. 새로 fit하면 입력의 ID 의미가 달라질 수 있다.

문장 → Token ID → Padding → Embedding → (B,T,D).
