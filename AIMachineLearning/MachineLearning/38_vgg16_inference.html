01핵심 개념 · 학습된 가중치로 출력 계산

이번 문제는 “새 이미지 한 장을 ImageNet으로 학습된 VGG16이 어떤 클래스로 판단하는가?”입니다. 기존 분류층을 유지하고 예측·저장·재사용 흐름을 익힙니다.

왜 배우나요?

이미 학습한 모델도 입력 크기·배치 축·전처리·출력 해석을 맞춰야 사용할 수 있습니다. 이번 실습은 모델을 실제 프로그램에서 사용하는 기본 과정을 보여 줍니다.

앞 단원과 무엇이 다른가요?

ML 37은 MobileNet 특징에 새 두 클래스 분류층을 학습했습니다. 이번에는 VGG16의 기존 1,000개 클래스 분류층으로 추론합니다. 새 가중치 학습은 없습니다.

사전학습·전이학습·미세조정·추론
개념 의미 이번 원문
사전학습 다른 데이터로 이미 학습된 가중치 ImageNet 가중치 사용
전이학습 기존 지식을 새로운 과제에 활용 새 과제 학습을 수행하지 않음
미세조정 기반 가중치 일부·전체 추가 학습 수행하지 않음
추론 현재 가중치로 출력 계산 실습의 중심 
ŷ = f(X; θ)

X: 전처리한 이미지
θ: 이미 학습된 VGG16 가중치
ŷ: 1,000개 클래스 예측 점수

이번에는 X로 ŷ를 계산합니다.
θ를 학습으로 업데이트하지 않습니다.

trainable과 실제 학습은 다릅니다. Trainable은 학습 시 업데이트 대상이 될 수 있는 상태입니다. predict는 현재 가중치로 출력만 계산하므로 추론하려고 반드시 모든 층을 trainable=False로 바꿀 필요는 없습니다.

VGG16의 16은 합성곱 13개와 완전연결층 3개를 가리킵니다. Pooling·Flatten까지 모두 세어서 16이라는 뜻은 아닙니다. ReLU는 해당 Conv·Dense의 활성화로 포함됩니다. 위 도식은 블록을 요약한 것입니다.

원본 모델 요약을 블록별로 읽기
구간 구성 출력 Shape
입력 RGB 이미지 배치 (B,224,224,3)
Block 1 Conv 64 두 번 → Pool (B,112,112,64)
Block 2 Conv 128 두 번 → Pool (B,56,56,128)
Block 3 Conv 256 세 번 → Pool (B,28,28,256)
Block 4 Conv 512 세 번 → Pool (B,14,14,512)
Block 5 Conv 512 세 번 → Pool (B,7,7,512)
Flatten 7×7×512 펼치기 (B,25088)
fc1 / fc2 각 Dense 4096 + ReLU 각 (B,4096)
predictions Dense 1000 + Softmax (B,1000)

합성곱은 블록 안에서 공간 크기를 유지하고 Pooling이 높이·너비를 줄입니다. 채널 수는 3→64→128→256→512→512로 변합니다. B는 배치 크기이며 원문 실제 추론에서는 1입니다. 

Flatten: 7 × 7 × 512 = 25,088

GAP라면 채널별 공간 평균을 구하지만, 이번 기본 분류부는 Flatten입니다.

def predict_vgg16_image(model, image_path, top=5):
    pil_image = image.load_img(
        image_path, target_size=(224, 224), color_mode='rgb'
    )
    rgb_array = image.img_to_array(pil_image)
    batch = np.expand_dims(rgb_array, axis=0)
    model_input = preprocess_input(batch.copy())

    predictions = model.predict(model_input, verbose=0)
    candidates = decode_predictions(predictions, top=top)[0]

    print('RGB 배열:', rgb_array.shape, rgb_array.dtype)
    print('모델 입력:', model_input.shape, model_input.dtype)
    print('예측 출력:', predictions.shape)
    print('이미지별 점수 합:', predictions.sum(axis=1))

    for rank, (imagenet_id, label, score) in enumerate(candidates, start=1):
        print(f'{rank}위: {label} ({imagenet_id}) — {float(score):.4%}')

    return predictions, candidates


new_predictions, new_candidates = predict_vgg16_image(

fit·Epoch·Learning Rate 실행·설정하지 않음 가중치 업데이트 없음
evaluate·Accuracy 계산하지 않음 정답 y 없음
predict·decode 실행 예측 계산·이름 해석
save·load 실행 모델 재사용

Loss · 정답이 주어졌을 때의 보충 개념

다중분류 Cross-Entropy: L = −Σ y_c log(p_c)
원핫 정답이면:          L = −log(정답 클래스 점수)

정답 점수 0.9 → Loss 약 0.1054
정답 점수 0.6 → Loss 약 0.5108
정답 점수 0.1 → Loss 약 2.3026

위는 원문에서 측정한 값이 아닌 보충 계산입니다. Loss는 오답률·백분율이 아닙니다. 높은 예측 점수만으로 원문이 정답 기반 손실을 계산했다고 말하지 않습니다.

서로 다른 출력과 지표
개념 뜻 이번 원문
개별 예측 점수 한 이미지의 특정 클래스에 부여한 값 있음
Accuracy 맞힌 이미지 수 / 전체 평가 이미지 수 계산 없음
Top-5 Accuracy 정답이 상위 5개 후보에 포함된 비율 계산 없음
Softmax 합 이미지별 클래스 점수의 합 ≈ 1 확인함
R² 연속값 회귀 지표 적용하지 않음

R² · 클래스 번호에 적용하지 않기

R² = 1 − SSE / SST
SSE = Σ(y − ŷ)²    예측 오차 제곱합
SST = Σ(y − ȳ)²    정답과 정답 평균의 차이 제곱합

정답에 변동이 있는 일반적인 회귀에서
1: 완벽한 예측 / 0: 평균 예측 수준 / 음수: 평균 예측보다 나쁨

정답이 모두 같아 SST=0이면 별도 처리가 필요하고 표본 한 개로도 일반적인 R² 평가를 할 수 없습니다. 클래스 231과 232는 연속적인 크기·거리 관계가 아니므로 번호에 R²를 적용하지 않습니다.

높은 Softmax 점수는 실제 정답을 보장하지 않습니다. 학습 범주에 맞지 않는 입력에도 점수를 배분할 수 있습니다. 한 장의 성공을 전체 서비스 정확도로 확대하지 않습니다.

16Data Leakage · 평가를 확장할 때 확인할 것

누수는 모델을 만들거나 선택하는 과정에 평가 시점에 사용하면 안 되는 정보가 들어가 성능을 실제보다 좋게 보이게 하는 문제입니다. 이번 원문에는 새 학습·정답 평가가 없어 Train/Test 누수를 직접 실험하지 않습니다.

후속 학습·평가에서 주의할 상황
상황 문제 확인 방향
동일 이미지가 Train·Test에 존재 본 적 있는 정보로 평가 내용 중복 확인

전체 데이터로 Scaler·PCA 학습 평가 정보가 변환 학습에 유입 Train에서 fit, 동일 변환 적용
잘 맞힌 사진만 골라 보고 대표성 없는 평가 실제 사용 분포를 반영한 표본

고정된 ImageNet 평균을 사용하는 전처리 자체를 누수라고 부르지 않습니다. 사전학습 가중치 사용 자체도 누수의 증거가 아닙니다. 현재 사진이 사전학습 데이터와 겹치는지 여부는 원문만으로 확인되지 않습니다.

22면접 포인트 · 스스로 답해 보기

Q1. 이번 실습의 목적은?

사전학습 VGG16으로 추론하고 저장·재로딩하여 다시 사용합니다. 새 학습은 없습니다.

Q2. VGG16의 16은 무엇인가요?

합성곱 13개와 완전연결층 3개를 합한 가중치 층 수입니다.

Q3. DogvsCat 파일이면 두 클래스 모델인가요?

아닙니다. 이번 실제 출력은 ImageNet 1,000개 클래스입니다.

Q4. weights를 생략했는데 왜 사전학습인가요?

VGG16의 기본 weights가 imagenet이기 때문입니다.

Q5. weights=None이면 가중치가 없나요?

아닙니다. 사전학습 값을 불러오지 않고 무작위 초기화합니다.

Q6. 배치 축이 필요한 이유는?

모델이 배치 단위로 입력을 처리하므로 이미지 한 장도 앞에 장수 축을 붙입니다.

Q7. 입력 Shape의 None은?

배치 크기를 모델 정의에서 고정하지 않았다는 뜻입니다.

Q8. VGG16 전처리는?

RGB→BGR 전환 후 채널 평균을 뺍니다. 추가 /255와 구분합니다.

Q9. 전처리 전후 Shape가 같으면 데이터도 같나요?

아닙니다. 값의 기준과 채널 순서가 달라집니다.

Q10. 전처리 그림의 색이 이상한 이유는?

BGR·평균 제거된 값을 RGB 표시 규칙으로 그리며 음수 등이 clipping되기 때문입니다.

Q11. 원문의 /255는 모델 입력을 바꾸나요?

표시용 임시 표현이며 입력 변수에 재대입하지 않습니다.

Q12. trainable=True이면 predict에서 학습되나요?

아닙니다. predict는 현재 가중치로 출력만 계산합니다.

Q13. argmax와 max의 차이는?

최댓값의 위치와 최댓값 자체입니다.

Q14. decode_predictions는 모델을 다시 실행하나요?

아닙니다. 기존 점수의 순위와 ImageNet 매핑으로 이름을 해석합니다.

Q15. 98.213%는 Accuracy인가요?

한 이미지의 collie 점수입니다. 실제 정답과 비교한 전체 정답 비율이 아닙니다.

Q16. Top 5 출력과 Top-5 Accuracy의 차이는?

후보를 반환하는 것과 정답이 그 후보 안에 포함된 비율을 측정하는 것은 다릅니다.

Q17. Loss·Optimizer가 없는 이유는?

정답 기반 학습·평가를 수행하지 않고 추론만 하기 때문입니다.

Q18. 전처리 셀만 반복하면 왜 위험한가요?

입력 NumPy 값이 바뀔 수 있어 평균 차감 등이 누적됩니다. 새로 읽은 복사본을 사용합니다.

Q19. 저장 파일에 전처리 코드가 포함되나요?

이번 모델 바깥에서 호출한 전처리·이미지 로딩 코드는 자동 포함되지 않습니다.

Q20. 저장 전후 argmax가 같으면 모든 점수도 같은가요?

단정할 수 없습니다. 필요하면 같은 입력의 전체 점수를 허용 오차로 비교합니다.

Q21. 추론 오류는 학습률을 바꾸면 해결되나요?

현재 추론에는 업데이트가 없습니다. 입력·전처리·클래스 의미부터 확인합니다.

Q22. 클래스 번호에 R²를 적용하지 않는 이유는?

번호에는 연속적인 크기·거리 의미가 없고 R²는 회귀 지표이기 때문입니다.

Q23. 다음 단원에서는 무엇을 학습하나요?

VGG19의 특징을 추출하고 LogisticRegression·SVC로 새 분류기를 학습합니다.
