FFNN으로 주택가격 예측하기

Boston Housing → X / y → 13 Features → Dense 64 → Dense 64 → Dense 1 → MSE + Adam → fit → evaluate → predict → R²
(batch, 13) → (batch, 64) → (batch, 64) → (batch, 1)

Metric Interpretation

MSE와 R²를 함께 보는 이유

MSE

작을수록 좋음

Common Mistakes

자주 하는 실수

01

Input Shape `(13,)`을 Dataset 전체 Shape라고 생각한다.

`(13,)`은 Sample 하나의 Shape이고, Batch 입력은 `(batch,13)`이다.

02

W1 Shape를 `(64,13)`이라고 생각한다.

Forward는 `(batch,13) @ (13,64)`이므로 Weight Shape는 `(13,64)`이다.

03

Regression Output에도 ReLU나 Sigmoid를 반드시 넣는다고 생각한다.

이번 교안은 Dense(1)의 Linear Output을 사용한다.

04

MSE 45를 평균 45만큼 틀렸다고 해석한다.

MSE는 Error의 제곱 평균이다.

05

R²는 반드시 0~1이라고 생각한다.

일반적인 R²는 음수가 될 수도 있다.

06

evaluate()가 Weight를 업데이트한다고 생각한다.

evaluate는 현재 Weight로 평가만 수행한다.

07

predict()가 Model을 더 학습한다고 생각한다.

predict는 Forward Propagation만 수행한다.

08

Test에 fit_transform을 사용해도 된다고 생각한다.

일반적인 평가에서는 Scaler는 Train에 fit하고 Test는 같은 통계로 transform한다.

09

0.459 → 0.768을 StandardScaler 단독 효과라고 생각한다.

같은 Model에 추가 100 Epoch 학습했기 때문에 여러 효과가 섞여 있다.

10

마지막 Loss Curve가 첫 번째 학습 결과라고 생각한다.

history가 두 번째 fit에서 다시 대입되므로 마지막 그래프는 두 번째 학습 결과다.

Interview Point

면접 포인트

Q1. FFNN이란 무엇입니까?

Feed Forward Neural Network로, 데이터가 Input에서 Hidden Layer를 거쳐 Output 방향으로 순방향 전달되는 신경망입니다.

Q2. 이번 Model Architecture는 무엇입니까?

13개의 입력 Feature에서 64 Node Hidden Layer 두 개를 거쳐 하나의 Regression Output을 생성하는 13 → 64 → 64 → 1 구조입니다.

Q3. X_train.shape=(404,13)은 무엇을 의미합니까?

Training Sample 404개, 각 Sample마다 Feature 13개가 있다는 뜻입니다.

Q4. InputLayer(shape=(13,))에서 13은 무엇입니까?

Sample 하나의 Feature 개수입니다. Batch Dimension은 별도로 관리됩니다.

Q5. Model Summary의 None은 무엇입니까?

Batch Size가 고정되어 있지 않다는 뜻입니다.

Q6. 첫 Dense Layer Parameter가 896개인 이유는 무엇입니까?

13×64개의 Weight와 64개의 Bias를 더해 총 896개입니다.

Q7. Output Layer가 Dense(1)인 이유는 무엇입니까?

하나의 연속적인 주택가격 값을 예측하는 Regression 문제이기 때문입니다.

Q8. Output에 Activation을 지정하지 않은 이유는 무엇입니까?

일반적인 Regression에서 연속 실수값을 그대로 출력하기 위해 Linear Activation을 사용하기 때문입니다.

Q9. 이번 Loss는 무엇입니까?

MSE, Mean Squared Error이며 실제값과 예측값 차이의 제곱 평균입니다.

Q10. Optimizer는 무엇입니까?

Adam이며 Learning Rate는 0.01입니다.

Q11. compile()은 무엇을 합니까?

Model이 사용할 Loss와 Optimizer 등 학습 전략을 설정합니다. 이 시점에는 아직 Weight 학습이 시작되지 않습니다.

Q12. fit()과 evaluate()의 차이는 무엇입니까?

fit은 Weight를 업데이트하며 학습하지만, evaluate는 현재 Weight를 이용해 평가만 합니다.

Q13. validation_split=0.2는 무엇입니까?

Training Dataset 일부를 Weight Update에는 사용하지 않고 Validation 성능 확인에 사용하는 설정입니다.

Q14. Regression에서 Accuracy를 사용하지 않는 이유는 무엇입니까?

연속값은 맞음/틀림보다 실제값과 얼마나 가까운지를 평가해야 하므로 MSE, MAE, RMSE, R² 같은 회귀 지표를 사용합니다.

Q15. R²는 음수가 될 수 있습니까?

가능합니다. 평균 Target을 예측하는 기준보다 Model이 더 나쁘면 음수가 될 수 있습니다.

Q16. StandardScaler는 무엇을 합니까?

Feature를 평균 0, 표준편차 1에 가까운 Scale로 변환합니다. 원래 분포를 자동으로 정규분포로 만드는 것은 아닙니다.

Q17. Test Set에 fit_transform을 사용하면 왜 문제가 될 수 있습니까?

Test Set 자체의 통계로 Scaler Parameter를 학습하게 되어 독립적인 평가 원칙을 훼손하기 때문입니다.

Q18. 이번 Notebook의 전·후 R²를 단순 비교하면 안 되는 이유는 무엇입니까?

StandardScaler 적용뿐 아니라 이미 학습한 동일 Model을 추가 100 Epoch 학습했기 때문에 여러 요인의 효과가 섞여 있기 때문입니다.

Q19. 마지막 Loss Graph는 어떤 학습 결과입니까?

history가 두 번째 fit에서 다시 대입되므로 Standardized Data로 추가 학습한 두 번째 History입니다.

Q20. Data Leakage를 막기 위한 Scaler 기본 원칙은 무엇입니까?

Scaler는 Training Data에만 fit하고, Validation과 Test에는 동일한 Training 통계로 transform해야 합니다.

Caution

헷갈리기 쉬운 개념

Input shape=(13,)은 전체 Dataset Shape인가?

X 아니다.

Sample 하나의 Shape다. 실제 Batch는 (batch,13)이다.

Regression Output에도 Sigmoid가 필요한가?

X 이번 교안에서는 사용하지 않는다.

Dense(1)의 Linear Output으로 연속값을 예측한다.

evaluate()의 4/4는 4번 Weight를 업데이트했다는 뜻인가?

X 아니다.

Test Dataset을 4개의 Batch로 나누어 평가했다는 의미다.

R²는 0~1만 가능한가?

X 아니다.

평균 기준보다 예측이 나쁘면 음수도 가능하다.

StandardScaler는 데이터를 정규분포로 만드는가?

X 아니다.

평균과 표준편차를 기준으로 Scale을 조정한다.

Test에도 fit_transform을 해야 하는가?

X 일반적인 평가 원칙에서는 아니다.

Train에 fit한 Scaler를 Test에는 transform한다.

R² 0.459 → 0.768은 Scaling 효과인가?

X 그렇게 단정할 수 없다.

동일 Model 추가 학습 등 여러 요인이 섞여 있다.
