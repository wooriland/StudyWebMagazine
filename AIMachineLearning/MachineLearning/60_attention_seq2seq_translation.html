01 · PROBLEM DEFINITION

실습 목표와 문제 정의

이번 실습은 기본 Seq2Seq에 Attention을 추가하여 Decoder가 영어 원문의 여러 위치에 있는 정보를 선택적으로 활용하면서 한국어 문장을 생성하도록 구현하는 것이 목표입니다.

왜 Attention을 배우는가?

기본 Seq2Seq 모델에서는 Encoder가 문장 전체를 읽고 마지막 상태를 Decoder에 전달합니다. 문장이 짧다면 충분할 수 있지만, 길고 복잡해질수록 모든 정보를 고정 크기 상태에 압축하는 데 한계가 있습니다.

02 · CORE CONCEPTS

핵심 개념 — Seq2Seq와 Attention

Sequence-to-Sequence

Seq2Seq는 하나의 Sequence를 입력받아 새로운 Sequence를 생성하는 구조입니다. 번역에서는 영어 문장이 입력 Sequence이고 한국어 문장이 출력 Sequence입니다.

기계번역 문제 X = (x₁, x₂, ..., xₙ) Y = (y₁, y₂, ..., yₘ)

영어 문장의 길이 n과 한국어 문장의 길이 m은 서로 달라도 됩니다.

Encoder–Decoder

Encoder

입력 문장을 읽어 시점별 출력과 최종 Hidden State, Cell State를 생성합니다.

Decoder

Encoder 정보를 활용하고 이전 출력 단어를 참고하여 다음 단어의 확률을 계산합니다.

Hidden State와 Cell State

구분 의미 Shape
Hidden State h 현재 시점의 전달 상태 (B, 256)
Cell State c 장기 정보를 유지하는 LSTM 상태 (B, 256)
Encoder Outputs 모든 timestep의 LSTM 출력 (B, 10, 256)

Attention을 이해하기 위한 네 가지 용어

Q

Query

지금 Decoder가 어떤 정보를 필요로 하는지 나타냅니다.

K

Key

Encoder 각 위치의 관련도를 계산하는 기준 정보입니다.

V

Value

Attention Weight를 적용해 실제로 가중합할 정보입니다.

C

Context

Value들을 가중합하여 얻는 현재 시점의 문맥 벡터입니다.

이번 Notebook에서 Q, K, V는 무엇인가?

역할 Tensor 설명
Query x Decoder LSTM 출력
Key encoder_outputs Encoder 전체 시점 출력
Value encoder_outputs Encoder 전체 시점 출력
원본 Attention 핵심 코드 Cell 038 
attention_vector = self.attention(
    [x, encoder_outputs]
)

위 코드는 Keras의 기본 Dot-Product Attention을 사용하는 형태입니다. Decoder 출력이 Query가 되고, Encoder 전체 출력이 Key와 Value에 사용됩니다.

기본 Attention과 Transformer의 차이

이번 원본의 keras.layers.Attention()은 기본적으로 Dot-Product 방식입니다. Transformer에서 흔히 배우는 Scaled Dot-Product Attention과 완전히 같은 구현이라고 생각하면 안 됩니다.

03 · VISUAL LEARNING

그림처럼 이해 — 현재 단어에 집중하기

"Tom bought a horse"라는 영어 문장을 한국어로 번역하는 상황을 생각해 보겠습니다.

Source Sequence

Tom bought a horse
↓
Encoder LSTM 영어 단어별 출력 벡터 생성
↓
Attention 현재 필요한 Encoder 위치 계산
↓
Decoder 한국어 단어 생성
↓
톰 은 말 을 샀어

Attention Weight는 어떻게 이해하는가?

Decoder가 "말"에 대응하는 단어를 생성할 때 영어 문장 중 "horse"에 높은 가중치를 줄 수 있다고 생각해 볼 수 있습니다.

Decoder 현재 출력: "말" 설명용 가상 Attention Weight
Tom
0.10
bought
0.12
a
0.08
horse
0.70

위 0.10, 0.12, 0.08, 0.70은 개념 이해를 위해 임의로 설정한 수치입니다. 원본 Notebook에서 Attention Weight를 직접 출력한 결과는 아닙니다.

한 문장 안에서 중요한 위치가 달라진다

생성하려는 한국어 단어 관련될 수 있는 영어 위치
톰 Tom
말 horse
샀어 bought

이 표는 단어 정렬을 이해하기 위한 설명입니다. 실제 모델의 Attention Weight가 반드시 동일한 정렬을 나타낸다는 뜻은 아닙니다.

Attention의 핵심은 "항상 똑같은 원문 정보를 전달하는 것"이 아니라 "현재 출력 시점에서 필요한 원문 정보를 새롭게 계산하는 것"입니다.

05 · X / y / TENSOR SHAPE

X / y와 전체 Shape 흐름

Seq2Seq 학습에는 Encoder Input, Decoder Input, Decoder Target의 세 배열이 필요합니다. Attention을 추가하더라도 이 학습 데이터 구성은 같습니다.

Encoder Input

encoder_in_pad (1000, 10) 영어 정수 토큰

Decoder Input

decoder_in_pad (1000, 10) SOS + 이전 정답

Decoder Target

decoder_out_pad (1000, 10) 다음 정답 + EOS

Teacher Forcing용 Shift

전체 한국어 문장 <SOS> 나는 학생이다 <EOS>
Decoder Input <SOS> 나는 학생이다
Decoder Target 나는 학생이다 <EOS>

설명용 예제입니다. 실제 첫 번째 데이터의 Decoder Input은 <SOS> 가, Target은 가 <EOS>입니다.

Encoder에서 Decoder까지 Shape 추적

Encoder 정수 입력 (B, 10) 문장별 10개 Token ID
↓
Encoder Embedding (B, 10, 128) 단어당 128차원
↓
Encoder LSTM 전체 출력 (B, 10, 256) 10개 시점의 256차원 출력
↓
Attention Score (B, 10, 10) Decoder 시점 × Encoder 시점
↓
Attention Context (B, 10, 256) Encoder 출력의 가중합
↓
Decoder LSTM + Context (B, 10, 512) 256 + 256 Concatenate
↓
Dense + Softmax (B, 10, 1947) 시점별 단어 확률

Shape 전체 비교표

Tensor Shape 의미
Encoder Input (B,10) 영어 정수 시퀀스
Encoder Embedding (B,10,128) 영어 임베딩 벡터
Encoder Outputs (B,10,256) 모든 시점의 출력
Encoder h (B,256) 최종 Hidden State
Encoder c (B,256) 최종 Cell State
Decoder Input (B,10) 한국어 정수 시퀀스
Decoder LSTM (B,10,256) Decoder Query
Attention Scores (B,10,10) Query-Key 유사도
Attention Context (B,10,256) 가중합 결과
Concatenate (B,10,512) Decoder + Context
Softmax Output (B,10,1947) 단어별 예측 확률
Target (B,10) 정답 Token ID
가장 중요한 Shape 변화

Encoder의 return_sequences=True로 (B,10,256) 전체 출력이 추가됩니다. Decoder 출력 (B,10,256)과 Attention Context (B,10,256)를 결합하면 (B,10,512)가 됩니다.

B는 배치 크기입니다. 원본의 Batch Size는 32이지만, 마지막 배치는 8개입니다. 중간 계층 Shape은 원본 계층 정의로부터 계산한 값입니다.

06 · PREPROCESSING

전처리 — 원문에서 Tensor까지

Attention을 사용해도 문장을 정수 시퀀스로 바꾸는 기본적인 NLP 전처리 흐름은 유지됩니다.

1

한국어 문장 정제

WordTokenizer의 preprocess_korean()을 사용합니다. 번역에는 조사와 문장 구조가 중요하므로 불용어를 함부로 제거하지 않습니다.

2

SOS와 EOS 추가

생성 시작과 종료를 모델이 구분할 수 있도록 한국어 문장의 양 끝에 특수 토큰을 추가합니다.

<SOS> 가 <EOS>
3

Decoder Input과 Target 분리

한 칸 이동한 두 시퀀스를 만들어 Teacher Forcing 학습에 사용합니다.

4

영어 구두점 제거

정규식을 사용하여 영어 입력의 구두점과 일부 특수 문자를 제거합니다.

5

Vocabulary 구축

영어 원문과 Decoder Input/Target을 합쳐 공통 단어 사전을 만듭니다. 저장된 Vocabulary Size는 1947입니다.

6

Integer Encoding / Padding

단어를 정수 Token ID로 변환하고 최대 길이 10에 맞춰 Padding합니다.

  • 전체 데이터를 사용해 단어 사전을 만든 뒤 Train/Test로 분리하는 경우

↓

09 · ATTENTION MECHANISM

Attention Score → Weight → Context

이번 실습에서 가장 중요한 부분입니다. Decoder는 Query를 사용하여 Encoder의 각 위치와 관련도를 계산하고 그 결과를 가중합하여 Context Vector를 생성합니다.

Step A. Query와 Key의 내적

Attention Score score(t,s) = qₜ · kₛ

qₜ는 Decoder의 t번째 Query, kₛ는 Encoder의 s번째 Key입니다.

이번 Notebook에서 Q와 K의 Feature 차원은 모두 256입니다. 따라서 Dot Product 계산이 가능합니다.

(B,10,256)
×
(B,256,10)
=
(B,10,10)

Attention Score Shape은 (batch, decoder timestep, encoder timestep)입니다.

Step B. Softmax로 가중치 계산

Attention Weight αₜ,ₛ = exp(scoreₜ,ₛ) / Σⱼ exp(scoreₜ,ⱼ)

Softmax를 적용하면 각 Decoder 시점에 대한 Encoder 위치별 가중치의 합이 1이 됩니다.

Step C. Value의 가중합

Attention Context contextₜ = Σₛ αₜ,ₛ × valueₛ

이 결과가 현재 번역 시점에서 Decoder가 참고하는 문맥 벡터입니다.

Step D. Decoder 출력과 결합

keras.layers.Attention()의 기본 score_mode는 dot입니다. 이번 Notebook은 별도의 Query/Key 투영 Dense 계층을 추가하지 않습니다. Transformer에서 사용하는 Multi-Head Attention과는 구조와 설정이 다릅니다.

원본에서 Padding Mask를 전달하지 않습니다.

입력 시퀀스에는 Padding이 포함되어 있지만 원본의 Attention 호출에는 Mask가 명시되어 있지 않습니다. Padding 위치에 가중치를 부여할 가능성이 있으므로 재실습 단계에서 반드시 검토해야 합니다.

class Encoder(tf.keras.Model):

    def __init__(self, units, vocab_size, embedding_dim):
        super(Encoder, self).__init__()

        self.embedding = keras.layers.Embedding(
            vocab_size,
            embedding_dim
        )

        self.dropout = keras.layers.Dropout(0.2)

        self.lstm = keras.layers.LSTM(
            units,
            return_state=True,
            return_sequences=True
        )

    def call(self, inputs, training):

        x = self.embedding(inputs)

        x = self.dropout(
            x,
            training=training
        )

        encoder_outputs, hidden_state, cell_state = self.lstm(
            x
        )

        return encoder_outputs, [
            hidden_state,
            cell_state
        ]

class Decoder(tf.keras.Model):

    def __init__(self, units, vocab_size, embedding_dim):
        super(Decoder, self).__init__()

        self.embedding = keras.layers.Embedding(
            vocab_size,
            embedding_dim
        )

        self.dropout = keras.layers.Dropout(0.2)

        self.lstm = keras.layers.LSTM(
            units,
            return_sequences=True,
            return_state=True
        )

        self.attention = keras.layers.Attention()

        self.dense = keras.layers.Dense(
            vocab_size,
            activation='softmax'
        )

    def call(self, inputs, initial_state, training=None):

        encoder_outputs, decoder_inputs = inputs

        x = self.embedding(decoder_inputs)

        x = self.dropout(
            x,
            training=training
        )

        x, hidden_state, cell_state = self.lstm(
            x,
            initial_state=initial_state
        )

        attention_vector = self.attention(
            [x, encoder_outputs]
        )

        x = tf.concat(
            [x, attention_vector],
            axis=-1
        )

        x = self.dense(x)

        print(
            '디코더의 현재 타임 스텝의 분류층을 통과한 출력값:',
            x
        )

        return x, hidden_state, cell_state

# Seq2Seq.call() 내부의 추론 분기

x = inputs

encoder_outputs, context_vector = self.encoder(x)

target_seq = np.array(
    [[self.start_token]],
    dtype=np.float32
)

results = []

for i in range(self.time_steps):

    decoder_output, decoder_hidden, decoder_cell = self.decoder(
        (encoder_outputs, target_seq),
        initial_state=context_vector
    )

    decoder_output = np.argmax(
        decoder_output,
        axis=-1
    ).astype(np.int32)

    results.append(decoder_output)

    if decoder_output == self.end_token:
        break

    target_seq = decoder_output

    context_vector = [
        decoder_hidden,
        decoder_cell
    ]

return np.array(results).reshape(
    (1, len(results), 1)
)

Loss는 무엇인가?

Decoder는 각 timestep에서 Vocabulary 전체에 대한 확률 분포를 계산합니다. 실제 정답 단어에 부여한 확률이 높을수록 Crossentropy Loss는 작아집니다.

한 timestep의 Crossentropy L = -log(P(정답 단어))

정수 ID 한 개로 표현합니다.

Accuracy의 의미

Training Accuracy는 각 시점의 예측 Token ID와 정답 Token ID가 같은지를 기준으로 계산됩니다. 하지만 실제 번역 품질에는 다음과 같은 요소도 중요합니다.

  • 문장 전체의 의미를 정확하게 전달하는가?
  • 영어 원문의 중요한 단어를 누락하지 않았는가?
  • 한국어 조사와 어순이 자연스러운가?
  • EOS로 적절한 시점에 문장 생성을 끝내는가?
  • 학습에서 보지 못한 문장도 번역할 수 있는가?

14 · COMMON MISTAKES

자주 하는 실수와 주의사항

01. Encoder의 마지막 상태와 전체 출력을 혼동한다.

마지막 Hidden/Cell State는 각각 (B,256)입니다. Encoder의 전체 출력은 (B,10,256)입니다. Attention에는 전체 출력이 필요합니다.

02. return_sequences=True를 누락한다.

이 옵션이 없으면 Encoder의 전체 시점 출력을 반환하지 않습니다. 따라서 Attention에 필요한 시퀀스 형태의 정보가 사라집니다.

03. Query, Key, Value를 혼동한다.

이번 실습에서 Decoder LSTM 출력이 Query, Encoder 전체 출력이 Key와 Value입니다.

04. Attention Score와 Context Vector를 혼동한다.

Score는 Query-Key 유사도입니다. Context는 Attention Weight로 Value를 가중합한 결과입니다.

05. tf.concat() 후 Shape을 잘못 해석한다.

(B,10,256)과 (B,10,256)을 axis=-1로 결합하면 (B,10,512)가 됩니다.

06. PAD와 EOS를 같은 것으로 생각한다.

PAD는 길이를 맞추는 값이고 EOS는 문장 생성을 종료하는 특수 토큰입니다. 두 역할은 완전히 다릅니다.

07. Attention에 Padding Mask를 적용하지 않는다.

원본에서는 Mask를 명시적으로 전달하지 않습니다. Padding 위치에 Attention이 분산될 수 있으므로 개선 시 Mask 처리를 검토해야 합니다.

08. Token ID를 실수형으로 전달한다.

원본 추론 시작 Token은 float32로 생성됩니다. 정수 Token ID는 일반적으로 int32 또는 int64를 사용하는 것이 적절합니다.

09. 영어 입력에 한국어 전처리를 적용한다.

원본의 추론 전처리 함수는 preprocess_korean()을 호출합니다. 영어 학습 전처리와 같은 규칙이 적용되는지 확인해야 합니다.

10. 학습 Accuracy를 번역 정확도로 해석한다.

97.35%는 Training Accuracy입니다. Padding과 Teacher Forcing의 영향이 있을 수 있으며, 독립적인 문장 번역 평가가 아닙니다.

11. Checkpoint 경로를 이전 모델과 같이 사용한다.

이번 모델의 체크포인트 파일명에는 no-attention이 들어 있습니다. 다른 모델 가중치를 덮어쓰지 않도록 경로를 분리해야 합니다.

12. evaluate()를 그대로 호출하면 된다고 생각한다.

원본 Seq2Seq.call()은 학습 시 확률 Tensor를, 추론 시 Token ID를 반환합니다. 일반적인 Keras 평가 API를 추가할 때 입력과 출력 형식을 먼저 분리해야 합니다.

18 · INTERVIEW / REVIEW

면접 포인트와 복습 질문

질문을 먼저 읽고 스스로 답해 보세요. 각 질문을 펼치면 핵심 답변을 확인할 수 있습니다.

Q01. Seq2Seq에 Attention을 추가하는 이유는 무엇입니까?

기본 Seq2Seq는 입력 문장 전체의 정보를 고정 크기 마지막 상태에 압축해야 합니다. Attention은 Decoder가 각 시점에서 필요한 Encoder 출력 정보를 선택적으로 참고할 수 있게 합니다.

Q02. Encoder의 return_sequences=True는 왜 필요합니까?

Attention이 Encoder의 모든 시점 출력을 참고해야 하므로 LSTM의 전체 출력 시퀀스를 반환하기 위해 사용합니다.

Q03. Hidden State와 Encoder Outputs는 어떻게 다릅니까?

마지막 Hidden State는 (B,256)이고, Encoder Outputs는 모든 시점의 출력인 (B,10,256)입니다.

Q04. 이번 Notebook의 Query는 무엇입니까?

Decoder LSTM의 출력입니다. 현재 Decoder 시점이 필요한 원문 정보를 나타내는 역할을 합니다.

Q05. 이번 Notebook의 Key와 Value는 무엇입니까?

Encoder의 모든 timestep 출력입니다. Key는 관련도 계산에, Value는 Context 가중합에 사용됩니다.

Q06. Dot-Product Attention이란 무엇입니까?

Query와 Key의 내적을 사용하여 Attention Score를 계산하는 방법입니다.

Q07. Attention Score와 Weight의 차이는 무엇입니까?

Score는 Query-Key 관련도 값이고, Weight는 Score에 Softmax를 적용하여 얻는 위치별 가중치입니다.

Q08. Context Vector는 어떻게 계산합니까?

Encoder Value 벡터들에 Attention Weight를 곱한 뒤 모두 합산하여 계산합니다.

Q09. Attention Score의 Shape은 무엇입니까?

일반적으로 (batch, target_length, source_length)입니다. 이번 학습 배열에서는 (B,10,10)입니다.

Q10. tf.concat(axis=-1)을 사용하는 이유는 무엇입니까?

Decoder 출력 256차원과 Attention Context 256차원을 마지막 Feature 축으로 결합해 512차원 벡터를 만들기 위해서입니다.

Q11. Attention을 사용하면 Teacher Forcing이 필요 없습니까?

아닙니다. Teacher Forcing은 Decoder 학습 입력을 구성하는 방법이고, Attention은 원문 정보를 활용하는 방법입니다.

Q12. 학습과 추론은 무엇이 다릅니까?

학습에서는 이전 정답 단어를 입력하고, 추론에서는 이전 예측 단어를 입력합니다. 추론은 EOS가 나올 때까지 반복합니다.

Q13. Attention에 Padding Mask가 중요한 이유는 무엇입니까?

의미 없는 Padding 위치에 Attention Weight가 부여되는 문제를 방지하기 위해서입니다.

Q14. Accuracy 97.35%는 번역 정확도입니까?

아닙니다. 원본의 Training Accuracy입니다. 독립 Test와 문장 단위 번역 평가가 없으므로 실제 번역 정확도라고 해석할 수 없습니다.

Q15. Data Leakage를 어떻게 방지합니까?

Train/Validation/Test를 먼저 분리하고 Tokenizer 등 학습 가능한 전처리는 Train 데이터만으로 학습해야 합니다.

Q16. Overfitting은 어떻게 판단합니까?

Training Loss와 Validation Loss를 비교해야 합니다. 원본에는 Validation Loss가 없으므로 과적합 여부를 확정하기 어렵습니다.

Q17. 가장 좋은 Checkpoint는 마지막 Epoch와 같습니까?

반드시 그렇지는 않습니다. 원본에서는 Epoch 96의 Training Loss가 마지막 Epoch 100보다 낮아 해당 체크포인트가 저장되었습니다.

Q18. 다음 단원에서 Attention 챗봇으로 어떻게 확장합니까?

영어-한국어 번역 문장 쌍 대신 질문-답변 데이터 쌍을 학습합니다. Encoder는 질문을 처리하고 Decoder는 Attention을 활용해 응답 문장을 생성합니다.
