출력 Shape·반환값

Step 1·2 Dataset 보완 MNIST는 28×28 Grayscale 이미지이며 Training 60,000개·Test 10,000개를 제공한다. 원래 Pixel 범위는 0~255다. 이 Shape는 원문의 출력값이 아니라 Loader 구조를 풀어 쓴 설명이다.

설명용으로 X_train[i]가 숫자 3 이미지라면 y_train[i]는 정수 3이다. 이번에는 to_categorical을 호출하지 않는다. X와 y의 같은 Index는 같은 Sample이다.

128 / 255 ≈ 0.50196 설명용 계산
원문 주석과 실제 연산: “0~1사이로 표준화”라는 주석을 보존했다. 실제 코드는 고정 상수로 나누며 (X−평균)/표준편차를 계산하지 않는다. 이미지의 개수·높이·너비는 그대로다.

Cell 3 전체를 재실행하면 데이터를 다시 로드한 뒤 변환한다. 반면 마지막 정규화 줄만 반복하면 이미 변환한 X를 또 나눌 수 있다. Test도 전처리하지만 원본 루프에서 평가하지 않는다.

Dense(...)(x)의 첫 괄호는 Layer 생성, 두 번째 괄호는 호출이다. 변수 x를 재대입하면 가리키는 Tensor가 달라질 뿐 앞 Layer 연결이 사라지지 않는다. Model(inputs, outputs)는 최종 출력까지의 연결을 모델로 구성한다.

he_normal은 은닉 Dense128에만 명시했다. 출력 Dense10에는 활성화·초기화를 별도 지정하지 않았다. 이번은 은닉층 하나·출력 하나이며 이전의 짝홀 분류를 이어 학습하는 모델이 아니다.

원본 모델 구조에 따른 보완 계산 · Summary 출력 아님

변수와 Gradient의 대응
변수 Shape Parameter 수 Gradient Shape
첫 Dense Kernel (784,128) 100,352 (784,128)
첫 Dense Bias (128,) 128 (128,)

Dense의 기본 Bias 사용을 포함한 계산이다. 학습 변수 Tensor는 Kernel·Bias 두 쌍, 총 네 개다. 이 Tensor 안의 수치 개수가 101,770개다. Batch Size를 Parameter 수에 곱하지 않는다.

Gradient는 대응 변수와 같은 Shape지만 변수의 현재 값과는 다른 값이다. 실제 Gradient 수치나 모델 Summary를 이번 원본이 출력한 것은 아니다.

09

Logits·수식·Loss 해석

정수 Label과 Logits를 함께 읽는다

Logits는 확률이 아니다. 음수가 될 수 있고 합이 1일 필요가 없다. Softmax가 없다는 사실만으로 회귀라고 판단하지 않는다. 이번은 정수 Class 정답·Dense10·Sparse 분류 Loss의 조합이다.

from_logits=True는 Loss가 값을 해석하는 설정이다. model(X_batch)의 반환값을 확률로 바꾸거나 logits 변수를 수정하지 않는다. Sparse는 Pixel의 0 개수가 아니라 정답 표현을 가리킨다.
y_batch (B,) + logits (B,10)
→
loss_fn 호출
→
평균 Batch Loss ()

Step 1·2의 보완 수식

pi,k = exp(zi,k) / ∑j=0…9 exp(zi,j)
ℓi = −log pi,yᵢ = −zi,yᵢ + log ∑k=0…9 exp(zi,k)
Lbatch = (1/B) ∑i=1…B ℓi

z는 Logits, yᵢ는 실제 숫자 Class다. 정답 Class에 부여한 확률이 클수록 해당 Sample의 손실은 작아진다. 원문은 지수·로그를 직접 구현하지 않고 내장 Loss를 사용한다.

설명용 수치 계산
정답 Class 확률 Sample 손실
0.9 −log(0.9) ≈ 0.1054
0.1 −log(0.1) ≈ 2.3026

원문 Loss는 별도 reduction을 지정하지 않아 Batch의 집계 스칼라로 읽는다. 정답과 Logits의 Shape가 다른 것은 정상이다. from_logits=True의 Loss 앞에 Softmax를 따로 적용하지 않는다.

왜 필요한가?

60,000 = 64×937 + 32
937개의 일반 Batch + 1개의 작은 Batch = 938개
설정에서 도출한 계산
항목 값
epochs 1

Step Index 0~937
마지막 Batch 32개

원본 Cell 전체·실행 흐름

Forward·Loss·Gradient·Update를 연결한다

교안 원문 · Cell 7

#맞춤 학습 루프
for epoch in range(epochs):
    print(f"\nEpoch {epoch+1}/{epochs}")
    for step, (X_batch, y_batch) in enumerate(train_dataset):
        with tf.GradientTape() as tape:
            logits = model(X_batch)
            loss = loss_fn(y_batch, logits)
        grads = tape.gradient(loss, model.trainable_weights)
        optimizer.apply_gradients(zip(grads, model.trainable_weights))

        if step % 100 == 0:
            print(f"Step {step}: loss = {loss.numpy():.4f}")
무엇을 하는가?
Dataset을 순회하며 예측·손실·미분·변수 갱신을 반복한다.
왜 필요한가?
fit 대신 실제 학습을 진행한다.
입력 Shape·대상
X_batch (B,28,28), y_batch (B,).
출력 Shape·반환값
Logits (B,10), Loss (), 변수별 Gradient; 일부 Step의 문자열.
실행 후 변화
모델 Parameter·Optimizer 상태가 변한다. 자동 History는 만들지 않는다.
Epoch 반복문

epoch=0 → 화면에는 Epoch 1/1

Batch 반복문

step=0…937, 현재 X_batch·y_batch

Tape 안

model(X_batch) → loss_fn(y_batch, logits)

Tape 밖 · Batch 반복문 안

tape.gradient → zip → apply_gradients → 조건부 print

모델·Optimizer는 반복문 밖에서 생성했다. Batch마다 새 모델을 만드는 것이 아니다. enumerate의 step은 이미지 번호가 아니라 Batch Index이며 0부터 시작한다.

if step % 100 == 0은 출력 조건이다. 업데이트는 그 조건 앞에서 모든 Batch에 수행한다. 들여쓰기를 바꾸어 업데이트를 if 안으로 넣으면 원문과 다른 학습이 된다.

Tape·직접 모델 호출

미분할 계산을 Tape 안에 둔다

교안 원문 · Cell 7 발췌

with tf.GradientTape() as tape:
    logits = model(X_batch)
    loss = loss_fn(y_batch, logits)
무엇을 하는가?
연산 기록 범위 안에서 Forward와 Loss를 계산한다.
왜 필요한가?
Loss가 어떤 변수의 연산을 거쳤는지 추적한다.
입력 Shape·대상
X (B,28,28), 정수 y (B,).
출력 Shape·반환값
logits (B,10), loss ().
실행 후 변화
실제 계산 Tensor와 미분용 기록이 생긴다. Weight는 아직 갱신하지 않는다.

기본 Tape는 기록 범위에서 사용된 학습 가능한 변수를 자동 추적한다. 원문은 개별 Weight에 tape.watch를 호출하지 않는다. with를 나왔다는 것은 기록 범위가 끝났다는 뜻이며 그 뒤에서 gradient를 요청할 수 있다.

모델 구성 시 outputs는 기호적 연결의 Tensor다. 지금 logits는 실제 X_batch를 계산한 Tensor다. 원문은 Tape 안에서 predict가 아니라 model(X_batch) 직접 호출을 사용한다.

training=True 미지정: 원문 호출을 그대로 보존했다. 현재 모델은 Flatten·Dense·ReLU이며 Dropout·BatchNormalization이 없다. 인자가 없다는 이유만으로 학습하지 않는다고 볼 수 없다. 학습·추론 모드에 따라 동작이 다른 Layer를 추가하면 별도 관리가 필요하다.

loss_fn은 손실 객체이고 loss는 현재 Batch 손실이다. 이 Loss는 Test 전체나 지금까지 본 Training 전체의 평균이 아니다. 원문은 그런 집계를 작성하지 않았다.

Gradient·Variable·Update

미분 계산과 실제 갱신을 분리한다

교안 원문 · Cell 7 발췌

grads = tape.gradient(loss, model.trainable_weights)
optimizer.apply_gradients(zip(grads, model.trainable_weights))
무엇을 하는가?
손실의 변수별 Gradient를 구하고 대응 변수에 적용한다.
왜 필요한가?
계산된 미분값을 실제 모델 변화로 연결한다.
입력 Shape·대상
스칼라 Loss와 네 학습 변수.
출력 Shape·반환값
변수와 같은 Shape의 Gradient 네 개; 업데이트 반환값은 저장하지 않음.
실행 후 변화
gradient 줄은 계산만 한다. apply_gradients 줄이 모델·Adam 상태를 갱신한다.
Loss ()
→
tape.gradient(loss, 변수 목록)
→
grads: 변수와 같은 Shape
→
zip(grads, 변수 목록)
→
Adam으로 갱신

설명용 기호로 zip의 쌍은 (dW1,W1), (db1,b1), (dW2,W2), (db2,b2)다. 이 이름들은 원문에서 별도로 선언한 변수가 아니다. 두 목록의 순서를 독립적으로 바꾸지 않는다.

Batch마다 새 Tape를 만들고 기본 Tape에 한 번 미분을 요청한다. 다음 Batch에서는 새 Forward·Loss·Gradient를 계산한다. 여러 Batch의 Gradient를 따로 누적하는 코드는 없다.

Adam 상태 ≠ Gradient 누적 코드. Optimizer가 과거 모멘트 정보를 관리하는 것과 개발자가 여러 Batch의 Gradient를 모아 한 번 적용하는 것은 다르다. 실제 Gradient의 수치·0·None 여부는 원본에 출력되지 않았다.

원본 기록이 답하는 범위
항목 원본 상태

전체 Training Loss·Accuracy 계산·집계 없음
Validation Loss·Accuracy 분리·계산 없음
Test Loss·Accuracy 평가 없음

최적 Checkpoint 선택·저장 없음

Step 600의 0.1289와 Step 700의 0.3321은 서로 다른 Batch·Parameter 시점에서 계산했다. 이런 변동만으로 과적합을 판정하거나 Step 600을 최적 모델로 선택할 수 없다. 원문은 그 Weight를 저장하지 않는다.

Accuracy = 맞힌 Sample 수 / 평가 Sample 수
Loss ≠ 오분류율 · Accuracy ≠ 1−Loss

정확도를 구한다면 logits (B,10)의 Class 축에 argmax를 적용한 (B,)와 정수 y (B,)를 비교한다. y는 이미 정수이므로 y에 argmax(axis=1)을 적용하지 않는다. SparseCategoricalAccuracy는 이런 일치를 집계하며 Logits도 받을 수 있다.

R²는 회귀 평가 지표다. 이번 0~9는 Class 번호이므로 번호 사이 차이를 회귀 오차처럼 평가하지 않는다. 원본에 R² 계산은 없다.

열 개 출력값의 평균은 Epoch 평균이 아니다

938개 Batch 중 열 개만 출력했다. 모든 Batch 손실을 모았다고 가정하면 Sample 기준 평균은 다음처럼 Batch 크기를 반영한다.

Ltraining record = ∑s BsLs / ∑s Bs

마지막 Batch는 32개다. 이 값도 학습 중 변하는 Parameter의 기록이며 최종 모델을 고정해서 다시 평가한 손실과 다르다. 원본에는 필요한 전체 기록이 없다.

X_test[0]은 (28,28), X_test[:1]은 (1,28,28)이다. 이미 변환한 X에 /255.0을 다시 적용하지 않는다. y_test[0]은 정수 정답이므로 그대로 조회한다.

argmax(z) = argmax(softmax(z)) 같은 행의 유한한 Logits에서 크기 순서를 유지한다는 수식 해석

Class만 필요하면 Logits의 argmax를 사용할 수 있다. 확률을 표시하려면 별도로 Softmax를 적용한다. 이 추론용 확률 표시와 학습 Loss의 from_logits=True는 다른 단계다. 높은 예측 확률을 절대적인 정답 보장으로 읽지 않는다.

Q1. Functional API와 Custom Loop는 무엇이 다른가?

Q2. 원문은 compile·fit을 호출하는가?

아니다. Loss·Optimizer 객체와 반복문을 직접 사용한다.

반복과 호출 순서는 작성하지만 Gradient는 자동미분으로 계산한다.

0~9 정수 Class Label이며 전체 Shape는 (N,)다.

Softmax를 지정하지 않아 Logits로 사용한다.

정답이 One-Hot이 아닌 정수 Class Index이기 때문이다.

Loss의 예측값 해석이다. 모델의 반환 Tensor를 확률로 바꾸지 않는다.

60,000 = 64×937 + 32이기 때문이다.

별도의 shuffle 호출은 없다.

Q12. Gradient를 구하면 Weight도 바뀌는가?

아니다. apply_gradients가 갱신한다.

Q13. zip의 역할은?

각 Gradient와 대응하는 학습 변수를 짝짓는다.

Q14. 100 Step마다만 업데이트하는가?

아니다. 출력만 조건부이고 업데이트는 매 Batch에 수행한다.

Q15. Step 0 Loss의 계산 시점은?

첫 업데이트 이전에 계산하고 업데이트 이후에 표시한다.

정상 완료라면 Step 937까지 계속한다.

아니다. Step 900의 Training Batch Loss다.

계산·저장한 수치가 없다.

현재 기록만으로 판정할 수 없다. 고정 평가와 저장 절차가 없다.
