01핵심 개념 · 특징을 계산하고 분류기를 학습합니다

문제는 고양이·개 이미지에서 0 또는 1을 예측하는 이진 분류입니다. 사전학습 VGG19의 표현을 새 과제에 사용하는 특징 추출 기반 전이학습입니다.

VGG19의 역할

이미지를 4,096개 숫자로 표현합니다. 현재 데이터에는 predict만 수행하므로 가중치를 업데이트하지 않습니다.

LR·SVC의 역할

특징과 정답을 받아 고양이·개 구분 기준을 학습합니다. 두 분류기는 같은 특징을 각각 사용합니다. 

h = fθ(x)     이미지 x → VGG19 특징 h
ŷ = gφ(h)     특징 h → 분류 결과 ŷ

θ: 사전학습 VGG19 가중치 · 이번에 업데이트하지 않음
φ: 새로운 분류기의 학습 결과 · fit으로 학습
관련 개념 구분
개념 의미 이번 사용
사전학습 다른 데이터로 학습된 가중치 ImageNet VGG19
특징 추출 전이학습 기존 표현을 새 과제의 분류에 활용 수행
미세조정 기존 CNN 가중치 추가 학습 수행하지 않음
추론 현재 가중치로 출력 계산 VGG19 특징 계산

작은 데이터에서 대형 CNN 전체를 처음부터 학습하는 부담을 줄이고, 같은 특징으로 여러 분류기를 비교할 수 있습니다. 새로 학습하는 부분이 작아져도 VGG19 자체의 계산·메모리 비용은 남습니다. 항상 최선의 방법이라는 뜻은 아닙니다.

4,096개 값은 클래스 확률이 아닙니다. 합이 1일 필요가 없고 1보다 클 수 있습니다. 각 특징이 반드시 눈·귀·꼬리를 뜻한다고 단정하지 않습니다. 원시 픽셀 150,528개를 단순 reshape한 결과도 아닙니다.

생략된 기본값은 weights='imagenet', include_top=True, classes=1000, 최종 softmax입니다. None은 가변 배치 크기입니다. weights=None은 사전학습 로드 없이 무작위 초기화한다는 별도의 의미입니다.

  1. Image batch(B,224,224,3)
  2. Conv + ReLU 반복작은 3×3 필터
  3. Pooling 반복224→112→56→28→14→7
  4. Feature Map(B,7,7,512)
  5. Flatten(B,25088)
  6. fc1 + ReLU(B,4096)
  7. fc2 + ReLU(B,4096) · 이번 추출
  8. 새 ML 분류기LogisticRegression 또는 SVC
  9. Prediction(B,) · 고양이 0 / 개 1

원래 VGG19의 별도 끝점은 fc2 → predictions → (B,1000)입니다. 이번 경로는 이 1000클래스 층을 거치지 않고 fc2의 4096개 특징을 바로 ML 분류기에 전달합니다.

블록별 출력 Shape
단계 구성 출력
Block 1 Conv64 두 번 + Pool (B,112,112,64)
Block 2 Conv128 두 번 + Pool (B,56,56,128)
Block 3 Conv256 네 번 + Pool (B,28,28,256)
Block 4 Conv512 네 번 + Pool (B,14,14,512)
Block 5 Conv512 네 번 + Pool (B,7,7,512)

20자주 틀리는 Shape·라벨·실행 순서

검토·교정 “차원”이라는 말을 축의 수와 특징 수에 섞어 쓰면 설명이 흔들립니다. shape는 각 축의 크기, ndim은 축 개수, dtype은 원소의 자료형입니다.

Shape·축·특징 수를 정확히 말하기
대상 Shape / ndim 의미
이미지 한 장 (224,224,3) / 3 높이·너비·색 채널. 한 샘플에도 세 축이 있습니다.
CNN 입력 배치 (2000,224,224,3) / 4 맨 앞에 샘플 축을 붙입니다. 원문 변환 배열은 float32입니다.
fc2 특징 전체 (2000,4096) / 2 2000개 샘플, 샘플당 4096개 특징. “4096차원 특징 벡터”를 모은 2차원 배열입니다.
특징 한 행 (4096,) / 1 X[0]은 1차원입니다. 한 샘플을 ML에 넣을 때 X[0:1]로 (1,4096)을 유지합니다.
정답·일반 분류 예측 (N,) / 1 샘플마다 라벨 하나. 이진 분류라고 반드시 (N,2)가 되는 것은 아닙니다.
  1. 라벨 1000개씩은 파일 개수가 맞을 때만 맞습니다. 원문은 cats 목록 다음 dogs 목록을 이어 붙이고 [0]*1000+[1]*1000을 만듭니다. 실제 파일이 고양이 900장·개 1100장이면 총 2000장은 같지만, 첫 개 100장에 고양이 라벨이 붙습니다. 길이 검사만으로는 잡히지 않으므로 파일 목록과 라벨을 함께 관리합니다.
  2. 분할 셀만 재실행하면 원래 자료가 유지되지 않습니다. 원문은 X_train과 y_train을 훈련 부분으로 덮어씁니다. 처음 2000개가 1600개가 되고, 같은 셀을 다시 실행하면 1280개가 될 수 있습니다. random_state=42도 바뀐 입력을 복원하지 않습니다.
  3. 전처리는 원본 RGB에서 한 번만 적용합니다. preprocess_input을 이미 처리한 배열에 다시 적용하면 채널과 평균 보정이 중복됩니다. 원본 보존용 복사본을 두며 무조건 /255를 추가하지 않습니다.
  4. 배열 이름으로 단계를 판단하지 않습니다. X_train은 처음에는 전체 2000개의 특징이고, 분할 이후에는 훈련 1600개의 특징입니다. 셀 실행 시점과 실제 Shape를 함께 확인합니다.
  5. CNN의 4차원 입력과 ML의 2차원 입력을 구분합니다. 원본 픽셀을 LogisticRegression에 그대로 넣거나 fc2 벡터를 VGG에 다시 넣으면 입력 의미가 맞지 않습니다.
  6. 오류 없이 실행돼도 계산이 틀릴 수 있습니다. 예측 (3,)과 정답 (3,1)을 비교하면 NumPy가 (3,3)으로 broadcasting하여 아홉 쌍을 비교합니다. 
# 보충 예시: 모델을 실행하지 않고 shape 함정만 확인
pred = np.array([0, 1, 0])         # (3,)
truth = np.array([[0], [1], [0]])  # (3, 1)
print((pred == truth).shape)       # (3, 3): 샘플별 비교가 아님
print((pred == truth.ravel()).shape)  # (3,): 의도한 비교
print(np.mean(pred == truth.ravel())) # 1.0

위 예에서 잘못된 비교를 평균 내면 5/9, 합을 샘플 수 3으로 나누면 5/3까지 나옵니다. 정확도가 이상할 때는 모델 성능보다 y_pred.shape와 np.asarray(y_test).shape부터 확인합니다.

ML 수렴 경고·성능 저하 ML 입력 스케일과 solver·반복 상한·정규화를 확인합니다. 학습률을 무조건 낮추는 것으로 설명하지 않습니다.

용어 교정 lr_model = LogisticRegression()에서 lr은 변수 이름에 붙인 Logistic Regression의 약자입니다. lr_model을 learning rate 값이라고 읽으면 안 됩니다.

C
LogisticRegression·SVC의 정규화 강도와 관련됩니다. 일반적으로 C가 작을수록 더 강한 정규화가 적용됩니다. 학습률이 아닙니다.
gamma
RBF SVC의 커널 영향 범위와 관련됩니다. 원문 저장 설정은 gamma='scale'입니다. 학습률이 아닙니다.
max_iter
최적화 반복의 상한입니다. 원문 저장 LogisticRegression은 100, SVC는 -1이며 SVC의 -1은 상한을 두지 않는 설정입니다. 반복 한 번의 이동 크기를 뜻하지 않습니다.

개선 검토 라벨·분할·전처리의 정확성을 먼저 확인하고, 같은 훈련/검증 조건에서 ML 설정을 비교합니다. 스케일링을 추가하면 train에서만 학습하고 test에도 동일하게 적용합니다. 다른 특징 층이나 미세조정은 별도 실험이며, 원문의 98%보다 반드시 좋아진다고 보장할 수 없습니다.

24구술·면접 대비 24문답

답을 가리고 먼저 설명한 뒤 펼쳐 확인합니다. 원문 실행 흐름, 저장 결과, 검토·교정을 구분하여 말하는 것이 중요합니다.

01. 이번 단원의 전체 흐름을 한 문장으로 말하면?

ImageNet으로 사전학습된 VGG19를 이용해 개·고양이 이미지에서 4096개 특징을 추출하고, 그 특징과 정답으로 LogisticRegression과 SVC를 학습해 분류합니다. CNN은 특징 추출기, ML은 새 문제의 분류기 역할입니다.

02. 앞 단원의 사전학습 모델 예측과 무엇이 다른가?

사전학습 모델의 1000개 ImageNet 출력을 그대로 해석하는 대신, 이번에는 최종 분류층 이전의 특징을 가져와 개·고양이용 분류기를 따로 학습합니다. CNN 계산을 이용한다는 공통점과 최종 판정기의 차이를 함께 설명합니다.

03. 작은 데이터셋에 사용하는 이유는?

큰 자료에서 배운 시각적 표현을 재사용하므로 모든 CNN 가중치를 작은 자료로 처음부터 학습할 부담을 줄입니다. 다만 사전학습 자료와 새 이미지의 성격이 다르면 효과가 달라지므로 성능이 보장되는 것은 아닙니다.

04. VGG19의 19는 모든 레이어 수인가?

가중치를 갖는 16개 합성곱층과 3개 완전연결층을 세는 명칭입니다. pooling·flatten·입력층까지 포함한 model summary의 행 수와 같은 뜻이 아닙니다.

05. 이미지 입력이 왜 4차원인가?

(B,224,224,3)에서 B는 샘플 수, 나머지는 높이·너비·색 채널입니다. 한 장은 3차원이지만 모델에 배치로 전달하면 샘플 축이 추가됩니다.

06. VGG19 전처리에서 실제로 무엇을 하는가?

RGB 채널을 BGR로 바꾸고 ImageNet 기준 채널 평균을 뺍니다. 픽셀을 단순히 0~1로 바꾸는 /255와 같지 않습니다. 학습과 새 이미지 예측에 같은 규칙을 한 번 적용해야 합니다.

07. 전처리 후 그림 색이 이상하고 clipping 경고가 나면?

평균을 뺀 배열에는 음수가 있고 채널 순서도 표시용 RGB와 다릅니다. 원문 경고는 이 배열을 표시한 상황입니다. 원본 RGB 이미지를 표시하는 문제와 모델에 맞는 수치 입력을 만드는 문제를 구분합니다.

08. fc2 출력은 확률인가, 선형 출력인가?

둘 다 아닙니다. VGG19 fc2는 ReLU를 통과한 4096개 특징입니다. 최종 softmax 층을 제외했다고 모든 활성화 함수가 사라지는 것은 아닙니다. 각 값은 클래스 확률이 아니며 합이 1일 필요도 없습니다.

09. base_model.output으로 바꿔도 같은 특징인가?

기본 VGG19의 base_model.output은 predictions의 1000개 ImageNet 클래스 출력입니다. get_layer('fc2').output의 4096개 특징과 Shape·의미가 다르므로 서로 같은 코드가 아닙니다.

10. fc2 출력은 4096개인가, 편향까지 4097개인가?

출력은 4096개입니다. 편향은 각 출력 유닛에 더하는 학습 파라미터이며 별도 특징 열로 붙지 않습니다. fc2 파라미터 수는 4096×4096+4096=16,781,312입니다.

11. summary에 trainable이라고 나오면 이번에도 학습한 것인가?

trainable은 훈련에서 가중치 업데이트 대상으로 삼을 수 있다는 속성입니다. 원문은 VGG에 predict만 호출하므로 개·고양이 자료로 VGG 가중치를 업데이트하지 않습니다. 실제 학습 호출은 ML의 fit입니다.

12. 파라미터가 143,667,240개에서 139,570,240개로 줄어든 이유는?

마지막 1000개 분류층의 파라미터 4096×1000+1000=4,097,000개를 제외한 출력 모델이기 때문입니다. 전체 모델이 원래 객체에서 삭제됐거나 나머지 층을 재학습했다는 뜻은 아닙니다.

13. VGG predict 결과가 왜 0 또는 1이 아닌가?

호출한 모델의 출력 끝점이 fc2이기 때문입니다. Keras의 predict는 모델 출력값을 계산하는 메서드이며, 항상 클래스 라벨을 반환한다는 뜻이 아닙니다. 개·고양이 라벨은 이후 ML 분류기가 예측합니다.

14. 샘플당 4096차원인데 전체 배열이 2차원이라는 말은?

한 샘플의 특징 개수가 4096개라는 의미와 배열 축이 샘플·특징의 두 개라는 의미를 구분합니다. 전체 (2000,4096) 배열은 ndim=2이고, 한 행 (4096,)은 ndim=1입니다.

15. 주석의 GAP 대안도 4096개를 출력하는가?

아닙니다. block5_pool의 (B,7,7,512)에 GlobalAveragePooling2D를 적용하면 공간축을 평균내 (B,512)가 됩니다. 원문에서는 주석 처리된 대안이며 실제 저장 특징 (2000,4096)과 구분합니다.

16. cats가 0, dogs가 1이라고 말할 근거는?

파일 목록을 cats 다음 dogs 순서로 연결하고 라벨을 0 천 개 다음 1 천 개로 만들었기 때문입니다. 폴더명에서 자동 추론한 라벨이 아닙니다. 실제 각 폴더 파일 수가 천 개인지까지 맞아야 합니다.

17. stratify와 random_state는 각각 무엇인가?

층화 분할은 클래스 비율을 유지하도록 나누며, 정수 random_state는 같은 입력과 조건에서 분할을 재현하도록 돕습니다. 저장 훈련 라벨은 0·1 각각 800개입니다. 두 옵션이 라벨 오류·중복·누수를 없애 주지는 않습니다.

18. 전체 특징을 만든 뒤 나누면 반드시 누수인가?

고정 VGG를 각 이미지에 독립적으로 적용하는 것 자체는 새 데이터에서 무엇을 학습하는 과정이 아닙니다. 반면 전체 데이터로 scaler·PCA·특징 선택을 학습하거나 CNN을 미세조정하면 평가 정보가 들어갈 수 있습니다.

19. LogisticRegression은 회귀인가, 분류인가?

이 클래스는 분류기입니다. 이름에 Regression이 있어도 이 실습에서는 개·고양이 라벨을 예측합니다. lr_model이라는 변수명의 lr을 신경망의 learning rate로 읽지 않습니다.

20. 정확도 0.98은 구체적으로 무엇을 뜻하는가?

원문 test 400개에서 정확도가 98%이므로 맞힌 수는 392개, 틀린 수는 8개로 계산됩니다. 전체 모집단이나 다른 사진에서도 반드시 98%라는 의미는 아닙니다. 이미지별 예측 확률이 98%라는 뜻도 아닙니다.

21. score와 직접 비교한 계산은 왜 같은가?

이 분류기의 score(X,y)는 정확도이며, 원문의 np.sum(y_pred==y_test)/len(y_pred)도 샘플별 일치 비율입니다. 같은 모델·자료·일차원 라벨을 비교해야 같은 의미가 됩니다. Shape가 달라 broadcasting되면 이 전제가 깨집니다.

22. 기본 SVC의 predict가 확률을 출력하는가?

원문 SVC는 kernel='rbf', gamma='scale', probability=False입니다. predict는 클래스 라벨을 반환하며, score 0.98을 개별 확률로 읽지 않습니다. probability 관련 설정은 별도의 문제입니다.

23. 두 모델이 0.98이면 똑같은 모델인가?

맞힌 전체 개수가 같다는 뜻일 뿐입니다. 틀린 이미지, 결정 경계, 확신 정도, 학습·예측 시간은 다를 수 있습니다. 원문에는 이 차이를 판단할 오류 목록과 train 곡선이 없어 우열을 더 단정할 수 없습니다.

24. 새 이미지 한 장을 예측할 때 무엇을 재사용하는가?

같은 RGB·크기·VGG 전처리와 같은 fc2 추출기로 (1,4096) 특징을 만든 뒤 이미 학습된 ML 모델에 전달합니다. 예측할 이미지에서 다시 fit하지 않습니다. 추가 전처리와 라벨 매핑까지 같아야 0·1을 올바르게 해석할 수 있습니다.
