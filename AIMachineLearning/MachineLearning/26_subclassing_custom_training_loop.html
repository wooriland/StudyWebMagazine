X/y·모델 흐름·Shape

이미지는 Feature로, 정답은 Class Index로

X_train[i]와 y_train[i]는 같은 Sample이어야 한다. 설명용으로 숫자 3의 이미지라면 y는 정수 3이다. 이미지를 실제로 표시하는 코드는 원본에 없다.

Sample·Batch·추론의 규격 — Step 1·2 보완
대상 이미지 X 정답 y
Training 전체 (60000,28,28) (60000,)
Test 전체 (10000,28,28) (10000,)
Dataset의 Sample 하나 (28,28) () — 스칼라
일반 Training Batch (64,28,28) (64,)

B는 현재 Sample 수다. ()는 스칼라, (1,)은 원소 하나인 1차원 배열이다. 정답 (B,)와 Logits (B,10)의 차이는 Sparse Loss에서 정상이다. 정답은 Class 하나, 예측은 열 개 점수이기 때문이다.

ML 25는 숫자 One-Hot·짝홀 0/1과 출력 딕셔너리였지만, 이번은 정수 숫자 정답과 Logits Tensor 하나다. first_output·second_output Key나 정답 argmax를 가져오지 않는다.

07

Model Architecture·원문

__init__은 부품 준비, call은 실제 계산

교안 원문 · Cell 4

# 모델 정의
class MyModel(Model):
    def __init__(self):
        super(MyModel, self).__init__()
        self.flatten = Flatten()
        self.d1 = Dense(128, activation='relu',kernel_initializer='he_normal')
        self.d2 = Dense(10)

    def call(self, x, training=False):
        x = self.flatten(x)
        x = self.d1(x)
        return self.d2(x)
무엇을 하는가?
Model을 상속하여 Layer와 순전파를 정의한다.
왜 필요한가?
입력에서 숫자별 점수를 계산할 구조가 필요하다.
입력 Shape
클래스 정의 시 입력 없음. call은 (B,28,28)을 처리한다.
출력 Shape
call의 반환값은 (B,10) Tensor다.
실행 후 변화
MyModel 설계가 준비된다. 실제 객체는 다음 Cell에서 만든다.

super(MyModel, self).__init__()는 부모 초기화다. self.flatten·self.d1·self.d2에 같은 Layer를 보관한다. Keras는 모델 속성의 내부 Layer 변수를 추적한다.

속성과 계산
속성 역할 설정
self.flatten 이미지별 Pixel 펼치기 학습 Parameter 없음
self.d1 128개 은닉 특징 ReLU·he_normal
self.d2 10개 Class 점수 활성화·초기화 별도 명시 없음

call에서 x를 재대입하는 것은 다음 Layer에 넘길 계산 결과가 바뀌는 것이다. Weight가 초기화되는 것이 아니다. call 안에서 매번 새 Layer를 만드는 코드로 변경하지 않는다.

training=False는 학습 금지가 아니다. 원문은 training 인자를 받지만 내부에서 분기하지 않는다. Dropout·BatchNormalization도 없다. trainable과 실행 모드를 구분하며 실제 업데이트는 뒤의 apply_gradients에서 한다.

Loss·Logits·compile 대응

정수 Label + Logits + Sparse Cross-Entropy

교안 원문 · Cell 6

# 손실함수, 옵티마이저
loss_fn = tf.keras.losses.SparseCategoricalCrossentropy(from_logits=True)
optimizer = tf.keras.optimizers.Adam()
무엇을 하는가?
손실 객체와 Adam 객체를 준비한다.
왜 필요한가?
compile 대신 루프에서 손실·업데이트를 직접 호출한다.
입력 Shape
객체 생성 시 실제 Batch 입력 없음.
출력·반환값
loss_fn과 optimizer.
실행 후 변화
학습 규칙이 준비된다. Loss 계산·업데이트는 아직 없다.
각 설정의 의미
항목 이번 의미
Sparse 정답이 One-Hot이 아니라 정수 Class Index
Categorical 여러 Class 중 하나를 선택
from_logits=True 예측을 확률 변환 전 Class 점수로 받음
기본 손실 집계 · 보완 sum_over_batch_size → 이번 Batch 평균 스칼라

Sparse는 이미지에 0이 많다는 뜻이 아니다. Dense10에 활성화를 지정하지 않아 선형 변환 점수를 반환한다. 정수 Class·10개 점수·분류 Loss의 조합이므로 Softmax Layer가 없어도 다중 분류다.

Logits는 음수가 가능하고 합이 1일 필요가 없다. 확률 표시가 필요하면 별도로 Softmax를 적용한다. from_logits=True가 logits 변수 자체를 확률로 바꾸는 것은 아니다.

pi,k = exp(zi,k) / ∑j=0…9exp(zi,j)
ℓi = −log pi,yᵢ = −zi,yᵢ + log ∑k=0…9exp(zi,k)
Lbatch = (1/B)∑i=1…Bℓi Step 1·2 보완 수식. 원문이 지수·로그 연산을 직접 구현한 것은 아니다.
출력층에 Softmax를 추가하면서 from_logits=True를 그대로 유지하는 식으로 조합을 바꾸지 않는다. ML 25의 One-Hot·Categorical Loss도 이번 원문과 다르다.

Cell 6의 tf.keras.optimizers.Adam()은 학습률을 별도 인자로 쓰지 않는다. Step 1·2의 API 보완에 따르면 기본 학습률은 0.001이다. 원문에 lr=0.001이라는 선언이 있는 것처럼 제시하지 않는다.

Adam은 Gradient의 1차·2차 모멘트 추정치를 사용한다. 과거 통계를 관리하는 것과 여러 Batch의 Gradient를 모아 한 번에 적용하는 Gradient Accumulation은 다르다. 이번에는 별도 누적 코드가 없다.

핵심 원문·학습 흐름

직접 작성한 학습 루프 전체

교안 원문 · Cell 8

#맞춤 학습 루프
for epoch in range(epochs):
    print(f"\nEpoch {epoch+1}/{epochs}")
    for step, (X_batch, y_batch) in enumerate(train_dataset):
        with tf.GradientTape() as tape:
            logits = model(X_batch)
            loss = loss_fn(y_batch, logits)
        grads = tape.gradient(loss, model.trainable_weights)
        optimizer.apply_gradients(zip(grads, model.trainable_weights))

        if step % 100 == 0:
            print(f"Step {step}: loss = {loss.numpy():.4f}")

왜 필요한가?

순전파·Loss·자동미분

Tape는 Loss와 Weight 사이의 계산을 기록한다

Cell 8의 with tf.GradientTape() as tape: 안에 모델 호출과 손실 계산이 들어 있다. 기본 Tape는 계산에 사용된 학습 가능 변수를 추적한다. 미분식 전체를 NumPy로 다시 작성하는 과정이 아니다.

각 호출의 의미·입출력·상태
호출 무엇을·왜 입력 → 출력 실행 후 변화
model(X_batch) 정답과 비교할 예측 점수 계산 (B,28,28) → (B,10) Logits 생성. 첫 호출 시 필요한 Weight 준비
loss_fn(y_batch, logits) 학습 목적함수 값 계산 (B,), (B,10) → () 현재 Batch Loss 생성, 아직 업데이트 아님
tape.gradient(loss, model.trainable_weights) 각 학습 변수에 대한 미분 요청 스칼라 Loss·변수 목록 → Gradient 목록 미분값 생성, 아직 업데이트 아님
Weight → 모델 연산 → Logits → Loss 손실 숫자만이 아니라 변수에서 그 숫자로 이어진 계산 관계가 필요하다.
모델 구조에서 도출한 변수·Gradient Shape
변수 변수 Shape Gradient Shape
첫 Dense Kernel (784,128) (784,128)
첫 Dense Bias (128,) (128,)
출력 Dense Kernel (128,10) (128,10)
출력 Dense Bias (10,) (10,)

각 Batch에서 새 Tape를 만들고 한 번 미분한다. 기본 Tape를 반복 재사용하는 구조가 아니므로 persistent=True를 원문에 추가하지 않는다. 실제 Gradient 수치는 저장되어 있지 않다.

Gradient 대응·실제 업데이트

zip은 미분값과 적용할 변수를 짝짓는다

원문의 zip(grads, model.trainable_weights)는 같은 순서의 Gradient와 변수를 대응시킨다. 두 목록의 순서를 따로 바꾸지 않는다.

(dW1, W1) · (db1, b1) · (dW2, W2) · (db2, b2) W1·b1 등은 설명용 기호이며 원문의 별도 변수 선언이 아니다.
무엇을 하는가?
optimizer.apply_gradients(...)로 Adam 업데이트를 적용한다.
왜 필요한가?
Gradient를 구한 것과 실제 변수를 바꾸는 것은 다르다.
입력 Shape·대상
각각 Shape가 대응하는 (Gradient, 학습 변수) 쌍.
출력·반환값
원문은 반환값을 사용하지 않는다.
실행 후 변화
모델 Parameter와 Adam 내부 상태가 업데이트된다.
업데이트 줄은 출력용 if 바깥에 있다. 조건 안으로 들여쓰면 100 Step마다만 적용하는 다른 코드가 된다. 원문은 모든 Batch에 업데이트한다.

call()을 작성하거나 Loss를 계산한 사실만으로 학습이 진행되었다고 보지 않는다. gradient 계산과 apply_gradients 실행까지 연결해야 한다.

Loss·Accuracy·R²

부분 로그의 평균은 Epoch 평균이 아니다

원본은 정확도 Metric·맞힌 개수·전체 Epoch Loss 집계를 만들지 않는다. 따라서 ML 25의 Test Accuracy를 가져오거나 Loss에서 정확도를 역산할 수 없다.

Accuracy = 맞힌 Sample 수 / 평가 Sample 수
Accuracy ≠ 1−Loss

정수 Label의 분류는 Logits (B,10)에 argmax를 적용해 예측 Class (B,)를 얻고 y와 비교한다. SparseCategoricalAccuracy는 이 일치를 누적하며 Logits도 받을 수 있다. 정답 y에 argmax를 적용하지 않는다.

세 가지 기록을 구분한다
기록 의미 원본에 있는가?
표시된 열 개 Loss 938 Batch 중 일부 있음
Epoch 학습 손실 집계 변하는 Parameter로 계산한 전체 Batch 기록의 집계 없음
최종 모델 평가 손실 학습 후 모델을 고정해 평가 데이터에 적용 없음
Lrecord = ∑sBsLs / ∑sBs 모든 Batch 평균 Loss와 실제 Batch 크기를 기록했을 때의 Sample 기준 집계식

별도 보완 코드·평가

학습한 모델을 고정하고 Test를 평가한다

아래는 Step 1·2의 보완 예시다. 원문에 있던 코드가 아니며, 원본 학습을 마친 기존 model·loss_fn·X_test·y_test·batch_size를 사용한다.

Step 1·2 보완 평가 코드 · 미실행

# 보완 예시: 원본 학습을 마친 뒤 실행한다.
# 이 코드는 원본 Notebook에 포함되어 있지 않다.

test_dataset = tf.data.Dataset.from_tensor_slices(
    (X_test, y_test)
).batch(batch_size)

test_loss_metric = tf.keras.metrics.Mean(name="test_loss")
test_accuracy_metric = tf.keras.metrics.SparseCategoricalAccuracy(
    name="test_accuracy"
)

for X_eval_batch, y_eval_batch in test_dataset:
    eval_logits = model(X_eval_batch, training=False)
    eval_loss = loss_fn(y_eval_batch, eval_logits)

    tf.debugging.assert_all_finite(
        eval_loss,
        "평가 Loss에 NaN 또는 Inf가 있습니다."
    )

    # eval_loss는 현재 Batch의 평균이므로
    # 전체 Sample 평균을 위해 실제 Batch 크기를 가중치로 사용한다.
    current_batch_size = tf.cast(
        tf.shape(y_eval_batch)[0],
        tf.float32
    )

    test_loss_metric.update_state(
        eval_loss,
        sample_weight=current_batch_size
    )

    test_accuracy_metric.update_state(
        y_eval_batch,
        eval_logits
    )

print("Test Loss:", float(test_loss_metric.result().numpy()))
print("Test Accuracy:", float(test_accuracy_metric.result().numpy()))
무엇을 하는가?
현재 모델의 Test 전체 Loss·Accuracy를 집계한다.
왜 필요한가?
원본의 부분 Training 로그와 별도 평가를 구분한다.
입력 Shape
각 X (B,28,28), y (B,).
출력·반환값
Test 평균 Loss·Accuracy 집계값.
실행 후 변화
Metric 상태만 누적한다. Gradient 적용이 없어 모델을 학습하지 않는다.
10,000 = 64×156 + 16 → 157 Test Batch 마지막 16개도 Sample 수에 맞는 비중으로 집계한다.

eval_loss는 Batch 평균이므로 Mean에 실제 Batch 크기를 sample_weight로 전달한다. update_state는 집계, result는 조회다. 동일 Metric을 재사용하면 이전 집계가 남을 수 있어 새 객체 생성 또는 reset_state가 필요하다. 위 코드는 새 객체를 만든다.

이 보완 코드는 실행하지 않았고 새 Test 결과도 제시하지 않았다. 실제 정확도는 사용자 환경에서 평가한 후 별도 결과로 기록한다. Test로 반복 튜닝하는 방식과도 구분한다.

# 보완 예시: 원본 학습을 마친 뒤 실행한다.
# 이미 정규화된 X_test의 첫 이미지를 사용한다.

sample_x = X_test[:1]

if sample_x.shape != (1, 28, 28):
    raise ValueError(f"입력 Shape를 확인하세요: {sample_x.shape}")

if not np.isfinite(sample_x).all():
    raise ValueError("입력에 NaN 또는 Inf가 있습니다.")

sample_logits = model(sample_x, training=False)

if tuple(sample_logits.shape) != (1, 10):
    raise ValueError(
        f"출력 Shape를 확인하세요: {sample_logits.shape}"

    sample_logits,
    "예측 Logits에 NaN 또는 Inf가 있습니다."

sample_probabilities = tf.nn.softmax(sample_logits, axis=-1)

    tf.argmax(sample_logits, axis=-1)[0].numpy()

    sample_probabilities[0, predicted_number].numpy()

# 이번 정답은 One-Hot이 아니라 정수 Label이다.
actual_number = int(y_test[0])

print("예측 숫자:", predicted_number)
print("선택한 숫자의 확률:", selected_probability)
print("실제 정답:", actual_number)

왜 필요한가?

출력 Shape

실행 후 변화
추론 결과만 계산한다. 새 모델·업데이트 없음.
X_test[:1]
(1,28,28)
→
model(..., training=False)
(1,10) Logits
→
argmax: 숫자
Softmax: 확률

X_test[0]은 (28,28), X_test[:1]은 (1,28,28)이다. 유한한 Logits에서 Softmax는 크기 순서를 유지하므로 Class만 필요하면 Logits에 바로 argmax를 적용한다. 정답은 이미 정수이므로 y_test[0]을 그대로 읽는다.

이미 정규화한 X를 다시 나누지 않는다. 이번 반환값에 first_output Key는 없다. 학습 후 새 MyModel을 만들면 기존 학습 모델이 아니다. 이 예시는 실행하지 않았으므로 새 숫자·확률 결과는 없다.

Data Leakage·평가 범위

누수 없음과 성능 검증 완료는 같은 말이 아니다

원문은 Training만 업데이트 Dataset에 사용한다. Test를 학습에 섞는 코드가 있다는 근거는 없다. 하지만 Test 평가를 수행한 것도 아니다.

Test를 학습에 넣지 않음 ≠ Test 성능 확인

셔플을 하지 않았다는 사실 자체를 Data Leakage라고 부르지 않는다. 데이터 순서 문제와 평가 정보가 학습·선택에 들어가는 문제는 다르다.

평균·분산·Feature 선택처럼 데이터로 규칙을 학습하는 전처리를 추가하면 Training에만 적합하고 Validation·Test에는 적용한다. Test를 반복해서 보며 Epoch·학습률·모델을 고르는 것도 평가 독립성을 해친다. 이번 고정 상수 /255.0과는 구분한다.

원문 재현과 개선 실험을 따로 보관한다. 개선을 위한 Validation 분할을 만들었다면 Sample 수·Batch 수부터 새로 계산해야 하며, 원문 938 Batch 기록과 섞지 않는다.

Overfitting·Underfitting·Learning Rate

성능을 고치기 전에 판단 근거를 만든다

Overfitting: Training 적합이 새로운 데이터 성능으로 이어지지 않는 문제를 점검한다. 이번은 Validation 기록이 없어 Step 600→700의 Batch Loss 증가만으로 확정할 수 없다.

Underfitting: Training의 관련 패턴도 충분히 익히지 못한 상황이다. epochs=1이라는 설정만으로 확정하지 않는다. 이번 부분 로그만으로 충분한 평가를 했다고 할 수 없다.

Learning Rate: 너무 크면 업데이트가 불안정하고 너무 작으면 진행이 느릴 수 있다. 하지만 한 Batch의 Loss 상승만으로 원인을 학습률로 단정하지 않는다. 원문은 기본 Adam을 사용하며 후보 비교 기록이 없다.
