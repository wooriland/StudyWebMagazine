Practice Goal

이번 실습에서 무엇을 확인하는가?

이번 단원은 손글씨 숫자를 분류하는 문제를 통해 CNN 내부의 계산 구조를 읽는 실습이다. 단순히 model.fit()을 실행하는 데서 끝나지 않고, 층을 통과할 때 데이터가 어떻게 바뀌는지 설명할 수 있어야 한다.

문제 정의

이미지 한 장을 숫자 0~9 중 하나로 분류한다. 정답이 있는 지도학습이며, 클래스가 10개인 다중 분류다.

모델 구조 이해

합성곱 방식을 바꾸면 출력 채널, Flatten 길이, Dense 파라미터가 어떻게 달라지는지 확인한다.

실행 결과 해석

학습·검증 곡선, 테스트 손실, 정확도와 클래스별 확률을 서로 구분한다.

이미지에서 CNN이 활용하는 구조

손글씨를 구분할 때는 획의 방향, 경계, 곡선, 꺾이는 부분처럼 주변 픽셀이 함께 만드는 모양이 중요하다. CNN은 작은 영역을 계산하면서 이러한 패턴과 관련된 특징을 학습한다.

CNN을 이해하는 두 가지 출발점
성질 의미
국소 연결 이미지 전체가 아니라 작은 주변 영역을 한 번에 계산한다.
가중치 공유 같은 필터 가중치를 여러 공간 위치에서 반복 사용한다.
필터 값도 학습 대상이다.

실제 CNN에서는 사람이 모든 획 검출 규칙을 직접 작성하지 않는다. 초기화된 필터 가중치가 분류 손실을 줄이는 방향으로 조정된다.

02

Visual Flow

이미지가 숫자 예측으로 바뀌는 과정

아래는 현재 활성화된 모델의 흐름이다. B는 현재 처리하는 이미지 개수다. ReLU는 합성곱 층의 activation 설정에 포함되어 있다.

  1. INPUT Image (B, 28, 28, 1) 흑백 손글씨 배치
  2. SPATIAL Depthwise 3×3 + ReLU (B, 26, 26, 1) 채널별 공간 특징 추출
  3. CHANNEL Pointwise 1×1 + ReLU (B, 26, 26, 16) 출력 채널을 16개로 변환
  4. DOWNSAMPLE MaxPooling 2×2 (B, 13, 13, 16) 공간 크기를 줄인 Feature Map
  5. RESHAPE Flatten (B, 2704) 이미지별 특징을 벡터로 펼침
  6. CLASSIFIER Dense(128) + ReLU (B, 128) 추출한 특징 조합
  7. OUTPUT Dense(10) + Softmax (B, 10) 숫자 0~9의 확률
  8. DECISION argmax(axis=1) (B,) 이미지별 최종 예측 숫자
Feature Map은 별도의 층 이름이 아니다.

합성곱과 Pooling을 거치며 만들어진 특징 배열을 가리킨다. GAP는 현재 원본 경로에 없으며, 성능 개선 카드에서 별도 대안으로 다룬다.

합성곱은 작은 창을 이동시키는 계산이다

이미지의 작은 영역

1  2   3
5  6   7
9 10  11
×

설명용 필터

1 0 0
0 1 0
0 0 1
→
1 + 6 + 11 = 18

같은 위치끼리 곱한 뒤 합산

편향을 0으로 둔 설명용 계산이다. 실제 모델에서는 필터 가중치와 편향을 학습하고, ReLU도 적용한다.

보완 예제: NumPy로 필터 이동 직접 확인

② float32 변환과 /255

원문 · 셀 5 

X_train = X_train.astype(np.float32)/255
X_test  = X_test.astype(np.float32)/255
역할·필요성
실수 연산에 맞는 dtype과 일관된 입력 범위를 준비한다.
입력 Shape
(N,28,28,1), 원시 픽셀 범위 0~255
출력 Shape
동일한 (N,28,28,1), float32, 값 범위 0~1
실행 후 변화
X의 자료형과 값이 바뀐다. 정답 y는 클래스 번호 그대로 유지한다.
0 ÷ 255 = 0.0
127 ÷ 255 ≈ 0.498
255 ÷ 255 = 1.0

astype()는 자료형을 바꾸고, /255는 값의 범위를 바꾼다. 자료형만 float32로 바꾸었다고 픽셀이 자동으로 0~1이 되는 것은 아니다.

Train · Validation · Test

세 데이터는 서로 다른 질문에 답한다

원본은 학습용 60,000장 중 20%를 fit(validation_split=0.2)에서 검증용으로 분리한다. 처음 불러온 테스트 10,000장은 별도로 남는다.

TRAIN 48,000장

가중치 업데이트

VALIDATION 12,000장

학습 진행·설정 판단

TEST 10,000장

독립적인 최종 평가

fit 내부의 역할을 Shape로 표현
구분 이미지 정답 가중치 업데이트
Train (48000,28,28,1) (48000,) 예
Validation (12000,28,28,1) (12000,) 아니요
Test (10000,28,28,1) (10000,) 아니요

이 구분 때문에 X_train 변수 자체가 48,000장짜리로 바뀌는 것은 아니다. fit 내부에서 학습과 검증에 사용할 부분을 나눈다.

validation_split은 매번 무작위 추출하는 기능이 아니다.

NumPy 배열 입력에서는 셔플 전에 마지막 부분을 검증 데이터로 분리한다. 매 epoch마다 새로운 20%를 뽑거나 클래스별 비율을 자동으로 맞추지 않는다. 정답순으로 정렬된 자료라면 분할별 분포를 확인해야 한다.

검증 데이터는 역전파에 사용하지 않지만, 검증 결과를 보고 모델·학습률·epoch를 선택하므로 개발 과정에 쓰인다. 테스트 결과까지 반복적으로 보고 설정을 고르면 최종 평가의 독립성이 약해진다.

Normal Convolution

공간 영역과 입력 채널을 함께 계산한다

일반 합성곱의 필터 하나는 입력 채널 전체를 함께 고려한다. 현재 입력은 흑백 1채널이므로 필터 하나의 가중치 형태는 3×3×1이다.

원문 발췌 · 셀 12 현재 주석 처리 

# model.add(Conv2D(filters=32,kernel_size=(3,3),strides=1,padding='valid',activation='relu',kernel_initializer='he_normal'))
# model.add(MaxPooling2D(pool_size=(2,2)))
역할·필요성
일반 합성곱과 Pooling을 사용한 비교 모델을 구성한다.
입력 Shape
(B,28,28,1)
출력 Shape
Conv: (B,26,26,32) → Pooling: (B,13,13,32)
실행 후 변화
현재는 주석이므로 변화가 없다. 선택해 실행하면 해당 층이 추가된다.

출력 높이와 너비 계산

출력 크기 = floor((입력 크기 + 2P − 필터 크기) / stride) + 1

위 식은 dilation=1이고 양쪽 패딩이 P로 동일한 경우다. 원본은 padding='valid'이므로 P=0이다.

(28 − 3) / 1 + 1 = 26

padding='same'은 stride=1일 때 높이와 너비를 유지한다. 모든 stride에서 입력과 동일한 공간 크기를 보장하는 것은 아니다.

파라미터 수 계산

(필터 높이 × 필터 너비 × 입력 채널 + 편향 1) × 출력 채널
= (3 × 3 × 1 + 1) × 32
= 320

filters=32는 필터 32개가 출력 채널 32개를 만든다는 뜻이다. 가중치는 여러 위치에서 공유하므로 출력 위치 26×26마다 별도의 파라미터가 생기지 않는다.

코드의 옵션 읽기
설정 의미
kernel_size=(3,3) 공간 계산 창의 크기
filters=32 출력 채널 수
strides=1 한 칸씩 이동
padding='valid' 패딩을 추가하지 않음
activation='relu' 합성곱과 편향 계산 뒤 음수를 0으로 변경
kernel_initializer='he_normal' ReLU를 사용하는 층의 가중치 초기화 설정

ReLU와 Pooling의 차이

ReLU(z) = max(0, z)
[-3, 0, 2, 5] → [0, 0, 2, 5]

ReLU는 값에 비선형 변환을 적용하며 Shape는 유지한다. MaxPooling은 작은 영역의 최댓값을 골라 공간 크기를 줄인다.

MaxPooling2D(pool_size=(2,2))
기본 stride=2 → 26×26×32에서 13×13×32로 변경

Pooling은 채널별로 수행되므로 채널 수는 유지된다. 최댓값을 선택하는 고정 규칙이어서 학습할 파라미터는 없다. Conv·ReLU·Pooling을 하나의 블록으로 설명할 수 있지만, 모든 CNN이 반드시 이 세 가지를 같은 방식으로 붙이는 것은 아니다.

Depthwise Convolution

채널별 공간 계산을 독립적으로 수행한다

원문 발췌 · 셀 14 현재 주석 처리 

# model.add(DepthwiseConv2D(kernel_size=(3,3),strides=1,padding='valid',activation='relu',depthwise_initializer='he_normal'))
# model.add(MaxPooling2D(pool_size=(2,2)))
역할·필요성
채널별 독립적인 합성곱을 일반 Conv와 비교한다.
입력 Shape
(B,28,28,1), 기본 depth_multiplier=1
출력 Shape
(B,26,26,1) → Pooling 뒤 (B,13,13,1)
실행 후 변화
주석 상태에서는 아무 층도 추가되지 않는다.
채널 1→ 채널 1용 공간 필터 → 결과 1
채널 2→ 채널 2용 공간 필터 → 결과 2
채널 3→ 채널 3용 공간 필터 → 결과 3

위 그림은 입력이 여러 채널인 경우를 설명한 것이다. Depthwise 단계에서는 서로 다른 입력 채널의 정보를 섞지 않는다. 현재 MNIST 입력은 1채널이므로 첫 번째 경로 하나만 생각하면 된다.

출력 채널 수 = 입력 채널 수 × depth_multiplier
현재 출력 채널 = 1 × 1 = 1
파라미터 = (Kh × Kw + 1) × 입력 채널 × multiplier
= (3 × 3 + 1) × 1 × 1
= 10

원본에서 depth_multiplier를 생략했으므로 기본값 1이다. “입력 채널 수로 출력이 결정된다”는 설명에는 이 조건을 함께 붙여 이해한다. 초기화 옵션 이름도 일반 Conv의 kernel_initializer와 달리 depthwise_initializer다.

적은 파라미터는 표현력의 차이도 의미한다.

이 설정에서는 3×3 공간 필터 한 개만 학습한다. 파라미터가 적다는 사실만으로 정확도나 일반화 성능이 더 좋다고 결론 내릴 수 없다.

Depthwise + Pointwise

공간 특징 추출과 채널 변환을 나눈다

원문 · 셀 16 현재 활성 모델 

#step1)Depthwise Conv
model.add(DepthwiseConv2D(kernel_size=(3,3),strides=1,padding='valid',activation='relu',depthwise_initializer='he_normal'))

#step2)Pointhwise Conv
#Conv2D 의 kernel_size=(1,1)로 하면 Pointhwise Conv이다

model.add(MaxPooling2D(pool_size=(2,2)))
무엇을 하는가
Depthwise → Pointwise → Pooling을 연결한다.
왜 필요한가
공간 특징 추출과 채널 변환을 분리한 계산 구조를 확인한다.
입력 Shape
(B,28,28,1)
출력 Shape
(B,26,26,1) → (B,26,26,16) → (B,13,13,16)
실행 후 변화
해당 층과 초기 가중치를 모델에 추가한다. 실제 학습은 fit에서 수행한다.

1×1 필터는 무엇을 계산하는가?

여러 채널을 가진 입력의 한 위치가 [2,5,1]이라면 출력 채널 하나는 다음과 같은 가중합으로 만들 수 있다.

2×w1 + 5×w2 + 1×w3 + bias

공간 크기는 1×1이지만 채널 방향의 변환을 수행한다. 현재는 Depthwise 출력이 1채널이므로 위치별 특징값 h에 서로 다른 가중치와 편향을 적용해 16개 출력 채널을 만든다.

출력 채널 f의 값 = h×w_f + b_f
Pointwise 파라미터 = (1×1×1 + 1)×16 = 32
현재 합성곱 블록 = Depthwise 10 + Pointwise 32 = 42
16채널이 서로 다른 3×3 공간 필터 16개를 뜻하지 않는다.

이 모델에서는 공간 필터 하나가 만든 특징을 1×1 계산으로 16채널로 변환한다.

SeparableConv2D 한 층과 완전히 같은가?

원본은 Depthwise 뒤와 Pointwise 뒤에 각각 편향과 ReLU를 사용한다. 반면 SeparableConv2D(16,3,activation='relu')는 두 합성곱을 수행한 뒤 최종 편향과 활성화를 적용한다.

원본의 두 층 블록: 10 + 32 = 42개
단일 SeparableConv2D: 9 + 16 + 16 = 41개

단순히 클래스를 바꾸면 중간 활성화와 편향 구성도 달라진다. 같은 계산으로 조용히 대체하지 않고 별도 실험으로 구분해야 한다.

Data Leakage

평가 정보가 모델 개발에 섞이지 않게 한다

데이터 누수는 예측할 때 사용할 수 없는 정보나 평가용 정보가 모델을 만드는 과정에 들어가 성능을 실제보다 좋게 보이게 하는 문제다.

이후 실습에서 주의할 사례
사례 문제
훈련·테스트를 합쳐 학습 테스트가 독립적인 평가 자료가 아니게 된다.
테스트 점수를 보며 설정 반복 선택 테스트 정보가 모델 선택에 반영된다.
전체 데이터로 평균·표준편차 학습 검증·테스트 정보가 전처리에 들어간다.
같은 원본의 증강본이 서로 다른 분할에 포함 사실상 비슷한 이미지를 이미 본 상태에서 평가할 수 있다.

원본의 /255는 왜 구분해야 하는가?

X_train = X_train.astype(np.float32) / 255
X_test = X_test.astype(np.float32) / 255

255는 미리 정한 상수다. 테스트 데이터의 평균이나 최댓값을 계산해 학습한 값이 아니다. 따라서 검증 분할 전에 /255를 했다는 이유만으로 이 코드를 데이터 누수라고 판단하면 안 된다.

데이터에서 학습하는 전처리와 고정 변환을 구분한다.

평균·표준편차·특징 선택처럼 데이터에서 정보를 추정하는 과정은 훈련 부분에서 학습하고 검증·테스트에는 같은 변환을 적용한다. 고정 상수 나눗셈과 채널 축 추가는 그 자체로 같은 종류의 추정 과정이 아니다.

  • 원본은 MNIST 훈련용과 테스트용 자료를 따로 받는다.
  • 검증 부분은 훈련용 자료에서 분리한다.
  • 현재 코드만으로 반복적인 테스트 활용이 있었다고 단정할 수 없다.

Overfitting을 판단할 때

학습 정확도가 검증 정확도보다 높다는 사실만으로 확정하지 않는다. 학습 손실은 계속 내려가는데 검증 손실은 지속적으로 악화되고, 격차가 커지는지 본다. 현재 저장 기록은 검증 손실도 전반적으로 감소한다.

Underfitting을 판단할 때

훈련·검증 성능이 모두 낮다면 모델이 필요한 패턴을 충분히 학습하지 못했을 수 있다. 그러나 이미지와 정답의 대응, 잘못된 정규화, 손실 설정, 학습률을 먼저 확인해야 한다. 모델이 작다는 이유만으로 원인을 확정하지 않는다.

Learning Rate·Epoch·Batch Size는 역할이 다르다

Learning Rate → 업데이트 규모
Epoch → 훈련 자료 반복 횟수
Batch Size → 한 번에 묶는 샘플 수

NaN이나 발산을 곧바로 과적합이라고 해석하지 않는다. 입력에 비정상 값이 없는지 먼저 보고 학습률 등을 점검한다. 원인을 모른 채 epoch만 늘리면 해결되지 않을 수 있다.

일반 Conv와 분리 블록의 비교 조건

  • 출력 채널 수·padding·stride·후속 분류층을 맞춘다.
  • 중간 ReLU와 편향 구성의 차이를 기록한다.
  • 동일한 데이터 분리와 전처리를 사용한다.
  • 새 모델·새 옵티마이저로 시작한다.
  • 초기화 변동을 고려해 같은 난수 조건이나 반복 실험을 사용한다.
  • 정확도뿐 아니라 검증 손실·메모리·실제 시간을 함께 확인한다.

R²는 왜 이번 문제에 쓰지 않는가?

R²는 연속 수치의 회귀 예측을 평가하는 지표다. 실제 값이 모두 같지 않은 경우 다음 식으로 이해할 수 있다.

R² = 1 − Σ(yᵢ − ŷᵢ)² / Σ(yᵢ − ȳ)²

yᵢ는 실제 값, ŷᵢ는 예측값, ȳ는 평가 자료의 실제 값 평균이다. 실제 값이 모두 같으면 분모가 0이므로 별도 처리가 필요하다.

정답에 변동이 있는 경우
R² 해석
1 예측이 실제 값과 모두 일치한다.
0 평가 자료의 평균을 항상 예측하는 기준과 제곱오차가 같다.
음수 그 평균 기준보다 제곱오차가 크다.

R²=0.8을 “80% 맞혔다”라고 읽지 않는다. 이번 0~9는 클래스 ID이므로 숫자 거리로 오분류를 평가하지 않는다. 현재 96.38%는 Accuracy이며 R²가 아니다.

Interview & Review

코드를 보지 않고 설명해 보기

먼저 스스로 답한 뒤 펼쳐서 확인한다. 숫자를 외우는 것보다 입력과 출력의 연결을 설명하는 것이 중요하다.

1. CNN이 이미지에 적합한 이유는?

주변 픽셀의 관계를 작은 영역에서 계산하고, 같은 필터를 여러 위치에서 공유하기 때문이다. 국소적인 패턴을 반복적으로 추출할 수 있다.

2. Conv2D인데 입력 배열은 왜 4차원인가?

2D는 필터가 이동하는 공간 축이 높이·너비 두 개라는 뜻이다. 입력은 배치와 채널까지 포함해 (batch,height,width,channel)의 4차원이다.

3. 채널 축을 추가하면 새로운 픽셀이 생기는가?

아니다. 흑백 이미지의 채널이 1임을 배열 모양에 명시한다. (N,28,28)이 (N,28,28,1)이 되며 픽셀 값은 유지된다.

4. 일반 Conv와 Depthwise의 차이는?

일반 Conv는 입력 채널 전체를 함께 고려한다. Depthwise는 입력 채널별로 독립적인 공간 합성곱을 수행하며, 그 단계에서 채널 정보를 섞지 않는다.

5. 1×1 Pointwise는 무엇을 학습하는가?

같은 공간 위치의 채널 값을 가중합하여 새 채널을 만든다. 현재는 입력이 1채널이므로 한 특징값을 16채널로 변환한다. 파라미터는 (1×1×1+1)×16=32개다.

6. 합성곱 파라미터 수는 어떻게 계산하는가?

일반 Conv에서 groups=1이고 편향을 사용하면 (Kh×Kw×입력 채널+1)×출력 채널이다. 이번 일반 Conv 예제는 320개다.

7. 파라미터가 적으면 반드시 빠른가?

아니다. 출력 공간 크기와 가중치 재사용 횟수, 메모리 접근, 하드웨어와 구현이 실행 시간에 영향을 준다.

8. Flatten과 MaxPooling도 학습하는가?

이번 두 층에는 학습할 파라미터가 없다. Flatten은 모양을 바꾸고 MaxPooling은 최댓값을 선택한다.

9. 현재 모델에서 파라미터가 가장 많은 층은?

Flatten 뒤 Dense(128)이다. 2,704개 입력을 128개 노드에 연결하여 2,704×128+128=346,240개다.

10. 왜 sparse categorical crossentropy인가?

정답이 원핫 벡터가 아니라 정수 클래스 번호이고, 출력은 10개 클래스의 Softmax 확률이기 때문이다.

11. compile·fit·evaluate·predict의 차이는?

compile은 학습 방법 설정, fit은 가중치 학습, evaluate는 정답과 비교한 성능 계산, predict는 입력에 대한 모델 출력 생성이다.

12. 60,000장인데 왜 375 step인가?

20%인 12,000장을 검증용으로 분리하여 48,000장으로 학습하기 때문이다. 48,000÷128=375다.

13. 검증은 역전파하지 않으니 데이터 누수와 무관한가?

그렇게 단정할 수 없다. 테스트 결과로 설정을 반복 선택하거나 전체 데이터 통계로 전처리를 학습해도 평가 정보가 개발 과정에 들어갈 수 있다.

14. 100 epoch이면 반드시 과적합인가?

아니다. 원본의 100 epoch·47% 내용은 주석이며 현재 저장된 것은 10 epoch 결과다. epoch 수만으로 판단하지 않고 학습·검증 추세를 본다.

15. argmax(axis=1)의 의미는?

각 이미지 행의 10개 클래스 확률 중 가장 큰 값의 위치를 선택한다. (N,10)이 (N,) 클래스 번호 배열이 된다.

16. 모든 분류 문제에서 argmax를 사용하는가?

Sigmoid 출력 하나에 argmax를 그대로 쓰지 않는다.

(N,1)에 argmax(axis=1)를 적용하면 각 행에 원소가 하나뿐이므로 모든 결과가 인덱스 0이다. 클래스 1의 확률을 임계값과 비교해야 한다.

0과 1 중 어느 쪽이 고양이인지 클래스 매핑을 먼저 확인한다. p[:,0]으로 (N,)을 만들면 같은 모양의 정답과 비교할 수 있다. 이 코드는 연결 설명용이며 다음 단원의 학습 성능을 제시한 것은 아니다.
