Mini-batch

Batch Size 128이면 한 Epoch는 375번 Update한다

Training Sample = 60,000 × 0.8 = 48,000
48,000 ÷ 128 = 375 Batch / Epoch
375 × 10 = 3,750 Update / Model
Batch 1 128 Sample
→
Gradient
→
Weight Update
→
Batch 2
→
···
→
Batch 375

다섯 모델을 모두 같은 10 Epoch 조건으로 학습하면 Training Batch Update를 단순 합산해 약 18,750번으로 계산할 수 있다.

Validation Batch는 Weight Update가 아니다.

Model 2

HeNormal — ReLU와 함께 초기 Weight 변경

교안 원문 핵심 

he_initializer = tf.keras.initializers.HeNormal()

he_initializer_model = tf.keras.models.Sequential([
    tf.keras.layers.Input((28,28)),
    tf.keras.layers.Flatten(),

    tf.keras.layers.Dense(
        units=64,
        activation='relu',
        name='he_initializer_hidden1',
        kernel_initializer=he_initializer
    ),

    tf.keras.layers.Dense(
        units=32,
        activation='relu',
        kernel_initializer='he_normal'
    ),

    tf.keras.layers.Dense(
        units=10,
        activation='softmax',
        kernel_initializer='he_normal'
    )
])
Base GlorotNormal
→
He Model HeNormal
Shape와 Parameter 수는 동일하다.

바뀐 것은 Layer 크기가 아니라 Weight가 시작하는 초기 분포다.

출력층도 HeNormal

원본은 ReLU 은닉층뿐 아니라 Softmax 출력 Dense10에도 HeNormal을 지정한다.

Model 3

He + L1 Regularization

교안 원문 핵심 

L1 = tf.keras.regularizers.l1(l1=0.01)

he_initializer_L1_model = tf.keras.models.Sequential([
    tf.keras.layers.Input((28,28)),
    tf.keras.layers.Flatten(),

    tf.keras.layers.Dense(
        units=64,
        activation='relu',
        name='he_initializer_L1_hidden1',
        kernel_initializer=he_initializer,
        kernel_regularizer=L1
    ),

    tf.keras.layers.Dense(
        units=32,
        activation='relu',
        kernel_initializer='he_normal',
        kernel_regularizer='l1'
    ),

    tf.keras.layers.Dense(
        units=10,
        activation='softmax',
        kernel_initializer='he_normal',
        kernel_regularizer='l1'
    )
])
Losstotal = Lossclassification + λ Σ |w|
λ = 0.01
L1 추가 ≠ Parameter 수 증가
L1 추가 = Loss 계산 변화

Parameter 수는 여전히 52,650개다. 대신 Weight 크기에 대한 Regularization Loss가 추가된다.

L1 모델의 Loss 절대값을 Base와 그대로 비교하지 않는다.

L1 모델의 총 Loss에는 분류 Loss뿐 아니라 Regularization Penalty도 들어간다.

논리적 주의

lr 변수만 바꿔서는 현재 compile 결과가 바뀌지 않는다. 실제 compile은 문자열 'adam'을 사용하기 때문이다.

보완 예시 · 원본 수정 코드가 아님 

optimizer = tf.keras.optimizers.Adam(
    learning_rate=lr
)

base_model.compile(
    optimizer=optimizer,
    loss='sparse_categorical_crossentropy',
    metrics=['acc']
)

여러 모델에서 실제 Learning Rate 실험을 한다면 모델별 Optimizer 객체를 별도로 만드는 편이 상태 관리가 명확하다.

Metric 해석

Accuracy와 Loss를 함께 읽는다

Accuracy

맞힌 Sample 수 / 전체 Sample 수

최종 Class가 맞았는지를 평가한다.

Cross-Entropy

−log(정답 Class 확률)

정답에 부여한 확률까지 반영한다.

Accuracy ≠ 1 − Loss
Classification Loss ≠ L1 포함 Total Loss

R²는 이번 지표가 아니다

이번은 숫자 0~9의 다중 분류 문제이므로 Accuracy와 Cross-Entropy를 사용한다. R²는 회귀 문제에서 사용하는 대표 지표다.

면접 포인트

핵심 개념을 질문·답변으로 점검한다

Q1. Mini-batch란?
전체 Training 데이터를 일정 크기의 작은 Batch로 나누어 여러 번 Weight를 업데이트하는 학습 방식이다.
Q2. 이번 한 Epoch의 Training Batch 수는?
48,000 ÷ 128 = 375 Batch다.
Q3. Parameter와 Hyperparameter의 차이는?
Parameter는 모델이 학습하며 조정하고, Hyperparameter는 학습 전에 사람이 정한다.
Q4. Glorot와 He 초기화가 바꾸는 것은?
Layer Shape가 아니라 초기 Weight의 분포다.
Q5. Base 모델 Parameter 수는?
52,650개다.
Q6. He 모델도 52,650개인 이유는?
Layer 구조는 같고 초기화 방식만 다르기 때문이다.
Q7. L1을 넣으면 Parameter가 늘어나는가?
아니다. 기존 Weight에 대한 Regularization Loss가 추가된다.
Q8. L1 총 Loss의 개념식은?
Task Loss + λ Σ|w|이다.
Q9. L1 모델의 Loss를 Base와 그대로 비교하면 안 되는 이유는?
L1 모델의 Loss에는 Regularization Penalty가 포함되기 때문이다.
Q10. BatchNorm은 Shape를 바꾸는가?
이번 구조에서는 Feature 수를 유지하므로 Shape는 유지된다.
Q11. BatchNorm의 Trainable Parameter는?
gamma와 beta다.
Q12. BatchNorm의 Non-trainable 상태는?
moving mean과 moving variance다.
Q13. Dropout에 학습 Parameter가 있는가?
없다.
Q14. Dropout rate=0.2는?
Training 시 일부 출력을 약 20% 비율로 무작위 비활성화하는 설정이다.
Q15. Model 4와 Model 5의 차이는 Dropout 하나뿐인가?
아니다. Model 5에는 Flatten 뒤 BatchNorm도 하나 추가된다.
Q16. Dropout의 실제 위치는?
원본 실제 코드는 ReLU 이후 Dropout이다.
Q17. lr=0.001 변수는 실제 compile에 연결되어 있는가?
아니다. adm 객체를 만들지만 compile은 optimizer='adam' 문자열을 사용한다.
Q18. 이번 Validation은 X_test인가?
아니다. X_train의 20%다.
Q19. Test는 언제 사용하는가?
Cell 26의 evaluate에서 사용한다.
Q20. 이번 저장 실행에서 Test Accuracy가 가장 높은 모델은?
He 초기화 모델로 약 97.30%다.
Q21. He가 항상 가장 좋은 모델인가?
아니다. 이번 Dataset·설정·한 번의 저장 실행 결과다.
Q22. Overfitting은 어떻게 확인하는가?
Training 성능은 좋아지지만 Validation 성능이 정체·악화되는 방향을 확인한다.
Q23. Underfitting은?
Training 성능 자체도 충분히 높아지지 않는 상태를 점검한다.
Q24. R²를 쓰지 않는 이유는?
이번은 회귀가 아니라 10-Class 분류 문제이기 때문이다.
Q25. 성능 개선 기법은 많이 넣을수록 좋은가?
아니다. 데이터·모델·규제 강도·학습 설정에 따라 오히려 성능이 낮아질 수 있다.
