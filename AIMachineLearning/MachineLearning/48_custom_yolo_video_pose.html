핵심 코드

Frame 반복 Pose 추론의 전체 원문

교안 원문 · Cell 7 핵심 흐름 

print(cap.isOpened())

if cap.isOpened():

    delay = int(
        1000 /
        cap.get(cv2.CAP_PROP_FPS)
    )

    print('delay:',delay)

    while cap.isOpened():

        ret,img = cap.read()

        if ret:

            results = model(img)

            # Bounding Box 및 Class, Confidence 제거
            results[0].boxes = None

            cv2.imshow(
                'POSE_DETECTION',
                results[0].plot()
            )

            #key = cv2.waitKey(delay)
            key = cv2.waitKey(1)

            if key != -1:
                break

        else:

            print(
                '영상이 캡처가 안됬어요'
            )

            print(
                ret,
                img
            )

            break

cap.release()

cv2.destroyAllWindows()

원문

if key != -1:
    break
key == -1 → 다음 Frame
key != -1 → break
q 전용 종료가 아니다.

원문은 특정 Keyboard Key를 지정하지 않는다. 반환된 Key Code가 -1이 아니면 종료한다.

이는 원본 30 FPS 영상의 Frame 간격보다 긴 값이므로 모든 Frame을 순서대로 처리하면 원본 영상보다 느리게 진행될 수 있음을 보여 준다.

waitKey(1)이 속도를 결정하지 않는다.

전체 처리 속도는 read + preprocess + inference + postprocess + plot + imshow + waitKey의 합으로 결정된다.

ML 48에 새 Leakage 없음 ≠ 과거 학습 과정도 자동으로 완벽함

Q1. ML 47과 ML 48의 차이는?

datasets/yolo/people_pixabay.mp4
Q5. 웹캠 입력 대안은?
cv2.VideoCapture(0)
Q6. VideoCapture의 역할은?
영상·Camera를 열고 Frame을 순차적으로 읽게 해 준다.
Q7. Source FPS는?
원본 저장 출력 기준 30.0이다.

약 33.3ms다.

33이다.

아니다. 활성 코드는 waitKey(1)이다.

Frame 읽기 성공 여부 ret와 현재 Frame img다.

아니다. 현재 Frame 한 장이다.

Batch 1, Channel 3, Height 384, Width 640이다.

원문은 img.shape를 직접 출력하지 않아 확정할 수 없다.

Results의 Bounding Box 정보를 제거한다.

Rendering 이미지를 OpenCV Window에 표시한다.

Matplotlib 정적 Figure가 아니라 OpenCV 별도 GUI Window를 사용하기 때문이다.

특정 q키가 아니라 key가 -1이 아니면 종료한다.
Q24. 영상 Pose는 Tracking인가?
아니다. Frame-by-Frame Pose Predict이며 Person ID 유지 코드가 없다.
Q25. 5 persons는 Accuracy인가?
아니다. 현재 Frame의 Person Detection Count다.
Q26. 106.2ms는 정확도인가?
아니다. 해당 Frame의 Inference Time이다.
Q27. 이번에 Loss가 있는가?
새 Training Loss는 없다.
Q28. Optimizer와 Learning Rate는?
이번 Inference-only 실행에는 없다.

새 Training Split이 없어 현재 Notebook 자체의 신규 Leakage는 핵심이 아니다.

cap.release()와 cv2.destroyAllWindows()다.
