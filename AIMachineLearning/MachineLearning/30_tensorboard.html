Shape 흐름

Training · Validation · Test 역할을 나눈다

60,000 × 0.8 = 48,000
60,000 × 0.2 = 12,000
Training 48,000 (48000,28,28) Weight 업데이트
Validation 12,000 (12000,28,28) 학습 상태 확인
Test 10,000 (10000,28,28) 이번 원문에서는 평가하지 않음

validation_split=0.2는 X_train 자체를 48,000개 배열로 다시 저장한다는 뜻이 아니라, fit 내부에서 Training과 Validation 역할을 나눈다는 뜻이다.

Metric 해석

Loss와 Accuracy는 다른 질문에 답한다

Accuracy

맞힌 이미지 수 / 전체 이미지 수

최종 Class 선택이 맞았는지를 본다.

Cross-Entropy Loss

−log(정답 Class에 준 확률)

정답에 어느 정도의 확신을 주었는지까지 본다.

예측 A

정답 Class 확률 = 0.60

Class는 맞음
예측 B

정답 Class 확률 = 0.95

Class는 맞음

Accuracy 관점에서는 둘 다 정답이다. 그러나 Cross-Entropy Loss는 다르다.

Accuracy ≠ 1 − Loss
Best val_loss ≠ Best val_acc
val_acc ≠ Test Accuracy

이번 Epoch 10의 0.9722는 Validation 정확도 약 97.22%다.

    )

if not np.isfinite(sample_x).all():
    raise ValueError("입력에 NaN 또는 Inf가 있습니다.")

probabilities = np.asarray(
    model.predict(sample_x, verbose=0)
)

if probabilities.shape != (1, 10):
    raise ValueError(
        f"출력 Shape를 확인하세요: {probabilities.shape}"
    )

predicted_digit = int(
    np.argmax(probabilities, axis=1)[0]
)

print("예측 숫자:", predicted_digit)
print("실제 정답:", int(y_test[index]))

Data Leakage

Training · Validation · Test의 역할을 지킨다

Training

Weight를 학습

→
Validation

모델과 설정을 판단

→
Test

최종 성능 확인

이번 원문은 Test를 fit의 Validation으로 사용하지 않는다. Validation은 X_train의 20%다.

잘못된 선택 흐름 예
Model A → Test 확인 → Model B → Test 확인 → 가장 좋은 Test 모델 선택

Test 결과를 반복적으로 보며 모델을 선택하면 Test가 사실상 Validation 역할을 하게 된다.

/255 전처리에 대하여

이번 `/255`는 Training에서 통계량을 학습해 만든 규칙이 아니라 고정 상수이므로 StandardScaler의 fit 같은 데이터 의존 전처리와는 구분한다.

성능 개선·학습 곡선

TensorBoard는 문제를 고치는 도구보다 먼저 관찰하는 도구다

Overfitting 신호

Epoch 5 Train Loss 0.0517 Val Loss 0.0989
→
Epoch 10 Train Loss 0.0240 Val Loss 0.1247

Training Loss는 감소하지만 Validation Loss는 다시 증가한다. 이는 Overfitting을 점검할 수 있는 신호다. 다만 이 기록 하나만으로 모든 원인을 확정하지 않는다.

Underfitting

Training 성능 낮음 + Validation 성능 낮음

이 경우 모델 용량·학습 횟수·입력 정보·전처리·Optimizer 등을 함께 점검한다.

Learning Rate 문제

너무 큼

Loss 요동·불안정·발산 가능성 점검

너무 작음

Loss 감소가 지나치게 느린지 점검

곡선은 원인을 알려주는 단서이지 자동 진단 결과가 아니다.

입력·Label·Loss·모델 구조도 함께 확인한다.

면접 포인트

TensorBoard를 설명할 수 있는가?

Q1. TensorBoard란 무엇인가요?
TensorFlow/Keras 학습 과정에서 발생하는 Loss·Metric·Weight 분포 등의 기록을 시각적으로 확인하기 위한 도구입니다.
Q2. TensorBoard가 모델을 학습합니까?
아닙니다. 모델의 학습은 Optimizer와 fit이 수행하고, TensorBoard는 학습 기록을 저장·시각화합니다.
Q3. Callback이란 무엇인가요?
학습 과정의 특정 이벤트에서 Keras가 호출하여 추가 동작을 수행하게 하는 객체입니다.
Q4. 이번 TensorBoard Callback의 핵심 설정은?
log_dir과 histogram_freq=1입니다.
Q5. log_dir은 무엇인가요?
TensorBoard가 읽을 학습 이벤트 기록의 저장 위치입니다.
Q6. Timestamp를 사용하는 이유는?
서로 다른 학습 실행을 Run 단위로 분리하고 비교하기 위해서입니다.
Q7. histogram_freq=1의 의미는?
Weight Histogram을 Epoch 단위로 매 Epoch 기록하도록 설정한 것입니다.
Q8. histogram_freq=1은 Batch Size 1인가요?
아닙니다. Histogram 기록 주기입니다.
Q9. 이번 입력·출력 Shape는?
입력은 (B,28,28), 최종 출력은 (B,10)입니다.
Q10. 이번 모델 구조는?
Flatten → Dense128 → Dense64 → Dense32 → Dense10입니다.
Q11. Loss와 Optimizer는?
Sparse Categorical Cross-Entropy와 Adam입니다.
Q12. 이번 Validation 데이터는 X_test입니까?
아닙니다. X_train에서 validation_split=0.2로 분리한 데이터입니다.
Q13. 원본의 Test Accuracy는?
원본에는 evaluate(X_test, y_test)가 없어 저장된 Test Accuracy가 없습니다.
Q14. Epoch 10의 val_acc 0.9722는?
Validation Accuracy 약 97.22%입니다.
Q15. 가장 낮은 val_loss는?
저장 로그 기준 Epoch 5의 0.0989입니다.
Q16. 가장 높은 val_acc는?
저장 로그 기준 Epoch 9의 0.9738입니다.
Q17. 왜 두 Best Epoch가 다르나요?
Accuracy는 Class 일치 여부를 보고, Cross-Entropy는 정답 Class에 부여한 확률까지 반영하기 때문입니다.
Q18. 현재 model은 Epoch 5 상태인가요?
아닙니다. 원문에는 EarlyStopping 복원이나 ModelCheckpoint 로드가 없으므로 순차 실행 기준 Epoch 10 상태입니다.
Q19. %tensorboard와 CLI tensorboard의 차이는?
전자는 IPython Magic이고 후자는 터미널 실행 명령입니다.
Q20. TensorBoard와 History의 차이는?
History는 fit이 반환하는 Python 객체이고, TensorBoard는 이벤트 로그를 저장해 Dashboard에서 시각화합니다.
Q21. TensorBoard가 가장 좋은 모델을 저장합니까?
이번 원문에서는 아닙니다. 좋은 모델 상태 저장은 ModelCheckpoint와 구분합니다.
Q22. TensorBoard가 Overfitting을 해결합니까?
아닙니다. Training과 Validation의 차이를 관찰하여 문제를 판단하는 데 도움을 주는 도구입니다.
