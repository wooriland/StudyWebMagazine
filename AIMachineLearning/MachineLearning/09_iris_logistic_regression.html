Supplement

실무에서는 Pipeline으로 Scaling을 검토할 수 있다

보완 코드 — 교안 원본에는 없음

아래 코드는 원본을 교체하는 것이 아니라, Scaling과 Model을 하나의 Pipeline으로 묶는 실무 보완 예제입니다. 

from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

model_pipeline = Pipeline([
    (
        "scaler",
        StandardScaler()
    ),
    (
        "model",
        LogisticRegression(
            max_iter=1000
        )
    )
])

model_pipeline.fit(
    X_train,
    y_train
)

y_pred_pipeline = model_pipeline.predict(
    X_test
)
Raw X_train → StandardScaler → LogisticRegression → Prediction

Common Mistakes

자주 하는 실수

1. Iris는 항상 같은 문제라고 생각한다

Target이 petal width면 Regression, iris.target이면 Classification입니다.

2. One-Hot Encoding을 직접 해야 한다고 생각한다

이번 scikit-learn Model에는 Class Index를 그대로 전달합니다.

3. fit()은 데이터를 저장하기만 한다고 생각한다

fit()에서 Model Parameter 최적화가 수행됩니다.

4. predict()가 Probability라고 생각한다

원본의 predict()는 Class Label을 반환합니다.

5. 단일 Sample score 100%를 Confidence 100%로 해석한다

한 Sample 중 하나를 맞힌 Accuracy일 뿐입니다.

6. (4,)과 (1,4)을 같은 입력으로 생각한다

Sample 축 존재 여부가 다릅니다.

7. NumPy W와 sklearn coef_ Shape 방향을 혼동한다

직접 구현과 Library의 Parameter 저장 방향이 다릅니다.

8. 큰 coefficient = 절대적 Feature Importance라고 단정한다

Feature Scale과 관계 구조도 고려해야 합니다.

9. Scaling이 없으므로 원본 코드가 틀렸다고 생각한다

원본은 Scaling 없이도 정상 실행됐으며, Scaling은 별도의 보완 관점입니다.

10. Accuracy 96.67%만 보고 Overfitting이 없다고 판단한다

Train/Test 비교와 Validation이 필요합니다.

Interview

면접 포인트

Q1. 이번 Iris 문제는 Regression인가 Classification인가요?

iris.target의 0, 1, 2 세 Class를 예측하므로 Multiclass Classification입니다.

Q2. 전체 X Shape은 무엇인가요?

(150,4)이며 150개의 Sample과 4개의 Feature를 의미합니다.

Q3. Train/Test Shape은?

X_train=(120,4), X_test=(30,4)입니다.

Q4. stratify=y는 왜 사용하나요?

Train/Test 분할에서도 Class 비율을 유지하기 위해 사용합니다.

Q5. 왜 One-Hot Encoding을 직접 하지 않나요?

scikit-learn LogisticRegression이 Class Index Label을 직접 처리하기 때문입니다.

Q6. fit()은 무엇을 하나요?

Training Data로 Model Parameter를 최적화하여 학습된 Logistic Regression Model을 만듭니다.

Q7. 이번 Notebook에는 compile()이 왜 없나요?

scikit-learn Estimator는 Keras식 compile 단계를 사용하지 않으며 Model 생성 후 fit()으로 학습합니다.

Q8. 이번 Solver는 무엇인가요?

저장된 Estimator 설정에서는 lbfgs가 사용됩니다.

Q9. Learning Rate를 직접 지정하나요?

아닙니다. 원본에는 사용자가 설정하는 learning_rate가 없습니다.

Q10. Test Accuracy는 얼마인가요?

저장 결과 기준 약 96.67%입니다.

Q11. 96.67%는 몇 개를 맞힌 것인가요?

30개 Test Sample 중 29개를 맞힌 것에 해당합니다.

Q12. predict()는 Probability를 반환하나요?

원본의 predict()는 Class Label 0, 1, 2 중 하나를 반환합니다.

Q13. 단일 Sample score 100%는 Confidence 100%인가요?

아닙니다. 1개의 평가 Sample 중 1개를 맞힌 Accuracy 100%입니다.

Q14. coef_.shape이 왜 (3,4)인가요?

3개의 Class 각각에 대해 4개의 Feature Weight가 존재하기 때문입니다.

Q15. ML 08의 W와 sklearn coef_의 방향은 어떻게 다른가요?

직접 구현 W는 (features, classes), sklearn coef_는 (classes, features) 형태로 노출됩니다.

Q16. ConvergenceWarning은 무엇인가요?

설정된 반복 범위 안에서 Solver가 충분한 수렴 조건을 만족시키지 못했을 가능성을 알리는 Warning입니다.

Q17. Scaling이 없으면 반드시 잘못된 코드인가요?

아닙니다. 원본은 Scaling 없이 정상 실행되었습니다. 다만 Solver 수렴 측면에서 Scaling을 검토할 수 있습니다.

Q18. 이번 단원이 다음 Perceptron과 어떻게 연결되나요?

입력, Weight, Bias, Weighted Sum, Decision이라는 선형 분류 구조가 다음 단원에서 Neuron과 Perceptron 구조로 이어집니다.
