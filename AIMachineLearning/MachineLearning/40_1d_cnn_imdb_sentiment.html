01핵심 개념 — CNN으로 문장의 표현을 찾는다

목표는 리뷰 한 개를 읽고 부정 0 / 긍정 1 중 하나를 예측하는 이진 분류입니다. CNN은 이미지에만 쓰이지 않습니다. Conv1D는 순서가 있는 데이터의 한 축을 따라 일정 범위의 패턴을 찾습니다.

이전: 이미지 CNN

(B, H, W, C)에서 높이·너비 방향으로 필터가 이동합니다. 색·윤곽·질감 등의 패턴을 이용합니다.

이번: 텍스트 CNN

(B, L, E)에서 길이 L 방향으로 필터가 이동합니다. 인접한 토큰들의 조합을 학습합니다. B는 배치, E는 임베딩 차원입니다.

예를 들어 “not very interesting”처럼 여러 토큰을 함께 보아야 감정을 이해할 수 있습니다. 다만 kernel_size=7은 7개 위치를 보는 수치 연산이며, 특정 필터가 반드시 사람이 이름 붙일 수 있는 문법을 배운다고 보장하지 않습니다.

핵심 용어를 코드와 연결하기
용어 이번 실습에서의 의미
Token / 토큰 ID 텍스트를 나눈 단위 / 해당 단위의 정수 번호. ID의 크기가 감정의 강도를 뜻하지 않습니다.
Vocabulary / OOV 사용할 어휘 집합 / 어휘 범위 밖 토큰. 이 데이터에서는 OOV를 2로 표현합니다.
Padding / Truncation 짧은 리뷰에 0을 채움 / 긴 리뷰 일부를 잘라 고정 길이를 만듦.
Embedding ID에 대응하는 128차원 실수 벡터를 조회합니다. 이번 모델에서는 학습으로 벡터가 바뀝니다.
Conv1D / Feature Map 길이 방향으로 합성곱 / 필터 반응이 모인 출력. 여기서는 채널 32개입니다.
ReLU / MaxPool1D 음수 반응을 0으로 처리 / 각 길이 구간의 채널별 최댓값을 선택합니다.
Flatten / Dense 배치를 유지하며 특징을 펼침 / 펼친 특징으로 분류 근거를 조합합니다.
Softmax / Crossentropy 두 클래스 확률의 합을 1로 만듦 / 정답 클래스 확률이 낮을수록 큰 손실을 줍니다.

실습의 위치: 이번 모델은 사전학습 CNN을 불러오는 전이학습이 아닙니다. Embedding·Conv1D·Dense의 가중치를 IMDb 훈련 데이터로 학습합니다.

02Dataset — X는 리뷰, y는 감정 정답

Keras의 IMDb 데이터는 영어 영화 리뷰를 이미 정수 ID 시퀀스로 변환하여 제공합니다. 원문 문자열을 직접 읽거나 Tokenizer를 새로 학습하는 코드는 없습니다. imdb.load_data()의 기본 구성을 사용하면 훈련용 25,000개와 테스트용 25,000개를 받습니다.

데이터의 역할과 분할
구분 개수 용도 가중치 갱신
Train 20,000 원래 X_train의 앞 80%. 학습에 사용. 있음
Validation 5,000 fit에서 원래 X_train의 뒤 20%를 분리. Epoch마다 점검. 없음
Test 25,000 학습 종료 후 최종 평가. 없음

X[i]는 i번째 리뷰의 토큰 배열이고, y[i]는 그 리뷰 전체의 정답입니다. 토큰마다 감정 정답이 붙는 문제가 아닙니다. 

리뷰 한 개 X[i] : [1, 14, 22, 16, ...]
원래 정답 y[i] : 1             → 긍정
원핫 정답     : [0, 1]        → [부정, 긍정]
모델 출력     : [0.08, 0.92]  → 설명용 예시, 실제 저장 예측값 아님

MAX_FEATURES=10000은 입력 ID를 10,000 미만 범위로 제한하는 설정입니다. 특수 ID가 있으므로 “일반 단어 정확히 10,000개”라는 표현과는 다릅니다. MAX_LEN=300도 패딩·특수 토큰을 포함한 300개 위치를 뜻합니다.

04그림처럼 이해 — 데이터와 Shape의 이동

  1. 리뷰 ID 배열(B, 300)
  2. Embedding(B, 300, 128)
  3. Conv1D + ReLU(B, 294, 32)
  4. MaxPool1D(B, 58, 32)
  5. Flatten(B, 1856)
  6. Dense + ReLU(B, 32)
  7. Dense + Softmax(B, 2)
  8. argmax · 보충(B,)
  9. 의미 해석
    0 부정 / 1 긍정

Feature Map은 따로 추가하는 층이 아니라 Conv나 Pooling의 출력입니다. 원본은 GAP 대신 Flatten을 사용합니다. 위 흐름에서 ReLU는 Conv1D와 첫 Dense의 activation에 포함되어 있습니다.

Shape·차원 수·의미를 함께 확인
단계 Shape 해석
로드 직후 X_train (25000,) 길이가 서로 다른 리뷰 25,000개를 담은 바깥 배열.
첫 리뷰 / 두 번째 리뷰 (218,) / (189,) 각 리뷰의 정수 토큰 개수.
패딩 후 X_train / X_test (25000, 300) 샘플 수 × 토큰 위치. 모델 입력은 rank 2.
원래 y → 원핫 y (25000,) → (25000, 2) 클래스 ID → [부정, 긍정] 정답 벡터.
Embedding 출력 (B, 300, 128) 배치 × 길이 × 채널. Conv1D의 입력은 rank 3.
Conv1D (B, 294, 32) 300 − 7 + 1 = 294. 필터 수가 출력 채널 수.
MaxPool1D (B, 58, 32) floor((294 − 5) / 5) + 1 = 58.
Flatten (B, 1856) 58 × 32 = 1856. B는 합치지 않음.
최종 출력 (B, 2) 리뷰마다 부정·긍정 확률 2개.

B는 한 번에 처리하는 리뷰 수입니다. 일반 배치는 128개지만 마지막 훈련 배치는 32개입니다. None은 배치 크기를 고정하지 않았다는 뜻이며 0개를 뜻하지 않습니다.

Conv1D(32,7,relu) 인접 7개 위치의 패턴 32종을 학습 (B,300,128) → (B,294,32) 커널·편향
MaxPool1D(5) 5개 위치별 채널 최댓값을 선택해 길이 축소 (B,294,32) → (B,58,32) 학습 가중치 없음
Flatten() 분류층에 전달할 특징 벡터 생성 (B,58,32) → (B,1856) 학습 가중치 없음
Dense(32,relu) 특징을 조합하여 분류에 필요한 표현 생성 (B,1856) → (B,32) 가중치·편향
Dense(2,softmax) 두 클래스의 확률 출력 (B,32) → (B,2) 가중치·편향

Embedding은 어떻게 동작할까?

ID가 14라면 임베딩 표의 14번 행을 가져옵니다. 이렇게 300개 위치 각각에 128차원 벡터를 붙입니다. 이번 표는 사전학습 단어 벡터가 아니라 모델과 함께 학습하는 파라미터입니다.

Conv1D는 무엇을 7개씩 볼까?

길이 축에서 7개 토큰 위치를 봅니다. 각 위치의 128개 채널을 모두 사용하므로 필터 하나의 가중치 크기는 (7,128), 전체 커널은 (7,128,32)입니다. 기본 padding='valid'와 stride 1에서 길이는 300−7+1=294가 됩니다.

Pooling은 채널을 줄일까?

아닙니다. 기본 stride는 pool_size와 같은 5이고 길이만 294에서 58로 줄입니다. 각 채널을 따로 처리하므로 채널 수 32는 유지됩니다. 마지막에 완전한 크기 5 구간을 만들지 못하는 4개 위치는 이 설정에서 사용되지 않습니다.

모델에 층을 추가했다고 학습된 것은 아닙니다. 입력 Shape를 알게 되는 빌드 시점에 가중치가 준비되고, fit에서 손실을 이용한 갱신이 일어납니다. Embedding의 기본 mask_zero=False에서는 패딩 ID 0도 벡터를 조회합니다. 0을 자동으로 무시한다고 가정하지 마세요.

22면접 포인트 — 질문에 말로 답하기

1. CNN으로 텍스트를 분류할 수 있는 이유는?

임베딩된 토큰 시퀀스의 길이 축을 따라 Conv1D가 이동하며 인접 토큰들의 패턴을 학습하기 때문입니다.

2. 모델 입력과 Conv1D 입력 Shape는?

모델 입력은 (B,300) 정수 ID입니다. Embedding 후 Conv1D 입력은 (B,300,128) 실수 특징입니다.

3. Embedding의 input_dim과 output_dim은?

input_dim=10000은 ID를 조회할 표의 행 수이고 output_dim=128은 각 ID에 대응하는 벡터 길이입니다.

4. 토큰 ID를 정규화하지 않는 이유는?

ID는 크기를 비교하는 측정값이 아니라 범주를 가리키는 번호입니다. 나누기 연산은 원래 단어와의 대응을 깨뜨립니다.

5. 패딩과 절단의 기본 방향은?

둘 다 pre입니다. 짧으면 앞에 0을 채우고 길면 앞을 잘라 뒤쪽 300개 위치를 남깁니다.

6. 패딩 ID 0은 자동으로 무시되는가?

아닙니다. 원본 Embedding의 mask_zero 기본값은 False입니다. 마스크를 켜더라도 후속 층 전체가 처리하는지 확인해야 합니다.

7. kernel_size=7과 filters=32의 차이는?

7은 한 번에 보는 길이 축의 위치 수이고 32는 학습하는 필터 수, 즉 출력 채널 수입니다.

8. Conv1D 출력 길이는 왜 294인가?

입력 길이 300에 valid padding, stride 1, 커널 7을 적용하므로 300−7+1=294입니다.

9. MaxPool1D 출력 길이는 왜 58인가?

pool_size=5와 기본 stride=5에서 floor((294−5)/5)+1=58입니다. 채널은 32로 유지됩니다.

10. Flatten은 배치까지 펼치는가?

아닙니다. (B,58,32)를 (B,1856)으로 바꿉니다. 샘플끼리 섞지 않습니다.

11. Conv1D 파라미터는 어떻게 계산하는가?

(커널 길이 7 × 입력 채널 128 + 편향 1) × 필터 32 = 28,704개입니다.

12. 왜 두 칸 Softmax와 CCE를 사용하는가?

정답이 [부정,긍정] 원핫 벡터이기 때문입니다. 정답 표현·출력 형태·Loss의 조합이 일치해야 합니다.

13. compile과 fit은 무엇이 다른가?

compile은 학습 규칙을 설정하고 fit은 데이터로 손실·기울기를 계산하여 가중치를 갱신합니다.

14. validation_split=0.2는 언제 분리하는가?

훈련 shuffle 전에 배열 뒤쪽 20%를 분리합니다. 계층화 분할이나 매 Epoch 재추출이 아닙니다.

15. fit 이후 X_train은 20,000개가 되는가?

아닙니다. 내부적으로 Train 20,000개를 사용하지만 외부 X_train 배열은 25,000개 그대로입니다.

16. Epoch와 batch의 차이는?

Epoch는 훈련 부분 전체를 한 번 사용하는 반복 단위입니다. Batch는 한 번의 갱신에 사용하는 리뷰 묶음이며 이 실습은 Epoch당 157배치입니다.

17. Accuracy는 비슷한데 Loss가 커질 수 있는가?

가능합니다. 틀린 샘플에 더 높은 확신을 주면 정답 개수 변화가 작더라도 교차엔트로피는 커질 수 있습니다.

18. 저장 결과에서 과적합의 근거는?

Epoch 2 이후 훈련 손실은 감소하는데 검증 손실은 증가합니다. Train·Validation 간 차이가 벌어집니다.

19. 최종 Test는 어느 Epoch 모델인가?

Epoch 5입니다. 원본에는 검증상 가장 좋았던 Epoch 2 가중치를 복원하는 코드가 없습니다.

20. evaluate와 predict의 차이는?

evaluate는 X와 y로 손실·지표를 계산합니다. predict는 X로 클래스별 확률을 반환하며 정답은 필요하지 않습니다.

21. get_word_index 값에 왜 3을 더하는가?

load_data의 기본 index_from=3이 적용된 ID와 맞추기 위해서입니다. 시작·OOV·패딩의 특수 ID도 구분해야 합니다.

22. Total params 4,104,584가 모두 예측 가중치인가?

아닙니다. 저장 출력은 optimizer 상태를 포함합니다. 네트워크의 학습 가능한 파라미터는 1,368,194개입니다.

23. Test를 보며 모델을 고르면 왜 문제인가?

모델 선택에 Test 정보가 들어가 최종 평가의 독립성이 약해집니다. 선택은 Validation에서 하고 Test는 최종 확인에 사용합니다.

24. R²나 “RNN보다 낮다”는 설명을 그대로 써도 되는가?

R²는 이번 분류 목표의 지표가 아닙니다. RNN과의 우열도 동일 조건의 비교 실험이 없으므로 이 Notebook만으로 일반화할 수 없습니다.

헷갈리기 쉬운 개념

300 vs 128
300은 리뷰 길이, 128은 토큰 벡터 차원. batch_size도 우연히 128이지만 다른 개념입니다.
원핫 vs Embedding
이번 원핫은 정답 y 표현. Embedding은 입력 X의 토큰 표현.
Feature Map vs 층
Feature Map은 연산 결과를 뜻하며 독립 층 이름이 아닙니다.
Shape vs ndim
(32,300)은 Shape, 2는 ndim. 차원 수만 같아도 축 크기가 맞지 않을 수 있습니다.
Loss vs Accuracy
Loss는 확률에 대한 벌점, Accuracy는 최종 클래스 정답 비율.
Validation vs Test
Validation은 학습 선택·점검, Test는 최종 확인.
Confidence vs 성능
한 샘플의 확률과 전체 데이터의 정확도는 다릅니다.
Underfit vs Overfit
둘 다 부진하면 과소적합 등을 점검. 훈련만 좋아지고 검증이 나빠지면 과적합을 점검.
모델 가중치 vs optimizer
예측에 쓰는 네트워크 파라미터와 학습 상태를 구분.
원본 vs 보충
실행 설정을 바꾼 실험·새 예측 코드는 원문 재현 결과와 분리.
