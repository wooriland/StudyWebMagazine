from langchain_openai import ChatOpenAI
from langchain_core.prompts import PromptTemplate
from langchain_core.output_parsers import StrOutputParser
from dotenv import load_dotenv

load_dotenv()

llm = ChatOpenAI(
    model="gpt-4o-mini"
)

prompt = PromptTemplate.from_template(
    "'{topic}' 주제에 대해 "
    "'{num}'줄로 설명해줘."
)

output_str = StrOutputParser()

chain = (
    prompt
    | llm
    | output_str
)

result = chain.invoke({

    result

stream()

Input ↓ Chunk 1 Chunk 2 Chunk 3... ↓ 순차 출력

Python이 출력 Buffer에 데이터를 쌓아 두지 않고 현재 Chunk를 즉시 화면에 밀어내도록 합니다. LangChain 모델 기능이 아니라 Python 출력 제어입니다.

11 · FEW-SHOT PROMPTING

Few-shot — 예시를 보여주고 스타일과 구조를 유도하기

Few-shot은 Model Weight를 다시 학습하는 것이 아니라, 현재 Prompt에 몇 개의 입력·출력 예시를 넣어 LLM이 원하는 패턴을 참고하게 하는 방식입니다.

SYSTEM 츤데레 스타일의 카페 사장
인기 메뉴가 뭐예요?
아메리카노를 많이 마시긴 하는데...
에어컨 좀 더 세게 틀어주세요.
감기 걸리면 어쩌려고 그래...
새로운 질문: 비가 오는데 따뜻한 음료 추천해주실래요?
원본 Few-shot 핵심 코드 
llm = ChatOpenAI(
    model="gpt-4o-mini",
    temperature=0.8
)

prompt = ChatPromptTemplate.from_messages([
    (
        "system",
        "너는 이제부터 이 카페의 사장님이야. "
        "겉으로는 무심한 척하지만 속정 깊은 "
        "'츤데레' 스타일로 손님을 대해야 해."
    ),

    (
        "user",
        "여기 제일 인기 있는 메뉴가 뭐예요?"
    ),

    (
        "assistant",
        "글쎄, 뭐... 다들 아메리카노 마시긴 하던데."
    ),

    (
        "user",
        "에어컨 좀 더 세게 틀어주실 수 있나요?"
    ),

    (
        "assistant",
        "아니, 감기 걸리면 어쩌려고 그래?"
    ),

    (
        "user",
        "{question}"
    )
])

parser = StrOutputParser()

chain = (
    prompt
    | llm
    | parser
)

result = chain.stream({
    "question":
        "비가 오는데 따뜻한 음료 추천해주실래요?"
})

for chunk in result:
    print(
        chunk,
        end="",
        flush=True
    )
원본 주석과 실제 Prompt가 다릅니다.

실제 System Prompt는 츤데레 카페 사장 스타일인데, 일부 원본 주석에는 “백종원 말투”라는 이전 표현이 남아 있습니다. 실행 Prompt와 주석을 구분해서 읽습니다.

23 · PERFORMANCE IMPROVEMENT

성능 개선 — Weight가 아니라 Prompt와 Context를 개선하기

  1. System Prompt 명확화 역할, 금지사항, 출력 형식을 명확하게 정의합니다.
  2. Input Variable 계약 확인 Prompt 변수와 invoke Dictionary를 일치시킵니다.
  3. Output Parser 선택 AIMessage가 필요한지 문자열이 필요한지 결정합니다.
  4. Few-shot 품질 개선 실제 원하는 스타일을 잘 대표하는 예시를 사용합니다.
  5. Temperature 실험 정확성과 표현 다양성의 목적에 맞춰 조정합니다.
  6. Memory 전략 선택 전체·최근·요약 중 서비스 목적에 맞는 방식을 선택합니다.
  7. History 크기 관리 Token 수·Latency·Cost가 지나치게 증가하지 않게 합니다.
  8. Memory 사실성 검사 이전에 없던 정보를 기억했다고 생성하지 않는지 평가합니다.
  9. Streaming UX 첫 Token이 빠르게 화면에 나타나도록 구성합니다.
  10. 평가 질문 분리 Few-shot Example과 실제 Test Question을 분리합니다.
이번 단원의 튜닝은 Learning Rate 튜닝과 다릅니다.

모델 Weight를 수정하는 것이 아니라 애플리케이션의 입력 Context, Prompt 정책, History와 출력 흐름을 개선합니다.

25 · INTERVIEW / REVIEW

면접 포인트와 복습 질문

Q01. LangChain이란 무엇입니까?

LLM 자체가 아니라 Prompt, Model, Parser, Memory, Retriever, Tool 등을 연결해 LLM 애플리케이션을 구성하는 Framework입니다.

Q02. LCEL은 무엇입니까?

LangChain Expression Language이며 Runnable Component를 | 연산자로 연결합니다.

Q03. PromptTemplate과 ChatPromptTemplate의 차이는 무엇입니까?

PromptTemplate은 문자열 기반이고, ChatPromptTemplate은 System·Human·AI Role 기반 Message를 구성합니다.

Q04. StrOutputParser는 왜 사용합니까?

Chat Model의 Message Output에서 텍스트 결과를 문자열로 사용하기 위해서입니다.

Q05. invoke()와 stream()은 어떻게 다릅니까?

invoke는 최종 결과를 한 번에 반환하고, stream은 생성 결과를 Chunk 단위로 순차 반환합니다.

Q06. Parser 없는 Streaming에서는 어떻게 Text를 읽습니까?

원본에서는 Message Chunk의 .content를 읽습니다.

Q07. Few-shot은 Fine-tuning입니까?

아닙니다. Few-shot은 Prompt Context에 예시를 제공할 뿐 Weight를 변경하지 않습니다.

Q08. 이번 Notebook의 Loss는 무엇입니까?

없습니다. 사전 학습된 LLM을 API로 호출합니다.

Q09. Optimizer와 Learning Rate는 있습니까?

없습니다. Weight Training을 수행하지 않습니다.

Q10. Temperature와 Learning Rate의 차이는 무엇입니까?

Temperature는 생성 다양성을 조절하는 추론 설정이고, Learning Rate는 학습 중 Weight Update 크기를 조절하는 값입니다.

Q11. Conversation Memory의 본질은 무엇입니까?

이전 대화를 저장하고 다음 LLM 호출의 Prompt Context에 다시 제공하는 것입니다.

Q12. MessagesPlaceholder가 Memory 자체입니까?

아닙니다. History Message가 Prompt에 들어갈 위치를 정의합니다.

Q13. Buffer Memory는 무엇입니까?

전체 Conversation을 그대로 저장합니다.

Q14. Window Memory는 무엇입니까?

최근 일정 범위의 Conversation만 유지합니다.

Q15. Summary Memory는 무엇입니까?

이전 Conversation을 LLM이 요약하여 Context를 압축합니다.

Q16. Summary Memory의 주의점은 무엇입니까?

압축 과정에서 숫자·고유명사·작은 조건 등이 빠질 가능성이 있습니다.

Q17. 원본 Memory는 모든 History 처리를 자동으로 합니까?

실제 원본 코드는 load_memory_variables()로 불러오고, Chain 입력으로 전달한 뒤 save_context()로 저장합니다.

Q18. Streaming 응답을 왜 content 문자열에 누적합니까?

여러 Chunk를 하나의 완성된 Assistant 답변으로 만들어 Memory에 저장하기 위해서입니다.

Q19. 원본 저장 Output은 몇 개입니까?

한 개입니다. 기본 LCEL의 대한민국 설명 결과만 저장되어 있습니다.

Q20. Notebook 100에 완성된 PDF RAG 코드가 있습니까?

실제 셀의 중심은 LCEL·Prompt·Few-shot·Memory입니다. PDF·Embedding·FAISS RAG의 직접 구현은 ML 64에서 더 많이 다룹니다.

Q21. 환경 재현 시 주의할 점은 무엇입니까?

설치 명령에는 langchain-classic이 없지만 후반 Memory 코드에서는 langchain_classic.memory를 사용합니다.

Q22. R²를 사용합니까?

사용하지 않습니다. 이번 실습은 연속값 Regression 문제가 아닙니다.

Q23. 다음 Notebook은 무엇입니까?

없습니다. Notebook 100은 통합교안 36~100의 마지막 Notebook입니다. 이후는 전체 내용을 통합한 챗봇 프로젝트로 연결됩니다.
