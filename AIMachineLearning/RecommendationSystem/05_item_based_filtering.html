추천 05. Item-Based Filtering 내가 좋아한 Item과 비슷한 반응을 받은 Item을 찾는다

Item-Based Filtering은 여러 User가 Item들에 보인 Rating 또는 Interaction Pattern을 비교하여 Item 간 Similarity를 만들고, 사용자가 좋아한 Item과 Similar한 다른 Item을 추천하는 Collaborative Filtering 방식 입니다.

01 · 핵심 개념 설명

Item-Based Filtering이란?

교안 핵심 · Item 간 Similarity를 기반으로 Recommendation 수행

Item-Based Filtering은 사용자가 좋아한 Item의 내용 Feature를 직접 분석하는 것이 아니라, 여러 User들이 각 Item에 보인 Rating·Interaction Pattern을 비교 하여 Similar Item을 찾습니다.

1 Liked Item A 내가 좋아한 Item
→
2 User Reaction A에 대한 Rating Pattern
→
3 Similar Item B 반응 Pattern이 유사
→
4 Recommend B
가장 중요한 문장

Item-Based에서 “A와 B가 비슷하다” 는 것은 “같은 User들이 A와 B에 비슷하게 반응했다” 는 뜻입니다.

05 · 이번 단원의 핵심

Transpose — 비교 대상을 User에서 Item으로 바꾼다

Before · R

User × Item 
        A  B  C
U1      5  4  0
U2      5  4  3
U3      1  2  5
→ Rᵀ →

After · Rᵀ

Item × User 
        U1 U2 U3
A       5  5  1
B       4  4  2
C       0  3  5
R ∈ ℝm × n
↓ Transpose
Rᵀ ∈ ℝn × m
Transpose를 단순 문법으로 외우지 않습니다.

User-Based에서는 한 행이 User였고, Item-Based에서는 한 행이 Item이 되어야 하기 때문에 행렬을 전치합니다.

08 · Similarity 수식

Cosine Similarity

cos(A, B) = (A · B) / (||A|| × ||B||)

Item-Based에서는 A와 B가 여러 User의 Rating으로 표현된 Item Vector입니다.

User-Based cos(User A, User B)
같은 수식
Item-Based cos(Item A, Item B)

수식은 같아도 Vector가 무엇을 의미하는지가 달라집니다.

13 · Step 1·2 보완 개념

Candidate Score — Rating과 Similarity를 결합할 수 있다

Liked Item User Rating B와 Similarity Contribution
A 5 0.95 4.75
D 4 0.65 2.60
score(B) = 5×0.95 + 4×0.65 = 7.35

User가 더 좋아한 기준 Item과 Candidate의 Similarity가 높을수록 Candidate Score에 더 크게 기여하도록 설계할 수 있습니다.

이 7.35는 Item Similarity가 아닙니다.

User History와 여러 Item Similarity를 결합해서 만든 Recommendation Score 예입니다.

위 계산은 첨부 교안에서 필수 공식으로 제시한 내용이 아니라 Item-Based Ranking 원리를 이해하기 위한 보완 예제입니다.

26 · 코드 예제

Target User의 Liked Item에서 Recommendation 만들기 

target_user = "User_1"

user_history = ratings.loc[
    target_user
]


# Rating 4 이상을 선호 Item으로 정의
liked_items = user_history[
    user_history >= 4
].index


scores = {}


for liked_item in liked_items:

    user_rating = user_history[
        liked_item
    ]

    similarities = (
        item_similarity
        .loc[liked_item]
        .sort_values(
            ascending=False
        )
    )


    for candidate, similarity in similarities.items():

        # 기준 Item 자기 자신 제외
        if candidate == liked_item:
            continue

        # 이미 평가한 Item 제외
        if user_history[candidate] != 0:
            continue


        # 보완 예제:
        # User Rating × Item Similarity
        scores[candidate] = (
            scores.get(
                candidate,
                0.0
            )
            + user_rating * similarity
        )


recommendations = sorted(
    scores.items(),
    key=lambda x: x[1],
    reverse=True
)


print("[Recommendation]")


for rank, (item, score) in enumerate(
    recommendations,
    start=1
):
    print(
        f"{rank}. "
        f"{item} "
        f"- score={score:.4f}"
    )
user_history >= 4 Liked Item 선택 정책
item_similarity.loc[liked_item] Liked Item과 Similar한 Item
candidate == liked_item Self 제외
user_history[candidate] != 0 Seen Item 제외
user_rating * similarity Rating과 Similarity를 결합한 보완 Score
Rating×Similarity Score는 교안 직접 공식이 아니라 Item-Based Candidate Ranking을 이해하기 위한 보완 예제입니다.

Similarity뿐 아니라 해당 Similarity를 만들 때 실제로 몇 명의 User가 두 Item 모두에 Rating을 남겼는지도 확인할 수 있습니다.

Co-Rating은 Step 1·2의 보완 개념입니다.

29 · 실행 결과 해석

Item Similarity와 User Recommendation을 구분해서 읽는다

Item Similarity

  1. A → B 0.97
  2. A → E 0.91
  3. A → C 0.42

User Recommendation

  1. Item B 7.35
  2. Item E 6.91
  3. Item C 4.40
값 정확한 의미

Rank 1 현재 Recommendation Score 기준 첫 번째 Candidate
Item Similarity, Predicted Rating, Recommendation Score, Probability는 서로 같은 값이 아닙니다.

36 · 면접 포인트

질문과 답변으로 최종 복습

Q1. Item-Based Filtering이란 무엇인가요?

여러 User가 Item에 보인 Rating 또는 Interaction Pattern을 기준으로 Item 간 Similarity를 계산하고, 사용자가 선호한 Item과 Similar한 다른 Item을 추천하는 Collaborative Filtering 방식입니다.

Q2. Content-Based와 무엇이 다른가요?

Content-Based는 Item의 장르·텍스트 같은 Feature를 비교하고, Item-Based CF는 여러 User의 Reaction Pattern을 비교합니다.

Q3. 왜 User-Item Matrix를 Transpose하나요?

원래 Matrix에서는 한 행이 User이므로, Item을 행으로 만들어 Item Vector끼리 비교하기 위해 전치합니다.

Q4. Transpose 후 Matrix는 어떤 형태인가요?

User×Item이 Item×User로 바뀝니다.

Q5. Item Vector란 무엇인가요?

한 Item에 대해 여러 User가 남긴 Rating 또는 Interaction 값의 Vector입니다.

Q6. Item Similarity Matrix 크기는 어떻게 되나요?

Item이 n개라면 n×n입니다.

Q7. Cosine Similarity는 무엇을 의미하나요?

두 Item의 User Rating Vector 방향이 얼마나 유사한지를 나타냅니다.

Q8. Similarity 0.95는 좋아할 확률 95%인가요?

아닙니다. 두 Item에 대한 User Reaction Pattern이 현재 Vector 공간에서 유사하다는 뜻입니다.

Q9. Euclidean Distance는 어떻게 해석하나요?

Item Vector 간 거리이며 값이 작을수록 가깝다고 볼 수 있습니다.

Q10. 왜 Self Item을 제외하나요?

Item은 자기 자신과 가장 Similar하므로 새로운 다른 Item을 찾기 위해 제외합니다.

Q11. Target User의 Liked Item은 어떻게 정하나요?

Rating 4 이상처럼 Threshold를 사용할 수도 있고, Like·Purchase 등의 행동을 기준으로 정의할 수도 있습니다.

Q12. Candidate는 어떻게 만드나요?

Target User가 좋아한 Item 각각의 Similar Item을 모으고, 이미 경험한 Item을 제거하여 만들 수 있습니다.

Q13. 같은 Candidate가 여러 Item에서 나오면 어떻게 할 수 있나요?

Similarity를 합산하거나 User Rating과 Similarity를 결합하여 Recommendation Score를 만들 수 있습니다.

Q14. Item Similarity와 Recommendation Score는 같은 값인가요?

아닙니다. Similarity는 Item Pair의 관계이고, Recommendation Score는 Target User의 History를 반영한 User별 Candidate 점수입니다.

Q15. Item Cold Start란 무엇인가요?

New Item에 User Interaction이 없어 Item Vector와 다른 Item과의 Similarity를 만들기 어려운 문제입니다.

Q16. 왜 Item-Based는 초기 관심 Item이 있는 New User에게 사용할 수 있나요?

User History가 충분하지 않더라도 관심 Item 하나와 기존에 계산된 Item Similarity가 있으면 관련 Item을 찾을 수 있기 때문입니다.

Q17. 아무 행동도 없는 New User도 Item-Based로 개인화할 수 있나요?

기준이 되는 Liked Item 자체가 없으므로 Item-Based만으로는 어렵습니다.

Q18. Sparsity는 Item-Based에 어떤 문제를 만드나요?

두 Item을 함께 평가한 User가 적어 Item Similarity를 판단할 근거가 부족해질 수 있습니다.

Q19. Co-Rating Count란 무엇인가요?

두 Item 모두를 평가한 User의 수입니다. Similarity를 뒷받침하는 데이터 양을 확인하는 보조 정보가 될 수 있습니다.

Q20. Adjusted Cosine은 왜 사용할 수 있나요?

User마다 Rating Scale이 다를 수 있으므로 User 평균 Rating 등의 영향을 보정해서 Item 관계를 비교하기 위해 사용할 수 있습니다.

Q21. Item-Based가 항상 User-Based보다 빠른가요?

아닙니다. User 수와 Item 수, Similarity 저장 범위, Sparse 정도와 Offline 계산 방식에 따라 달라집니다.

Q22. Item-Based는 Hybrid에서 어떤 역할을 하나요?

실제 User Reaction에서 얻은 Item-Item 관계를 하나의 추천 Signal로 제공하고, Content-Based나 User-Based 결과와 결합할 수 있습니다.

Q23. Item Embedding과 어떻게 연결되나요?

Item-Based에서는 여러 User Rating으로 만든 긴 Item Vector를 직접 비교하지만, Model-Based에서는 Interaction 데이터를 사용해 더 작은 잠재 Item Embedding을 학습할 수 있습니다.
