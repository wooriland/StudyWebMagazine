추천 10. Deep Learning Hybrid Recommendation User·Item Embedding과 Content Feature를 DNN에서 통합한다

Deep Learning Hybrid Recommendation은 Collaborative Filtering에서 학습한 User·Item Embedding과 Text·Image·Genre 같은 Content Feature를 하나의 신경망에 입력하고, User·Item·Context 사이의 비선형 관계를 학습하여 Ranking Layer에서 최종 추천 점수를 계산하는 방식 입니다.

이번 단원의 핵심 질문

“User Embedding, Item Embedding, Content Feature를 하나의 신경망에서 학습하면 어떻게 User별 추천 점수를 만들고 무엇을 먼저 보여줄지 결정할 수 있는가?”

01 · 핵심 개념 설명

Deep Learning Hybrid Recommendation이란?

교안 직접 핵심 · Collaborative Filtering Embedding과 Content Feature를 신경망에서 통합

Deep Learning Hybrid Recommendation은 이미 계산된 추천 점수 몇 개를 마지막에 더하는 방식에서 한 단계 더 나아갑니다.

User ID와 Item ID에서 학습한 Embedding, Text·Image·Genre 같은 Content Feature, 필요하면 현재 Context까지 하나의 Model Input으로 결합하고 DNN에서 관계를 학습 합니다.

1 User Embedding 누구에게 추천하는가
+
2 Item Embedding 어떤 반응 Pattern의 Item인가
+
3 Content Feature Item이 어떤 내용인가
→
4 DNN 비선형 관계 학습
→
5 Ranking 무엇을 먼저 보여줄까
핵심 한 문장

Deep Hybrid는 Collaborative Signal과 Content Signal을 Model 내부에서 함께 학습하여 User별 Candidate Score와 순위를 만드는 방식 입니다.

+
Item Score × 0.4
↓

입력 표현과 관계를 함께 학습한다

User / Item Embedding
+
Content / Context
↓

↓
Ranking Score
기준 Weighted Hybrid Deep Hybrid
결합 대상 완성된 Score Embedding·Feature Vector

07 · Item Embedding

Item에 대한 User 반응 Pattern을 잠재 Vector로 표현한다

Movie A [0.72, 0.19, -0.44, 0.21, ...]
Movie B [0.68, 0.14, -0.39, 0.25, ...]
비슷한 User들이 Movie A와 B를 함께 소비
↓

↓

Item Embedding은 Item의 설명문 자체가 아니라 사람들이 그 Item에 보인 반응 관계 에서 학습됩니다.

09 · Content Feature

Text·Image·Genre를 Model Input Vector로 만든다

TEXT Text Encoder

줄거리·상품 설명·강의 소개를 Vector로 변환합니다.

IMAGE Image Encoder

포스터·상품 이미지의 시각 Pattern을 Vector로 변환합니다.

CATEGORY Category Embedding

Genre·Brand·Device 같은 Category를 Embedding으로 표현합니다.

NUMERIC Numeric Feature

가격·길이·조회 수 등의 Scale을 맞춰 사용합니다.

영화

Genre · Actor · Director · Synopsis · Poster · Release Year

쇼핑

음악

Artist · Genre · Tempo · Audio Feature · Lyrics

교육

10 · Context Feature · 보완 개념

같은 User와 Item도 현재 상황에 따라 Score가 달라질 수 있다

Time 시간대·요일
Device Mobile·TV·PC
Session 현재 탐색 흐름
Recent Action 최근 Click·Search
Location 현재 위치·지역
Exposure 이전 노출 횟수

평일 출근 시간 · Mobile

짧은 영상이나 빠르게 소비할 콘텐츠의 Score가 높아질 수 있습니다.

주말 저녁 · TV

긴 영화나 몰입형 콘텐츠의 Score가 높아질 수 있습니다.

Context Feature는 교안이 직접 열거한 입력은 아니지만, 실제 Deep Hybrid가 장기 취향과 현재의 단기 의도를 함께 표현하는 방법으로 이해할 수 있는 보완 개념입니다.

11 · Feature Combination

여러 Vector를 하나의 DNN Input으로 결합한다

x = [ eu ; ei ; ci ; z ]
User Embedding [B, 32]
Item Embedding [B, 32]
Content Feature [B, 64]
Context Feature [B, 16]
[B, 32] + [B, 32] + [B, 64] + [B, 16] → [B, 144]

결합 Vector는 누구인지, 어떤 Item인지, 어떤 내용인지, 지금 어떤 상황인지 를 하나의 입력으로 표현합니다.

14 · 출력값의 의미

Click·Watch Time·Satisfaction은 서로 다른 Target이다

Item Click 확률 Watch Time Satisfaction
Item A 0.92 5분 2.8
Item B 0.71 42분 4.5
Item C 0.80 20분 3.9

Click 최적화

A > C > B

Watch Time 최적화

B > C > A

Satisfaction 최적화

B > C > A
좋은 추천을 무엇으로 정의할지 먼저 결정해야 합니다.

Click만 높이는 추천은 Click 후 즉시 이탈하거나 만족도가 낮은 Item을 과도하게 노출할 수 있습니다.

15 · Sigmoid · Softmax · Regression

Output Layer는 Target의 성격에 맞춰 설계한다

Sigmoid

Click / No Click처럼 독립적인 Binary Probability를 출력할 수 있습니다.

0 ≤ p ≤ 1

Softmax

여러 Class 중 하나의 확률 분포를 만들 때 사용할 수 있습니다.

Σp = 1

Regression Head

Watch Time·Rating 같은 연속값을 예측할 수 있습니다.

ŷ ∈ ℝ
Sigmoid(x) = 1 / ( 1 + e-x )
교안은 Ranking Layer에서 Click Probability·Watch Time· Satisfaction과 Sigmoid 또는 Softmax를 제시합니다. 실제 구현에서는 Watch Time처럼 연속적인 Target에 Regression Output을 사용할 수 있으며, Output Layer는 Target에 맞춰 선택해야 합니다.

18 · Positive·Negative·Sampling · 보완 개념

미관측 Item을 모두 싫어한다고 해석하면 안 된다

Positive Example

  • Click = 1
  • Purchase = 1
  • Like = 1
  • Completion = 1

Negative 또는 미반응 Example

  • 노출 후 Click하지 않음
  • Click 후 바로 이탈
  • Sampling한 미관측 Item
  • 구매 후보였지만 미구매
Interaction 없음 ≠ User가 싫어함
Positive Item 1개 + Negative Item 4개 Sampling
미관측 Item은 User에게 노출되지 않았거나 아직 발견하지 못한 Item일 수 있습니다. Negative Sampling 방법은 모델이 무엇을 비선호로 학습하는지에 영향을 줍니다.

20 · Candidate Generation · Ranking · Re-ranking

전체 Item을 좁히고, 정교하게 평가하고, 최종 노출을 조정한다

STAGE 1

Candidate Generation

전체 Item에서 평가할 후보를 빠르게 좁힙니다.

1,000,000 → 2,000
STAGE 2

Deep Ranking

각 Candidate에 정교한 Prediction Score를 계산합니다.

2,000 → 100
STAGE 3

Re-ranking

정책·다양성·반복 노출을 반영해 최종 순서를 조정합니다.

100 → Top-10

Re-ranking 실제 서비스에 어떤 순서로 노출할까? Diversity·Availability·Policy

26 · 코드 또는 실제 예제

Deep Hybrid Model 구조 의사 코드

deep_hybrid_model.py 

class DeepHybridRecommender:

    def __init__(
        self,
        num_users: int,
        num_items: int,
        user_embedding_dim: int,
        item_embedding_dim: int,
        content_dim: int,
        context_dim: int,
    ) -> None:
        self.user_embedding = Embedding(
            num_users,
            user_embedding_dim,
        )

        self.item_embedding = Embedding(
            num_items,
            item_embedding_dim,
        )

        input_dim = (
            user_embedding_dim
            + item_embedding_dim
            + content_dim
            + context_dim
        )

        self.dnn = NeuralNetwork(
            input_dim=input_dim,
            hidden_dims=[
                128,
                64,
                32,
            ],
        )

        self.click_head = OutputLayer(
            input_dim=32,
            output_dim=1,
        )

        self.watch_head = OutputLayer(
            input_dim=32,
            output_dim=1,
        )

        self.satisfaction_head = OutputLayer(
            input_dim=32,
            output_dim=1,
        )


    def forward(
        self,
        user_ids,
        item_ids,
        content_features,
        context_features,
    ):
        user_vector = self.user_embedding(
            user_ids
        )

        item_vector = self.item_embedding(
            item_ids
        )

        combined = concatenate(
            [
                user_vector,
                item_vector,
                content_features,
                context_features,
            ],
            axis=-1,
        )

        hidden = self.dnn(
            combined
        )

        click_probability = sigmoid(
            self.click_head(
                hidden
            )
        )

        expected_watch_time = positive_output(
            self.watch_head(
                hidden
            )
        )

        satisfaction_score = self.satisfaction_head(
            hidden
        )

        return {
            "click_probability": click_probability,
            "expected_watch_time": expected_watch_time,
            "satisfaction_score": satisfaction_score,
        }
Embedding User·Item ID를 학습 Vector로 변환
concatenate() Embedding과 Feature를 하나의 입력으로 결합
self.dnn() 비선형 관계를 학습한 Hidden Representation 생성
Output Heads 각 Recommendation Target을 별도로 출력
이 코드는 교안의 구조를 설명하기 위한 개념적 의사 코드이며, 특정 Framework에서 바로 실행되는 완성 코드는 아닙니다.

27 · Multi-Task Training 코드

각 Task Loss를 결합하고 Parameter를 업데이트한다 

for epoch in range(max_epochs):

    model.train()

    outputs = model.forward(
        user_ids=train_user_ids,
        item_ids=train_item_ids,
        content_features=train_content,
        context_features=train_context,
    )

    click_loss = binary_cross_entropy(
        outputs["click_probability"],
        click_labels,
    )

    watch_loss = regression_loss(
        outputs["expected_watch_time"],
        watch_time_labels,
    )

    satisfaction_loss = regression_loss(
        outputs["satisfaction_score"],
        satisfaction_labels,
    )

    total_loss = (
        click_weight * click_loss
        + watch_weight * watch_loss
        + satisfaction_weight * satisfaction_loss
    )

    optimizer.zero_grad()

    total_loss.backward()

    optimizer.step()
click_loss Click Target Error
watch_loss Watch Time Target Error
total_loss Task별 Loss Weight를 반영한 전체 학습 목표
backward() Embedding과 DNN Parameter의 Gradient 계산

def generate_candidates(
    *,
    item_based_items: list[str],
    embedding_items: list[str],
    popular_items: list[str],
    recent_items: list[str],
    limit: int = 2000,
) -> list[str]:
    merged = (
        item_based_items
        + embedding_items
        + popular_items
        + recent_items
    )

    unique_candidates = list(
        dict.fromkeys(
            merged
        )
    )

    return unique_candidates[:limit]

30 · 장점과 한계

복잡한 관계를 학습할 수 있지만 구현·학습·운영 비용이 증가한다

장점

  • Collaborative와 Content 정보를 함께 사용
  • User·Item·Context의 비선형 관계 학습
  • Click·Watch·Satisfaction 등 여러 Target 예측
  • User·Item의 잠재 Embedding 학습
  • Side Feature를 이용한 Cold Start 보완 가능성
  • 실제 서비스 목표와 Ranking 연결

한계

  • Data·Feature·Model Pipeline이 복잡함
  • 많은 데이터와 연산 자원이 필요할 수 있음
  • 많은 Parameter로 Overfitting 가능
  • 추천 근거 설명이 어려울 수 있음
  • Popularity Bias를 그대로 학습할 수 있음
  • Training-Serving Skew와 Drift 관리 필요

38 · 면접 포인트

질문과 답변으로 최종 복습

Q1. Deep Learning Hybrid Recommendation이란 무엇인가요?

User·Item ID를 Embedding으로 학습하고 Text·Image·Genre 같은 Content Feature를 결합한 뒤 DNN으로 비선형 관계를 학습하여 Ranking Layer에서 최종 Recommendation Score를 만드는 방식입니다.

Q2. 왜 Hybrid Recommendation이 필요한가요?

Content-Based, User-Based, Item-Based가 서로 다른 정보와 한계를 가지므로 Collaborative Signal과 Content Signal을 함께 사용해 단일 방식의 약점을 보완하기 위해서입니다.

Q3. User Embedding이란 무엇인가요?

User ID를 학습 가능한 작은 잠재 Vector로 변환한 것으로, User의 Interaction Pattern을 Prediction에 유용한 형태로 표현합니다.

Q4. Item Embedding이란 무엇인가요?

Item ID를 학습 가능한 잠재 Vector로 표현한 것으로, 여러 User가 해당 Item에 보인 반응 Pattern을 반영합니다.

Q5. Item Embedding과 Content Feature의 차이는 무엇인가요?

Item Embedding은 Interaction에서 학습된 잠재 표현이고, Content Feature는 Genre·Text·Image처럼 Item이 가진 명시적 정보입니다.

Q6. Embedding은 어떻게 학습되나요?

초기값에서 시작하여 Prediction Loss가 줄어드는 방향으로 Backpropagation 과정에서 다른 Parameter와 함께 업데이트됩니다.

Q7. DNN의 역할은 무엇인가요?

User Embedding, Item Embedding, Content Feature, Context 사이의 복잡한 비선형 관계를 학습합니다.

Q8. Ranking Layer의 역할은 무엇인가요?

DNN의 Hidden Representation을 Click Probability, Watch Time, Satisfaction 또는 Final Ranking Score로 변환합니다.

Q9. Sigmoid와 Softmax는 어떻게 다른가요?

Sigmoid는 Click 여부 같은 독립 Binary Probability에, Softmax는 여러 Class의 확률 분포를 만들 때 사용할 수 있습니다.

Q10. Watch Time도 Sigmoid로 예측하나요?

실제 구현에서는 Watch Time 같은 연속 Target에 Regression Output을 사용할 수 있습니다. Output Layer는 Target의 성격에 맞춰야 합니다.

Q11. Single-Task와 Multi-Task의 차이는 무엇인가요?

Single-Task는 하나의 Target만 예측하고, Multi-Task는 Shared Representation에서 여러 Target을 함께 예측합니다.

Q12. Candidate Generation과 Ranking의 차이는 무엇인가요?

Candidate Generation은 전체 Item에서 평가할 후보를 빠르게 좁히는 단계이고, Ranking은 Candidate별 Score를 계산해 순서를 정하는 단계입니다.

Q13. Negative Sampling이 필요한 이유는 무엇인가요?

미관측 Item이 매우 많기 때문에 일부 Negative Candidate만 선택하여 학습 비용을 줄이고 Positive와의 차이를 학습하기 위해서입니다.

Q14. 미관측 Item은 모두 Negative인가요?

아닙니다. 노출되지 않았거나 아직 발견하지 못해서 Interaction이 없을 수 있으므로 미관측과 실제 비선호를 구분해야 합니다.

Q15. Deep Hybrid는 Cold Start를 해결하나요?

User Profile이나 Item Content Feature가 있다면 보완할 수 있지만, Interaction과 Feature가 모두 없는 User·Item을 완전히 해결하지는 못합니다.

Q16. Ranking Score는 Probability인가요?

반드시 그렇지는 않습니다. Click Probability 자체일 수도 있지만, 여러 Signal을 결합한 상대적인 Ranking Score일 수도 있습니다.

Q17. Click Probability만 최적화하면 어떤 문제가 있나요?

Click은 높지만 Watch Time이나 Satisfaction이 낮은 Item이 과도하게 노출될 수 있습니다.

Q18. Training과 Prediction의 차이는 무엇인가요?

Training은 과거 Interaction으로 Embedding과 DNN Parameter를 업데이트하는 과정이고, Prediction은 저장된 Model로 현재 Candidate Score를 계산하는 과정입니다.

Q19. Training-Serving Skew란 무엇인가요?

Training에서 사용한 Feature 계산 방식과 Online Serving의 Feature가 달라 Prediction 성능이 저하되는 문제입니다.

Q20. Deep Hybrid를 한 문장으로 설명한다면?

User·Item Embedding과 Content Feature를 DNN에서 통합 학습하고 Ranking Layer를 통해 User별 최종 추천 순서를 계산하는 방식입니다.
