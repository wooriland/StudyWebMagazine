RECOMMENDATION SYSTEM · LESSON 06 · USER-BASED VS ITEM-BASED

추천 06. User-Based와 Item-Based 비교 같은 User-Item Matrix를 왜 서로 다르게 보는가?

User-Based와 Item-Based는 모두 Collaborative Filtering이며 동일한 User-Item Interaction에서 출발합니다. 하지만 User-Based는 User를 비교 축으로 사용하고, Item-Based는 Item을 비교 축으로 사용하기 때문에 Cold Start, Sparsity, 계산량, 확장성, 취향 변화에서 서로 다른 특성을 가집니다.

이번 단원의 핵심 질문

“같은 User-Item Matrix에서 출발하는데, 왜 User-Based와 Item-Based는 서로 다른 장점과 문제를 가지는가?”
User-Based Item-Based User-Item Matrix User × User Item × Item Cold Start Sparsity Scalability Preference Drift Cosine Similarity Ranking Hybrid Embedding
추천 이론 과목에서의 역할

이번 단원은 User-Based와 Item-Based 코드를 다시 실습하는 것이 목적이 아닙니다.

핵심은 “비교 대상이 User인가 Item인가?” 라는 차이가 왜 신규 사용자·신규 아이템·계산량·확장성·취향 변화 문제로 이어지는지 이해하는 것입니다.

05 · Cosine Similarity

같은 공식, 다른 의미

cos(x, y) = (x · y) / (||x|| × ||y||)

User-Based

cos(User A, User B)

여러 Item에 대한 두 User의 Rating Pattern을 비교합니다.

Item-Based

cos(Item A, Item B)

여러 User가 두 Item에 보인 Rating Pattern을 비교합니다.

Similarity = Probability가 아닙니다.

0.92라고 해서 92% 확률로 좋아한다는 뜻이 아닙니다.

10 · 계산량

무엇을 몇 개 비교해야 하는가?

User-Based

User Similarity = m × m

User 수를 m이라고 할 때 User Pair 규모가 빠르게 증가합니다.

Item-Based

Item Similarity = n × n

Item 수를 n이라고 할 때 Item Pair 규모가 빠르게 증가합니다.

Item-Based가 항상 더 가벼운 것은 아닙니다.

Item 수가 User 수보다 훨씬 많다면 Item × Item 관계가 더 커질 수 있습니다.

11 · Scalability

확장성은 단순히 “느리다”는 뜻이 아니다

User가 10배 늘면? Item이 10배 늘면? Interaction이 계속 쌓이면? Similarity를 얼마나 자주 갱신? Memory는 충분한가? 응답 시간은 유지되는가?

Step 1·2 보완 계산 관점

User-Based

약 O(m²n)

모든 User Pair를 Item 축으로 직접 비교한다고 단순화한 개념적 비용입니다.

Item-Based

약 O(n²m)

모든 Item Pair를 User 축으로 직접 비교한다고 단순화한 개념적 비용입니다.

실제 Sparse Matrix·벡터화·Top-N 계산에서는 계산 비용이 달라질 수 있으므로 위 수식은 알고리즘 구조 이해용입니다.

12 · Preference Drift

사용자의 취향이 바뀌면 어디가 변하는가?

User-Based

↓
User Vector 변화
↓
User Similarity 변화
↓
Neighborhood 변화
↓
Recommendation 변화

Item-Based

User 취향 변화
↓

↓

↓

Recent N Time Decay Recent Weight Short-term Profile
Time Decay 등은 교안의 기본 비교 범위를 확장한 보완 개념입니다.

13 · Item Relation 안정성

왜 Item-Based 관계가 상대적으로 안정적일 수 있는가?

개별 User

User A의 취향은 시간에 따라 빠르게 변할 수 있습니다.

SF → History → Travel

집단 Item Relation

많은 User가 지속적으로 A와 B에 비슷하게 반응하면 A-B 관계는 상대적으로 안정적으로 나타날 수 있습니다.

A ↔ B 0.92
패션·뉴스·계절 상품처럼 Item 관계 자체가 빠르게 변하는 서비스에서는 Item-Based 관계도 자주 업데이트해야 합니다.

→

User-Based

많은 Neighbor가 이미 인기 Item을 평가했기 때문에 Candidate에 자주 등장할 수 있습니다.

Item-Based

인기 Item은 Co-Rating User가 많아 다른 Item과 관계를 만들기 쉬울 수 있습니다.

Popular ≠ Personalized

17 · 코드 또는 실제 예제

코드 한 줄 차이를 알고리즘 의미로 읽기

compare_cf.py 

import pandas as pd
from sklearn.metrics.pairwise import cosine_similarity


ratings = pd.DataFrame(
    [
        [5, 4, 0, 1],
        [5, 4, 3, 0],
        [1, 2, 5, 4],
        [5, 4, 4, 0],
    ],
    index=[
        "User_A",
        "User_B",
        "User_C",
        "User_D",
    ],
    columns=[
        "Movie_A",
        "Movie_B",
        "Movie_C",
        "Movie_D",
    ],
)


# ---------------------------------
# User-Based
# 행 = User
# ---------------------------------
user_similarity = pd.DataFrame(
    cosine_similarity(
        ratings
    ),
    index=ratings.index,
    columns=ratings.index,
)


# ---------------------------------
# Item-Based
# ratings.T에서 행 = Item
# ---------------------------------
item_similarity = pd.DataFrame(
    cosine_similarity(
        ratings.T
    ),
    index=ratings.columns,
    columns=ratings.columns,
)


print(
    "User-Item:",
    ratings.shape
)

print(
    "User Similarity:",
    user_similarity.shape
)

print(
    "Item Similarity:",
    item_similarity.shape
)
cosine_similarity(ratings) User 행끼리 비교 → User × User
ratings.T 비교 축을 User에서 Item으로 변경
cosine_similarity(ratings.T) Item 행끼리 비교 → Item × Item

Sparsity 확인 — 보완 코드

observed = (
    ratings > 0
).sum().sum()


total = (
    ratings.shape[0]
    * ratings.shape[1]
)


sparsity = (
    1
    - observed / total
)


print(
    "Sparsity:",
    sparsity
)

19 · 자주 하는 실수

비교 단원에서 특히 틀리기 쉬운 부분

실수 왜 틀렸는가? 올바른 이해
Item-Based가 무조건 우수 절대적 우위 없음 서비스 구조에 따라 선택
Item-Based는 항상 빠름 Item 수가 더 많을 수 있음 m과 n을 함께 확인
User-Based만 User Cold Start 행동 0이면 Item-Based도 기준 Item 없음 완전 Cold Start 구분
User-Based는 New Item 해결 Interaction 0이면 Neighbor도 정보 없음 CF 전체 Cold Start 이해
Cold Start = Sparsity 원인이 다름 초기 데이터 없음 vs 전체 희소성
Similarity = Probability Vector 관계와 확률은 다름 Similarity로 해석
높은 Similarity = Final 추천 Filtering·Ranking 남음 Candidate 단계 구분
Item 관계는 영원히 고정 Interaction 변화 가능 Update 고려
User-Based는 항상 최신 취향 과거 Rating 영향 가능 Preference Drift 고려
Item-Based는 개인화가 약함 User History로 Rank 가능 Relation과 Ranking 분리

21 · 실무 연결

같은 서비스에서도 두 방식의 설명이 다르다

영화 · User-Based

나와 시청·Rating Pattern이 비슷한 User들이 좋아한 Movie를 추천합니다.

Similar Viewer → Movie

영화 · Item-Based

내가 좋아한 Movie와 같은 User들이 비슷하게 평가한 Movie를 추천합니다.

Movie → Similar Movie

쇼핑 · User-Based

나와 구매 Pattern이 비슷한 고객의 구매 상품을 참고합니다.

Similar Customer → Product

쇼핑 · Item-Based

내가 구매한 상품을 구매한 고객들이 함께 구매한 다른 상품을 추천합니다.

Product → Related Product

25 · 면접 포인트

질문과 답변으로 최종 복습

Q1. User-Based와 Item-Based의 가장 큰 차이는 무엇인가요?

User-Based는 User Rating Vector끼리 비교하여 Similar User를 찾고, Item-Based는 User-Item Matrix를 전치한 뒤 Item Rating Vector끼리 비교하여 Similar Item을 찾습니다.

Q2. 두 방식은 서로 다른 데이터를 사용하나요?

아닙니다. 둘 다 User-Item Interaction에서 만든 User-Item Matrix를 사용하지만 비교 방향이 다릅니다.

Q3. User-Based Similarity Matrix의 크기는?

User가 m명이면 m×m입니다.

Q4. Item-Based Similarity Matrix의 크기는?

Item이 n개이면 n×n입니다.

Q5. User-Based가 New User에 약한 이유는?

신규 User는 Interaction이 부족하기 때문에 User Vector와 다른 User와의 Similarity를 계산할 근거가 부족합니다.

Q6. Item-Based가 New User에게 유리할 수 있는 이유는?

초기 관심 Item이 있다면 기존에 계산된 Item Similarity를 이용해 바로 관련 Item을 찾을 수 있기 때문입니다.

Q7. 아무 행동도 없는 User도 Item-Based로 개인화 가능한가요?

아닙니다. 기준 Liked Item 자체가 없기 때문에 별도의 Fallback이 필요합니다.

Q8. Item-Based의 대표 Cold Start는 무엇인가요?

New Item입니다. Interaction이 없어 Item Vector와 Item Similarity를 만들기 어렵습니다.

Q9. User-Based는 New Item에 강한가요?

완전히 그렇지 않습니다. Interaction이 전혀 없는 Item은 Similar User도 해당 Item 정보를 가지고 있지 않기 때문에 Collaborative Filtering 전체에서 어렵습니다.

Q10. Sparsity는 두 방식에 어떻게 다르게 나타나나요?

User-Based에서는 공통 Item 부족으로, Item-Based에서는 공통 User 부족으로 나타납니다.

Q11. User-Based의 확장성 문제가 발생하는 이유는?

User 수가 증가할수록 User×User Similarity 관계가 빠르게 증가하기 때문입니다.

Q12. Item-Based가 항상 더 빠른가요?

아닙니다. Item 수가 훨씬 많다면 Item×Item 계산이 더 커질 수 있습니다.

Q13. Preference Drift가 User-Based에 중요한 이유는?

User의 취향이 바뀌면 User Vector와 Similarity, Neighborhood 자체가 바뀔 수 있기 때문입니다.

Q14. Item-Based 관계는 항상 안정적인가요?

아닙니다. 충분한 데이터에서는 상대적으로 안정적일 수 있지만, 뉴스·패션·계절 상품 등에서는 관계도 빠르게 변할 수 있습니다.

Q15. Similarity 0.9는 90% 선호 확률인가요?

아닙니다. 현재 Vector 공간에서 User 또는 Item 관계가 유사한 정도입니다.

Q16. Similarity와 Ranking Score는 어떤 차이가 있나요?

Similarity는 User Pair 또는 Item Pair 관계이고, Ranking Score는 특정 User에게 Candidate Item의 우선순위를 정하기 위한 별도의 점수입니다.

Q17. User-Based와 Item-Based 중 무엇이 더 좋은가요?

절대적으로 더 좋은 방식은 없습니다. User·Item 규모, Sparsity, Cold Start, 변화 속도와 운영 비용을 보고 판단해야 합니다.

Q18. 왜 Hybrid가 필요한가요?

Content-Based, User-Based, Item-Based가 각각 서로 다른 Signal과 한계를 가지므로 여러 결과를 결합해 단점을 보완할 수 있기 때문입니다.

Q19. Model-Based로 왜 확장하나요?

User·Item 수가 커지고 Matrix가 Sparse해지면 긴 Rating Vector를 직접 비교하는 방식에 한계가 있으므로, User와 Item의 잠재 Embedding을 학습하는 방식으로 확장할 수 있습니다.

Q20. 두 알고리즘을 한 문장으로 구분한다면?

User-Based는 비슷한 사람의 선택을 이용하고, Item-Based는 내가 좋아한 Item의 관계를 이용합니다.
