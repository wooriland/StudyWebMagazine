추천 02. Content-Based Recommendation 이 사람이 좋아했던 것과 비슷한 것은 무엇인가?

Content-Based Recommendation은 사용자가 좋아했던 아이템의 장르·텍스트·태그·속성과 같은 Item Feature를 분석하고, 그 Feature와 비슷한 새로운 아이템을 찾는 추천 방식입니다.

이번 단원의 핵심 질문

“사용자가 좋아했던 Item에는 어떤 Feature가 있고, 어떤 다른 Item이 그 Feature와 가장 비슷한가?”
Item Feature Item-Feature Matrix Vector User Profile Multi-Hot TF-IDF Word2Vec Cosine Similarity Ranking Cold Start
이 단원의 역할

추천시스템 과목에서는 모델 성능 튜닝보다 어떤 데이터를 추천 근거로 사용하고, 그것을 어떻게 Vector로 표현하며, 무엇과 무엇을 비교하는가 를 이해하는 것이 우선입니다.

뒤의 TF-IDF·Word2Vec 코드는 AI Machine Learning 실습을 반복하기 위한 것이 아니라, 콘텐츠 기반 추천의 계산 구조를 확인하기 위한 보조 예제입니다.

01 · 핵심 개념 설명

Content-Based Recommendation이란?

교안 핵심 · 사용자가 선호하는 Item의 특성을 기반으로 추천

콘텐츠 기반 추천은 사용자가 좋아했던 아이템 자체가 어떤 특징을 가지고 있는지 분석하는 것에서 시작합니다.

1 Liked Item 사용자가 좋아한 대상
→
2 Item Feature 장르·텍스트·속성
→
3 Similarity 후보와 얼마나 비슷한가
→
4 Recommendation 높은 점수의 후보

사용자가 SF + Action + Space 영화를 좋아했다.

↓

후보 영화 중 SF + Action + Space 특성이 강한 영화를 찾는다.

↓

Feature Similarity가 높은 영화를 추천한다.

한 문장으로 기억하기

Content-Based는 “나와 비슷한 사람” 을 찾는 것이 아니라 “내가 좋아했던 콘텐츠와 비슷한 콘텐츠” 를 찾습니다.

Item ID와 Feature는 다릅니다

04 · 핵심 개념 설명

Feature Vectorization — 계산 가능한 숫자로 바꾼다

사람은 장르·문장·이미지를 이해할 수 있지만, 유사도 계산에는 숫자 표현이 필요합니다.

Raw Feature SF + Action + Space
→
Representation Multi-Hot
→
Vector [1, 1, 0, 0, 1]
Feature 종류 예 표현 방법 예
범주형 장르, 카테고리 One-Hot / Multi-Hot
태그형 SF, 입문, 가족 Multi-Hot
텍스트 줄거리, 상품 설명 TF-IDF / Embedding
숫자형 가격, 시간, 길이 Scaling 후 활용
이미지 포스터, 상품 사진 Image Embedding
복합형 장르 + 텍스트 + 가격 여러 Feature Vector 결합
Feature가 많다고 무조건 좋은 것은 아닙니다.

추천 목표와 관계없는 Feature까지 넣으면 Vector 공간과 Similarity가 오히려 왜곡될 수 있습니다.

05 · 핵심 개념 설명

User Profile — 좋아했던 Item으로 취향 Vector 만들기

사용자가 좋아한 여러 아이템의 Feature를 합치면 사용자의 콘텐츠 취향을 하나의 Vector로 표현할 수 있습니다.

Movie A [1, 1, 0] Action + SF
+
Movie B [1, 0, 0] Action
→ 평균 →
User Profile [1.0, 0.5, 0.0]
pu = 1 / |Iu| × Σ xi

여기서 xi는 선호 Item의 Feature Vector이고, pu는 사용자 Profile입니다.

Rating을 가중치로 사용할 수도 있습니다

pu = Σ wuixi / Σ wui

예를 들어 5점을 준 영화의 Feature를 3점을 준 영화보다 더 강하게 반영할 수 있습니다.

보완 구조

위 User Profile 수식은 콘텐츠 기반 추천을 이해하기 쉽게 확장한 설계 예입니다. 특정 하나의 고정 공식으로 외우기보다 “선호한 Item Feature를 어떻게 사용자 취향으로 합칠 것인가?” 라는 문제로 이해합니다.

07 · 핵심 개념 · 수식

Cosine Similarity — Vector 방향이 얼마나 비슷한가?

cos(A, B) = (A · B) / (||A|| × ||B||)

두 Vector가 같은 방향을 가리킬수록 코사인 유사도가 높아집니다.

손으로 계산하기

A = [1, 1, 0]

B = [1, 1, 1]

A · B = 1×1 + 1×1 + 0×1 = 2

||A|| = √2

||B|| = √3

cos(A, B) = 2 / (√2 × √3) ≈ 0.8165

값 Vector 관점의 의미
1 같은 방향
0 직교하는 방향
-1 정반대 방향
Similarity 0.82 ≠ 선호 확률 82%

0.82는 선택한 Feature Vector 공간에서 두 Vector 방향의 유사도를 나타내는 값입니다.

영벡터 주의

[0, 0, 0]처럼 Feature 정보가 전혀 없는 Vector는 수학적 코사인 공식의 분모가 0이 됩니다. Feature 부족 상태를 별도로 처리해야 합니다.

09 · 텍스트 Feature

TF-IDF — 이 문서에서 중요한 단어는 무엇인가?

TF · Term Frequency

특정 단어가 현재 문서에서 얼마나 많이 등장하는가 를 봅니다.

IDF · Inverse Document Frequency

그 단어가 전체 문서에서는 얼마나 희귀한가 를 반영합니다.

TF-IDF(t, d) = TF(t, d) × IDF(t)
현재 문서에서 많이 등장
+
전체 문서에서는 상대적으로 드묾
→
높은 TF-IDF

Document-Term Matrix

Movie space robot future love family
Movie A .42 .31 .25 0 0
Movie B .35 .20 .30 0 .04
Movie C 0 0 0 .51 .39

행 하나가 영화 하나의 줄거리 Vector가 됩니다.

Overview → TF-IDF → Document Vector → Cosine Similarity
TF-IDF의 특징

실제로 등장한 단어와 그 단어의 중요도에 강하게 의존합니다. 의미가 비슷해도 표현 단어가 크게 다르면 Similarity가 낮게 나올 수 있습니다.

10 · 텍스트 Feature · Embedding

Word2Vec — 단어의 문맥 관계를 Vector로 표현한다

Word2Vec은 단어 주변의 문맥 관계를 학습하여 각 단어를 고정 길이 Vector로 표현합니다.

space [0.12, -0.34, 0.51, ...]
planet [0.10, -0.30, 0.49, ...]
robot [-0.04, 0.27, 0.62, ...]

문장이 아니라 단어 Vector라는 점이 중요합니다

Overview
↓
Word Tokens space / robot / future / earth
↓
Word Embeddings
↓
Average 단어 Vector 평균
↓
Movie Vector
MovieVector = (v₁ + v₂ + ... + vₙ) / n
단어 평균 Vector가 문장의 모든 의미를 보존하지는 않습니다.

단어 순서와 문장 구조 정보가 많이 사라질 수 있습니다. 이 방식은 콘텐츠 기반 추천 구조를 이해하기 위한 비교적 단순한 문서 표현 방법입니다.

11 · 비교

TF-IDF vs Word2Vec — 같은 줄거리라도 추천이 달라진다

기준 TF-IDF Word2Vec
핵심 단어의 등장과 중요도 단어의 문맥 관계
Feature 공간 Vocabulary 단어 Embedding 차원
문서 표현 TF-IDF Weight Vector 단어 Vector를 결합
장점 단순하고 해석하기 쉬움 단어 의미 관계를 반영할 수 있음
대표 한계 다른 표현의 의미적 유사성을 놓칠 수 있음 학습 데이터와 문서 Vector 구성법에 영향받음

문장 A

“지난날의 잘못에 대해 사과를 구한다.”

문장 B

“과거의 실수에 대해 용서를 빈다.”

사람이 보기에는 의미가 비슷하지만, 사용된 단어가 다르므로 TF-IDF와 Word2Vec이 서로 다른 Similarity를 만들 수 있습니다.

같은 원본 데이터라도 Vector Representation이 달라지면 추천 결과도 달라질 수 있습니다.

텍스트의 Sparsity

TF-IDF의 Document-Term Matrix는 Vocabulary가 매우 크지만 한 문서에는 일부 단어만 등장하므로 대부분 값이 0이 됩니다.

Movie × Vocabulary → 대부분의 셀 = 0 → Sparse Matrix

이는 User-Item Matrix의 Sparsity와 연결되는 개념이지만, 현재는 문서-단어 행렬에서 값이 대부분 0이라는 의미로 구분합니다.

가장 작은 장르 기반 Content-Based

먼저 텍스트 없이 장르 Vector → User Profile → Similarity 만 확인합니다.

genre_content_based.py 

import numpy as np
from sklearn.metrics.pairwise import cosine_similarity


# Feature 순서
# [Action, SF, Romance]

movie_a = np.array([1, 1, 0], dtype=float)
movie_b = np.array([1, 0, 0], dtype=float)

candidate_c = np.array([1, 1, 0], dtype=float)
candidate_d = np.array([0, 0, 1], dtype=float)


# 1. 사용자가 좋아한 영화의 평균 Feature
user_profile = np.mean(
    [movie_a, movie_b],
    axis=0
)

print("User Profile:")
print(user_profile)


# 2. cosine_similarity는 2차원 입력을 사용
profile_2d = user_profile.reshape(1, -1)

candidate_matrix = np.vstack(
    [candidate_c, candidate_d]
)


# 3. User Profile과 후보 영화 비교
scores = cosine_similarity(
    profile_2d,
    candidate_matrix
)[0]


print("\nSimilarity:")
print("Candidate C:", scores[0])
print("Candidate D:", scores[1])


# 4. 점수가 높은 순서
ranking = np.argsort(scores)[::-1]

print("\nRanking:")
for rank, index in enumerate(ranking, start=1):
    print(
        rank,
        ["Candidate C", "Candidate D"][index],
        scores[index]
    )

이 코드에서 읽어야 하는 것

movie_a Item Feature Vector
np.mean() 선호 Item으로 User Profile 생성
cosine_similarity() User Profile과 Candidate Item 비교
np.argsort() Similarity Ranking

TF-IDF로 줄거리 기반 유사 영화 찾기

tfidf_content_based.py 

from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity


titles = [
    "Space Rescue",
    "Mars Mission",
    "Family Wedding",
    "Robot Planet"
]

overviews = [
    "astronaut space rescue future planet",
    "space mars astronaut mission planet",
    "family love wedding relationship",
    "robot future space planet technology"
]


# 1. 텍스트 → TF-IDF Vector
vectorizer = TfidfVectorizer(
    stop_words="english"
)

tfidf_matrix = vectorizer.fit_transform(
    overviews
)


print(
    "TF-IDF Matrix Shape:",
    tfidf_matrix.shape
)


# 2. 영화 줄거리끼리 Cosine Similarity
similarity = cosine_similarity(
    tfidf_matrix
)


# 3. 첫 번째 영화를 기준으로 추천
target_index = 0

scores = list(
    enumerate(
        similarity[target_index]
    )
)


# 4. 자기 자신 제외
scores = [
    (index, score)
    for index, score in scores
    if index != target_index
]


# 5. Similarity 내림차순
scores.sort(
    key=lambda x: x[1],
    reverse=True
)


# 6. Top-3
print("\nRecommendation:")

for rank, (index, score) in enumerate(
    scores[:3],
    start=1
):
    print(
        f"{rank}. "
        f"{titles[index]} "
        f"- similarity={score:.4f}"
    )

코드 흐름

TfidfVectorizer 줄거리를 TF-IDF Vector로 변환
fit_transform() Document-Term Matrix 생성
cosine_similarity() 영화와 영화의 줄거리 비교
index != target_index 자기 자신 제외
reverse=True 높은 Similarity부터 정렬

Word2Vec으로 Movie Vector 만들기

Word2Vec은 단어 Vector를 제공하므로, 영화 줄거리 전체를 표현할 Movie Vector를 별도로 만듭니다.

word2vec_content_based.py 

import numpy as np

from gensim.models import Word2Vec
from sklearn.metrics.pairwise import cosine_similarity


titles = [
    "Space Rescue",
    "Mars Mission",
    "Family Wedding",
    "Robot Planet"
]


sentences = [
    ["astronaut", "space", "rescue", "future", "planet"],
    ["space", "mars", "astronaut", "mission", "planet"],
    ["family", "love", "wedding", "relationship"],
    ["robot", "future", "space", "planet", "technology"]
]


# 1. Word2Vec 학습
model = Word2Vec(
    sentences=sentences,
    vector_size=50,
    window=3,
    min_count=1,
    sg=1
)


# 2. 한 문장을 하나의 Vector로 만들기
def sentence_vector(tokens):
    vectors = [
        model.wv[word]
        for word in tokens
        if word in model.wv
    ]

    if not vectors:
        return np.zeros(
            model.vector_size
        )

    return np.mean(
        vectors,
        axis=0
    )


# 3. 모든 영화 Vector 생성
movie_vectors = np.stack([
    sentence_vector(tokens)
    for tokens in sentences
])


print(
    "Movie Vector Shape:",
    movie_vectors.shape
)


# 4. Movie × Movie Similarity
similarity = cosine_similarity(
    movie_vectors
)


target_index = 0


# 5. 자기 자신 제외 + Ranking
scores = [
    (index, score)
    for index, score
    in enumerate(similarity[target_index])
    if index != target_index
]


scores.sort(
    key=lambda x: x[1],
    reverse=True
)


print("\nRecommendation:")

for rank, (index, score) in enumerate(
    scores[:3],
    start=1
):
    print(
        f"{rank}. "
        f"{titles[index]} "
        f"- similarity={score:.4f}"
    )
Word2Vec 코드에서 가장 중요한 부분

model.wv[word]는 단어 Vector입니다. 여러 단어 Vector를 평균해 영화 하나의 Vector를 만든 뒤 영화끼리 비교합니다.

23 · 다음 개념 연결

Content-Based는 Hybrid의 한 축이 된다

Content-Based는 사용자가 이미 좋아했던 것과 비슷한 콘텐츠를 찾는 데 강하지만, 새로운 취향이나 다른 사용자들이 발견한 아이템을 놓칠 수 있습니다.

Content-Based 콘텐츠 Feature
+
Collaborative Filtering User-Item Interaction
+
Other Signal Popularity · Freshness
→
Hybrid Recommendation

이후 Deep Hybrid에서는 콘텐츠의 텍스트·이미지·장르 Feature와 사용자·아이템 Embedding을 함께 사용할 수 있습니다.

이번 단원의 개념은 이후에도 사라지지 않습니다.

Item Feature와 Vector Representation은 모델 기반 추천이나 Deep Hybrid 안에서도 계속 중요한 입력 정보로 사용될 수 있습니다.

24 · 면접 포인트

질문과 답변으로 다시 설명하기

Q1. Content-Based Recommendation이란 무엇인가요?

사용자가 좋아했던 아이템의 장르·텍스트·태그 같은 Feature를 분석하고, 그 Feature와 비슷한 다른 아이템을 추천하는 방식입니다.

Q2. Content-Based에서 가장 중요한 데이터는 무엇인가요?

Item Feature입니다. 영화라면 장르·줄거리·배우·키워드 등을 사용할 수 있습니다.

Q3. Item ID와 Item Feature의 차이는 무엇인가요?

Item ID는 대상을 식별하고, Item Feature는 대상의 내용을 설명합니다. Content-Based의 Similarity는 Feature를 기준으로 계산합니다.

Q4. User-Item Matrix와 Item-Feature Matrix의 차이는 무엇인가요?

User-Item Matrix는 사용자와 아이템의 행동·평점 관계이고, Item-Feature Matrix는 각 아이템의 특성을 표현합니다. 콘텐츠 기반 추천에서는 후자가 핵심입니다.

Q5. 왜 Feature를 Vector로 바꾸나요?

장르나 문장 자체로는 수학적인 유사도 계산이 어려우므로 Multi-Hot, TF-IDF, Embedding 등의 숫자 Vector로 표현합니다.

Q6. User Profile이란 무엇인가요?

사용자가 선호한 여러 Item Feature를 합치거나 평균하여 사용자의 콘텐츠 취향을 Vector 형태로 표현한 것입니다.

Q7. Item-to-Item과 User-to-Item의 차이는 무엇인가요?

Item-to-Item은 기준 Item과 후보 Item을 비교하고, User-to-Item은 선호 이력으로 만든 User Profile과 후보 Item을 비교합니다.

Q8. Cosine Similarity 0.9는 90% 선호 확률인가요?

아닙니다. 선택한 Vector 공간에서 두 Vector 방향이 얼마나 유사한지를 나타낸 값입니다.

Q9. TF-IDF는 무엇을 표현하나요?

한 문서에서 자주 등장하면서 전체 문서에서는 상대적으로 드문 단어에 높은 가중치를 주어 문서를 Vector로 표현합니다.

Q10. Word2Vec은 무엇인가요?

단어의 주변 문맥 관계를 학습하여 각 단어를 고정 길이 Vector로 표현하는 방법입니다.

Q11. Word2Vec의 단어 Vector를 바로 영화 Vector라고 할 수 있나요?

아닙니다. 영화 줄거리는 여러 단어로 이루어져 있으므로 단어 Vector를 평균하는 등의 문서 Vector 구성 과정이 필요합니다.

Q12. TF-IDF와 Word2Vec의 차이는 무엇인가요?

TF-IDF는 단어 등장 빈도와 전체 문서에서의 희귀성을 중심으로 하고, Word2Vec은 단어의 문맥 관계를 학습합니다.

Q13. Content-Based와 Item-Based CF의 차이는 무엇인가요?

Content-Based는 아이템 자체의 Feature를 비교하고, Item-Based CF는 여러 사용자가 아이템에 보인 행동·평점 패턴을 비교합니다.

Q14. Content-Based는 신규 Item에 왜 유리할 수 있나요?

아직 사용자 행동이 없더라도 장르·설명·태그 같은 Feature가 있으면 기존 Item과 비교할 수 있기 때문입니다. 다만 Feature가 있어야 한다는 조건이 필요합니다.

Q15. 신규 User Cold Start도 해결하나요?

자동으로 해결하지 않습니다. 선호 Item이나 관심 Feature가 전혀 없으면 User Profile을 만들 수 없습니다.

Q16. Content-Based의 대표적인 한계는 무엇인가요?

Feature 품질에 크게 의존하고, 기존 선호와 비슷한 콘텐츠만 반복 추천하여 다양성이나 새로운 발견이 떨어질 수 있습니다.

Q17. 높은 Similarity가 항상 최종 추천 1위인가요?

아닙니다. 필터링과 최신성·다양성·운영 규칙 등을 반영한 Re-ranking으로 최종 순위가 달라질 수 있습니다.

Q18. Content-Based가 Hybrid에서 어떤 역할을 하나요?

Item Feature에서 계산한 콘텐츠 기반 추천 점수를 제공하는 하나의 신호가 되며, 이후 Collaborative Filtering 등의 점수와 결합할 수 있습니다.

  8. TF-IDF는 단어의 등장과 중요도를 봅니다.
  9. Word2Vec은 단어의 문맥 관계를 Vector로 학습합니다.
  10. Word2Vec의 단어 Vector를 문서 Vector로 만드는 과정이 필요합니다.
  11. 신규 Item은 Feature가 있어야 콘텐츠 기반 추천에 활용할 수 있습니다.
  12. 신규 User의 선호 정보가 없으면 User Profile을 만들기 어렵습니다.
  13. Similarity Rank와 Final Rank는 다를 수 있습니다.
