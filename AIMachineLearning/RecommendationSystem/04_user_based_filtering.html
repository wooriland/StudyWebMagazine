01 · 핵심 개념 설명

User-Based Filtering이란?

교안 핵심 · 사용자 간 Similarity를 기반으로 Recommendation 수행

User-Based Filtering은 Target User와 여러 Item에 대해 비슷한 Rating Pattern을 보인 다른 User를 먼저 찾는 방식 입니다.

1 나 Target User
→
2 Similar User 비슷한 Rating Pattern
→
3 Liked Item Neighbor가 선호
→
4 Recommendation 내가 아직 안 본 Item

User A는 Movie 1과 Movie 2를 높게 평가했습니다.

↓

User B도 Movie 1과 Movie 2를 높게 평가했습니다.

↓

A와 B는 비슷한 취향일 가능성이 있습니다.

↓

B가 좋아하지만 A가 아직 평가하지 않은 Movie 3을 A의 Candidate로 만들 수 있습니다.

한 문장으로 기억하기

User-Based는 Item보다 사람을 먼저 찾습니다.

04 · 핵심 개념

User Vector — Matrix의 한 행

User A [5, 4, 0, 1]
User B [5, 4, 5, 0]
User C [1, 2, 5, 4]
User D [5, 4, 4, 0]

각 Vector의 위치는 반드시 같은 Movie를 뜻해야 합니다.

올바른 비교

[Movie A, Movie B, Movie C]

모든 User에서 같은 Column 순서를 사용합니다.

잘못된 비교

A = [Movie A, B, C]
B = [Movie C, A, B]

Shape가 같아도 의미는 완전히 달라집니다.

같은 Vector Index는 항상 같은 Item이어야 합니다.

07 · Similarity 수식

Cosine Similarity

cos(x, y) = (x · y) / (||x|| × ||y||)

두 User Rating Vector의 방향이 얼마나 비슷한가를 봅니다.

작은 예제

A = [1, 1, 0]

B = [1, 1, 1]

A · B = 1×1 + 1×1 + 0×1 = 2

||A|| = √2

||B|| = √3

cos(A, B) = 2 / (√2 × √3) ≈ 0.8165

0.8165는 81.65% 선호 확률이 아닙니다.

현재 Vector 공간에서 두 Rating Pattern의 방향이 유사한 정도입니다.

d(x, y) = √Σ(xi − yi)²

    ],

        "Movie_C",

25 · 코드 예제

Neighborhood를 이용해 Candidate Score 만들기 

target_ratings = ratings.loc[
    target_user
]

scores = {}


for movie in ratings.columns:

    # 이미 평가한 Movie는 제외
    if target_ratings[movie] != 0:
        continue

    weighted_sum = 0.0
    weight_sum = 0.0


    for neighbor, similarity in neighbors.items():

        neighbor_rating = ratings.loc[
            neighbor,
            movie
        ]

        # Neighbor도 평가하지 않은 Movie
        if neighbor_rating == 0:
            continue


        weighted_sum += (
            similarity
            * neighbor_rating
        )

        weight_sum += similarity


    if weight_sum > 0:

        predicted_rating = (
            weighted_sum
            / weight_sum
        )

        scores[movie] = predicted_rating


recommendations = sorted(
    scores.items(),
    key=lambda item: item[1],
    reverse=True
)


print("[Recommendation]")

for rank, (movie, score) in enumerate(
    recommendations,
    start=1
):
    print(
        f"{rank}. "
        f"{movie} "
        f"- predicted={score:.4f}"
    )
target_ratings[movie] != 0 이미 평가한 Movie 제외
neighbor_rating == 0 Neighbor의 미평가 Item 제외
similarity * neighbor_rating Similarity 기반 Weight
weight_sum > 0 0으로 나누는 상황 방지
reverse=True 높은 예상 Score부터 Ranking

26 · 코드 예제

Euclidean Distance로 Similar User 찾기 

import pandas as pd
from sklearn.metrics import pairwise_distances


user_distance = pd.DataFrame(
    pairwise_distances(
        ratings,
        metric="euclidean"
    ),
    index=ratings.index,
    columns=ratings.index,
)


target_user = "User_A"


distances = (
    user_distance
    .loc[target_user]
    .drop(target_user)
    .sort_values(
        ascending=True
    )
)


print(distances)
Cosine Similarity는 보통 큰 값부터, Euclidean Distance는 작은 값부터 봅니다.

33 · 면접 포인트

질문과 답변으로 최종 복습

Q1. User-Based Filtering이란 무엇인가요?

Target User와 Rating 또는 행동 Pattern이 비슷한 User를 찾고, 그 User들이 선호한 Item 중 Target User가 아직 경험하지 않은 Item을 추천하는 Collaborative Filtering 방식입니다.

Q2. User-Based의 핵심 자료 구조는 무엇인가요?

User-Item Matrix입니다. 행은 User, 열은 Item이고 셀에는 Rating 또는 Interaction이 들어갑니다.

Q3. User Vector는 무엇인가요?

User-Item Matrix에서 한 User의 행 전체입니다. 각 위치는 동일한 Item에 대한 Rating을 의미합니다.

Q4. Missing Rating과 낮은 Rating은 무엇이 다른가요?

Missing은 평가를 관찰하지 못했다는 뜻이고, 낮은 Rating은 실제로 낮게 평가했다는 관찰 정보입니다.

Q5. User Similarity Matrix의 크기는 어떻게 되나요?

User가 m명이면 m×m입니다.

Q6. 왜 Self를 제외해야 하나요?

자기 자신과의 Similarity가 일반적으로 가장 높기 때문에 실제 다른 Similar User를 찾으려면 자기 자신을 제외해야 합니다.

Q7. Cosine Similarity는 무엇인가요?

두 User Rating Vector의 방향이 얼마나 유사한지를 나타내는 값입니다.

Q8. Cosine 0.9는 90% 선호 확률인가요?

아닙니다. 현재 Vector 공간에서 Rating Pattern의 방향이 유사한 정도입니다.

Q9. Euclidean Distance는 어떻게 해석하나요?

두 Rating Vector 사이의 거리이며, 값이 작을수록 가까운 User로 볼 수 있습니다.

Q10. Neighborhood란 무엇인가요?

Target User와 Similarity가 높은 User 집합입니다.

Q11. neighbor_k와 top_k의 차이는 무엇인가요?

neighbor_k는 참고할 Similar User 수이고, top_k는 최종 추천 Item 수입니다.

Q12. Candidate Item은 어떻게 만드나요?

Neighbor가 좋아한 Item 중 Target User가 아직 이용하지 않은 Item을 Candidate로 만들 수 있습니다.

Q13. Similarity Weighted Rating이란 무엇인가요?

Target User와 더 Similar한 Neighbor의 Rating을 더 큰 Weight로 반영하여 Candidate 예상 점수를 만드는 방법입니다.

Q14. Predicted Rating과 실제 Rating은 무엇이 다른가요?

Predicted Rating은 현재 Neighbor와 계산식으로 추정한 값이며, 실제 User가 남긴 Rating이 아닙니다.

Q15. Rating Bias란 무엇인가요?

User마다 같은 만족도라도 Rating을 높거나 낮게 주는 성향이 다른 문제입니다.

Q16. Mean Centering은 왜 사용할 수 있나요?

User별 평균 Rating을 제거하여 절대 Rating보다 평균 대비 선호 Pattern을 비교하는 데 활용할 수 있습니다.

Q17. 공통 평가 Item 수는 왜 중요할 수 있나요?

동일한 Similarity라도 공통 평가 Item이 한 개뿐인 경우보다 많은 Item에서 지속적으로 비슷한 Pattern을 보인 경우가 더 풍부한 비교 근거를 제공합니다.

Q18. User Cold Start란 무엇인가요?

신규 User에게 Interaction이 없어 User Vector와 Similar User를 만들기 어려운 문제입니다.

Q19. Sparsity란 무엇인가요?

전체 User-Item 관계에 비해 실제 관찰된 Rating이 적어 Matrix 대부분이 비어 있는 상태입니다.

Q20. User-Based의 Scalability 문제는 무엇인가요?

User 수가 증가하면 User×User Similarity 계산량과 저장 공간이 크게 증가할 수 있습니다.

Q21. Preference Drift란 무엇인가요?

사용자의 과거 취향과 최근 취향이 달라져 오래된 Rating Pattern이 현재 선호를 잘 설명하지 못하는 문제입니다.

Q22. User-Based와 Item-Based의 차이는 무엇인가요?

User-Based는 User를 비교하고, Item-Based는 여러 User가 Item에 보인 Rating Pattern을 기준으로 Item을 비교합니다.

Q23. User-Based와 Content-Based의 차이는 무엇인가요?

User-Based는 User Interaction Pattern을 사용하고, Content-Based는 Item의 장르·텍스트·태그 같은 Feature를 사용합니다.

Q24. User-Based가 Hybrid와 어떻게 연결되나요?

User-Based의 Collaborative Score를 Content-Based나 Item-Based Score와 결합하여 각 알고리즘의 약점을 보완할 수 있습니다.

Q25. User Embedding과는 어떻게 연결되나요?

User-Based에서는 Item 수만큼 긴 Rating Vector를 직접 비교하지만, Model-Based에서는 Interaction 데이터로 더 작은 잠재 User Vector인 Embedding을 학습할 수 있습니다.
