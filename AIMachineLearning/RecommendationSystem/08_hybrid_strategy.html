05 · Weighted Hybrid

여러 Component Score에 신뢰 비율을 적용한다

교안 직접 핵심 · Content 30% + User 30% + Item 40%

Content Score × 0.30
+
User-Based Score × 0.30
+
Item-Based Score × 0.40
→
Final Score
FinalScore(u,i) = αC(u,i) + βU(u,i) + γI(u,i)
α + β + γ = 1

Weight는 단순한 계산 숫자가 아니라, 어떤 추천 논리를 최종 결과에 더 강하게 반영할 것인지 나타냅니다.

같은 Candidate를 세 추천 Signal로 평가한다

09 · 코드 예제

Weight 검증과 Final Score 계산

weighted_hybrid.py 

from dataclasses import dataclass


@dataclass(frozen=True)
class HybridWeights:
    content: float = 0.3
    user_based: float = 0.3
    item_based: float = 0.4

    def validate(self) -> None:
        values = (
            self.content,
            self.user_based,
            self.item_based,
        )

        if any(value < 0 for value in values):
            raise ValueError(
                "가중치는 음수가 될 수 없습니다."
            )

        total = sum(values)

        if abs(total - 1.0) > 1e-9:
            raise ValueError(
                "Weighted Average에서는 "
                "가중치 합이 1이어야 합니다."
            )


def calculate_hybrid_score(
    content_score: float,
    user_score: float,
    item_score: float,
    weights: HybridWeights,
) -> float:
    weights.validate()

    scores = {
        "content_score": content_score,
        "user_score": user_score,
        "item_score": item_score,
    }

    for name, value in scores.items():
        if not 0.0 <= value <= 1.0:
            raise ValueError(
                f"{name}는 0과 1 사이여야 합니다."
            )

    return (
        weights.content * content_score
        + weights.user_based * user_score
        + weights.item_based * item_score
    )
HybridWeights 추천 방식별 반영 비율
validate() 음수·Weight 합 검증
calculate_hybrid_score() Component Score의 가중 합산

Candidate Ranking 

weights = HybridWeights(
    content=0.3,
    user_based=0.3,
    item_based=0.4,
)


candidates = {
    "Item_A": {
        "content": 0.90,
        "user": 0.40,
        "item": 0.80,
    },
    "Item_B": {
        "content": 0.50,
        "user": 0.90,
        "item": 0.60,
    },
    "Item_C": {
        "content": 0.70,
        "user": 0.60,
        "item": 0.70,
    },
}


results = []


for item_id, scores in candidates.items():
    final_score = calculate_hybrid_score(
        content_score=scores["content"],
        user_score=scores["user"],
        item_score=scores["item"],
        weights=weights,
    )

    results.append(
        {
            "item_id": item_id,
            "component_scores": scores,
            "final_score": final_score,
        }
    )


results.sort(
    key=lambda row: row["final_score"],
    reverse=True,
)


for rank, row in enumerate(
    results,
    start=1,
):
    print(
        rank,
        row["item_id"],
        round(
            row["final_score"],
            4,
        ),
    )

12 · Filtering과 Re-ranking

제거하는 단계와 순서를 바꾸는 단계를 구분한다

Filtering

부적합한 Item 제거
  • 이미 사용한 Item
  • 재고 없는 Item
  • 서비스 종료 Item
  • 연령 제한 Item
  • User가 차단한 Item

Re-ranking

남은 Item의 순서 변경
  • Popularity
  • Freshness
  • Diversity
  • Novelty
  • Business Priority

초기 Ranking

  1. A · 0.90
  2. B · 0.85
  3. C · 0.80
→

Final Ranking

  1. B · 최신성 높음
  2. A · 사용 가능
  3. C · 제공 불가로 제외
Algorithm Rank ≠ Final Display Rank

17 · Threshold와 Fallback

선택 기준과 실패 후 대체 흐름을 함께 설계한다

Threshold 예

History ≥ 20 User-Based
History < 20 Initial Item 확인
20은 교안의 고정값이 아니라 Switching 구조를 설명하기 위한 예시 Threshold입니다.

Fallback Flow

User-Based → 실패 → Item-Based → 실패 → Content-Based → 실패 → Popularity
선택한 알고리즘이 Candidate를 만들지 못할 가능성이 있으므로 Fallback 순서도 함께 정의해야 합니다.

18 · 코드 예제

User 상태에 따라 Recommender 선택 

def choose_recommender(
    *,
    user_history_count: int,
    has_initial_item: bool,
    has_content_profile: bool,
) -> str:
    if user_history_count < 0:
        raise ValueError(
            "user_history_count는 음수가 될 수 없습니다."
        )

    if user_history_count >= 20:
        return "user_based"

    if has_initial_item:
        return "item_based"

    if has_content_profile:
        return "content_based"

    return "popularity"
user_history_count User-Based 사용 가능성
has_initial_item Item-Based의 기준 Item 존재 여부
has_content_profile Content-Based에 사용할 취향 정보
popularity 개인화 정보가 없을 때 Fallback

Fallback 순서 

def recommendation_order(
    selected_algorithm: str,
) -> list[str]:
    fallback_map = {
        "user_based": [
            "user_based",
            "item_based",
            "content_based",
            "popularity",
        ],
        "item_based": [
            "item_based",
            "content_based",
            "popularity",
        ],
        "content_based": [
            "content_based",
            "popularity",
        ],
        "popularity": [
            "popularity",
        ],
    }

    if selected_algorithm not in fallback_map:
        raise ValueError(
            "지원하지 않는 추천 알고리즘입니다."
        )

    return fallback_map[selected_algorithm]

30 · 면접 포인트

질문과 답변으로 최종 복습

Q1. Hybrid 결합 방법 세 가지는 무엇인가요?

Weighted Hybrid, Post-processing Hybrid, Switching Hybrid입니다.

Q2. 세 방식을 한 문장씩 구분한다면?

Weighted는 점수를 합치고, Post-processing은 결과를 다시 정렬하며, Switching은 실행할 알고리즘을 선택합니다.

Q3. Weighted Hybrid란 무엇인가요?

Content-Based, User-Based, Item-Based의 Component Score에 Weight를 곱하고 합산하여 Final Score를 만드는 방식입니다.

Q4. 교안의 Weighted 예시는 무엇인가요?

Content-Based 30%, User-Based 30%, Item-Based 40%입니다.

Q5. Weight는 무엇을 의미하나요?

각 추천 방식의 결과를 Final Score에 얼마나 강하게 반영할지 나타내는 비율입니다.

Q6. Score Normalization이 필요한 이유는 무엇인가요?

Similarity, Rating, Count처럼 Score 범위와 단위가 다르면 범위가 큰 Signal이 Final Score를 지배할 수 있기 때문입니다.

Q7. Missing Signal은 0점과 같은가요?

아닙니다. Score를 계산할 수 없었거나 해당 알고리즘의 Candidate가 아니었다는 뜻일 수 있습니다.

Q8. Post-processing Hybrid란 무엇인가요?

각 추천 방식이 먼저 결과를 만든 뒤 Candidate를 통합하고 인기도·최신성 등의 추가 기준으로 다시 정렬하는 방식입니다.

Q9. Weighted와 Post-processing의 차이는 무엇인가요?

Weighted는 Component Score를 결합하고, Post-processing은 추천 결과 목록을 결합한 뒤 Re-ranking합니다.

Q10. Candidate Pool이란 무엇인가요?

여러 추천 방식이 제안한 Item을 통합하여 Filtering과 최종 Ranking을 수행할 후보 집합입니다.

Q11. 중복 Candidate는 어떻게 처리하나요?

Item ID 기준으로 하나로 합치되 Component Score와 추천 출처는 유지할 수 있습니다.

Q12. Filtering과 Re-ranking은 무엇이 다른가요?

Filtering은 보여줄 수 없는 Item을 제거하고, Re-ranking은 남은 Item의 노출 순서를 변경합니다.

Q13. Switching Hybrid란 무엇인가요?

현재 User와 Item 상태에 맞는 하나의 추천 알고리즘을 선택해 실행하는 방식입니다.

Q14. New User에게 Item-Based를 사용할 조건은 무엇인가요?

Initial Liked Item이 존재하여 기존 Item Similarity를 조회할 수 있어야 합니다.

Q15. 아무 정보도 없는 User에게는 어떻게 하나요?

Popularity, Trending, Editorial 또는 Onboarding 같은 Fallback이 필요합니다.

Q16. New Item에는 어떤 방식이 도움이 되나요?

Interaction이 부족하므로 Metadata가 있다면 Content-Based를 사용할 수 있습니다.

Q17. Switching Threshold가 중요한 이유는 무엇인가요?

Threshold에 따라 선택되는 알고리즘과 추천 결과가 크게 달라질 수 있기 때문입니다.

Q18. Fallback은 무엇인가요?

선택하거나 우선 실행한 추천 방식이 결과를 만들지 못했을 때 사용하는 대체 추천 흐름입니다.

Q19. Final Hybrid Score는 확률인가요?

반드시 그렇지는 않습니다. Candidate의 상대적인 순위를 정하는 Ranking Score일 수 있습니다.

Q20. Weighted Hybrid의 대표 한계는 무엇인가요?

Score Normalization, Weight 결정, Missing Signal 처리와 특정 Signal의 결과 지배 문제가 있습니다.

Q21. Post-processing의 대표 한계는 무엇인가요?

중복 Candidate 통합, 서로 다른 Rank 의미의 조정, Re-ranking 정책 설계가 필요합니다.

Q22. Switching의 대표 한계는 무엇인가요?

조건과 Threshold가 잘못되면 현재 상황에 맞지 않는 알고리즘을 선택할 수 있습니다.

Q23. Hybrid 결합 방법은 Model-Based와 어떻게 연결되나요?

사람이 Weight와 Rule을 직접 설정하는 구조에서 User·Item Embedding과 Content Feature의 관계를 모델이 학습하고 Ranking Score를 출력하는 구조로 확장됩니다.
