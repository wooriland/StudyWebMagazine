01 · 핵심 개념

추천시스템이란? — 누구에게 무엇을 보여줄 것인가

교안 1쪽 · 추천 알고리즘의 정의 / Step 1·2 보완 · 추천 목표와 결과 해석

추천시스템은 수많은 아이템 중에서 특정 사용자에게 적합할 것으로 예상되는 대상을 찾고, 보여줄 순서를 정하는 시스템 입니다. 이 과목의 중심은 AI 전체가 아니라 사용자와 아이템 사이의 관계를 이해하는 것입니다.

사용자가 모든 영화·상품·강의를 직접 비교하기는 어렵습니다. 추천은 선택할 후보를 줄이고, 관심 있을 만한 대상을 발견하도록 돕습니다. 단순히 좋은 아이템이 아니라 이 사용자에게 적합한 아이템을 찾습니다.

선호도 예측

“사용자 A는 영화 C에 몇 점을 줄까?”처럼 특정 사용자·아이템 조합의 값을 추정합니다. 예: 예상 평점 4.3점.

추천 목록과 Ranking

“영화 C·D·E 중 무엇을 먼저 보여줄까?”를 결정합니다. 예: D → E → C 순서의 Top-3 목록.

  1. 사용자 추천받을 대상
  2. 행동 기록 시청·평점·클릭
  3. 적합도 계산 후보별 점수
  4. 추천 목록 상위 K개 표시
추천을 시작하기 전에 정할 질문
질문 확인할 내용
누구에게? 로그인 사용자, 비회원 세션, 사용자 그룹 등 추천의 대상
무엇을? 영화·상품·음악·강의·장소처럼 추천할 아이템
왜? 콘텐츠 특성, 유사 사용자, 아이템 관계, 학습된 모델 등 추천 근거
언제·어떤 상황에서? 최근 관심사, 시간, 접속 상황 등 사용할 맥락
몇 개를·어떤 순서로? Top-K의 K와 정렬·제외·재정렬 규칙
무엇이 성공인가? 클릭, 구매, 시청 완료, 학습 완료, 만족도 등 서비스의 목표
인기 추천과 개인화 추천

인기순 목록도 추천의 한 형태이며 비교 기준이나 초기 대체 정책으로 사용할 수 있습니다. 다만 모든 사용자에게 동일한 목록을 보여주는 인기 추천과, 사용자별 관계를 반영하는 개인화 추천은 구분합니다.

추천 점수 계산 → 추천 가능 여부 확인 → 정렬 → Top-K 선택. 점수를 계산하는 것만으로 서비스의 추천이 완성되지는 않습니다.

User / Item / Interaction — 추천 데이터의 세 축

교안 1쪽 · 사용자의 취향, 아이템 특성, 상호작용 / Step 1·2 용어 정리

추천시스템의 기본 용어
용어 뜻 예와 해석
User 추천받는 대상 시청자·고객·학습자. 로그인 ID 또는 설계에 따라 세션을 사용합니다.
Item 추천할 대상 영화·상품·노래·강의·장소. item_id는 대상을 식별합니다.
Interaction 사용자가 아이템에 보인 행동 조회·클릭·평점·찜·시청·구매·숨기기·환불 등입니다.
Rating 직접 표현한 평가 별점·좋아요·싫어요. 사용자마다 평가 성향이 다를 수 있습니다.
Click 아이템을 선택해 확인한 행동 상세 페이지나 썸네일을 클릭한 사실입니다. 만족과 같지 않습니다.
Purchase 구매 행동 구매를 관찰했다는 뜻입니다. 선물·일회성 구매·취소·환불을 구분합니다.
Feature 계산에 사용하는 특성 장르·줄거리·태그·가격·등록일 등. 아이템 ID 자체와 구분합니다.
Recommendation 제시할 추천 결과 아이템 ID·순위·점수·추천 이유·알고리즘 버전·생성 시각 등을 포함할 수 있습니다.

사용자 정보

사용자 ID, 관심사, 최근 행동, 누적 행동처럼 추천에 필요한 정보를 사용합니다. 나이·성별 등 개인정보가 반드시 있어야 추천할 수 있는 것은 아닙니다.

아이템 정보

제목·장르·태그·설명·가격·등록일·이미지 등을 특성으로 표현할 수 있습니다. 콘텐츠 기반 추천의 중요한 입력입니다.

관계 정보

“누가 어떤 아이템에 언제 어떤 행동을 했는가?”를 기록합니다. 같은 아이템도 사용자에 따라 관계가 다릅니다.

User + Item + Interaction → 추천 근거 → Score → Ranking

명시적 피드백과 암묵적 피드백

Step 1·2 보완 · 행동의 의미를 해석하는 기준

두 종류의 피드백
구분 명시적 피드백 · Explicit 암묵적 피드백 · Implicit
의미 사용자가 직접 선호를 표현합니다. 행동에서 관심이나 선호를 간접 추정합니다.
예 별점, 좋아요, 싫어요, 만족도 클릭, 시청, 구매, 반복 재생
장점 평가의 의미가 비교적 명확합니다. 직접 평가를 입력하지 않아도 행동을 관찰할 수 있습니다.
주의점 모든 사용자가 평가하지 않으며 평가 기준도 다릅니다. 클릭·구매의 이유와 실제 만족을 구분해야 합니다.

영화를 클릭했지만 곧바로 나갈 수 있고, 자동 재생으로 시청 시간이 쌓일 수도 있습니다. 구매도 선물용일 수 있으며 나중에 환불될 수 있습니다. 하나의 행동을 만족의 확정 증거로 사용하지 않습니다.

  1. 조회·클릭 관심의 시작일 수 있음
  2. 찜·장바구니 보관·비교 행동
  3. 시청·구매 실제 이용
  4. 평가·재이용 후속 반응 확인

위 흐름은 행동을 함께 읽는 예시이며, 모든 서비스에 공통인 선호 강도의 순서를 뜻하지 않습니다.

학습용 가정: 클릭 1점 + 찜 3점 + 구매 5점
행동 가중치는 공식이 아니라 설계값입니다.

클릭 열 번과 구매 한 번을 어떻게 비교할지, 중복 클릭과 취소를 어떻게 처리할지 먼저 결정해야 합니다. 미클릭은 싫어요와 다릅니다. 노출되지 않은 아이템은 클릭할 기회 자체가 없었을 수 있습니다.

형식·단위 통일 ID 타입, 시간 형식, 이벤트 이름, 시청 시간 단위가 일치하는가?

User-Item Matrix — 행은 사용자, 열은 아이템

교안 2~4쪽 · 행렬 구성 / Step 1의 평점 예제

평점 예제 · ?는 미관찰입니다.
사용자 / 아이템 영화 A 영화 B 영화 C
사용자 A · 추천 대상 5 4 ? · 미관찰
사용자 B 5 4 3
사용자 C 1 2 5
R의 크기 = 사용자 수 m × 아이템 수 n
R[A, C] = 사용자 A의 영화 C에 대한 아직 관찰되지 않은 평점

핵심 질문은 “물음표에 어떤 영화 이름을 넣을까?”가 아니라 “사용자 A가 영화 C에 어떻게 반응할까?”입니다. 여러 미관찰 후보의 점수를 계산하면 무엇을 먼저 추천할지 결정할 수 있습니다.

낮은 평점

평점 1점은 실제로 낮게 평가한 기록입니다. 부정적인 선호를 표현했을 수 있습니다.

관찰하지 못한 관계

아직 보지 않았거나, 몰랐거나, 노출되지 않았거나, 봤지만 평점을 남기지 않았을 수 있습니다. 이 상태가 바로 ?입니다.

필요하면 평점표 R과 관측 여부표 O를 분리합니다. O는 관찰한 칸을 1, 관찰하지 못한 칸을 0으로 표시합니다. 이렇게 하면 평가값과 평가가 존재하는지를 구분할 수 있습니다.

빈 평점을 무조건 0점으로 바꾸지 않습니다.

뒤의 이진 상호작용 실습에서 0은 미관찰을 나타내는 입력 표현입니다. 낮은 별점이나 싫어요를 뜻하는 값이 아닙니다.

교안의 추천 지도 — Memory-Based에서 Model-Based까지

교안 1~7쪽 · 분류와 학습 순서 / Step 2 보완 · 분류 기준 구분

  • Recommendation
    • Memory-Based Approach
      • Content-Based Approach · 아이템 특성을 활용
      • Collaborative Filtering
        • User-Based · 사용자를 비교

교안은 Memory-Based를 과거의 사용자 취향, 아이템 특성, 상호작용 정보를 기반으로 추천하는 방식으로 설명합니다. 이 페이지도 교안의 분류와 순서를 학습 지도에 사용합니다.

Memory-Based의 장점과 한계
구분 교안의 설명
장점 Model-Based에 비해 비교적 간단한 구조로 구현할 수 있습니다.
초기 데이터 문제 새로운 사용자나 아이템에 대한 추천 성능이 낮아질 수 있습니다.
데이터 편향 과거 데이터가 편향되어 있으면 추천 결과에도 문제가 생길 수 있습니다.
Step 2에서 보완한 분류 읽기

Content-Based / Collaborative는 어떤 정보를 근거로 쓰는가, Memory-Based / Model-Based는 어떻게 관계를 계산하거나 학습하는가, Hybrid는 여러 방법을 어떻게 결합하는가에 초점이 있습니다.

하이브리드가 교안의 Memory-Based 설명 뒤에 배치되어 있다고 해서 모델 기반 방법과 결합할 수 없다는 뜻은 아닙니다. 교안에도 임베딩과 DNN을 결합한 하이브리드 예제가 나옵니다.

용어 범위 참고: Step 1·2에서는 다른 자료의 Memory-Based 범위와 교안의 분류가 다를 수 있음을 구분했습니다. 이 페이지에서는 교안의 목차를 다른 분류로 바꾸지 않습니다.

Content-Based — 내가 좋아한 아이템의 특성을 읽는다

교안 1쪽 · 컨텐츠 기반 추천 / Step 1·2 예제와 보완 설명

사용자가 선호한 아이템의 장르·태그·줄거리 같은 특성을 이용해 사용자 취향을 표현하고, 후보 아이템의 특성과 비교합니다.

  1. 좋아한 Item 영화 A·B
  2. Item Feature 액션·SF
  3. 취향과 후보 비교 특성의 유사성
  4. 추천 유사한 콘텐츠
영화 특성으로 이해하기 · 설명용 예제
아이템 특성 사용자 A의 관계
영화 A 액션·SF·우주 높은 평점
영화 B 액션·SF·미래 높은 평점
영화 C 로맨스·음악·가족 아직 평가하지 않음

이 예에서는 사용자 A의 취향 프로필을 액션·SF 중심으로 표현할 수 있습니다. 영화 C는 해당 특성과 다르므로 콘텐츠 유사도가 낮을 수 있습니다. 실제 점수는 특성 표현과 비교 방법에 따라 달라집니다.

장점

대상 사용자의 취향 근거와 아이템 특성이 있으면 다른 사용자의 행동 없이도 비교할 수 있습니다. “최근 본 SF 영화와 장르가 비슷합니다”처럼 추천 근거를 연결하기 쉽습니다.

한계

특성이 부족하면 비교 근거도 부족해집니다. 사용자가 이미 좋아한 것과 비슷한 콘텐츠만 계속 추천하면 새로운 주제를 발견하기 어려울 수 있습니다.

Content-Based의 “비슷함”은 콘텐츠의 특성에서 나옵니다.

Collaborative Filtering — 여러 사용자의 행동 관계를 읽는다

교안 1~2쪽 · 협업 필터링의 정의, 장점, 신규 데이터의 한계

협업 필터링은 사용자 간 유사도 또는 아이템 간 유사도를 이용합니다. 기본 입력은 여러 사용자가 여러 아이템에 보인 행동이나 평가입니다.

User-Based

나와 비슷한 행동을 한 사용자를 찾고, 그 사용자가 좋아한 다른 아이템을 추천합니다.

Item-Based

내가 이용한 아이템과 사용자 반응 패턴이 비슷한 다른 아이템을 추천합니다.

교안은 콘텐츠 기반보다 사용자의 취향을 더 잘 반영할 수 있다는 장점과, 신규 사용자·신규 아이템의 데이터가 없을 때 추천이 어렵다는 단점을 설명합니다.

항상 더 정확하다는 보장은 아닙니다.

Step 2의 해석처럼 실제 성능은 데이터와 평가 조건을 확인해야 합니다. 행동이 적거나 공통으로 관찰된 관계가 적으면 비교 근거가 약할 수 있습니다.

콘텐츠의 장르나 줄거리 정보가 없어도 상호작용 데이터로 관계를 계산할 수 있습니다. 다만 관찰된 행동의 유사성이 사용자의 취향 전체를 설명하는 것은 아닙니다.

User-Based — 나와 비슷한 사람은 무엇을 좋아했는가

교안 2~3쪽 · User-Based 단계와 장단점 / Step 2 보완 · 평점 계산 예제

  1. 나의 기록 사용자 행
  2. 유사 사용자 User × User
  3. 이웃의 아이템 내 미사용 후보
  4. 추천 점수와 순위

작업 순서는 사용자-아이템 행렬 생성 → 사용자 간 유사도 계산 → 유사 사용자 선택 → 이웃이 평가한 후보의 점수 계산 → 이미 이용한 아이템 제외 → Top-K 입니다.

평점 예제를 읽는 가장 단순한 방법

사용자 A와 B는 공통 평가 영화 A·B에 각각 [5, 4]를 주었습니다. 이 두 차원만 비교하면 동일한 벡터입니다. B 한 명을 이웃으로 사용한다는 가정에서는 B의 영화 C 평점인 3점을 A의 예상 평점으로 사용할 수 있습니다.

예상 평점 r̂(u, i) = Σ[s(u, v) × r(v, i)] / Σs(u, v)

이 식은 양수 유사도를 가진 이웃 중 후보 아이템 i의 평점을 실제로 가진 사람 에 대해서만 합산하는 단순 가중평균 예제입니다. 분모가 0이면 계산할 근거가 없으므로 대체 정책이 필요합니다.

교안의 장점

유사한 사람의 선택을 참고하므로 간단하고 직관적으로 이해할 수 있습니다.

교안의 한계

사용자 행동이 적으면 유사 사용자를 찾기 어렵습니다. 사용자 수가 늘면 계산량이 커질 수 있고, 자주 바뀌는 취향을 반영하기 어려울 수 있습니다.

이웃 수와 추천 개수는 다릅니다.

neighbor_k는 참고할 이웃 수, top_k는 최종 아이템 개수입니다. 자기 자신을 이웃으로 사용하지 않습니다.

Item-Based — 비슷한 반응을 받은 아이템을 찾는다

교안 3~4쪽 · Item-Based 단계와 장단점 / Step 2 보완 · 유사성의 근거

  1. 이용한 Item 나의 출발 아이템
  2. 사용자 반응 비교 아이템별 행동 벡터
  3. 유사 Item Item × Item
  4. 추천 미사용 후보

사용자-아이템 행렬을 전치하여 아이템을 행으로 놓고 비교합니다. 예를 들어 영화 A를 평가한 사람들의 패턴과 영화 C를 평가한 사람들의 패턴이 얼마나 비슷한지 계산합니다.

R: User × Item
Rᵀ: Item × User
아이템 유사도 행렬: Item × Item

작업 순서는 행렬 생성 → 전치 → 아이템 유사도 계산 → 사용자가 이용한 아이템 확인 → 유사 후보의 점수 계산 → 필터링 → Top-K 입니다.

교안의 장점

새 사용자라도 초기 관심 아이템이 있으면 추천에 활용할 수 있습니다. 충분한 데이터가 있을 때 아이템 관계가 상대적으로 안정적일 수 있습니다.

교안의 한계와 조건

신규 아이템은 상호작용이 없어 관계를 계산하기 어렵습니다. 관심 아이템을 하나 선택했더라도, 그 아이템과 다른 아이템의 협업 관계를 구할 데이터가 필요합니다.

장르가 비슷하다는 설명만으로는 Item-Based CF가 아닙니다.

장르·줄거리 유사성은 Content-Based의 근거입니다. 여기서는 여러 사용자가 두 아이템에 보인 반응 패턴을 비교합니다.

Cosine Similarity — 벡터의 방향을 비교한다

교안 3~4쪽 · 코사인 유사도 언급 / Step 2 보완 · 수식·계산·주의점

코사인 유사도는 두 벡터가 이루는 각도를 이용합니다. 사용자를 벡터로 표현하면 사용자 간 유사도를, 아이템을 벡터로 표현하면 아이템 간 유사도를 계산할 수 있습니다.

cos(x, y) = (x · y) / (‖x‖ × ‖y‖)
= Σ(xkyk) / [√Σxk² × √Σyk²]

손으로 계산하기

x = [1, 1, 0], y = [1, 1, 1]
내적 = 1×1 + 1×1 + 0×1 = 2
벡터 길이 = √2, √3
cos(x, y) = 2 / (√2 × √3) ≈ 0.8165
코사인 유사도 해석
상태 의미
1 같은 방향입니다. 크기까지 같다는 뜻은 아닙니다.
0 비영벡터끼리는 직교하는 방향입니다. 서비스에서 취향이 절대 무관하다는 단정은 아닙니다.
-1 정반대 방향입니다. 일반적인 실수 벡터의 범위는 -1부터 1입니다.
모든 원소가 음수 아님 코사인 유사도도 0 이상입니다. 원래의 양수 평점으로 음수 유사도를 기대하지 않습니다.
영벡터 [0, 0, 0] 벡터 길이가 0이므로 수학적 공식에서 분모가 0입니다. 별도 처리가 필요합니다.
유사도 0.8165는 선호 확률 81.65%가 아닙니다.

선택한 특성 공간에서 방향이 비슷하다는 값입니다. 뒤의 scikit-learn 예제는 영벡터 비교를 0으로 반환하지만, 행동 정보 부족과 실제 취향 차이를 혼동하지 않습니다.

원래 평점의 코사인이 직관과 다를 수 있다

[5, 4]와 [5, 4] → 1
[5, 4]와 [1, 2] → 약 0.9080

두 번째 쌍은 어떤 영화를 더 높게 평가했는지가 다르지만 원시 평점 벡터의 코사인은 높습니다. Step 2에서는 이러한 차이를 이해하기 위해 사용자별 평가 성향과 평균 보정을 함께 고려할 수 있다고 보완했습니다.

유사도와 거리는 정렬 방향이 다릅니다.

유사도는 일반적으로 클수록 비슷하고, 유클리디안 거리와 같은 거리는 작을수록 가깝습니다. 함수가 반환하는 값의 의미부터 확인합니다.

개념 의미 예
Cold Start 초기 추천 근거가 부족합니다. 가입 직후 사용자, 방금 등록한 상품

희소성 계산

희소성 = 1 − 관찰된 사용자-아이템 쌍 수 / (사용자 수 × 아이템 수)
사용자 100명 × 아이템 1,000개 = 100,000개 조합
관찰된 서로 다른 쌍 500개 → 1 − 500 / 100,000 = 99.5%

여기서 500개는 중복을 포함한 로그 행 수가 아니라 서로 다른 사용자-아이템 쌍의 수 입니다. 같은 상품을 열 번 클릭해도 관찰된 관계 셀은 하나일 수 있습니다. 희소성이 높으면 공통 행동이나 공통 평점이 부족해 유사도를 판단하기 어려워질 수 있습니다.

① Weighted Hybrid · 가중치 기반

교안의 예처럼 여러 결과에 비율을 부여합니다. 아래 수치는 각 점수를 비교 가능한 척도로 조정했다고 가정한 학습용 예입니다.

최종 점수 = 0.3 × 콘텐츠 점수 + 0.3 × 사용자 기반 점수 + 0.4 × 아이템 기반 점수
가중치 결합 예제
후보 콘텐츠 사용자 기반 아이템 기반 최종 점수
영화 C 0.8 0.7 0.6 0.69
영화 D 0.6 0.9 0.8 0.77

영화 D는 0.6×0.3 + 0.9×0.3 + 0.8×0.4 = 0.77입니다. 콘텐츠 점수만으로는 C가 높지만 결합 결과는 D가 높습니다.

예상 평점 1~5, 코사인 유사도, 행동 횟수 합처럼 의미와 범위가 다른 값을 그대로 더하지 않습니다. 점수의 척도·분포를 조정할 규칙과 결합 가중치가 필요합니다.

③ Switching Hybrid · 교차 기반

교안은 신규 사용자에게 Item-Based, 충분한 데이터가 있으면 User-Based, Item-Based도 어려우면 Content-Based로 전환하는 예를 제시합니다.

Step 2의 조건 보완: 이 예는 각 방식이 사용할 근거가 확보되어 있어야 합니다. 관심 아이템도 없으면 Item-Based를 시작하기 어렵고, 사용자 취향이나 콘텐츠 정보가 없으면 Content-Based도 근거가 부족합니다.

현재 사용할 수 있는 정보 확인 → 적용 가능한 방식 선택 → 근거 부족 시 대체 정책

Model-Based는 과거 데이터를 학습한 모델로 추천 점수를 계산합니다. Memory-Based도 과거 데이터를 사용하므로, 둘의 차이는 과거 데이터 사용 여부가 아니라 관계를 계산하고 표현하는 방식에 있습니다.

모델 기반 방식의 장점과 한계
구분 교안 내용과 Step 2의 해석
장점 복잡한 관계를 학습하여 신규 사용자·아이템 추천이나 편향 보정에 도움이 될 수 있습니다.
조건 어떤 입력 특성과 학습 구조를 사용하는지에 따라 달라집니다. 모델을 사용한다고 문제가 자동으로 해결되지는 않습니다.
구현·자원 구조가 복잡하며 학습 시간과 데이터·계산 자원이 필요할 수 있습니다.
과적합 과거 데이터에 지나치게 맞춰지면 새로운 데이터의 추천 성능이 낮아질 수 있습니다.

Embedding은 무엇인가?

사용자와 아이템을 계산 가능한 숫자 벡터로 표현합니다. 추천 모델에서는 이 벡터가 관계를 반영하도록 학습할 수 있습니다. 다음 숫자는 설명용 가상 값입니다.

사용자 U1 → [0.8, 0.3, −0.2, …]
아이템 M3 → [0.7, 0.4, 0.1, …]

U1 → 0, U2 → 1처럼 ID를 정수 인덱스로 바꾸는 작업과, 학습된 임베딩 벡터를 만드는 작업은 다릅니다. 학습된 벡터의 첫 좌표가 반드시 “액션 선호도”라는 뜻도 아닙니다.

행렬 분해로 연결하기 · Step 2 보충 예제

P: 사용자 수 m × 임베딩 차원 d
Q: 아이템 수 n × 임베딩 차원 d
예측 점수 행렬 R̂ = P × Qᵀ → m × n
개별 점수 예: 사용자 벡터 pu · 아이템 벡터 qi
신규 ID의 문제

ID만으로 학습하는 모델은 처음 보는 ID의 표현이 준비되어 있지 않을 수 있습니다. 사용자·아이템 특성, 세션 행동, 초기 관심사, 대체 추천 정책이 여전히 필요할 수 있습니다.

  1. 전체 아이템 대상 범위
  2. 추천 후보 관련 대상 선별

최신성·다양성·중복 카테고리 제한·사용자 피로도·운영 정책을 반영한 Re-ranking이 적용되면 원래 점수 1위가 최종 1위가 아닐 수 있습니다. 필수 제외 조건은 후보 단계와 최종 응답 단계에서 함께 검사하도록 설계할 수 있습니다.

app.py · 전체 코드

"""추천 01 / Step 2: 같은 데이터로 세 추천 방식 비교.

실행: python app.py
의존성: numpy, pandas, scikit-learn
1은 관찰된 상호작용, 0은 상호작용 미관찰을 뜻한다.
점수는 교육용 순위 점수이며 확률이나 예상 별점이 아니다.
"""

import numpy as np
import pandas as pd
from sklearn.metrics.pairwise import cosine_similarity


def recommend(
    user_id: str,
    interactions: pd.DataFrame,
    features: pd.DataFrame,
    top_k: int = 3,
) -> dict[str, pd.Series]:
    """양수 근거가 있는 미사용 아이템을 방식별로 최대 top_k개 반환한다."""
    if not isinstance(top_k, int) or isinstance(top_k, bool) or top_k < 1:
        raise ValueError("top_k는 1 이상의 정수여야 합니다.")
    if not interactions.index.is_unique or not interactions.columns.is_unique:
        raise ValueError("사용자 ID와 아이템 ID는 중복될 수 없습니다.")
    if not features.index.is_unique or not features.columns.is_unique:
        raise ValueError("특성표의 아이템 ID와 특성명은 중복될 수 없습니다.")
    if user_id not in interactions.index:
        raise KeyError(f"등록되지 않은 사용자: {user_id}")
    if interactions.empty or features.shape[1] == 0:
        raise ValueError("아이템과 특성이 필요합니다.")
    if not interactions.isin([0, 1]).all().all():
        raise ValueError("이 예제의 상호작용 값은 결측 없이 0 또는 1이어야 합니다.")
    if not interactions.columns.isin(features.index).all():
        raise ValueError("특성표에 누락된 아이템이 있습니다.")

    R = interactions.astype(float)
    # 아이템 순서를 맞춘다. 행 개수만 같아도 순서가 다르면 잘못 비교한다.
    X = features.loc[R.columns].astype(float)
    if not np.isfinite(X.to_numpy()).all():
        raise ValueError("특성값에 NaN 또는 무한대가 있습니다.")

    history = R.loc[user_id]
    seen = history.index[history > 0]
    methods = ("Content-Based", "User-Based", "Item-Based")
    if len(seen) == 0:
        # Cold Start: 이 예제는 근거 없이 개인화 결과를 만들지 않는다.
        return {name: pd.Series(dtype=float) for name in methods}

    def select_top(scores: pd.Series) -> pd.Series:
        candidates = scores.drop(index=seen)
        # 0점 후보를 억지로 채워 넣지 않는다. 동점은 원래 아이템 순서 유지.
        return candidates[candidates > 0].sort_values(
            ascending=False, kind="stable"
        ).head(top_k)

    # 1. Content-Based: 선호 아이템의 특성 평균과 후보 특성을 비교한다.
    profile = X.loc[seen].mean(axis=0).to_numpy().reshape(1, -1)
    content_scores = pd.Series(
        cosine_similarity(profile, X)[0], index=R.columns
    )

    # 2. User-Based: 사용자 행을 비교하고, 유사 사용자의 행동을 합산한다.
    user_similarity = pd.DataFrame(
        cosine_similarity(R), index=R.index, columns=R.index
    )
    neighbors = user_similarity.loc[user_id].copy()
    neighbors.loc[user_id] = 0.0  # 자기 자신을 이웃으로 사용하지 않는다.
    user_scores = R.T.dot(neighbors)

    # 3. Item-Based: 전치한 아이템 행을 비교하고, 내 행동으로 가중한다.
    item_similarity = pd.DataFrame(
        cosine_similarity(R.T), index=R.columns, columns=R.columns
    )
    item_scores = item_similarity.dot(history)

    return {
        "Content-Based": select_top(content_scores),
        "User-Based": select_top(user_scores),
        "Item-Based": select_top(item_scores),
    }


def main() -> None:
    items = ["M1", "M2", "M3", "M4", "M5"]
    interactions = pd.DataFrame(
        [
            [1, 1, 0, 0, 0],  # U1: 추천 대상
            [1, 1, 1, 0, 0],  # U2
            [0, 0, 1, 1, 1],  # U3
            [1, 0, 1, 0, 0],  # U4
        ],
        index=["U1", "U2", "U3", "U4"],
        columns=items,
    )
    features = pd.DataFrame(
        [
            [1, 1, 0],  # M1
            [1, 0, 0],  # M2
            [0, 0, 1],  # M3
            [0, 1, 1],  # M4
            [1, 1, 0],  # M5
        ],
        index=items,
        columns=["action", "sf", "romance"],
    )

    m, n = interactions.shape
    print(f"User-Item: {(m, n)}")
    print(f"User-User: {(m, m)}")
    print(f"Item-Item: {(n, n)}")
    print(f"Item-Feature: {features.shape}")

    for name, scores in recommend("U1", interactions, features).items():
        print(f"\n[{name}]")
        if scores.empty:
            print("추천 근거가 부족합니다.")
        for rank, (item_id, score) in enumerate(scores.items(), start=1):
            print(f"{rank}. {item_id}: {score:.4f}")

Precision과 Recall의 분모는 다르다

추천 목록 10개 중 관련 아이템이 3개이고, 평가 데이터에 있는 전체 관련 아이템이 5개라고 가정합니다.

Precision@10 = 3 / 10 = 0.3
Recall@10 = 3 / 5 = 0.6

관련 아이템의 기준은 “평점 4점 이상”, “실제로 구매”, “수강 완료”처럼 미리 정합니다. 추천 모델의 점수 자체를 정답으로 사용하지 않습니다.

26 · 면접 포인트

면접 포인트 — 질문과 답변으로 다시 설명하기

Step 1·2 핵심 개념 복습 · 답을 외우기보다 사용한 근거를 설명합니다.

Q1. 추천시스템이 해결하는 문제는 무엇인가요?

많은 아이템 중 사용자에게 적합할 것으로 예상되는 대상을 찾아 제시하는 문제입니다. 특정 사용자·아이템의 선호 값을 예측하는 작업과, 여러 후보를 정렬하여 Top-K를 구성하는 작업을 구분합니다.

Q2. User·Item·Interaction을 설명해 보세요.

User는 추천받는 대상, Item은 추천할 대상, Interaction은 사용자가 아이템에 보인 행동입니다. 영화 서비스에서는 시청자·영화·시청이나 평점으로 대응합니다.

Q3. 명시적 피드백과 암묵적 피드백의 차이는 무엇인가요?

명시적 피드백은 별점처럼 직접 표현한 평가이고, 암묵적 피드백은 클릭·시청·구매 같은 행동입니다. 행동을 관찰했다는 사실과 만족을 구분해야 합니다.

Q4. Content-Based와 Item-Based CF는 무엇이 다른가요?

Content-Based는 장르·줄거리 등 아이템 특성을 비교합니다. Item-Based CF는 아이템에 대한 여러 사용자의 반응 패턴을 비교합니다. 비슷한 아이템이라는 결과보다 유사성의 근거가 중요합니다.

Q5. User-Based와 Item-Based의 행렬 크기는 어떻게 되나요?

사용자 m명, 아이템 n개일 때 원본 R은 m×n입니다. 전체 사용자 유사도는 m×m, 아이템 유사도는 n×n입니다. R의 행을 비교하면 사용자, R.T의 행을 비교하면 아이템입니다.

Q6. 행렬의 빈칸은 무엇인가요?

평가나 행동을 관찰하지 못한 상태입니다. 낮은 평점·싫어요와 동일하지 않습니다. 계산용으로 0을 쓰더라도 미관찰이라는 의미를 유지해야 합니다.

Q7. 코사인 유사도 0.9는 선호 확률 90%인가요?

아닙니다. 선택한 벡터 표현에서 방향이 비슷하다는 뜻입니다. 특성의 의미와 순서, 정규화, 영벡터 처리도 확인해야 합니다.

Q8. Cold Start와 Sparsity는 어떻게 다른가요?

Cold Start는 초기 추천 근거가 부족한 문제이고, Sparsity는 전체 관계에 비해 관찰된 관계가 적은 상태입니다. 기존 사용자 데이터도 희소할 수 있습니다.

Q9. Hybrid가 필요한 이유와 종류를 설명해 보세요.

방식마다 사용할 정보와 한계가 다르기 때문에 결합합니다. 점수를 가중 결합하는 Weighted, 목록을 통합·재정렬하는 Post-processing, 상황에 따라 선택하는 Switching이 교안에 나옵니다.

Q10. Embedding은 ID 인코딩과 어떻게 다른가요?

정수 인코딩은 대상을 구분할 인덱스를 만드는 것입니다. 임베딩은 계산 가능한 벡터 표현이며, 추천에서는 관계를 반영하도록 학습할 수 있습니다. 각 좌표에 고정된 장르 의미가 있는 것은 아닙니다.

Q11. Model-Based면 신규 사용자 문제가 사라지나요?

자동으로 사라지지는 않습니다. ID만 사용하는 모델은 신규 ID의 학습된 표현이 없을 수 있습니다. 콘텐츠 특성·세션 행동·초기 관심사·대체 정책 등을 함께 고려해야 합니다.

Q12. Item-Based가 항상 더 빠른가요?

아닙니다. 사용자 수, 아이템 수, 전체 유사도 행렬을 만드는지, 사전 계산을 하는지에 따라 달라집니다. 아이템이 더 많은 경우 아이템 유사도 행렬이 더 클 수 있습니다.

Q13. 후보 생성과 Ranking의 차이는 무엇인가요?

후보 생성은 비교할 대상을 좁히는 단계이고, Ranking은 그 후보의 순서를 결정하는 단계입니다. 노출 조건과 재정렬 때문에 모델 점수순과 최종 노출 순서가 다를 수 있습니다.

Q14. 추천의 성능을 어떻게 평가하나요?

평점 예측은 MAE·RMSE, 추천 목록은 Precision@K·Recall@K·NDCG@K 등을 사용합니다. 데이터 누수를 막고 관련 아이템 기준과 실제 서비스 목표를 함께 정합니다.

Q15. 추천 결과가 비어 있으면 오류인가요?

항상 그렇지는 않습니다. Cold Start, 미사용 후보 없음, 필터로 전부 제외, 유사도 근거 없음과 실제 예외를 구분해야 합니다. 원인마다 대체 정책도 달라집니다.
