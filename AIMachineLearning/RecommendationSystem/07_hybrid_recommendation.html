추천 07. Hybrid Recommendation 서로 다른 추천 Signal을 결합해 Final Recommendation을 만든다

Hybrid Recommendation은 Content-Based, User-Based, Item-Based, Popularity 등 서로 다른 추천 방식의 결과를 선택하거나 결합하고 필요하면 다시 정렬하여 최종 추천 순위를 만드는 방식 입니다.

이번 단원의 핵심 질문

“각 추천 방식이 서로 다른 장점과 한계를 가진다면, 여러 추천 결과를 어떻게 합쳐 최종 Recommendation으로 만들 것인가?”
Hybrid Recommendation Signal Content-Based User-Based Item-Based Weighted Hybrid Post-processing Switching Candidate Pool Normalization Filtering Re-ranking Fallback Embedding Deep Neural Network Ranking Layer
추천 이론 과목에서의 역할

핵심은 각 추천 방식이 어떤 Signal을 만들고, 그 Signal을 어느 단계에서 어떤 규칙으로 결합하는지 이해하는 것입니다.

01 · 핵심 개념 설명

Hybrid Recommendation이란?

교안 직접 핵심 · 여러 추천 기법의 장점을 결합하고 단점을 보완

Hybrid Recommendation은 여러 추천 알고리즘 중 하나만 선택하는 것이 아니라, 서로 다른 추천 방식이 제공하는 정보와 점수를 함께 사용하여 최종 추천을 만드는 구조 입니다.

CONTENT Content-Based Item Feature
+
USER User-Based User Relation
+
ITEM Item-Based Item Relation
→
FINAL Hybrid Final Recommendation
핵심 한 문장

Hybrid는 여러 추천 결과를 아무 기준 없이 섞는 것이 아니라, 현재 User·Item·서비스 상황에 맞게 Signal을 선택·결합·재정렬하는 방식 입니다.

02 · 왜 배우는가?

하나의 추천 방식이 모든 상황을 해결하지 못한다

Content-Based

Item Feature를 잘 활용하지만 기존 취향과 비슷한 Item에 지나치게 집중할 수 있습니다.

과도한 유사성

User-Based

Similar User의 선택을 활용하지만 행동이 없는 New User에게 약합니다.

User Cold Start

Item-Based

Item 관계를 재사용할 수 있지만 Interaction이 없는 New Item에 약합니다.

Item Cold Start

Popularity

서비스 초기에도 사용할 수 있지만 개인별 취향을 충분히 반영하지 못합니다.

개인화 부족
하나의 알고리즘만 사용
↓
특정 데이터나 상황에서 약점 발생
↓
다른 추천 Signal로 보완
↓
Hybrid Recommendation

03 · Recommendation Signal

각 방식은 서로 다른 추천 근거를 제공한다

Signal 중심 정보 질문 예시
Content Score Item Feature 내 취향과 내용이 비슷한가? 장르·텍스트·태그
User-Based Score User Relation Similar User가 좋아했는가? Rating·Click Pattern
Item-Based Score Item Relation Liked Item과 반응이 비슷한가? Item Similarity
Popularity Score Global Interaction 전체에서 많이 소비되는가? 조회·구매·시청 수
Freshness Score 시간 얼마나 최신인가? 출시일·등록일

Hybrid의 목적은 알고리즘 수를 늘리는 것이 아니라, 서로 다른 정보의 장점을 하나의 Ranking에 반영하는 것 입니다.

05 · 핵심 용어

Candidate · Component Score · Final Score

01

Candidate

최종 추천 여부와 순위를 평가할 후보 Item입니다.

A, B, C, D
02

Component Score

각 추천 방식이 Candidate에 부여한 개별 점수입니다.

03

Final Score

여러 Signal을 결합한 최종 Ranking용 점수입니다.

Final Score는 반드시 확률이 아닙니다.

별도로 확률로 보정한 모델 출력이 아니라면 Candidate의 상대적 순서를 정하는 Ranking Score일 수 있습니다.

07 · Weighted Hybrid

각 Recommendation Score에 Weight를 적용한다

Content × 0.3
+
User-Based × 0.3
+
Item-Based × 0.4
→
Final Score
FinalScore(u,i) = αC(u,i) + βU(u,i) + γI(u,i)

Weighted Average로 구성한다면 일반적으로:

α + β + γ = 1

계산 예

Candidate Content User Item Final
Item A 0.90 0.40 0.80 0.71
Item B 0.50 0.90 0.60 0.66
Item C 0.70 0.60 0.70 0.67
1 Item A 0.71
2 Item C 0.67
3 Item B 0.66
Weight는 단순 숫자가 아니라 어떤 추천 논리를 얼마나 강하게 반영할지 나타냅니다.

20 · 코드 예제

Weighted Hybrid Score

weighted_hybrid.py 

from dataclasses import dataclass


@dataclass(frozen=True)
class HybridWeights:
    content: float = 0.3
    user_based: float = 0.3
    item_based: float = 0.4

    def validate(self) -> None:
        values = (
            self.content,
            self.user_based,
            self.item_based,
        )

        if any(value < 0 for value in values):
            raise ValueError(
                "Weights must not be negative."
            )

        total = sum(values)

        if abs(total - 1.0) > 1e-9:
            raise ValueError(
                "Weights must sum to 1.0."
            )


def hybrid_score(
    content_score: float,
    user_score: float,
    item_score: float,
    weights: HybridWeights,
) -> float:
    weights.validate()

    scores = {
        "content_score": content_score,
        "user_score": user_score,
        "item_score": item_score,
    }

    for name, value in scores.items():
        if not 0.0 <= value <= 1.0:
            raise ValueError(
                f"{name} must be between 0 and 1."
            )

    return (
        weights.content * content_score
        + weights.user_based * user_score
        + weights.item_based * item_score
    )
HybridWeights 추천 방식별 Weight
validate() 음수와 Weight 합 검증
hybrid_score() Component Score를 결합

    "Item_A": {

        "item": 0.80,

        "content": 0.50,

21 · 보완 코드

Missing Signal이 있을 때 Weight 재정규화 

from typing import Mapping


def available_weighted_score(
    scores: Mapping[str, float | None],
    weights: Mapping[str, float],
) -> float | None:
    weighted_sum = 0.0
    available_weight = 0.0

    for name, weight in weights.items():
        score = scores.get(name)

        if score is None:
            continue

        if not 0.0 <= score <= 1.0:
            raise ValueError(
                f"{name} score must be between 0 and 1."
            )

        weighted_sum += score * weight
        available_weight += weight

    if available_weight == 0:
        return None

    return (
        weighted_sum
        / available_weight
    )


scores = {
    "content": 0.8,
    "user": None,
    "item": 0.7,
}


weights = {
    "content": 0.3,
    "user": 0.3,
    "item": 0.4,
}


final_score = available_weighted_score(
    scores=scores,
    weights=weights,
)


print(final_score)
이 예에서는 User Score가 없다고 해서 0점으로 처리하지 않고, 사용 가능한 Signal의 Weight만 다시 정규화합니다.

22 · 코드 예제

User 상태에 따라 Recommender 선택 

def choose_recommender(
    *,
    user_history_count: int,
    has_initial_item: bool,
    has_content_profile: bool,
) -> str:
    if user_history_count < 0:
        raise ValueError(
            "user_history_count must not be negative."
        )

    if user_history_count >= 20:
        return "user_based"

    if has_initial_item:
        return "item_based"

    if has_content_profile:
        return "content_based"

    return "popularity"

    item_ids: list[str],
    source: str,
) -> None:
    for item_id in item_ids:
        candidate_sources.setdefault(
            item_id,
            set(),
        ).add(source)


add_candidates(
    content_items,
    "content_based",
)

add_candidates(
    user_items,
    "user_based",
)

add_candidates(
    item_items,
    "item_based",
)


for item_id, sources in candidate_sources.items():
    print(
        item_id,
        sorted(sources),
    )

25 · Hybrid의 장점

여러 정보의 장점을 함께 활용한다

01

약점 보완

단일 추천 방식의 Cold Start와 편향을 다른 Signal로 보완할 수 있습니다.

02

Coverage 확대

여러 추천기가 서로 다른 Candidate를 제공해 후보 범위를 넓힐 수 있습니다.

03

상황별 대응

New User, New Item, Active User에 따라 다른 방식이나 Weight를 사용할 수 있습니다.

04

추천 설명

내용·Similar User·Similar Item 등 다양한 추천 근거를 제공할 수 있습니다.

05

다양한 목표

정확도뿐 아니라 최신성·다양성·재고 등도 Ranking에 반영할 수 있습니다.

06

모델 확장

Embedding과 DNN을 사용하는 Deep Hybrid로 확장할 수 있습니다.

구현 복잡도

Score 의미 차이

Similarity, Rating, Count, Probability가 서로 다른 단위를 가질 수 있습니다.

어떤 Signal을 얼마나 반영할지 실험과 검증이 필요합니다.

원인 추적

Latency

Signal 지배

34 · 면접 포인트

질문과 답변으로 최종 복습

Q1. Hybrid Recommendation이란 무엇인가요?

Content-Based, Collaborative Filtering, Popularity 등 서로 다른 추천 Signal을 선택하거나 결합하고 필요하면 다시 정렬하여 Final Recommendation을 만드는 방식입니다.

Q2. Hybrid가 필요한 이유는 무엇인가요?

Content-Based, User-Based, Item-Based가 서로 다른 정보를 사용하고 서로 다른 Cold Start와 편향 문제를 가지기 때문에 이를 보완하기 위해 사용합니다.

Q3. Recommendation Signal이란 무엇인가요?

Candidate를 추천하거나 순위를 정할 때 사용하는 개별 추천 근거 또는 점수입니다.

Q4. Weighted Hybrid란 무엇인가요?

각 추천 방식의 Component Score에 Weight를 곱한 뒤 합산하여 Final Score를 만드는 방식입니다.

Q5. Weighted Hybrid에서 Normalization이 필요한 이유는 무엇인가요?

Similarity, Rating, Count처럼 Score의 범위와 단위가 서로 다르면 범위가 큰 Signal이 Final Score를 지배할 수 있기 때문입니다.

Q6. Missing Component Score는 0점과 같은가요?

아닙니다. 해당 알고리즘에서 계산할 수 없었거나 Candidate로 선택되지 않았다는 의미일 수 있습니다.

Q7. Post-processing Hybrid란 무엇인가요?

각 추천 방식이 만든 결과를 Candidate Pool로 합친 뒤 중복을 제거하고 Popularity·Freshness·Diversity 등의 기준으로 다시 정렬하는 방식입니다.

Q8. Switching Hybrid란 무엇인가요?

User History와 Item 상태 같은 현재 조건에 따라 Content-Based, User-Based, Item-Based 중 적합한 추천 방식을 선택하는 방식입니다.

Q9. New User에게 어떤 방식을 사용할 수 있나요?

Initial Liked Item이 있다면 Item-Based를, Content Profile이 있다면 Content-Based를 사용할 수 있습니다. 아무 정보도 없으면 Popularity 같은 Fallback이 필요합니다.

Q10. New Item에는 어떤 방식이 도움이 되나요?

Collaborative Interaction이 부족하므로 Text·Genre·Tag 같은 Metadata를 이용한 Content-Based가 도움이 될 수 있습니다.

Q11. Candidate Pool이란 무엇인가요?

여러 추천 방식이 제안한 Item을 합쳐 Final Score와 Ranking을 계산할 대상 집합입니다.

Q12. 동일 Candidate가 여러 추천기에서 나오면 어떻게 하나요?

Item ID 기준으로 하나로 통합하되, 각 Component Score와 source algorithm 정보는 유지할 수 있습니다.

Q13. Final Hybrid Score는 확률인가요?

반드시 그렇지는 않습니다. 여러 Candidate의 상대적 노출 순서를 정하는 Ranking Score일 수 있습니다.

Q14. Weighted와 Switching의 차이는 무엇인가요?

Weighted는 여러 방식을 동시에 실행해 Score를 합치고, Switching은 현재 상황에 맞는 하나의 방식을 선택합니다.

Q15. Weighted와 Post-processing의 차이는 무엇인가요?

Weighted는 Score 단계에서 결합하고, Post-processing은 각 추천 결과 목록을 만든 뒤 마지막 단계에서 다시 정렬합니다.

Q16. Re-ranking이란 무엇인가요?

초기 Recommendation Score 순위에 Freshness·Diversity·Availability 등의 추가 조건을 적용해 최종 노출 순서를 다시 만드는 과정입니다.

Q17. Deep Hybrid는 무엇인가요?

User·Item Embedding과 Text·Image·Genre 같은 Content Feature를 하나의 신경망에서 함께 학습하고 Ranking Score를 출력하는 구조입니다.

Q18. Embedding의 역할은 무엇인가요?

User ID와 Item ID를 작은 잠재 Vector로 변환하여 Interaction에서 직접 보이지 않는 관계를 모델이 학습할 수 있게 합니다.

Q19. Ranking Layer의 역할은 무엇인가요?

Candidate별 Click, Watch Time, Satisfaction 등의 목표에 맞는 Score를 계산하여 최종 노출 순위를 정합니다.

Q20. Hybrid가 Cold Start를 완전히 해결하나요?

아닙니다. User History, Initial Item, Item Feature가 모두 없다면 Popularity·Editorial 같은 별도의 Fallback이 필요합니다.

Q21. Hybrid의 대표적인 한계는 무엇인가요?

구현 복잡도, Score 정규화, Weight 결정, Latency 증가, 오류 원인 추적과 운영 비용 증가가 있습니다.

Q22. Hybrid Weight는 어떻게 결정할 수 있나요?

Domain Knowledge로 초기값을 정하고 Offline Evaluation과 A/B Test를 통해 조정할 수 있습니다. Deep Hybrid에서는 모델이 결합 관계를 학습할 수도 있습니다.

Q23. Hybrid가 실제로 더 좋은지 어떻게 확인하나요?

단일 알고리즘 결과와 Full Hybrid 결과를 Precision@K, NDCG, Coverage, CTR, Watch Time 등의 지표로 비교해야 합니다.

Q24. Hybrid를 한 문장으로 설명한다면?

서로 다른 추천 Signal을 상황과 목적에 맞게 선택·결합·재정렬하여 Final Recommendation을 만드는 방식입니다.
