RECOMMENDATION SYSTEM · LESSON 09 · MODEL-BASED RECOMMENDATION

추천 09. Model-Based Recommendation 과거 User-Item 관계에서 예측 규칙을 학습한다

Model-Based Recommendation은 과거의 User·Item·Interaction 데이터를 Machine Learning 또는 Deep Learning 모델에 학습시키고, 학습된 모델로 아직 관찰하지 않은 User-Item 관계의 점수를 예측하여 추천 순위를 만드는 방식 입니다.

이번 단원의 핵심 질문

“과거의 User-Item Interaction을 모델에 학습시키면, 아직 관찰하지 않은 관계를 어떻게 예측하고 무엇을 먼저 보여줄지 결정할 수 있을까?”
Model-Based Machine Learning Deep Learning Training Data Feature Target Parameter Hyperparameter Loss Model Training Prediction Generalization Overfitting Matrix Factorization Latent Factor Embedding Candidate Generation Ranking
추천 이론 과목에서의 역할

이번 단원은 특정 Deep Learning Framework의 문법을 깊게 실습하는 단계가 아닙니다.

핵심은 Interaction이 Training Data가 되고, 모델이 Parameter를 학습하며, Prediction을 Ranking으로 연결하는 전체 구조 를 이해하는 것입니다.

01 · 핵심 개념 설명

Model-Based Recommendation이란?

교안 직접 핵심 · 과거 데이터로 모델을 학습하고 새로운 데이터에 추천 수행

Model-Based Recommendation은 기존 User나 Item의 Similarity를 직접 찾아 사용하는 데서 끝나지 않습니다.

과거 Interaction을 학습 데이터로 만들고, Model이 User와 Item 사이의 반복 Pattern을 학습한 뒤 아직 관찰하지 않은 관계의 Score를 예측 합니다.

1 Historical Data 과거 Interaction
→
2 Model Training Pattern 학습
→
3 Prediction 미관측 관계 예측
→
4 Ranking 추천 순서 결정
핵심 한 문장

Model-Based는 과거 User-Item 관계를 단순 조회하는 방식이 아니라, 과거 관계에서 Prediction Rule을 학습하는 방식 입니다.

09 · Loss Function

모델의 Prediction이 실제값과 얼마나 다른가?

Actual 5.0
−
Prediction 4.2
→
Error 0.8
Squared Error = (5.0 − 4.2)² = 0.64
MSE = (1 / N) × Σ(rui − r̂ui)²

Rating Prediction

MSE·RMSE·MAE 등을 사용할 수 있습니다.

Click Prediction

Binary Cross Entropy 등을 사용할 수 있습니다.

Loss는 Parameter가 어느 방향으로 변경되어야 하는지 알려 주는 학습 신호 입니다.

14 · Overfitting

Training Data
↓
Pattern + Noise까지 암기
↓

↓
Validation / Test 성능 저하
Epoch Train Loss Validation Loss 해석
1 0.80 0.85 학습 초기

Train Loss ↓ + Validation Loss ↑ = Overfitting Signal

16 · Step 1·2 보완

Overfitting을 줄이는 방법

01

Validation

학습에 직접 사용하지 않은 데이터로 성능을 확인합니다.

02

Regularization

Parameter가 지나치게 커지고 복잡해지는 것을 제한합니다.

03

Early Stopping

Validation 성능이 악화되면 학습을 중단합니다.

04

Model 단순화

Embedding Dimension·Layer·Parameter를 줄입니다.

05

Dropout

특정 연결에 지나치게 의존하는 것을 줄입니다.

06

Data 확대

더 다양한 User·Item·Context 데이터를 사용합니다.

Total Loss = Prediction Loss + λ × Regularization
Validation, Regularization, Early Stopping 등은 교안의 Overfitting 설명을 실제 학습 흐름으로 확장한 보완 개념입니다.

Model-Based는 Cold Start를 보완할 수 있지만 완전히 제거하는 것은 아닙니다.

18 · 대표 보완 예 · Matrix Factorization

큰 User-Item Matrix를 작은 Latent Matrix로 분해한다

R ≈ P × QT
R User × Item Rating Matrix
≈
P User × Latent User Factors
×
QT Latent × Item Item Factors
Matrix Factorization은 첨부 교안이 직접 지정한 알고리즘이 아니라, Model-Based가 User·Item 관계를 학습하는 원리를 이해하기 위한 대표적인 보완 예입니다.

19 · Latent Factor와 Prediction

User와 Item을 같은 잠재 공간의 Vector로 표현한다

User A [0.7, 0.1, -0.3]
Movie C [0.6, -0.2, -0.1]
r̂ui = puT qi

User Vector와 Item Vector의 내적을 이용해 미관측 Rating을 예측할 수 있습니다.

Bias를 포함한 보완식

r̂ui = μ + bu + bi + puTqi
기호 의미
μ 전체 평균 Rating
bu User의 Rating 성향
bi Item의 평균적 인기·평가 성향
pu User Latent Vector
qi Item Latent Vector

24 · 전체 의사 코드

Data → Training → Prediction → Ranking

model_based_flow.py 

# 1. 과거 Interaction을 불러옵니다.
data = load_interactions()


# 2. Feature와 Target을 생성합니다.
features, target = build_training_data(
    data
)


# 3. 시간 기준으로 데이터를 나눕니다.
train_data, valid_data, test_data = split_by_time(
    features,
    target,
)


# 4. 추천 모델을 생성합니다.
model = RecommendationModel()


# 5. Train Data로 학습합니다.
model.fit(
    train_data
)


# 6. Validation 성능을 확인합니다.
validation_result = model.evaluate(
    valid_data
)


# 7. Test Data에서 최종 성능을 확인합니다.
test_result = model.evaluate(
    test_data
)


# 8. Target User와 Candidate Item의 Score를 예측합니다.
predictions = model.predict(
    target_user,
    candidate_items,
)


# 9. Prediction Score를 기준으로 Ranking합니다.
recommendations = rank_top_k(
    predictions,
    k=10,
)
build_training_data() Feature와 Target 구성

25 · Training Loop 의사 코드

Train과 Validation을 함께 기록한다 

best_validation_loss = float("inf")
patience_count = 0


for epoch in range(max_epochs):

    # -----------------------------
    # Train
    # -----------------------------
    model.train()

    train_prediction = model(
        train_input
    )

    train_loss = loss_function(
        train_prediction,
        train_target,
    )

    optimizer.zero_grad()
    train_loss.backward()
    optimizer.step()


    # -----------------------------
    # Validation
    # -----------------------------
    model.eval()

    validation_prediction = model(
        validation_input
    )

    validation_loss = loss_function(
        validation_prediction,
        validation_target,
    )


    # -----------------------------
    # Early Stopping
    # -----------------------------
    if validation_loss < best_validation_loss:
        best_validation_loss = validation_loss
        patience_count = 0

        save_model(
            model
        )
    else:
        patience_count += 1


    if patience_count >= patience:
        break
model.train() Parameter Update가 필요한 학습 모드
train_loss.backward() Gradient 계산
optimizer.step() Parameter Update
model.eval() Validation·Prediction 모드
Early Stopping Validation 악화 시 학습 중단

26 · Matrix Factorization 보완 코드

User Factor와 Item Factor를 학습한다 

import numpy as np


ratings = np.array(
    [
        [5.0, 4.0, 0.0],
        [5.0, 4.0, 3.0],
        [1.0, 2.0, 5.0],
    ],
    dtype=float,
)


num_users, num_items = ratings.shape
latent_dim = 2


rng = np.random.default_rng(
    seed=42
)


user_factors = rng.normal(
    scale=0.1,
    size=(
        num_users,
        latent_dim,
    ),
)


item_factors = rng.normal(
    scale=0.1,
    size=(
        num_items,
        latent_dim,
    ),
)


learning_rate = 0.01
regularization = 0.02
epochs = 500


observed = np.argwhere(
    ratings > 0
)


for epoch in range(epochs):

    squared_error = 0.0

    for user_index, item_index in observed:

        actual = ratings[
            user_index,
            item_index,
        ]

        prediction = np.dot(
            user_factors[user_index],
            item_factors[item_index],
        )

        error = actual - prediction

        squared_error += error ** 2


        old_user = user_factors[
            user_index
        ].copy()


        user_factors[user_index] += (
            learning_rate
            * (
                error
                * item_factors[item_index]
                - regularization
                * user_factors[user_index]
            )
        )


        item_factors[item_index] += (
            learning_rate
            * (
                error
                * old_user
                - regularization
                * item_factors[item_index]
            )
        )


predicted_ratings = (
    user_factors
    @ item_factors.T
)


print(
    predicted_ratings
)
이 코드는 Matrix Factorization의 학습 원리를 보여 주는 최소 교육 예제이며, 첨부 교안의 직접 실습 코드는 아닙니다.

target_user_index = 0


scores = predicted_ratings[
    target_user_index
]

    ratings[target_user_index]
    > 0
)

    ~seen_mask

recommendations = sorted(

            int(item_index),

        )
        for item_index in candidate_indices

    key=lambda row: row[1],

    recommendations,

        rank,

    )

29 · Model-Based의 장점

과거 데이터에서 복잡한 Pattern을 학습한다

01

새로운 관계 Prediction

아직 관찰하지 않은 User-Item Pair의 Score를 계산할 수 있습니다.

02

다양한 Feature

User·Item·Content·Context 정보를 함께 사용할 수 있습니다.

03

복잡한 Pattern

DNN으로 Feature 사이의 비선형 관계를 학습할 수 있습니다.

04

다양한 Target

Rating·Click·Purchase·Watch Time을 예측할 수 있습니다.

05

Latent Representation

User와 Item을 작은 잠재 Vector로 표현할 수 있습니다.

06

Cold Start 보완 가능성

Side Feature가 있다면 신규 User·Item을 일부 보완할 수 있습니다.

30 · Model-Based의 한계

모델을 학습하고 운영하는 비용이 필요하다

구현 복잡도

Dataset·Feature·Model·Deployment Pipeline이 필요합니다.

학습 자원

많은 데이터와 CPU·GPU·Memory·Training Time이 필요할 수 있습니다.

Overfitting

Training Data에 지나치게 맞으면 새로운 데이터 성능이 낮아집니다.

설명 어려움

복잡한 Model Score의 추천 근거를 설명하기 어려울 수 있습니다.

Training-Serving Skew

학습과 Online 환경의 Feature가 다르면 성능이 나빠집니다.

Drift와 Retraining

User 취향과 Item 분포가 변하면 재학습이 필요할 수 있습니다.

38 · 면접 포인트

질문과 답변으로 최종 복습

Q1. Model-Based Recommendation이란 무엇인가요?

과거 User-Item 데이터에서 Machine Learning 또는 Deep Learning 모델을 학습하고, 학습된 모델로 미관측 User-Item 관계의 Score를 예측해 추천 순위를 만드는 방식입니다.

Q2. Memory-Based와 Model-Based의 차이는 무엇인가요?

Memory-Based는 기존 User·Item Similarity를 직접 이용하고, Model-Based는 과거 Interaction에서 Prediction 함수와 Parameter를 학습합니다.

Q3. Machine Learning은 추천에서 어떤 역할을 하나요?

User·Item·Interaction·Context Feature에서 반복 Pattern을 학습해 Rating, Click, Purchase 또는 Ranking Score를 예측합니다.

Q4. Model Training이란 무엇인가요?

Prediction과 실제 Target의 차이를 Loss로 계산하고, Loss가 줄어들도록 Parameter를 반복 조정하는 과정입니다.

Q5. Feature와 Target은 무엇인가요?

Feature는 Prediction에 사용하는 입력 정보이고, Target은 모델이 예측해야 하는 실제 정답입니다.

Q6. Parameter와 Hyperparameter의 차이는 무엇인가요?

Parameter는 Training으로 학습되는 Weight·Embedding이고, Hyperparameter는 Learning Rate·Dimension처럼 사람이 설정하거나 탐색하는 값입니다.

Q7. Prediction이란 무엇인가요?

학습된 모델에 Target User와 Candidate Item을 입력하여 Rating·Probability·Ranking Score 등을 계산하는 과정입니다.

Q8. Prediction Score는 항상 Probability인가요?

아닙니다. Predicted Rating이나 Raw Ranking Score일 수 있으므로 Target과 score_type을 확인해야 합니다.

Q9. Generalization이란 무엇인가요?

Training에 직접 사용하지 않은 새로운 데이터에서도 모델이 합리적인 Prediction을 만드는 능력입니다.

Q10. Overfitting이란 무엇인가요?

모델이 Training Data의 Pattern과 Noise를 지나치게 암기하여 Train 성능은 좋지만 Validation·Test 성능은 낮아지는 현상입니다.

Q11. Overfitting은 어떻게 확인하나요?

Train Loss는 계속 낮아지는데 Validation Loss가 증가하거나 Validation Ranking 지표가 악화되는지 확인합니다.

Q12. Overfitting을 줄이는 방법은 무엇인가요?

Regularization, Early Stopping, Dropout, Model 단순화, Embedding Dimension 축소, 데이터 확대 등을 사용할 수 있습니다.

Q13. Train·Validation·Test를 왜 나누나요?

Train은 Parameter 학습, Validation은 Model 선택, Test는 최종 Generalization 평가에 사용하기 위해서입니다.

Q14. 추천에서 시간 기준 Split이 중요한 이유는 무엇인가요?

과거로 미래 행동을 예측하는 실제 서비스 구조를 재현하고, 미래 정보가 Training에 포함되는 Data Leakage를 방지하기 위해서입니다.

Q15. Loss Function의 역할은 무엇인가요?

Prediction과 실제 Target의 차이를 수치화해 Parameter가 어느 방향으로 업데이트되어야 하는지 알려 줍니다.

Q16. Matrix Factorization이란 무엇인가요?

User-Item Matrix를 User Latent Matrix와 Item Latent Matrix로 분해하고, 두 Latent Vector의 관계로 미관측 Rating을 예측하는 방법입니다.

Q17. Latent Factor란 무엇인가요?

Interaction Data에서 모델이 학습한 잠재적인 User 취향과 Item 특성 축입니다.

Q18. Embedding이란 무엇인가요?

User ID나 Item ID를 학습 가능한 작은 Vector로 변환하여 숨은 User-Item 관계를 모델이 학습하도록 하는 방법입니다.

Q19. Model-Based는 Cold Start를 완전히 해결하나요?

아닙니다. Side Feature가 있다면 보완할 수 있지만, 아무 Interaction과 Feature도 없다면 여전히 어렵습니다.

Q20. Candidate Generation과 Ranking의 차이는 무엇인가요?

Candidate Generation은 평가할 Item을 좁히는 단계이고, Ranking은 Candidate별 Score를 계산해 노출 순서를 정하는 단계입니다.

Q21. Model-Based의 주요 장점은 무엇인가요?

복잡한 Pattern을 학습하고 다양한 Feature를 사용하며, 미관측 User-Item 관계의 Score를 예측할 수 있다는 점입니다.

Q22. Model-Based의 주요 단점은 무엇인가요?

구현이 복잡하고 많은 데이터·시간·자원이 필요하며, Overfitting·Drift·Serving 복잡성이 발생할 수 있습니다.

Q23. Ranking Layer의 역할은 무엇인가요?

Candidate별 Prediction Score를 계산하여 어떤 Item을 먼저 노출할지 결정합니다.

Q24. Model-Based를 한 문장으로 설명한다면?

과거 User-Item 관계에서 예측 규칙을 학습해 보지 못한 관계의 Score를 계산하고 Ranking하는 방식입니다.
