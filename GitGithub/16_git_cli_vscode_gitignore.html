Git Bash와 현재 폴더 확인

Git 명령어는 현재 터미널이 위치한 폴더를 기준으로 실행됩니다. 명령어가 맞아도 잘못된 폴더에서 실행하면 다른 Repository를 수정하거나 Repository를 찾지 못할 수 있습니다.

프로젝트 구조

sample-project/
├── .git/
├── .gitignore
├── src/
├── build.gradle
└── README.md

기본 위치 명령

# 현재 위치
pwd

# 파일 목록
ls

# 숨김 파일 포함
ls -a

# 폴더 이동
cd sample-project

# 상위 폴더
cd ..
1 현재 위치 확인 pwd
2 .git 존재 확인 ls -a
3 Repository 상태 확인 git status

`fatal: not a git repository`가 보인다면

현재 폴더 또는 상위 폴더에서 `.git`을 찾지 못했다는 의미입니다. 올바른 프로젝트 폴더로 이동하거나 새 프로젝트라면 `git init`을 실행합니다.

08

PAT와 Credential Manager

PAT

개인 인증 Token

HTTPS Git 작업이나 API 접근에서 사용할 수 있는 민감한 인증 정보입니다.

Credential Manager

인증 정보 보관

매번 인증 정보를 입력하지 않도록 계정과 Token을 안전하게 연결합니다.

Repository Permission

실제 접근 권한

인증에 성공해도 해당 Repository에 쓰기 권한이 있어야 Push할 수 있습니다.

공유 금지

PAT를 팀원과 함께 사용하지 않습니다.

최소 권한

필요한 Repository와 Permission만 선택합니다.

만료 관리

유효 기간을 설정하고 만료 전에 갱신합니다.

노출 시 폐기

노출된 Token은 즉시 폐기하고 새로 발급합니다.

1 Commit 작성자 확인 git config user.email
2 Remote URL 확인 git remote -v
3 Credential Helper 확인 git config --global credential.helper
4 권한 확인 Collaborator / Organization
Windows 저장 Credential 확인 제어판 → 사용자 계정 → 자격 증명 관리자 → Windows 자격 증명 → GitHub 관련 항목 확인

`git init`과 `git clone` 선택

NEW LOCAL PROJECT

EXISTING REMOTE PROJECT

기존 Remote를 Clone

git clone URL
cd project
git status
git remote -v

GitHub에 이미 README, License나 기존 History가 있다면 Clone 방식이 더 단순합니다.

Remote가 완전히 비어 있음 → Local init 후 첫 Push
Remote에 Commit이 있음 → Clone으로 시작

Remote README와 Local 첫 Commit이 따로 존재하면

Local과 Remote History가 서로 다른 시작점을 가질 수 있습니다. 단순히 Force Push하지 말고 History를 확인하거나 Clone 방식으로 다시 시작합니다.

15

Restore · RM · Revert · Reset 구분

RESTORE

파일 상태 복원

git restore 파일 git restore --staged 파일

Commit 전 파일 변경이나 Stage를 되돌립니다.

RM

파일 제거·추적 해제

git rm 파일 git rm --cached 파일

실제 파일 삭제 또는 Git Index에서만 제거합니다.

REVERT

반대 변경 Commit

git revert CommitID

공유 History를 지우지 않고 새 취소 Commit을 만듭니다.

RESET

과거 위치로 이동

git reset --soft git reset --mixed git reset --hard

Local History와 파일 상태를 되돌리며 `--hard`는 손실 위험이 큽니다.

교안 명령 오탈자 보완

잘못된 표기 git restore --statged 파일
정확한 표기 git restore --staged 파일

복원 명령은 실행 전에 상태를 확인합니다

`git restore`, `git reset --hard`, VS Code의 Discard Changes는 Working Directory 수정 내용을 잃게 할 수 있습니다. 먼저 `git status`와 `git diff`를 확인합니다.

초보자가 자주 하는 실수

1. 잘못된 폴더에서 명령 실행

`pwd`, `ls -a`, `git status`로 현재 Repository를 확인합니다.

2. user.name을 GitHub ID로 이해

user.name은 Commit 작성자 이름이며 로그인 계정 설정이 아닙니다.

3. 이메일 변경이 인증 계정도 바꾼다고 생각

Credential Manager의 GitHub 인증 정보는 별도로 확인해야 합니다.

4. 모든 프로젝트에서 Global 설정만 변경

회사와 개인 프로젝트는 Local 설정으로 분리할 수 있습니다.

5. PAT를 코드나 메신저로 공유

PAT는 개인 인증 정보이며 노출 시 즉시 폐기해야 합니다.

6. PAT 권한을 무조건 모두 허용

작업에 필요한 Repository와 최소 Permission만 선택합니다.

7. Remote URL을 확인하지 않고 Push

`git remote -v`로 실제 Push 대상을 확인합니다.

8. git add . 후 검토 생략

Secret, 로그, Build 결과와 개인 설정이 포함될 수 있습니다.

9. Commit과 Push를 혼동

Commit은 Local 저장이고 Push는 Remote 전송입니다.

10. Fetch와 Pull을 혼동

Fetch는 정보만 가져오고 Pull은 현재 Branch에 통합합니다.

11. Remote README가 있는데 Local init부터 시작

기존 History가 있다면 Clone 방식이 더 안전합니다.

12. VS Code Changes를 모두 바로 Commit

Staged Changes에 원하는 파일만 포함됐는지 확인합니다.

13. Discard Changes를 가볍게 실행

Working Directory 수정이 사라질 수 있으므로 Diff를 먼저 봅니다.

14. .gitignore를 늦게 작성

첫 Commit에 Dependency, Build와 Secret이 포함될 수 있습니다.

15. Tracked 파일도 자동 Ignore된다고 생각

`git rm --cached`로 Index에서 추적을 제거해야 할 수 있습니다.

16. .env.example에 실제 Secret 작성

실제 값이 아닌 Placeholder만 작성합니다.

17. Gradle Wrapper를 무조건 제외

팀과 CI의 동일한 Gradle 실행 환경이 깨질 수 있습니다.

18. .gitignore를 보안 삭제 도구로 오해

이미 Commit된 Secret은 History에 남을 수 있습니다.

19. 공유 Branch에서 무분별한 Rebase

Commit ID와 History가 변경되어 팀원과 충돌할 수 있습니다.

20. Force Push로 모든 오류 해결 시도

권한, Conflict와 rejected의 기본 해결 방법이 아닙니다.

면접 포인트

Q1. Git GUI와 CLI의 차이는 무엇인가요?

같은 Git Repository와 기능을 서로 다른 인터페이스로 조작합니다. GUI는 시각적이고, CLI는 상태 확인·자동화·오류 분석에 유리합니다.

Q2. `git status`를 자주 사용하는 이유는 무엇인가요?

현재 Branch, Working Directory 변경, Staging 상태, Untracked 파일과 Merge·Rebase 진행 상태를 한 번에 확인할 수 있기 때문입니다.

Q3. `user.name`과 `user.email`은 무엇인가요?

새 Commit에 기록되는 작성자 이름과 이메일입니다. GitHub 로그인 ID나 Repository 접근 권한을 설정하는 값은 아닙니다.

Q4. Commit 작성자와 Push 사용자는 항상 같은가요?

아닙니다. Commit 작성자는 Git 설정으로 기록되고, Push 사용자는 PAT, Credential Manager, GitHub CLI 또는 SSH로 인증됩니다.

Q5. Global과 Local Git 설정의 차이는 무엇인가요?

Global은 현재 OS 사용자의 기본값이고, Local은 현재 Repository에만 적용되며 같은 항목에서는 우선할 수 있습니다.

Q6. Commit과 Push의 차이는 무엇인가요?

Commit은 변경을 Local Repository에 저장하고, Push는 Local Commit을 Remote Repository로 전송합니다.

Q7. Fetch와 Pull의 차이는 무엇인가요?

Fetch는 Remote 정보를 가져와 Remote-tracking Branch를 갱신하고, Pull은 Fetch 후 현재 Branch에 Remote 변경을 통합합니다.

Q8. VS Code의 Changes와 Staged Changes는 무엇인가요?

Changes는 Stage하지 않은 Working Directory 변경이고, Staged Changes는 다음 Commit에 포함하도록 Index에 등록한 변경입니다.

Q9. 기존 GitHub Repository가 있을 때 init과 clone 중 무엇을 사용하나요?

이미 Remote History가 존재한다면 Clone하는 것이 일반적으로 단순합니다. 새 Local 프로젝트와 빈 Remote를 연결할 때는 init으로 시작할 수 있습니다.

Q10. `.gitignore`란 무엇인가요?

Git이 의도적으로 추적하지 않을 Untracked 파일과 폴더 패턴을 지정하는 파일입니다.

Q11. `.gitignore`를 추가했는데 파일이 계속 표시되는 이유는 무엇인가요?

해당 파일이 이미 Tracked 상태일 수 있습니다. `.gitignore`는 이미 추적하는 파일에 자동으로 적용되지 않습니다.

Q12. 이미 추적 중인 파일을 제외하려면 어떻게 하나요?

`.gitignore`에 패턴을 추가한 뒤 git rm --cached 파일명으로 Index에서 제거하고 Commit합니다.

Q13. `.gitignore`는 보안 도구인가요?

Secret의 실수 Commit을 예방하는 데 도움을 주지만, 이미 Commit된 Secret을 History에서 삭제하지는 않습니다.

Q14. `git restore`와 `git restore --staged`의 차이는 무엇인가요?

`git restore 파일`은 Working Directory 변경을 복원하고, `--staged`는 파일을 Staging Area에서 내립니다.

Q15. 403 오류가 발생하면 무엇을 확인하나요?

Remote URL, GitHub 인증 계정, PAT 권한과 만료, Collaborator 권한, 현재 Branch와 Branch Protection을 확인합니다.

최종 문장

Git CLI를 이해한다는 것은 명령어를 단순히 외우는 것이 아니라, 네 개의 Git 공간에서 현재 변경이 어디에 있는지 읽는 것입니다. VS Code는 그 상태를 시각적으로 보여주고, `.gitignore`는 실제 프로젝트에서 관리할 파일과 제외할 파일의 경계를 지켜줍니다.

학습 메모

오늘의 암기 포인트

  • GUI와 CLI는 같은 Git Repository를 조작합니다.
  • Git 작업이 헷갈리면 먼저 git status를 실행합니다.
  • user.name과 user.email은 Commit 작성자 정보입니다.
  • GitHub 인증 계정은 PAT·Credential·SSH 등으로 별도 관리됩니다.
  • Commit은 Local 저장이고 Push는 Remote 전송입니다.
  • `.gitignore`는 이미 Tracked된 파일에 자동 적용되지 않습니다.

오류 빠른 분류

  • command not found: Git 설치·PATH 확인
  • not a git repository: 현재 폴더와 `.git` 확인
  • Author identity unknown: 사용자 이름·이메일 설정
  • Authentication failed: PAT·Credential 확인
  • 403: 계정·권한·Push 대상 확인
  • non-fast-forward: Remote 변경을 먼저 통합
  • CONFLICT: 최종 코드를 직접 결정
  • paths are ignored: Ignore 패턴 확인
