Git/GitHub - Chapter 09

GitHub 원격 저장소 만들기

지금까지 만든 Commit은 모두 내 컴퓨터의 Local Repository에만 존재합니다.
다른 컴퓨터에서 프로젝트를 이어서 작업하고, 팀원과 같은 Commit History를 공유하고, GitHub에서 프로젝트를 공개하려면 Remote Repository가 필요합니다.
이번 단원의 핵심 질문은 “내 컴퓨터에만 있는 Commit History를 왜 GitHub에 별도의 저장소로 만들어야 하는가?” 입니다.

01

원격 저장소를 공부한다는 것

Local Repository를 만들고 Commit을 여러 번 생성해도 그 기록은 기본적으로 내 컴퓨터의 .git 안에만 있습니다.
GitHub Repository는 이 Local History를 네트워크를 통해 보관하고 공유할 수 있는 원격 공간입니다.

Local

내 컴퓨터의 저장소

Add, Commit, Branch, Reset 같은 작업이
먼저 기록되는 저장소입니다.

Remote

네트워크의 저장소

GitHub 서버에서 Commit History와
Branch를 보관하고 공유합니다.

Connect

주소로 연결

Remote URL을 Local Repository에
등록해야 두 저장소 사이의 통로가 생깁니다.

Share

Push로 공유

Local Commit을 Push해야
GitHub Repository에 실제 History가
올라갑니다.

핵심 문장

GitHub Repository는 단순한 업로드 폴더가 아니라, Commit, Branch, Tag, History를 원격에서 관리하는 Git 저장소입니다.

02

Local Repository와 Remote Repository 비교

LOCAL REPOSITORY

내 컴퓨터의 Git 저장소

  • 프로젝트 폴더와 .git이 존재합니다.
  • 인터넷 없이도 Add, Commit, Branch 작업이 가능합니다.
  • 아직 Push하지 않은 Commit은 이곳에만 존재합니다.
  • 현재 작업 Branch와 HEAD를 직접 관리합니다.
Local History
A → B → C
        ↑
   HEAD, main
Push → ← Fetch / Pull
REMOTE REPOSITORY

GitHub 서버의 Git 저장소

  • 네트워크를 통해 접근하는 공유 저장소입니다.
  • Push된 Commit과 Branch를 보관합니다.
  • 다른 컴퓨터와 팀원이 같은 History를 받을 수 있습니다.
  • Pull Request, Issue, Review 같은 협업 기능을 제공합니다.
Remote History
A → B → C
        ↑
       main
구분 Local Repository Remote Repository
위치 내 컴퓨터 GitHub 서버
주요 작업 Add, Commit, Branch, Reset Push, Pull, Clone, PR, Review
인터넷 필요 여부 대부분 필요 없음 접속과 동기화에 필요
초보자가 자주 하는 착각 Commit하면 GitHub에 올라간다고 생각함 Repository를 만들면 Local 코드가 자동 업로드된다고 생각함
03

Commit과 Push는 서로 다른 단계다

Commit은 Local Repository에 변경 이력을 저장하는 작업이고, Push는 이미 만들어진 Local Commit을 Remote Repository로 전송하는 작업입니다.
두 단계를 구분하지 못하면 “분명 Commit했는데 GitHub에 안 보인다”는 문제가 생깁니다.

3

Local Repository

내 컴퓨터에
Commit History가 저장됩니다.

git commit

GitHub에
Commit History가 공유됩니다.

초보자 핵심 주의

git commit은 내 컴퓨터에 저장하는 단계이고, git push는 GitHub에 보내는 단계입니다. Commit만으로는 GitHub 웹 화면에 변경 사항이 나타나지 않습니다.

07

Public과 Private 선택 기준

Repository 공개 범위는 코드가 보이는 사람을 결정합니다.
학습 포트폴리오처럼 공개해도 되는 코드는 Public을 사용할 수 있지만, 민감한 정보나 수업 자료 원문, API Key가 포함될 수 있는 프로젝트는 Private이 안전합니다.

PUBLIC

누구나 볼 수 있는 저장소

  • 포트폴리오 공개에 적합합니다.
  • README, Commit History, 코드가 외부에 보입니다.
  • 민감 정보가 들어가면 바로 노출됩니다.
PRIVATE

권한이 있는 사람만 보는 저장소

  • 개인 실습, 수업 자료, 미완성 프로젝트에 적합합니다.
  • Collaborator를 추가해야 팀원이 접근할 수 있습니다.
  • 공개 전 점검용으로 사용하기 좋습니다.
절대 올리면 안 되는 것

비밀번호, DB 접속 정보, API Key, 토큰, 개인 정보, 수업 자료 원문은 공개 저장소에 올리지 않습니다.

.env, application.properties, token.txt

GitHub 새 Repository 화면의 초기화 옵션은 편리하지만, 이미 Local Repository에 Commit History가 있는 프로젝트라면 조심해야 합니다.
GitHub에서 README를 자동 생성하면 Remote에도 첫 Commit이 생기기 때문입니다.

옵션 선택 안 함

빈 Remote Repository

Local History를 그대로 첫 Push하기 쉽습니다.

또는
README 자동 생성

Remote에 첫 Commit 생성

Local History와 Remote History가 서로 달라져 Push가 막힐 수 있습니다.

Local : A → B → C

기존 Local 프로젝트를 올릴 때 추천

이미 내 컴퓨터에서 Git을 시작하고 Commit까지 만든 상태라면 GitHub Repository 생성 시 README, .gitignore, License 자동 생성 옵션을 비워 두는 것이 가장 단순합니다.

12

HTTPS 인증과 Personal Access Token

GitHub는 비밀번호만으로 Git 작업을 인증하지 않습니다. HTTPS로 Push할 때는 브라우저 로그인, Credential Manager, 또는 Personal Access Token 같은 인증 흐름을 사용합니다.

Credential Manager

운영체제가 인증 정보를 기억

처음 Push할 때 브라우저 또는 로그인 창이 열리고, 이후 인증 정보가 저장될 수 있습니다.

PAT

비밀번호 대신 사용하는 토큰

권한 범위를 정해 만든 토큰이며, 노출되면 Repository 접근 권한이 유출될 수 있습니다.

토큰은 코드에 쓰지 않는다

Personal Access Token은 절대 HTML, JS, properties, README, 캡처 이미지에 남기지 않습니다.

14

Force Update와 Force Push를 조심해야 하는 이유

GitHub에 이미 존재하는 History와 내 Local History가 다를 때, 일부 도구는 Force Update 또는 Force Push 옵션을 보여 줄 수 있습니다.
이 기능은 Remote History를 내 Local 기준으로 덮어쓸 수 있으므로 신중하게 사용해야 합니다.

Normal Push

History가 이어질 때만 전송

Remote History를 보존하면서 Local Commit을 뒤에 붙입니다.

Remote: A → B
Local : A → B → C
Push  : A → B → C
Force Push

Remote History를 강제로 변경

Remote에 있던 Commit이 사라질 수 있어 협업 환경에서는 위험합니다.

Remote: A → B → X
Local : A → B → C
Force : A → B → C

Force Push는 오류 해결 버튼이 아니다

Remote의 기존 History를 덮어쓰는 방식은 팀 작업에서 매우 위험합니다. 특히 다른 사람이 이미 사용 중인 Repository에서는 임의로 Force Push하지 않습니다.

17

면접 포인트

Q1. Local Repository와 Remote Repository의 차이는 무엇인가요?

Local Repository는 내 컴퓨터에 있는 Git 저장소이고, Remote Repository는 GitHub 같은 서버에 있는 공유 저장소입니다.

Q2. Commit과 Push의 차이는 무엇인가요?

Commit은 Local Repository에 변경 이력을 저장하는 작업이고, Push는 그 Commit을 Remote Repository로 전송하는 작업입니다.

Q3. origin은 무엇인가요?

origin은 원격 저장소 URL에 붙이는 기본 별칭입니다. 긴 URL 대신 origin이라는 이름으로 Push와 Pull을 실행할 수 있습니다.

Q4. 기존 Local 프로젝트를 GitHub에 올릴 때 README 자동 생성을 조심해야 하는 이유는?

Remote에 별도의 초기 Commit이 생겨 Local History와 달라질 수 있고, 첫 Push에서 History 불일치 오류가 발생할 수 있기 때문입니다.

Q5. git push -u origin main의 -u는 무슨 의미인가요?

Local main Branch가 origin/main을 기본 추적 대상으로 사용하도록 Upstream을 설정한다는 의미입니다.

학습 메모

오늘의 암기 포인트

  • GitHub Repository는 원격에 있는 Git 저장소입니다.
  • Commit은 Local 저장, Push는 Remote 전송입니다.
  • origin은 원격 저장소 URL의 별칭입니다.
  • main은 Local Branch이고, origin/main은 Remote Tracking Branch입니다.
  • 기존 Local Commit이 있다면 GitHub Repository를 빈 상태로 만드는 것이 안전합니다.

헷갈리기 쉬운 개념

  • Repository 생성과 Local 연결은 같은 일이 아닙니다.
  • README 자동 생성은 Remote Commit을 하나 만드는 일입니다.
  • Public 저장소는 누구나 볼 수 있으므로 민감 정보를 올리면 안 됩니다.
  • Force Push는 오류 해결 버튼이 아니라 Remote History를 바꾸는 위험한 작업입니다.
