01

이번 단원의 핵심: 주소를 등록하고, 인증하고, Commit을 보낸다

로컬에서 Commit을 만들었다고 해서 GitHub에 자동으로 올라가지는 않습니다.
Git은 먼저 어느 원격 저장소로 보낼지 알아야 하고, GitHub는 Push를 요청한 사용자가 누구이며 쓰기 권한이 있는지 확인해야 합니다.
따라서 최초 연결은 Remote 등록 → 인증 → Push → Upstream 설정의 순서로 진행됩니다.

Local

Commit이 만들어진 곳

Working Directory의 변경을
Add하고 Commit하면
내 컴퓨터의 Local Repository에
버전이 생깁니다.

Remote

목적지 주소 등록

GitHub Repository URL을
origin이라는 이름으로
로컬 Git 설정에 저장합니다.

Auth

사용자와 권한 확인

HTTPS Push에서는
GitHub Username과
Personal Access Token으로 인증합니다.

Push

Commit History 전송

로컬 Branch의 Commit을
원격 Branch로 보내고 추적 관계를 설정합니다.

한 문장으로 정리

Remote는 목적지, PAT는 출입 권한, Push는 Commit 전송, Upstream은 다음부터 사용할 기본 연결 관계입니다.

02

Git·GitHub·Local·Remote를 정확히 구분하기

LOCAL REPOSITORY

내 컴퓨터의 Git 저장소

  • .git 안에 Commit, Branch, HEAD가 저장됩니다.
  • 인터넷 없이도 Add, Commit, Branch, Log 작업이 가능합니다.
  • Push하지 않은 Commit은 이곳에만 존재합니다.
  • main은 로컬에서 직접 작업하는 Branch입니다.
Local History
A ── B ── C
          ↑
       HEAD, main
Push → ← Fetch / Pull
REMOTE REPOSITORY

GitHub 서버의 Git 저장소

  • 네트워크를 통해 여러 개발자가 공유합니다.
  • Push된 Commit과 Branch만 보관합니다.
  • Clone, Pull Request, Review, Actions의 기준점이 됩니다.
  • origin/main은 원격 상태를 로컬에서 추적하는 이름입니다.
Remote History
A ── B ── C
          ↑
         main
용어 정확한 의미 초보자가 자주 하는 착각
Git 변경 이력과 Branch를 관리하는 분산 버전 관리 도구 GitHub와 같은 서비스라고 생각함
GitHub Git 저장소를 원격에서 보관·공유하는 서비스 GitHub가 없으면 Git을 사용할 수 없다고 생각함
Commit Staging Area의 변경으로 Local Repository에 버전을 생성 Commit하면 GitHub에도 자동 반영된다고 생각함
Push Local Repository의 Commit을 Remote Repository로 전송 현재 폴더의 모든 파일을 그대로 업로드한다고 생각함
03

파일 수정부터 GitHub 반영까지의 전체 저장 흐름

Push되는 대상은 지금 화면에 보이는 모든 파일이 아니라 Local Repository에 확정된 Commit입니다. 따라서 파일 수정 후 Add와 Commit을 거치지 않은 내용은 GitHub에 올라가지 않습니다.

04

Remote, origin, Remote URL은 각각 무엇인가?

Remote는 원격 저장소 연결 정보이고, origin은 그 연결 정보에 붙이는 관례적인 이름입니다. 실제 GitHub 저장소 위치는 HTTPS 또는 SSH URL로 기록됩니다.

Remote

원격 연결 정보

로컬 Git이 어느 외부 저장소와 통신할지
저장하는 설정입니다.

origin

기본 Remote 별칭

긴 주소 대신 사용하는 이름이며
Git 예약어는 아니지만 관례적으로 사용합니다.

Remote URL

https://github.com/OWNER/REPO.git

05

최초 Push 전에 GitHub 저장소와 로컬 상태 점검하기

이미 로컬에서 Commit을 만든 프로젝트라면 GitHub 저장소는 README, .gitignore, License를 자동 생성하지 않은 빈 저장소로 준비하는 것이 가장 단순합니다.
원격에 별도의 첫 Commit이 생기면 로컬과 시작 이력이 달라질 수 있습니다.

권장 상태

Remote는 비어 있고 Local에만 Commit이 있음

로컬 History를 그대로 최초 Push하기 쉽습니다.

비교
주의 상태

GitHub README로 Remote Commit이 이미 생김

Remote: R
Local : A ── B ── C

서로 다른 시작 이력 때문에 Pull 또는 Merge가 필요할 수 있습니다.

git push -u origin main과 Upstream

최초 Push에서 사용하는 -u는 --set-upstream의 축약형입니다. 로컬 main이 앞으로 어느 원격 Branch를 기본 대상으로 사용할지 연결합니다.

LOCAL BRANCH

main

내 컴퓨터에서 HEAD가 가리키고 직접 Commit하는 Branch

git push -u origin main ↕ Upstream Tracking 이후 git push / git pull
REMOTE-TRACKING BRANCH

origin/main

마지막으로 확인한 GitHub main의 상태를 로컬에서 나타내는 이름

git push

Commit을 전송

git push

Upstream이 설정되어 있으면
origin과 Branch 이름을 생략할 수 있습니다.

git pull

연결된 원격 변경 반영

git pull

다음 단원에서 Fetch와 Merge 관계를 함께 학습합니다.

git branch -vv

추적 관계 확인

* main abc1234 [origin/main]

대괄호에 origin/main이 보이면
Upstream이 연결된 상태입니다.

19

면접 포인트

Q1. Git과 GitHub의 차이는 무엇인가요?

Git은 로컬에서 변경 이력과 Branch를 관리하는 분산 버전 관리 도구이고, GitHub는 Git 저장소를 원격에서 보관하고 협업 기능을 제공하는 서비스입니다.

Q2. Commit과 Push의 차이는 무엇인가요?

Commit은 Staging Area의 변경으로 Local Repository에 버전을 만들고, Push는 Local Commit을 Remote Repository로 전송합니다.

Q3. Remote와 origin은 무엇인가요?

Remote는 원격 저장소 연결 정보이고 origin은 최초 또는 기본 Remote에 관례적으로 붙이는 별칭입니다.

Q4. PAT는 왜 사용하나요?

HTTPS Git 작업에서 사용자를 인증하고 저장소 접근 권한을 제한하기 위해 사용합니다. Password 필드에는 GitHub 로그인 비밀번호 대신 PAT를 입력합니다.

Q5. Fine-grained PAT의 장점은 무엇인가요?

특정 소유자와 Repository, 세부 권한, 만료일을 제한할 수 있어 최소 권한 원칙을 적용하기 쉽습니다.

Q6. git push -u origin main을 설명해보세요.

로컬 main Commit을 origin으로 Push하고, 로컬 main이 원격 Branch를 기본 추적하도록 Upstream을 설정합니다.

Q7. main과 origin/main의 차이는 무엇인가요?

main은 직접 Commit하는 Local Branch이고, origin/main은 마지막으로 확인한 Remote main 상태를 로컬에서 나타내는 Remote-tracking Branch입니다.

Q8. 403 오류는 무엇을 의미하나요?

GitHub에 접근은 했지만 현재 계정이나 PAT가 대상 Repository에 쓰기 권한을 갖지 못한 경우가 많습니다.

Q9. non-fast-forward로 Push가 거절되는 이유는 무엇인가요?

Remote에 Local이 가지고 있지 않은 Commit이 있어, 그대로 Push하면 원격 History가 손실될 수 있기 때문입니다.

Q10. Force Push가 위험한 이유는 무엇인가요?

Remote Branch의 기존 Commit History를 강제로 변경하여 팀원이 기반으로 작업한 Commit을 사라지게 할 수 있기 때문입니다.
