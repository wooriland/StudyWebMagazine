Local Destination

새 Clone 경로 지정

기존 프로젝트 파일이 남아 있는 폴더, 다른 Git 저장소 내부, Eclipse의 .metadata 폴더는 피합니다.

D:\
├── eclipse-workspace\
│   └── .metadata\
└── git-repositories\
    └── sample-project\

D:\eclipse-workspace\.metadata\sample-project

또는

기존 파일이 남은
D:\workspace\sample-project

기존 프로젝트와 같은 폴더에 다시 Clone하지 않습니다

오래된 파일, 이전 .git, build 결과물과 새 Clone 파일이 섞이면 프로젝트 상태를 판단하기 어려워집니다.

Import as General Project
GENERAL PROJECT

파일과 폴더를 Eclipse에 표시

  • Project Explorer에서 파일을 볼 수 있습니다.
  • HTML·CSS·문서 프로젝트에 사용할 수 있습니다.
  • Java Source Folder가 자동 구성되지 않을 수 있습니다.
  • Gradle Dependency가 연결되지 않을 수 있습니다.
GRADLE PROJECT

빌드 모델을 읽어 개발 환경 구성

  • src/main/java를 Source Folder로 구성합니다.
  • 외부 Dependency를 Classpath에 연결합니다.
  • Gradle Tasks를 사용할 수 있습니다.
  • 멀티 Module 관계를 구성합니다.

16

초보자가 자주 하는 실수

1. Clone하면
Eclipse에 자동 표시된다고 생각

Clone은 디스크 저장이고
Eclipse 등록에는 Import가 필요합니다.

2. Import하면
GitHub 파일이 내려온다고 생각

Import는 이미 디스크에 있는
프로젝트를 등록합니다.

3. ZIP 다운로드를 Clone으로 착각

ZIP에는 일반적으로
.git과 Commit History가 없습니다.

4. Clone 후 git init 실행

Clone 과정에서
이미 Local Repository가 만들어졌습니다.

5. Clone 후 origin을 다시 등록

Clone은 원격 URL을
origin으로 자동 등록합니다.

6. 기존 파일이 있는 폴더에 Clone

새 폴더 또는 비어 있는 폴더를 사용해야 합니다.

7. 같은 프로젝트를 중복 Import

Workspace에
동일 이름 프로젝트가 있으면 충돌합니다.

8. 디스크 내용까지 삭제

Delete contents on disk는
실제 Clone 폴더를 삭제합니다.

9. Gradle 프로젝트를 General로만 사용

Dependency와 Source Folder가
정상 구성되지 않을 수 있습니다.

10. src 폴더를 Gradle Root로 선택

build.gradle과 settings.gradle이
있는 루트를 선택합니다.

11. 매번 다시 Clone

이미 Clone한 프로젝트의 최신화는
Pull 또는 Fetch를 사용합니다.

12. Public이면 Push도 가능하다고 생각

Public은 읽기 공개이며
쓰기 권한은 별도입니다.

17

Clone·Import·Gradle 오류 메시지 읽기

오류가 발생하면 먼저 Clone, Eclipse Import, Gradle, Build, Git 동기화 중 어느 단계의 문제인지 분류해야 합니다.

오류 메시지
발생 단계와 의미
확인 방향
Repository not found
Clone 단계에서 저장소를 찾지 못했거나 접근 권한이 없습니다.
Owner, Repository 이름, URL, Private 권한을 확인합니다.
Authentication failed
GitHub 인증 정보가 올바르지 않습니다.
Username, PAT, 만료일, 저장된 Credential을 확인합니다.
403
계정은 확인됐지만 읽기 또는 쓰기 권한이 부족합니다.
Collaborator, PAT Repository Access, 저장소 권한을 확인합니다.
Could not resolve host
github.com에 네트워크로 연결하지 못했습니다.
인터넷, DNS, Proxy, 방화벽과 VPN을 확인합니다.

면접 포인트

Q1. Git Clone이란 무엇인가요?

원격 Git 저장소의 파일과 Commit History, Branch, Git 객체를 내 컴퓨터에 복제하여 새로운 Local Repository를 만드는 작업입니다.

Q2. Clone과 Pull의 차이는 무엇인가요?

Clone은 Local Repository가 없을 때 저장소 전체를 처음 복제하고, Pull은 이미 존재하는 Local Repository에 원격 최신 변경을 가져와 반영합니다.

Q3. Clone과 Download ZIP의 차이는 무엇인가요?

ZIP은 일반적으로 현재 파일만 포함하지만, Clone은 .git, Commit History, Branch와 Remote 정보까지 포함합니다.

Q4. Clone 후 origin은 어떻게 설정되나요?

Clone한 원격 저장소의 URL이 일반적으로 origin이라는 이름으로 자동 등록됩니다.

Q5. Clone과 Eclipse Import의 차이는 무엇인가요?

Clone은 Git 저장소를 로컬 디스크에 복제하는 작업이고, Import는 해당 프로젝트를 Eclipse Workspace에 등록하는 작업입니다.

Q6. General Project와 Gradle Project의 차이는 무엇인가요?

General Project는 폴더를 Eclipse에 표시하는 수준이며, Gradle Project는 빌드 파일을 해석하여 Source Folder와 Dependency를 구성합니다.

Q7. Gradle Wrapper를 사용하는 이유는 무엇인가요?

개발자와 CI 서버가 프로젝트에서 지정한 동일한 Gradle 버전을 사용하도록 하기 위해서입니다.

Q8. Public Repository를 Clone하면 Push도 가능한가요?

아닙니다. Public은 읽기 권한이 공개된다는 의미이며, Push에는 별도의 쓰기 권한이 필요합니다.

Q9. Fork와 Clone의 차이는 무엇인가요?

Fork는 다른 사용자의 GitHub 저장소를 내 GitHub 계정으로 복사하는 작업이고, Clone은 저장소를 내 컴퓨터로 복제하는 작업입니다.

Q10. Clone 후 프로젝트가 실행되지 않는 이유는 무엇인가요?

Clone은 저장소 복제만 보장합니다. 실행에는 JDK, Gradle, Dependency, 환경 변수, DB와 외부 서비스 설정이 추가로 필요할 수 있습니다.
