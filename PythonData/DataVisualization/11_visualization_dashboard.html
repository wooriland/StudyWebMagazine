시각화 설계와 최종 대시보드 Question · Graph Choice · Layout · Title · Unit · Accessibility · Save

이번 단원은 지금까지 공부한 Line, Bar, Scatter, Pie, Histogram, KDE, Boxplot, Heatmap과 Seaborn의 Statistical Plot을 하나의 분석 화면으로 통합하는 마지막 단계입니다. 단순히 그래프를 많이 배치하는 것이 아니라, 분석 질문에 적합한 그래프를 고르고, 제목·단위·축·범례·색상·배치를 정리하고, 왜곡과 접근성 문제를 검토한 뒤, 여러 그래프의 Observation을 연결하여 새로운 Insight를 만드는 것 이 목표입니다.

최종 시각화 원칙 Question First → Graph Choice → Honest Design → Insight
Data → Question → Graph → Figure / Axes → Design → Check → Save → Insight
가장 중요한 기억

Dashboard는 그래프가 많은 화면이 아니라, 하나의 분석 목적을 여러 질문으로 나누고 각각의 질문에 가장 적합한 그래프를 의도적으로 배치한 분석 구조입니다. 한 Panel에는 하나의 핵심 질문을 두고, 여러 Panel의 Observation을 서로 연결해 다음 Hypothesis를 만들어야 합니다.

시간 변화 Line
범주 비교 Bar
수치 관계 Scatter
한 변수 분포 Histogram / KDE
범주별 분포 Boxplot
여러 변수 관계 Heatmap

학습 목표

  • Dashboard가 단순한 그래프 모음이 아니라 분석 질문을 구조화한 Figure라는 것을 설명할 수 있다.
  • Figure, Axes, Plot, Axis의 계층을 Dashboard 구조와 연결할 수 있다.
  • Panel별 분석 질문에 따라 Line, Bar, Scatter, Histogram, Boxplot, Heatmap 등을 올바르게 선택할 수 있다.
  • Figure 전체 제목과 개별 Axes 제목의 역할을 구분할 수 있다.
  • X/Y Label에 단위를 명확하게 표시할 수 있다.
  • Legend가 필요한 경우와 불필요한 경우를 구분할 수 있다.
  • Tick Label이 지나치게 많거나 길 때 회전·간격·요약을 적용할 수 있다.
  • Grid가 데이터 읽기를 돕는 보조 요소임을 설명할 수 있다.
  • Axis Range를 변경해도 Raw Data는 변하지 않는다는 것을 이해한다.
  • Bar Chart에서 축을 과도하게 잘라 값의 차이를 과장하면 안 되는 이유를 설명할 수 있다.
  • Line Chart와 Bar Chart의 Axis Baseline 설계 차이를 설명할 수 있다.
  • 같은 Metric의 여러 Panel을 직접 비교할 때 Unit과 Scale 일관성이 중요한 이유를 설명할 수 있다.
  • Log Scale을 사용할 경우 명확하게 표시해야 하는 이유를 설명할 수 있다.
  • 여러 Axes가 있는 Figure의 적절한 figsize를 결정할 수 있다.
  • 현재 Matplotlib의 layout="constrained"를 학습 보완 개념으로 이해한다.
  • Korean Glyph를 지원하는 Font를 Matplotlib에 적용할 수 있다.
  • axes.unicode_minus와 Korean Font 설정의 역할 차이를 이해한다.
  • savefig()를 사용해 Dashboard를 이미지로 저장할 수 있다.
  • 저장한 결과 파일을 다시 열어 잘림·Font·DPI를 점검할 수 있다.
  • 색상만으로 정보를 구분하지 않고 Marker·Line Style·Text를 함께 사용할 수 있다.
  • Dashboard 전체에서 같은 Category가 같은 Visual Meaning을 유지하도록 설계할 수 있다.
  • 기간, Filter, Sample, Unit을 숨기지 않아야 하는 이유를 설명할 수 있다.
  • Observation, Hypothesis, Causal Conclusion을 구분할 수 있다.
  • Dashboard의 여러 Observation을 연결하여 새로운 분석 질문을 만들 수 있다.

01 · Core Concept

핵심 개념 — Dashboard는 Figure와 Axes를 이용한 분석 설계다

첨부 교안에서 Figure는 전체 도화지, Axes는 그 안의 개별 그래프 칸, Plot은 실제 Line·Bar·Scatter 같은 그래프, Axis는 X·Y축과 눈금·Label을 담당합니다. 이번 단원에서는 이 구조를 그대로 확장하여 Figure를 Dashboard, Axes를 Dashboard Panel 로 이해합니다.

Figure / Axes / Plot / Axis → Dashboard

Axis Scale · Tick · Label

값을 읽는 좌표 체계를 제공합니다.

One Panel → One Main Question

하나의 Axes 안에서 너무 많은 질문을 동시에 해결하려고 하지 않습니다. 시간 변화, 범주 비교, 관계, 분포, 상관관계는 서로 다른 Panel로 분리하고, Dashboard 전체에서 서로 보완하도록 구성합니다.

Dashboard 왜곡 방지 원칙

01 Wrong Graph

질문과 맞지 않는 그래프를 쓰지 않는다.

02 Hidden Unit

숫자의 단위를 숨기지 않는다.

03 Truncated Bar Axis

Bar 차이를 과장하지 않는다.

04 Hidden Period

분석 기간을 명시한다.

05 Sample vs Population

표본 결과를 전체처럼 말하지 않는다.

06 Hidden Filter

Top-N 등 필터 조건을 표시한다.

07 Hidden Log Scale

로그 축 사용을 숨기지 않는다.

08 Scale Consistency

직접 비교 Panel의 Scale을 점검한다.

09 Color Only

색상만으로 정보를 전달하지 않는다.

10 Decoration

3D·Shadow가 Data를 방해하지 않게 한다.

예제 3 · Korean Font 설정 현재 실무 보완 

import matplotlib.pyplot as plt
import matplotlib.font_manager as fm


installed_fonts = set(
    fm.get_font_names()
)


font_candidates = [
    "Malgun Gothic",
    "Noto Sans CJK KR",
    "AppleGothic"
]


for font_name in font_candidates:
    if font_name in installed_fonts:
        plt.rcParams[
            "font.family"
        ] = font_name

        break


plt.rcParams[
    "axes.unicode_minus"
] = False

07 · Interview

면접 포인트

Q1. Dashboard란 무엇입니까?

하나의 분석 목적을 여러 질문으로 나누고, 각 질문에 적합한 그래프를 하나의 Figure 안에 의도적으로 배치하여 여러 관점의 정보를 함께 해석할 수 있도록 구성한 분석 화면입니다.

Q2. Figure와 Dashboard는 어떻게 연결됩니까?

Figure는 전체 Dashboard 화면으로, 각 Axes는 Dashboard의 개별 Panel로 이해할 수 있습니다.

Q3. Dashboard 설계의 첫 단계는 무엇입니까?

Graph를 고르는 것이 아니라 분석 목적과 질문을 정의하는 것입니다.

Q4. 그래프 선택 기준은 무엇입니까?

데이터 유형과 질문을 함께 봅니다. 시간 변화는 Line, 범주 비교는 Bar, 수치 관계는 Scatter, 분포는 Histogram/KDE, 범주별 분포는 Boxplot, 여러 변수 상관관계는 Heatmap을 고려합니다.

Q5. Figure Title과 Axes Title의 차이는?

Figure Title은 Dashboard 전체 목적, Axes Title은 해당 Panel이 답하는 개별 질문을 나타냅니다.

Q6. Unit이 중요한 이유는?

500이라는 숫자만으로는 원·만원·명·건 중 어떤 의미인지 알 수 없기 때문입니다.

Q7. Legend는 언제 필요합니까?

하나의 Axes 안에 여러 Series나 Category가 있어 색·Marker·Line Style의 의미를 설명해야 할 때 사용합니다.

Q8. Axis Range를 바꾸면 데이터도 바뀝니까?

아닙니다. Raw Data는 그대로이고 화면에 보이는 View Range만 변경됩니다.

Q9. Bar Chart에서 Zero Baseline이 중요한 이유는?

막대 길이 자체가 수치를 표현하므로 축을 과도하게 잘라 시작하면 작은 차이가 실제보다 크게 보일 수 있기 때문입니다.

Q10. Line Chart도 항상 0부터 시작해야 합니까?

반드시 그렇지는 않습니다. 작은 변화 자체가 분석 목적이라면 합리적인 범위로 조정할 수 있지만 축 범위를 독자가 분명히 볼 수 있어야 합니다.

Q11. 여러 Panel의 Scale을 맞추는 이유는?

같은 Metric을 직접 비교할 때 Panel의 높이나 선 위치를 시각적으로 정확하게 비교하기 위해서입니다.

Q12. Log Scale을 사용할 때 주의할 점은?

Linear Scale과 해석 방법이 다르므로 Log Scale을 사용했다는 사실을 명확하게 표시해야 합니다.

Q13. 한글이 깨지는 이유는 무엇입니까?

현재 선택된 Font가 Korean Glyph를 지원하지 않을 수 있기 때문입니다. 시스템에 실제 설치된 Korean 지원 Font를 확인합니다.

Q14. axes.unicode_minus는 한글 Font 설정입니까?

아닙니다. 음수 기호 표시와 관련된 설정으로 Korean Glyph 지원과는 별개입니다.

Q15. savefig()는 무엇입니까?

완성한 Figure를 PNG, PDF, SVG 등의 파일로 저장하기 위한 기능입니다.

Q16. bbox_inches="tight"는 왜 사용합니까?

저장할 Figure의 Bounding Box를 내용에 맞춰 계산하여 주변 여백이나 잘림 문제를 줄이는 데 활용할 수 있습니다.

Q17. 색상만으로 Group을 구분하면 왜 문제입니까?

색상을 구분하기 어려운 환경이나 사용자에게 정보 자체가 전달되지 않을 수 있기 때문입니다. Marker·Line Style·Text Label 등을 함께 사용합니다.

Q18. Dashboard 왜곡의 대표 사례는?

과도하게 잘린 Bar Axis, 숨겨진 Log Scale, 서로 다른 Scale의 직접 비교, 기간·단위·Filter 미표시, 일부 Category만 선택하면서 조건을 숨기는 경우 등이 있습니다.

Q19. Correlation이 높으면 Cause입니까?

아닙니다. 상관관계는 관계의 단서이며 인과관계 증명이 아닙니다.

Q20. Dashboard가 분석의 마지막 단계입니까?

아닙니다. 여러 Observation을 연결해 새로운 Hypothesis와 추가 분석 질문을 만드는 도구이기도 합니다.

Q21. 좋은 Dashboard의 핵심 원칙은?

Question First, 적절한 Graph Choice, 명확한 Title·Unit, 정직한 Axis, 일관된 Visual Encoding, 접근성, 분석 Context, 저장 결과 검증입니다.

Q22. Monitoring Dashboard와 Analysis Dashboard 차이는?

Monitoring은 지금 시스템 상태가 정상인지 빠르게 확인하는 데 초점이 있고, Analysis Dashboard는 왜 그런 Pattern이 생겼는지 관계와 원인 후보를 탐색하는 데 초점이 있습니다.

오늘의 암기 포인트

  • Dashboard = Question + Multiple Views
  • Figure는 Dashboard 전체, Axes는 개별 Panel이다.
  • 한 Panel에는 하나의 핵심 질문을 둔다.
  • Question을 먼저 정의하고 Graph를 선택한다.
  • Time → Line.
  • Category Comparison → Bar.
  • Numerical + Numerical → Scatter.
  • Distribution → Histogram / KDE.
  • Category Distribution → Boxplot.
  • Multiple Correlation → Heatmap.
  • Figure Title은 전체 목적, Axes Title은 Panel 질문이다.
  • 숫자에는 반드시 Unit을 확인한다.
  • Legend는 여러 Series를 구분할 필요가 있을 때 사용한다.
  • Axis Range는 View만 변경한다.
  • Bar Chart는 Zero Baseline을 특히 주의한다.
  • 같은 Metric을 직접 비교하면 Unit과 Scale을 맞출지 검토한다.
  • Log Scale은 숨기지 않는다.
  • Korean Glyph를 지원하는 Font가 필요하다.
  • axes.unicode_minus는 한글 Font 설정이 아니다.
  • Color에만 의존하지 않는다.
  • Marker·Line Style·Text를 함께 사용한다.
  • Period·Filter·Sample을 명확히 한다.
  • Dashboard 저장 후 최종 파일도 다시 확인한다.
  • Observation과 Causal Conclusion을 구분한다.
  • Dashboard는 새로운 질문을 만드는 도구다.
