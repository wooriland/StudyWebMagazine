Data Analysis · Lesson 14 · Pandas Concat · Merge · GroupBy

Pandas 데이터 결합과 그룹화

실제 데이터 분석에서는 모든 정보가 하나의 DataFrame 안에 들어 있지 않습니다. 월별 CSV는 여러 파일로 나뉘고, 고객·주문·상품 정보는 서로 다른 Table에 저장되며, 분석 단계에서는 같은 지역·고객·카테고리끼리 다시 묶어서 합계와 평균을 계산해야 합니다. 이번 단원에서는 pd.concat()으로 여러 데이터 조각을 축 방향으로 연결하고, pd.merge()로 공통 Key를 기준으로 SQL JOIN과 유사한 관계형 결합을 수행하며, groupby()의 Split → Apply → Combine 흐름을 이용해 그룹별 분석 결과를 만드는 방법 을 공부합니다.

01 · Core Concept

여러 데이터 조각을 하나의 분석 Dataset으로 만든다

이번 단원에서는 하나의 DataFrame 내부를 처리하는 관점에서 벗어나 여러 DataFrame 사이의 관계를 다룹니다. 핵심은 “그냥 이어 붙이는가?”, “Key로 연결하는가?”, “같은 Key끼리 묶어 계산하는가?” 를 구분하는 것입니다.

Combine · Join · Aggregate

Concat은 여러 객체를 축 방향으로 이어 붙이는 작업, Merge는 관계형 Key를 기준으로 서로 다른 정보를 연결하는 작업, GroupBy는 같은 기준을 가진 Row를 그룹화한 뒤 각 그룹을 대표하는 분석값으로 요약하는 작업입니다.

CONCAT 이어 붙인다 pd.concat()

월별 파일처럼 같은 구조의 데이터 조각을 연결합니다.

MERGE Key를 맞춘다 pd.merge()

고객·주문처럼 서로 다른 정보를 관계 Key로 연결합니다.

GROUPBY 같은 값을 묶는다 groupby()

지역·카테고리별로 Row를 묶어 통계를 계산합니다.

5초 판정 공식
그냥 붙이는가? concat
Key를 비교하는가? merge
같은 Key끼리 계산하는가? groupby

07 · Concat Join

axis와 join은 서로 다른 질문이다

JOIN 반대 축 Label을 어떻게 맞추는가? join="outer" join="inner"
OUTER join="outer"

concat의 join과 SQL JOIN은 다른 문맥

pd.concat(..., join="inner")는 반대 축의 Label 집합을 교집합으로 맞추는 것이고, pd.merge(..., how="inner")는 Join Key가 양쪽에 존재하는 Row를 연결하는 것입니다.

import numpy as np
import pandas as pd


def show_state(name, obj):
    print()
    print("=" * 80)
    print(name)
    print("=" * 80)

    print(obj)

    print()
    print("type:", type(obj))

    if hasattr(obj, "shape"):
        print("shape:", obj.shape)

    if isinstance(obj, pd.DataFrame):
        print()
        print("index:")
        print(obj.index)

        print()
        print("columns:")
        print(obj.columns)

        print()
        print("dtypes:")
        print(obj.dtypes)

        print()
        print("missing:")
        print(obj.isna().sum())


def inspect_key(df, key):
    print()
    print("-" * 80)

    print("KEY:", key)

    print(
        "dtype:",
        df[key].dtype
    )

    print(
        "missing:",
        df[key].isna().sum()
    )

    print(
        "duplicates:",
        df[key].duplicated().sum()
    )

    print(
        "unique:",
        df[key].nunique(
            dropna=False
        )
    )

25 · Common Mistakes

초보자가 자주 하는 실수

Mistake 01

concat과 merge를 같은 기능이라고 생각한다

concat은 Axis, merge는 Key가 핵심입니다.

Mistake 02

같은 구조의 월별 파일을 불필요하게 merge한다

같은 Schema를 이어 붙이는 작업은 concat이 자연스럽습니다.

Mistake 03

고객 Table과 주문 Table을 단순 concat한다

관계 Key가 있다면 merge가 더 적절합니다.

Mistake 04

concat 후 Index가 자동 재설정된다고 생각한다

기본적으로 기존 Index를 유지합니다.

Mistake 05

concat(axis=1)이 단순 위치 결합이라고 생각한다

Index Label Alignment를 먼저 생각해야 합니다.

Mistake 06

concat join과 SQL JOIN을 같은 의미로 이해한다

concat join은 반대 축 Label 집합에 대한 규칙입니다.

Mistake 07

교안의 DataFrame.append()를 그대로 사용한다

현재 학습에서는 pd.concat()으로 연결합니다.

Mistake 08

Merge Key 이름만 보고 바로 결합한다

dtype·Missing·Duplicate도 확인합니다.

Mistake 09

문자열 Join Key를 정규화하지 않는다

공백·대소문자 차이가 Join 실패의 원인이 될 수 있습니다.

Mistake 10

INNER JOIN이 모든 Row를 유지한다고 생각한다

양쪽에 공통으로 존재하는 Key 중심입니다.

Mistake 11

LEFT JOIN을 왼쪽 Column만 남기는 것으로 이해한다

왼쪽 Key를 모두 유지하고 오른쪽 정보를 연결합니다.

Mistake 12

Merge 결과 Row 수가 항상 Left와 같다고 생각한다

1:N 관계에서는 Row가 증가할 수 있습니다.

Mistake 13

N:N Merge를 모르고 실행한다

양쪽 중복 Key 조합으로 Row가 크게 증가할 수 있습니다.

Mistake 14

validate 없이 관계를 추측만 한다

기대 관계를 코드로 명시하면 데이터 오류를 빨리 찾을 수 있습니다.

Mistake 15

Merge 결과를 눈으로만 검증한다

indicator와 shape를 함께 확인합니다.

Mistake 16

Pandas와 SQL의 Null Join 동작이 완전히 같다고 생각한다

Pandas에서는 Null Key끼리 매칭될 수 있습니다.

Mistake 17

status_x와 status_y의 의미를 확인하지 않는다

suffixes로 출처를 명확하게 만들 수 있습니다.

Mistake 18

groupby()만 실행하면 집계가 끝났다고 생각한다

GroupBy 객체를 만든 뒤 Aggregation이 필요합니다.

Mistake 19

Group Key와 계산 Column을 구분하지 않는다

하나는 그룹 기준, 다른 하나는 실제 집계 대상입니다.

Mistake 20

size()와 count()를 같은 것으로 생각한다

Row 수와 non-NA 수를 구분합니다.

Mistake 21

Group Key NaN이 사라진 것을 오류라고 생각한다

기본 dropna 동작을 확인합니다.

Mistake 22

as_index 기본값을 모르고 결과 구조를 헷갈린다

SQL형 표가 필요하면 as_index=False를 고려합니다.

Mistake 23

여러 Group Key를 독립 그룹으로 이해한다

Key 값의 조합 하나가 하나의 그룹입니다.

Mistake 24

단순 그룹 합계에도 GroupBy.apply()부터 사용한다

sum, mean, agg 같은 기본 연산을 먼저 생각합니다.

Mistake 25

GroupBy 결과 정렬을 생각하지 않는다

집계 후 sort_values()로 Ranking을 만들 수 있습니다.

28 · Interview

면접 포인트

Q1. pd.concat()은 무엇인가요?
A. 여러 Series 또는 DataFrame을 지정한 axis를 따라 이어 붙이는 함수입니다.
Q2. concat의 axis=0과 axis=1 차이는?
A. axis=0은 Row 방향, axis=1은 Column 방향 결합입니다.
Q3. ignore_index=True는 무엇인가요?
A. concat하는 축의 기존 Label 대신 새로운 0부터 n-1까지의 Label을 사용합니다.
Q4. concat의 outer와 inner 차이는?
A. concat하지 않는 반대 축의 Label을 outer는 합집합, inner는 교집합으로 처리합니다.
Q5. concat과 merge 차이는?
A. concat은 Axis 기반 연결, merge는 Join Key 기반 관계형 연결입니다.
Q6. 현재 DataFrame.append()를 사용하나요?
A. 현재 학습에서는 제거된 append 대신 pd.concat()을 사용합니다.
Q7. pd.merge()의 기본 Join은?
A. 기본적으로 Inner Join입니다.
Q8. INNER JOIN은 무엇인가요?
A. 양쪽 DataFrame에 공통으로 존재하는 Join Key 중심으로 결과를 만듭니다.
Q9. LEFT JOIN은 무엇인가요?
A. 왼쪽 Key를 모두 유지하고 오른쪽의 일치하는 정보를 연결합니다.
Q10. OUTER JOIN은 무엇인가요?
A. 양쪽 Join Key의 합집합을 유지하는 Join입니다.
Q11. on과 left_on/right_on 차이는?
A. 같은 이름의 Key를 사용할 때는 on, 서로 다른 Key 이름이면 left_on과 right_on을 사용합니다.
Q12. Pandas Merge와 SQL JOIN은 완전히 같은가요?
A. 관계형 개념은 매우 유사하지만 Pandas에서는 양쪽 Null Key가 서로 매칭될 수 있는 등 세부 차이가 있습니다.
Q13. 1:N Merge란?
A. 한쪽 Key는 하나지만 다른 쪽에 같은 Key의 Row가 여러 개 있는 관계입니다.
Q14. N:N Merge가 위험한 이유는?
A. 양쪽에서 같은 Key가 여러 번 나타나면 조합 수만큼 결과 Row가 크게 증가할 수 있기 때문입니다.
Q15. validate는 무엇인가요?
A. Join Key 관계가 1:1·1:N·N:1 같은 기대 관계와 일치하는지 검사하는 옵션입니다.
Q16. indicator=True는 무엇인가요?
A. Merge 결과에 각 Row가 left_only, right_only, both 중 어디에서 왔는지 나타내는 Column을 추가합니다.
Q17. GroupBy란 무엇인가요?
A. 데이터를 Key에 따라 Split하고, 각 Group에 함수를 Apply한 뒤 결과를 Combine하는 과정입니다.
Q18. groupby()만 호출하면 계산 결과인가요?
A. 아닙니다. Group 정보를 가진 GroupBy 객체를 만든 것이며 이후 sum, mean, agg 등의 연산이 필요합니다.
Q19. as_index=False는 무엇인가요?
A. Group Key를 결과 Index가 아닌 일반 Column 형태로 유지합니다.
Q20. size()와 count() 차이는?
A. size는 Group의 Row 수, count는 선택한 Column의 non-NA 값 개수입니다.
Q21. Group Key가 NaN이면 어떻게 되나요?
A. 기본 GroupBy에서는 NA Key가 제외될 수 있으며 dropna=False로 NA도 하나의 그룹으로 포함할 수 있습니다.
Q22. 여러 Column으로 GroupBy할 수 있나요?
A. 가능합니다. 여러 Column 값의 조합을 하나의 Group Key로 사용할 수 있습니다.
Q23. agg()는 무엇인가요?
A. 각 Group에 합계·평균·개수 등 하나 이상의 Aggregation을 적용하는 기능입니다.
Q24. GroupBy 결과의 Row 수가 원본보다 적어지는 이유는?
A. 여러 원본 Row가 같은 Group에 속하고, Aggregation 결과에서는 한 Group이 하나의 Summary Row로 축약되기 때문입니다.

  • concat = Axis 기반 결합
  • merge = Key 기반 결합
  • groupby = 같은 Key끼리 묶어 계산
  • concat axis=0은 Row 방향이다.
  • concat axis=1은 Column 방향이다.
  • axis=1에서는 Index Alignment를 확인한다.
  • concat outer는 반대 축 Label 합집합이다.
  • concat inner는 반대 축 Label 교집합이다.
  • ignore_index=True는 concat 축 Label을 새로 만든다.
  • 현재 Pandas에서는 과거 append 대신 concat을 사용한다.
  • Merge 기본 Join은 Inner다.
  • INNER = 공통 Key다.
  • LEFT = Left Key 전체다.
  • RIGHT = Right Key 전체다.
  • OUTER = 양쪽 Key 합집합이다.
  • 같은 Key 이름은 on, 다른 이름은 left_on/right_on이다.
  • Merge에서는 Key dtype을 확인한다.
  • Merge에서는 Key Missing을 확인한다.
  • Merge에서는 Key Duplicate를 확인한다.
  • 1:1 · 1:N · N:1 · N:N 관계를 먼저 생각한다.
  • N:N Merge는 Row가 크게 늘어날 수 있다.
  • validate는 관계 검증이다.
  • indicator는 Join 출처 검증이다.
  • Pandas Null Join은 SQL과 세부 동작이 다를 수 있다.
  • GroupBy는 Split → Apply → Combine이다.
  • groupby()만 호출하면 아직 계산 전이다.
  • size()는 Row 수다.
  • count()는 non-NA 수다.
  • as_index=False는 Group Key를 일반 Column으로 만든다.
  • Group Key Missing과 Value Missing은 다르다.
  • GroupBy 결과도 필요하면 sort_values()한다.

헷갈리기 쉬운 개념

concat ≠ merge

Axis 기반 연결과 Key 기반 관계 연결의 차이입니다.

concat join ≠ SQL JOIN

하나는 반대 축 Label, 하나는 관계 Key를 다룹니다.

axis=1 ≠ 위치 기반 단순 결합

Index Alignment를 먼저 확인합니다.

LEFT JOIN ≠ 왼쪽 Column만 유지

왼쪽 Key 전체를 유지하고 오른쪽 정보를 붙입니다.

INNER JOIN ≠ 모든 Row 유지

양쪽 공통 Key 중심입니다.

Merge shape ≠ 입력 Row 수 단순 합

Join 관계와 Key 중복이 결과 Row를 결정합니다.

1:N ≠ N:N

N:N은 양쪽 모두 중복 Key를 가질 수 있습니다.

groupby() ≠ 집계 완료

GroupBy Object를 만든 뒤 Aggregation이 필요합니다.

size ≠ count

Row 수와 non-NA 값 수를 구분합니다.

Group Key Missing ≠ Value Missing

전자는 그룹 생성, 후자는 집계 함수의 Missing 처리와 관련됩니다.

DataFrame.apply ≠ GroupBy.apply

Row/Column 단위와 Group 단위를 구분합니다.
