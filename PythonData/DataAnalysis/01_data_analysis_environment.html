01 · Core Concept

데이터 분석 환경은 무엇으로 구성되는가?

데이터 분석 환경은 단순히 Python 프로그램 하나를 설치한 상태가 아닙니다. 실제 분석 코드를 실행하려면 Python Interpreter, 분석 라이브러리, 독립 Environment, Package 관리 도구, 그리고 코드를 실행할 Jupyter 또는 PyCharm이 서로 연결되어 있어야 합니다.

데이터 분석 환경

분석에 사용할 Python Interpreter와 필요한 Package를 하나의 독립적인 Environment 안에 준비하고, Jupyter Notebook이나 PyCharm이 그 Interpreter를 사용하도록 연결한 실행 환경입니다.

05 · Package Management

Conda와 pip를 어떻게 구분할까?

첨부 교안은 Conda와 pip를 패키지 지원 범위, 의존성 관리, 가상환경 관리, 패키지 저장소 관점에서 비교합니다. 초보 단계에서는 다음 차이를 먼저 이해하면 됩니다.

Conda

  • Environment 생성·관리 가능
  • Package 설치·업데이트·삭제 가능
  • 데이터 분석 환경 전체를 관리하는 데 사용
  • Conda 채널을 통한 패키지 관리 
conda install pandas

pip

  • Python Package 설치 도구
  • Python Package Index 계열의 패키지 사용
  • Conda Environment 안에서도 사용할 수 있음
  • 실행 중인 Python 환경이 어디인지 확인 필요 
pip install ipykernel
설치 명령보다 먼저 확인할 것

conda를 사용했는지 pip를 사용했는지뿐 아니라 그 명령을 어느 Environment에서 실행했는가 가 중요합니다.

07 · Python Environment Test

Python 코드로 환경 연결 확인하기

이번 단원의 Python 코드는 복잡한 분석을 수행하는 것이 목적이 아닙니다. 현재 Interpreter와 분석 라이브러리가 올바르게 연결되어 있는지 확인하는 것 이 목적입니다. 

import sys

import numpy as np
import pandas as pd
import scipy
import matplotlib


# --------------------------------------------------
# 1. 현재 Python Interpreter 확인
# --------------------------------------------------
print("================================")
print("1. Python Interpreter")
print("================================")

print(sys.executable)


# --------------------------------------------------
# 2. 분석 Library 확인
# --------------------------------------------------
print("\n================================")
print("2. Library Version")
print("================================")

print("NumPy      :", np.__version__)
print("Pandas     :", pd.__version__)
print("SciPy      :", scipy.__version__)
print("Matplotlib :", matplotlib.__version__)


# --------------------------------------------------
# 3. NumPy 간단 환경 테스트
# --------------------------------------------------
print("\n================================")
print("3. NumPy Test")
print("================================")

scores = np.array([
    [80, 90, 70],
    [75, 85, 95]
])

print(scores)
print("shape :", scores.shape)
print("dtype :", scores.dtype)


# --------------------------------------------------
# 4. Pandas 간단 환경 테스트
# --------------------------------------------------
print("\n================================")
print("4. Pandas Test")
print("================================")

data = {
    "name": [
        "Kim",
        "Lee",
        "Park"
    ],
    "score": [
        80,
        90,
        None
    ]
}

df = pd.DataFrame(data)

print(df)


# --------------------------------------------------
# 5. DataFrame 상태 확인
# --------------------------------------------------
print("\nshape")
print(df.shape)

print("\ndtypes")
print(df.dtypes)

print("\nmissing values")
print(df.isna().sum())

코드를 어떤 순서로 읽어야 하는가?

01 Interpreter 확인 sys.executable
→
02 Package import NumPy / Pandas
→
03 NumPy 테스트 ndarray
→
04 Pandas 테스트 DataFrame
→
05 데이터 상태 확인 shape / dtype / NaN

예상되는 데이터 상태

NumPy 

[[80 90 70]
 [75 85 95]]

shape
(2, 3)

2행 3열의 배열이 만들어졌음을 확인합니다.

Pandas 

   name  score
0   Kim   80.0
1   Lee   90.0
2  Park    NaN

shape
(3, 2)

3행 2열이며 score에 결측치가 하나 있습니다.

이번 단원에서 shape·dtype·결측치가 변하는가?

shape 확인만 수행 (3, 2) → (3, 2)
dtype 확인만 수행 변경 없음
결측치 확인만 수행 1개 → 1개
axis 다음 NumPy 단원에서 심화 axis 0 / axis 1

shape, dtypes, isna()처럼 데이터를 확인하는 작업과, 실제 데이터를 변경하는 작업은 구분해야 합니다.

08 · Common Mistakes

초보자가 실제로 자주 하는 실수

Mistake 01

base와 data_analysis를 구분하지 않는다 

(base) C:\Users\user>

프롬프트 앞의 Environment 이름을 항상 확인합니다.

Mistake 02

Environment를 만들면 자동으로 사용하는 줄 안다 

conda create -n data_analysis python

생성 후 별도로 conda activate data_analysis가 필요합니다.

Mistake 03

설치된 Python이 모두 같은 Python이라고 생각한다

System Python, base Python, data_analysis Python이 서로 다를 수 있습니다. 

import sys
print(sys.executable)
Mistake 04

Jupyter를 Python 자체라고 생각한다

Jupyter는 실행 UI이며 실제 Python 코드는 Kernel을 통해 실행됩니다.

Mistake 05

Conda Environment와 Kernel을 같은 개념으로 본다

Environment는 Python과 Package가 있는 실행 공간이고, Kernel은 Notebook 코드 실행 엔진입니다.

Mistake 06

Kernel 이름만 보고 올바른 환경이라고 생각한다

의심스러우면 sys.executable로 실제 Python을 확인합니다.

Mistake 07

PyCharm이 Conda 환경을 자동으로 사용할 것이라 생각한다

프로젝트의 Python Interpreter가 어느 환경을 가리키는지 반드시 확인합니다.

Mistake 08

Conda 명령과 Python 코드를 섞는다 

# Prompt
conda activate data_analysis

# Python
import pandas as pd
Mistake 09

import가 성공하면 환경도 무조건 맞다고 생각한다

다른 환경에도 동일 Package가 설치되어 있을 수 있으므로 Interpreter 위치까지 확인합니다.

Mistake 10

Jupyter Cell의 화면 순서와 실행 순서를 동일하게 본다

Notebook에서는 Cell을 임의 순서로 실행할 수 있으므로 최종적으로 Restart → Run All을 확인합니다.

09 · Error Reading

환경 관련 오류 메시지 읽는 법

이번 단원에서 오류가 발생하면 데이터를 먼저 의심하기보다 Environment → Interpreter → Package → Kernel 연결을 먼저 확인하는 것이 좋습니다.

1 Environment 지금 어느 환경인가?
→
2 Interpreter 누가 Python을 실행하는가?
→
3 Package 필요한 라이브러리가 있는가?
→
4 Kernel Notebook은 어떤 환경인가?
→
5 Data 그 다음 데이터 문제를 본다.
오류 의미 먼저 확인할 것
ModuleNotFoundError 현재 Python에서 해당 모듈을 찾지 못함 Environment, Interpreter, Package 설치 위치, Kernel
NameError 사용한 이름이 정의되지 않음 import Cell 실행 여부, 변수 선언 여부
SyntaxError Python 문법이 올바르지 않음 괄호, 따옴표, 콜론, 들여쓰기
FileNotFoundError 읽으려는 파일을 찾지 못함 파일명, 현재 작업 경로, 상대·절대경로
ImportError Module 또는 특정 기능 import 과정 문제 Package, 버전, 현재 Interpreter

ModuleNotFoundError를 만났을 때 

import pandas as pd

ModuleNotFoundError:
No module named 'pandas'
  1. Prompt가 (data_analysis)인가?
  2. conda list에 pandas가 존재하는가?
  3. Python에서 sys.executable은 어느 경로인가?
  4. Jupyter라면 현재 Kernel은 무엇인가?
  5. PyCharm이라면 Project Interpreter는 무엇인가?

면접 포인트

Q1. Anaconda란 무엇인가요?
A. Python 데이터 분석 환경을 구성하기 편하도록 Python, Conda 및 여러 분석 관련 도구를 함께 관리할 수 있도록 제공하는 Python 배포 환경으로 이해할 수 있습니다.
Q2. Conda란 무엇인가요?
A. Conda는 Environment를 만들고 Package를 설치·업데이트·삭제하는 환경 및 패키지 관리 도구입니다.
Q3. Anaconda와 Conda의 차이는 무엇인가요?
A. Anaconda는 데이터 분석을 위한 더 큰 Python 배포 환경이고, Conda는 그 환경에서 Environment와 Package를 관리하는 도구입니다.
Q4. Conda Environment를 왜 사용하나요?
A. 프로젝트마다 필요한 Python과 Package 구성을 독립적으로 관리하고, 다른 프로젝트와의 의존성 충돌을 줄이기 위해 사용합니다.
Q5. base 환경이란 무엇인가요?
A. Anaconda의 기본 Conda Environment입니다. Prompt에 (base)가 표시되면 현재 base 환경이 활성화된 상태입니다.
Q6. conda create와 conda activate의 차이는?
A. create는 새로운 Environment를 만들고, activate는 존재하는 Environment를 현재 실행 환경으로 전환합니다.
Q7. Python Interpreter란 무엇인가요?
A. Python 코드를 실제로 해석하고 실행하는 프로그램입니다. 서로 다른 Conda Environment는 서로 다른 Python Interpreter를 사용할 수 있습니다.
Q8. Jupyter Notebook은 Python인가요?
A. 아닙니다. Jupyter Notebook은 코드를 작성하고 실행 결과를 확인하는 대화형 인터페이스이고, 실제 Python 코드는 Kernel을 통해 실행됩니다.
Q9. Kernel이란 무엇인가요?
A. Jupyter Notebook에서 작성한 코드를 실제로 실행하는 계산 엔진입니다.
Q10. ipykernel은 어떤 역할을 하나요?
A. 특정 Python Environment를 Jupyter에서 Python Kernel로 사용할 수 있도록 연결하는 역할을 합니다.
Q11. --name과 --display-name의 차이는 무엇인가요?
A. --name은 Kernel의 내부 식별 이름이고, --display-name은 Jupyter 화면에서 사용자에게 보여줄 이름입니다.
Q12. NumPy와 Pandas의 차이는 무엇인가요?
A. NumPy는 ndarray 기반의 배열·수치 계산을 담당하고, Pandas는 Series와 DataFrame을 이용해 표 형태 데이터를 처리합니다.
Q13. Jupyter와 PyCharm의 차이는 무엇인가요?
A. Jupyter는 Cell 단위의 탐색적 데이터 분석에 적합하고, PyCharm은 Python 파일·함수·모듈을 이용해 프로그램을 구조화하는 데 적합합니다.
Q14. pandas를 설치했는데 ModuleNotFoundError가 발생한다면?
A. 먼저 현재 Python Interpreter가 어느 Environment에 있는지, 해당 Environment에 pandas가 설치되어 있는지, Jupyter라면 Kernel, PyCharm이라면 Interpreter 설정이 올바른지 확인합니다.
Q15. 현재 Python Interpreter를 어떻게 확인할 수 있나요?
A. 
import sys
print(sys.executable)
로 현재 코드를 실제 실행하는 Python 경로를 확인할 수 있습니다.

오늘의 암기 포인트

  • Anaconda 는 데이터 분석 환경을 구성하기 위한 큰 Python 배포 환경이다.
  • Conda 는 Environment와 Package를 관리한다.
  • Environment는 프로젝트별 Python과 Package를 분리하는 실행 공간이다.
  • base는 Anaconda의 기본 Conda Environment이다.
  • conda create 는 환경 생성, conda activate 는 환경 전환이다.
  • Package를 설치했는가보다 어느 Environment에 설치했는가 가 중요하다.
  • Python Interpreter가 실제 Python 코드를 실행한다.
  • Jupyter Notebook은 Python 자체가 아니라 대화형 실행 인터페이스이다.
  • Jupyter의 Python 코드는 Kernel을 통해 실행된다.
  • ipykernel은 Python Environment와 Jupyter Kernel을 연결한다.
  • --name은 내부 이름, --display-name은 화면 표시 이름이다.
  • NumPy는 배열·수치 계산, Pandas는 표 데이터, Matplotlib는 시각화, SciPy는 과학·수치 계산이다.
  • 환경 오류는 Environment → Interpreter → Package → Kernel 순서로 점검한다.

헷갈리기 쉬운 개념

Anaconda ≠ Conda

Anaconda는 큰 배포 환경이고, Conda는 환경·패키지 관리 도구입니다.

create ≠ activate

create는 작업방을 만들고, activate는 그 작업방을 사용하도록 전환합니다.

Project Folder ≠ Environment

Project Folder는 코드·데이터 파일의 위치이고, Environment는 Python 실행 환경입니다.

Jupyter ≠ Python

Jupyter는 UI, Python Interpreter가 실제 코드를 실행합니다.

Environment ≠ Kernel

Environment는 Python과 Package가 있는 공간, Kernel은 Notebook 실행 엔진입니다.

Kernel 이름 ≠ 실제 Python 경로

환경 문제가 의심되면 sys.executable을 확인합니다.

conda 명령 ≠ Python 코드

Conda 명령은 Prompt에서 환경을 관리하고, Python 코드는 Interpreter에서 실행됩니다.

확인 ≠ 변경

shape, dtypes, isna()를 조회하는 것은 데이터 자체를 변경하는 작업이 아닙니다.
