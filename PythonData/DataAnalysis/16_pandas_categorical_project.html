08 · Category Structure

Category는 범주 목록과 Code의 관계로 이해한다

OBSERVED VALUES Seoul Busan Seoul Incheon
→
CATEGORIES 0 → Busan 1 → Incheon 2 → Seoul
+
CODES 2 0 2 1
Category Code는 자동으로 수학적 크기를 뜻하지 않는다

Code는 해당 값이 Category 목록의 어느 위치를 참조하는지를 표현하는 내부적인 번호로 이해합니다. 특히 명목형에서 0·1·2라는 숫자가 실제 크기 순서를 의미한다고 해석하면 안 됩니다.

→
BOOLEAN True True False True
→
FILTER Seoul Row Busan Row Seoul Row 
target = df[

13 · Encoding

범주의 의미를 훼손하지 않으면서 숫자 구조로 변환한다

CATEGORY Seoul Busan Incheon
→
SIMPLE CODE Seoul = 0 Busan = 1 Incheon = 2
명목형에 존재하지 않는 수치 순서를 만들 수 있다

도시에는 Incheon > Busan > Seoul이라는 수학적 크기 관계가 없으므로, 단순 숫자 Code를 실제 수치처럼 해석해서는 안 됩니다.

교안 직접 내용

교안은 범주형 데이터를 숫자로 변환하는 방법으로 더미 변수와 One-Hot Encoding을 소개하고, One-Hot은 0과 1로 특징의 존재 여부를 표현한다고 설명합니다.

20 · Common Mistakes

초보자가 자주 하는 실수

Mistake 01

문자열이면 모두 범주형이라고 생각한다

자유 Text와 제한된 Category를 구분합니다.

Mistake 02

GroupBy 가능한 값은 모두 범주형이라고 외운다

Column이 실제로 어떤 의미의 변수인지 먼저 판단합니다.

Mistake 03

Nominal과 Ordinal을 구분하지 않는다

순서가 의미 있는지부터 확인합니다.

Mistake 04

Ordinal을 일반 문자열 정렬한다

업무 순서를 CategoricalDtype으로 정의합니다.

Mistake 05

Ordinal Code 사이의 거리를 수치 차이로 해석한다

순서가 있다고 동일 간격이 생기는 것은 아닙니다.

Mistake 06

명목형 0·1·2가 실제 크기를 뜻한다고 생각한다

내부 Code와 실제 수치 Feature를 구분합니다.

Mistake 07

unique()가 자동 정렬된다고 생각한다

실제 등장값을 확인하는 관점으로 사용합니다.

Mistake 08

unique()와 cat.categories를 같은 것으로 생각한다

실제 등장값과 정의된 범주를 구분합니다.

Mistake 09

isin("Seoul")처럼 문자열 하나를 직접 전달한다

isin(["Seoul"])처럼 목록으로 전달합니다.

Mistake 10

isin()이 직접 Row를 반환한다고 생각한다

결과는 Boolean Mask이고 Selection이 한 단계 더 필요합니다.

Mistake 11

value_counts()가 Missing을 항상 보여준다고 생각한다

NA까지 필요하면 dropna=False를 고려합니다.

Mistake 12

normalize=True 결과를 개수라고 생각한다

normalize는 비율을 보는 방향입니다.

Mistake 13

교안의 숫자 Code 설명과 get_dummies를 같은 것으로 생각한다

하나는 하나의 Code, 다른 하나는 여러 Indicator Column입니다.

Mistake 14

One-Hot 후 shape가 그대로라고 생각한다

범주 수에 따라 Column이 증가할 수 있습니다.

Mistake 15

Missing 정책 없이 바로 Encoding한다

Missing 유지·Unknown·Indicator 중 의미를 먼저 결정합니다.

Mistake 16

Identifier까지 무조건 One-Hot한다

거의 모든 Row가 다른 ID는 Feature 의미를 먼저 검토합니다.

Mistake 17

Encoding 전에 Category 수를 확인하지 않는다

고유값이 많으면 Column 수가 과도하게 증가할 수 있습니다.

Mistake 18

CSV에 항상 Index를 같이 저장한다

단순 RangeIndex라면 index=False가 자연스러울 수 있습니다.

Mistake 19

CSV를 다시 읽으면 category가 자동 복원된다고 생각한다

dtype과 ordered 상태를 다시 확인합니다.

Mistake 20

분석 마지막에 shape·dtype·Missing을 확인하지 않는다

파일 저장 전후에도 동일한 검증 습관을 유지합니다.

24 · Interview

면접 포인트

Q1. 범주형 데이터란 무엇인가요?
A. 제한된 종류의 가능한 값 중 하나를 가지며 각 값이 분류상의 의미를 갖는 데이터입니다.
Q2. 명목형과 순서형 차이는?
A. 명목형은 범주 구분만 의미 있고 순서는 없으며, 순서형은 범주 사이의 순서에도 의미가 있습니다.
Q3. 이산형과 연속형 차이는?
A. 입문 관점에서는 이산형은 주로 세어서 얻는 수치, 연속형은 측정을 통해 연속적으로 표현할 수 있는 수치로 구분할 수 있습니다.
Q4. 문자열 Column과 범주형 Column은 같은가요?
A. 아닙니다. 자유 Text는 문자열이지만 반드시 범주형은 아니며, 제한된 종류가 분류 의미를 갖는 경우 범주형으로 해석할 수 있습니다.
Q5. Pandas에서 category dtype을 만들려면?
A. astype("category")를 사용할 수 있습니다.
Q6. 순서형 범주는 어떻게 정의하나요?
A. CategoricalDtype에 categories 순서를 지정하고 ordered=True를 설정할 수 있습니다.
Q7. cat.categories란?
A. 해당 Categorical에 정의된 전체 범주 목록을 확인합니다.
Q8. unique()는 무엇인가요?
A. 실제 Series에 등장하는 중복 없는 값들을 확인할 때 사용합니다.
Q9. unique()와 cat.categories 차이는?
A. unique는 실제 등장값, cat.categories는 정의되어 있는 전체 범주를 보는 관점입니다.
Q10. nunique()는 무엇인가요?
A. 고유한 값이 몇 종류인지 계산합니다.
Q11. isin()은 무엇인가요?
A. 각 값이 지정된 여러 후보 중 하나에 포함되는지 검사하여 Boolean Mask를 만듭니다.
Q12. value_counts()는 무엇인가요?
A. 각 고유값이 몇 번 등장하는지 빈도를 계산합니다.
Q13. normalize=True는 무엇인가요?
A. 빈도 개수 대신 각 값의 상대적인 비율을 확인할 때 사용합니다.
Q14. Missing도 value_counts 결과에 포함하려면?
A. dropna=False를 사용할 수 있습니다.
Q15. One-Hot Encoding은 무엇인가요?
A. 하나의 범주형 변수를 범주별 Indicator Column으로 펼쳐 각 범주의 존재 여부를 0/1 형태 등으로 표현하는 방법입니다.
Q16. get_dummies() 후 shape는 어떻게 되나요?
A. 일반적으로 Row 수는 유지되지만 범주별 Indicator Column이 추가되어 Column 수가 증가할 수 있습니다.
Q17. drop_first=True의 목적은?
A. k개의 Category 중 한 Indicator를 제외하고 k-1개의 Dummy Column을 생성하는 데 사용합니다.
Q18. dummy_na=True는?
A. Missing 여부도 별도의 Indicator Column으로 표현하고 싶을 때 사용할 수 있습니다.
Q19. read_csv와 to_csv 역할은?
A. read_csv는 CSV 파일을 DataFrame으로 읽고, to_csv는 DataFrame을 CSV 형식으로 저장합니다.
Q20. 왜 to_csv(index=False)를 자주 사용하나요?
A. 단순 RangeIndex가 실제 데이터가 아니라면 불필요한 Index Column이 CSV에 저장되는 것을 막기 위해 사용할 수 있습니다.
Q21. CSV를 다시 읽으면 category dtype도 자동 복원되나요?
A. 값은 다시 읽을 수 있지만 category dtype·범주 목록·순서 상태까지 자동 복원되었다고 가정하지 않고 다시 검증해야 합니다.
Q22. 범주형 분석에서 가장 먼저 확인할 것은?
A. Column의 의미, 실제 unique 값, Missing, 범주 수, 순서 유무를 먼저 확인하는 것이 좋습니다.

오늘의 암기 포인트

  • 범주형 = 제한된 종류의 값을 분류 의미로 사용
  • Nominal은 순서가 없다.
  • Ordinal은 순서가 있다.
  • Discrete는 세어서 얻는 값으로 이해하기 쉽다.
  • Continuous는 측정하는 값으로 이해하기 쉽다.
  • int·float dtype과 이산형·연속형은 같은 분류가 아니다.
  • astype("category")는 범주형 dtype 변환이다.
  • CategoricalDtype은 categories와 ordered를 정의한다.
  • unique()는 실제 등장값을 본다.
  • cat.categories는 정의된 전체 범주를 본다.
  • nunique()는 고유값의 개수를 센다.
  • isin() → Boolean Mask
  • value_counts() → 범주별 빈도
  • normalize=True는 비율이다.
  • dropna=False는 Missing도 빈도 결과에 포함한다.
  • 명목형에 0·1·2를 부여했다고 실제 수치 순서가 생기는 것은 아니다.
  • get_dummies() → Indicator Columns
  • One-Hot은 Row를 유지하면서 Column을 증가시킬 수 있다.
  • Encoding 전에 Missing 정책을 정한다.
  • dummy_na=True는 Missing Indicator를 만들 수 있다.
  • drop_first=True는 k-1 Dummy 구조를 만들 수 있다.
  • CSV 읽기 = pd.read_csv()
  • CSV 저장 = df.to_csv()
  • 단순 Index가 불필요하면 index=False를 고려한다.
  • CSV Reload 후 dtype을 다시 확인한다.
  • 마지막까지 shape·dtype·Missing을 확인한다.

헷갈리기 쉬운 개념

String ≠ Categorical

자유 Text와 제한된 범주를 구분합니다.

Nominal ≠ Ordinal

범주 사이의 순서가 의미 있는지를 확인합니다.

int ≠ Discrete

저장 dtype과 통계적 변수 성격을 구분합니다.

unique ≠ categories

실제 등장값과 정의된 전체 범주입니다.

isin ≠ Filtering 완료

isin은 Boolean Mask까지만 만듭니다.

value_counts ≠ nunique

하나는 각 범주의 빈도, 하나는 범주 종류의 개수입니다.

Category Code ≠ 실제 수치 크기

Code는 범주를 참조하는 번호일 수 있습니다.

Integer Encoding ≠ One-Hot

하나의 숫자 Code와 여러 Indicator Columns를 구분합니다.

One-Hot ≠ shape 유지

Column 수가 증가할 수 있습니다.

NaN ≠ 자동 Category

Missing 처리 정책을 별도로 결정합니다.

CSV 값 보존 ≠ dtype metadata 보존

Reload 후 category Schema를 다시 확인합니다.
