Python Database · Lesson 04

Python DB-API 작업 구조 Connection과 Cursor의 역할부터 execute · fetch · commit · rollback · close까지

지금까지 SQL 자체의 역할을 배웠다면, 이번 단원에서는 Python이 그 SQL을 Database에 어떤 객체와 순서를 이용해 전달하는지 공부합니다. Connection은 Database 연결과 Transaction을 관리하고, Cursor는 SQL을 실행하고 SELECT 결과를 처리합니다. 이 둘의 역할을 구분하면 SQLite뿐 아니라 이후 MySQL과 Oracle 연동 구조도 훨씬 쉽게 이해할 수 있습니다.

Python → connect() → Connection → cursor() → Cursor → execute()
SELECT → fetch()
INSERT / UPDATE / DELETE → commit() / rollback()

  • Connection과 Cursor의 역할 차이를 설명할 수 있다.
  • cursor()가 SQL 작업용 Cursor 객체를 만든다는 것을 이해한다.
  • execute()와 executemany()의 차이를 설명할 수 있다.
  • fetchone(), fetchmany(), fetchall()의 차이를 설명할 수 있다.
  • SELECT와 변경 SQL의 후속 작업이 서로 다른 이유를 이해한다.
  • commit()과 rollback()의 역할을 구분한다.
  • Cursor와 Connection의 생명주기와 close()의 의미를 이해한다.
  • 다음 단원의 sqlite3.connect()와 SQLite 연결 학습으로 자연스럽게 이어갈 수 있다.

import sqlite3


conn = sqlite3.connect("dbapi_practice.db")
cur = conn.cursor()


# 실습 Table 초기화
cur.execute("""

Supplement Practice

성공하면 commit, 실패하면 rollback

아래 코드는 첨부 교안의 commit()과 rollback() 역할을 Python의 실제 제어 흐름으로 이해하기 위해 추가한 보완 예제입니다. 

import sqlite3


conn = sqlite3.connect("sample.db")
cur = conn.cursor()


try:
    cur.execute(
        """
        UPDATE Member
        SET tel = ?
        WHERE _id = ?
        """,
        ("010-9999", 1)
    )

    conn.commit()

    print("변경을 확정했습니다.")


except Exception as error:
    conn.rollback()

    print("변경을 취소했습니다.")
    print(error)


finally:
    cur.close()
    conn.close()
SQL 실행 → 성공?
YES → commit() NO → rollback()
→ finally → close()

Beginner Mistakes

초보자가 자주 하는 실수

01

Connection과 Cursor를 같은 객체라고 생각한다.

Connection은 연결·Transaction, Cursor는 SQL·Result 담당입니다.

02

connect()가 SQL을 실행한다고 생각한다.

connect는 Database 연결, execute는 SQL 실행입니다.

03

cursor()의 결과를 조회 데이터라고 생각한다.

cursor()는 SQL 작업용 Cursor 객체를 반환합니다.

04

execute()와 fetch()를 같은 작업이라고 생각한다.

execute는 SQL 실행, fetch는 SELECT Result를 가져오는 단계입니다.

05

SELECT 후 fetch를 하지 않는다.

execute(SELECT) 이후 fetchone/fetchmany/fetchall을 사용합니다.

06

SELECT 뒤에 무조건 commit을 찾는다.

기본 학습 공식은 SELECT → fetch, 변경 SQL → commit입니다.

07

INSERT 후 fetchall을 호출한다.

INSERT는 변경 SQL입니다. 저장 결과가 궁금하다면 이후 SELECT를 실행합니다.

08

UPDATE 후 commit을 잊는다.

변경 SQL 실행 후 Transaction 확정을 생각합니다.

09

cur.commit()이라고 작성한다.

commit은 현재 구조에서 Connection의 역할입니다.

conn.commit()
10

conn.fetchall()이라고 작성한다.

SELECT Result는 Cursor가 처리합니다.

cur.fetchall()
11

fetchone 결과를 값 하나라고 생각한다.

한 Row는 보통 tuple 형태로 가져옵니다.

12

fetchall 결과를 tuple 하나라고 생각한다.

여러 Row를 list 안의 tuple들로 생각하면 쉽습니다.

13

fetchone 결과가 없는데 바로 row[0]을 사용한다.

결과가 없다면 None일 수 있으므로 존재 여부를 먼저 확인합니다.

14

fetchall 결과가 없으면 None이라고 생각한다.

교안 기준 fetchall은 결과가 없으면 빈 list를 반환합니다.

15

execute와 executemany의 사용 상황을 구분하지 않는다.

execute는 한 Data Set, executemany는 여러 Data Set 처리에 연결합니다.

16

Cursor를 닫은 뒤 다시 execute한다.

객체의 생명주기를 지키고 close 이후에는 새 작업 흐름을 준비해야 합니다.

Python → connect() → Connection → Cursor → execute() → SQLite → fetch / commit
SyntaxError

Python 문법

Database에 연결하기 전 Python 코드 자체를 확인합니다.

NameError

변수 생성 문제

conn 또는 cur가 먼저 만들어졌는지 확인합니다.

TypeError

Python Type 문제

함수·메서드에 전달한 Python 값의 형태를 확인합니다.

KeyError

Dictionary 문제

DB 오류가 아니라 Python Dictionary 접근 문제일 수 있습니다.

OperationalError

SQL 실행 문제

Table·Column 이름, SQL 문법 등을 확인합니다.

IntegrityError

Constraint 위반

PRIMARY KEY, UNIQUE, NOT NULL, CHECK 규칙을 확인합니다.

ProgrammingError

객체 사용 순서

이미 닫힌 Cursor나 Connection을 다시 사용하지 않았는지 확인합니다.

Binding Error

Parameter 전달 문제

Placeholder 개수와 전달 값의 개수를 확인합니다.

def find_all_members(conn):
    cur = conn.cursor()

    cur.execute("""
    SELECT
        _id,
        name,
        tel
    FROM Member
    ORDER BY _id
    """)

    rows = cur.fetchall()

    cur.close()

    return rows

Interview Point

면접에서 설명할 수 있어야 하는 질문

Q1. Connection 객체란 무엇인가요?
A.

Python 프로그램과 Database 사이의 연결을 나타내는 객체입니다. Cursor 생성, commit, rollback, 연결 종료 등의 작업과 연결됩니다.

Q2. Cursor 객체란 무엇인가요?
A.

Connection을 통해 SQL을 실행하고 SELECT 결과를 처리하는 작업 객체입니다.

Q3. Connection과 Cursor의 차이는 무엇인가요?
A.

Connection은 Database 연결과 Transaction을 관리하고, Cursor는 SQL 실행과 조회 결과 처리를 담당합니다.

Q4. connect()는 무엇을 반환하나요?
A.

Database 연결을 나타내는 Connection 객체를 반환합니다.

Q5. cursor()는 무엇을 반환하나요?
A.

SQL을 실행하고 조회 결과를 처리할 수 있는 Cursor 객체를 반환합니다.

Q6. execute()와 fetch()의 차이는 무엇인가요?
A.

execute()는 SQL을 실행하고, fetch 계열 메서드는 SELECT로 만들어진 조회 결과를 Python으로 가져옵니다.

Q7. fetchone(), fetchmany(), fetchall()의 차이는 무엇인가요?
A.

fetchone은 한 Row, fetchmany는 지정 개수의 Row, fetchall은 남은 전체 Row를 가져옵니다.

Q8. execute()와 executemany()의 차이는 무엇인가요?
A.

execute는 하나의 SQL 실행과 한 Data Set 처리에 사용하고, executemany는 같은 SQL을 여러 Data Set에 반복 적용할 때 사용합니다.

Q9. SELECT 후 왜 fetch가 필요한가요?
A.

SELECT SQL을 실행하는 단계와 그 조회 결과를 Python으로 가져오는 단계가 분리되어 있기 때문입니다.

Q10. INSERT·UPDATE·DELETE 후 왜 commit()을 사용하나요?
A.

Database 데이터를 변경하는 SQL이므로 Transaction의 변경 내용을 확정하기 위해 Connection의 commit()을 사용합니다.

Q11. rollback()은 무엇인가요?
A.

현재 Transaction에서 수행한 변경 내용을 취소할 때 사용하는 Connection 메서드입니다.

Q12. 왜 commit()은 Cursor가 아니라 Connection에서 호출하나요?
A.

Cursor는 SQL 실행을 담당하고, Transaction의 확정과 취소는 Database 연결을 관리하는 Connection의 책임으로 이해할 수 있기 때문입니다.

Q13. fetchone() 결과가 없으면 무엇이 반환되나요?
A.

교안 기준으로 None이 반환됩니다.

Q14. fetchall() 결과가 없으면 무엇이 반환되나요?
A.

교안 기준으로 빈 list []가 반환됩니다.

Q15. close()는 Database를 삭제하나요?
A.

아닙니다. Cursor나 Connection의 작업과 연결을 종료하는 것이며, Database File을 삭제하는 명령이 아닙니다.

Q16. DBMS가 달라져도 DB-API 구조를 배우는 이유는 무엇인가요?
A.

Driver와 세부 연결 방식은 달라질 수 있지만 Connection, Cursor, SQL 실행, Result 처리와 Transaction이라는 큰 구조가 반복되기 때문입니다.

오늘의 암기 포인트

  • connect()는 Connection 객체를 반환한다.
  • cursor()는 Cursor 객체를 반환한다.
  • Connection은 연결과 Transaction을 담당한다.
  • Cursor는 SQL 실행과 Result 처리를 담당한다.
  • execute()는 SQL 실행, fetch()는 SELECT 결과 가져오기다.
  • fetchone()은 한 Row, fetchmany(n)은 n Row, fetchall()은 남은 전체 Row다.
  • SELECT는 execute → fetch 흐름으로 기억한다.
  • INSERT·UPDATE·DELETE는 execute → commit 흐름으로 기억한다.
  • 문제가 있는 Transaction은 rollback()으로 취소한다.
  • 마지막에는 cur.close()와 conn.close()로 작업을 종료한다.
connect → Connection → Cursor → execute → fetch / commit

Confusing Point

헷갈리기 쉬운 개념

Connection ≠ Cursor

Connection은 연결, Cursor는 SQL 작업입니다.

connect ≠ execute

connect는 DB 연결, execute는 SQL 실행입니다.

execute ≠ fetch

SQL 실행과 SELECT 결과 가져오기는 다른 단계입니다.

SELECT → fetch

조회 작업의 후속 단계입니다.

DML → commit

INSERT·UPDATE·DELETE 변경 확정과 연결합니다.

commit ≠ rollback

확정과 취소는 서로 반대 역할입니다.

fetchone ≠ fetchall

한 Row와 남은 전체 Row를 구분합니다.

close ≠ delete

Connection 종료와 DB 파일 삭제는 다릅니다.
