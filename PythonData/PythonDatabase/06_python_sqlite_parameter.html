Source vs Supplement

Named Placeholder — 교안 내용과 보완 내용을 구분해서 기억하기

첨부 교안 기준 Python 3.14부터 Named Placeholder 사용 불가

첨부 교안에 기재된 문장입니다. 교안 원문의 흐름을 파악할 때는 이 내용이 포함되어 있음을 기억합니다.

Step 1·2 현재 기준 보완 Named Placeholder 자체는 사용 가능

Named Placeholder에는 이름에 대응하는 dict 형태의 Parameter를 사용한다고 구분해서 정리했습니다.

:name → {"name": value}
학습 매거진에서는 둘을 섞지 않는다.

교안 원문과 Step 1·2의 현재 기준 보완을 별도의 영역으로 표시하면 원문을 보존하면서 잘못된 내용을 그대로 암기하는 문제도 줄일 수 있습니다.

Value vs Identifier

Placeholder는 Data Value에 사용한다

VALUE · 적합 
WHERE name = ?

VALUES (?, ?)

SET tel = ?

name, tel, id처럼 실제 Data Value를 전달하는 위치입니다.

IDENTIFIER · 별도 처리 
SELECT *
FROM Member

ORDER BY name

Member나 name처럼 SQL 구조에 해당하는 Table·Column Identifier는 별도로 다룹니다.

이런 형태로 생각하지 않는다. 
cur.execute(
    "SELECT * FROM ?",
    ("Member",)
)

동적 Identifier가 꼭 필요하다면

allowed_columns = {
    "name",
    "joindate"
}


sort_column = "name"


if sort_column not in allowed_columns:
    raise ValueError(
        "허용하지 않는 정렬 기준입니다."
    )


sql = f"""
SELECT *
FROM Member
ORDER BY {sort_column}
"""
핵심은 f-string을 무조건 금지한다는 뜻이 아니다.

사용자 Data Value를 SQL Code에 직접 삽입하는 것을 피하고, SQL Identifier를 동적으로 만들어야 한다면 개발자가 허용한 값인지 먼저 검증하는 구조로 분리합니다.

Bulk Insert Example

executemany + commit + rollback 전체 예제

06_python_sqlite_parameter.py Bulk Parameterized Insert 
import sqlite3


members = [
    (
        "홍길동",
        "010-1111"
    ),
    (
        "김철수",
        "010-2222"
    ),
    (
        "이영희",
        "010-3333"
    )
]


conn = None
cur = None


try:
    # 1. Connection
    conn = sqlite3.connect(
        "parameter_practice.db"
    )


    # 2. Cursor
    cur = conn.cursor()


    # 3. Table 준비
    cur.execute("""
    CREATE TABLE IF NOT EXISTS Member (
        _id INTEGER
            PRIMARY KEY
            AUTOINCREMENT,

        name TEXT NOT NULL,

        tel TEXT NOT NULL
    )
    """)


    # 4. Parameterized SQL
    insert_sql = """
    INSERT INTO Member(
        name,
        tel
    )
    VALUES (?, ?)
    """


    # 5. 여러 Parameter Set 실행
    cur.executemany(
        insert_sql,
        members
    )


    # 6. 성공 → Commit
    conn.commit()


    # 7. 결과 조회
    cur.execute("""
    SELECT
        _id,
        name,
        tel
    FROM Member
    ORDER BY _id
    """)


    for row in cur.fetchall():
        print(row)


except sqlite3.Error as error:

    # 8. 실패 → Rollback
    if conn is not None:
        conn.rollback()


    print(
        "Database 작업에 실패했습니다."
    )

    print(error)


finally:

    # 9. Cursor 정리
    if cur is not None:
        cur.close()


    # 10. Connection 정리
    if conn is not None:
        conn.close()
List of tuples → Parameterized SQL → executemany() → Binding → INSERT × N → commit / rollback

01

? 개수와 전달 데이터의 개수를 비교합니다.

위치 기반 Placeholder에서는 순서가 중요합니다.

한 요소 Tuple에서 쉼표를 빼먹는다.

Interview Point

면접에서 설명할 수 있어야 하는 질문

Q1. Parameterized Query란 무엇인가요?
A.

SQL Code에 실제 값을 직접 조립하지 않고 Placeholder를 둔 뒤, 실제 Data를 별도의 Parameter로 전달하는 방식입니다.

Q2. Parameter Query를 사용하는 이유는 무엇인가요?
A.

SQL Code와 Data를 분리하여 값 전달을 일관되게 처리할 수 있고, 사용자 입력을 SQL 문자열에 직접 결합하는 방식보다 SQL Injection 위험을 줄이는 데 중요한 역할을 합니다.

Q3. SQLite의 기본 Placeholder는 무엇인가요?
A.

위치 기반 ?와 Named Placeholder 방식을 학습할 수 있습니다.

Q4. ? 방식에서는 Parameter를 어떻게 전달하나요?
A.

Placeholder의 순서와 맞는 tuple 또는 list 같은 Sequence로 전달합니다.

Q5. 한 요소 tuple은 어떻게 작성하나요?
A.

(value,)처럼 요소 뒤에 쉼표를 붙여 작성합니다.

Q6. Named Placeholder는 어떻게 사용하나요?
A.

:name 같은 이름을 SQL에 사용하고, 이름에 대응하는 값을 dict 형태로 전달합니다.

Q7. execute()와 executemany()의 차이는 무엇인가요?
A.

execute는 하나의 Parameter Set에 SQL을 적용하고, executemany는 같은 Parameterized SQL을 여러 Parameter Set에 반복 적용합니다.

Q8. Placeholder는 Table Name에도 사용할 수 있나요?
A.

일반적으로 Bind Parameter는 Data Value를 위한 것이고, Table·Column 같은 Identifier는 SQL 구조이므로 별도의 검증이 필요합니다.

Q9. commit()과 rollback()의 차이는 무엇인가요?
A.

commit은 Transaction의 변경을 확정하고, rollback은 확정되지 않은 변경을 취소합니다.

Q10. Auto Commit과 Manual Commit은 어떻게 다른가요?
A.

Auto Commit은 변경을 자동 확정하는 방향이고, Manual Transaction은 개발자가 업무 단위를 구성한 뒤 commit 또는 rollback을 결정합니다.

Q11. finally를 사용하는 이유는 무엇인가요?
A.

Database 작업이 성공하거나 실패하더라도 Cursor와 Connection 같은 자원을 마지막에 정리하기 위해 사용할 수 있습니다.

Q12. Context Manager를 사용하면 Connection이 자동으로 닫히나요?
A.

SQLite Connection의 Transaction Context와 실제 Connection close는 구분해야 합니다. Transaction 처리와 Connection 생명주기가 같은 개념은 아닙니다.

Q13. DB 접속 정보를 Source Code와 분리하는 이유는 무엇인가요?
A.

환경별 설정을 쉽게 관리하고 비밀번호 같은 민감한 정보를 Application Logic과 분리하기 위해서입니다.

Q14. SQLite와 MySQL의 Placeholder는 같은가요?
A.

Parameterized Query라는 개념은 같지만 Python Driver에 따라 Placeholder 표기법이 다를 수 있습니다.

Q15. Repository 계층을 사용하는 이유는 무엇인가요?
A.

SQL과 Database 접근 책임을 Application의 다른 Business Logic에서 분리하여 코드를 유지보수하기 쉽게 만들기 위해 사용할 수 있습니다.

Q16. 대량 입력에서 Transaction이 중요한 이유는 무엇인가요?
A.

여러 Record를 하나의 업무 단위로 처리하는 중 일부가 실패했을 때 전체 변경을 확정할지 취소할지 결정해야 하기 때문입니다.

Memory

오늘의 암기 포인트

  • 사용자 Data를 SQL 문자열에 직접 결합하지 않고 Parameterized Query를 기본으로 사용한다.
  • SQLite의 위치 기반 Placeholder는 ?이다.
  • Placeholder 순서와 Parameter 순서를 맞춘다.
  • Placeholder 개수와 Parameter 개수를 맞춘다.
  • 한 요소 tuple은 (value,)처럼 쉼표가 필요하다.
  • Named Placeholder는 :name + dict 구조로 이해한다.
  • execute()는 한 Parameter Set, executemany()는 여러 Parameter Set에 연결한다.
  • 대량 입력 구조는 list of tuples로 이해하면 쉽다.
  • 작업 성공 시 commit(), 실패 시 rollback()이다.
  • 성공·실패와 상관없이 마지막에는 Connection과 Cursor의 생명주기를 정리한다.
  • DB Password와 환경별 접속 정보는 Source Code와 분리하는 방향을 사용한다.
  • Driver마다 Placeholder 문법이 다를 수 있다.

Confusing Point

헷갈리기 쉬운 개념

SQL String ≠ Parameter Query

SQL 문자열 직접 조립과 Data Binding은 서로 다른 방식입니다.

? Count = Parameter Count

Placeholder와 Data 개수를 맞춥니다.

(value) ≠ (value,)

한 요소 tuple은 쉼표가 필요합니다.

execute ≠ executemany

하나의 Parameter Set과 여러 Set 처리를 구분합니다.

Value ≠ Identifier

Placeholder는 기본적으로 Data Value Binding에 사용합니다.

commit ≠ rollback

변경 확정과 변경 취소입니다.

Auto Commit ≠ Manual Commit

Transaction 확정 시점을 누가 관리하는지 구분합니다.

with conn ≠ 자동 close

Transaction Context와 Connection 종료를 구분합니다.

Driver마다 Placeholder가 다르다

SQLite의 ?를 모든 DBMS에 그대로 적용하지 않습니다.

교안 기준 ≠ 보완 기준

Named Placeholder 관련 교안 내용과 Step 1·2의 현재 기준 보완을 구분합니다.
