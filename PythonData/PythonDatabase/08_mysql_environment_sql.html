Python Database · Lesson 08

MySQL 설치와 기본 SQL File 기반 SQLite에서 Server 기반 MySQL로 확장하기

지금까지 SQLite에서는 sample.db 같은 Database File을 직접 열어 사용했습니다. 이번 단원부터는 구조가 달라집니다. MySQL에서는 Client가 실행 중인 MySQL Server에 접속하고, User 인증을 거친 뒤 Database를 선택하여 그 안의 Table에 SQL을 실행합니다. 설치와 접속부터 SHOW DATABASES, CREATE DATABASE, USE, CREATE TABLE, CRUD와 조건 검색까지 하나의 흐름으로 연결합니다.

18

Transaction

Auto Commit과 Manual Transaction

첨부 교안의 MySQL 기본 SQL을 앞 단원의 Transaction 학습과 연결한 실무 보완 카드입니다.

AUTO COMMIT
Statement ↓ 자동 확정 방향
MANUAL
START TRANSACTION ↓ 여러 DML ↓ COMMIT / ROLLBACK

Manual Transaction 실습

START TRANSACTION;


UPDATE Member
SET tel = '010-7777-7777'
WHERE _id = 1;


SELECT *
FROM Member
WHERE _id = 1;


ROLLBACK;
변경 SQL → 정상?
YES → COMMIT NO → ROLLBACK
DDL을 DML과 동일한 rollback 대상으로 단순하게 생각하지 않는다.

CREATE, ALTER, DROP은 Schema 변경 작업이므로 Transaction 실습은 우선 INSERT·UPDATE·DELETE 중심으로 이해합니다.

Interview Point

면접에서 설명할 수 있어야 하는 질문

Q1. SQLite와 MySQL의 구조적 차이는 무엇인가요?
A.

SQLite는 File 기반 Embedded Database로 사용하기 쉽고, MySQL은 Client가 실행 중인 Database Server에 연결하는 Client–Server 구조를 중심으로 사용합니다.

Q2. MySQL Server와 Client의 차이는 무엇인가요?
A.

Server는 Database와 SQL 처리, User 인증과 Transaction 등을 관리하고, Client는 Server에 접속하여 요청을 보냅니다.

Q3. mysql -u root -p는 무엇을 의미하나요?
A.

mysql Client를 실행해 root User로 접속하고 Password 입력을 요청하는 명령입니다.

Q4. CREATE DATABASE와 USE는 무엇이 다른가요?
A.

CREATE DATABASE는 Database를 생성하고, USE는 현재 Session에서 작업할 기본 Database를 선택합니다.

Q5. Server, Database, Table, Row의 관계는 무엇인가요?
A.

하나의 Server가 여러 Database를 관리하고, Database 안에 여러 Table, Table 안에 여러 Row가 존재하는 계층 구조입니다.

Q6. DESC 명령은 왜 사용하나요?
A.

Table의 Column Type, Null, Key, Default, Extra 같은 Schema 정보를 확인할 때 사용합니다.

Q7. AUTO_INCREMENT는 무엇인가요?
A.

새로운 Row를 INSERT할 때 증가하는 값을 자동으로 생성하도록 하는 Column 속성입니다.

Q8. UNSIGNED는 무엇인가요?
A.

정수 Column에서 음수 범위를 사용하지 않고 0 이상의 범위를 사용하도록 하는 속성입니다.

Q9. FLOAT/DOUBLE과 DECIMAL은 어떻게 다른가요?
A.

FLOAT와 DOUBLE은 근사 실수 표현, DECIMAL은 정확한 Fixed-Point 값에 적합한 Type입니다.

Q10. CHAR와 VARCHAR의 차이는 무엇인가요?
A.

CHAR는 고정 길이, VARCHAR는 가변 길이 문자열입니다.

Q11. WHERE의 역할은 무엇인가요?
A.

조건을 만족하는 Row를 선택하여 SELECT·UPDATE·DELETE 등의 대상 범위를 정합니다.

Q12. LIKE의 %와 _는 무엇인가요?
A.

%는 여러 문자 길이의 Pattern, _는 한 문자 위치를 나타냅니다.

Q13. ORDER BY의 ASC와 DESC는 무엇인가요?
A.

ASC는 오름차순, DESC는 내림차순 정렬입니다.

Q14. LIMIT는 실무에서 어디에 연결되나요?
A.

조회 결과 수를 제한하며 Backend의 Pagination 구현과 연결됩니다.

Q15. UPDATE와 ALTER TABLE은 무엇이 다른가요?
A.

UPDATE는 Row Data를 수정하고, ALTER TABLE은 Table Schema를 변경합니다.

Q16. DELETE와 DROP TABLE은 무엇이 다른가요?
A.

DELETE는 Row를 삭제하고, DROP TABLE은 Table 자체를 삭제합니다.

Q17. COMMIT과 ROLLBACK은 무엇인가요?
A.

COMMIT은 Transaction 변경을 확정하고, ROLLBACK은 미확정 변경을 취소합니다.

Q18. MySQL의 Auto Commit은 무엇인가요?
A.

Statement의 변경 결과가 자동으로 확정되는 Transaction Mode의 한 형태입니다. 여러 SQL을 하나의 업무로 묶을 때는 명시적 Transaction을 사용할 수 있습니다.

Q19. 실제 Application에서 root 사용을 피하는 이유는 무엇인가요?
A.

Application이 필요로 하는 범위보다 과도한 Database 권한을 갖지 않도록 별도의 User에 필요한 Privilege만 부여하는 방향이 안전하기 때문입니다.

Q20. Parameterized Query를 사용하는 이유는 무엇인가요?
A.

외부 Data를 SQL Code에 직접 문자열로 결합하지 않고 Driver Parameter로 분리하여 전달하기 위해 사용합니다.

Q21. Access denied 오류가 나오면 무엇을 확인하나요?
A.

SQL Syntax보다 User·Host·Password·Authentication·Privilege 영역을 먼저 확인합니다.

Q22. Repository 계층은 왜 사용하나요?
A.

SQL과 Database 접근 책임을 Application의 다른 Business Logic과 분리해 유지보수하기 쉽게 만들기 위해 사용합니다.

  • CHAR는 고정 길이, VARCHAR는 가변 길이다.
  • CRUD는 INSERT · SELECT · UPDATE · DELETE다.
  • SELECT Query는 FROM → WHERE → ORDER BY → LIMIT 흐름으로 읽는다.

Confusing Point

헷갈리기 쉬운 개념

Client ≠ Server

접속하는 쪽과 Database를 관리하는 쪽입니다.

Install ≠ Running

설치됐다고 Server가 항상 실행 중인 것은 아닙니다.

Server ≠ Database

Server 안에 여러 Database가 존재할 수 있습니다.

CREATE DATABASE ≠ USE

Database 생성과 현재 작업 대상 선택입니다.

CREATE TABLE ≠ INSERT

Schema 생성과 Row 입력입니다.

CHAR ≠ VARCHAR

고정 길이와 가변 길이입니다.

FLOAT ≠ DECIMAL

근사 값과 정확한 Fixed-Point 값입니다.

= ≠ LIKE

정확한 값 비교와 Pattern 검색입니다.

UPDATE ≠ ALTER TABLE

Row Data와 Table Schema 변경입니다.

DELETE ≠ DROP

Row 삭제와 객체 삭제입니다.

root ≠ Application User

관리 계정과 최소 권한 Application 계정을 구분합니다.

SQL Literal ≠ 문자열 직접 결합

Application 외부 입력은 Parameter Binding을 사용합니다.

Access denied ≠ SQL Syntax Error

인증·Host·Privilege 영역을 먼저 확인합니다.
