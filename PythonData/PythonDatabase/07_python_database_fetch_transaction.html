Python Database · Lesson 07

조회 결과와 트랜잭션 fetchone · fetchmany · fetchall · commit · rollback · close

SQL을 execute()한 뒤에는 SQL의 종류에 따라 작업 흐름이 달라집니다. SELECT는 Cursor가 관리하는 조회 결과를 fetchone(), fetchmany(), fetchall()로 Python에 가져오고, INSERT·UPDATE·DELETE 같은 변경 SQL은 Transaction 관점에서 commit() 또는 rollback()으로 처리합니다. 마지막에는 Transaction 처리와 별개로 Cursor와 Connection의 생명주기를 종료해야 합니다.

Connection → Cursor → execute()
READ SELECT ↓ fetch() Python Data
CHANGE INSERT · UPDATE · DELETE ↓
commit() 또는 rollback()
Transaction

학습 목표

  • SELECT 실행과 Result Fetch가 서로 다른 단계임을 설명할 수 있다.
  • Cursor가 현재 SELECT Result의 위치를 관리한다는 개념을 이해한다.
  • fetchone()으로 다음 Row 하나를 가져올 수 있다.
  • fetchmany(n)으로 일정 개수의 Row를 가져올 수 있다.
  • fetchall()이 현재 남은 Result 전체를 가져온다는 것을 이해한다.
  • 조회 결과가 없을 때의 None과 []을 오류와 구분할 수 있다.
  • Transaction이 무엇인지 설명할 수 있다.
  • commit()과 rollback()의 역할을 구분할 수 있다.
  • commit()과 close()가 서로 다른 책임임을 설명할 수 있다.
  • Manual Transaction과 Auto Commit의 차이를 개념적으로 이해한다.
  • try / except / finally를 이용해 Transaction과 Resource를 나누어 관리할 수 있다.
  • Context Manager의 Transaction 처리와 Connection 종료를 구분할 수 있다.
  • SQL Injection 방지를 위해 Parameterized Query 규칙을 유지할 수 있다.
  • 접속 정보 분리, DBMS별 Placeholder, Connection·권한 오류를 구분할 수 있다.
  • Repository와 Service의 역할, 그리고 Transaction 경계의 관계를 이해한다.

14

Transaction Mode

Manual Commit과 Auto Commit을 구분한다

첨부 교안에서는 commit()과 rollback()을 직접 호출하는 흐름을 학습합니다. 아래는 이를 Transaction Mode 관점으로 확장한 현재 기준 실무 보완입니다.

MANUAL

Manual Transaction

변경 SQL ↓ 업무 작업 ↓ commit / rollback

Application이 Transaction 결과를 명시적으로 결정합니다.

AUTO

Auto Commit

변경 Statement ↓ 자동 확정 방향

수동 Transaction과 동작 방식이 다르다는 점을 이해합니다.

이번 과정에서는 Manual Transaction 사고방식을 먼저 익힌다.

변경 SQL을 실행한 뒤 “업무를 확정할 것인가, 취소할 것인가?”를 명시적으로 판단하는 습관을 먼저 만듭니다.

Resource Management

conn = None
cur = None


try:

    conn = sqlite3.connect(
        "sample.db"
    )


    cur = conn.cursor()


    cur.execute(
        """
        UPDATE Member
        SET tel = ?
        WHERE id = ?
        """,
        (
            "010-9999",
            1
        )
    )


    conn.commit()


except sqlite3.Error as error:

    if conn is not None:
        conn.rollback()


    print(
        "Database 작업 실패:"
    )

    print(error)


finally:

    if cur is not None:
        cur.close()


    if conn is not None:
        conn.close()

EXCEPT 실패 처리

오류를 해석하고 필요한 경우 rollback

FINALLY Resource 정리

성공·실패와 관계없이 Cursor와 Connection 종료

Transaction Practice

오류를 발생시켜 rollback 확인하기

Transaction Rollback UNIQUE Error 
import sqlite3


conn = sqlite3.connect(
    ":memory:"
)


cur = conn.cursor()


cur.execute("""
CREATE TABLE Member (
    id INTEGER PRIMARY KEY,
    name TEXT UNIQUE
)
""")


conn.commit()


try:

    # 첫 번째 INSERT
    cur.execute(
        """
        INSERT INTO Member(
            id,
            name
        )
        VALUES (?, ?)
        """,
        (
            1,
            "홍길동"
        )
    )


    # 같은 name → UNIQUE 위반
    cur.execute(
        """
        INSERT INTO Member(
            id,
            name
        )
        VALUES (?, ?)
        """,
        (
            2,
            "홍길동"
        )
    )


    conn.commit()


except sqlite3.IntegrityError as error:

    conn.rollback()


    print(
        "Transaction을 취소했습니다."
    )


    print(error)


cur.execute("""
SELECT *
FROM Member
""")


print(
    cur.fetchall()
)


cur.close()
conn.close()
INSERT 1 → INSERT 2 → IntegrityError → rollback → 미확정 변경 취소

Python → Connection → Authentication → Cursor → Binding → SQL → Constraint → Transaction → Resource
SyntaxError

Python 문법

괄호·따옴표·콜론 등 Python 코드부터 확인합니다.

NameError

변수

conn, cur 등의 객체가 먼저 생성됐는지 확인합니다.

TypeError

Python Type

메서드에 전달한 Python 값의 Type을 확인합니다.

KeyError

Dictionary

SQLite가 아니라 Python dict 접근 문제일 수 있습니다.

ProgrammingError

DB-API 사용

닫힌 Cursor·Connection 또는 잘못된 API 사용 순서를 확인합니다.

OperationalError

실행 / 연결

Path, Database File, SQL 실행 환경 등을 확인합니다.

IntegrityError

Constraint

PRIMARY KEY, UNIQUE, CHECK, NOT NULL을 확인합니다.

Empty Result

오류가 아닐 수 있음

None과 []은 정상적인 빈 조회 결과일 수 있습니다.

연결·권한 오류는 SQL과 분리해서 본다

SQLite unable to open database file

Path·Directory·File Access를 확인합니다.

SQLite attempt to write a readonly database

현재 Connection이 쓰기 가능한지 확인합니다.

MySQL ERROR 1045 Access denied

User·Host·Password·Privilege 영역을 확인합니다.

Oracle ORA-01017

Credential·Authorization을 확인합니다.

오류 읽는 순서
  1. 오류 이름을 확인한다.
  2. Python 문법 문제인지 확인한다.
  3. Connection이 정상적으로 생성됐는지 확인한다.
  4. Path·Host·Port를 확인한다.
  5. User·Password·Privilege를 확인한다.
  6. Cursor가 아직 사용 가능한지 확인한다.
  7. Parameter Binding을 확인한다.
  8. SQL Syntax를 확인한다.
  9. Table·Column을 확인한다.
  10. Constraint를 확인한다.
  11. Transaction 상태를 확인한다.
  12. rollback이 필요한지 확인한다.
  13. Resource가 정상적으로 닫혔는지 확인한다.

def find_by_id(
    conn,
    member_id
):

    cur = conn.cursor()


    try:

        cur.execute(
            """
            SELECT
                id,
                name,
                tel

            (member_id,)

Beginner Mistakes

01

SELECT를 execute하면 결과가 자동으로 Python에 들어온다고 생각한다.

SELECT 실행과 fetch는 별도 단계입니다.

02

fetchone()이 계속 첫 Row를 가져온다고 생각한다.

현재 Result에서 다음 Row를 가져옵니다.

03

이미 소비한 Row 뒤의 남은 전체를 가져옵니다.

04

fetchone()의 None을 오류라고 생각한다.

정상적인 빈 조회 결과일 수 있습니다.

05

fetchall()의 빈 결과를 None이라고 생각한다.

기본적으로 빈 list []입니다.

06

모든 SELECT에 무조건 fetchall()을 사용한다.

한 건, Batch, 전체 조회 목적을 구분합니다.

07

INSERT 후 fetch를 찾는다.

Interview Point

면접에서 설명할 수 있어야 하는 질문

Q1. execute(SELECT)와 fetch의 차이는 무엇인가요?
A.

execute()는 SELECT SQL을 실행하고, fetch 계열 메서드는 조회 결과를 Python으로 가져옵니다.

Q2. fetchone()은 무엇인가요?
A.

현재 Cursor Result에서 다음 Row 하나를 가져옵니다. 기본 설정에서는 tuple 형태이고 더 이상 Row가 없으면 None을 반환합니다.

Q3. fetchmany(n)은 무엇인가요?
A.

현재 Result에서 다음 n개의 Row를 list 형태로 가져오는 메서드입니다.

Q4. fetchall()은 무엇인가요?
A.

현재 Cursor Result에서 아직 가져오지 않은 남은 Row 전체를 가져옵니다.

Q5. fetchone() 후 fetchall()을 호출하면 어떻게 되나요?
A.

fetchone()으로 이미 가져온 Row 다음부터 남아 있는 Result를 fetchall()이 가져옵니다.

Q6. 조회 결과가 없는 것과 오류는 어떻게 다른가요?
A.

None이나 빈 list는 정상적인 빈 Result일 수 있지만, OperationalError·IntegrityError 같은 Exception은 실제 작업 오류입니다.

Q7. Transaction이란 무엇인가요?
A.

여러 Database 변경을 하나의 논리적인 업무 단위로 묶고, 전체 성공 여부에 따라 확정하거나 취소할 수 있도록 관리하는 개념입니다.

Q8. commit()은 무엇인가요?
A.

현재 Transaction에서 수행한 변경 내용을 확정하는 Connection 작업입니다.

Q9. rollback()은 무엇인가요?
A.

현재 Transaction의 아직 확정되지 않은 변경을 취소합니다.

Q10. 왜 commit과 rollback은 Connection에서 호출하나요?
A.

Cursor는 SQL과 Result를 담당하고, Connection은 Database 연결과 Transaction을 담당하기 때문입니다.

Q11. commit과 close는 같은가요?
A.

아닙니다. commit은 Transaction 확정이고, close는 Connection 종료입니다.

Q12. Auto Commit과 Manual Transaction의 차이는 무엇인가요?
A.

Manual Transaction에서는 Application이 commit 또는 rollback으로 결과를 결정하고, Auto Commit은 변경 확정 방식이 자동화된 Transaction Mode입니다.

Q13. finally는 왜 사용하나요?
A.

Database 작업이 성공하거나 실패하더라도 마지막에 Cursor와 Connection 같은 Resource를 정리하기 위해 사용할 수 있습니다.

Q14. with conn을 사용하면 Connection도 닫히나요?
A.

SQLite Connection Context Manager의 Transaction 처리와 Connection 종료는 별개의 개념입니다.

Q15. Repository의 역할은 무엇인가요?
A.

SQL과 Database 접근 책임을 다른 Application Logic에서 분리하는 역할을 합니다.

Q16. Transaction 경계를 Service에 둘 수 있는 이유는 무엇인가요?
A.

하나의 Business 업무가 여러 Repository의 SQL 작업을 포함할 수 있기 때문입니다.

Q17. MySQL Access denied는 무엇부터 확인하나요?
A.

SQL 문법보다 User·Host·Password·Privilege 같은 연결·인증·권한 영역부터 확인합니다.

Q18. ORA-01017은 어떤 오류 방향인가요?
A.

Oracle Database의 Credential 또는 Authorization과 연결해서 확인해야 하는 오류입니다.

오늘의 암기 포인트

  • SELECT → execute → fetch 순서로 생각한다.
  • fetchone()은 다음 Row 하나를 가져온다.
  • fetchmany(n)은 다음 n개의 Row를 가져온다.
  • fetchall()은 현재 남아 있는 Row 전체를 가져온다.
  • 기본 설정에서 fetchone() 결과는 tuple이고, 결과가 없으면 None이다.
  • fetchmany()과 fetchall()의 빈 결과는 []이다.
  • INSERT·UPDATE·DELETE는 Transaction을 생각한다.
  • 성공하면 commit(), 실패하면 rollback()이다.
  • Cursor는 SQL·Result, Connection은 연결·Transaction을 담당한다.
  • commit()과 close()는 전혀 다른 책임이다.
  • finally는 Resource 정리와 연결한다.
  • SQL의 Data Value는 Parameter Binding을 기본으로 사용한다.
SELECT → Result → fetch
DML → Transaction → commit / rollback

Confusing Point

헷갈리기 쉬운 개념

execute ≠ fetch

SQL 실행과 Result 가져오기는 다른 단계입니다.

fetchone ≠ 첫 Row 고정

현재 Result의 다음 Row를 가져옵니다.

fetchall = 남은 전체

이미 가져온 Row까지 다시 반환하는 것이 아닙니다.

None ≠ Exception

정상적인 빈 조회 결과일 수 있습니다.

Cursor ≠ Connection

SQL/Result와 Connection/Transaction 역할을 구분합니다.

commit ≠ rollback

변경 확정과 변경 취소입니다.

commit ≠ close

Transaction 결과와 Resource 종료입니다.

Auto Commit ≠ Manual Transaction

Transaction 확정 방식이 다릅니다.

with conn ≠ automatic close

Transaction Context와 Connection 종료를 구분합니다.

Connection Error ≠ SQL Error

Path·Credential·Permission 문제를 별도로 확인합니다.
