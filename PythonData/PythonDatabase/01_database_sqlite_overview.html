01

Core Concept

DBMS는 무엇을 하는 시스템인가?

DBMS는 Database Management System의 약자입니다. 데이터베이스에 데이터를 저장하고 조회하며, 수정·삭제할 수 있도록 관리하는 시스템으로 이해하면 됩니다.

Database + Management + System = DBMS

DBMS가 담당하는 일

01

저장

프로그램에서 생성된 데이터를 Database에 보관합니다.

02

조회

필요한 데이터를 SQL을 이용하여 찾아옵니다.

03

수정

기존 데이터의 값을 변경할 수 있습니다.

04

삭제

더 이상 필요하지 않은 데이터를 제거합니다.

05

구조 관리

Table과 Column 같은 데이터 구조를 관리합니다.

06

규칙 관리

Primary Key와 제약조건 등을 통해 데이터의 규칙을 관리합니다.

Database와 DBMS는 같은 개념이 아니다.
Database 데이터가 저장되는 구조 ↔ DBMS Database를 관리하는 시스템
02

Relational Database

관계형 데이터베이스는 Table로 데이터를 표현한다

SQLite를 공부하면서 가장 먼저 만나게 되는 구조는 Table입니다. Table은 같은 종류의 데이터를 일정한 Column 구조에 맞추어 저장하는 공간입니다.

MEMBER TABLE
id name email tel
1 홍길동 hong@example.com 010-1111-1111
2 김철수 kim@example.com 010-2222-2222
3 이영희 lee@example.com 010-3333-3333
Table 데이터 집합

같은 종류의 데이터를 일정한 구조로 모아 둔 공간입니다.

Column 데이터 속성

id, name, email처럼 어떤 값을 저장할지를 나타냅니다.

Row 데이터 한 건

회원 Table이라면 한 명의 회원 데이터가 한 Row입니다.

Primary Key 고유 식별자

서로 비슷한 Row가 있더라도 특정 데이터를 정확하게 구분합니다.

Row → 가로 → 데이터 한 건
Column → 세로 → 데이터 속성

하나의 Database 안에는 여러 Table이 존재할 수 있다

DATABASE shopping.db
Member
Product
Orders
OrderItem

따라서 Database File 하나 = Table 하나가 아닙니다. 하나의 SQLite Database File 안에 여러 Table을 구성할 수 있습니다.

03

SQLite

SQLite는 어떤 Database Engine인가?

첨부 교안에서는 SQLite를 별도의 DB Server가 필요하지 않고, 파일에 기초하여 데이터베이스 처리를 구현하는 Embedded SQL DB Engine으로 설명합니다.

Relational

관계형

Table, Row, Column과 SQL을 이용하여 데이터를 관리합니다.

Embedded

내장형

별도 DB Server에 접속하는 구조보다 Application과 가까운 곳에서 DB Engine이 동작합니다.

Serverless

별도 DB Server 불필요

SQLite를 사용하기 위해 별도의 SQLite Server 프로세스를 먼저 실행할 필요가 없습니다.

File-based

파일 기반

sample.db 같은 하나의 Database File로 데이터를 관리할 수 있습니다.

Lightweight

간단한 구성

복잡한 Server 설정 없이 비교적 작은 환경에서 DB 학습과 개발을 시작할 수 있습니다.

SQLite = Relational + Embedded + Serverless + File-based

05

Important Distinction

Embedded와 :memory:는 같은 뜻이 아니다

SQLite를 처음 공부할 때 가장 많이 헷갈리는 부분입니다. Embedded는 SQLite Engine이 동작하는 구조를 설명하고, :memory:는 Database가 저장되는 위치를 나타냅니다.

Embedded

DB Engine 구조

별도 DB Server를 두고 Network로 접속하는 대신, SQLite Engine이 Application에 내장되어 동작하는 구조입니다.

Application + SQLite Engine
:memory:

Database 저장 위치

SQLite Database를 디스크 파일이 아니라 Memory에 생성하여 사용하는 연결 방식입니다.

SQLite → Memory Database
Embedded ≠ :memory:
06

Database Location

파일 Database와 Memory Database

FILE DATABASE 
sqlite3.connect("sample.db")
Python 실행 ↓ SQLite 연결 ↓ sample.db ↓ Connection 종료 ↓ Database File 유지 가능
MEMORY DATABASE 
sqlite3.connect(":memory:")
Python 실행 ↓ SQLite 연결 ↓ Memory Database ↓ Connection 종료 ↓ Memory Database 종료
주의

Python의 일반적인 list나 dict와 SQLite의 :memory: Database도 같은 개념이 아닙니다. SQLite Memory Database는 여전히 SQLite Engine과 SQL을 이용하여 관리됩니다.

Beginner Mistakes

초보자가 자주 하는 실수

01

SQLite와 sample.db를 같은 것으로 생각한다.

SQLite는 Database Engine이고, sample.db는 SQLite가 관리하는 Database File입니다.

02

sqlite3와 SQLite를 완전히 같은 개념으로 생각한다.

Python의 sqlite3는 Python 코드에서 SQLite를 사용하는 인터페이스이고, SQLite는 Database Engine입니다.

03

Database와 Table을 같은 것으로 생각한다.

하나의 Database 안에 Member, Product, Orders 같은 여러 Table이 존재할 수 있습니다.

04

Row와 Column을 반대로 기억한다.

Row는 가로 방향의 데이터 한 건, Column은 세로 방향의 데이터 속성입니다.

05

Embedded를 Memory Database라고 생각한다.

Embedded는 Engine 구조, :memory:는 Database 저장 위치입니다.

06

SQLite Server를 따로 실행해야 한다고 생각한다.

기본적인 SQLite 사용에서는 별도의 Database Server를 먼저 실행하지 않습니다.

07

connect()만 하면 Table까지 만들어진다고 생각한다.

Database 연결과 Table 생성은 다른 단계입니다. Table은 CREATE TABLE로 만듭니다.

08

close()를 Database 삭제라고 생각한다.

close()는 Connection을 종료하는 작업입니다.

09

sample.db가 보이지 않으면 생성에 실패했다고 생각한다.

먼저 Working Directory와 실제 파일 경로를 확인합니다.

10

SQLite DB 파일을 일반 TXT처럼 확인한다.

SQLite Database File의 구조는 DB Browser 같은 SQLite용 도구에서 확인하는 것이 좋습니다.

Error Reading

오류는 어느 단계에서 발생했는지부터 찾는다

SQLite 코드에는 Python 문법 오류, Python 객체 오류, SQLite Connection 오류, SQL 실행 오류가 함께 등장할 수 있습니다.

Python 문법 → Python 객체 → sqlite3 → Connection → SQL / SQLite
SyntaxError

Python 문법 오류

괄호, 따옴표 등 Python 문법 자체를 먼저 확인합니다.

NameError

이름·변수 문제

sqlite3, conn, cur 등이 먼저 정의되었는지 확인합니다.

TypeError

Python 타입 문제

메서드에 전달한 값이나 인자의 형태를 확인합니다.

OperationalError

SQLite 실행 문제

없는 Table, 잘못된 SQL, Database 경로 등을 확인합니다.

ProgrammingError

Connection 사용 흐름 문제

이미 닫은 Connection이나 Cursor를 다시 사용하지 않았는지 확인합니다.

IntegrityError

제약조건 위반

다음 단원에서 배울 PRIMARY KEY, UNIQUE, NOT NULL 등의 규칙 위반과 연결됩니다.

KeyError

Python Dictionary 문제

DB 오류와 구분하여 Python Dictionary의 Key를 확인합니다.

ModuleNotFoundError

Python 환경 문제

현재 Interpreter와 Python 실행 환경을 먼저 확인합니다.

Interview Point

면접에서 설명할 수 있어야 하는 핵심 질문

Q1. DBMS란 무엇인가요?
A.

Database Management System의 약자로, 데이터를 저장·조회·수정·삭제하고 Database를 관리하도록 기능을 제공하는 시스템입니다.

Q2. Database와 DBMS의 차이는 무엇인가요?
A.

Database는 구조화된 데이터가 저장되는 공간이고, DBMS는 해당 Database를 관리하는 시스템입니다.

Q3. 관계형 Database란 무엇인가요?
A.

데이터를 주로 Table 형태로 구조화하고, Table 사이의 관계를 이용하여 데이터를 관리하는 방식의 Database입니다.

Q4. Table, Row, Column을 설명해 보세요.
A.

Table은 같은 종류의 데이터 집합, Row는 데이터 한 건, Column은 데이터의 속성을 의미합니다.

Q5. Primary Key는 왜 필요한가요?
A.

Table의 각 Row를 고유하게 식별하기 위해 사용합니다. 같은 이름이나 비슷한 데이터를 가지고 있어도 특정 Row를 정확하게 구분할 수 있습니다.

Q6. SQLite란 무엇인가요?
A.

SQLite는 SQL을 사용하는 관계형 Database Engine으로, 별도의 DB Server를 운영하지 않고 Application에 내장하여 사용할 수 있으며 Database를 파일로 관리할 수 있습니다.

Q7. Embedded Database란 무엇인가요?
A.

별도의 Database Server에 Network로 접속하는 방식보다 Database Engine이 Application과 가까운 곳에 내장되어 동작하는 구조를 의미합니다.

Q8. Embedded와 :memory:는 같은 의미인가요?
A.

아닙니다. Embedded는 Database Engine의 동작 구조이고, :memory:는 SQLite Database의 저장 위치를 Memory로 사용하는 연결 방식입니다.

Q9. SQLite와 MySQL의 구조적 차이는 무엇인가요?
A.

SQLite는 별도의 DB Server 없이 Application에서 Database File을 사용할 수 있는 구조이고, MySQL은 Client가 별도의 MySQL Server에 Network로 접속하는 구조입니다.

Q10. Python에서 SQLite는 어떻게 사용하나요?
A.

Python의 sqlite3 모듈을 import하고, sqlite3.connect()를 이용해 SQLite Database File을 열거나 생성합니다.

Q11. connect()만 하면 Table도 만들어지나요?
A.

아닙니다. Database를 생성하거나 여는 작업과 Table을 생성하는 작업은 다릅니다. Table은 CREATE TABLE 같은 DDL을 실행하여 생성합니다.

오늘의 암기 포인트

  • DBMS는 Database를 관리하는 시스템이다.
  • Table은 데이터 집합, Row는 데이터 한 건, Column은 데이터 속성이다.
  • Primary Key는 각 Row를 고유하게 식별한다.
  • SQLite는 Embedded SQL Database Engine이다.
  • SQLite 기본 구조에서는 별도의 Database Server를 먼저 실행하지 않는다.
  • SQLite는 sample.db 같은 Database File을 사용할 수 있다.
  • Python에서는 sqlite3를 통해 SQLite를 사용한다.
  • sample.db와 :memory:는 Database 저장 위치가 다르다.
Python → sqlite3 → SQLite → sample.db

Confusing Point

헷갈리기 쉬운 개념

SQLite ≠ sample.db

SQLite는 Engine, sample.db는 Database File입니다.

sqlite3 ≠ sample.db

sqlite3는 Python 인터페이스이고 sample.db는 실제 Database File입니다.

Database ≠ Table

하나의 Database 안에 여러 Table이 존재할 수 있습니다.

Row ≠ Column

Row는 데이터 한 건, Column은 데이터 속성입니다.

Embedded ≠ :memory:

Embedded는 Engine 구조, :memory:는 저장 위치입니다.

connect ≠ CREATE TABLE

Database 연결과 Table 생성은 서로 다른 단계입니다.

close ≠ delete

close는 Connection 종료이지 Database File 삭제가 아닙니다.
