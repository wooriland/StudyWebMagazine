Error & Resource

try · except · finally로 안정적인 구조 만들기 

conn = None
cur = None


try:

    conn = pymysql.connect(...)

    cur = conn.cursor()


    cur.execute(
        """
        UPDATE Member
        SET tel = %s
        WHERE _id = %s
        """,
        (
            "010-9999",
            1
        )
    )


    conn.commit()


except Exception as error:

    if conn is not None:
        conn.rollback()


    print(
        "Database 작업 실패:"
    )

    print(error)


finally:

    if cur is not None:
        cur.close()


    if conn is not None:
        conn.close()
TRY 정상 작업

Connection → Cursor → SQL → commit

EXCEPT 실패 처리

오류 확인 → rollback

FINALLY Resource 정리

Cursor / Connection close

connect() 자체가 실패할 수도 있다.

따라서 Connection이 실제 생성되었는지 확인한 뒤 rollback이나 close를 호출하는 구조가 안전합니다.

Integrated Practice

Connection · Parameter · Transaction · close 전체 코드

PyMySQL Transaction Complete Flow 
import os
import pymysql


conn = None


try:

    # ------------------------------------------
    # 1. Connection
    # ------------------------------------------

    conn = pymysql.connect(
        host=os.getenv(
            "DB_HOST",
            "localhost"
        ),
        port=int(
            os.getenv(
                "DB_PORT",
                "3306"
            )
        ),
        user=os.getenv(
            "DB_USER"
        ),
        password=os.getenv(
            "DB_PASSWORD"
        ),
        database=os.getenv(
            "DB_NAME",
            "python_study"
        ),
        charset="utf8mb4",
        cursorclass=(
            pymysql.cursors.DictCursor
        )
    )


    # ------------------------------------------
    # 2. Cursor
    # ------------------------------------------

    with conn.cursor() as cursor:


        # --------------------------------------
        # 3. Parameterized INSERT
        # --------------------------------------

        cursor.execute(
            """
            INSERT INTO Member(
                name,
                tel
            )
            VALUES(
                %s,
                %s
            )
            """,
            (
                "홍길동",
                "010-1111"
            )
        )


        # --------------------------------------
        # 4. Parameterized UPDATE
        # --------------------------------------

        cursor.execute(
            """
            UPDATE Member
            SET tel = %s
            WHERE name = %s
            """,
            (
                "010-9999",
                "홍길동"
            )
        )


    # ------------------------------------------
    # 5. Success → Commit
    # ------------------------------------------

    conn.commit()


except Exception as error:

    # ------------------------------------------
    # 6. Failure → Rollback
    # ------------------------------------------

    if conn is not None:
        conn.rollback()


    print(
        "Database 작업 실패:"
    )

    print(error)


finally:

    # ------------------------------------------
    # 7. Resource Close
    # ------------------------------------------

    if conn is not None:
        conn.close()
Environment → Connection → Cursor → %s Binding → SQL → commit / rollback → close

import os
import pymysql


def get_connection():

    return pymysql.connect(
        host=os.getenv(
            "DB_HOST",
            "localhost"
        ),
        port=int(
            os.getenv(
                "DB_PORT",
                "3306"
            )
        ),
        user=os.getenv(
            "DB_USER"
        ),
        password=os.getenv(
            "DB_PASSWORD"
        ),
        database=os.getenv(
            "DB_NAME"
        ),
        charset="utf8mb4",
        cursorclass=(
            pymysql.cursors.DictCursor
        )
    )

def find_by_id(
    conn,
    member_id
):

    with conn.cursor() as cursor:

            """

Beginner Mistakes

초보자가 실제로 자주 하는 실수

01

PyMySQL을 설치하지 않고 import한다.

Package 설치와 Interpreter부터 확인합니다.

02

다른 Python Interpreter에 Package를 설치한다.

현재 PyCharm Interpreter와 pip 대상 Python을 확인합니다.

03

MySQL Server가 꺼져 있는데 SQL 코드만 수정한다.

Connection 전 단계부터 확인합니다.

04

Application Connection에 root를 사용한다.

앞 단원에서 만든 최소 권한 User를 사용합니다.

05

Password를 Source Code에 직접 작성한다.

Environment 또는 Configuration으로 분리합니다.

06

Connection과 Cursor를 같은 객체로 생각한다.

연결/Transaction과 SQL/Result 책임을 구분합니다.

07

DictCursor가 다른 SQL 방식이라고 생각한다.

주요 차이는 Row 표현 방식입니다.

08

%s를 Python 문자열 Formatting으로 직접 사용한다.

cursor.execute()의 Parameter로 값을 분리합니다.

09

%s는 문자열만 받을 수 있다고 생각한다.

PyMySQL Parameter 위치로 이해합니다.

10

한 요소 Tuple의 쉼표를 빼먹는다.

(value,)
11

Placeholder 개수와 Parameter 개수가 다르다.

Binding 전에 개수를 확인합니다.

12

Parameter 순서를 잘못 전달한다.

SQL의 Placeholder 의미 순서와 맞춥니다.

13

여러 Row를 execute() 반복만으로 처리한다.

대량 입력은 executemany()를 고려합니다.

14

INSERT·UPDATE·DELETE 뒤 Transaction을 생각하지 않는다.

성공 commit, 실패 rollback을 기본으로 생각합니다.

15

commit과 close를 같은 것으로 생각한다.

Transaction 확정과 Resource 종료입니다.

16

Connection 생성 실패에도 무조건 rollback한다.

conn이 실제 생성되었는지 먼저 확인합니다.

17

모든 SELECT에 fetchall()만 사용한다.

한 건·Batch·전체 Result 목적을 구분합니다.

18

Access denied를 SQL Syntax 문제로 생각한다.

User·Host·Password·Privilege를 확인합니다.

19

Connection 오류 상태에서 SELECT 문만 수정한다.

Server·Host·Port·Authentication부터 확인합니다.

20

DictCursor Key를 추측한다.

실제 SELECT Column 이름 또는 Alias를 확인합니다.

21

LIKE 검색어를 SQL 문자열에 직접 붙인다.

Pattern은 Data로 만들고 LIKE %s에 Binding합니다.

22

Repository마다 무조건 commit한다.

Business Transaction이 더 넓다면 Service 경계를 고려합니다.

23

Privilege와 Transaction을 같은 문제로 생각한다.

SQL 실행 가능 여부와 변경 확정 여부는 다릅니다.

24

SQLite의 ? Placeholder를 PyMySQL에 그대로 사용한다.

Driver별 Parameter Style을 확인합니다.

Interview Point

면접에서 설명할 수 있어야 하는 질문

Q1. PyMySQL은 무엇인가요?
A.

Python Application이 MySQL Server에 연결하고 SQL을 실행할 수 있도록 사용하는 Database Driver입니다.

Q2. SQLite와 PyMySQL 연결의 차이는 무엇인가요?
A.

SQLite는 주로 Database File에 연결하지만, PyMySQL은 Host·Port·User·Password 등의 정보로 MySQL Server에 연결합니다.

Q3. pymysql.connect()의 역할은 무엇인가요?
A.

MySQL Server와 연결하고 Connection 객체를 생성하는 역할입니다.

Q4. Connection의 역할은 무엇인가요?
A.

MySQL Server와의 연결, Cursor 생성, Transaction, commit·rollback·close와 연결됩니다.

Q5. Cursor의 역할은 무엇인가요?
A.

SQL을 실행하고 Parameter를 전달하며 SELECT Result를 fetch하는 객체입니다.

Q6. Connection과 Cursor의 차이는 무엇인가요?
A.

Connection은 연결과 Transaction, Cursor는 SQL과 Result 처리를 담당합니다.

Q7. DictCursor란 무엇인가요?
A.

조회 Row를 Column 이름을 Key로 하는 Dictionary 형태로 다루기 쉽게 하는 Cursor입니다.

Q8. 일반 Cursor와 DictCursor의 차이는 무엇인가요?
A.

SQL 실행 구조는 유사하지만 일반 Cursor는 Tuple 중심, DictCursor는 Dictionary 중심으로 Result를 다룹니다.

Q9. PyMySQL에서 %s는 무엇인가요?
A.

Parameterized Query에서 Python Data가 Binding될 위치를 표시하는 Placeholder로 사용합니다.

Q10. %s는 문자열만 받을 수 있다는 뜻인가요?
A.

아닙니다. PyMySQL Parameter Binding 위치로 이해해야 합니다.

Q11. 왜 Parameterized Query를 사용하나요?
A.

외부 값을 SQL 문자열에 직접 결합하지 않고 SQL Code와 Data를 분리하기 위해 사용합니다.

Q12. execute와 executemany의 차이는 무엇인가요?
A.

execute는 한 Parameter Set, executemany는 여러 Parameter Set을 같은 SQL에 적용할 때 사용합니다.

Q13. fetchone, fetchmany, fetchall의 차이는 무엇인가요?
A.

각각 다음 Row 하나, 일정 개수의 Row, 전체 Result를 가져오는 방향으로 사용합니다.

Q14. INSERT 뒤 왜 commit을 사용하나요?
A.

현재 Transaction에서 발생한 Database 변경을 확정하기 위해 사용합니다.

Q15. rollback은 언제 사용하나요?
A.

Transaction 도중 오류가 발생했을 때 미확정 변경을 취소하는 데 사용합니다.

Q16. commit과 close는 같은가요?
A.

아닙니다. commit은 Transaction 확정, close는 Resource 종료입니다.

Q17. 왜 DB Password를 Source Code와 분리하나요?
A.

Secret 노출을 줄이고 개발·테스트·운영별 Connection 설정을 분리하기 위해서입니다.

Q18. Application에서 root를 사용하지 않는 이유는 무엇인가요?
A.

Application이 필요로 하는 범위보다 강한 Database Privilege를 갖지 않도록 최소 권한 User를 사용하기 위해서입니다.

Q19. SQLite와 PyMySQL Placeholder의 차이는 무엇인가요?
A.

SQLite sqlite3에서는 대표적으로 ?, PyMySQL에서는 %s를 사용합니다.

Q20. Privilege와 Transaction은 같은 개념인가요?
A.

아닙니다. Privilege는 SQL 실행 가능 여부, Transaction은 실행한 변경의 확정·취소 문제입니다.

Q21. Repository 계층의 역할은 무엇인가요?
A.

SQL과 Database 접근 책임을 다른 Business Logic에서 분리하는 역할입니다.

Q22. 왜 Service가 Transaction 경계를 가질 수 있나요?
A.

하나의 Business 작업이 여러 Repository의 SQL을 포함할 수 있기 때문입니다.

Q23. Connection 오류와 SQL 오류는 어떻게 구분하나요?
A.

Server·Host·Port·User·Password에서 실패했다면 SQL보다 앞선 Connection 단계이고, 연결 후에는 Privilege·Binding·SQL·Constraint 순으로 확인합니다.

Q24. DictCursor에서 KeyError가 나면 무엇을 확인하나요?
A.

실제 SELECT Column 이름이나 Alias와 Dictionary에서 사용하는 Key 이름이 일치하는지 확인합니다.

오늘의 암기 포인트

  • Python과 MySQL 사이에서는 이번 교안에서 PyMySQL을 사용한다.
  • 기본 흐름은 install → import → connect → cursor → execute 이다.
  • Connection은 연결과 Transaction을 담당한다.
  • Cursor는 SQL 실행과 Result 처리를 담당한다.
  • 기본 Cursor는 Tuple 중심, DictCursor는 Dictionary 중심이다.
  • PyMySQL의 대표 Placeholder는 %s다.
  • %s는 직접 Python 문자열 치환을 하라는 의미가 아니다.
  • 한 요소 Tuple은 (value,)다.
  • Placeholder 개수와 Parameter 개수를 맞춘다.
  • Parameter 순서는 SQL의 의미와 맞춘다.
  • execute()는 한 Parameter Set, executemany()는 여러 Parameter Set이다.
  • SELECT는 execute → fetch다.
  • INSERT·UPDATE·DELETE는 Transaction을 생각한다.
  • 성공하면 commit(), 실패하면 rollback()이다.
  • commit()과 close()는 다르다.
  • Password 같은 Secret은 Source Code에서 분리한다.
  • 외부 Input은 SQL 문자열에 직접 결합하지 않고 Parameter Binding한다.
  • root 대신 최소 권한 Application User를 사용한다.
  • Repository는 SQL, Service는 Business Transaction과 연결할 수 있다.
PyMySQL → Connection → Cursor → %s → MySQL

Confusing Point

헷갈리기 쉬운 개념

PyMySQL ≠ MySQL Server

PyMySQL은 Python Driver, MySQL은 Database Server입니다.

Install ≠ Connection

Package 설치와 Server 접속은 다른 단계입니다.

Connection ≠ Cursor

연결·Transaction과 SQL·Result의 역할을 구분합니다.

Tuple Cursor ≠ DictCursor

조회 Row의 표현 방식이 다릅니다.

%s Placeholder ≠ Python 문자열 Formatting

값은 execute()의 Parameter로 별도 전달합니다.

%s ≠ String 전용

Driver Parameter 위치로 이해합니다.

(value) ≠ (value,)

한 요소 Tuple에는 쉼표가 필요합니다.

execute ≠ executemany

한 Parameter Set과 여러 Parameter Set입니다.

commit ≠ close

Transaction 확정과 Connection 종료입니다.

Privilege ≠ Transaction

실행 가능 여부와 변경 확정 여부입니다.

Access denied ≠ SQL Syntax

User·Host·Password·Privilege부터 확인합니다.

Repository ≠ Service

SQL 책임과 Business Logic·Transaction 책임을 구분합니다.
