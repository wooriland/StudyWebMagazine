Python & Data · Python Database · Lesson 00

Python Database 파이썬 데이터베이스 전체 로드맵

Python 프로그램의 메모리에 존재하던 데이터를 어떻게 영구적으로 저장하고 다시 조회할 것인지에서 데이터베이스 학습이 시작됩니다. 이 과정에서는 메모리·파일·데이터베이스의 차이를 이해하고, SQLite에서 가장 작은 데이터베이스 구조를 익힌 뒤 MySQL과 Oracle 같은 서버형 DBMS로 확장합니다.

Memory → File → Database → SQLite → MySQL → Oracle

  • Python Database 과정이 웹 크롤링·백엔드·데이터 분석·시각화와 어떻게 연결되는지 파악한다.
01

Core Concept

왜 데이터베이스가 필요한가?

데이터베이스를 배우는 출발점은 SQL 문법이 아닙니다. 먼저 “Python 프로그램이 종료된 뒤에도 데이터를 남겨 두려면 어떻게 해야 하는가?” 라는 질문에서 시작해야 합니다.

STEP 1 Python 실행 members = []
→
STEP 2 데이터 생성 members.append(...)
→
STEP 3 프로그램 종료 메모리 데이터 소멸
여기에서 첫 번째 질문

회원가입한 사용자, 주문 기록, 수집한 데이터, 분석에 사용할 데이터가 프로그램을 종료할 때마다 사라져도 될까요?

메모리 · 파일 · 데이터베이스 비교

Memory

메모리 저장

list / dict / object
  • 프로그램 실행 중 사용하기 편하다.
  • 빠르게 값을 읽고 변경할 수 있다.
  • 임시 계산과 상태 관리에 적합하다.
  • 일반적으로 프로그램이 종료되면 데이터가 사라진다.
File

파일 저장

TXT / CSV / JSON
  • 프로그램 종료 후에도 데이터가 남는다.
  • 간단한 설정과 데이터 교환에 유용하다.
  • 복잡한 조건 검색·수정·관계 관리는 개발자가 직접 구현해야 한다.
Database

데이터베이스

SQLite / MySQL / Oracle
  • 데이터를 구조화하여 저장한다.
  • SQL을 이용해 데이터를 검색한다.
  • 조건 검색과 정렬을 지원한다.
  • 수정과 삭제를 체계적으로 처리한다.
  • 관계·제약조건·트랜잭션을 관리한다.
Memory → 영구 저장 필요 → Database

06

Python DB Flow

Python에서 반복해서 만나는 DB 처리 메서드

메서드 객체 역할 기억할 점
connect() DB 모듈 데이터베이스와 연결한다. Connection 객체를 얻는다.
cursor() Connection SQL을 실행할 Cursor를 생성한다. SQL 작업을 담당한다.
execute() Cursor 하나의 SQL 또는 한 세트의 데이터를 처리한다. SELECT와 DML 모두 사용한다.
executemany() Cursor 같은 SQL을 여러 데이터에 반복 적용한다. 여러 Row 입력에 유용하다.
fetchone() Cursor 조회 결과에서 한 Row를 가져온다. 더 없으면 None을 생각한다.
fetchmany(n) Cursor 조회 결과에서 일정 개수의 Row를 가져온다. 여러 건을 나누어 처리한다.
fetchall() Cursor 남아 있는 조회 결과를 가져온다. 전체 결과를 한 번에 확인하기 편하다.
commit() Connection 변경 내용을 확정한다. INSERT·UPDATE·DELETE와 연결한다.
rollback() Connection 트랜잭션의 변경을 취소한다. 오류 발생 시 복구 흐름과 연결한다.
close() Cursor / Connection 사용한 연결과 자원을 정리한다. DB 삭제가 아니라 연결 종료다.
가장 중요한 공식

connect → Connection → cursor → Cursor → execute → fetch / commit → close

07

Runnable Example

Python + SQLite 전체 흐름 한 번에 보기

아직 SQLite 세부 문법을 모두 외울 필요는 없습니다. 지금은 코드가 연결 → 테이블 생성 → 입력 → commit → 조회 → fetch → 종료 순서로 진행된다는 점을 확인합니다.

00_database_overview.py Python + SQLite 
import sqlite3


# 1. 데이터베이스 연결
conn = sqlite3.connect("sample.db")


# 2. Cursor 생성
cur = conn.cursor()


# 3. 테이블 생성
cur.execute("""
CREATE TABLE IF NOT EXISTS member (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    tel TEXT
)
""")


# 4. 데이터 입력
cur.execute(
    """
    INSERT INTO member(name, tel)
    VALUES (?, ?)
    """,
    ("홍길동", "010-1234-5678")
)


# 5. 변경 사항 확정
conn.commit()


# 6. 데이터 조회
cur.execute("""
SELECT id, name, tel
FROM member
""")


# 7. 조회 결과를 Python으로 가져오기
rows = cur.fetchall()


# 8. 결과 출력
for row in rows:
    print(row)


# 9. Cursor 종료
cur.close()


# 10. Connection 종료
conn.close()
첫 실행 예시 
(1, '홍길동', '010-1234-5678')

같은 sample.db 파일을 사용하면서 프로그램을 반복 실행하면 기존 데이터가 유지되므로 새로운 Row가 계속 추가될 수 있습니다.

Safe SQL

SQL Parameter와 Transaction 미리 보기

SQL과 실제 값은 분리한다

사용자 입력값을 SQL 문자열에 직접 붙이는 습관보다 DB Driver가 제공하는 Parameter Binding을 사용하는 습관을 처음부터 들이는 것이 좋습니다.

피해야 할 방식 
name = input("이름: ")

sql = f"""
SELECT *
FROM member
WHERE name = '{name}'
"""

cur.execute(sql)
권장 학습 방식 
name = input("이름: ")

cur.execute(
    """
    SELECT *
    FROM member
    WHERE name = ?
    """,
    (name,)
)
SQL VALUES (?, ?)
+
Python Data ("홍길동", "010-1234-5678")
→ Parameter Binding

Transaction

SUCCESS
A 계좌 -10,000 ↓ B 계좌 +10,000 ↓ commit()

Database Comparison

SQLite → MySQL → Oracle은 무엇이 달라질까?

LEVEL 1

SQLite

Python → sqlite3 → DB File

MySQL

LEVEL 3

Oracle

Python → Driver → Oracle DB

DBMS가 바뀌어도 반복되는 핵심

Connection → Cursor → SQL → Result / Transaction

DBMS마다 자료형, 함수, 자동 증가, 계정·권한, 연결 정보에는 차이가 있지만 데이터베이스를 다루는 핵심 사고방식은 계속 이어집니다.

Error Reading

오류 메시지는 발생 단계를 먼저 찾는다

데이터베이스 프로그램에서는 Python 오류와 SQL 오류, Connection 오류와 제약조건 오류가 함께 등장할 수 있습니다. 따라서 오류 이름을 외우기 전에 어느 단계에서 실패했는지를 먼저 판단합니다.

Python 문법 → Python 객체 → Connection → SQL 실행 → DB 제약조건
SyntaxError

Python 문법 문제

괄호, 따옴표, 콜론 등 Python 코드 자체의 문법을 확인합니다.

NameError

변수 이름 문제

conn이나 cur가 먼저 생성되었는지 확인합니다.

TypeError

Python 타입 문제

함수에 전달한 값의 타입이나 인자 형태가 올바른지 확인합니다.

KeyError

Dictionary Key 문제

조회 결과를 Dictionary로 처리할 때 실제 key와 접근하려는 이름이 같은지 확인합니다.

OperationalError

DB 실행 과정 문제

없는 Table, SQL 문법, 파일·연결 상태 등을 확인합니다.

IntegrityError

데이터 규칙 위반

PRIMARY KEY, UNIQUE, NOT NULL 등 테이블의 제약조건을 확인합니다.

ProgrammingError

DB API 사용 흐름 문제

이미 닫힌 Connection이나 Cursor를 다시 사용하지 않았는지 확인합니다.

ModuleNotFoundError

패키지 문제

PyMySQL 같은 외부 패키지와 현재 Python Interpreter가 맞는지 확인합니다.

오류 메시지 읽는 순서

  1. 오류 이름을 확인한다.
  2. 어느 파일의 몇 번째 줄인지 찾는다.
  3. Python / Connection / SQL / DB 중 어느 단계인지 구분한다.
  4. 오류 메시지의 마지막 원인 문장을 읽는다.
  5. 수정한 뒤 다시 같은 흐름으로 실행한다.
예시 
cur.execute(
    "SELECT * FROM members"
)
sqlite3.OperationalError:
no such table: members
sqlite3 → SQLite 단계 OperationalError → SQL 실행 과정 no such table → 해당 Table 없음 members → 확인해야 할 Table 이름

Beginner Mistakes

초보자가 자주 하는 실수

01

DB와 DBMS를 같은 의미로 생각한다.

Database는 데이터 저장 구조, DBMS는 이를 관리하는 시스템으로 구분합니다.

02

Table 하나를 Database 전체라고 생각한다.

하나의 Database 안에는 여러 Table이 존재할 수 있습니다.

03

execute()와 fetch()의 역할을 혼동한다.

execute는 SQL 실행, fetch는 SELECT 결과를 Python으로 가져오는 작업입니다.

04

INSERT 후 commit()을 잊는다.

데이터를 변경하는 작업에서는 Transaction 확정 여부를 반드시 확인합니다.

05

close()를 DB 삭제라고 생각한다.

close는 DB를 삭제하는 명령이 아니라 Connection이나 Cursor를 종료하는 작업입니다.

06

SQLite DB 파일의 위치를 착각한다.

상대 경로는 현재 Working Directory를 기준으로 합니다.

07

SQL 문법 오류를 Python SyntaxError라고 생각한다.

Python 문자열은 정상이어도 DBMS가 SQL 문장을 해석하는 과정에서 실패할 수 있습니다.

08

하나짜리 Tuple의 쉼표를 빼먹는다.

(name,) ← 쉼표 필요
09

사용자 값을 SQL 문자열에 직접 연결한다.

Placeholder와 Parameter Binding을 기본 습관으로 사용합니다.

10

모든 DBMS의 SQL이 완전히 같다고 생각한다.

공통 SQL은 많지만 자료형·함수·자동 증가·계정·연결 방법에는 DBMS별 차이가 있습니다.

Interview Point

면접에서 설명할 수 있어야 하는 핵심 질문

Q1. 데이터베이스가 필요한 이유는 무엇인가요?
A.

프로그램 메모리의 데이터는 실행 종료 후 일반적으로 유지되지 않기 때문에 지속적인 저장 방법이 필요합니다. 데이터베이스는 영구 저장뿐 아니라 SQL을 통한 조회·수정·삭제, 관계 관리와 트랜잭션 같은 데이터 관리 기능을 제공합니다.

Q2. Database와 DBMS의 차이는 무엇인가요?
A.

Database는 구조화된 데이터 저장소이고, DBMS는 그 데이터를 생성·조회·수정·삭제하고 관리하는 시스템입니다.

Q3. RDBMS란 무엇인가요?
A.

Relational Database Management System의 약자로, 데이터를 주로 Table 형태로 관리하고 Table 사이의 관계를 이용하는 데이터베이스 관리 시스템입니다.

Q4. CRUD란 무엇인가요?
A.

Create, Read, Update, Delete의 약자로, SQL에서는 각각 INSERT, SELECT, UPDATE, DELETE와 연결해서 이해할 수 있습니다.

Q5. Connection과 Cursor의 차이는 무엇인가요?
A.

Connection은 Python 프로그램과 DB 사이의 연결을 나타내고, Cursor는 해당 Connection을 통해 SQL을 실행하고 결과를 처리하는 객체입니다.

Q6. execute()와 fetchall()의 차이는 무엇인가요?
A.

execute()는 SQL을 실행하는 역할이고, fetchall()은 SELECT 실행 결과를 Python으로 가져오는 역할입니다.

Q7. commit()과 rollback()은 무엇이 다른가요?
A.

commit()은 데이터 변경을 확정하고, rollback()은 트랜잭션 중 문제가 발생했을 때 변경 내용을 취소합니다.

Q8. SQLite를 먼저 배우는 이유는 무엇인가요?
A.

별도의 DB 서버 환경에 먼저 집중하지 않고 Table, SQL, CRUD, Connection, Cursor, Transaction 같은 데이터베이스 기본 원리를 비교적 작은 환경에서 학습하기 좋기 때문입니다.

Q9. SQLite와 MySQL의 구조적 차이는 무엇인가요?
A.

SQLite는 애플리케이션 가까이에서 DB 파일을 사용하는 Embedded 구조이고, MySQL은 별도의 DB Server에 Client가 접속하는 구조입니다.

Q10. 왜 SQL Parameter를 사용하나요?
A.

SQL 구조와 실제 데이터를 분리해서 처리할 수 있고, 사용자 입력값을 SQL 문자열에 직접 조립하는 방식보다 안전하고 관리하기 좋은 코드를 작성할 수 있기 때문입니다.

Memory

오늘의 암기 포인트

  • Database는 데이터 저장소, DBMS는 그 데이터를 관리하는 시스템이다.
  • 관계형 데이터베이스는 Table · Row · Column을 중심으로 이해한다.
  • Primary Key는 하나의 Row를 고유하게 식별한다.
  • CRUD는 INSERT · SELECT · UPDATE · DELETE 와 연결한다.
  • Python Database의 핵심 공식은 connect → cursor → execute → fetch/commit → close 이다.
  • execute()는 SQL 실행, fetch()는 SELECT 결과 가져오기다.
  • commit()은 변경 확정, rollback()은 변경 취소다.
  • SQLite → MySQL → Oracle 순서로 Embedded 환경에서 Server DB 환경으로 확장한다.
연결 → 커서 → 실행 → 조회 / 확정 → 종료

Confusing Point

헷갈리기 쉬운 개념

DB ≠ DBMS

DB는 데이터 저장 구조, DBMS는 관리 시스템입니다.

execute ≠ fetch

execute는 SQL 실행, fetch는 결과를 가져오는 작업입니다.

execute ≠ commit

SQL 실행과 변경 확정은 서로 다른 단계입니다.

close ≠ delete

close는 데이터 삭제가 아니라 DB 연결 종료입니다.

File ≠ Database Engine

SQLite가 파일을 사용하더라도 단순 파일 저장과 SQLite DB Engine을 이용하는 것은 같은 개념이 아닙니다.

SQLite ≠ MySQL 구조

SQLite는 Embedded DB, MySQL은 별도의 Server와 통신하는 구조입니다.
