Python Database · Lesson 05

sqlite3 연결과 SQL 실행 Database File 생성·열기부터 Connection · Cursor · execute까지

이번 단원에서는 Python의 sqlite3 모듈을 이용해 SQLite Database에 실제로 연결합니다. sqlite3.connect()가 Database File을 어떻게 생성하거나 여는지, 그 결과로 만들어지는 Connection 객체는 무엇인지, Connection에서 Cursor를 얻은 뒤 execute()로 SQL을 어떻게 전달하는지 하나의 실행 흐름으로 이해합니다.

Python → sqlite3 → connect() → Connection → cursor() → Cursor → execute()
FILE DATABASE "sample.db" 파일로 유지
OR
MEMORY DATABASE ":memory:" 메모리에서 사용

  • Database File이 없을 때와 이미 존재할 때의 연결 차이를 이해한다.
  • sample.db와 Connection 객체를 구분할 수 있다.
  • 상대 경로가 어떤 기준으로 해석되는지 이해한다.

  • connect()와 CREATE TABLE, execute()의 역할을 구분한다.

01

Core Concept

Python과 SQLite 사이에는 연결 과정이 필요하다

Python 코드에서 SQL 문자열을 작성했다고 해서 Database가 자동으로 그 SQL을 실행하는 것은 아닙니다. 먼저 Python이 어떤 SQLite Database를 사용할 것인지 연결해야 합니다.

PYTHON STRING 
sql = """
SELECT *
FROM Member
"""

현재는 단순한 Python 문자열입니다.

+
DATABASE CONNECTION 
conn = sqlite3.connect(
    "sample.db"
)

SQL을 실행할 Database를 연결합니다.

→
SQL EXECUTION 
cur.execute(sql)

연결된 Database에 SQL을 실행합니다.

이번 단원의 핵심 3줄 
conn = sqlite3.connect("sample.db")
cur = conn.cursor()
cur.execute("SQL")
connect() Database 연결
cursor() SQL 작업 객체 생성
execute() SQL 실행
02

Concept Separation

sqlite3 · SQLite · sample.db를 구분한다

PYTHON sqlite3

Python 코드에서 SQLite 기능을 사용하도록 연결하는 모듈입니다.

import sqlite3
DATABASE ENGINE SQLite

SQL을 해석하고 Database 처리를 수행하는 Database Engine입니다.

DATABASE FILE sample.db

SQLite가 Table과 Row를 저장하는 실제 Database File입니다.

sqlite3 ≠ SQLite ≠ sample.db
모두 같은 이름처럼 느껴져도 역할은 다르다.

sqlite3는 Python 쪽, SQLite는 Database Engine, sample.db는 실제 Database File이라는 세 계층을 분리해서 기억합니다.

첨부 교안에서도 Python에서 SQLite를 사용하기 위한 첫 코드 단계로 import sqlite3를 제시합니다. 이 모듈을 통해 이후의 sqlite3.connect()를 호출합니다.

05

Create or Open

파일이 없으면 만들고, 있으면 기존 Database를 연다

CASE 01

sample.db가 없음

File 없음 ↓ connect() ↓ sample.db 생성 ↓ Connection 생성
CASE 02

sample.db가 있음

기존 File ↓ connect() ↓ 기존 DB 열기 ↓ 기존 Table·Row 사용
connect()를 이렇게 기억한다.

같은 위치의 기존 sample.db가 있다면 그 Database를 다시 열어 기존 Table과 데이터를 사용할 수 있습니다.

07

Path

"sample.db"는 어디에 만들어질까?

교안에서는 다음과 같이 현재 디렉터리의 Database File을 생성하거나 연다고 설명합니다. 

conn = sqlite3.connect(
    "./sample.db"
)
Current Working Directory + sample.db → 실제 Database 위치
보완 학습 · Working Directory

상대 경로 문제를 실제로 확인하기 위해 Python의 pathlib를 사용할 수 있습니다. 이 부분은 첨부 교안의 직접 실습이 아니라 Database File 위치를 이해하기 위한 보완 내용입니다. 

from pathlib import Path


print("현재 작업 위치:")
print(Path.cwd())


print("Database 절대 경로:")
print(
    Path("sample.db").resolve()
)

execute()

execute() — Python 문자열을 SQL 명령으로 전달한다

cur.execute("""
SELECT *
FROM Member
""")
Python String → Cursor → execute() → SQLite Engine → sample.db
connect() Database 연결
≠
execute() SQL 실행
SQL 문자열을 만드는 것과 실행하는 것은 다르다. 
sql = """
SELECT *
FROM Member
"""

여기까지는 Python 문자열입니다. 

cur.execute(sql)

이 단계에서 SQLite가 SQL로 처리합니다.

13

Minimum Test

가장 작은 연결 테스트 — SELECT 1

Table이 없어도 Connection → Cursor → execute → fetch 흐름 자체를 확인할 수 있습니다.

05_python_sqlite_connect.py Minimum Connection Test 
import sqlite3


# 1. Database 연결
conn = sqlite3.connect(
    "sample.db"
)


# 2. Cursor 생성
cur = conn.cursor()


# 3. SQL 실행
cur.execute("""
SELECT 1
""")


# 4. 결과 한 Row 가져오기
row = cur.fetchone()


# 5. 출력
print(row)


# 6. 종료
cur.close()
conn.close()

File Database Practice

Database File 생성부터 INSERT·SELECT까지 연결하기

File Database sample.db 
import sqlite3
from pathlib import Path


# -------------------------------------------------
# 1. Database File 위치 확인
# -------------------------------------------------

db_path = Path(
    "sample.db"
).resolve()


print("Database:")
print(db_path)


# -------------------------------------------------
# 2. Connection
# -------------------------------------------------

conn = sqlite3.connect(
    db_path
)


# -------------------------------------------------
# 3. Cursor
# -------------------------------------------------

cur = conn.cursor()


# -------------------------------------------------
# 4. Table 준비
# -------------------------------------------------

cur.execute("""
CREATE TABLE IF NOT EXISTS Member (
    _id INTEGER
        PRIMARY KEY
        AUTOINCREMENT,

    name TEXT NOT NULL,

    tel TEXT NOT NULL
)
""")


# -------------------------------------------------
# 5. Row 추가
# -------------------------------------------------

cur.execute(
    """
    INSERT INTO Member(
        name,
        tel
    )
    VALUES (?, ?)
    """,
    (
        "홍길동",
        "010-1111-1111"
    )
)


# -------------------------------------------------
# 6. 변경 확정
# -------------------------------------------------

conn.commit()


# -------------------------------------------------
# 7. SELECT
# -------------------------------------------------

cur.execute("""
SELECT
    _id,
    name,
    tel
FROM Member
ORDER BY _id
""")


# -------------------------------------------------
# 8. Result → Python
# -------------------------------------------------

rows = cur.fetchall()


print("=== Member ===")

for row in rows:
    print(row)


# -------------------------------------------------
# 9. 종료
# -------------------------------------------------

cur.close()
conn.close()
DB Path → connect → Connection → Cursor → CREATE / INSERT → commit → SELECT → fetchall

Persistence

Connection을 닫아도 File Database는 남는다

PROGRAM 1 connect("sample.db") INSERT commit()
→
DISK sample.db Member Row 저장
→
PROGRAM END conn.close() Connection 종료
→
STILL EXISTS sample.db File 유지
→
PROGRAM 2 connect("sample.db") 기존 데이터 조회
conn.close() ≠ sample.db 삭제
16

:memory:

파일 없이 Memory에 SQLite Database 만들기

conn = sqlite3.connect(
    ":memory:"
)
Python → connect(":memory:") → Connection → Memory Database
FILE DB "sample.db"
  • Disk File 사용
  • Connection 종료 후 File 유지
  • 다음 실행에서 다시 열기 가능
  • 실제 로컬 저장에 활용
MEMORY DB ":memory:"
  • Memory에서 Database 사용
  • Database File 없음
  • Connection 생명주기와 밀접
  • 학습·실험·테스트에 활용 가능
Embedded와 :memory:는 같은 개념이 아니다.

Embedded는 SQLite Engine의 동작 구조를 설명하고, :memory:는 Database를 저장하는 위치를 Memory로 사용하는 연결 방식입니다.

17

Memory Practice

:memory: Database에서 Table과 Row 사용하기

Memory Database No DB File 
import sqlite3


conn = sqlite3.connect(
    ":memory:"
)


cur = conn.cursor()


cur.execute("""
CREATE TABLE Member (
    id INTEGER PRIMARY KEY,
    name TEXT
)
""")


cur.execute("""
INSERT INTO Member(
    id,
    name
)
VALUES (
    1,
    '홍길동'
)
""")


conn.commit()


cur.execute("""
SELECT *
FROM Member
""")


rows = cur.fetchall()


print(rows)


cur.close()
conn.close()

Beginner Mistakes

초보자가 자주 하는 실수

01

import sqlite3를 빼먹는다.

sqlite3.connect()를 사용하기 전에 모듈을 import해야 합니다.

02

sqlite3와 Database File을 같은 것으로 생각한다.

sqlite3는 Python 모듈, sample.db는 Database File입니다.

03

connect()가 Table까지 생성한다고 생각한다.

connect는 Database를 열고, Table은 CREATE TABLE SQL로 만듭니다.

04

connect()는 항상 새 Database를 만든다고 생각한다.

File이 존재하면 기존 Database를 엽니다.

05

기존 DB라고 생각했는데 다른 새 DB에 연결한다.

상대 경로와 Working Directory를 확인해야 합니다.

06

sample.db 위치를 확인하지 않는다.

필요하면 Path.resolve()로 실제 경로를 확인합니다.

07

Connection과 Database File을 같은 것으로 생각한다.

conn은 Python Object, sample.db는 File입니다.

08

Connection과 Cursor를 같은 것으로 생각한다.

Connection은 연결, Cursor는 SQL 작업을 담당합니다.

09

conn.cursor라고만 작성한다.

Cursor를 생성하려면 메서드를 실제로 호출해야 합니다.

conn.cursor()
10

SQL 문자열을 만들면 실행됐다고 생각한다.

SQL 문자열과 execute()는 서로 다른 단계입니다.

11

conn.close()가 DB File을 삭제한다고 생각한다.

Error Reading

연결 오류는 SQL보다 앞 단계부터 확인한다

Python → import → Path → connect() → Connection → Cursor → execute() → SQL
SyntaxError

Python 문법

괄호와 따옴표 등 Python 문법부터 확인합니다.

NameError

이름 문제

sqlite3, conn, cur가 정의되어 있는지 확인합니다.

ModuleNotFoundError

실행 환경 문제

현재 PyCharm Interpreter와 Python 실행 환경을 확인합니다.

OperationalError

SQLite 실행 문제

Database File 경로, Table·Column, SQL 등을 확인합니다.

ProgrammingError

객체 상태 문제

이미 닫힌 Connection이나 Cursor를 사용하지 않았는지 확인합니다.

IntegrityError

Constraint 위반

Connection 자체보다 INSERT 데이터와 Table 규칙을 확인합니다.

TypeError

Python Type

Python 함수와 메서드에 전달한 인자를 확인합니다.

KeyError

Dictionary Key

SQLite가 아니라 Python Dictionary 문제일 수 있습니다.

  6. Cursor 객체가 생성됐는지 확인한다.
  7. execute()의 SQL 문법을 확인한다.
  8. Table과 Column 이름을 확인한다.

면접에서 설명할 수 있어야 하는 질문

Q1. Python에서 SQLite를 사용하려면 무엇을 import하나요?
A.

Python의 sqlite3 모듈을 import하여 SQLite 연결과 SQL 실행 기능을 사용합니다.

Q2. sqlite3.connect()는 무엇을 하나요?
A.

지정한 SQLite Database에 연결하고 Connection 객체를 반환합니다. 교안 기준 File이 없으면 새 Database File을 만들고, 있으면 기존 File을 엽니다.

Q3. sample.db와 conn의 차이는 무엇인가요?
A.

sample.db는 실제 Database File이고, conn은 Python에서 그 Database와의 연결을 표현하는 Connection 객체를 참조하는 변수입니다.

Q4. connect()만 호출하면 Table도 생성되나요?
A.

아닙니다. connect()는 Database를 생성하거나 여는 연결 단계이고, Table은 CREATE TABLE SQL을 별도로 실행해야 합니다.

Q5. Connection과 Cursor의 차이는 무엇인가요?
A.

Connection은 Database 연결과 Transaction을 관리하고, Cursor는 SQL 실행과 조회 Result를 담당합니다.

Q6. cursor()의 역할은 무엇인가요?
A.

Connection에서 SQL을 실행할 수 있는 Cursor 객체를 얻는 메서드입니다.

Q7. execute()의 역할은 무엇인가요?
A.

Cursor를 통해 SQL 명령을 SQLite Database에 실행하는 역할을 합니다.

Q8. connect()와 execute()의 차이는 무엇인가요?
A.

connect()는 Database와 연결하는 작업이고, execute()는 연결된 Database에 SQL을 실행하는 작업입니다.

Q9. SQLite 상대 경로 사용 시 무엇을 주의해야 하나요?
A.

상대 경로는 현재 작업 위치를 기준으로 해석되므로 의도한 Database File에 실제로 연결되어 있는지 확인해야 합니다.

Q10. no such table 오류에서 경로를 확인해야 하는 이유는 무엇인가요?
A.

Table이 실제로 없는 경우뿐 아니라, 같은 이름의 다른 Database File에 연결했을 때도 해당 Table을 찾지 못할 수 있기 때문입니다.

Q11. :memory:는 무엇인가요?
A.

SQLite Database를 File이 아니라 Memory에 생성해서 사용하는 연결 방식입니다.

Q12. File Database와 Memory Database의 차이는 무엇인가요?
A.

File Database는 파일로 보존되어 다시 열 수 있고, Memory Database는 메모리에서 사용되며 Connection의 생명주기와 밀접하게 연결됩니다.

Q13. Embedded Database와 :memory:는 같은 의미인가요?
A.

아닙니다. Embedded는 Engine 구조의 특성이고, :memory:는 Database의 저장 위치를 의미합니다.

Q14. conn.close()하면 Database File이 삭제되나요?
A.

아닙니다. Connection을 종료할 뿐이며 File Database 자체를 삭제하지 않습니다.

Q15. SQLite 연결을 배우는 것이 MySQL 학습에 어떻게 도움이 되나요?
A.

세부 Connection 정보는 달라도 connect → Connection → Cursor → execute라는 Database 작업의 큰 구조가 반복되기 때문입니다.

오늘의 암기 포인트

  • import sqlite3로 Python에서 SQLite 사용을 준비한다.
  • sqlite3.connect()는 Database를 열고 Connection 객체를 반환한다.
  • File이 없으면 새 Database File을 만들고, 있으면 기존 File을 연다.
  • sample.db는 File, conn은 Connection 객체다.
  • conn.cursor()는 Cursor 객체를 만든다.
  • cur.execute()는 SQL을 실행한다.
  • connect()와 CREATE TABLE은 서로 다른 단계다.
  • 상대 경로는 현재 Working Directory를 기준으로 해석한다.
  • "sample.db"는 File DB, ":memory:"는 Memory DB다.
  • conn.close()는 Database File 삭제가 아니라 연결 종료다.
sqlite3 → connect → Connection → Cursor → execute

Confusing Point

헷갈리기 쉬운 개념

sqlite3 ≠ sample.db

Python 모듈과 Database File은 다릅니다.

Connection ≠ Database File

Python Object와 실제 File을 구분합니다.

Connection ≠ Cursor

Connection은 연결, Cursor는 SQL 작업입니다.

connect ≠ execute

Database 연결과 SQL 실행은 다른 단계입니다.

connect ≠ CREATE TABLE

Database와 Table 생성을 구분합니다.

close ≠ delete

연결 종료와 File 삭제는 다릅니다.

Embedded ≠ :memory:

Engine 구조와 저장 위치를 구분합니다.

no such table ≠ SQL만의 문제

잘못된 DB File을 열었는지도 확인합니다.
