DDL vs CRUD

Table 구조와 실제 Row를 구분한다

DDL

Schema를 다룬다

CREATE TABLE Member (
    id INTEGER,
    name TEXT
);

데이터를 담을 Table 구조를 만듭니다.

CRUD

Row를 다룬다

INSERT INTO Member(id, name)
VALUES (1, '홍길동');

이미 만들어진 Table 안에 실제 데이터를 넣습니다.

Schema
id name tel

Column과 Constraint 같은 데이터 구조

Row Data
1 홍길동 010-1111

Schema에 맞추어 저장되는 실제 데이터

가장 중요한 구분

CREATE TABLE은 회원 한 명을 추가하는 SQL이 아닙니다. 회원 데이터를 저장할 Table 구조를 만드는 SQL입니다.

Key Design

PRIMARY KEY와 AUTOINCREMENT 구분하기

1 김민수 010-1111
2 김민수 010-2222

이름이 같아도 _id 값이 다르면 서로 다른 Row를 정확하게 구분할 수 있습니다.

PRIMARY KEY 식별 규칙

한 Row를 대표하여 고유하게 식별합니다.

AUTOINCREMENT ID 할당 관련 옵션

교안에서는 자동 증가 Primary Key를 만들기 위해 함께 사용합니다.

_id라는 이름 자체가 Primary Key인 것은 아니다. 
_id INTEGER

_id INTEGER PRIMARY KEY

처럼 PRIMARY KEY가 선언되어야 Primary Key가 됩니다.

Value Rule

NOT NULL과 DEFAULT는 서로 다른 문제를 해결한다

tel CHAR(12)
    NOT NULL
    DEFAULT 'unknown'
NOT NULL NULL을 허용하지 않는다.
NULL → 거절
DEFAULT 값을 생략하면 기본값을 사용한다.
값 생략 → 'unknown'
NULL과 빈 문자열도 다르다.
NULL 값이 없음
'' 길이가 0인 문자열 값

CURRENT_TIMESTAMP 기본값

joindate DATETIME
    DEFAULT CURRENT_TIMESTAMP

가입 시각 값을 따로 지정하지 않았을 때 현재 시각을 기본값으로 사용하기 위한 구조로 교안에서 소개합니다.

09

Data Integrity

UNIQUE와 CHECK로 데이터 규칙 강화하기

UNIQUE(name, tel)

name tel 결과
홍길동 010-1111 첫 조합
홍길동 010-2222 다른 조합
홍길동 010-1111 중복 조합
주의

UNIQUE(name, tel)은 name과 tel을 각각 독립적으로 UNIQUE하게 만든다는 의미가 아니라 두 값의 조합을 기준으로 중복을 검사한다는 뜻입니다.

CHECK(length(tel) >= 3)

tel 입력 → length(tel) → 3 이상? →
YES → 허용 NO → 위반

CHECK 활용 예시

나이 CHECK(age >= 0)
가격 CHECK(price >= 0)
이름 길이 CHECK(length(name) <= 10)

Visual Schema

교안의 Member Table을 한눈에 읽기

CREATE TABLE Member(
    _id INTEGER PRIMARY KEY AUTOINCREMENT,
    name VARCHAR(10) NOT NULL,
    tel CHAR(12) NOT NULL DEFAULT 'unknown',
    joindate DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(name, tel),
    CHECK(length(tel) >= 3)
);
TABLE Member
_id
INTEGER PRIMARY KEY AUTOINCREMENT
name
VARCHAR(10) NOT NULL
tel
CHAR(12) NOT NULL DEFAULT 'unknown'
joindate
DATETIME DEFAULT CURRENT_TIMESTAMP
TABLE CONSTRAINT UNIQUE(name, tel) CHECK(length(tel) >= 3)
한국어로 읽어 보기

Member Table을 만들고, _id를 정수 Primary Key로 사용하며 자동 증가 옵션을 적용합니다. name과 tel은 NULL을 허용하지 않습니다. tel을 생략하면 unknown을, joindate를 생략하면 CURRENT_TIMESTAMP를 사용합니다. 그리고 name과 tel의 조합은 중복을 제한하고, tel의 길이는 최소 3 이상이 되도록 검사합니다.

Python Example

Python에서 Member Table 생성하기

02_sqlite_table_ddl.py CREATE TABLE 
import sqlite3


# 1. SQLite Database 연결
conn = sqlite3.connect("sample.db")


# 2. Cursor 생성
cur = conn.cursor()


# 3. Member Table 생성
cur.execute("""
CREATE TABLE IF NOT EXISTS Member (
    _id INTEGER PRIMARY KEY AUTOINCREMENT,
    name VARCHAR(10) NOT NULL,
    tel CHAR(12) NOT NULL DEFAULT 'unknown',
    joindate DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(name, tel),
    CHECK(length(tel) >= 3)
)
""")


# 4. 변경 내용 반영
conn.commit()


# 5. Cursor / Connection 종료
cur.close()
conn.close()

Supplement Practice

만든 Table 구조를 Python에서 다시 확인하기

이 카드는 첨부 교안의 직접적인 실습 항목이 아니라, Step 1·2에서 이해를 돕기 위해 추가한 보완 실습입니다.

PRAGMA로 Column 구조 확인

import sqlite3


conn = sqlite3.connect("sample.db")
cur = conn.cursor()


cur.execute("PRAGMA table_info(Member)")


columns = cur.fetchall()


for column in columns:
    print(column)


cur.close()
conn.close()
CREATE TABLE → Schema 생성 → PRAGMA table_info(Member) → Column 구조 확인

출력 Tuple의 모든 위치를 지금 외우는 것이 목표가 아니라, “DDL 실행 후 실제 Database 구조를 다시 조회해서 확인할 수 있다.” 는 흐름을 익히는 것이 목적입니다.

Beginner Mistakes

초보자가 자주 하는 실수

01

CREATE TABLE을 데이터 입력이라고 생각한다.

CREATE TABLE은 구조 생성, INSERT는 실제 Row 생성입니다.

02

Database와 Table 생성을 같은 것으로 생각한다.

sqlite3.connect()는 Database 연결, CREATE TABLE은 내부 Table 생성입니다.

03

_id라는 이름만 쓰면 Primary Key라고 생각한다.

Primary Key를 만드는 것은 Column 이름이 아니라 PRIMARY KEY Constraint입니다.

04

PRIMARY KEY와 AUTOINCREMENT를 같은 것으로 생각한다.

Primary Key는 Row 식별, AUTOINCREMENT는 ID 할당과 관련된 옵션입니다.

05

NOT NULL과 DEFAULT를 같은 규칙으로 생각한다.

NOT NULL은 NULL 금지, DEFAULT는 값 생략 시 사용할 기본값입니다.

06

NULL과 빈 문자열을 같은 값으로 생각한다.

NULL은 값 없음, ''은 길이가 0인 문자열입니다.

07

UNIQUE(name, tel)을 각각의 UNIQUE로 생각한다.

두 Column의 조합을 기준으로 중복을 검사합니다.

08

DELETE와 DROP TABLE을 혼동한다.

DELETE는 Row, DROP TABLE은 Table 구조 자체를 제거합니다.

09

ALTER TABLE과 UPDATE를 혼동한다.

ALTER TABLE은 Schema 변경, UPDATE는 실제 Row의 값 변경입니다.

10

IF NOT EXISTS가 기존 Schema를 수정한다고 생각한다.

이미 Table이 존재하면 CREATE를 건너뛸 뿐, 새로운 Column을 자동 추가하지 않습니다.

11

SQLite와 MySQL의 ALTER 문법을 섞어서 외운다.

첨부 교안 후반의 MySQL DDL과 SQLite DDL을 서로 구분해서 공부해야 합니다.

12

DROP TABLE이 sample.db 파일까지 삭제한다고 생각한다.

DROP TABLE은 Database 안의 특정 Table 구조를 삭제합니다.

IntegrityError

ProgrammingError

DB API 사용 순서 문제

이미 닫은 Cursor나 Connection을 다시 사용하지 않았는지 확인합니다.

KeyError

Python Dictionary 문제

SQLite 자체보다 Python Dictionary Key 접근을 확인합니다.

no such table

Table을 찾지 못함

Table 이름뿐 아니라 현재 연결된 DB 파일의 경로도 확인합니다.

문법 오류와 Constraint 오류 구분

SQL 자체 문제 
CREAT TABLE Member (...);

SQLite가 SQL 자체를 정상적으로 해석하지 못합니다.

Constraint 문제 
name TEXT NOT NULL

name = NULL

SQL 실행 구조는 가능하지만 데이터가 Table 규칙을 위반합니다.

오류 메시지를 읽는 순서
  1. 오류 이름을 확인한다.

Interview Point

면접에서 설명할 수 있어야 하는 핵심 질문

Q1. DDL이란 무엇인가요?
A.

Data Definition Language의 약자로, Database의 Schema 구조를 정의하는 SQL입니다. 대표적으로 CREATE, ALTER, DROP이 있습니다.

Q2. CREATE TABLE과 INSERT의 차이는 무엇인가요?
A.

CREATE TABLE은 데이터를 저장할 Table 구조를 만들고, INSERT는 이미 만들어진 Table에 실제 Row 데이터를 추가합니다.

Q3. Schema란 무엇인가요?
A.

Database의 구조에 대한 설계 정보입니다. Table, Column, Type, Key, Constraint 등이 포함됩니다.

Q4. PRIMARY KEY란 무엇인가요?
A.

Table의 각 Row를 고유하게 식별하기 위한 대표 Key입니다.

Q5. AUTOINCREMENT와 PRIMARY KEY는 같은 개념인가요?
A.

아닙니다. PRIMARY KEY는 Row의 식별 규칙이고, AUTOINCREMENT는 정수 식별자 할당과 관련해 추가되는 옵션입니다.

Q6. NOT NULL과 DEFAULT는 어떻게 다른가요?
A.

NOT NULL은 NULL 값을 허용하지 않는 규칙이고, DEFAULT는 해당 Column 값을 생략했을 때 사용할 기본값을 정의합니다.

Q7. NULL과 빈 문자열은 같은가요?
A.

아닙니다. NULL은 값이 없다는 뜻이고, 빈 문자열은 길이가 0인 문자열 값입니다.

Q8. UNIQUE(name, tel)은 어떤 의미인가요?
A.

name과 tel 각각이 독립적으로 유일하다는 뜻이 아니라, 두 Column 값의 조합이 중복되지 않아야 한다는 의미입니다.

Q9. CHECK Constraint는 무엇인가요?
A.

데이터가 사용자가 정의한 논리 조건을 만족하는지 검사하는 Constraint입니다.

Q10. ALTER TABLE의 역할은 무엇인가요?
A.

이미 존재하는 Table의 Schema를 변경합니다. 교안에서는 Table 이름 변경과 새로운 Column 추가를 다룹니다.

Q11. DROP TABLE과 DELETE의 차이는 무엇인가요?
A.

DELETE는 Table 구조를 유지하면서 Row 데이터를 삭제하고, DROP TABLE은 Table 자체를 제거합니다.

Q12. Database Constraint가 필요한 이유는 무엇인가요?
A.

Database 자체에서도 잘못된 데이터를 제한하여 데이터 무결성을 보호할 수 있기 때문입니다.

Memory

오늘의 암기 포인트

  • DDL은 Database Schema를 정의하는 SQL이다.
  • CREATE는 생성, ALTER는 변경, DROP은 삭제다.
  • CREATE TABLE은 Row가 아니라 Table 구조를 만든다.
  • Column 정의는 Column Name + Type + Constraint 구조로 읽는다.
  • PRIMARY KEY는 Row의 대표 식별자다.
  • NOT NULL은 NULL 금지, DEFAULT는 값 생략 시 기본값이다.
  • UNIQUE(name, tel)은 두 값의 조합을 기준으로 중복을 제한한다.
  • CHECK는 논리 조건을 이용해 데이터를 검사한다.
  • ALTER TABLE은 Schema 변경, UPDATE는 Row 값 변경이다.
  • DROP TABLE은 Table 삭제, DELETE는 Row 삭제다.
CREATE → ALTER → DROP

Confusing Point

헷갈리기 쉬운 개념

CREATE ≠ INSERT

CREATE는 구조, INSERT는 Row 데이터를 만듭니다.

ALTER ≠ UPDATE

ALTER는 Schema, UPDATE는 실제 Row 값을 변경합니다.

DROP ≠ DELETE

DROP은 Table, DELETE는 Row를 제거합니다.

PRIMARY KEY ≠ AUTOINCREMENT

Primary Key는 식별 규칙, AUTOINCREMENT는 번호 할당과 관련된 옵션입니다.

NOT NULL ≠ DEFAULT

NULL 금지와 기본값 정의는 서로 다른 역할입니다.

NULL ≠ ''

NULL은 값 없음, ''은 빈 문자열 값입니다.

UNIQUE(name, tel)

각각이 아니라 두 Column의 조합을 검사합니다.

IF NOT EXISTS ≠ Schema Update

기존 Table 구조를 자동으로 최신 상태로 바꾸지 않습니다.
