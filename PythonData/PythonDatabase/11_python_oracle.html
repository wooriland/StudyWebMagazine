01

Core Concept

Database가 바뀌어도 Python DB 구조는 반복된다

SQLite에서는 sqlite3, MySQL에서는 PyMySQL, Oracle에서는 Oracle Driver를 사용합니다. Driver는 달라지지만 Python Database Programming의 기본 구조는 계속 반복됩니다.

SQLite
Python ↓ sqlite3 ↓ DB File
?
MySQL
Python ↓ PyMySQL ↓ MySQL Server
%s
Oracle
Python ↓ Oracle Driver ↓ Oracle DB
:name
Driver → Connection → Cursor → Parameterized SQL → execute → fetch / Transaction
Driver 이름을 외우기 전에 공통 구조를 먼저 잡는다.

SQLite, MySQL, Oracle은 서로 다른 DBMS지만 Python 코드에서 반복되는 객체 책임은 매우 비슷합니다.

Transaction Mode

Manual Transaction을 먼저 이해한다

MANUAL
DML ↓ 업무 상태 판단 ↓ commit / rollback

이번 과정의 기본 사고 방식입니다.

AUTO COMMIT
DML ↓ 자동 확정 Mode

편의 옵션보다 Business Transaction 범위를 먼저 판단합니다.

여러 SQL이 하나의 업무라면 중간마다 확정하면 안 될 수 있다.

Transaction의 기준은 SQL 한 줄이 아니라 “어디까지가 하나의 업무인가?”라는 질문으로 접근합니다.

Error Handling

try · except · finally 구조 

import oracledb


connection = None
cursor = None


try:

    connection = oracledb.connect(
        user="MAVEN",
        password="<PASSWORD>",
        dsn="localhost:1521/orcl"
    )


    cursor = connection.cursor()


    cursor.execute(
        """
        UPDATE ONEMEMBER
        SET PWD = :new_password
        WHERE ID = :member_id
        """,
        new_password="new-password",
        member_id="hong"
    )


    connection.commit()


except Exception as error:

    if connection is not None:
        connection.rollback()


    print(
        "Oracle 작업 실패:"
    )

    print(error)


finally:

    if cursor is not None:
        cursor.close()


    if connection is not None:
        connection.close()
TRY 정상 작업

Connection → SQL → commit

EXCEPT 오류 처리

오류 확인 → rollback

FINALLY Resource 정리

Cursor / Connection close

Connection 생성 자체가 실패할 수 있다.

따라서 rollback이나 close 전에 Connection 객체가 실제로 생성됐는지 확인하는 구조가 필요할 수 있습니다.

Context Manager

with 문으로 Resource Scope 표현하기

Step 1·2에서 추가한 Resource Lifecycle 보완입니다. 

with oracledb.connect(
    user=ORACLE_USER,
    password=ORACLE_PASSWORD,
    dsn=ORACLE_DSN
) as connection:


    with connection.cursor() as cursor:

        cursor.execute(
            """
            SELECT
                ID,
                PWD
            FROM ONEMEMBER
            """
        )


        for row in cursor:

            print(row)
RESOURCE Context Manager

Connection과 Cursor의 사용 범위를 코드 블록으로 표현합니다.

TRANSACTION commit / rollback

Resource Lifecycle과는 별도의 책임으로 이해합니다.

Context Manager ≠ Transaction 자동 해결

Oracle Transaction Complete Flow 
import os
import oracledb


connection = None


try:

    # ------------------------------------------
    # 1. Connection
    # ------------------------------------------

    connection = oracledb.connect(
        user=os.getenv(
            "ORACLE_USER"
        ),
        password=os.getenv(
            "ORACLE_PASSWORD"
        ),
        dsn=os.getenv(
            "ORACLE_DSN",
            "localhost:1521/orcl"
        )
    )


    # ------------------------------------------
    # 2. Cursor
    # ------------------------------------------

    with connection.cursor() as cursor:


        # --------------------------------------
        # 3. Bind Variable UPDATE
        # --------------------------------------

        cursor.execute(
            """
            UPDATE ONEMEMBER
            SET PWD = :new_password
            WHERE ID = :member_id
            """,
            new_password="new-password",
            member_id="hong"
        )


    # ------------------------------------------
    # 4. Success → Commit
    # ------------------------------------------

    connection.commit()


except Exception as error:

    # ------------------------------------------
    # 5. Failure → Rollback
    # ------------------------------------------

    if connection is not None:
        connection.rollback()


    print(
        "Oracle Database 작업 실패:"
    )

    print(error)


finally:

    # ------------------------------------------
    # 6. Resource Close
    # ------------------------------------------

    if connection is not None:
        connection.close()

Beginner Mistakes

초보자가 자주 하는 실수

01

교안의 cx_Oracle과 보완 Driver를 구분하지 않는다.

교안 직접 내용과 Step 1·2 보완을 분리해서 학습합니다.

02

Oracle 연동은 무조건 Instant Client부터 설치한다고 생각한다.

교안의 설치 흐름과 Thin/Thick 보완 구조를 구분합니다.

03

Thin Mode와 Thick Mode를 같은 것으로 생각한다.

Oracle Client Library 사용 구조를 구분합니다.

04

Host·Port·Service Name을 하나의 값처럼 생각한다.

DSN 안의 서로 다른 역할로 분리합니다.

05

orcl을 모든 Oracle 환경의 고정 Service Name으로 외운다.

orcl은 첨부 교안의 예제 값입니다.

06

Connection과 Cursor를 같은 객체로 생각한다.

연결/Transaction과 SQL/Result 책임을 구분합니다.

07

MySQL의 %s를 Oracle에서도 사용한다.

Oracle 보완 학습에서는 :name 또는 :1을 사용합니다.

08

SQLite의 ?를 Oracle에서도 사용한다.

Driver별 Parameter Style을 확인합니다.

09

User Input을 SQL 문자열에 직접 결합한다.

Bind Variable로 Data를 전달합니다.

10

Bind Variable로 Table Name까지 바꾸려고 한다.

Bind는 일반적으로 Data Value와 연결합니다.

11

SELECT 실행 즉시 Python 변수에 결과가 생긴다고 생각한다.

Cursor 반복 또는 fetch 단계가 필요합니다.

12

조회 결과가 없으면 무조건 Exception이라고 생각한다.

fetchone()의 None을 정상 분기로 처리할 수 있습니다.

13

모든 목록에 fetchall()만 사용한다.

단건·Batch·전체 Result 목적을 구분합니다.

14

SQL Developer의 세미콜론을 Python execute 문자열에도 습관적으로 넣는다.

실행 도구의 차이를 구분합니다.

15

DML 뒤 commit을 생각하지 않는다.

성공하면 변경 확정을 고려합니다.

16

오류 뒤 rollback을 생각하지 않는다.

하나의 Transaction 전체를 취소해야 할 수 있습니다.

17

close를 저장 명령으로 생각한다.

commit과 Resource 종료는 서로 다른 책임입니다.

18

Connection 생성 실패에도 무조건 rollback한다.

Connection 객체가 실제 생성됐는지 확인합니다.

19

Context Manager를 사용하면 Transaction 처리가 필요 없다고 생각한다.

Resource와 Transaction을 분리합니다.

20

Password를 Source Code에 그대로 저장한다.

환경 변수 또는 별도 설정으로 분리합니다.

21

ORA-01017을 SQL Syntax 오류로 판단한다.

Credential·Login 계층부터 확인합니다.

22

ORA-01031을 Password 오류로 판단한다.

Privilege 계층을 확인합니다.

23

ORA-00942를 무조건 Table 삭제라고 판단한다.

Object·Schema·Privilege를 함께 확인합니다.

24

Client Library 문제에서 SQL만 수정한다.

오류가 SQL 이전 환경 계층인지 먼저 판단합니다.

25

Repository 내부에서 항상 commit한다.

더 큰 Business Transaction은 Service가 관리할 수 있습니다.

Interview Point

면접에서 설명할 수 있어야 하는 질문

Q1. 첨부 교안에서는 어떤 Oracle Python Driver를 사용하나요?
A.

첨부 교안에서는 cx_Oracle을 사용하며, Instant Client와 PATH 설정, cx_Oracle.connect() 순서로 연동합니다.

Q2. Step 1·2에서 현재 학습 방향은 어떻게 보완했나요?
A.

교안의 Connection·Cursor 구조는 유지하면서 Oracle Python Driver를 python-oracledb 관점으로 추가 정리했습니다.

Q3. Thin Mode와 Thick Mode는 무엇이 다른가요?
A.

이번 학습에서는 Thin Mode를 Driver 중심 연결, Thick Mode를 Oracle Client Library를 사용하는 구조로 구분합니다.

Q4. Oracle Instant Client는 교안에서 왜 등장하나요?
A.

교안의 cx_Oracle 환경에서 Python이 Oracle Client Library를 이용하도록 준비하는 과정으로 등장합니다.

Q5. Oracle Connection에 필요한 주요 정보는 무엇인가요?
A.

User, Password, Host, Port, Service Name을 중심으로 이해합니다.

Q6. DSN은 어떻게 이해하면 되나요?
A.

어떤 Oracle Database Service에 연결할지 표현하는 Connection 정보로 이해하며, 이번 학습에서는 host:port/service_name 구조로 봅니다.

Q7. localhost:1521/orcl은 어떻게 읽나요?
A.

localhost는 Host, 1521은 교안의 Port, orcl은 교안에서 사용하는 Service Name입니다.

Q8. Connection과 Cursor의 차이는 무엇인가요?
A.

Connection은 Database 연결과 Transaction, Cursor는 SQL 실행과 Result 처리를 담당합니다.

Q9. 첨부 교안에서는 SELECT 결과를 어떻게 처리하나요?
A.

for id, pwd in cursor처럼 Cursor 자체를 반복하여 Row를 읽습니다.

Q10. Oracle에서도 fetch 계열 메서드를 사용할 수 있나요?
A.

Step 1·2에서는 Cursor 반복과 함께 fetchone, fetchmany, fetchall을 같은 Result 처리 흐름으로 정리했습니다.

Q11. Oracle 기본 조회 Row는 어떤 구조로 이해하나요?
A.

이번 입문 과정에서는 Tuple 형태를 기준으로 이해합니다.

Q12. Oracle Named Bind Variable은 어떤 형태인가요?
A.

:member_id처럼 앞에 콜론을 붙인 이름을 사용하는 형태로 공부합니다.

Q13. Oracle 위치 기반 Bind는 어떻게 표현하나요?
A.

Step 1·2에서는 :1, :2 같은 위치 기반 Bind도 함께 정리했습니다.

Q14. SQLite·MySQL·Oracle Parameter 문법을 비교해 보세요.
A.

대표적으로 SQLite는 ?, PyMySQL은 %s, Oracle 보완 학습에서는 :name을 사용합니다. 공통 목적은 SQL Code와 Data를 분리하는 것입니다.

Q15. Bind Variable을 사용하는 이유는 무엇인가요?
A.

외부 Data를 SQL 문자열에 직접 결합하지 않고 SQL Code와 Data를 분리하기 위해 사용합니다.

Q16. Bind Variable로 Table 이름을 전달해도 되나요?
A.

이번 과정에서는 Bind Variable을 Data Value 전달과 연결하고, Table·Column 같은 SQL 구조 요소와 구분해서 학습합니다.

Q17. execute와 executemany의 차이는 무엇인가요?
A.

execute는 한 SQL 실행 단위, executemany는 같은 SQL에 여러 Parameter Set을 적용할 때 사용합니다.

Q18. DML이 성공하면 무엇을 해야 하나요?
A.

Transaction 변경을 확정하려면 Connection의 commit()을 사용합니다.

Q19. DML 중 오류가 발생하면 무엇을 생각해야 하나요?
A.

미확정 변경 전체를 취소해야 한다면 rollback()을 고려합니다.

Q20. commit과 close는 같은가요?
A.

아닙니다. commit은 Transaction 확정, close는 Resource 종료입니다.

Q21. Context Manager와 Transaction은 같은 책임인가요?
A.

아닙니다. Context Manager는 Resource Scope, commit과 rollback은 Transaction 책임으로 구분합니다.

Q22. 왜 Oracle Password를 Source Code와 분리하나요?
A.

Credential이 Source Repository, 코드 공유나 화면 노출을 통해 유출될 위험을 줄이고 환경별 설정을 분리하기 위해서입니다.

Q23. ORA-01017은 어떤 계층부터 확인하나요?
A.

User, Password, 접속 대상과 Credential·Login 계층을 먼저 확인합니다.

Q24. ORA-01031은 어떤 오류로 분류하나요?
A.

로그인 이후 Database Operation에 필요한 Privilege가 부족한 방향으로 읽습니다.

Q25. ORA-00942에서는 무엇을 확인하나요?
A.

Object 이름, Schema, Table/View 존재 여부와 접근 Privilege를 확인합니다.

Q26. Repository 계층의 역할은 무엇인가요?
A.

SQL, Bind Variable, execute, fetch 같은 Database 접근 책임을 Business Logic과 분리합니다.

Q27. SQLite·MySQL·Oracle에서 가장 중요한 공통 구조는 무엇인가요?
A.

Driver → Connection → Cursor → Parameterized SQL → execute → fetch 또는 commit/rollback → close 구조입니다.
