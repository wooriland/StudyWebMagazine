Selenium과 브라우저 자동화

앞 단원까지는 requests로 서버의 HTTP Response를 받고 BeautifulSoup으로 HTML을 분석했습니다. 이번 단원부터는 Selenium WebDriver를 이용해 실제 Browser Session을 생성하고 직접 제어합니다. 페이지 이동, 요소 검색, 문자열 입력, 클릭, Form 제출, Text·Attribute 추출, 현재 HTML Source 확보와 Browser Session 종료까지 Selenium의 기본 실행 흐름을 공부합니다.

핵심 공식 Python → Selenium → WebDriver → Browser → WebElement → Interaction → Python Data

01

Core Concept

Selenium과 Browser Automation의 핵심

Selenium의 핵심은 HTML Parser를 하나 더 배우는 것이 아닙니다. Python 코드가 WebDriver를 통해 실제 Browser의 상태와 사용자 행동을 제어한다 는 점을 이해하는 것이 가장 중요합니다.

Requests · BeautifulSoup · Selenium 역할 비교

URL → Response
서버와 통신
HTML PARSER

BeautifulSoup

이미 확보한 HTML을 파싱하고 Tag·Text·Attribute를 탐색합니다.

HTML → Tag
HTML 분석
BROWSER AUTOMATION

Selenium

실제 Browser를 실행하고 페이지 이동·입력·클릭을 자동화합니다.

Python → Browser
Browser 제어
Selenium은 BeautifulSoup의 업그레이드 버전이 아니다.

세 도구는 경쟁 관계라기보다 서로 다른 계층의 역할을 담당합니다. 정적 HTML이면 Requests + BeautifulSoup이 더 단순할 수 있고, 실제 Browser 상호작용이 필요할 때 Selenium을 검토합니다.

Selenium이 필요한 대표적인 이유

STATIC response.text에 데이터 존재
Server → HTML → BeautifulSoup
DYNAMIC JavaScript 실행 후 데이터 생성
HTML → JS → API → DOM
버튼 클릭 후 데이터 표시 검색어 입력 후 결과 생성 스크롤 후 추가 데이터 로딩 Tab·Modal 등 UI 상태 변화 JavaScript 동적 DOM 로그인 후 접근

from pathlib import Path

from selenium import webdriver
from selenium.webdriver.common.by import By


html_path = (
    Path(
        "selenium_practice.html"
    )
    .resolve()
    .as_uri()
)


driver = webdriver.Chrome()


try:

    # --------------------------------------------
    # 1. 페이지 이동
    # --------------------------------------------

    driver.get(
        html_path
    )


    # --------------------------------------------
    # 2. 현재 페이지 확인
    # --------------------------------------------

    print(
        "TITLE:",
        driver.title,
    )


    print(
        "URL:",
        driver.current_url,
    )


    # --------------------------------------------
    # 3. 제목 Element
    # --------------------------------------------

    title = driver.find_element(
        By.ID,
        "title",
    )


    print(
        "TITLE TEXT:",
        title.text,
    )


    # --------------------------------------------
    # 4. 검색 Input
    # --------------------------------------------

    keyword = driver.find_element(
        By.ID,
        "keyword",
    )


    keyword.clear()


    keyword.send_keys(
        "Python Selenium"
    )


    # --------------------------------------------
    # 5. Button 클릭
    # --------------------------------------------

    button = driver.find_element(
        By.ID,
        "search-button",
    )


    button.click()


    # --------------------------------------------
    # 6. 변경된 결과
    # --------------------------------------------

    result = driver.find_element(
        By.ID,
        "result",
    )


    print(
        "RESULT:",
        result.text,
    )


    # --------------------------------------------
    # 7. Attribute
    # --------------------------------------------

    link = driver.find_element(
        By.ID,
        "detail-link",
    )


    print(
        "HREF:",
        link.get_attribute(
            "href"
        ),
    )


    print(
        "DATA-ID:",
        link.get_attribute(
            "data-id"
        ),
    )


    # --------------------------------------------
    # 8. Page Source
    # --------------------------------------------

    html = driver.page_source


    print(
        "PAGE SOURCE LENGTH:",
        len(html),
    )


finally:

    # --------------------------------------------
    # 9. Session 종료
    # --------------------------------------------

    driver.quit()

Common Mistakes

Selenium 초보자가 자주 하는 실수

01

Selenium을 HTML Parser라고 생각한다

Selenium = Browser ≠ BeautifulSoup = Parser

08 단원의 코드를 버리지 않는다.

Selenium이 동적인 Browser 상태를 만드는 역할을 하고, 기존 BeautifulSoup Parser가 HTML을 분석하도록 분리하면 이미 작성한 Selector·Cleaning·Validation 코드를 다시 사용할 수 있습니다.

Browser Automation 함수를 분리하는 기본 구조 

from selenium import webdriver


def fetch_dynamic_html(
    url: str,
) -> str:

    driver = webdriver.Chrome()


    try:

        driver.get(
            url
        )


        return driver.page_source


    finally:

        driver.quit()
아직 완성된 동적 수집 함수는 아니다.

실제 동적 페이지에서는 필요한 Element가 준비될 때까지 기다려야 할 수 있습니다. 다음 단원에서 이 함수에 WebDriverWait과 Expected Conditions를 연결하게 됩니다.

Interview Point

Selenium 면접 핵심 질문

Q1 Selenium은 무엇인가요?

A.

WebDriver를 통해 실제 Browser를 자동화하는 도구입니다. 페이지 이동, Element 검색, 문자열 입력, 클릭과 Form 제출 같은 사용자 행동을 코드로 수행할 수 있습니다.

Q2 Requests와 Selenium은 무엇이 다른가요?

A.

Requests는 HTTP Client로 서버와 직접 통신하고, Selenium은 WebDriver를 통해 실제 Browser Session을 제어합니다.

Requests = HTTP / Selenium = Browser

Q3 BeautifulSoup과 Selenium의 차이는 무엇인가요?

A.

BeautifulSoup은 확보된 HTML을 파싱하는 도구이고, Selenium은 실제 Browser를 실행하고 조작하는 도구입니다.

Q4 WebDriver란 무엇인가요?

A.

Selenium 코드가 Browser를 제어하기 위해 사용하는 핵심 Browser Automation 인터페이스입니다.

Q5 WebDriver와 WebElement의 차이는 무엇인가요?

A.

WebDriver는 Browser Session 전체를 제어하고, WebElement는 현재 DOM 안의 특정 Element를 나타냅니다.

Q6 driver.get()은 무엇을 하나요?

A.

현재 WebDriver Browser Session을 지정된 URL로 이동시킵니다. Requests의 get()처럼 Response 객체를 받는 API와 목적이 다릅니다.

Q7 find_element()과 find_elements()의 차이는?

A.

find_element()은 단일 WebElement 검색, find_elements()는 여러 WebElement 검색에 사용합니다.

Q8 Selenium에서 사용할 수 있는 Locator에는 무엇이 있나요?

A.

대표적으로 ID, Name, Class Name, CSS Selector, XPath, Tag Name 등이 있습니다.

By.ID / By.NAME / By.CLASS_NAME / By.CSS_SELECTOR / By.XPATH / By.TAG_NAME

Q9 BeautifulSoup에서 공부한 CSS Selector를 Selenium에서도 사용할 수 있나요?

A.

가능합니다. By.CSS_SELECTOR를 이용해 앞 단원에서 학습한 CSS Selector를 Selenium Locator로 사용할 수 있습니다.

Q10 Selenium에서는 XPath를 사용할 수 있나요?

A.

교안에서는 Selenium의 Element 검색 방식으로 CSS Selector와 XPath를 모두 설명합니다. By.XPATH와 XPath 표현식을 사용합니다.

Q11 send_keys()는 무엇인가요?

A.

Input 등 Keyboard Interaction이 가능한 WebElement에 문자열이나 Keyboard 입력을 전달합니다.

Q12 click()과 submit()은 어떻게 다른가요?

A.

click()은 특정 Element를 클릭하는 동작이고, submit()은 Form 제출 동작과 연결됩니다.

Q13 element.text와 get_attribute()의 차이는?

A.

element.text는 표시 Text를 읽고, get_attribute()는 href·src·data-*와 같은 HTML Attribute 값을 읽습니다.

Q14 page_source는 무엇인가요?

A.

현재 WebDriver 페이지의 HTML Source 문자열입니다. 이 값을 BeautifulSoup에 전달해 기존 HTML Parser를 사용할 수도 있습니다.

Q15 driver.quit()은 왜 필요한가요?

A.

Browser 자동화가 끝난 뒤 WebDriver Session과 관련 리소스를 종료하기 위해 사용합니다.

Q16 NoSuchElementException은 왜 발생하나요?

A.

현재 검색 Context에서 Locator와 일치하는 Element를 찾지 못한 경우 발생할 수 있습니다. 현재 페이지, Locator, Element 생성 시점을 함께 확인합니다.

Q17 Element를 찾았는데 click()이 실패할 수 있나요?

A.

가능합니다. Element가 숨겨져 있거나 비활성 상태이거나, Popup·Overlay 등 다른 UI가 위를 가리고 있을 수 있습니다.

Q18 Browser가 열렸는데 Element를 못 찾는 이유는 무엇인가요?

A.

Browser의 기본 Page Load 완료 시점과 JavaScript·Ajax 처리 이후 필요한 Element가 DOM에 생성되는 시점이 다를 수 있기 때문입니다. 이 문제를 다음 단원의 Wait로 해결합니다.

오늘의 암기 포인트

Driver → Get → Find → Interact → Read → Quit
  • Requests = HTTP Client
  • BeautifulSoup = HTML Parser
  • Selenium = Browser Automation
  • Python → WebDriver → Browser
  • webdriver.Chrome() = Browser Session 생성
  • driver.get() = Browser 페이지 이동
  • WebDriver = Browser 전체
  • WebElement = DOM Element 하나
  • find_element() = 단일 Element
  • find_elements() = 여러 Element
  • By.CSS_SELECTOR = CSS 표현식
  • By.XPATH = XPath 표현식
  • send_keys() = 입력
  • click() = 클릭
  • submit() = Form 제출
  • element.text = Text
  • get_attribute() = Attribute
  • driver.page_source = 페이지 HTML Source
  • execute_script() = Browser JavaScript 실행
  • driver.quit() = Session 종료
  • Browser가 열렸다고 원하는 Element가 준비된 것은 아니다.
  • Element가 존재한다고 현재 Interaction 가능한 것도 아니다.

Requests vs Selenium

HTTP Response 중심과 실제 Browser Session 중심의 차이입니다.

BeautifulSoup vs Selenium

HTML Parsing과 Browser Automation의 차이입니다.

WebDriver vs WebElement

Browser 전체와 DOM Element 하나의 차이입니다.

requests.get() vs driver.get()

HTTP 요청과 Browser Navigation의 차이입니다.

find_element() vs find_elements()

단일 검색과 복수 검색의 차이입니다.

select_one() vs find_element()

BeautifulSoup은 실패 시 None이 될 수 있지만, Selenium 단일 검색은 예외가 발생할 수 있습니다.

CSS vs XPath

Locator 종류에 맞는 표현식을 사용해야 합니다.

element.text vs page_source

특정 Element Text와 페이지 전체 HTML 문자열의 차이입니다.

click() vs submit()

Element 클릭과 Form 제출의 차이입니다.

Element 존재 vs Interaction 가능

DOM에 있다고 해서 바로 클릭·입력 가능한 것은 아닙니다.

Page Load vs Element Ready

페이지가 열렸어도 JavaScript Element는 아직 준비 중일 수 있습니다.

close() vs quit()

Window/Tab 종료와 WebDriver Session 종료를 구분합니다.
