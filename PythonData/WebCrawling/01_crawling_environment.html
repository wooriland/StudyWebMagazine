Python & Data · Web Crawling · Lesson 01

Anaconda, conda와 Jupyter 환경

웹크롤링 코드를 작성하기 전에 프로젝트 전용 Python 실행환경을 준비합니다. Anaconda와 conda의 역할을 구분하고, web_crawling 가상환경을 만든 뒤 Anaconda Prompt, PyCharm, Jupyter Notebook이 모두 같은 Python Interpreter를 사용하도록 연결합니다.

이번 단원의 핵심 어떤 패키지를 설치했는가보다 어떤 Python에서 실행하고 있는가를 먼저 확인한다.
Anaconda → conda → web_crawling → Python Interpreter → PyCharm · Jupyter

학습 목표

  • Anaconda, conda, 가상환경, Python Interpreter의 역할을 구분할 수 있다.
  • base 환경과 web_crawling 환경의 차이를 설명할 수 있다.
  • conda 환경을 생성·조회·활성화·비활성화·삭제할 수 있다.
  • 패키지가 컴퓨터 전체가 아니라 특정 Python 환경에 설치된다는 의미를 이해한다.
  • Jupyter Notebook, Kernel, ipykernel의 관계를 설명할 수 있다.
  • PyCharm Interpreter와 Jupyter Kernel을 동일한 web_crawling 환경으로 연결할 수 있다.
  • sys.executable을 이용해 실제 실행 중인 Python의 위치를 확인할 수 있다.
  • ModuleNotFoundError를 만났을 때 환경과 패키지 위치를 먼저 검사할 수 있다.

예제 3. 패키지 설치 여부 확인 

from importlib.util import find_spec


packages = {
    "requests": "requests",
    "BeautifulSoup": "bs4",
    "Selenium": "selenium",
    "Scrapy": "scrapy",
}


for package_name, module_name in packages.items():

    installed = (
        find_spec(module_name) is not None
    )

    status = (
        "설치됨"
        if installed
        else "설치되지 않음"
    )

    print(
        f"{package_name}: {status}"
    )
실행 결과 예

BeautifulSoup: 설치됨
Selenium: 설치되지 않음
Scrapy: 설치되지 않음

아직 배우지 않은 패키지가 설치되지 않았어도 이번 단원에서는 문제가 아닙니다. 앞으로 각 라이브러리 단원에서 필요한 패키지를 순서대로 설치하면 됩니다.

05

Common Mistakes

초보자가 자주 하는 실수

01

base와 web_crawling을 같은 환경으로 생각한다

잘못된 생각

“Anaconda에서 만든 Python이니까 모두 같은 환경이다.”

올바른 생각

base와 web_crawling은 별도의 Python과 패키지 공간을 가질 수 있다.

02

다른 환경에 패키지를 설치한다 

(base) python -m pip install requests

그런데 PyCharm은 web_crawling을 사용한다면 requests를 찾지 못할 수 있습니다.

03

PyCharm Interpreter를 확인하지 않는다

Prompt web_crawling ≠ PyCharm base

같은 소스코드를 실행해도 사용할 수 있는 패키지와 Python 버전이 달라질 수 있습니다.

04

Jupyter Kernel의 표시 이름만 믿는다

Kernel 메뉴의 이름보다 실제 Interpreter 경로가 중요합니다. 

import sys

print(sys.executable)
05

create, activate, deactivate, remove를 혼동한다

create 만든다
activate 사용한다
deactivate 사용을 종료한다
remove 환경을 삭제한다
06

프로젝트 폴더와 가상환경을 같은 것으로 생각한다

프로젝트 폴더에는 내가 작성한 코드가, 가상환경에는 Python Interpreter와 설치된 패키지가 존재합니다.

07

패키지가 안 보이면 PATH부터 수정한다

먼저 환경과 Interpreter를 확인해야 합니다.

  1. 현재 환경 확인
  2. sys.executable 확인
  3. 패키지 설치 위치 확인
  4. PyCharm / Jupyter 연결 확인
08

환경 오류를 HTTP 오류라고 생각한다

ModuleNotFoundError HTTP 요청 전
403 Forbidden HTTP 응답 후

requests 자체를 import하지 못한다면 아직 웹 서버에 요청을 보내지도 못한 상태입니다.

06

Error Reading

환경 오류 메시지 읽는 법

이번 단원에서는 HTTP 상태 코드나 HTML 선택자보다 먼저 Python 실행환경 오류를 구분하는 연습을 합니다.

conda → Environment → Interpreter → Package → Jupyter Kernel → PyCharm
ModuleNotFoundError

현재 Python이 모듈을 찾지 못함 

ModuleNotFoundError:
No module named 'requests'

requests가 컴퓨터에 전혀 없는 것일 수도 있지만, 다른 환경에 설치되어 있을 수도 있습니다.

확인 순서
  1. sys.executable
  2. python -m pip show requests
  3. PyCharm Interpreter
  4. Jupyter Kernel
ImportError

모듈은 찾았지만 원하는 이름을 가져오지 못함

패키지 버전 차이, API 변경, 잘못된 import 대상 등을 확인합니다.

확인 Python 버전 · 패키지 버전 · import 대상
NameError

Python 이름이 정의되지 않음 

print(sys.executable)

# sys를 import하지 않았다면
# NameError

환경 설정 문제가 아니라 Python 코드에서 이름을 정의하지 않은 문제입니다.

SyntaxError

Python 문법 오류

괄호, 따옴표, 콜론 등 코드 문법 자체를 확인합니다. conda 환경 문제와 구분해야 합니다.

FileNotFoundError

지정한 파일 또는 경로를 찾지 못함

프로젝트 폴더의 파일 경로 문제인지, 가상환경 문제인지 분리해서 판단합니다.

'jupyter' is not recognized

현재 Shell에서 Jupyter 실행 파일을 찾지 못함

현재 환경에 Jupyter가 설치되어 있는지, web_crawling 환경이 활성화되어 있는지 확인합니다.

08

Interview Point

면접에서 설명할 수 있어야 할 질문

Q1 Python 가상환경을 사용하는 이유는 무엇인가요?

A.

프로젝트마다 필요한 Python 버전과 패키지 구성이 다를 수 있기 때문에 환경을 독립적으로 관리하고 의존성 충돌을 줄이기 위해 사용합니다.

Q2 Anaconda와 conda의 차이는 무엇인가요?

A.

Anaconda는 Python과 여러 개발 도구를 사용할 수 있도록 구성한 배포 환경이고, conda는 가상환경과 패키지를 관리하는 도구입니다.

Anaconda = 배포 환경 / conda = 관리 도구

Q3 base 환경은 무엇인가요?

A.

Anaconda 설치와 연결되는 기본 conda 환경입니다. 프로젝트별 패키지를 분리하려면 별도의 환경을 만들어 사용할 수 있습니다.

Q4 Python Interpreter란 무엇인가요?

A.

Python 소스코드를 읽고 실제로 실행하는 Python 실행 프로그램입니다. 가상환경마다 다른 Interpreter를 사용할 수 있습니다.

Q5 Jupyter Notebook과 Kernel의 차이는 무엇인가요?

A.

Jupyter Notebook은 코드를 작성하고 결과를 확인하는 인터페이스이고, Kernel은 실제 코드를 실행할 Python 환경과 연결됩니다.

Notebook → Kernel → Python Interpreter

Q6 ipykernel을 사용하는 이유는 무엇인가요?

A.

특정 Python 가상환경을 Jupyter에서 선택 가능한 Kernel로 등록해 해당 환경의 Interpreter와 패키지를 Notebook에서 사용하기 위해서입니다.

Q7 PyCharm에서 가상환경을 연결해야 하는 이유는 무엇인가요?

A.

PyCharm 프로젝트가 어느 Python Interpreter를 사용해 실행될지 지정해야 그 환경에 설치된 패키지를 사용할 수 있기 때문입니다.

Q8 패키지를 설치했는데 ModuleNotFoundError가 발생하는 이유는 무엇인가요?

A.

패키지를 설치한 Python 환경과 실제 코드를 실행하는 Python 환경이 다를 수 있습니다. 먼저 sys.executable로 현재 Interpreter를 확인해야 합니다.

Q9 conda activate와 deactivate의 차이는 무엇인가요?

A.

activate는 특정 환경을 현재 Shell에서 사용하도록 전환하고, deactivate는 현재 환경의 사용을 종료합니다. deactivate는 환경 삭제가 아닙니다.

Q10 프로젝트 폴더와 가상환경의 차이는 무엇인가요?

A.

프로젝트 폴더에는 개발자가 만든 소스코드와 데이터가 들어가고, 가상환경에는 코드를 실행할 Python과 설치된 패키지가 들어갑니다.

Q11 Jupyter와 PyCharm을 함께 사용하는 이유는 무엇인가요?

A.

Jupyter는 요청 결과와 데이터, 선택자를 단계별로 실험하기 편하고, PyCharm은 검증한 코드를 함수·모듈·클래스로 구조화하여 프로젝트로 관리하기 좋습니다.

Q12 현재 Python 환경을 가장 간단하게 확인하는 방법은 무엇인가요?

A. 
import sys

print(sys.executable)

현재 코드를 실제로 실행하고 있는 Python Interpreter의 경로를 확인할 수 있습니다.

오늘의 암기 포인트

어떤 패키지를 설치했는가보다 어떤 Python에서 실행하는가를 먼저 확인한다.
  • Anaconda = Python 개발 배포 환경
  • conda = 환경 + 패키지 관리 도구
  • base 와 web_crawling 은 서로 다른 환경이다.
  • conda create = 환경 생성
  • conda activate = 환경 활성화
  • conda deactivate = 환경 사용 종료
  • 패키지는 특정 Python 환경에 설치된다.
  • Jupyter Notebook과 Python Interpreter는 같은 것이 아니다.
  • ipykernel은 Python 환경을 Jupyter Kernel로 연결한다.
  • PyCharm Interpreter, Jupyter Kernel Python, Console Python이 같은 환경을 가리키는지 확인한다.
  • 환경 디버깅의 핵심 코드는 sys.executable이다.

헷갈리기 쉬운 개념

Anaconda vs conda

Anaconda는 전체 배포 환경, conda는 환경과 패키지를 관리하는 도구입니다.

base vs web_crawling

둘은 별개의 Python 환경이며 설치된 패키지도 서로 다를 수 있습니다.

Project vs Environment

프로젝트에는 소스코드, 환경에는 Interpreter와 패키지가 존재합니다.

Jupyter vs Kernel

Jupyter는 Notebook 인터페이스, Kernel은 실제 실행환경과 연결되는 부분입니다.

deactivate vs remove

deactivate는 사용 종료, remove는 환경 자체의 삭제입니다.

ModuleNotFoundError vs 403 Forbidden

전자는 Python 환경·패키지 단계, 후자는 실제 HTTP 요청 이후의 응답 단계 문제입니다.
