Python & Data · Web Crawling · Lesson 10

동적 페이지와 대기 처리

앞 단원에서는 Selenium으로 Browser를 실행하고, Element를 찾고, 입력하고, 클릭하는 방법을 배웠습니다. 하지만 JavaScript·AJAX로 동작하는 페이지에서는 Browser가 열렸다는 사실과 필요한 Element가 준비되었다는 사실이 같지 않습니다. 이번 단원에서는 Python 코드의 실행 시점과 Browser의 동적 상태를 맞추기 위해 Implicit Wait, Explicit Wait, WebDriverWait, Expected Conditions와 TimeoutException을 공부합니다.

이번 단원의 핵심 “몇 초를 기다릴까?”보다 “어떤 상태가 되면 다음 코드로 넘어갈까?”를 먼저 생각한다.
Interaction → JavaScript → Wait → Expected Condition → DOM Ready → Next Action

학습 목표

  • Page Load 완료와 Dynamic Element Ready 상태를 구분할 수 있다.
  • AJAX·JavaScript에 의해 DOM이 뒤늦게 변하는 흐름을 설명할 수 있다.
  • Wait를 단순한 지연이 아니라 Browser와 Python 사이의 동기화로 이해할 수 있다.
  • time.sleep()과 Selenium Wait의 차이를 설명할 수 있다.
  • driver.implicitly_wait()의 기본 동작을 설명할 수 있다.
  • Implicit Wait와 Explicit Wait의 적용 범위와 목적을 구분할 수 있다.
  • WebDriverWait, until(), Expected Conditions의 관계를 설명할 수 있다.
  • presence_of_element_located()의 의미를 이해한다.
  • Presence와 Visibility를 구분할 수 있다.
  • Visibility와 Clickable을 구분할 수 있다.
  • Text 변화, Loading 제거, DOM 교체와 같은 다양한 완료 조건을 이해한다.
  • iframe 문제를 Timing 문제와 Context 문제로 구분할 수 있다.
  • NoSuchElementException과 TimeoutException의 발생 과정 차이를 설명할 수 있다.
  • Locator Error와 Timing Error를 서로 구분할 수 있다.
  • Timeout 발생 시 단순히 시간을 늘리지 않고 현재 URL, Locator, Condition, DOM 상태를 순서대로 점검할 수 있다.
  • Wait를 실제 로그인·동적 Scraping 흐름에 연결할 수 있다.
01

Core Concept

Selenium Wait의 핵심 개념

Selenium Wait에서 가장 중요한 것은 “얼마나 오래 멈출 것인가?”가 아니라 “Browser의 어떤 상태를 완료로 볼 것인가?” 입니다.

Page Load 완료와 Element Ready는 다르다

PAGE LOAD 기본 페이지가 열림
HTML → Browser

Browser가 기본 문서를 표시할 수 있는 상태입니다.

ELEMENT READY 필요한 동적 상태까지 준비
JS → AJAX → DOM

실제 자동화 대상 Element가 생성되거나 표시·활성화된 상태입니다.

반드시 기억 Page Load 완료 ≠ Element Ready

AJAX·JavaScript가 DOM을 늦게 변경할 수 있다

1 Click
→
2 JavaScript
→
3 AJAX / Fetch
→
4 Response
→
5 DOM Change

Python은 click() 다음 줄을 빠르게 실행할 수 있지만, Browser에서는 JavaScript와 비동기 처리가 아직 진행 중일 수 있습니다.

같은 코드가 실행 속도에 따라 성공하거나 실패할 수 있다

FAST Element가 0.1초 후 생성
click() → result 생성 → find 성공
SLOW Element가 1.8초 후 생성
click() → find 실행 → Element 없음

from selenium import webdriver
from selenium.webdriver.common.by import By

from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC

from selenium.common.exceptions import TimeoutException


html_path = (
    Path(
        "selenium_wait_practice.html"
    )
    .resolve()
    .as_uri()
)


driver = webdriver.Chrome()


try:

    # ------------------------------------------
    # 1. 페이지 이동
    # ------------------------------------------

    driver.get(
        html_path
    )


    # ------------------------------------------
    # 2. 늦게 생성되는 Element
    # ------------------------------------------

    driver.find_element(
        By.ID,
        "load-button",
    ).click()


    message = WebDriverWait(
        driver,
        3,
    ).until(
        EC.presence_of_element_located(
            (
                By.ID,
                "late-message",
            )
        )
    )


    print(
        "MESSAGE:",
        message.text,
    )


    # ------------------------------------------
    # 3. 늦게 표시되는 Input
    # ------------------------------------------

    driver.find_element(
        By.ID,
        "show-button",
    ).click()


    late_input = WebDriverWait(
        driver,
        3,
    ).until(
        EC.visibility_of_element_located(
            (
                By.ID,
                "late-input",
            )
        )
    )


    late_input.send_keys(
        "Visibility 완료"
    )


    # ------------------------------------------
    # 4. 늦게 활성화되는 Button
    # ------------------------------------------

    driver.find_element(
        By.ID,
        "enable-button",
    ).click()


    submit_button = WebDriverWait(
        driver,
        3,
    ).until(
        EC.element_to_be_clickable(
            (
                By.ID,
                "delayed-submit",
            )
        )
    )


    submit_button.click()


    # ------------------------------------------
    # 5. Loading 종료 대기
    # ------------------------------------------

    WebDriverWait(
        driver,
        3,
    ).until(
        EC.invisibility_of_element_located(
            (
                By.ID,
                "loading",
            )
        )
    )


    print(
        "동적 처리 완료"
    )


except TimeoutException:

    )

05

Common Mistakes

Selenium Wait에서 자주 하는 실수

01

Page가 열리면 모든 Element가 준비됐다고 생각한다

Page Load ≠ Element Ready
02

sleep() 시간을 계속 늘린다

1초 → 3초 → 10초 → 원인은 그대로
03

implicitly_wait()를 sleep()이라고 생각한다

Implicit Wait는 모든 코드를 고정 시간만큼 멈추는 것이 아니라, Element를 찾는 과정에 대기 동작을 적용하는 개념입니다.

04

timeout을 실제 대기 시간이라고 생각한다

조건이 timeout보다 빨리 만족되면 그 시점에 다음 코드로 넘어갈 수 있습니다.

05

Presence와 Visibility를 같은 것으로 생각한다

Presence → DOM Visibility → DOM + 표시
06

Visible이면 Clickable이라고 생각한다

화면에 보이는 Button도 disabled 상태라면 아직 클릭할 수 없을 수 있습니다.

07

모든 상황에 Presence만 사용한다

존재 → Presence 입력 → Visibility 클릭 → Clickable 로딩 종료 → Invisibility
08

Locator 오류를 Wait로 해결하려 한다

wrong-id ≠ 더 긴 timeout

Locator가 틀렸다면 오래 기다려도 해당 Element는 나타나지 않습니다.

09

TimeoutException이면 시간을 먼저 늘린다

URL Locator Condition Click Frame DOM
10

403·404 페이지에서 원하는 Element를 기다린다

404 → #product 없음 → TimeoutException
11

iframe 문제를 시간 문제로만 본다

iframe 내부 Element는 기다리는 시간뿐 아니라 현재 Browser Context가 올바른지도 확인해야 합니다.

12

DOM이 바뀌었는데 기존 Element를 계속 사용한다

old_element → DOM 교체 → stale
13

Implicit와 Explicit를 이유 없이 중첩한다

어떤 Wait 전략을 사용하는지 명확하게 설계하고, 학습 단계에서는 두 방식의 동작을 각각 분리해 확인합니다.

14

모든 코드 줄에 WebDriverWait를 붙인다

Wait는 주로 Navigation, Click, AJAX, Modal, DOM 교체 등 Browser 상태가 바뀌는 경계에 배치합니다.

15

첫 Product가 나오면 전체 목록 로딩이 끝났다고 생각한다

Product 하나의 Presence와 전체 목록 로딩 완료는 다른 조건일 수 있습니다. 실제 사이트의 완료 신호를 확인합니다.

08

Interview Point

Selenium Wait 면접 핵심 질문

Q1 Selenium에서 Wait가 왜 필요한가요?

A.

페이지가 열렸더라도 JavaScript나 AJAX로 생성되는 Element가 즉시 준비되지 않을 수 있습니다. Python 실행 시점과 Browser의 동적 상태를 맞추기 위해 Wait를 사용합니다.

Q2 Page Load와 Element Ready는 무엇이 다른가요?

A.

Page Load는 기본 문서가 로드된 상태이고, Element Ready는 JavaScript·비동기 처리 이후 실제 사용할 Element가 생성·표시·활성화된 상태입니다.

Q3 time.sleep()과 Selenium Wait는 어떻게 다른가요?

A.

sleep은 Browser 상태와 관계없이 정해진 시간 동안 실행을 멈추지만, Selenium Wait는 특정 조건을 확인하고 조건이 만족되는 시점에 진행하도록 설계할 수 있습니다.

Q4 Implicit Wait란 무엇인가요?

A.

Element 검색 시 대상 Element가 바로 발견되지 않으면 지정한 최대 시간 동안 기다리도록 설정하는 암묵적 대기입니다.

driver.implicitly_wait(5)

Q5 Explicit Wait란 무엇인가요?

A.

특정 코드 위치에서 특정 Expected Condition이 만족될 때까지 최대 시간 동안 기다리는 방식입니다.

WebDriverWait(driver, 10).until(...)

Q6 Implicit와 Explicit Wait의 차이는 무엇인가요?

A.

Implicit Wait는 Element 검색에 기본 대기를 적용하고, Explicit Wait는 특정 코드 지점에서 Presence·Visibility·Clickable 같은 구체적인 상태를 기다릴 수 있습니다.

Q7 WebDriverWait의 timeout은 항상 실제 대기 시간인가요?

A.

아닙니다. 최대 대기 시간이며 조건이 그보다 빨리 만족되면 즉시 다음 코드로 진행할 수 있습니다.

Q8 until()은 무엇을 하나요?

A.

전달받은 Expected Condition을 확인하고 조건이 만족될 때까지 대기합니다. 제한 시간 안에 성공하면 결과를 반환하고, 끝까지 실패하면 TimeoutException으로 연결됩니다.

Q9 Expected Condition이란 무엇인가요?

A.

Browser가 어떤 상태가 되면 대기를 종료할 것인지 정의한 완료 조건입니다.

Q10 Presence와 Visibility의 차이는 무엇인가요?

A.

Presence는 Element가 DOM에 존재하는 상태이고, Visibility는 DOM에 존재하면서 화면에 보이는 상태까지 의미합니다.

Q11 Clickable은 어떤 상태인가요?

A.

Element가 화면에 표시되고 활성화되어 클릭 동작을 수행할 수 있는 상태입니다.

Q12 TimeoutException은 무엇인가요?

A.

WebDriverWait가 지정한 제한 시간까지 Expected Condition을 만족하지 못했을 때 발생하는 예외입니다.

Q13 TimeoutException이 발생하면 timeout을 늘리면 되나요?

A.

먼저 현재 URL, Locator, Expected Condition, 이전 Click 성공 여부, Frame Context와 실제 DOM 변화를 확인해야 합니다. Locator가 잘못된 경우 시간을 늘려도 해결되지 않습니다.

Q14 NoSuchElementException과 TimeoutException의 차이는?

A.

단순 find_element()가 현재 시점에 찾지 못하면 NoSuchElementException으로 연결될 수 있고, WebDriverWait으로 일정 시간 조건을 확인했지만 끝까지 실패하면 TimeoutException이 발생합니다.

Q15 DOM에는 있는데 입력이 안 되는 이유는 무엇일 수 있나요?

A.

Element가 Presence 상태이지만 아직 Hidden 상태일 수 있습니다. 실제 입력 목적이라면 Visibility 같은 더 적절한 상태 조건을 검토해야 합니다.

Q16 Loading이 사라질 때까지 기다릴 수도 있나요?

A.

Step 1·2 보완 내용에서는 Loading Element가 보이지 않게 되는 상태를 완료 기준으로 잡는 Invisibility 조건을 연결했습니다.

Q17 Stale Element와 Wait는 어떻게 연결되나요?

A.

DOM이 다시 그려지면 기존 WebElement가 이전 DOM의 참조가 될 수 있습니다. 기존 Element가 더 이상 유효하지 않은 상태를 확인한 뒤 현재 DOM에서 다시 검색하는 흐름으로 연결할 수 있습니다.

Q18 iframe Element를 오래 기다리기만 하면 찾을 수 있나요?

A.

반드시 그렇지는 않습니다. iframe은 Timing 외에도 Browser Context가 다른 문제일 수 있으므로 적절한 Frame 전환 여부를 확인해야 합니다.

오늘의 암기 포인트

Action → Wait → Condition → Ready → Next
  • Page Load 완료 ≠ Element Ready
  • Wait = Python과 Browser 상태의 동기화
  • time.sleep() = 고정 시간 대기
  • Implicit Wait = Element 검색 기본 대기
  • Explicit Wait = 특정 상태 대기
  • driver.implicitly_wait(5) = Implicit Wait
  • WebDriverWait(driver, 10) = 최대 대기 시간
  • timeout 10초 ≠ 항상 10초 대기
  • until() = 조건 확인
  • Expected Condition = 완료 기준
  • Presence = DOM 존재
  • Visibility = DOM 존재 + 화면 표시
  • Clickable = Visible + Enabled
  • Text 변화 = Text Condition
  • Loading 제거 = Invisibility
  • DOM 교체 = Staleness
  • iframe = Timing뿐 아니라 Context 확인
  • NoSuchElementException = 지금 찾지 못함
  • TimeoutException = 기다렸지만 끝까지 조건 실패
  • Locator Error ≠ Timing Error
  • Timeout 발생 시 시간을 늘리기 전에 페이지와 조건부터 확인

헷갈리기 쉬운 개념

Page Load vs Element Ready

기본 페이지가 열리는 시점과 실제 동적 Element가 사용할 수 있는 시점의 차이입니다.

sleep vs Wait

고정된 시간 동안 멈추는 것과 Browser 조건을 기다리는 것의 차이입니다.

Implicit vs Explicit

Element 검색에 기본 대기를 적용하는 것과 특정 상태를 명시적으로 기다리는 차이입니다.

timeout vs 실제 대기 시간

timeout은 최대 시간이며 조건이 빨리 만족되면 더 일찍 진행할 수 있습니다.

Presence vs Visibility

DOM 존재와 실제 화면 표시 상태의 차이입니다.

Visibility vs Clickable

화면에 보이는 것과 실제 활성화되어 클릭 가능한 상태의 차이입니다.

Locator Error vs Timing Error

잘못된 위치 지정과 맞는 Element를 너무 일찍 찾는 문제의 차이입니다.

NoSuchElement vs TimeoutException

현재 검색 실패와 대기 후에도 조건이 끝까지 실패한 차이입니다.

HTTP Timeout vs Selenium Timeout

서버 Response 대기와 Browser Expected Condition 대기의 차이입니다.

Timing vs Frame Context

늦게 생성되는 문제와 다른 iframe 안에 있는 문제를 구분합니다.

Element Presence vs 전체 목록 완료

첫 Element 등장과 전체 비동기 데이터 로딩 완료는 다를 수 있습니다.
