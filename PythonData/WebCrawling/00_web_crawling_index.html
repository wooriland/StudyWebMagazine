Web Crawling 웹크롤링 전체 로드맵

웹크롤링은 단순히 웹페이지의 HTML을 가져오는 작업이 아닙니다. URL을 준비하고 HTTP 요청을 보내 응답을 받은 뒤, 필요한 데이터를 선택하고 정제·검증하여 CSV·JSON·데이터베이스에 저장하는 전체 데이터 수집 파이프라인입니다.

핵심 공식 요청 → 응답 → 파싱 → 선택 → 정제 → 검증 → 저장 → 반복

학습 목표

  • 웹크롤링과 웹 스크레이핑의 차이를 설명할 수 있다.
  • URL → HTTP 요청 → 응답 → HTML/JSON → 데이터 저장으로 이어지는 전체 파이프라인을 이해한다.
  • urllib, requests, BeautifulSoup, Selenium, Scrapy의 역할을 구분할 수 있다.
  • 정적 페이지와 동적 페이지의 차이를 이해하고 상황에 맞는 수집 방법을 판단할 수 있다.
  • 403, 404, 429, Timeout과 같은 HTTP 상황과 선택자 오류를 단계별로 해석할 수 있다.
  • 수집한 데이터를 CSV·JSON·Database와 데이터 분석 과정으로 연결할 수 있다.

Python Example

전체 파이프라인 코드 미리보기

아직 각 라이브러리를 자세히 배우기 전이므로 모든 문법을 외우려고 하지 않아도 됩니다. 아래 코드에서 요청 → 응답 검사 → 파싱 → 선택 → 저장 순서만 먼저 확인합니다. 

from pathlib import Path
import csv

import requests
from bs4 import BeautifulSoup


URL = "https://example.com/"
OUTPUT_PATH = Path("output") / "example_heading.csv"


def fetch_html(url: str) -> str:
    """웹 서버에 요청을 보내 HTML 문자열을 반환합니다."""

    headers = {
        "User-Agent": "WebCrawlingStudy/1.0",
    }

    response = requests.get(
        url,
        headers=headers,
        timeout=(3, 10),
    )

    print("상태 코드:", response.status_code)
    print("최종 URL:", response.url)
    print(
        "Content-Type:",
        response.headers.get("Content-Type")
    )

    response.raise_for_status()

    content_type = response.headers.get(
        "Content-Type",
        "",
    ).lower()

    if "text/html" not in content_type:
        raise ValueError(
            f"HTML 응답이 아닙니다: {content_type}"
        )

    return response.text


def parse_heading(html: str) -> dict[str, str]:
    """HTML에서 h1 요소를 찾아 Python dict로 변환합니다."""

    soup = BeautifulSoup(
        html,
        "html.parser",
    )

    heading = soup.select_one("h1")

    if heading is None:
        raise LookupError(
            "h1 요소를 찾지 못했습니다."
        )

    return {
        "url": URL,
        "heading": heading.get_text(
            " ",
            strip=True,
        ),
    }


def save_csv(
    record: dict[str, str],
    path: Path,
) -> None:
    """Python dict 데이터를 CSV 파일에 저장합니다."""

    path.parent.mkdir(
        parents=True,
        exist_ok=True,
    )

    with path.open(
        "w",
        encoding="utf-8",
        newline="",
    ) as file:

        writer = csv.DictWriter(
            file,
            fieldnames=[
                "url",
                "heading",
            ],
        )

        writer.writeheader()
        writer.writerow(record)


def main() -> None:

    try:
        html = fetch_html(URL)

        record = parse_heading(html)

        save_csv(
            record,
            OUTPUT_PATH,
        )

        print("수집 결과:", record)
        print(
            "저장 완료:",
            OUTPUT_PATH.resolve(),
        )

    except requests.Timeout:
        print(
            "요청 제한 시간 안에 "
            "응답을 받지 못했습니다."
        )

    except requests.HTTPError as error:

        status_code = (
            error.response.status_code
            if error.response is not None
            else "알 수 없음"
        )

        print(
            "HTTP 오류:",
            status_code,
        )

    except requests.RequestException as error:
        print(
            "네트워크 요청 오류:",
            error,
        )

    except (ValueError, LookupError) as error:
        print(
            "데이터 처리 오류:",
            error,
        )

    except OSError as error:
        print(
            "파일 저장 오류:",
            error,
        )


if __name__ == "__main__":
    main()

HTTP 상태 코드

상태 코드 의미 크롤링에서 확인할 것
200 OK HTTP 요청 성공 정말 원하는 페이지가 반환되었는지 본문까지 확인
301 / 302 다른 URL로 이동 최종 response.url 확인
400 잘못된 요청 파라미터와 요청 데이터 확인

429 요청 과다 요청 속도·반복 횟수·간격 확인
500 서버 내부 오류 서버 상태와 재시도 필요성 확인

200 OK를 받았다고 해서 크롤링이 성공한 것은 아닙니다. 로그인 페이지, 차단 안내, 검색 결과 없음 페이지가 HTTP 200으로 반환될 수도 있습니다.

08

Interview Point

면접에서 설명할 수 있어야 할 핵심 질문

Q1 웹크롤링과 웹 스크레이핑의 차이는 무엇인가요?

A.

웹크롤링은 정해진 규칙에 따라 웹페이지와 링크를 순회하는 과정이고, 웹 스크레이핑은 방문한 페이지에서 필요한 특정 데이터를 추출하는 과정입니다. 실제 프로젝트에서는 두 작업이 함께 사용되는 경우가 많습니다.

Q2 requests와 BeautifulSoup의 차이는 무엇인가요?

A.

requests는 HTTP 요청을 보내고 서버의 응답을 받는 역할을 하며, BeautifulSoup은 전달받은 HTML을 파싱하여 필요한 태그와 데이터를 찾는 역할을 합니다.

requests는 가져오고, BeautifulSoup은 찾는다.

Q3 정적 페이지와 동적 페이지의 차이는 무엇인가요?

A.

정적 페이지는 서버 응답 HTML 안에 필요한 데이터가 포함되어 있는 반면, 동적 페이지는 JavaScript 실행이나 추가 네트워크 요청 후 화면에 데이터가 만들어질 수 있습니다.

Q4 HTTP 403 Forbidden은 무엇인가요?

A.

서버가 요청을 이해했지만 해당 요청의 접근을 허용하지 않았다는 의미입니다. 공개 여부, 인증, Header, 접근 정책, 요청 빈도 등을 확인해야 합니다.

Q5 HTTP 200이면 크롤링에 성공한 것인가요?

A.

아닙니다. HTTP 200은 HTTP 요청이 성공적으로 처리되었다는 의미일 뿐이며, 실제 본문이 로그인 페이지나 오류 안내 페이지일 수도 있습니다. 원하는 데이터가 실제 응답에 존재하는지 추가 검증해야 합니다.

Q6 BeautifulSoup의 select_one()과 select() 차이는 무엇인가요?

A.

select_one()은 첫 번째 요소 하나를 반환하며 찾지 못하면 None을 반환합니다. select()는 일치하는 모든 요소를 리스트로 반환하며 결과가 없으면 빈 리스트를 반환합니다.

Q7 Selenium을 사용하는 이유는 무엇인가요?

A.

WebDriver를 통해 실제 브라우저를 제어할 수 있기 때문에 클릭, 입력, 스크롤과 같이 브라우저 동작이 필요하거나 JavaScript 이후 생성되는 요소를 처리해야 할 때 사용할 수 있습니다.

Q8 Selenium에서 Explicit Wait가 필요한 이유는 무엇인가요?

A.

JavaScript 또는 Ajax로 요소가 늦게 생성될 수 있기 때문에 특정 요소나 상태가 준비될 때까지 기다린 뒤 다음 코드를 실행하기 위해 사용합니다.

Q9 Scrapy는 언제 사용하면 좋은가요?

A.

많은 URL과 링크를 반복적으로 수집하고 데이터 추출·정제·저장을 구조적으로 관리해야 할 때 유용합니다. Spider, Item, Pipeline, Settings 등으로 역할을 분리합니다.

Q10 크롤링 데이터가 나오지 않을 때 무엇부터 확인하나요?

A.

URL → HTTP 상태 코드 → 최종 URL → Content-Type → 실제 응답 본문 → 선택자 → 정제 결과 → 저장 직전 데이터 순으로 확인합니다.

오늘의 암기 포인트

요청 → 응답 → 파싱 → 선택 → 정제 → 검증 → 저장 → 반복
  • urllib = URL 요청의 기본 구조
  • requests = 읽기 쉬운 HTTP 요청
  • BeautifulSoup = HTML 파싱과 데이터 선택
  • Selenium = 실제 브라우저 제어
  • Scrapy = 대규모·반복 크롤링 구조화
  • 단일 선택 실패는 None, 복수 선택 실패는 [] 형태로 확인할 수 있다.
  • 200 OK 와 데이터 수집 성공은 같은 의미가 아니다.
  • 데이터는 반드시 수집 → 정제 → 검증 → 저장 순서로 생각한다.

헷갈리기 쉬운 개념

requests vs BeautifulSoup

requests는 데이터를 가져오고, BeautifulSoup은 받아온 HTML에서 데이터를 찾습니다.

BeautifulSoup vs Selenium

BeautifulSoup은 이미 받은 HTML을 분석하고, Selenium은 실제 브라우저와 DOM을 제어합니다.

Selenium vs Scrapy

Selenium은 브라우저 자동화 중심, Scrapy는 여러 HTTP 요청과 데이터 처리 구조 중심입니다.

HTTP 성공 vs 크롤링 성공

HTTP 200이어도 원하는 데이터가 없는 페이지를 받은 것이라면 수집에는 실패한 것입니다.
