Python & Data · Web Crawling · Lesson 06

BeautifulSoup과 HTML 파싱

requests로 받아온 response.text는 HTML처럼 보이지만 Python 입장에서는 아직 하나의 긴 문자열(str)입니다. 이번 단원에서는 BeautifulSoup(html, "html.parser")를 이용해 HTML 문자열을 탐색 가능한 구조로 파싱하고, find(), find_all(), Tag의 텍스트와 속성값을 읽어 Python 데이터로 변환하는 기본 구조를 공부합니다.

핵심 공식 HTML str → BeautifulSoup → Tag → Text / Attribute → Python Data
requests → response.text → HTML str → BeautifulSoup() → soup → Tag → Python Data

학습 목표

  • Requests와 BeautifulSoup의 역할 차이를 설명할 수 있다.
  • HTML Parsing이 무엇인지 설명할 수 있다.
  • HTML 문자열과 BeautifulSoup 객체를 구분할 수 있다.
  • BeautifulSoup(html, "html.parser")의 두 인자가 무엇인지 설명할 수 있다.
  • HTML 문서를 Tree 구조로 바라볼 수 있다.
  • BeautifulSoup의 Tag 객체가 무엇인지 이해한다.
  • soup.태그명, find(), find_all()의 차이를 설명할 수 있다.
  • find() 실패 시 None, 복수 검색 결과가 없을 때 빈 결과가 된다는 것을 이해한다.
  • .name, .string, .text, .get_text()를 구분할 수 있다.
  • tag["href"], tag.get("href"), tag.attrs를 이용해 HTML Attribute를 읽을 수 있다.
  • id와 class_ 조건으로 요소를 찾을 수 있다.
  • 문자열 검색, 정규표현식 검색, limit의 기본 역할을 이해한다.
  • HTTP 오류와 BeautifulSoup 검색 실패를 서로 다른 단계의 문제로 구분할 수 있다.
  • 정적 HTML과 JavaScript로 생성되는 동적 DOM의 차이를 이해한다.
01

Core Concept

BeautifulSoup의 핵심 개념

BeautifulSoup 학습의 핵심은 함수 이름을 많이 암기하는 것이 아니라 HTML 문자열을 구조로 바꾸고, 그 구조에서 Tag를 찾아 Text와 Attribute를 Python 값으로 꺼내는 과정 을 이해하는 것입니다.

Requests와 BeautifulSoup의 역할

HTTP CLIENT

requests

웹 서버에 HTTP Request를 보내고 Response를 받아오는 역할입니다.

URL → GET → Response
“HTML을 어떻게 가져올까?”
HTML PARSER

BeautifulSoup

받아온 HTML 문자열을 구조적으로 파싱하고 Tag, Text, Attribute를 탐색합니다.

HTML → Parse → Tag
“HTML 안에서 무엇을 찾을까?”
핵심 구분

Requests = 가져오기, BeautifulSoup = 분석하기입니다. BeautifulSoup 자체를 브라우저나 HTTP Client처럼 이해하지 않습니다.

Parsing이란?

BEFORE HTML String 
<article>
    <h2>Python</h2>
    <p>웹크롤링</p>
</article>
Python str
Parsing →
AFTER HTML Structure 
article
├─ h2
│  └─ Python
└─ p
   └─ 웹크롤링
탐색 가능한 구조
기억하기

Parsing은 문자열을 단순히 출력하는 것이 아니라 문법과 계층 관계를 해석하여 탐색 가능한 구조로 만드는 과정 입니다.

BeautifulSoup 객체 만들기

soup = BeautifulSoup(

2nd Argument "html.parser" Parser

HTML 문자열을 어떤 Parser로 해석할지를 지정합니다.

Tag에서 Text 읽기

.string 단순 문자열 구조

내부 구조가 단순할 때 하나의 문자열을 확인하기 편합니다. 중첩 구조에서는 기대한 결과가 나오지 않을 수 있습니다.

.text 내부 Text

Tag 아래에 포함된 텍스트를 편리하게 가져오는 속성입니다.

.get_text() Text 추출

내부 텍스트를 읽는 메서드로, 실무에서는 strip=True 같은 옵션을 사용하기 편합니다.

tag.get_text(strip=True)
"\n Python 입문서 \n" → "Python 입문서"

HTML Attribute 읽기

tag["href"] 직접 접근

속성이 존재하면 값을 반환하지만 속성이 없으면 KeyError 가능성이 있습니다.

tag.get("href") 안전하게 확인

속성이 없을 경우 기본적으로 None으로 확인하기 편합니다.

tag.attrs 전체 Attribute

현재 Tag가 가지고 있는 속성 전체를 확인합니다.

id와 class 조건

ID 
title = soup.find(
    "h1",
    id="main-title",
)

특정 id 값을 가진 요소를 찾습니다.

CLASS 
products = soup.find_all(
    "div",
    class_="product",
)

Python의 class 예약어 때문에 BeautifulSoup Keyword Argument에서는 class_를 사용합니다.

문자열 검색과 검색 개수 제한

STRING string="Python 입문서"

특정 문자열과 일치하는 내용을 검색합니다.

OR string=["Python", "Database"]

여러 문자열 후보를 검색 조건으로 사용할 수 있습니다.

REGEX re.compile("입문서")

문자열 검색 조건에 정규표현식을 연결할 수 있습니다.

LIMIT limit=2

여러 검색 결과 중 필요한 개수만 제한합니다.

예제 9. 문자열과 정규표현식 검색 

import re

from bs4 import BeautifulSoup


HTML = """
<h2>Python 입문서</h2>
<h2>Database 입문서</h2>
<h2>JavaScript 실전</h2>
"""


soup = BeautifulSoup(
    HTML,
    "html.parser",
)


exact = soup.find_all(
    string="Python 입문서"
)


multiple = soup.find_all(
    string=[
        "Python 입문서",
        "Database 입문서",
    ]
)


pattern = soup.find_all(
    string=re.compile(
        "입문서"
    )
)


print(exact)
print(multiple)
print(pattern)

예제 11. 상품 하나를 Python dict로 변환 

from bs4 import BeautifulSoup


HTML = """
<div
    class="product"
    data-id="P001"
>

    <h2>
        Python 입문서
    </h2>

    <p class="price">
        25000
    </p>

    <a href="/products/P001">
        상세보기
    </a>

</div>
"""


soup = BeautifulSoup(
    HTML,
    "html.parser",
)


product = soup.find(
    "div",
    class_="product",
)


product_id = product.get(
    "data-id"
)


name_tag = product.find(
    "h2"
)


price_tag = product.find(
    "p",
    class_="price",
)


link_tag = product.find(
    "a"
)


name = (
    name_tag.get_text(
        strip=True
    )
    if name_tag is not None
    else None
)


price = (
    price_tag.get_text(
        strip=True
    )
    if price_tag is not None
    else None
)


link = (
    link_tag.get(
        "href"
    )
    if link_tag is not None
    else None
)


record = {
    "product_id":
        product_id,

    "name":
        name,

    "price":
        price,

    "link":
        link,
}


print(
    record
)

Common Mistakes

초보자가 자주 하는 실수

01

BeautifulSoup이 HTTP Request도 보내는 것으로 생각한다

requests = HTTP ≠ BeautifulSoup = Parse
02

HTML 문자열과 soup 객체를 같은 것으로 생각한다

response.text → str ≠ soup → Parsed Object
03

find() 결과가 항상 Tag라고 생각한다

조건에 맞는 요소가 없다면 None이 될 수 있으므로 값을 읽기 전에 결과를 확인합니다.

04

find_all()도 실패하면 None이라고 생각한다

find() → None ≠ find_all() → []
05

.string을 모든 텍스트 추출에 사용한다

내부에 여러 자식 Tag가 있는 구조에서는 .string만으로 원하는 전체 텍스트를 얻지 못할 수 있습니다. .text나 .get_text()도 구분해서 사용합니다.

06

Attribute가 항상 존재한다고 생각한다

tag["href"] vs tag.get("href")

외부 웹페이지는 구조가 변경될 수 있으므로 Attribute 존재 여부를 고려합니다.

07

HTML class를 그대로 Python 인자로 작성한다

HTML class="product"
BeautifulSoup class_="product"
08

find_all() 결과를 Tag 하나처럼 사용한다

여러 Tag 결과이므로 반복문이나 인덱스를 이용해 개별 Tag에 접근해야 합니다. 

for product in products:

    print(
        product.get_text(
            strip=True
        )
    )
09

빈 리스트가 나오면 BeautifulSoup 조건만 수정한다

URL Status Response HTML 데이터 존재 Tag 조건
10

브라우저 화면에 보이면 response.text에도 있다고 생각한다

JavaScript 실행 후 추가 요청이나 DOM 변경으로 데이터가 생성되는 페이지에서는 브라우저 화면과 최초 Response HTML이 다를 수 있습니다.

11

Text를 추출하면 자동으로 숫자가 된다고 생각한다

"25,000원" → "25000" → 25000

BeautifulSoup은 Text를 찾아 주지만 업무용 자료형으로 바꾸는 것은 Cleaning 단계의 책임입니다.

12

처음부터 긴 메서드 체인을 작성한다

초보 학습에서는 find()와 get_text()를 변수로 나누어 어느 단계에서 실패했는지 확인하는 것이 좋습니다. 

name_tag = product.find(
    "h2"
)


if name_tag is not None:

    name = name_tag.get_text(
        strip=True
    )

403 · 404 · Timeout은 BeautifulSoup보다 앞 단계

403 Forbidden

정상 상품 HTML 대신 접근 거부 안내 HTML을 받은 것은 아닌지 확인합니다.

404 Not Found

잘못된 URL의 오류 페이지를 BeautifulSoup이 파싱하고 있을 수 있습니다.

Timeout Response 이전

Response 자체를 받지 못했으므로 BeautifulSoup 단계까지 진행되지 않았습니다.

선택 조건 문제가 아닌데 빈 결과가 나오는 경우

잘못된 URL / 403 → 다른 HTML 수신 → BeautifulSoup → product 검색 → []

겉으로는 HTML 검색 실패처럼 보이지만 실제 원인은 HTTP Request/Response 단계일 수 있습니다.

동적 페이지라면 검색 조건을 고쳐도 찾을 수 없다

HTTP 요청 함수 

import requests


def fetch_html(
    url: str,
) -> str:

    response = requests.get(
        url,
        timeout=10,
    )


    response.raise_for_status()


    return response.text

HTML Parser 함수 

from bs4 import BeautifulSoup


def parse_products(
    html: str,
) -> list[dict]:

    soup = BeautifulSoup(
        html,
        "html.parser",
    )


    products = soup.find_all(
        "div",
        class_="product",
    )


    records = []


    for product in products:

        name_tag = product.find(
            "h2"
        )


        price_tag = product.find(
            "p",
            class_="price",
        )


        link_tag = product.find(
            "a"
        )


        records.append(
            {
                "name":
                    (
                        name_tag.get_text(
                            strip=True
                        )
                        if name_tag
                        else None
                    ),

                "price":
                    (
                        price_tag.get_text(
                            strip=True
                        )
                        if price_tag
                        else None
                    ),

                "link":
                    (
                        link_tag.get(
                            "href"
                        )
                        if link_tag
                        else None
                    ),
            }
        )


    return records

08

Interview Point

면접에서 설명할 수 있어야 할 질문

Q1 BeautifulSoup은 무엇인가요?

A.

HTML이나 XML 문서를 파싱하여 Tag 구조를 탐색하고 텍스트와 Attribute를 추출할 수 있게 하는 Python 외부 라이브러리입니다.

Q2 Requests와 BeautifulSoup의 차이는 무엇인가요?

A.

Requests는 웹 서버와 HTTP 통신을 하여 Response를 받아오고, BeautifulSoup은 그 Response의 HTML을 파싱하고 탐색하는 역할을 담당합니다.

requests = 가져오기 / BeautifulSoup = 분석하기

Q3 Parsing이란 무엇인가요?

A.

HTML 같은 문자열을 문법과 계층 관계에 따라 분석하여 Tag 구조를 탐색할 수 있는 객체 형태로 만드는 과정입니다.

Q4 BeautifulSoup 객체는 어떻게 생성하나요?

A.

분석할 HTML과 사용할 Parser를 BeautifulSoup 생성자에 전달합니다.

BeautifulSoup(html, "html.parser")

Q5 find()는 무엇을 반환하나요?

A.

조건에 맞는 첫 번째 Tag를 반환하고 요소가 없다면 None이 될 수 있습니다.

Q6 find_all()은 무엇을 반환하나요?

A.

조건에 맞는 여러 Tag 결과를 반환하며 일치하는 요소가 없으면 빈 결과가 됩니다.

Q7 find()와 find_all()의 가장 중요한 차이는 무엇인가요?

A.

find()는 첫 번째 요소 하나를 찾고 없으면 None, find_all()은 여러 요소를 찾고 없으면 빈 결과가 됩니다.

find() → None / find_all() → []

Q8 Tag 객체에서는 어떤 값을 읽을 수 있나요?

A.

Tag 이름, 내부 Text, href·src·id·class 등의 HTML Attribute를 읽을 수 있습니다.

Q9 .string, .text, .get_text()는 어떻게 다른가요?

A.

.string은 단순한 문자열 구조에서 사용하기 쉽고, 중첩 구조에서는 기대한 값이 나오지 않을 수 있습니다. .text와 .get_text()는 내부 텍스트를 읽는 데 사용하며 get_text()는 strip 같은 옵션도 활용할 수 있습니다.

Q10 HTML Attribute는 어떻게 읽나요?

A.

직접 인덱싱, get(), attrs 등을 사용할 수 있습니다.

tag["href"] / tag.get("href") / tag.attrs

Q11 class_를 사용하는 이유는 무엇인가요?

A.

class가 Python 예약어이기 때문에 BeautifulSoup의 Keyword Argument에서는 class_ 형태를 사용합니다.

Q12 NoneType 오류는 왜 발생하나요?

A.

find()가 원하는 요소를 찾지 못해 None을 반환했는데, 그 결과에 .text나 get_text() 같은 속성·메서드를 사용하면 발생할 수 있습니다.

Q13 빈 리스트가 나오면 검색 조건이 틀린 것인가요?

A.

반드시 그렇지는 않습니다. 실제 데이터가 없거나, 다른 URL이나 403·404 페이지를 받았거나, JavaScript로 동적으로 생성되는 데이터일 수도 있습니다.

Q14 BeautifulSoup은 JavaScript를 실행하나요?

A.

BeautifulSoup은 전달받은 HTML/XML을 파싱하는 도구입니다. 브라우저처럼 JavaScript를 실행하고 동적으로 DOM을 만드는 역할은 하지 않습니다.

Q15 브라우저에는 보이는데 BeautifulSoup에서 찾을 수 없는 이유는?

A.

해당 데이터가 최초 HTTP Response HTML에 없고 JavaScript 실행이나 추가 API 요청 후 DOM에 생성되는 동적 데이터일 수 있습니다.

Q16 Parsing과 Cleaning의 차이는 무엇인가요?

A.

Parsing은 HTML에서 필요한 Tag·Text·Attribute를 구조적으로 추출하는 단계이고, Cleaning은 추출한 문자열에서 공백·단위·기호를 제거하거나 숫자·날짜 등의 필요한 자료형으로 변환하는 단계입니다.

오늘의 암기 포인트

HTML → BeautifulSoup → Tag → Text / Attribute → Python Data
  • Requests = HTML 가져오기
  • BeautifulSoup = HTML 분석하기
  • response.text = HTML 문자열
  • BeautifulSoup(html, "html.parser") = HTML 파싱
  • find() = 첫 번째 Tag
  • find() 실패 = None
  • find_all() = 여러 Tag
  • find_all() 결과 없음 = 빈 결과 []
  • tag.name = Tag 이름
  • .string, .text, .get_text() = Text 읽기
  • tag.get("href") = Attribute 읽기
  • tag.attrs = Attribute 전체
  • HTML의 class → BeautifulSoup에서는 class_
  • None.text처럼 사용하면 AttributeError가 발생할 수 있다.
  • 브라우저에 보인다고 response.text에 반드시 있는 것은 아니다.

헷갈리기 쉬운 개념

requests vs BeautifulSoup

requests는 HTTP 통신, BeautifulSoup은 HTML 분석입니다.

HTML str vs soup

HTML str은 문자열, soup는 파싱된 HTML 문서 객체입니다.

find() vs find_all()

하나와 여러 개를 찾는 차이이며, 검색 실패 결과도 None과 빈 결과로 다릅니다.

.string vs .get_text()

.string은 단순 구조에서 편하고, 중첩된 Text 전체를 읽을 때는 get_text()가 더 유연합니다.

tag["href"] vs tag.get("href")

직접 접근은 Attribute가 없을 경우 오류 가능성이 있고, get()은 None으로 존재 여부를 확인하기 편합니다.

None vs []

find() 실패와 find_all() 결과 없음의 차이입니다.

Parsing vs Cleaning

Parsing은 HTML에서 값을 찾는 단계, Cleaning은 찾은 값을 업무에 맞게 정리하는 단계입니다.

403 / 404 vs None / []

앞은 HTTP Response 단계, 뒤는 HTML 검색 단계입니다.

Static HTML vs Dynamic DOM

서버가 준 HTML과 JavaScript 실행 후 브라우저에 만들어진 화면은 다를 수 있습니다.
