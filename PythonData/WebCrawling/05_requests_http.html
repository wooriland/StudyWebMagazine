Python & Data · Web Crawling · Lesson 05

requests로 GET과 POST 요청하기

앞 단원까지는 urllib을 이용해 URL 인코딩, Request 객체, Header, urlopen(), read(), decode()를 직접 다뤘습니다. 이번에는 외부 HTTP 라이브러리 requests를 사용하여 GET·POST 요청을 더 읽기 쉽게 작성하고, params, data, json, headers, cookies, timeout으로 요청 조건을 표현하는 방법을 공부합니다.

이번 단원의 핵심 Request를 만들고 → Response를 검사하고 → Body의 종류에 맞게 처리한다.
Python Data → GET / POST → HTTP Request → Web Server → Response → HTML / JSON / bytes

학습 목표

  • urllib과 requests의 역할 차이를 설명할 수 있다.
  • requests가 Python 표준 라이브러리가 아닌 외부 HTTP 라이브러리라는 것을 이해한다.
  • requests.get()과 requests.post()로 HTTP 요청을 보낼 수 있다.
  • params와 data가 HTTP Request에서 들어가는 위치를 구분할 수 있다.
  • data=와 json=의 역할을 구분할 수 있다.
  • json=과 response.json()의 방향이 반대라는 것을 설명할 수 있다.
  • headers, cookies, timeout을 Request에 전달할 수 있다.
  • response.status_code, response.headers, response.text, response.content를 구분할 수 있다.
  • response.json()으로 JSON Response를 Python 객체로 변환할 수 있다.
  • raise_for_status()를 이용해 HTTP 4xx·5xx 상태를 예외 처리와 연결할 수 있다.
  • response.request를 이용하여 실제로 전송된 URL, Header, Body를 검사할 수 있다.
  • 403, 404, 429, Timeout, JSONDecodeError, 인코딩 문제와 선택자 오류를 단계별로 구분할 수 있다.
01

Core Concept

requests의 HTTP Request · Response 구조

requests가 HTTP 구조를 바꾸는 것은 아닙니다. 앞에서 배운 URL, Query, Header, Request, Response 개념을 더 읽기 쉽고 짧은 Python 코드로 표현 하는 라이브러리입니다.

urllib에서 requests로

STANDARD LIBRARY

urllib

Python 표준 라이브러리입니다. URL 인코딩부터 Request 객체, Response Body의 bytes 처리까지 HTTP 요청 과정을 비교적 직접적으로 볼 수 있습니다.

urlencode() → Request() → urlopen()
EXTERNAL LIBRARY

requests

별도로 설치하는 HTTP 라이브러리입니다. Query, Header, Body, Cookie, Timeout 등을 함수 인자로 전달할 수 있어 코드 의도가 더 쉽게 보입니다.

params= → requests.get() → Response
Requests는 HTTP 원리를 없애지 않는다.

앞에서 직접 만들었던 Query String, Request Header, Response Body 처리를 더 편리한 API로 감싼 것으로 이해합니다.

requests는 별도 설치가 필요하다

05

Common Mistakes

초보자가 자주 하는 실수

01

requests를 Python 표준 라이브러리라고 생각한다

urllib = 표준 라이브러리 ≠ requests = 외부 라이브러리
02

params와 data를 같은 것으로 생각한다

params URL Query String
data Request Body
03

data=와 json=을 같은 형식이라고 생각한다

FORM data=
JSON json=
04

json=과 response.json()을 혼동한다

json= → 서버로 보냄 response.json() → 서버에서 받음
05

response.json()은 항상 dict라고 생각한다

JSON Object는 dict, JSON Array는 list 등 실제 JSON 구조에 따라 반환되는 Python 객체가 달라질 수 있습니다.

06

JSON 변환 성공을 HTTP 성공이라고 생각한다

HTTP 4xx·5xx 오류 상태에서도 서버가 유효한 JSON 오류 메시지를 반환할 수 있습니다.

raise_for_status() → json()
07

text와 content를 혼동한다

text → str ≠ content → bytes
08

timeout을 생략한다

외부 서버는 언제든 응답이 느려지거나 응답하지 않을 수 있습니다. 요청 코드에는 적절한 Timeout을 두는 습관이 좋습니다.

09

Timeout을 HTTP 상태 코드라고 생각한다

RESPONSE 403 / 404 / 500
WAITING Timeout
10

200이면 원하는 페이지를 받았다고 확정한다

200 → Final URL → Content-Type → Body
11

raise_for_status()를 200이 아니면 모두 실패라고 외운다

이번 학습에서는 HTTP 4xx·5xx 실패 상태를 HTTPError로 연결하는 메서드로 이해합니다.

12

Response만 보고 실제 Request를 확인하지 않는다

response.request.url response.request.headers response.request.body

ConnectionError

ConnectionError

서버와 정상적인 연결을 만들지 못함

DNS, 연결 거부, 네트워크 접근 실패 등 서버로부터 정상 HTTP Response를 받기 전 단계에서 발생할 수 있습니다.

Timeout

requests.get() → Network → Waiting → Timeout
Timeout ≠ HTTP Status Code

403·404·500은 HTTP Response를 받은 뒤의 상태이고, Timeout은 정상 Response를 기다리는 과정에서 실패할 수 있는 Exception입니다.

HTML 수집 함수 

import requests


def fetch_html(
    url: str,
    params: dict | None = None,
) -> str:

    response = requests.get(
        url,
        params=params,
        headers={
            "User-Agent":
                "WebCrawlingStudy/1.0",
        },
        timeout=10,
    )


    response.raise_for_status()


    return response.text

08

Interview Point

면접에서 설명할 수 있어야 할 질문

Q1 requests는 어떤 라이브러리인가요?

A.

Python에서 GET·POST 등의 HTTP Request와 Query Parameter, Header, Cookie, Timeout, Response Text·JSON 등을 비교적 간결하게 처리할 수 있게 하는 외부 HTTP 라이브러리입니다.

Q2 urllib과 requests의 차이는 무엇인가요?

A.

urllib은 Python 표준 라이브러리이고, URL·Request·Response 처리를 비교적 직접적으로 다룰 수 있습니다. requests는 외부 라이브러리로 같은 HTTP 작업을 더 간결한 API로 제공합니다.

Q3 requests.get()은 무엇을 반환하나요?

A.

HTTP GET Request를 보내고 Response 객체를 반환합니다.

requests.get() → Response

Q4 params의 역할은 무엇인가요?

A.

URL Query String에 들어갈 Parameter를 Python 딕셔너리 등의 형태로 전달합니다.

params → URL Query

Q5 data의 역할은 무엇인가요?

A.

POST 등의 Request Body에 Form 데이터를 전달할 때 사용할 수 있습니다.

data → Form Body

Q6 data=와 json=은 어떻게 다른가요?

A.

data=는 일반적으로 Form 데이터, json=은 Python 객체를 JSON Request Body로 보내는 상황과 연결합니다.

Q7 json=과 response.json()의 차이는 무엇인가요?

A.

json=은 Client가 Server에 JSON Request Body를 보내는 기능이고, response.json()은 Server가 반환한 JSON을 Python 객체로 변환하는 기능입니다.

json= : 보내기 / response.json() : 받기

Q8 response.text와 response.content의 차이는 무엇인가요?

A.

response.text는 문자로 해석된 str이고, response.content는 bytes 형태의 Response Body입니다.

text → str / content → bytes

Q9 response.json()은 항상 dict를 반환하나요?

A.

아닙니다. JSON의 최상위 구조가 Object이면 dict, Array이면 list 등 실제 JSON 구조에 따라 달라질 수 있습니다.

Q10 response.json()이 성공하면 HTTP 요청도 성공인가요?

A.

아닙니다. HTTP 오류 상태에서도 서버가 유효한 JSON 오류 메시지를 반환할 수 있기 때문에 상태 코드는 별도로 확인해야 합니다.

Q11 raise_for_status()는 어떤 역할을 하나요?

A.

HTTP 4xx·5xx 실패 상태를 HTTPError 예외 처리 흐름으로 연결하는 Response 메서드입니다.

Q12 timeout은 왜 지정하나요?

A.

외부 서버의 응답이 지연되거나 응답하지 않는 상황에서 프로그램이 무한정 기다리지 않도록 네트워크 대기에 제한을 두기 위해 사용합니다.

Q13 headers=와 response.headers의 차이는 무엇인가요?

A.

headers=는 Client에서 Server로 전달하는 Request Header이고, response.headers는 Server가 반환한 Response Header입니다.

Q14 cookies=와 response.cookies의 차이는 무엇인가요?

A.

cookies=는 Request에 Cookie를 실어 보내고, response.cookies는 Response에서 전달된 Cookie를 확인합니다.

Q15 response.request는 무엇인가요?

A.

현재 Response를 만들기 위해 실제로 전송된 Request 정보를 담고 있습니다. Method, URL, Header, Body 확인에 유용합니다.

Q16 데이터가 나오지 않으면 Selector부터 확인하나요?

A.

아닙니다. 먼저 실제 Request URL, HTTP Status, Response Header와 Body를 확인한 뒤 정상 HTML이라는 것이 확인되면 Selector를 점검합니다.

오늘의 암기 포인트

Request → Response → Status → Body → Parser
  • requests.get() = GET Request
  • requests.post() = POST Request
  • params = URL Query String
  • data = Form Request Body
  • json= = JSON Request Body
  • json= = 보내기, response.json() = 받기
  • headers= = Request Header
  • response.headers = Response Header
  • cookies= = Cookie 전송
  • response.cookies = Cookie 수신 확인
  • response.status_code = HTTP 상태
  • response.text = str
  • response.content = bytes
  • raise_for_status() = 4xx·5xx → HTTPError
  • response.request = 실제로 보낸 Request
  • Timeout은 HTTP Status Code가 아니다.

헷갈리기 쉬운 개념

urllib vs requests

urllib은 표준 라이브러리, requests는 외부 HTTP 라이브러리입니다.

params vs data

params는 URL Query, data는 Request Body에 연결합니다.

data= vs json=

Form Body와 JSON Body의 차이입니다.

json= vs response.json()

앞은 서버로 보내는 JSON, 뒤는 서버에서 받은 JSON을 읽는 기능입니다.

text vs content

text는 str, content는 bytes입니다.

headers= vs response.headers

Request Header와 Response Header의 차이입니다.

cookies= vs response.cookies

보내는 Cookie와 Response에서 받은 Cookie의 차이입니다.

Status Code vs Timeout

Status는 Response 결과이고, Timeout은 응답 대기 과정의 Exception입니다.

HTTPError vs JSONDecodeError

앞은 HTTP 상태 문제, 뒤는 Response Body의 JSON 변환 문제입니다.

403 / 404 vs None / []

앞은 HTTP Response, 뒤는 이후 HTML Selector 단계입니다.
