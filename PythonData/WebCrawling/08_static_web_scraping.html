정적 웹페이지 스크레이핑 실습

지금까지는 requests로 HTTP Response를 받고, BeautifulSoup으로 HTML을 파싱하고, find()·select()으로 원하는 요소를 찾는 방법을 각각 공부했습니다. 이번 단원에서는 이 기술들을 하나로 연결하여 목록 → 제목 → 가격 → 링크 → 속성값을 하나의 Python 데이터 레코드로 수집하는 정적 웹 스크레이핑 전체 흐름 을 공부합니다.

이번 단원의 핵심 Request → Parse → Select → Extract → Clean → Validate → Store
URL → requests → HTML → BeautifulSoup → Selector → list[dict]

학습 목표

  • Web Crawling과 Web Scraping의 역할 차이를 실제 데이터 수집 흐름에서 설명할 수 있다.

  • requests.get()으로 Response를 받고 Status·Final URL·Content-Type을 확인할 수 있다.
  • BeautifulSoup()으로 HTML을 파싱할 수 있다.
  • 반복되는 목록 요소를 먼저 선택한 뒤 각 카드 내부의 필드를 수집하는 Card-first Parsing 구조를 설명할 수 있다.
  • 제목·가격 같은 Text와 href·data-* 같은 Attribute를 구분해 수집할 수 있다.
  • Tag 없음, 빈 Text, Attribute 없음이라는 서로 다른 결측 상황을 구분할 수 있다.
  • 결측값을 None 등 일관된 형태로 정규화할 수 있다.
  • Parsing, Cleaning, Validation의 책임을 서로 구분할 수 있다.
  • "25,000원"과 같은 문자열을 숫자 자료형으로 정제할 수 있다.
  • 상대 URL을 urljoin()으로 절대 URL로 변환하는 이유를 이해한다.
  • Selector Match Count를 이용해 HTML 구조 변경을 감지할 수 있다.
  • 403·404·429·Timeout과 Selector의 None·빈 결과를 서로 다른 단계의 문제로 구분할 수 있다.
  • 모든 레코드를 동일한 key 구조로 만들어 CSV·JSON·Database 저장 단계로 연결할 수 있다.
  • 정적 HTML에 데이터가 없을 때 JSON API 또는 Selenium을 검토해야 하는 이유를 설명할 수 있다.

Core Concept

정적 웹 스크레이핑의 전체 구조

이번 단원은 새로운 라이브러리를 많이 배우는 단원이 아니라 지금까지 배운 기술을 하나의 데이터 수집 파이프라인으로 연결하는 단원 입니다.

Crawling과 Scraping

CRAWLING

페이지를 찾아간다

URL이나 링크를 따라 이동하거나, 페이지 번호를 바꾸면서 여러 페이지를 순회하는 과정입니다.

page=1 → page=2 → page=3
SCRAPING

필요한 값을 추출한다

현재 HTML에서 상품명, 가격, 링크처럼 필요한 정보만 선택하여 Python 데이터로 만드는 과정입니다.

HTML → name + price + link

RESPONSE response.text
→
HTML 수집할 데이터가 이미 존재
→
TOOL Requests + BeautifulSoup
학습 보완

가장 중요한 원칙 — Card First

주의 필드를 페이지 전체에서 각각 수집
.name → 3개 .price → 3개 .link → 2개

하나의 필드가 누락되면 이름·가격·링크의 인덱스 관계가 깨질 수 있습니다.

권장 상품 카드부터 선택
Product P001 ├─ name ├─ price └─ link

각 카드 내부에서 필드를 찾으면 같은 상품에 속한 데이터 관계를 유지할 수 있습니다.

    tag,

    )


    if value == "":

예제 6. 가격 정제 

def parse_price(
    value: str | None,
) -> int | None:

    if not value:
        return None


    cleaned = (
        value
        .replace(",", "")
        .replace("원", "")
        .strip()
    )


    if not cleaned.isdigit():
        return None


    return int(
        cleaned
    )
"25,000원" → 25000
"" → None
"가격문의" → None

예제 7. 상대 URL 정규화 

from urllib.parse import urljoin


def normalize_url(
    base_url: str,
    href: str | None,
) -> str | None:

    if not href:
        return None


    return urljoin(
        base_url,
        href,
    )
print(
    normalize_url(
        "https://example.com",
        "/products/P001",
    )
)

예제 8. 상품 하나를 dict로 변환 

def parse_product(
    product,
    base_url: str,
) -> dict:

    name_tag = product.select_one(
        ".name"
    )


    price_tag = product.select_one(
        ".price"
    )


    link_tag = product.select_one(
        ".detail-link"
    )


    name = clean_text(
        name_tag
    )


    price = parse_price(
        clean_text(
            price_tag
        )
    )


    href = (
        link_tag.get(
            "href"
        )
        if link_tag
        else None
    )


    return {
        "product_id":
            product.get(
                "data-id"
            ),

        "name":
            name,

        "price":
            price,

        "link":
            normalize_url(
                base_url,
                href,
            ),
    }

예제 9. 여러 상품을 list[dict]로 변환 

PRODUCT_SELECTOR = (
    "article.product"
)


def parse_products(
    html: str,
    base_url: str,
) -> list[dict]:

    soup = BeautifulSoup(
        html,
        "html.parser",
    )


    products = soup.select(
        PRODUCT_SELECTOR
    )


    print(
        "PRODUCT MATCH COUNT:",
        len(products),
    )


    records = []


    for product in products:

        record = parse_product(
            product,
            base_url,
        )


        records.append(
            record
        )


    return records
records = parse_products(
    HTML,
    "https://example.com",
)


for record in records:

    print(
        record
    )

예제 10. 필수 필드 Validation 

def is_valid_product(
    record: dict,
) -> bool:

    if not record.get(
        "product_id"
    ):
        return False


    if not record.get(
        "name"
    ):
        return False


    price = record.get(
        "price"
    )


    if (
        price is not None
        and price < 0
    ):
        return False


    return True

        .replace("원", "")
        .strip()
    )


    if not cleaned.isdigit():
        return None


    return int(
        cleaned
    )


def normalize_url(
    base_url: str,
    href: str | None,
) -> str | None:

    if not href:
        return None


    return urljoin(
        base_url,
        href,
    )


def parse_product(
    product,
    base_url: str,
) -> dict:

    name_tag = product.select_one(
        NAME_SELECTOR
    )


    price_tag = product.select_one(
        PRICE_SELECTOR
    )


    link_tag = product.select_one(
        LINK_SELECTOR
    )


    href = (
        link_tag.get(
            "href"
        )
        if link_tag
        else None
    )


    return {
        "product_id":
            product.get(
                "data-id"
            ),

        "name":
            clean_text(
                name_tag
            ),

        "price":
            parse_price(
                clean_text(
                    price_tag
                )
            ),

        "link":
            normalize_url(
                base_url,
                href,
            ),
    }


def parse_products(
    html: str,
    base_url: str,
) -> list[dict]:

    soup = BeautifulSoup(
        html,
        "html.parser",
    )


    products = soup.select(
        PRODUCT_SELECTOR
    )


    print(
        "MATCH_COUNT:",
        len(products),
    )


    records = []


    for product in products:

        record = parse_product(
            product,
            base_url,
        )


        records.append(
            record
        )


    return records


def is_valid_product(
    record: dict,
) -> bool:

    return bool(
        record.get(
            "product_id"
        )
        and record.get(
            "name"
        )
    )


records = parse_products(
    HTML,
    "https://example.com",
)


valid_records = [
    record
    for record in records
    if is_valid_product(
        record
    )
]


for record in valid_records:

    print(
        record
    )

Common Mistakes

실제 Scraping에서 자주 하는 실수

01

상품명·가격·링크를 페이지 전체에서 각각 수집한다

일부 상품에서 링크나 가격이 빠지면 각 리스트의 인덱스가 서로 달라질 수 있습니다. 반복 카드부터 찾고 카드 내부의 필드를 추출합니다.

02

모든 상품 카드의 HTML 구조가 같다고 가정한다

외부 HTML에는 특정 필드가 없는 레코드가 존재할 수 있으므로 None 가능성을 고려합니다.

03

Tag가 있으면 값도 있다고 생각한다

<span class="price"></span> → ""
04

None과 빈 문자열을 구분하지 않는다

Tag 없음 → None 빈 Text → ""
05

모든 결측값을 무조건 레코드에서 제거한다

필수 필드와 선택 필드를 구분해야 합니다. 가격이나 링크는 프로젝트 정책에 따라 None으로 유지할 수도 있습니다.

06

get_text()까지 하면 Cleaning이 끝났다고 생각한다

"25,000원" → 아직 str → 25000
07

상대 URL을 완성된 URL이라고 생각한다

/products/P001 → urljoin() → https://...
08

목록 결과가 0개면 Selector만 수정한다

Status Final URL Content-Type HTML Body Selector
09

HTTP 200이면 원하는 페이지라고 판단한다

검색 결과 없음 페이지나 로그인 안내 페이지도 200을 반환할 수 있습니다. Final URL과 Response Body까지 확인합니다.

10

첫 번째 상품 하나만 보고 Parser를 확정한다

여러 레코드를 반복해서 확인해야 특정 카드의 누락 필드나 다른 구조를 발견할 수 있습니다.

11

Match Count를 확인하지 않는다

프로그램이 Exception 없이 종료되더라도 수집 결과가 0건일 수 있습니다. 목록 Selector의 개수를 반드시 확인합니다.

12

Selector 변경을 Python 문법 오류로 생각한다

외부 사이트 HTML은 독립적으로 변경될 수 있습니다. Python과 Selector 문법은 정상인데 검색 결과만 None이 될 수도 있습니다.

13

Browser에 보이면 정적 페이지라고 생각한다

JavaScript 실행 이후 만들어진 DOM일 수 있으므로 실제 response.text 안에 데이터가 있는지 확인해야 합니다.

14

각 record마다 다른 key를 만든다

권장 product_id / name / price / link 값이 없으면 None

08

Interview Point

면접에서 설명할 수 있어야 할 질문

Q1 정적 웹 Scraping의 기본 흐름은 무엇인가요?

A.

Requests로 HTML Response를 받아 상태를 확인하고, BeautifulSoup으로 파싱한 뒤 반복되는 목록 요소를 선택합니다. 각 요소에서 Text와 Attribute를 추출하고, Cleaning과 Validation을 거쳐 Python 데이터 구조로 변환합니다.

Request → Parse → Select → Extract → Clean → Validate

Q2 Crawling과 Scraping의 차이는 무엇인가요?

A.

Crawling은 여러 페이지나 링크를 따라 탐색하는 과정이고, Scraping은 현재 페이지에서 필요한 정보를 추출하는 과정입니다.

Q3 왜 상품 카드부터 선택하나요?

A.

상품명·가격·링크를 같은 상품 단위로 묶기 위해서입니다. 각 필드를 전체 페이지에서 따로 검색하면 일부 값이 누락될 때 인덱스 관계가 틀어질 수 있습니다.

Q4 Tag가 없는 것과 Text가 비어 있는 것은 어떻게 다른가요?

A.

Tag가 없으면 select_one()이 None이 될 수 있고, Tag는 존재하지만 내용이 없으면 get_text(strip=True)가 빈 문자열을 반환할 수 있습니다.

Q5 Missing Value는 어떻게 처리할 수 있나요?

A.

필수값과 선택값을 구분하고, Tag 없음·빈 Text·Attribute 없음 등을 프로젝트 정책에 따라 None처럼 일관된 형태로 정규화할 수 있습니다.

Q6 Parsing과 Cleaning은 어떻게 다른가요?

A.

Parsing은 HTML에서 필요한 값을 찾는 과정이고, Cleaning은 추출한 문자열을 사용 목적에 맞는 형태로 변환하는 과정입니다.

"25,000원" → 25000

Q7 Validation은 왜 필요한가요?

A.

HTML에서 값을 찾았다고 해서 그 데이터가 업무에 사용할 수 있는 값이라는 보장은 없습니다. 필수값·범위·중복 등을 검사하기 위해 Validation을 수행합니다.

Q8 상대 URL은 어떻게 처리할 수 있나요?

A.

/products/P001 같은 상대 경로는 기준 URL과 urljoin()을 이용해 절대 URL로 변환할 수 있습니다.

Q9 Selector Match Count는 왜 확인하나요?

A.

Selector가 문법적으로 실행되어도 너무 많거나 너무 적은 요소를 선택할 수 있기 때문입니다. 예상 개수와 실제 개수를 비교하면 HTML 구조 변경이나 잘못된 Response를 발견하기 쉽습니다.

Q10 select() 결과가 []이면 Selector가 틀린 것인가요?

A.

반드시 그렇지는 않습니다. 상품이 실제로 없거나, 403·404 페이지를 받았거나, HTML 구조가 변경되었거나, 동적으로 생성되는 데이터일 수도 있습니다.

Q11 HTTP 200인데 데이터가 없을 수 있나요?

A.

가능합니다. 검색 결과 없음, 로그인 안내, 다른 페이지로 이동한 결과 등도 HTTP 200을 반환할 수 있으므로 Final URL과 Body를 같이 확인해야 합니다.

Q12 Selector 변경에는 어떻게 대응할 수 있나요?

A.

Selector를 별도 상수로 관리하고, 목록 Match Count와 필수 필드를 검증하여 HTML 구조 변경을 빠르게 감지할 수 있습니다. 변경이 발견되면 실제 HTML을 다시 확인해야 합니다.

Q13 왜 HTTP Client와 Parser를 분리하나요?

A.

네트워크 문제와 HTML Parsing 문제를 독립적으로 테스트하고 디버깅하기 위해서입니다. HTTP Client는 통신, Parser는 HTML 구조 분석에 집중할 수 있습니다.

Q14 왜 list[dict] 구조를 사용하나요?

A.

여러 레코드를 일정한 필드 구조로 표현하기 쉽고, 반복·Validation·JSON·CSV·Database 저장으로 연결하기 편리하기 때문입니다.

Q15 모든 record의 key를 같게 만드는 이유는?

A.

Schema를 일정하게 유지하면 CSV의 열 구조와 Database 컬럼에 데이터를 안정적으로 매핑하기 쉽습니다. 값이 없으면 None으로 표현할 수 있습니다.

Q16 Browser에는 데이터가 있는데 BeautifulSoup에서 찾을 수 없는 이유는?

A.

JavaScript가 페이지 로드 이후 추가 API를 호출하여 DOM에 데이터를 만드는 동적 페이지일 수 있습니다. 이 경우 Response HTML, Network API, Selenium 사용 여부를 차례로 검토합니다.

오늘의 암기 포인트

Request → HTML → Parse → Select → Clean → Validate
  • 정적 Scraping = Request → Parse → Select → Extract
  • 목록형 페이지는 Card 먼저 → Field 나중
  • select_one() = Tag 또는 None
  • select() = 여러 Tag, 없으면 빈 결과
  • Tag 없음 = None
  • Tag 있음 + Text 없음 = ""
  • Text = get_text()
  • Attribute = get()
  • Parsing = 값 찾기
  • Cleaning = 값 변환
  • Validation = 값 사용 가능 여부 판단
  • "25,000원" → 25000
  • 상대 URL → urljoin()
  • 목록 Selector 뒤에는 len()으로 Match Count 확인
  • HTTP 200 ≠ 원하는 데이터 존재
  • [] ≠ 무조건 Selector 오류
  • Browser DOM ≠ response.text
  • 모든 record는 가능한 한 동일한 key 구조를 유지한다.

헷갈리기 쉬운 개념

Crawling vs Scraping

페이지 탐색과 현재 페이지의 정보 추출이라는 차이입니다.

정적 HTML vs 동적 DOM

Response에 이미 있는 데이터와 JavaScript 실행 후 생성된 데이터의 차이입니다.

List Selector vs Field Selector

전자는 반복 레코드 경계, 후자는 각 레코드의 개별 값을 찾습니다.

None vs ""

Tag 없음과 Tag는 있지만 Text가 비어 있는 경우의 차이입니다.

Text vs Attribute

화면에 표시되는 내용과 href·src·data-* 같은 HTML 속성값의 차이입니다.

Parsing vs Cleaning

값을 찾는 것과 찾은 값을 사용할 형태로 바꾸는 것의 차이입니다.

Cleaning vs Validation

값 변환과 그 값이 유효한지 판단하는 단계의 차이입니다.

상대 URL vs 절대 URL

/product/1과 https://.../product/1의 차이입니다.

403 / 404 vs None / []

앞은 HTTP 단계, 뒤는 HTML 검색 단계입니다.

0 Match vs 마지막 페이지

빈 목록이 마지막 페이지일 수도 있지만 Selector 변경이나 HTTP 문제일 수도 있습니다.

list[dict] vs CSV

전자는 Python 메모리 데이터, 후자는 이를 파일로 저장하는 한 방법입니다.
