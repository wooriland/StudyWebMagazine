Python & Data · Web Crawling · Lesson 03

urllib.request로 웹 요청하기

앞 단원에서 배운 URL → HTTP Request → Server → HTTP Response 구조를 Python 표준 라이브러리 urllib.request로 직접 확인합니다. urlopen()으로 Response 객체를 받고, 상태 코드와 Header를 확인한 뒤 read()로 Body를 bytes로 읽고, 텍스트 데이터라면 decode()를 통해 Python 문자열 str로 변환합니다.

핵심 데이터 흐름 URL → urlopen() → Response → read() → bytes → decode() → str
URL → urlopen() → Response → status / headers → read() → bytes → decode() → str

학습 목표

  • urllib과 urllib.request의 관계를 설명할 수 있다.
  • urlopen()이 URL 요청 후 Response 객체를 반환한다는 것을 이해한다.
  • Response 객체에서 status, headers, url을 확인할 수 있다.
  • read()가 Response Body를 bytes로 읽는다는 것을 이해한다.
  • bytes → decode() → str 자료형 변화를 설명할 수 있다.
  • encode()와 decode()의 방향을 구분할 수 있다.
  • urlopen()과 urlretrieve()의 역할을 구분할 수 있다.
  • HTML과 이미지 같은 바이너리 데이터의 처리 방법이 다른 이유를 설명할 수 있다.
  • HTTPError, URLError, Timeout, UnicodeDecodeError의 발생 단계를 구분할 수 있다.
  • urllib 요청 오류와 BeautifulSoup·Selenium 선택자 오류가 서로 다른 단계의 문제라는 것을 설명할 수 있다.

05

Common Mistakes

초보자가 자주 하는 실수

01

urllib과 urllib.request를 같은 것으로 생각한다

urllib 패키지 ≠ urllib.request 요청 모듈
02

urlopen() 결과가 HTML str이라고 생각한다

urlopen()은 먼저 Response 객체를 반환합니다.

urlopen() → Response
03

read() 결과를 str이라고 생각한다

read()의 결과는 일반적으로 bytes입니다.

read() → bytes
04

decode()를 urllib.request 함수라고 생각한다

잘못된 생각 urllib.request.decode()
올바른 구조 raw_data.decode("utf-8")
05

모든 웹페이지를 무조건 UTF-8로 decode한다

실제 대상 페이지의 문자 인코딩이 무엇인지 확인해야 합니다. 잘못된 문자셋을 사용하면 한글이 깨지거나 UnicodeDecodeError가 발생할 수 있습니다.

06

이미지·PDF도 decode()한다

HTML decode() vs Image / PDF bytes 저장
07

urlopen()과 urlretrieve()를 같은 목적으로 사용한다

urlopen()은 응답을 코드에서 직접 처리하는 흐름, urlretrieve()는 파일 저장 흐름으로 구분합니다.

08

urlopen().read().decode()를 처음부터 한 줄로만 작성한다

실행은 가능하지만 학습과 디버깅에서는 Response, bytes, str의 중간 상태를 확인하기 어렵습니다. 

response = urllib.request.urlopen(URL)

raw_data = response.read()

html = raw_data.decode("utf-8")
09

read()를 여러 번 호출해도 같은 Body가 계속 나온다고 생각한다

학습 단계에서는 Response Body를 한 번 읽어 변수에 저장하고 그 변수를 재사용하는 방식이 안전하게 이해됩니다.

10

상태와 Header를 확인하지 않고 Body부터 분석한다

먼저 현재 받은 Response가 예상한 페이지인지 확인해야 이후 HTML 선택자 오류와 혼동하지 않습니다.

status → headers → Body → HTML → Selector

HTTP & Error Reading

urllib.request 오류 메시지 읽는 법

이번 단원부터 오류를 요청 단계 → Response 단계 → Body 읽기 단계 → decode 단계 로 나누어 읽습니다.

REQUEST urlopen() URLError · Timeout
→
RESPONSE HTTP Status HTTPError 403 / 404
→
BODY read() bytes
→
TEXT decode() UnicodeDecodeError

HTTPError

HTTPError

서버의 HTTP 오류 상태와 연결

URL 요청은 서버에 도달했지만 서버가 403, 404 같은 HTTP 실패 상태를 반환한 경우 확인하게 되는 오류입니다. 

except HTTPError as error:

    print(
        "HTTP 오류:",
        error.code,
    )
403

Forbidden

서버가 요청을 이해했지만 요청 처리를 허용하지 않은 상황입니다.

URL 공개 여부 인증 Header 접근 정책 요청 빈도

교안에서는 대표적인 예로 User-Agent Header를 추가한 Request 객체를 사용합니다. 다만 모든 403의 원인이 User-Agent라는 뜻은 아닙니다.

404

Not Found

요청한 URL의 자원을 찾지 못한 경우 주소 구조부터 확인합니다.

URL 오타 Path Query 페이지 번호

URLError

URLError

URL 또는 네트워크 요청 자체의 문제

서버 이름을 찾지 못하거나 네트워크 연결이 정상적으로 이루어지지 않는 등 URL 요청 과정의 더 넓은 오류와 연결합니다. 

except URLError as error:

    print(
        "URL / Network 오류:",
        error.reason,
    )

HTTPError와 URLError 관계

URLError 더 넓은 URL 요청 오류
└─ HTTPError HTTP 오류 상태
예외 처리 순서 HTTPError → URLError

구체적인 오류를 먼저 처리하고 더 넓은 오류를 뒤에서 처리하는 구조로 이해합니다.

Timeout

urlopen() 요청 시작
→
Waiting 응답 대기
→
시간 안에 응답 Response
제한 시간 초과 Timeout
Timeout은 HTTP Status Code가 아니다.

403·404는 Response를 받은 뒤 확인하는 HTTP 상태이고, Timeout은 정상 Response가 도착하기 전에 대기 과정에서 실패할 수 있습니다.

UnicodeDecodeError

HTTP Response 성공 → read() 성공 → bytes 정상 → decode() 실패 → UnicodeDecodeError

즉 HTTP 서버에 연결하지 못한 것이 아니라, 이미 받아 온 bytes를 잘못된 문자 인코딩 규칙으로 해석하려다 문제가 발생한 것입니다.

08

Interview Point

면접에서 설명할 수 있어야 할 질문

Q1 urllib과 urllib.request의 차이는 무엇인가요?

A.

urllib은 URL 관련 기능을 모은 Python 표준 라이브러리 패키지이고, urllib.request는 그 안에서 URL을 열고 웹 자원을 요청하는 역할을 담당하는 모듈입니다.

Q2 urlopen()은 어떤 역할을 하나요?

A.

URL에 요청을 보내고 HTTP Response를 Python에서 다룰 수 있는 Response 객체를 반환합니다.

URL → urlopen() → Response

Q3 urlopen()의 결과는 HTML 문자열인가요?

A.

아닙니다. 먼저 Response 객체를 반환하고, 실제 Body는 read()를 이용해 읽습니다.

Q4 read()의 결과는 어떤 자료형인가요?

A.

Response Body를 bytes 형태로 읽습니다. 텍스트라면 이후 적절한 문자 인코딩으로 decode하여 str로 변환할 수 있습니다.

read() → bytes

Q5 decode()는 왜 필요한가요?

A.

웹에서 받은 bytes를 Python 문자열로 변환하여 HTML이나 JSON 등의 텍스트로 처리하기 위해 사용합니다.

bytes → decode() → str

Q6 decode()는 urllib.request의 함수인가요?

A.

아닙니다. response.read()로 얻은 bytes 객체의 메서드입니다.

raw_data.decode("utf-8")

Q7 urlopen()과 urlretrieve()의 차이는 무엇인가요?

A.

urlopen()은 Response를 프로그램 내부에서 읽고 처리하는 흐름에 사용하고, urlretrieve()는 URL 자원을 로컬 파일로 내려받는 흐름에 사용합니다.

urlopen = 처리 / urlretrieve = 다운로드

Q8 HTTP 상태 코드는 어떻게 확인할 수 있나요?

A.

urlopen()으로 얻은 Response 객체의 status 값을 통해 확인할 수 있습니다.

response.status

Q9 Response Header는 왜 확인하나요?

A.

응답의 Content-Type, 문자 인코딩이나 크기 등 Response 데이터에 대한 부가 정보를 파악하는 데 사용할 수 있습니다.

Q10 HTML과 이미지의 처리 방식은 어떻게 다른가요?

A.

HTML은 텍스트이므로 bytes를 적절한 인코딩으로 decode할 수 있지만, 이미지·PDF 같은 바이너리 파일은 일반적으로 bytes 상태 그대로 저장합니다.

Q11 HTTPError와 URLError의 차이는 무엇인가요?

A.

HTTPError는 403·404처럼 HTTP 응답 상태와 연결되는 보다 구체적인 오류이고, URLError는 URL·연결·네트워크 요청 문제까지 포함하는 더 넓은 요청 오류로 이해할 수 있습니다.

Q12 UnicodeDecodeError는 HTTP 오류인가요?

A.

아닙니다. 이미 Response Body를 bytes로 정상적으로 받은 뒤, bytes를 잘못된 문자 인코딩으로 str로 바꾸는 과정에서 발생할 수 있는 문자 변환 오류입니다.

Q13 왜 requests 전에 urllib.request를 공부하나요?

A.

URL 요청부터 Response, read(), bytes, decode(), str로 이어지는 기본 데이터 흐름을 직접 확인하면 이후 requests가 같은 HTTP 작업을 더 편리하게 추상화한 도구라는 것을 이해하기 쉽기 때문입니다.

오늘의 암기 포인트

URL → urlopen() → Response → read() → bytes → decode() → str
  • urllib = URL 관련 기능을 모은 패키지
  • urllib.request = URL 요청을 담당하는 모듈
  • urlopen() = Response 객체 반환
  • response.status = HTTP 상태 코드
  • response.headers = Response Header
  • response.read() = Response Body 읽기
  • read() 결과는 bytes다.
  • 텍스트 bytes는 decode()하여 str로 변환할 수 있다.
  • decode()는 urllib 함수가 아니라 bytes 객체의 메서드다.
  • urlopen() = 읽고 처리
  • urlretrieve() = 내려받아 저장
  • 이미지·PDF 같은 바이너리는 무조건 decode하지 않는다.

헷갈리기 쉬운 개념

urllib vs urllib.request

urllib은 패키지, urllib.request는 URL 요청 모듈입니다.

Response vs HTML

urlopen()은 HTML 문자열이 아니라 먼저 Response 객체를 반환합니다.

bytes vs str

read()는 bytes, 텍스트 decode 이후에는 str입니다.

encode vs decode

encode는 str → bytes, decode는 bytes → str 방향입니다.

urlopen() vs urlretrieve()

전자는 응답 처리, 후자는 파일 다운로드 흐름입니다.

HTTPError vs UnicodeDecodeError

전자는 HTTP 요청·응답 단계, 후자는 bytes → str 변환 단계입니다.

HTTPError vs None

HTTPError는 네트워크 요청 단계, None은 이후 HTML 선택 단계의 문제입니다.
