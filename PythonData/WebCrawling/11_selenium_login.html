Python & Data · Web Crawling · Lesson 11

로그인과 사용자 상호작용 자동화

이번 단원에서는 앞에서 배운 WebDriver, find_element(), send_keys(), click(), Keys, WebDriverWait와 Expected Conditions를 하나로 연결합니다. 로그인 자동화는 단순히 아이디와 비밀번호를 입력하는 것이 아니라 로그인 전 → 인증 처리 중 → 성공 또는 실패 로 변하는 Browser의 상태를 자동화하고 검증하는 과정입니다.

이번 단원의 핵심 Locate → Wait → Input → Submit → Wait → Verify
Login Page → Username → Password → Submit → Authentication → Verify

학습 목표

  • 로그인 자동화를 단순 입력이 아니라 상태 전이 자동화로 설명할 수 있다.
  • ANONYMOUS → AUTHENTICATING → AUTHENTICATED / FAILURE 흐름을 설명할 수 있다.
  • Username·Password Input에 필요한 Wait 상태를 판단할 수 있다.
  • clear()와 send_keys()로 로그인 값을 입력할 수 있다.
  • Login Button의 Clickable 상태를 기다릴 수 있다.
  • click()과 Keys.ENTER를 로그인 Submit 흐름에 연결할 수 있다.
  • Submit 실행과 Login Success를 서로 다른 단계로 구분할 수 있다.
  • URL 변화와 Dashboard 표시를 로그인 성공 상태로 검증할 수 있다.
  • 로그인 실패 메시지를 애플리케이션 상태로 해석할 수 있다.
  • Login Failure와 Selenium Exception을 구분할 수 있다.
  • NoSuchElementException, TimeoutException, ElementNotInteractableException 등의 발생 단계를 구분할 수 있다.
  • Login 성공 후 같은 WebDriver Session에서 회원 전용 페이지로 이동하는 흐름을 이해한다.
  • 로그인 후 page_source를 BeautifulSoup Parser에 연결할 수 있다.
  • 실제 Credential을 Source Code와 Debug Log에서 분리해야 하는 이유를 이해한다.
  • 다음 Scrapy 학습에서 Selenium Login이 어떻게 재사용되는지 설명할 수 있다.

예제 11. enter_credentials() 

def enter_credentials(
    driver,
    username_value: str,
    password_value: str,
) -> None:

    username = WebDriverWait(
        driver,
        5,
    ).until(
        EC.visibility_of_element_located(
            USERNAME_INPUT
        )
    )


    password = WebDriverWait(
        driver,
        5,
    ).until(
        EC.visibility_of_element_located(
            PASSWORD_INPUT
        )
    )


    username.clear()
    password.clear()


    username.send_keys(
        username_value
    )


    password.send_keys(
        password_value
    )

예제 12. submit_login() 

def submit_login(
    driver,
) -> None:

        driver,
        5,
    ).until(
        EC.element_to_be_clickable(
            LOGIN_BUTTON
        )
    )


    button.click()

예제 13. wait_for_login_success() 

def wait_for_login_success(
    driver,
    timeout=5,
):

    WebDriverWait(
        driver,
        timeout,
    ).until(
        EC.url_contains(
            "#dashboard"
        )
    )


    return WebDriverWait(
        driver,
        timeout,
    ).until(
        EC.visibility_of_element_located(
            DASHBOARD
        )
    )

예제 14. login() 함수 

def login(
    driver,
    username_value: str,
    password_value: str,
):

    enter_credentials(
        driver,
        username_value,
        password_value,
    )


    submit_login(
        driver
    )


    return wait_for_login_success(
        driver
    )
enter_credentials() 입력
submit_login() 인증 요청
wait_for_login_success() 성공 검증

from selenium import webdriver
from selenium.webdriver.common.by import By

from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC

from selenium.common.exceptions import TimeoutException


USERNAME_INPUT = (
    By.ID,
    "username",
)

PASSWORD_INPUT = (
    By.ID,
    "password",
)

LOGIN_BUTTON = (
    By.ID,
    "login-button",
)

DASHBOARD = (
    By.ID,
    "dashboard",
)

    Path(
        "selenium_login_practice.html"
    )
    .resolve()
    .as_uri()
)

    # ==========================================
    # 1. Login Page
    # ==========================================

    )

    )

    # 2. Username
    # ==========================================

        5,

        "study"
    )


    print(
        "[LOGIN] username entered"
    )


    # ==========================================
    # 3. Password
    # ==========================================

    password = WebDriverWait(
        driver,
        5,
    ).until(
        EC.visibility_of_element_located(
            PASSWORD_INPUT
        )
    )


    password.clear()


    password.send_keys(
        "python1234"
    )


    print(
        "[LOGIN] password entered"
    )


    # ==========================================
    # 4. Login Submit
    # ==========================================

    login_button = WebDriverWait(
        driver,
        5,
    ).until(
        EC.element_to_be_clickable(
            LOGIN_BUTTON
        )
    )


    login_button.click()


    print(
        "[LOGIN] submit"
    )


    # ==========================================

    # ==========================================
    # 6. Dashboard

        5,

    )

    print(
        dashboard.text

except TimeoutException:

    )


finally:

Common Mistakes

로그인 자동화에서 자주 하는 실수

01

Login Button Click을 성공이라고 생각한다

click() → 인증 요청 ≠ Login Success
02

Page가 열리면 Input도 바로 사용할 수 있다고 생각한다

Page Load ≠ Input Ready
03

Presence만 확인하고 바로 값을 입력한다

Input이 DOM에 있어도 Hidden일 수 있으므로 실제 입력 목적에 맞는 Visibility 상태를 검토합니다.

04

Login Button이 보이면 Clickable하다고 생각한다

Visible ≠ Enabled
05

실제 Password를 Source Code에 기록한다

Source Git README Log
06

Password를 Debug Log에 출력한다

Password 값 출력 X Password 입력 완료 O
07

잘못된 Password를 Selenium Exception이라고 생각한다

로그인 요청을 정상 처리하고 Error Message가 나타났다면 자동화가 실패한 것이 아니라 인증 결과가 실패한 것입니다.

08

TimeoutException을 Credential 오류라고 단정한다

Timeout은 기대 상태가 제한 시간 안에 만족되지 않았다는 뜻입니다. Locator·페이지·이전 Click·Condition을 함께 확인합니다.

09

URL만 바뀌면 로그인 성공이라고 확정한다

URL Change + Dashboard → 더 강한 검증
10

현재 Login Page인지 확인하지 않는다

current_url title Login Form DevTools
11

Enter Key를 아무 Element에 보낸다

Form Submit과 연결되는 Input처럼 Keyboard Interaction에 의미가 있는 Element를 대상으로 사용합니다.

12

Success만 생각하고 Failure 상태를 설계하지 않는다

SUCCESS FAILURE TIMEOUT
13

로그인 후 이전 Login WebElement를 계속 사용한다

Old DOM → Login Success → New DOM
14

인증 처리 중 Login Button을 반복 클릭한다

AUTHENTICATING은 반복 Click 단계가 아니라 인증 결과를 기다리는 상태입니다.

15

추가 인증·SSO 같은 서비스 절차를 Selenium 오류라고 본다

실제 서비스가 추가 인증 단계를 제공한다면 로그인 흐름 자체가 더 복잡한 것입니다. 서비스가 요구하는 정상 인증 절차와 정책을 따릅니다.

Interview Point

Selenium Login 면접 핵심 질문

Q1 Selenium 로그인 자동화의 기본 흐름은 무엇인가요?

A.

Login Page로 이동하고 Username·Password Element가 준비되는 것을 기다린 뒤 값을 입력합니다. Button Click 또는 Enter로 인증을 요청하고, URL·Dashboard·Error Message 등의 상태를 기다려 성공과 실패를 구분합니다.

Q2 로그인 자동화를 상태 전이라고 하는 이유는?

A.

Browser가 Anonymous 상태에서 인증 요청을 거쳐 Authenticated 또는 Failure 상태로 바뀌기 때문입니다.

ANONYMOUS → AUTHENTICATING → RESULT

Q3 Login Button을 클릭하면 로그인 성공인가요?

A.

아닙니다. Click은 인증 요청을 시작한 것이며 로그인 성공 여부는 이후 Browser 상태를 별도로 검증해야 합니다.

Q4 Username과 Password에 Wait가 필요한 이유는?

A.

Page가 열렸다고 Input이 즉시 보이고 Interaction 가능한 상태라는 보장이 없기 때문입니다.

Q5 Input에 Visibility를 사용할 수 있는 이유는?

A.

DOM에 존재하는 것뿐 아니라 사용자가 볼 수 있는 입력 상태까지 확인하고 싶을 때 사용할 수 있습니다.

Q6 Login Button에는 왜 Clickable을 기다릴 수 있나요?

A.

Button이 보이더라도 Disabled 상태일 수 있기 때문에 실제 Click 전에 활성 상태를 확인할 수 있습니다.

Q7 Enter Key로도 로그인할 수 있나요?

A.

Form이 Keyboard Submit을 지원한다면 가능합니다. 교안의 예제도 Password Element에 Keys.RETURN을 전송합니다.

Q8 로그인 성공은 무엇으로 검증할 수 있나요?

A.

사이트에 따라 URL 변경, Dashboard, User Menu, Logout Button, Login Form 제거 등을 성공 신호로 사용할 수 있습니다.

Q9 URL만 바뀌면 성공이라고 볼 수 있나요?

A.

경우에 따라 부족할 수 있습니다. 중요 화면에서는 URL과 Dashboard 같은 핵심 Element 상태를 함께 확인할 수 있습니다.

Q10 잘못된 Password는 Selenium Exception인가요?

A.

반드시 그렇지 않습니다. 서비스가 정상적으로 인증 요청을 처리하고 실패 메시지를 표시했다면 Application Login Failure입니다.

Q11 NoSuchElementException과 Login Failure의 차이는?

A.

전자는 Selenium이 Element를 찾지 못한 자동화 문제이고, 후자는 Credential 검증 결과가 실패한 애플리케이션 상태입니다.

Q12 TimeoutException은 로그인에서 언제 발생할 수 있나요?

A.

Username, Button, Dashboard 같은 기대 상태가 지정 시간 안에 준비되지 않을 때 발생할 수 있습니다. 현재 Page, Locator, Wait Condition과 이전 상호작용을 함께 확인해야 합니다.

Q13 Login 후 기존 WebElement를 계속 사용해도 되나요?

A.

페이지 이동이나 DOM 재구성이 발생하면 기존 Element가 stale 상태가 될 수 있으므로 새 화면에서 필요한 Element를 다시 검색합니다.

Q14 Login 후 Browser Session이 중요한 이유는?

A.

같은 WebDriver Session을 유지하면 로그인으로 만들어진 Browser 상태를 이어서 사용하여 회원 전용 페이지로 이동할 수 있기 때문입니다.

Q15 Login 후 BeautifulSoup을 사용할 수 있나요?

A.

가능합니다. Selenium으로 인증 상태를 만든 뒤 page_source를 가져와 BeautifulSoup으로 HTML을 파싱할 수 있습니다.

Q16 실제 Credential을 코드와 분리하는 이유는?

A.

실제 ID·Password가 Source, Git, README, Debug Log 등에 노출되는 위험을 줄이고 환경별 설정을 분리하기 위해서입니다.

Q17 Logout도 상태 자동화인가요?

A.

그렇습니다. Authenticated 상태에서 Logout 동작을 통해 다시 Anonymous 상태로 이동하는 반대 방향의 상태 전이입니다.

Q18 Selenium Login과 Scrapy는 어떻게 연결되나요?

A.

Selenium은 Browser Login과 동적 상태 생성에 강하고, Scrapy는 여러 URL의 반복 Crawling과 Item·Pipeline 구조화에 강합니다. 교안 후반에서도 Selenium을 이용하는 로그인 페이지 Scrapy 사례를 연결합니다.

Locate → Wait → Input → Submit → Wait → Verify
  • Login = Input 자동화 + 상태 자동화
  • ANONYMOUS → AUTHENTICATING → AUTHENTICATED / FAILURE
  • Username → Visibility
  • Password → Visibility
  • Login Button → Clickable
  • clear() = 기존 Input 제거
  • send_keys() = 사용자 입력
  • click() = 인증 요청 시작
  • Keys.ENTER = Keyboard Submit 가능
  • Click ≠ Login Success
  • Submit → Wait → Verify
  • Login Success 후보 = URL · Dashboard · User Menu · Logout
  • Login Failure ≠ Selenium Failure
  • NoSuchElementException = Element Search 문제
  • TimeoutException = 기대 상태가 시간 안에 준비되지 않음
  • Locator Error ≠ Credential Error
  • Login 후 DOM이 바뀌면 Element를 다시 찾는다.
  • 실제 Credential은 Source·Git·Log와 분리한다.
  • Authenticated Session에서는 같은 driver를 이어서 사용할 수 있다.
  • Selenium = Browser 상태 생성
  • BeautifulSoup = HTML Parsing

헷갈리기 쉬운 개념

Input Automation vs Login Automation

값 입력만 하는 것과 인증 상태 변화까지 검증하는 것의 차이입니다.

Submit vs Success

인증 요청을 시작한 것과 인증 결과가 성공한 것은 다릅니다.

Presence vs Visibility

DOM에 있는 것과 실제 Input으로 사용할 수 있는 화면 상태를 구분합니다.

Visibility vs Clickable

화면에 보이는 상태와 실제 활성화되어 클릭할 수 있는 상태의 차이입니다.

Button Click vs Keys.ENTER

서로 다른 사용자 입력 방식이지만 Form Submit이라는 같은 목적에 연결될 수 있습니다.

Login Failure vs Selenium Error

인증 정보 실패와 자동화 코드·Element 검색 실패를 구분합니다.

URL Change vs Dashboard Ready

Navigation 완료와 실제 핵심 화면 준비 상태는 다를 수 있습니다.

Credential Error vs Timeout

잘못된 로그인 정보와 기대 상태가 시간 안에 준비되지 않은 문제를 구분합니다.

Cookie vs Login Success

Cookie는 Session의 단서일 수 있지만 실제 성공 UI를 직접 확인하는 것이 더 명확할 수 있습니다.

Old Element vs New DOM
