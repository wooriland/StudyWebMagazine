Python & Data · Web Crawling · Lesson 13

Spider, Item과 Pipeline

앞 단원에서는 Scrapy Shell에서 Response와 CSS·XPath Selector를 시험하고 Scrapy Project의 구조를 공부했습니다. 이번에는 검증한 Selector를 Spider.parse(response) 안으로 옮기고, 수집한 값을 Item에 담은 뒤 yield하여 Pipeline으로 전달합니다. Pipeline에서는 Cleaning → Validation → Duplicate Check → Storage 로 데이터를 후처리하고, Spider는 동시에 새로운 Request를 yield하여 다음 페이지를 계속 Crawling할 수 있습니다.

이번 단원의 핵심 Spider는 수집하고, Item은 구조화하고, Pipeline은 데이터를 믿을 수 있는 형태로 만든다.
Response → Spider → Item → yield → Pipeline → Storage

Cleaning Pipeline 

class CleanNewsPipeline:

    def process_item(
        self,
        item,
    ):

        title = item.get(
            "title"
        )


        if title is not None:

            item[
                "title"
            ] = title.strip()


        category = item.get(
            "category"
        )


        if category is not None:

            item[
                "category"
            ] = category.strip()


        return item

Validation Pipeline과 DropItem 

from scrapy.exceptions import DropItem


class ValidateNewsPipeline:

import scrapy

from crawlingbot.items import NewsItem


class NewsSpider(
    scrapy.Spider
):

    name = "news"

    start_urls = [
        "http://127.0.0.1:8000/index.html"
    ]


    def parse(
        self,
        response,

        cards = response.css(
            "article.news-item"
        )

            item = NewsItem()


            item[
                "news_id"
            ] = card.css(
                "::attr(data-id)"
            ).get()


            item[
                "title"
            ] = card.css(
                ".title::text"
            ).get()


            item[
                "category"
            ] = card.css(
                ".category::text"
            ).get()


            item[

import scrapy

from crawlingbot.items import NewsItem


class NewsSpider(
    scrapy.Spider
):

    name = "news"

    start_urls = [
        "http://127.0.0.1:8000/index.html"
    ]


    def parse(
        self,
        response,
    ):

        cards = response.css(
            "article.news-item"
        )


        self.logger.info(
            "CARD COUNT = %s",
            len(cards),
        )


        for card in cards:

            item = NewsItem()


            item[
                "news_id"
            ] = card.css(
                "::attr(data-id)"
            ).get()


            item[
                "title"
            ] = card.css(
                ".title::text"
            ).get()


            item[
                "category"
            ] = card.css(
                ".category::text"
            ).get()


            item[
                "link"
            ] = card.css(
                "a.detail::attr(href)"
            ).get()


            item[
                "source_url"
            ] = response.url


            yield item


        next_page = response.css(
            "a.next::attr(href)"
        ).get()


        if next_page:

            yield response.follow(
                next_page,
                callback=self.parse,
            )

Common Mistakes

Spider · Item · Pipeline에서 자주 하는 실수

01

Python 파일명과 Spider name을 혼동

news_spider.py ≠ name = "news"
02

Shell에서 검증하지 않은 Selector를 바로 Spider에 사용

Response·Selector 문제와 Spider 구현 문제를 한꺼번에 디버깅하게 됩니다.

03

Item 객체를 만들기만 하고 yield하지 않음

NewsItem() → Field 입력 → yield 필요
04

response.follow()만 호출하고 yield하지 않음

Request 객체를 만든 것과 Scrapy Crawling Flow에 Request를 전달한 것은 다릅니다.

05

새 Page를 self.parse()로 직접 호출

새로운 URL은 Request → Downloader → Response → Callback이라는 Framework Cycle로 처리합니다.

06

Spider에 Cleaning·DB 저장까지 모두 넣음

Spider → Extraction Pipeline → Processing
07

process_item()에서 item을 반환하지 않음

일반적인 Pipeline은 처리한 Item을 다음 단계로 전달하기 위해 반환해야 합니다.

08

Pipeline을 만들고 settings.py에 등록하지 않음

pipelines.py O ITEM_PIPELINES X
09

Pipeline Priority 방향을 반대로 이해

300 → 먼저 800 → 나중
10

DropItem을 무조건 Crawler 실패로 생각

Validation 규칙에 따라 잘못된 Record를 의도적으로 제거한 결과일 수 있습니다.

11

Item Field 이름 오타

title ≠ titel
12

상대 URL을 문자열로 직접 이어 붙임

상대 Link는 response.follow()로 현재 Response 기준 Request로 만들 수 있습니다.

13

next_page가 None인데 Follow 

if next_page:

    yield response.follow(
        next_page,
        callback=self.parse,
    )
14

Raw Data와 Clean Data를 혼동

"\n Python \n" → "Python"
15

단순 JSON 저장에도 무조건 Pipeline 작성

단순 Export는 Feed Export로 처리하고 복잡한 Data Processing은 Pipeline으로 분리할 수 있습니다.

16

일반 JSON에 -o를 반복 사용

-O JSON → Overwrite -o JSONL → Append 활용
17

403·404인데 Selector부터 수정

HTTP Page 자체가 다르면 정상 Selector도 원하는 Item을 만들 수 없습니다.

18

Browser DOM과 Scrapy Response를 동일하게 생각

JavaScript 이후 DOM이 필요한 페이지라면 앞에서 공부한 Network 분석 또는 Selenium이 다시 필요할 수 있습니다.

19

source_url을 남기지 않아 원본 추적이 어려움

Crawling 결과의 출처를 다시 검증하려면 원본 URL 같은 추적 Field가 유용합니다.

08

Interview Point

Spider · Item · Pipeline 면접 핵심 질문

Q1 Scrapy Spider의 역할은 무엇인가요?

A.

Crawling 시작 URL과 Response 처리 규칙을 정의하고, Selector로 데이터를 추출하거나 다음 Request를 생성하는 역할입니다.

Q2 Spider의 name은 무엇인가요?

A.

Scrapy가 Spider를 식별하는 이름이며 scrapy crawl name에서 사용합니다. Python 파일명과는 별개의 값입니다.

Q3 start_urls는 무엇인가요?

A.

Spider가 처음 Crawling할 URL들의 목록으로, 기본 시작 흐름에서 초기 Request 생성에 사용됩니다.

Q4 parse(response)는 무엇인가요?

A.

다운로드된 Response를 처리하는 기본 Callback이며, 데이터를 추출하거나 다음 Request를 생성합니다.

Q5 Shell의 Selector와 Spider의 Selector가 다른가요?

A.

기본 문법은 같습니다. Shell에서 검증한 CSS·XPath를 Spider의 Callback으로 옮기는 것이 일반적인 학습 흐름입니다.

Q6 Scrapy Item은 무엇인가요?

A.

수집 데이터를 일정한 Field 구조로 표현하기 위한 구조화된 Item Type입니다.

Q7 Dictionary와 scrapy.Item은 무엇이 다른가요?

A.

Dictionary도 Item으로 사용할 수 있지만 scrapy.Item은 정의된 Field 집합을 사용하므로 Field 구조와 오타를 더 명확하게 관리할 수 있습니다.

Q8 yield item은 무엇인가요?

A.

Spider가 추출한 Item을 Scrapy의 다음 처리 단계로 전달하는 일반적인 패턴입니다. 활성화된 Pipeline 등으로 이어집니다.

Q9 Spider는 Item만 yield하나요?

A.

아닙니다. 새로운 Request도 yield할 수 있습니다. Item은 데이터 처리 방향, Request는 다음 Crawling 방향으로 연결됩니다.

Q10 response.follow()은 무엇인가요?

A.

현재 Response를 기준으로 상대 Link를 처리하여 다음 Request를 만드는 편의 기능입니다. 실제 Crawling Flow로 보내려면 Request를 yield합니다.

Q11 Pipeline의 역할은 무엇인가요?

A.

Spider가 만든 Item을 받아 Cleaning, Validation, Duplicate Check, Database 저장 같은 후처리를 수행합니다.

Q12 현재 process_item()의 형태는 무엇인가요?

A.

이번 학습에서 사용하는 현재 API 형태는 process_item(self, item)이며, Item을 반환하거나 DropItem을 발생시킵니다.

Q13 DropItem은 무엇인가요?

A.

Validation이나 중복 검사에서 더 이상 처리하지 않을 Item을 Pipeline에서 제거할 때 사용하는 예외입니다.

Q14 Pipeline을 어떻게 활성화하나요?

A.

settings.py의 ITEM_PIPELINES에 Pipeline Class의 Import Path와 Priority를 등록합니다.

Q15 Pipeline Priority 숫자는 무엇을 의미하나요?

A.

Pipeline 실행 순서를 의미하며 낮은 값의 Component부터 먼저 실행됩니다.

Q16 JSON 저장에는 반드시 Pipeline이 필요한가요?

A.

아닙니다. 단순 JSON·CSV·JSONL 출력은 Feed Export를 사용할 수 있고, Cleaning·Validation·DB 저장 같은 로직은 Pipeline으로 분리할 수 있습니다.

Q17 -o와 -O의 차이는 무엇인가요?

A.

이번 학습 기준으로 -o는 기존 Output에 추가하고, -O는 기존 Output을 덮어씁니다. 일반 JSON 반복 저장에는 이 차이를 주의해야 합니다.

Q18 source_url을 Item에 넣는 이유는 무엇인가요?

A.

나중에 어떤 Page에서 수집된 Record인지 확인하고 오류 데이터의 원본을 재검증하기 쉽기 때문입니다.

Q19 Spider와 Pipeline의 핵심 차이는 무엇인가요?

A.

Spider는 어디에서 무엇을 수집할지를 담당하고, Pipeline은 수집된 데이터를 어떻게 처리할지를 담당합니다.

Q20 Scrapy와 Selenium을 함께 사용할 수 있나요?

A.

역할이 다르므로 필요에 따라 결합할 수 있습니다. Scrapy는 반복 Crawling 구조, Selenium은 Browser의 동적 상태·상호작용을 담당합니다.

오늘의 암기 포인트

Spider → Item → yield → Pipeline → Storage
  • Spider = Crawling Rule
  • Item = Data Schema
  • Pipeline = Data Processing
  • name = "news" = Spider 실행 이름
  • Spider 파일명 ≠ Spider name
  • start_urls = 초기 Crawling URL
  • parse(response) = Response 처리 Callback
  • Shell에서 검증한 Selector를 parse()로 옮긴다.
  • Card 먼저 → Field 나중
  • yield item = Item 처리 방향
  • yield Request = 다음 Crawling 방향
  • Spider의 두 출구 = Item + Request
  • response.follow() = 상대 URL Request 생성
  • follow()만 하지 말고 Request를 yield한다.
  • Spider = Extraction
  • Pipeline = Cleaning / Validation
  • Raw Item → Pipeline → Clean Item
  • 현재 학습 Pipeline = process_item(self, item)
  • Pipeline의 일반 처리 결과 = return item
  • 잘못된 Item = DropItem
  • Clean → Validate → Duplicate → Save
  • 낮은 Priority 숫자부터 실행
  • pipelines.py 작성 + settings.py 등록 = Pipeline 활성화
  • Item Field 오타 → KeyError 가능
  • Card Count = 0이면 Pipeline보다 Response·Spider부터 확인
  • Field = None이면 개별 Field Selector·Optional 여부 확인
  • 단순 JSON·CSV = Feed Export 가능
  • -O = Overwrite
  • -o = Append
  • JSON Append는 주의하고 JSONL을 고려할 수 있다.
  • source_url = 데이터 출처 추적
  • 403·404 = Selector보다 HTTP 먼저
  • Scrapy = 반복 Crawling 구조
  • Selenium = Browser State Automation

헷갈리기 쉬운 개념

Spider File vs Spider name

Python 파일명과 Scrapy가 사용하는 실행 식별자는 다릅니다.

Spider vs Item

Crawling 규칙과 수집 결과 데이터 구조의 차이입니다.

Item vs DB Table

Item은 Crawling 과정에서 이동하는 데이터 객체이며 DB Table 자체가 아닙니다.

Spider vs Pipeline

Extraction 책임과 Data Processing 책임의 차이입니다.

yield Item vs yield Request

Item 처리 방향과 다음 Crawling 방향의 차이입니다.

follow() vs yield follow()

Request 객체를 만드는 것과 실제 Scrapy 흐름에 내보내는 것을 구분합니다.

parse() vs parse_detail()

목록 Page와 상세 Page의 역할을 다른 Callback으로 분리할 수 있습니다.

Raw Item vs Clean Item

HTML에서 바로 추출한 값과 정제 후 저장 가능한 값의 차이입니다.

return item vs DropItem

다음 처리 단계로 넘기는 것과 해당 Item을 제거하는 것의 차이입니다.

Priority 300 vs Priority 800

중요도 점수가 아니라 실행 순서이며 작은 숫자가 먼저입니다.

Feed Export vs Pipeline

단순 파일 출력과 복잡한 후처리 로직을 구분합니다.

-o vs -O

Append와 Overwrite의 차이입니다.

DropItem vs Program Failure

데이터 품질 정책에 따른 정상 제거와 Crawler 실행 오류를 구분합니다.

HTTP Error vs Selector Error

잘못된 Page를 받은 문제와 정상 Page에서 위치 지정이 틀린 문제를 구분합니다.

Browser DOM vs Scrapy Response

JavaScript 실행 이후 화면과 Scrapy가 받은 HTTP HTML은 다를 수 있습니다.
