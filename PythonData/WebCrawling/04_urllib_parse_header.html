URL 인코딩과 요청 헤더

실제 웹 요청에서는 단순한 URL뿐 아니라 한글 검색어, 공백, 페이지 번호와 같은 Query Parameter를 URL에 넣어야 합니다. 이번 단원에서는 urllib.parse의 quote(), quote_plus(), urlencode(), urlsplit(), urlunsplit()을 이용해 URL을 만들고 분석하는 방법을 배우고, urllib.request.Request와 User-Agent를 이용해 Request Header를 구성하는 방법까지 연결합니다.

이번 단원의 핵심 Python 데이터 → URL Encoding → URL → Headers → Request → urlopen()
사용자 입력 → urlencode() → Query String → URL → Headers → Request → urlopen()

학습 목표

  • urllib.request와 urllib.parse의 역할을 구분할 수 있다.
  • URL Encoding이 필요한 이유를 설명할 수 있다.
  • URL Encoding과 Response의 decode()가 서로 다른 개념임을 설명할 수 있다.
  • quote()와 quote_plus()의 차이를 설명할 수 있다.
  • unquote()와 unquote_plus()를 이용해 URL 인코딩 값을 다시 복원할 수 있다.
  • Python 딕셔너리를 urlencode()로 Query String으로 변환할 수 있다.
  • urlsplit()을 이용해 URL의 scheme, netloc, path, query, fragment를 구분할 수 있다.
  • urlunsplit()으로 URL 구성요소를 다시 조립할 수 있다.
  • Request Header와 Response Header의 방향과 역할을 구분할 수 있다.
  • User-Agent가 HTTP Request Header라는 것을 이해한다.
  • URL과 Header를 urllib.request.Request 객체로 구성할 수 있다.
  • 403, 404, Timeout, URL 구성 오류, Selector 오류를 발생 단계별로 구분할 수 있다.

예제 10. URL Encoding부터 HTTP Request까지 

import urllib.request

from urllib.parse import urlencode
from urllib.error import (
    HTTPError,
    URLError,
)


BASE_URL = (
    "https://example.com/search"
)


def build_url(
    base_url: str,
    params: dict,
) -> str:

    query_string = urlencode(
        params
    )

    return (
        base_url
        + "?"
        + query_string
    )


def fetch(
    url: str,
) -> str:

    headers = {
        "User-Agent":
            "WebCrawlingStudy/1.0",

        "Accept":
            "text/html",
    }


    request = urllib.request.Request(
        url,
        headers=headers,
    )


    try:

        with urllib.request.urlopen(
            request,
            timeout=10,
        ) as response:

            print(
                "Status:",
                response.status,
            )

            print(
                "Final URL:",
                response.url,
            )

            print(
                "Content-Type:",
                response.headers.get(
                    "Content-Type"
                ),
            )

            raw_data = (
                response.read()
            )

            return raw_data.decode(
                "utf-8"
            )


    except HTTPError as error:

        print(
            "HTTP Error:",
            error.code,
        )

        raise


    except URLError as error:

        print(
            "URL Error:",
            error.reason,
        )

        raise


def main() -> None:

    params = {
        "keyword":
            "파이썬 웹크롤링",

        "page":
            2,
    }


    url = build_url(
        BASE_URL,
        params,
    )


    print(
        "Request URL:"
    )

    print(
        url
    )


    # example.com/search는 학습용 구조 예시입니다.
    # 실제 서비스의 검색 URL로 요청할 때 fetch()를 연결합니다.


if __name__ == "__main__":
    main()

Common Mistakes

초보자가 자주 하는 실수

01

한글과 공백을 직접 replace()해서 URL을 만든다

공백만 바꾸면 URL 인코딩이 끝나는 것이 아닙니다. 한글과 예약 문자까지 고려할 수 있도록 표준 URL 인코딩 함수를 사용합니다.

quote() quote_plus() urlencode()
02

quote()를 str.encode()와 같은 기능이라고 생각한다

encode() str → bytes
quote() str → URL용 str
03

URL Encoding과 Response decode()를 혼동한다

REQUEST 전 str → URL Encoding
RESPONSE 후 bytes → decode → str
04

quote()와 quote_plus()를 완전히 같다고 생각한다

두 함수 모두 인코딩할 수 있지만 공백과 /의 기본 처리 방식에서 차이가 있습니다.

05

Query String 전체를 무조건 quote()한다

여러 Parameter는 딕셔너리로 구조화한 후 urlencode()를 사용하면 =, & 구조를 직접 조립할 필요가 줄어듭니다.

06

urlencode() 결과에 ?가 포함된다고 생각한다

base_url + "?" + urlencode(params)
07

urlsplit()이 URL을 자동으로 수정·검증한다고 생각한다

urlsplit()의 핵심은 URL을 구성요소로 분해하는 것입니다. 외부 입력의 안전성이나 허용 가능한 Host 등은 필요하면 별도의 검증이 필요합니다.

08

netloc과 hostname을 같은 값이라고 생각한다

netloc = example.com:8443 hostname = example.com port = 8443
09

Request Header와 Response Header를 혼동한다

User-Agent는 Client가 Server에 보내는 Request Header이고, Content-Type은 Response에서 자주 확인하는 Header입니다.

10

User-Agent를 추가하면 모든 403이 해결된다고 생각한다

403은 접근 권한, 인증, 요청 조건과 사이트 정책 등 여러 이유로 발생할 수 있습니다. User-Agent는 확인해야 할 요소 중 하나입니다.

서버가 요청을 이해했지만 처리를 거부

서버 자체를 찾지 못한 것이 아니라 요청이 서버에 전달된 뒤 서버가 해당 요청을 허용하지 않은 상황으로 이해합니다.

from urllib.parse import urlencode


BASE_URL = (
    "https://example.com/search"
)


for page in range(
    1,
    6,
):

    params = {
        "keyword":
            "여주 관광지",

        "page":
            page,
    }


    query = urlencode(
        params
    )


    url = (
        BASE_URL
        + "?"
        + query
    )


    print(url)

Interview Point

면접에서 설명할 수 있어야 할 질문

Q1 urllib.parse는 어떤 역할을 하나요?

A.

URL을 구성 요소로 분리하거나 다시 조합하고, URL에서 사용할 문자열을 인코딩·디코딩하는 역할을 담당하는 Python 표준 라이브러리 모듈입니다.

Q2 URL Encoding이 필요한 이유는 무엇인가요?

A.

사용자 입력의 한글, 공백, 특수문자 등을 URL의 특정 구성요소에서 사용할 수 있는 형태로 표현하기 위해 필요합니다.

Q3 quote()와 quote_plus()의 차이는 무엇인가요?

A.

둘 다 URL용 인코딩을 수행하지만, quote()는 공백을 %20으로 표현하고 기본적으로 /를 유지합니다. quote_plus()는 공백을 +로 표현하고 /도 기본적으로 인코딩합니다.

Q4 unquote()와 unquote_plus()는 무엇이 다른가요?

A.

unquote()는 Percent-Encoding을 복원하고, unquote_plus()는 Percent-Encoding을 복원하면서 +도 공백으로 변환합니다.

Q5 urlencode()는 무엇을 하나요?

A.

Python의 key-value 데이터를 URL Query String 형태인 key=value&key2=value2 구조로 변환합니다.

dict → urlencode() → Query String

Q6 urlencode() 결과에 ?도 포함되나요?

A.

일반적으로 Query String만 반환하므로 Base URL과 연결할 때 ?를 별도로 붙여 완전한 URL을 구성합니다.

Q7 urlsplit()은 무엇을 반환하나요?

A.

URL을 scheme, netloc, path, query, fragment로 나눈 결과를 반환합니다.

scheme · netloc · path · query · fragment

Q8 urlunsplit()은 무엇인가요?

A.

URL의 분리된 구성요소를 다시 하나의 URL 문자열로 조합할 때 사용합니다.

Q9 URL Encoding과 bytes.decode()는 같은 개념인가요?

A.

아닙니다. URL Encoding은 요청 전에 Python 문자열을 URL용 문자열로 변환하는 과정이고, decode()는 응답 이후 bytes를 Python str로 해석하는 과정입니다.

Q10 urllib.request.Request를 사용하는 이유는 무엇인가요?

A.

URL뿐 아니라 User-Agent 같은 Header 등 추가적인 HTTP Request 정보를 하나의 요청 객체로 구성하기 위해 사용합니다.

Q11 User-Agent는 무엇인가요?

A.

HTTP Request를 보내는 Client에 관한 정보를 Server에 전달하는 Request Header 중 하나입니다.

Q12 Request Header와 Response Header의 차이는 무엇인가요?

A.

Request Header는 Client가 Server에 보내는 정보이고, Response Header는 Server가 Client에게 돌려주는 정보입니다.

Q13 403 Forbidden은 무엇인가요?

A.

서버가 요청을 이해했지만 해당 요청을 처리하지 않기로 한 상태입니다. URL, 인증·권한, Header, 접근 정책과 요청 조건을 확인해야 합니다.

Q14 User-Agent를 변경하면 모든 403을 해결할 수 있나요?

A.

아닙니다. User-Agent는 Request Header의 한 요소일 뿐이고, 403은 인증·권한·정책 등 다양한 원인으로 발생할 수 있습니다.

Q15 404가 발생하면 이번 단원에서는 무엇을 먼저 확인하나요?

A.

URL의 Path와 Query Parameter, 페이지 번호, URL 인코딩과 문자열 조립 결과를 우선 확인합니다.

오늘의 암기 포인트

dict → urlencode() → URL → Headers → Request → urlopen()
  • urllib.request = 실제 URL 요청
  • urllib.parse = URL 분석·인코딩·조합
  • quote() : 공백 → %20
  • quote_plus() : 공백 → +
  • quote() ↔ unquote()
  • quote_plus() ↔ unquote_plus()
  • urlencode() : dict → Query String
  • urlsplit() : URL → 구성요소
  • urlunsplit() : 구성요소 → URL
  • URL + Headers → Request
  • User-Agent는 Request Header다.
  • 403은 User-Agent만의 문제라고 단정하지 않는다.
  • URL Encoding과 Response decode()를 구분한다.

헷갈리기 쉬운 개념

urllib.request vs urllib.parse

request는 요청, parse는 URL 구성·분석입니다.

quote() vs quote_plus()

공백은 각각 %20과 +로 표현되며 /의 기본 처리에도 차이가 있습니다.

URL Encoding vs decode()

전자는 요청 전 URL 문자열 변환, 후자는 Response bytes의 문자열 변환입니다.

netloc vs hostname

netloc에는 포트 같은 네트워크 위치 정보가 함께 포함될 수 있습니다.

Request Header vs Response Header

Request는 Client → Server, Response는 Server → Client 방향입니다.

User-Agent vs 접근 권한

User-Agent는 Client 정보를 전달하는 Header이며 접근 권한 자체와 같은 개념은 아닙니다.

403 vs 404

403은 접근 조건, 404는 URL과 대상 자원을 먼저 확인합니다.

403 / 404 vs None / []

앞쪽은 HTTP Response 단계, 뒤쪽은 HTML Selector 단계입니다.
