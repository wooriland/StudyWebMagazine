태그 검색과 CSS 선택자

앞 단원에서는 HTML 문자열을 BeautifulSoup 객체로 파싱하고, Tag의 Text와 Attribute를 읽는 기본 구조를 공부했습니다. 이번 단원에서는 find(), find_all(), select_one(), select()을 비교하고, #id, .class, 부모·후손·직접 자식 관계와 Attribute Selector를 이용하여 복잡한 HTML에서 원하는 요소를 정확하게 지정하는 방법 을 공부합니다.

이번 단원의 핵심 HTML 구조 확인 → Selector 작성 → 검색 결과 검증 → Text·Attribute 추출
DevTools → HTML 구조 → Selector → find / select → None / [] / len() → Python Data

  • article.product와 article .product의 차이를 설명할 수 있다.

  • 여러 Class를 동시에 가진 요소를 .product.featured처럼 선택할 수 있다.

  • Browser DevTools Elements에서 Tag, id, class, Attribute를 확인할 수 있다.
  • DevTools에서 얻은 Selector를 그대로 믿지 않고 Python에서 검색 개수와 결과를 검증할 수 있다.

01

Core Concept

BeautifulSoup 검색 방법의 전체 구조

이번 단원에서는 “HTML에서 어떤 요소를 선택할 것인가?” 를 다룹니다. BeautifulSoup에서는 Tag·Attribute 조건을 사용하는 find() 계열과 CSS 문법을 사용하는 select() 계열을 함께 사용할 수 있습니다.

두 가지 검색 계열

TAG SEARCH

find 계열

Tag 이름과 id, class, Attribute 등의 조건을 Python 인자 형태로 표현합니다.

find() find_all()
CSS SELECTOR

select 계열

HTML/CSS에서 사용하는 CSS Selector 문법으로 Tag 관계와 Attribute 조건을 표현합니다.

select_one() select()

네 가지 검색 메서드

SINGLE find() 첫 번째 Tag 없으면 None
MULTIPLE find_all() 여러 Tag 없으면 빈 결과
CSS · SINGLE select_one() 첫 번째 Tag 없으면 None
CSS · MULTIPLE select() 여러 Tag 없으면 빈 결과
하나 찾기 find() select_one()
여러 개 찾기 find_all() select()

같은 요소를 두 방식으로 찾기

FIND 
products = soup.find_all(
    "article",
    class_="product",
)
CSS SELECTOR 
products = soup.select(
    "article.product"
)
어느 방식이 무조건 더 좋은 것은 아니다.

Tag와 한두 개 Attribute 조건이면 find() 계열이 읽기 쉽고, 부모·자식 관계처럼 HTML 구조를 한 번에 표현하려면 CSS Selector가 편리할 수 있습니다.

CSS Selector 기본 문법

TAG h2 모든 h2
ID #products id="products"
CLASS .product class="product"
TAG + CLASS article.product article이면서 product

공백 하나가 Selector의 의미를 바꾼다

article.product 같은 요소의 조건 
<article class="product">
article .product 부모와 후손 관계 
<article>
    <div class="product">
    </div>
</article>

여러 Class를 동시에 가진 요소 

<article class="product featured">
.product.featured

하나의 요소가 product와 featured 두 Class를 동시에 가진 경우 Class 사이에 공백을 넣지 않습니다.

후손과 직접 자식

DESCENDANT .product .name 내부 어느 깊이든
.product └─ .info └─ .name ✓
DIRECT CHILD .product > .info 바로 아래 자식만
.product └─ .info ✓ └─ .name
.parent .child 공백 = 후손 .parent > .child > = 직접 자식

HTML 범위를 단계적으로 좁힌다

#products → .product → .info → .name 
names = soup.select(
    "#products .product .info .name"
)

Attribute Selector

a[href] Attribute 존재

href를 가진 a 요소

[data-id="P001"] 정확한 값

data-id가 P001인 요소

a[href^="/products/"] 시작

/products/로 시작

a[href*="products"] 포함

products 문자열 포함

a[href$=".pdf"] 끝

.pdf로 끝나는 링크

학습 보완

DevTools의 자동 Selector는 현재 DOM 위치에 맞춘 긴 경로가 될 수 있습니다. 크롤링 코드에서는 가능한 경우 의미 있는 id, class, data-* Attribute를 이용해 더 읽기 쉽고 안정적인 Selector로 정리합니다.

Python에서 최종 검증

  1. Selector 결과 select_one() 결과가 None인지 확인한다.
  2. Match Count select() 결과의 len()을 확인한다.
  3. Text 실제로 원하는 상품명이 선택되었는지 본다.
  4. Attribute href·src 등이 예상한 값인지 확인한다.
  5. 반복성 첫 요소뿐 아니라 다음 상품에도 적용되는지 확인한다.
  6. 안정성 nth-child나 자동 생성 Class에 지나치게 의존하지 않는지 본다.

예제 13. 상품 카드 → list[dict] 

products = soup.select(
    "#products article.product"
)


records = []


for product in products:

    name_tag = product.select_one(
        ".name"
    )


    price_tag = product.select_one(
        ".price"
    )


    link_tag = product.select_one(
        "a.detail-link"
    )


    record = {
        "product_id":
            product.get(
                "data-id"
            ),

        "name":
            (
                name_tag.get_text(
                    strip=True
                )
                if name_tag is not None
                else None
            ),

        "price":
            (
                price_tag.get_text(
                    strip=True
                )
                if price_tag is not None
                else None
            ),

        "link":
            (
                link_tag.get(
                    "href"
                )
                if link_tag is not None
                else None
            ),
    }


    records.append(
        record
    )


for record in records:

    print(
        record
    )

Common Mistakes

초보자가 자주 하는 선택자 실수

01

#과 .을 반대로 사용한다

#products → id .product → class

from bs4 import BeautifulSoup


PRODUCT_SELECTOR = (
    "article.product"
)


NAME_SELECTOR = (
    ".name"
)


PRICE_SELECTOR = (
    ".price"
)


LINK_SELECTOR = (
    "a.detail-link"
)


def parse_products(
    html: str,
) -> list[dict]:

    soup = BeautifulSoup(
        html,
        "html.parser",
    )


    products = soup.select(
        PRODUCT_SELECTOR
    )


    records = []


    for product in products:

        name_tag = product.select_one(
            NAME_SELECTOR
        )


        price_tag = product.select_one(
            PRICE_SELECTOR
        )


        link_tag = product.select_one(
            LINK_SELECTOR
        )


        records.append(
            {
                "product_id":
                    product.get(
                        "data-id"
                    ),

                "name":
                    (
                        name_tag.get_text(
                            strip=True
                        )
                        if name_tag
                        else None
                    ),

                "price":
                    (
                        price_tag.get_text(
                            strip=True
                        )
                        if price_tag
                        else None
                    ),

                "link":
                    (
                        link_tag.get(
                            "href"
                        )
                        if link_tag
                        else None
                    ),
            }
        )


    return records

08

Interview Point

면접에서 설명할 수 있어야 할 질문

Q1 find()와 select_one()의 차이는 무엇인가요?

A.

둘 다 첫 번째 일치 요소 하나를 찾지만, find()는 Tag와 Attribute 조건을 BeautifulSoup 인자로 표현하고, select_one()은 CSS Selector 문법을 사용합니다. 찾지 못하면 둘 다 None이 될 수 있습니다.

Q2 find_all()과 select()의 차이는 무엇인가요?

A.

둘 다 여러 요소를 검색합니다. find_all()은 Tag와 Attribute 조건을 사용하고, select()은 CSS Selector로 복잡한 HTML 관계를 표현하기 편리합니다.

Q3 CSS Selector에서 #과 .은 무엇인가요?

A.

#은 id를, .은 class를 의미합니다.

#products → id / .product → class

Q4 article.product와 article .product의 차이는?

A.

article.product는 article Tag 자체가 product Class를 가진 같은 요소이고, article .product는 article 내부 후손 중 product Class를 가진 요소를 의미합니다.

Q5 공백과 >는 어떻게 다른가요?

A.

공백은 모든 깊이의 후손 관계, >는 바로 아래 직접 자식 관계를 의미합니다.

Q6 여러 Class를 동시에 가진 요소는 어떻게 선택하나요?

A.

Class 이름을 공백 없이 연속해서 작성합니다.

.product.featured

Q7 select_one()으로 못 찾으면 무엇이 반환되나요?

A.

None이 될 수 있습니다. 따라서 Text나 Attribute에 접근하기 전에 검색 결과 존재 여부를 확인합니다.

Q8 select() 결과가 비어 있으면 오류인가요?

A.

반드시 Exception은 아닙니다. 현재 HTML에서 Selector와 일치하는 요소가 0개라는 결과일 수 있습니다.

Q9 Attribute Selector는 언제 사용하나요?

A.

href, src, type, data-* 등 HTML Attribute의 존재 여부나 값을 기준으로 요소를 찾고 싶을 때 사용합니다.

a[href] / [data-id="P001"]

Q10 CSS Selector와 정규표현식의 역할 차이는 무엇인가요?

A.

CSS Selector는 HTML 구조와 관계를 표현하는 데 적합하고, 정규표현식은 Text나 Attribute 값의 문자열 패턴을 검색하는 데 유용합니다.

Q11 BeautifulSoup에서 XPath를 사용할 수 있나요?

A.

이번 교안 기준 BeautifulSoup은 CSS Selector를 지원하지만 XPath는 직접 지원하지 않습니다. XPath는 이후 Selenium·Scrapy에서 다시 공부합니다.

Q12 Copy selector를 그대로 사용하지 않는 이유는?

A.

자동 생성 Selector는 긴 DOM 경로나 nth-child 등에 의존하여 구조가 조금만 바뀌어도 깨질 수 있기 때문입니다. 의미 있는 id·class·Attribute를 중심으로 단순화하는 것이 좋습니다.

Q13 Browser에서는 찾는데 BeautifulSoup에서 []인 이유는?

A.

Browser가 JavaScript 실행 이후 DOM을 보고 있지만, Requests가 받은 최초 Response HTML에는 해당 데이터가 없을 수 있습니다. Network/API 또는 Selenium 필요 여부를 확인합니다.

Q14 좋은 크롤링 Selector의 조건은 무엇인가요?

A.

원하는 범위만 정확하게 선택하고, 반복되는 데이터에도 적용되며, 지나치게 DOM 위치에 의존하지 않고 의미 있는 id·class·Attribute를 사용하는 읽기 쉽고 유지보수 가능한 Selector가 좋습니다.

Q15 find()와 select() 계열을 함께 사용해도 되나요?

A.

가능합니다. find()로 부모 영역을 찾은 뒤 select()을 사용하거나, CSS Selector로 영역을 좁힌 뒤 find()와 Regex를 사용할 수도 있습니다.

Q16 Selector 결과 개수를 왜 확인해야 하나요?

A.

문법적으로 동작하는 Selector도 너무 많은 요소나 너무 적은 요소를 선택할 수 있기 때문입니다. 예상 건수와 실제 Match Count를 비교하면 Selector 오류나 HTML 구조 변경을 발견하기 쉽습니다.

오늘의 암기 포인트

DevTools → Selector → select() → len() → Data
  • find() = 하나, 없으면 None
  • find_all() = 여러 개, 없으면 빈 결과
  • select_one() = CSS Selector 단일 검색
  • select() = CSS Selector 복수 검색
  • #id = id Attribute
  • .class = class Attribute
  • article.product = article이면서 product Class
  • article .product = article 내부의 product 후손
  • .parent .child = 후손
  • .parent > .child = 직접 자식
  • .product.featured = 두 Class를 동시에 가진 요소
  • a[href] = href가 존재하는 a
  • CSS Selector = HTML 구조 검색
  • Regex = 문자열 패턴 검색
  • BeautifulSoup은 CSS Selector를 지원하지만 XPath는 직접 사용하지 않는다.
  • select() 후에는 len()으로 Match Count도 확인한다.
  • Browser DOM과 response.text는 다를 수 있다.

헷갈리기 쉬운 개념

find() vs select_one()

둘 다 단일 검색이지만 Tag 조건과 CSS Selector라는 문법 차이가 있습니다.

find_all() vs select()

둘 다 복수 검색이지만 검색 조건을 표현하는 방식이 다릅니다.

#name vs .name

#은 id, .은 class입니다.

article.product vs article .product

앞은 같은 요소, 뒤는 부모·후손 관계입니다.

공백 vs >

공백은 후손, >는 직접 자식입니다.

None vs []

단일 검색 실패와 복수 검색 결과 없음의 차이입니다.

CSS Selector vs Regex

HTML 구조와 문자열 패턴이라는 목적 차이가 있습니다.

CSS Selector vs XPath

이번 BeautifulSoup 단원에서는 CSS Selector를 사용하고, XPath는 이후 Selenium·Scrapy에서 다시 만납니다.

DevTools DOM vs response.text

JavaScript 동적 페이지에서는 서로 다른 구조일 수 있습니다.

Selector 오류 vs HTTP 오류

[]가 나와도 403·404 안내 페이지를 파싱한 것이 아닌지 먼저 확인합니다.
