Python & Data · Web Crawling · Lesson 02

웹크롤링과 웹스크레이핑

웹크롤링은 여러 웹페이지를 규칙에 따라 탐색하는 과정이고, 웹스크레이핑은 방문한 페이지에서 필요한 데이터를 추출하는 과정입니다. 이 모든 과정의 기반에는 URL과 HTTP Request·Response 구조가 있습니다.

핵심 공식
Crawling = 어디를 방문할 것인가? Scraping = 무엇을 가져올 것인가?
URL → HTTP Request → Web Server → HTTP Response → HTML / JSON

학습 목표

  • 웹크롤링과 웹스크레이핑의 차이를 설명할 수 있다.
  • Client와 Server의 역할을 구분할 수 있다.
  • URL의 Scheme, Host, Path, Query, Fragment 구조를 구분할 수 있다.
  • HTTP Request와 HTTP Response의 기본 구조를 설명할 수 있다.
  • GET과 POST가 HTTP Method라는 것을 이해한다.
  • Request Header와 Response Header의 역할을 이해한다.
  • 200, 403, 404 등의 HTTP 상태 코드를 크롤링 흐름 안에서 해석할 수 있다.
  • Timeout과 HTTP 상태 코드의 차이를 설명할 수 있다.
  • HTTP 오류와 BeautifulSoup·Selenium 선택자 오류가 서로 다른 단계에서 발생한다는 것을 구분할 수 있다.
01

Core Concept

Crawling, Scraping 그리고 HTTP

웹크롤링을 제대로 이해하려면 단순히 requests.get() 같은 코드를 외우는 것이 아니라, 페이지 탐색과 데이터 추출, 그리고 그 아래에서 동작하는 HTTP 통신을 서로 구분 해야 합니다.

Web Crawling

웹크롤링

정해진 규칙에 따라 하나 또는 여러 웹페이지를 방문하고 링크를 따라가며 다음 수집 대상을 탐색하는 과정입니다.

핵심 질문 어디를 방문할 것인가?
목록 1페이지 → 상세 URL 발견 → 상세 페이지 → 다음 페이지
Web Scraping

웹스크레이핑

현재 방문한 웹페이지에서 상품명, 가격, 주소, 작성일처럼 필요한 특정 정보를 추출하는 과정입니다.

핵심 질문 무엇을 가져올 것인가?
HTML → 상품명 가격 평점
Crawling과 Scraping은 경쟁 관계가 아니다.

실제 프로그램에서는 여러 URL을 방문하는 Crawling과 각 페이지에서 필요한 값을 추출하는 Scraping이 함께 사용됩니다.

Client와 Server

CLIENT

요청하는 쪽

Chrome, Edge 같은 브라우저뿐 아니라 Python의 urllib·requests도 HTTP Client 역할을 할 수 있습니다.

Browser urllib requests
SERVER

요청을 처리하는 쪽

Client가 보낸 URL과 Request를 확인하고 요청 결과를 HTTP Response 형태로 반환합니다.

Web Server API Server

URL은 요청 대상의 주소다

https://example.com/products?category=book&page=2#review
Scheme https

어떤 통신 방식을 사용할지 표현

Host example.com

요청 대상 서버

Path /products

서버 내부의 자원 위치

Query category=book&page=2

검색 조건이나 페이지 번호 등의 추가 정보

Fragment #review

문서 내부 특정 위치를 나타낼 수 있는 부분

HTTP Request

METHOD GET / POST

서버에 어떤 종류의 작업을 원하는지 나타냅니다.

TARGET URL

어느 자원에 요청하는지를 나타냅니다.

HEADERS User-Agent · Accept

요청에 필요한 추가 정보를 전달합니다.

BODY 요청 데이터

필요한 경우 서버에 보낼 실제 데이터를 포함할 수 있습니다.

HTTP Response

STATUS 200 · 403 · 404

요청을 처리한 결과를 숫자로 나타냅니다.

HEADERS Content-Type 등

서버가 응답에 대한 추가 정보를 제공합니다.

BODY HTML · JSON · 파일

실제로 Client가 전달받는 응답 데이터입니다.

기억하기

HTTP Request는 “무엇을 요청했는가”, HTTP Response는 “서버가 무엇을 돌려주었는가”이다.

04

Python Example

Python 코드로 HTTP 구조 미리보기

`urllib.request`의 자세한 문법은 다음 단원에서 공부합니다. 이번에는 첨부 교안의 urlopen() → status → headers → read() 구조를 이용해 HTTP Request와 Response가 실제 코드에서 어떻게 보이는지만 확인합니다.

예제 1. URL 요청과 Response 확인 

from urllib.request import urlopen


url = "https://example.com/"


response = urlopen(
    url,
    timeout=10,
)


print("=" * 50)
print("HTTP Response Check")
print("=" * 50)


print("\n[1] 요청 URL")
print(url)


print("\n[2] 상태 코드")
print(response.status)


print("\n[3] 응답 Headers")
print(response.headers)


body = response.read()


print("\n[4] Response Body 자료형")
print(type(body))


print("\n[5] Response Body 일부")
print(body[:200])
1 url 요청 대상

어떤 웹 자원을 요청할지 URL 문자열로 지정합니다.

2 urlopen() HTTP 요청

서버에 요청을 보내고 응답 객체를 얻습니다.

3 status 상태 코드

HTTP 요청 처리 결과를 확인합니다.

4 headers 응답 정보

서버가 함께 전달한 Response Header를 확인합니다.

5 read() Response Body

서버가 보내 준 실제 응답 데이터를 읽습니다.

6 bytes 현재 자료형

자세한 bytes와 decode()는 다음 단원에서 공부합니다.

실행 결과를 이렇게 읽는다

200

HTTP 요청 자체가 정상적으로 처리되었다.

Headers

서버가 Response에 대한 부가 정보를 함께 제공했다.

<class 'bytes'>

Response Body를 아직 바이너리 데이터 상태로 읽었다.

URL → urlopen() → Request → Server → Response → status / headers / read()

예제 2. 여러 URL을 순회하는 Crawling 개념 

urls = [

05

Common Mistakes

초보자가 자주 하는 실수

01

Crawling과 Scraping을 완전히 같은 개념으로 생각한다

학습 단계에서는 페이지 탐색과 데이터 추출을 나누어 이해하는 것이 좋습니다.

02

URL을 아무 의미 없는 문자열로만 생각한다

URL에는 Scheme, Host, Path, Query 등 요청 대상을 구성하는 여러 부분이 있습니다.

03

HTTP Request와 브라우저 화면을 같은 것으로 생각한다

Request는 서버에 보내는 요청이고, 화면은 Response 이후 브라우저가 HTML·CSS·JavaScript 등을 처리한 결과입니다.

04

200 OK이면 크롤링 전체가 성공했다고 생각한다

HTTP 요청이 성공했더라도 로그인 안내나 다른 페이지를 받았을 수 있습니다. 실제 Body와 수집 데이터를 추가로 확인해야 합니다.

05

403이 나오면 무조건 User-Agent만 변경한다

User-Agent는 확인할 항목 중 하나입니다. 접근 가능 여부, 인증, 요청 조건, 사이트 정책 등을 함께 확인해야 합니다.

06

404를 서버 자체가 고장 난 것으로 생각한다

먼저 URL, Path, Query Parameter, 페이지 번호를 확인합니다.

07

Timeout을 HTTP 상태 코드로 생각한다

Timeout은 정상적인 Response 상태 코드를 받기 전에 요청이나 응답 대기 과정에서 발생할 수 있습니다.

08

데이터가 없으면 바로 Selector부터 바꾼다

URL → Status → Response → HTML → Selector
09

브라우저에 보이는 값은 최초 HTML에도 반드시 있다고 생각한다

JavaScript 실행 이후 데이터가 만들어지는 동적 페이지에서는 두 상태가 다를 수 있습니다.

06

HTTP & Error Reading

HTTP 상태 코드와 오류 위치 읽는 법

크롤링 오류는 하나의 종류가 아닙니다. 환경 → URL → Request → Response → HTML → Selector → 저장 중 어느 단계에서 실패했는지를 먼저 찾아야 합니다.

1xx 정보

요청 처리와 관련된 중간 정보

2xx 성공

요청이 정상적으로 처리됨

3xx 이동

다른 위치로 이동하거나 재사용

4xx 요청·접근 문제

주소, 인증, 접근 조건 등을 확인

5xx 서버 문제

서버 측 처리 실패 또는 일시적 장애

크롤링에서 자주 확인할 상태 코드

상태 기본 해석 크롤링에서 확인할 내용
200 OK 요청 성공 실제 Body가 원하는 페이지인지 추가 확인
301 / 302 다른 위치로 이동 최종 요청 URL과 이동된 페이지 확인
400 잘못된 요청 Parameter와 요청 형식 확인
401 인증 필요 로그인·인증 정보 확인
403 Forbidden 요청 처리 거부 공개 여부, 인증, Header, 접근 정책, 요청 조건 확인
404 Not Found 요청 대상 확인 필요 URL, Path, Query, 페이지 번호 확인
429 요청 빈도 문제 반복 요청 간격과 요청량 확인
500 서버 내부 오류 서버 상태와 일시적 오류 여부 확인
503 서비스 이용 불가 서버 점검·과부하 여부 확인
200

HTTP 성공 ≠ 크롤링 전체 성공

상품 페이지 요청 → 200 OK → 로그인 안내 페이지

HTTP 계층은 성공했지만, 원하는 상품 데이터 수집에는 실패한 상황일 수 있습니다.

403

Forbidden을 만나면 요청 조건을 확인한다

공개 페이지인가? 인증이 필요한가? Header가 필요한가? 접근 정책은? 요청 빈도는?

첨부 교안에서는 User-Agent Header 추가 예제를 보여 주지만, 모든 403이 User-Agent 하나로 해결되는 것은 아닙니다.

404

URL 구조를 먼저 확인한다

오타 Path Query 페이지 번호 상대 URL 조합

Timeout은 Status Code가 아니다

Request 요청 전송
→
Waiting 응답 대기
→
시간 안에 응답 Status Code
제한 시간 초과 Timeout

선택자 오류와도 구분한다

None

BeautifulSoup 단일 선택 실패

선택자가 틀린 것일 수도 있지만 실제로 403 페이지나 로그인 페이지를 받은 상태일 수도 있습니다.

[]

복수 선택 결과 없음

HTML 구조 변경, 데이터 없음, 동적 페이지 등 다양한 가능성을 확인합니다.

NoSuchElementException

Selenium 요소 탐색 실패

브라우저 DOM과 Locator 단계에서 발생하는 문제입니다.

TimeoutException

Selenium 기대 조건 실패

특정 요소나 조건이 제한 시간 안에 만족되지 않은 경우입니다.

08

Interview Point

면접에서 설명할 수 있어야 할 질문

Q1 웹크롤링과 웹스크레이핑의 차이는 무엇인가요?

A.

웹크롤링은 정해진 규칙에 따라 여러 URL이나 웹페이지를 탐색하는 과정이고, 웹스크레이핑은 방문한 페이지에서 필요한 특정 정보를 추출하는 과정입니다.

Crawling = 탐색 / Scraping = 추출

Q2 Client와 Server의 역할은 무엇인가요?

A.

Client는 서버에 Request를 보내는 쪽이고, Server는 요청을 처리하여 HTTP Response를 반환하는 쪽입니다. Python의 urllib나 requests도 HTTP Client 역할을 할 수 있습니다.

Q3 HTTP Request와 Response의 차이는 무엇인가요?

A.

Request는 Client가 서버에 보내는 요청이고, Response는 서버가 처리 결과를 돌려주는 응답입니다. Response에서는 Status Code, Headers, Body 등을 확인할 수 있습니다.

Q4 URL은 어떤 역할을 하나요?

A.

요청할 서버와 자원의 위치, 추가 요청 조건 등을 표현합니다. 학습 단계에서는 Scheme, Host, Path, Query, Fragment 등으로 나누어 이해할 수 있습니다.

Q5 HTTP Method란 무엇인가요?

A.

서버에 어떤 종류의 작업을 요청하는지 표현하는 방식입니다. 웹 자원 조회에서는 GET을 자주 사용하고, 데이터 전달이 필요한 경우 POST도 볼 수 있습니다.

Q6 HTTP Response의 주요 구성은 무엇인가요?

A.

상태 코드, Response Headers, Response Body로 구분해서 볼 수 있습니다.

Status + Headers + Body

Q7 HTTP 200이면 크롤링에 성공한 것인가요?

A.

HTTP 요청 자체는 성공했지만 전체 데이터 수집 성공을 의미하지는 않습니다. 실제 Response Body가 예상한 페이지인지, 필요한 데이터가 존재하는지까지 확인해야 합니다.

Q8 403 Forbidden을 만나면 무엇을 확인해야 하나요?

A.

접근 가능한 자원인지, 인증이 필요한지, 요청 Header나 요청 조건이 적절한지, 사이트의 접근 정책 등을 확인해야 합니다.

Q9 404가 발생하면 무엇부터 확인하나요?

A.

요청 URL, Path, Query Parameter, 페이지 번호와 같은 요청 주소 구조를 먼저 확인합니다.

Q10 Timeout은 HTTP 상태 코드인가요?

A.

아닙니다. HTTP Response를 정상적으로 받기 전에 네트워크 연결이나 응답 대기 시간이 초과되어 발생할 수 있는 상황입니다.

Q11 브라우저와 Python 크롤러의 공통점은 무엇인가요?

A.

둘 다 HTTP Client가 되어 서버에 Request를 보내고 Response를 받을 수 있습니다. 브라우저는 화면 렌더링에 집중하고, Python 크롤러는 응답 데이터를 프로그램으로 처리한다는 차이가 있습니다.

Q12 데이터가 나오지 않을 때 무엇부터 확인해야 하나요?

A.

URL → Request → Status → Response Body → 데이터 존재 여부를 먼저 확인한 뒤 HTML Selector를 확인합니다.

오늘의 암기 포인트

Crawling 어디를 방문할 것인가? Scraping 무엇을 가져올 것인가?
  • 웹 통신은 Client → Request → Server → Response 구조로 이해한다.
  • URL에는 Scheme, Host, Path, Query, Fragment 등의 부분이 있다.
  • Request는 Method, URL, Headers, Body 관점으로 볼 수 있다.
  • Response는 Status Code, Headers, Body 관점으로 볼 수 있다.
  • 200 = HTTP 요청 성공
  • 403 = 요청 처리 거부
  • 404 = 요청 대상 확인 필요
  • Timeout은 HTTP Status Code가 아니다.
  • HTTP 200과 전체 크롤링 성공은 같은 뜻이 아니다.
  • 데이터가 없으면 URL → Status → Response → HTML → Selector 순서로 확인한다.

헷갈리기 쉬운 개념

Crawling vs Scraping

Crawling은 페이지 탐색, Scraping은 데이터 추출입니다.

Request vs Response

Request는 Client가 보내고, Response는 Server가 돌려줍니다.

200 OK vs 수집 성공

HTTP 요청 성공과 원하는 데이터 추출 성공은 다른 단계입니다.

403 vs 404

403은 요청 처리 거부, 404는 요청 대상 주소를 우선 확인합니다.

Status Code vs Timeout

Timeout은 정상 Response 상태 코드를 받기 전에 발생할 수 있습니다.

HTTP 오류 vs Selector 오류

HTTP 오류는 요청·응답 단계, Selector 오류는 HTML을 받은 이후 단계입니다.
