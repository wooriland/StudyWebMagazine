Python Basics · Lesson 24

예외 처리와 사용자 정의 예외

예외 처리는 프로그램의 오류를 숨기는 문법이 아닙니다. 실행 중 실패할 가능성이 있는 작업을 try에서 시도하고, except에서 발생한 문제를 처리하며, else에서 성공한 경우의 후속 작업을 수행하고, finally에서 성공·실패와 관계없는 정리 작업을 실행하는 제어 구조입니다. 또한 raise를 이용하면 업무 규칙을 위반한 상태를 직접 예외로 만들 수 있고, Exception을 상속하여 프로그램의 의미를 담은 사용자 정의 예외를 설계할 수 있습니다.

Exception try except else finally raise Traceback Propagation BaseException Custom Exception rollback cleanup

이 단원의 중심 질문

실행 중 문제가 발생했을 때 프로그램을 무조건 종료시키지 않고, 실패 원인에 맞게 처리하고 필요한 상태를 안전하게 정리하려면 어떻게 해야 할까요?

예외 처리를 이해하려면 단순히 try-except 문법을 외우는 것이 아니라 예외가 발생하는 순간 try의 나머지 코드가 중단되고, 일치하는 except를 탐색하며, 처리되지 않은 예외는 호출한 코드로 전파된다는 실행 흐름을 함께 이해해야 합니다.

학습 목표

  • 예외가 무엇이며 처리되지 않은 예외가 프로그램 흐름에 어떤 영향을 주는지 설명할 수 있습니다.
  • try와 except의 역할을 구분할 수 있습니다.
  • 여러 종류의 예외를 각각 처리하거나 튜플로 묶어 한 번에 처리할 수 있습니다.
  • except Error as error로 발생한 예외 객체를 확인할 수 있습니다.
  • BaseException과 Exception의 관계를 큰 구조로 이해할 수 있습니다.
  • 구체적인 예외를 상위 예외보다 먼저 작성해야 하는 이유를 설명할 수 있습니다.
  • else와 finally의 실행 조건을 구분할 수 있습니다.
  • 처리되지 않은 예외가 호출 스택을 따라 전파되는 구조를 설명할 수 있습니다.
  • ValueError, TypeError, IndexError, KeyError, AttributeError를 원인별로 구분할 수 있습니다.
  • raise를 이용해 업무 규칙 위반을 예외로 표현할 수 있습니다.
  • Exception을 상속하여 사용자 정의 예외를 만들 수 있습니다.
  • raise ... from ...으로 원래 예외와 새로운 예외를 연결할 수 있습니다.
  • 파일·DB·웹 요청에서 예외 처리와 리소스 정리 흐름을 설명할 수 있습니다.
  • Pandas 데이터 변환 실패가 NaN, dtype, shape 변화로 이어지는 경우를 이해할 수 있습니다.

01 · Core Concept

예외는 정상 실행 흐름을 바꾸는 객체다

예외는 프로그램 실행 중 현재 작업을 정상적으로 계속할 수 없는 상황이 발생했음을 나타냅니다. 예외를 처리하지 않으면 현재 코드의 실행이 중단되고 호출 스택을 따라 상위 코드로 전달됩니다.

정상 실행 
number = int("20")

print(number)
20
≠
예외 발생 
number = int("Python")

print(number)
ValueError
정상 문법 실행 가능
실행 중 문제 Exception 발생
처리 코드 있음 except 이동
처리 코드 없음 상위로 전파
1 print("시작")
→
2 int("Python")
→
3 이후 정상 코드 중단

예외 처리의 목적

  • 오류가 발생한 원인을 구분합니다.
  • 사용자에게 이해 가능한 메시지를 제공합니다.
  • 실패한 작업의 상태를 복구합니다.
  • DB 트랜잭션을 롤백할 수 있습니다.
  • 파일·DB·네트워크 리소스를 정리합니다.
  • 현재 위치에서 처리할 수 없는 예외는 상위 계층으로 전달합니다.

03 · Except Patterns

예외를 어떤 범위까지 잡을 것인가?

bare except 
except:
    ...

매우 넓은 범위의 예외를 처리하므로 특별한 이유가 없다면 주의해서 사용합니다.

특정 예외 
except ValueError:
    ...

어떤 실패를 예상하고 있는지 코드에서 바로 확인할 수 있습니다.

여러 예외 
except (
    ValueError,
    TypeError,
):
    ...

여러 예외에 동일한 처리가 필요할 때 하나의 블록으로 묶습니다.

예외 객체 
except ValueError as error:
    print(error)

예외 객체와 실제 오류 메시지를 확인할 수 있습니다.

일반 예외 
except Exception as error:
    ...

대부분의 일반적인 애플리케이션 예외를 마지막 단계에서 처리할 수 있습니다.

BaseException과 Exception

BaseException
KeyboardInterrupt Ctrl + C 중단
SystemExit 프로그램 종료
Exception 일반 애플리케이션 예외

bare except:는 KeyboardInterrupt나 SystemExit 같은 흐름까지 너무 넓게 잡을 수 있습니다.

구체적인 예외부터 처리한다

잘못된 순서 
except Exception:
    ...

except KeyError:
    ...

KeyError가 이미 위의 Exception에 포함됩니다.

권장 순서 
except KeyError:
    ...

except Exception as error:
    ...

구체적인 하위 예외부터 검사하고 마지막에 넓은 예외를 둡니다.

04 · Else & Finally

성공 경로와 정리 경로를 분리한다

else try가 예외 없이 정상 완료

성공한 경우에만 필요한 후속 작업을 작성합니다.

finally 성공·실패와 관계없이 실행

파일·DB·네트워크 리소스 정리에 주로 사용합니다. 

try:
    number = int(
        input("숫자: ")
    )

    result = 100 / number

except ValueError:
    print(
        "숫자를 입력해야 합니다."
    )

except ZeroDivisionError:
    print(
        "0으로 나눌 수 없습니다."
    )

else:
    print(
        "계산 결과:",
        result,
    )

finally:
    print(
        "계산 작업을 종료합니다."
    )

정상 실행

try → else → finally

처리되는 예외

try → except → finally

처리되지 않은 예외

try → finally → 상위로 전파
파일 close
Database connection close
네트워크 연결 정리
잠금 lock release
로그 종료 기록

finally 안의 return은 주의한다 

def example() -> int:
    try:
        return 10

    finally:
        return 20


print(example())
20

finally의 반환이 기존 반환 흐름을 덮어버릴 수 있으므로 일반적으로 finally는 리소스 정리에 집중시키는 것이 좋습니다.

08 · Custom Exception

프로그램의 업무 의미를 예외 클래스로 표현한다

내장 예외만으로 업무 문제의 의미를 충분히 표현하기 어렵다면 Exception을 상속한 사용자 정의 예외를 만들 수 있습니다.

InvalidScoreError 잘못된 점수
InsufficientBalanceError 잔액 부족
ReservationClosedError 예약 마감
InvalidOrderStateError 잘못된 주문 상태 
class InvalidScoreError(
    Exception
):
    pass
def validate_score(
    score: int,
) -> None:
    if not 0 <= score <= 100:
        raise InvalidScoreError(
            f"잘못된 점수입니다: {score}"
        )
Exception 부모 예외
↑ 상속
InvalidScoreError 업무 예외
↓
validate_score() 규칙 검사
↓
raise 예외 발생
↓

사용자 정의 예외에 추가 데이터 저장 

class InvalidScoreError(
    Exception
):
    def __init__(
        self,
        score: int,
    ) -> None:
        self.score = score

        super().__init__(
            f"점수 범위 오류: {score}"
        )
try:
    raise InvalidScoreError(
        150
    )

except InvalidScoreError as error:
    print(
        "입력값:",
        error.score,
    )

    print(
        "메시지:",
        error,
    )

raise ... from ... 으로 원인 연결 

class ScoreParseError(
    Exception
):
    pass


def parse_score(
    value: str,
) -> int:
    try:
        return int(value)

    except ValueError as error:
        raise ScoreParseError(
            "점수를 해석할 수 없습니다: "
            f"{value}"
        ) from error

from __future__ import annotations


class ScoreRangeError(
    Exception
):
    """점수 범위를 벗어난 경우 발생한다."""

    def __init__(
        self,
        score: int,
    ) -> None:
        self.score = score

        super().__init__(
            "점수는 0~100 사이여야 합니다. "
            f"입력값: {score}"
        )


def print_section(
    title: str,
) -> None:
    """실습 영역의 제목을 출력한다."""

    print(
        "\n"
        + "=" * 70
    )

    print(title)

    print(
        "=" * 70
    )


def parse_score(
    value: str,
) -> int:
    """문자열 점수를 정수로 변환한다."""

    try:
        return int(value)

    except ValueError as error:
        raise ValueError(
            f"숫자 형식이 아닙니다: {value}"
        ) from error


def validate_score(
    score: int,
) -> None:
    """점수의 업무 범위를 검사한다."""

    if not 0 <= score <= 100:
        raise ScoreRangeError(
            score
        )


def calculate_grade(
    score: int,
) -> str:
    """점수에 따른 등급을 반환한다."""

    if score >= 90:
        return "A"

    if score >= 80:
        return "B"

    if score >= 70:
        return "C"

    if score >= 60:
        return "D"

    return "F"


def process_score(
    raw_score: str,
) -> None:
    """입력 문자열을 검증하고 등급을 출력한다."""

    print_section(
        f"입력값: {raw_score!r}"
    )

    try:
        score = parse_score(
            raw_score
        )

        validate_score(
            score
        )

    except ValueError as error:
        print(
            "입력 형식 오류:",
            error,
        )

    except ScoreRangeError as error:
        print(
            "업무 범위 오류:",
            error,
        )

        print(
            "잘못된 점수:",
            error.score,
        )

    else:
        grade = calculate_grade(
            score
        )

        print(
            "점수:",
            score,
        )

        print(
            "등급:",
            grade,
        )

    finally:
        print(
            "점수 처리 작업 종료"
        )


def main() -> None:
    """여러 입력값에 대해 예외 흐름을 확인한다."""

    test_values = [
        "85",
        "Python",
        "150",
        "-10",
    ]

    for value in test_values:
        process_score(
            value
        )


if __name__ == "__main__":
    main()

코드 실행 순서

  1. 테스트 문자열을 process_score()에 전달합니다.
  2. parse_score()가 문자열을 정수로 변환합니다.
  3. 변환할 수 없다면 ValueError가 발생합니다.
  4. 숫자로 변환되면 validate_score()가 0~100 범위를 확인합니다.
  5. 범위를 벗어나면 ScoreRangeError를 직접 발생시킵니다.
  6. 두 검사 모두 성공하면 else에서 등급을 계산합니다.
  7. 어떤 경로든 마지막에는 finally가 실행됩니다.

12 · Common Mistakes

초보자가 자주 하는 예외 처리 실수

01

프로그램 전체를 하나의 try로 감쌉니다

어디에서 실패했는지 파악하기 어렵고 실제 버그까지 숨길 수 있습니다.

02

항상 bare except:만 사용합니다

너무 넓은 예외를 처리하므로 구체적인 예외 클래스를 우선합니다.

03

Exception을 가장 먼저 작성합니다

하위 예외가 먼저 잡혀 구체적인 처리 블록이 의미를 잃습니다.

04

예외를 pass로 완전히 숨깁니다

실패 사실이 남지 않아 원인을 추적하기 매우 어려워집니다.

05

else의 의미를 일반 조건문의 else와 혼동합니다

예외 처리의 else는 try가 정상 완료된 경우에만 실행됩니다.

06

finally는 실패했을 때만 실행된다고 생각합니다

성공·처리된 실패·처리되지 않은 실패 모두에서 실행됩니다.

07

성공해야만 실행할 코드를 finally에 넣습니다

성공 후 작업은 else가 더 적절합니다.

08

finally 안에서 무조건 return 합니다

기존 반환값이나 예외 흐름을 덮어버릴 수 있습니다.

09

raise를 메시지 출력으로 생각합니다

raise는 실제 예외를 발생시켜 정상 실행 흐름을 중단합니다.

10

사용자 정의 예외를 일반 클래스처럼 만듭니다

보통 Exception을 상속해야 합니다.

11

DB 실패 후 오류만 출력합니다

트랜잭션이라면 rollback()이 필요한지 확인해야 합니다.

12

선택자 오류를 단순히 AttributeError로 숨깁니다

먼저 왜 select_one() 결과가 None인지 확인해야 합니다.

16 · Interview

면접 포인트

Python에서 예외란 무엇입니까?

프로그램 실행 중 정상적인 흐름을 계속할 수 없는 상황이 발생했음을 나타내는 객체입니다. 처리되지 않은 예외는 현재 실행 흐름을 중단하고 호출 스택을 따라 상위로 전파됩니다.

예외 처리는 왜 사용합니까?

실패 가능 작업에서 문제가 발생했을 때 프로그램을 무조건 종료하는 대신 오류 종류에 맞는 복구, 사용자 안내, 로그 기록과 리소스 정리를 수행하기 위해 사용합니다.

try의 역할은 무엇입니까?

예외가 발생할 수 있는 작업을 실행합니다. 실행 중 예외가 발생하면 해당 지점 아래의 try 코드는 건너뛰고 일치하는 except를 찾습니다.

여러 예외를 한 번에 처리하려면 어떻게 합니까?

예외 클래스를 튜플로 묶어 except (ValueError, TypeError): 형태로 작성할 수 있습니다.

except Error as error의 error는 무엇입니까?

발생한 예외 객체입니다. 예외 메시지를 확인하거나 사용자 정의 예외가 보관한 추가 데이터를 확인할 수 있습니다.

bare except:와 except Exception:은 무엇이 다릅니까?

bare except는 매우 넓은 BaseException 계열까지 잡을 수 있지만, Exception은 일반적인 애플리케이션 예외의 기반 클래스입니다. 가능한 경우 예상되는 구체적인 예외를 직접 지정하는 것이 좋습니다.

여러 except의 순서는 어떻게 작성해야 합니까?

구체적인 하위 예외를 먼저 작성하고, 마지막에 Exception 같은 넓은 상위 예외를 작성합니다.

else는 언제 실행됩니까?

try 블록이 예외 없이 정상적으로 완료되었을 때만 실행됩니다.

finally는 언제 실행됩니까?

예외 발생 여부와 관계없이 실행됩니다. 주로 파일, DB 연결, 네트워크와 같은 리소스의 정리에 사용합니다.

else와 finally의 차이는 무엇입니까?

else는 try 성공 시에만 실행되고, finally는 성공·실패와 관계없이 실행됩니다.

ValueError와 TypeError의 차이는 무엇입니까?

ValueError는 자료형 자체는 받을 수 있지만 실제 값이 부적절한 경우이고, TypeError는 자료형이나 연산 조합 자체가 적절하지 않은 경우입니다.

IndexError와 KeyError는 어떻게 다릅니까?

IndexError는 리스트·튜플·문자열 등의 없는 위치에 접근할 때 발생하고, KeyError는 딕셔너리에 없는 키를 요청할 때 발생합니다.

예외 전파란 무엇입니까?

현재 함수에서 처리하지 않은 예외가 그 함수를 호출한 상위 코드로 전달되는 동작입니다.

raise는 무엇입니까?

개발자가 직접 예외 객체를 발생시키는 문법입니다. 업무 규칙에 맞지 않는 상태를 호출자에게 전달할 때 사용할 수 있습니다.

사용자 정의 예외는 어떻게 만듭니까?

일반적으로 Exception을 상속한 클래스를 정의합니다. 클래스 이름으로 오류의 업무 의미를 명확하게 표현할 수 있습니다.

raise ... from ...의 목적은 무엇입니까?

새로운 예외를 발생시키면서 그 원인이 된 기존 예외를 연결합니다. 낮은 수준의 기술 예외를 업무 수준 예외로 바꾸면서 원인을 보존할 때 유용합니다.

왜 try 영역은 작게 작성하는 것이 좋습니까?

정확히 어떤 작업이 실패했는지 파악하기 쉽고, 예상하지 않은 다른 프로그래밍 오류까지 같은 except에서 숨기는 것을 방지할 수 있기 때문입니다.

DB 예외 처리의 핵심 흐름은 무엇입니까?

정상 작업이면 commit(), 실패하면 필요에 따라 rollback(), 마지막에는 연결을 정리하는 흐름이 중요합니다.

HTTP 404와 Python 예외는 같은 것입니까?

아닙니다. 404는 서버가 반환한 HTTP 상태이고, Timeout이나 ConnectionError는 요청 과정의 예외입니다. raise_for_status()를 사용하면 HTTP 오류 상태를 예외로 바꿀 수 있습니다.

Pandas에서 변환 실패를 예외 대신 NaN으로 처리할 수 있습니까?

가능합니다. pd.to_numeric(..., errors="coerce") 같은 기능은 숫자로 변환할 수 없는 값을 NaN으로 바꿀 수 있습니다. 이후 dtype, 결측치 수와 shape 변화를 확인해야 합니다.

오늘의 암기 포인트

  • 예외는 실행 중 정상 흐름을 계속할 수 없는 상황을 나타내는 객체입니다.
  • try에는 실패 가능 작업을 작성합니다.
  • except에는 실패 처리 코드를 작성합니다.
  • 예외가 발생하면 그 아래 try 코드는 실행되지 않습니다.
  • 여러 예외는 튜플로 묶어 처리할 수 있습니다.
  • as error로 예외 객체를 받을 수 있습니다.
  • 구체적인 예외를 상위 Exception보다 먼저 작성합니다.
  • else는 try가 성공했을 때만 실행됩니다.
  • finally는 성공·실패와 관계없이 실행됩니다.
  • 처리되지 않은 예외는 상위 호출자로 전파됩니다.
  • raise는 예외를 직접 발생시킵니다.
  • 사용자 정의 예외는 보통 Exception을 상속합니다.
  • DB 실패에서는 필요에 따라 rollback()을 수행합니다.
  • 오류를 except: pass로 무조건 숨기지 않습니다.

헷갈리기 쉬운 개념

ValueError vs TypeError
ValueError는 값의 내용 문제, TypeError는 자료형·연산 방식 문제입니다.
IndexError vs KeyError
IndexError는 위치, KeyError는 딕셔너리 키 문제입니다.
except vs else
except는 실패 시, else는 try 성공 시 실행됩니다.
else vs finally
else는 성공한 경우에만, finally는 모든 경우에 실행됩니다.
raise vs print
print는 메시지만 출력하지만 raise는 실제 실행 흐름을 중단하는 예외를 발생시킵니다.
except Exception vs bare except
bare except가 더 넓은 BaseException 계열까지 잡을 수 있습니다.
조건문 vs 예외 처리
조건문은 정상적인 선택, 예외 처리는 작업 실패 상황에 사용합니다.
HTTP 오류 vs Python 예외
404는 HTTP 응답 상태이고, Timeout은 요청 과정의 예외입니다.
오류 vs NaN
Pandas에서는 일부 실패를 예외 대신 NaN 데이터 상태로 바꿀 수도 있습니다.
