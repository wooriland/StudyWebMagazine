01 · Core Concept

인수 전달은 값의 순서·이름·생략 여부를 함수의 지역 이름에 연결하는 과정이다

매개변수는 함수 정의에서 값을 받을 자리이고, 인수는 호출할 때 전달하는 실제 표현식입니다. Python은 값을 보고 의미를 추측하지 않습니다. 위치 인수는 앞에서부터 연결하고, 키워드 인수는 매개변수 이름을 찾아 연결합니다. 연결되지 않은 값은 가변 매개변수가 수집하고, 전달되지 않은 선택 자리에는 기본값을 적용합니다. 이 과정에서 누락이나 중복이 발견되면 본문을 실행하기 전에 오류가 납니다.

06

언패킹

호출에서 컬렉션을 여러 위치 또는 키워드 인수로 풀어 전달합니다.

function(*values, **options)

매개변수와 인수는 나타나는 위치가 다르다

PARAMETER · 함수 정의

def introduce(name, age):
    return f"{name}, {age}"

name과 age는 호출할 때 값을 받을 지역 이름입니다.

ARGUMENT · 함수 호출

message = introduce("민지", 20)

"민지"와 20은 이번 호출에 실제로 전달하는 값입니다.

호출 계약 필수 자리는 빠짐없이 전달한다. 하나의 자리에 값을 두 번 연결하지 않는다. 함수가 허용한 이름만 사용한다. 선택 옵션은 의미가 드러나게 키워드로 전달한다.

정의의 별표는 모으고, 호출의 별표는 푼다

DEFINITION · PACKING

def show(*values, **options):
    print(values)
    print(options)

여러 위치 값은 튜플, 여러 키워드 값은 딕셔너리로 모입니다.

CALL · UNPACKING

values = [10, 20]
options = {"unit": "점"}

show(*values, **options)

컬렉션 하나가 여러 위치 인수와 여러 키워드 인수로 풀립니다.

03 · Syntax & Binding Rules

필수 값부터 가변 값까지 선언 순서를 지키고 호출에서는 위치 뒤에 키워드를 둔다

인수 전달 방법과 함수 내부 결과
구분 정의 또는 호출 연결 규칙 함수 내부 결과
위치 인수 f(10, 20) 앞에서부터 순서대로 각 매개변수에 직접 연결
키워드 인수 f(y=20, x=10) 매개변수 이름으로 각 매개변수에 직접 연결
기본값 def f(x=10): 해당 인수가 생략될 때 x에 10 연결
가변 위치 def f(*args): 남은 위치 인수 수집 튜플
가변 키워드 def f(**kwargs): 남은 키워드 인수 수집 딕셔너리
위치 언패킹 f(*values) 반복 가능한 객체의 요소를 풂 여러 위치 인수
키워드 언패킹 f(**options) 문자열 키를 이름으로 풂 여러 키워드 인수

초보자가 먼저 익힐 매개변수 배치

def function(
    required,
    optional=10,
    *args,
    keyword_only,
    keyword_default=True,
    **kwargs
):
    pass
required필수 위치 또는 키워드 optional=10기본값이 있는 일반 매개변수 *args남은 위치 인수를 튜플로 수집 keyword_only이름이 필요한 필수 옵션 keyword_default=True기본값이 있는 키워드 전용 옵션 **kwargs남은 키워드 인수를 딕셔너리로 수집

WITH *ARGS

*args 뒤는 키워드 전용

def upload(filename, *tags, public=False):
    return filename, tags, public

upload("report.csv", "data", public=True)

BARE *

수집하지 않고 경계만 표시

def connect(host, *, timeout=5, secure=True):
    return host, timeout, secure

connect("example.com", timeout=10)

전체 매개변수 종류를 읽는 확장 지도

def example(
    positional_only,
    /,
    positional_or_keyword,
    *args,
    keyword_only,
    **kwargs
):
    pass

/ 앞은 위치로만 전달합니다.

/와 * 사이는 위치 또는 키워드로 전달합니다.

* 뒤는 이름을 지정해 전달합니다.

**kwargs는 그 밖의 키워드를 마지막에 수집합니다.

호출 규칙과 실패 이유

VALID

introduce("민지", age=20)

위치 인수 뒤에 키워드 인수를 둡니다.

INVALID

introduce(name="민지", 20)

키워드 뒤에 일반 위치 인수를 둘 수 없습니다.

DUPLICATE

introduce("민지", name="서연")

name에 값을 두 번 연결합니다.

UNKNOWN

introduce(job="개발자")

정의에 없고 **kwargs도 받지 않는 이름입니다.

정의와 호출에서 별표가 바꾸는 데이터 방향
위치 문법 방향 결과
함수 정의 *args 여러 값 → 하나 튜플
함수 정의 **kwargs 여러 키워드 → 하나 딕셔너리
함수 호출 *values 하나 → 여러 값 위치 인수
함수 호출 **options 하나 → 여러 항목 키워드 인수
function(*dictionary)딕셔너리의 키를 위치 인수로 전달
≠
function(**dictionary)키를 이름, 값을 인수로 전달

기본값은 함수 정의 시 평가된다

AVOID · SHARED STATE

def add_item(item, items=[]):
    items.append(item)
    return items

리스트 하나를 여러 호출이 공유하여 이전 호출의 값이 남습니다.

SAFE · NEW OBJECT PER CALL

def add_item(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items

인수가 생략된 호출마다 새로운 리스트를 만듭니다.

EXAMPLE 02

*args로 점수 개수 변화 처리

학생 이름은 필수이지만 점수는 0개 이상 받을 수 있습니다.

def summarize_scores(student, *scores):
    if not scores:
        return {
            "student": student,
            "count": 0,
            "average": 0
        }

    average = sum(scores) / len(scores)
    return {
        "student": student,
        "count": len(scores),
        "average": round(average, 1)
    }


print(summarize_scores("민지", 80, 90, 100))
print(summarize_scores("서연"))

SQLITE · QMARK PLACEHOLDERS

튜플 전체가 execute()의 두 번째 인수

FROM member

params는 SQL 자리표시자에 바인딩할 값 컨테이너입니다. 일반적으로 cursor.execute(sql, *params)로 풀지 않습니다.

이름 있는 자리표시자는 딕셔너리 전달

FROM member
WHERE name = :name
"""

params = {"name": "민지"}
cursor.execute(sql, params)

여기서도 딕셔너리는 두 번째 인수 하나입니다. 드라이버별 자리표시자 문법을 확인하고 SQL 문자열 결합은 피합니다.

웹 요청 · URL은 필수, 요청 옵션은 키워드

DIRECT KEYWORDS

import requests

    "https://example.com/search",

URL은 필수 위치 인수이고 params·headers·timeout은 의미가 드러나는 키워드 인수입니다.

OPTIONS UNPACKING

request_options = {
    "params": query,
    "headers": headers,
    "timeout": 10
}

response = requests.get(
    "https://example.com/search",
    **request_options
)

**request_options는 바깥 딕셔너리의 세 항목을 각각의 키워드 인수로 풉니다.

params=query와 **request_options는 서로 다른 층이다

params=query는 검색 조건 딕셔너리 전체를 params의 값 하나로 전달합니다.

**request_options는 바깥 딕셔너리의 params·headers·timeout을 함수 옵션으로 전개합니다.

requests.get(url, **query)는 keyword와 page를 함수의 키워드 이름으로 해석하므로 검색 조건 전달과 같지 않습니다.

08 · Interview Points

별표 문법을 외우는 데서 멈추지 않고 호출 바인딩과 자료형 변화를 설명한다

Q1. 매개변수와 인수의 차이는 무엇인가요?

매개변수는 함수 정의에서 전달값을 받을 지역 이름이고, 인수는 함수 호출에서 실제로 전달하는 표현식과 값입니다.

Q2. 위치 인수와 키워드 인수의 차이는 무엇인가요?

위치 인수는 작성 순서대로 매개변수에 연결되고, 키워드 인수는 매개변수명=값으로 대상을 지정합니다. 키워드는 순서 의존성을 줄이고 옵션의 의미를 드러냅니다.

Q3. 기본값이 있는 매개변수와 키워드 인수는 같은 개념인가요?

아닙니다. 함수 정의의 name="익명"은 인수가 생략됐을 때 사용할 기본값이고, 호출의 name="민지"는 이름을 지정해 값을 전달하는 키워드 인수입니다.

Q4. *args와 **kwargs의 자료형은 무엇인가요?

*args는 남은 위치 인수를 튜플로, **kwargs는 남은 키워드 인수를 딕셔너리로 수집합니다. 인수가 없으면 각각 빈 튜플과 빈 딕셔너리입니다.

Q5. 반드시 args와 kwargs라는 이름을 써야 하나요?

아닙니다. 문법을 만드는 것은 *와 **이며 이름은 관례입니다. 의미가 분명하다면 *scores나 **options처럼 쓸 수 있습니다.

Q6. 정의와 호출에서 *의 의미는 어떻게 다른가요?

정의의 *args는 여러 위치 인수를 튜플 하나로 패킹하고, 호출의 *values는 반복 가능한 객체의 요소를 여러 위치 인수로 언패킹합니다.

Q7. 정의와 호출에서 **의 의미는 어떻게 다른가요?

정의의 **kwargs는 남은 키워드를 딕셔너리로 모으고, 호출의 **mapping은 문자열 키를 매개변수 이름으로 사용해 여러 키워드 인수로 풉니다.

Q8. 키워드 전용 매개변수란 무엇인가요?

*args 또는 이름 없는 * 뒤에 선언되어 호출할 때 반드시 이름을 지정해야 하는 매개변수입니다. 선택 옵션의 의미를 명확히 하는 데 유용합니다.

Q9. 왜 리스트를 기본값으로 직접 사용하면 안 되나요?

기본값은 함수 정의 시 한 번 평가되므로 같은 리스트가 여러 호출에서 재사용될 수 있습니다. 일반적으로 None을 기본값으로 두고 함수 안에서 새 리스트를 만듭니다.

Q10. 리스트를 함수에 전달하면 자동으로 언패킹되나요?

아닙니다. f(values)는 리스트 전체를 인수 하나로 전달하고, f(*values)가 요소를 여러 위치 인수로 풉니다.

Q11. 딕셔너리에 * 하나와 **를 사용할 때 차이는 무엇인가요?

*dictionary는 딕셔너리의 키를 위치 인수로 전달합니다. **dictionary는 키를 매개변수 이름, 값을 해당 인수로 전달합니다.

Q12. **kwargs를 모든 함수에 사용하면 더 유연하지 않나요?

유연성은 늘지만 허용되는 옵션을 정의만 보고 알기 어렵고 철자 오류가 늦게 발견될 수 있습니다. 핵심 입력과 자주 쓰는 옵션은 명시하고 확장 항목에만 제한적으로 사용하는 편이 좋습니다.

Q13. figure, axes = plt.subplots()도 인수 언패킹인가요?

아닙니다. 함수가 반환한 두 객체를 변수 두 개에 나누는 반환값·대입 언패킹입니다. axes.plot(**options)가 호출의 키워드 인수 언패킹입니다.

Q14. 좋은 함수 시그니처의 기준은 무엇인가요?

필수 입력과 선택 옵션이 분명하고, 불리언·설정값은 키워드로 읽기 쉬우며, 가변 인수는 실제로 개수가 달라지는 데이터에만 사용하고, 변경 가능한 기본값을 피해야 합니다.

Q15. execute(sql, params)와 execute(sql, *params)의 차이는 무엇인가요?

전자는 SQL 문자열과 값 컨테이너를 인수 두 개로 전달합니다. 후자는 컨테이너 요소를 Python 위치 인수로 먼저 풀어 execute(sql, value1, value2)처럼 다른 호출을 만듭니다.

Q16. params=query와 **request_options의 차이는 무엇인가요?

params=query는 검색 조건 딕셔너리 전체를 한 옵션의 값으로 전달합니다. **request_options는 params·headers·timeout 같은 바깥 설정을 여러 키워드 인수로 전개합니다.

Q17. 데이터 분석 함수 호출 뒤 어떤 상태를 확인해야 하나요?

shape, 처리 방향인 axis, 각 열의 dtype, 결측치 개수와 원본 변경 여부를 호출 전후로 비교합니다.

MEMORY · 오늘의 암기 포인트

시험·면접·실습 전 18문장

  1. 매개변수는 정의에, 인수는 호출에 나타난다.
  2. 위치 인수는 앞에서부터 순서대로 연결된다.
  3. 키워드 인수는 매개변수 이름으로 연결된다.
  4. 일반 호출에서는 위치 인수를 키워드 인수보다 먼저 쓴다.
  5. 하나의 매개변수에 값을 두 번 전달할 수 없다.
  6. 정의의 =는 기본값을 정한다.
  7. 호출의 =는 전달할 매개변수 이름을 정한다.
  8. *args는 남은 위치 인수를 튜플로 모은다.
  9. **kwargs는 남은 키워드 인수를 딕셔너리로 모은다.
  10. args와 kwargs는 관례이고 별표가 문법이다.
  11. 호출의 *iterable은 요소를 위치 인수로 푼다.
  12. 호출의 **mapping은 항목을 키워드 인수로 푼다.
  13. **mapping의 키는 문자열이어야 한다.
  14. *dictionary는 딕셔너리의 키를 전달한다.
  15. * 뒤의 일반 매개변수는 키워드 전용이다.
  16. 정의에서는 모으고 호출에서는 푼다.
  17. 변경 가능한 객체를 기본값으로 직접 두지 않는다.
  18. 생략할 때 새 컬렉션이 필요하면 None 패턴을 쓴다.

함수에 값을 전달한 다음에는 함수 자체를 전달한다

이번 단원에서는 숫자·문자열·컬렉션·설정값을 함수 인수로 전달했습니다. 다음에는 짧은 함수를 한 줄로 만드는 lambda와 함수 객체를 다른 함수의 key 인수에 전달하는 방법을 공부합니다. 키워드 인수와 함수 객체의 연결을 알면 정렬 기준, 데이터 변환, 콜백 코드를 읽을 수 있습니다.

이번 단원값 전달→ 함수 객체괄호 없이 전달→ 짧은 함수lambda→ 정렬 기준key=→ 확장콜백·고차 함수 
students = [
    {"name": "민지", "score": 85},
    {"name": "준호", "score": 95},
    {"name": "서연", "score": 90}
]

result = sorted(
    students,
    key=lambda student: student["score"],
    reverse=True
)

key=get_score는 함수 객체 자체를 전달하지만 key=get_score()는 함수를 즉시 호출한 결과를 전달하려는 표현입니다. 같은 원리는 map()·filter()·Pandas의 apply()처럼 함수를 인수로 받는 API로 이어집니다.

연결 포인트: students는 위치 인수, key와 reverse는 키워드 인수이며, 람다 함수 객체는 호출하지 않고 key에 전달합니다.
