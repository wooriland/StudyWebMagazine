주석, 독스트링과 pass

실행되지 않는 # 주석과 실행 중 문자열 객체가 되는 삼중 따옴표 문자열을 구분합니다. 모듈·함수·클래스의 첫 번째 문자열이 독스트링으로 등록되는 원리를 이해하고, __doc__과 help()로 문서를 확인합니다. 또한 빈 함수나 조건문에 pass가 필요한 이유와 continue, break, return의 실행 흐름 차이를 공부합니다.

# Comment Inline Comment Shebang String Literal Docstring __doc__ help() pass continue NotImplementedError

이 단원의 중심 질문

주석과 독스트링은 모두 설명처럼 보이는데, Python은 둘을 어떻게 다르게 처리할까요?

# 주석은 실행 코드에서 제외됩니다. 반면 삼중 따옴표는 문자열을 만드는 Python 문법이며, 그 문자열이 모듈·함수·클래스 본문의 첫 번째 문장에 있으면 독스트링이 됩니다. pass는 설명이 아니라 아무 동작도 하지 않는 정상적인 Python 명령문입니다.

학습 목표

  • # 주석의 적용 범위와 문자열 안의 #을 구분합니다.
  • 한 줄 전체 주석과 인라인 주석의 사용 기준을 설명할 수 있습니다.
  • 좋은 주석이 코드의 무엇보다 왜를 설명해야 하는 이유를 이해합니다.
  • 셔뱅이 Unix 계열 운영체제에서 어떤 역할을 하는지 설명할 수 있습니다.
  • 삼중 따옴표가 주석이 아니라 문자열 문법이라는 사실을 이해합니다.
  • 모듈·함수·클래스·메서드 독스트링의 작성 위치를 구분합니다.
  • __doc__, help(), pydoc으로 문서를 확인합니다.
  • 주석만 있는 빈 블록에 pass가 필요한 이유를 설명합니다.
  • pass, continue, break, return을 비교합니다.
  • except: pass와 미구현 pass의 위험성을 실무 관점에서 판단합니다.

def calculate_average(scores):
    """점수 목록의 산술 평균을 계산한다.

    Args:
        scores: 평균을 계산할 숫자 목록.

    Returns:
        점수의 산술 평균.

    Raises:
        ValueError: 점수 목록이 비어 있는 경우.
    """

    if not scores:
        raise ValueError(
            "점수 목록은 비어 있을 수 없습니다."
        )

    return sum(scores) / len(scores)

#!/usr/bin/env python3
"""주석, 독스트링과 pass의 차이를 보여 주는 학습 모듈이다."""

from __future__ import annotations


PASS_SCORE = 80


class ReportBuilder:
    """학생 이름과 점수를 이용해 보고서를 생성한다."""

    def build(
        self,
        student_name: str,
        score: int,
    ) -> str:
        """학생 이름과 점수를 받아 판정 보고서를 반환한다.

        Args:
            student_name: 보고서에 표시할 학생 이름.
            score: 학생의 점수.

        Returns:
            이름, 점수와 통과 상태가 포함된 문자열.
        """

        normalized_name = student_name.strip()

        # 교육 과정의 통과 기준은 80점 이상이다.
        if score >= PASS_SCORE:
            status = "통과"
        else:
            status = "복습 필요"

        return (
            f"학생: {normalized_name}, "
            f"점수: {score}, "
            f"판정: {status}"
        )


class ReportRepository:
    """학생 보고서의 저장을 담당할 저장소이다."""

    def save(
        self,
        report: str,
    ) -> None:
        """보고서를 데이터베이스에 저장할 예정이다."""

        # TODO: Python 데이터베이스 단원에서 구현한다.
        pass


def print_documentation() -> None:
    """예제 객체에 등록된 독스트링을 출력한다."""

    print("-" * 60)
    print("모듈 독스트링")
    print(__doc__)

    print("-" * 60)
    print("클래스 독스트링")
    print(ReportBuilder.__doc__)

    print("-" * 60)
    print("메서드 독스트링")
    print(ReportBuilder.build.__doc__)

    print("-" * 60)
    print("저장소 독스트링")
    print(ReportRepository.save.__doc__)


def main() -> None:
    """프로그램의 전체 실행 흐름을 담당한다."""

    builder = ReportBuilder()
    repository = ReportRepository()

    report = builder.build(
        student_name="  김길동  ",
        score=85,
    )

    print("=" * 60)
    print("학생 보고서")
    print("=" * 60)

    print(report)

    save_result = repository.save(report)

    print("저장 메서드 반환값:", save_result)

    print_documentation()


if __name__ == "__main__":
    main()

14 · Common Mistakes

초보자가 자주 하는 실수

01

삼중 따옴표를 완전한 주석이라고 생각합니다

삼중 따옴표는 문자열 문법이며 # 주석과 처리 방식이 다릅니다.

02

모든 삼중 따옴표 문자열을 독스트링이라고 생각합니다

객체 본문의 첫 번째 문장에 있어야 독스트링으로 등록됩니다.

03

실행 코드 뒤에 독스트링을 작성합니다

함수 실행 코드보다 앞, 함수 본문의 첫 문장에 작성해야 합니다.

04

주석만 있으면 빈 블록이 완성된다고 생각합니다

주석은 명령문이 아니므로 pass 같은 문장이 필요합니다.

05

pass()처럼 호출합니다

pass는 함수가 아니라 Python 키워드입니다.

06

Pass로 대문자를 사용합니다

Python은 대소문자를 구분하며 올바른 키워드는 소문자 pass입니다.

07

pass가 다음 반복으로 이동한다고 생각합니다

다음 반복으로 이동하려면 continue를 사용합니다.

08

pass가 함수를 종료한다고 생각합니다

함수 종료에는 return이 필요합니다.

09

except: pass로 오류를 숨깁니다

장애 원인과 데이터 누락을 발견하기 어려워질 수 있습니다.

10

오래된 코드를 주석으로 계속 보관합니다

Git 이력을 활용하고 더 이상 사용하지 않는 코드는 삭제합니다.

11

주석과 실제 코드가 서로 다릅니다

코드가 변경되면 관련 주석도 함께 수정해야 합니다.

12

주석에 비밀번호와 토큰을 기록합니다

주석도 Git과 배포 파일에 포함될 수 있습니다.

13

셔뱅을 파일 중간에 작성합니다

운영체제 실행 정보로 사용하려면 파일의 첫 줄에 있어야 합니다.

14

pass가 남아 있어도 구현 완료라고 판단합니다

문법 오류가 없더라도 핵심 기능이 전혀 동작하지 않을 수 있습니다.

    response = requests.get(
        url,
        headers=HEADERS,
        timeout=10,
    )

    return response.text

17 · Interview

면접 포인트

Python 주석은 어떻게 작성합니까?

따옴표 바깥에서 #을 사용합니다. #부터 현재 물리적 줄의 끝까지 주석으로 처리되며 Python 실행 코드에서 제외됩니다.

문자열 안의 #도 주석입니까?

아닙니다. 따옴표 안의 #은 문자열을 구성하는 일반 문자입니다.

좋은 주석은 어떤 내용을 설명해야 합니까?

코드가 무엇을 하는지 그대로 반복하기보다 왜 그 처리가 필요한지, 어떤 업무 규칙과 외부 제약이 있는지를 설명해야 합니다.

셔뱅이란 무엇입니까?

스크립트 첫 줄의 #!로 시작하는 줄입니다. Unix 계열 운영체제에서 파일을 직접 실행할 때 사용할 인터프리터를 지정합니다.

셔뱅은 Python 코드입니까?

Python 문법 관점에서는 #으로 시작하는 주석입니다. 다만 Unix 운영체제가 파일을 직접 실행할 때 Python보다 먼저 이 줄을 해석합니다.

삼중 따옴표는 주석입니까?

아닙니다. 삼중 따옴표는 여러 줄을 포함할 수 있는 문자열 문법입니다. 사용하지 않는 문자열을 주석처럼 보이게 작성할 수는 있지만 처리 방식은 다릅니다.

독스트링이란 무엇입니까?

모듈, 함수, 클래스 또는 메서드를 문서화하기 위해 그 본문의 첫 번째 문장으로 작성하는 문자열입니다. __doc__과 help()에서 확인할 수 있습니다.

모든 삼중 따옴표 문자열이 독스트링입니까?

아닙니다. 모듈이나 함수, 클래스 본문의 첫 번째 문장에 있어야 독스트링으로 등록됩니다.

주석과 독스트링의 차이는 무엇입니까?

주석은 Python 명령문이 아니며 런타임 객체에 저장되지 않습니다. 독스트링은 문자열 표현식이며 정해진 위치에 작성되면 __doc__으로 보존됩니다.

주석만 있는 함수가 오류인 이유는 무엇입니까?

주석은 Python 명령문이 아니므로 함수 본문에 실제 문장이 없는 빈 블록으로 판단되기 때문입니다. pass를 추가하면 문법적으로 유효해집니다.

pass란 무엇입니까?

아무 작업도 하지 않는 Python 명령문입니다. 함수, 클래스, 조건문처럼 명령문이 필요한 블록에 아직 구현할 내용이 없을 때 사용합니다.

pass가 None을 반환합니까?

아닙니다. pass는 아무 작업도 하지 않습니다. 함수가 명시적 return 없이 끝에 도달하면 함수가 암시적으로 None을 반환합니다.

pass와 continue의 차이는 무엇입니까?

pass는 흐름을 바꾸지 않고 다음 명령문으로 진행합니다. continue는 현재 반복의 남은 코드를 건너뛰고 다음 반복으로 이동합니다.

pass와 break의 차이는 무엇입니까?

pass는 아무 작업 없이 계속 진행하지만, break는 현재 반복문을 종료합니다.

pass와 return의 차이는 무엇입니까?

pass는 함수 실행을 종료하지 않습니다. return은 현재 함수 실행을 종료하고 호출한 위치로 값을 돌려줍니다.

pass와 NotImplementedError는 언제 구분해서 사용합니까?

호출하지 않을 임시 구조에는 pass를 사용할 수 있습니다. 호출 시 미구현 사실을 반드시 알려야 한다면 NotImplementedError를 발생시키는 편이 명확합니다.

except: pass가 위험한 이유는 무엇입니까?

발생한 예외를 아무 기록 없이 숨기기 때문에 데이터 누락이나 장애가 발생해도 원인을 발견하기 어려워질 수 있습니다.

주석에 비밀번호나 토큰을 적으면 안 되는 이유는 무엇입니까?

주석도 소스 파일의 일부이며 Git 저장소, 코드 리뷰와 배포 파일에 포함될 수 있기 때문입니다.
