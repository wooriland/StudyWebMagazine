08 · Python Example

현재 개발 환경을 검사하는 종합 코드

다음 파일을 PyCharm, Eclipse PyDev 또는 터미널에서 실행합니다. 실행 도구를 바꿀 때마다 출력되는 인터프리터 경로를 비교합니다.

파일명: environment_report.py 

from __future__ import annotations

import platform
import sqlite3
import sys
from pathlib import Path


def get_environment_type() -> str:
    """현재 Python이 가상환경인지 전역 환경인지 반환한다."""

    if sys.prefix != sys.base_prefix:
        return "가상환경"

    return "전역 환경"


def print_environment_report() -> None:
    """현재 Python 개발 환경 정보를 출력한다."""

    executable = Path(sys.executable)

    print("=" * 60)
    print("Python 개발 환경 보고서")
    print("=" * 60)

    print("Python 버전:", platform.python_version())
    print(
        "Python 구현체:",
        platform.python_implementation()
    )

    print("실행 파일:", executable)
    print("실행 파일 존재:", executable.exists())

    print("운영체제:", platform.system())
    print("운영체제 버전:", platform.release())
    print("아키텍처:", platform.architecture()[0])

    print("환경 종류:", get_environment_type())
    print("sys.prefix:", sys.prefix)
    print("sys.base_prefix:", sys.base_prefix)

    print("현재 작업 폴더:", Path.cwd())
    print("SQLite 버전:", sqlite3.sqlite_version)

    print("=" * 60)
    print("환경 확인 완료")


if __name__ == "__main__":
    print_environment_report()

실행 순서

  1. Python이 필요한 표준 라이브러리를 불러옵니다.
  2. sys.executable로 현재 실행 파일을 확인합니다.
  3. Python 버전과 구현체를 확인합니다.
  4. 운영체제와 아키텍처를 확인합니다.

  7. 현재 작업 폴더와 SQLite 환경을 확인합니다.

10 · Common Mistakes

개발 환경 구축에서 자주 하는 실수

01

설치 후 기존 터미널을 계속 사용합니다

환경 변수나 명령 별칭 변경이 반영되도록 터미널을 닫고 다시 실행합니다.

02

교안의 Python36 경로를 그대로 찾습니다

설치 경로는 버전과 설치 방식마다 다르므로 sys.executable로 확인합니다.

03

PyCharm만 설치하면 Python도 준비된다고 생각합니다

PyCharm은 IDE이며 프로젝트에서 사용할 Python 인터프리터가 필요합니다.

04

PATH에 여러 Python 경로를 무작정 추가합니다

먼저 where python으로 현재 검색 순서를 확인해야 합니다.

05

pip와 python이 같은 환경이라고 가정합니다

python -m pip --version으로 현재 Python과 연결된 pip를 확인합니다.

06

모든 패키지를 전역 Python에 설치합니다

프로젝트별 가상환경을 사용하여 패키지 충돌을 줄입니다.

07

가상환경은 만들었지만 IDE는 전역 Python을 사용합니다

IDE의 Interpreter 경로가 .venv 안의 Python인지 확인합니다.

08

PyCharm Run과 Terminal이 같은 환경이라고 생각합니다

양쪽에서 sys.executable을 출력해 비교합니다.

09

PowerShell 활성화 오류를 Python 설치 실패로 생각합니다

가상환경은 생성되었지만 PowerShell이 활성화 스크립트를 차단한 것일 수 있습니다.

10

가상환경 폴더를 Git에 저장합니다

.venv/는 제외하고 패키지 목록을 별도로 저장합니다.

11

가상환경을 다른 위치로 그대로 복사합니다

절대경로가 깨질 수 있으므로 새 위치에서 다시 생성하는 것이 안전합니다.

12

공식 Python과 Anaconda 환경을 혼동합니다

터미널·PyCharm·Jupyter에서 각각 실제 인터프리터 경로를 확인합니다.

11 · Error Reading

설치·PATH·가상환경 오류 메시지 읽기

실행한 명령 확인 → 오류 종류 확인 → Python 버전 확인 → 실행 경로 확인 → 가상환경 확인 → IDE 설정 비교
Command Not Found

Python 실행 파일을 찾지 못함

'python' is not recognized as an
internal or external command

Python 설치, 새 터미널 실행, py 명령과 PATH를 확인합니다.

Can't Open File

실행할 Python 파일을 찾지 못함

python: can't open file 'app.py':
[Errno 2] No such file or directory

Python은 실행됐지만 현재 폴더에 지정한 파일이 없는 상태입니다.

ModuleNotFoundError

현재 환경에 패키지가 없음

ModuleNotFoundError:
No module named 'requests'

패키지가 다른 Python 환경에 설치된 것은 아닌지 확인합니다.

No Module Named pip

현재 Python에 pip가 준비되지 않음

No module named pip

필요하면 ensurepip를 이용해 pip 준비 상태를 확인합니다.

PowerShell Policy

활성화 스크립트 실행 차단

Activate.ps1 cannot be loaded because
running scripts is disabled on this system

Python 문법 오류가 아니라 PowerShell 실행 정책 문제입니다.

Invalid Environment

IDE의 인터프리터 경로가 유효하지 않음

Invalid environment

삭제되거나 이동된 가상환경을 IDE가 계속 가리키는지 확인합니다.

PermissionError

파일 또는 디렉터리 권한 문제

PermissionError: [Errno 13]
Permission denied

쓰기 권한, 파일 사용 상태와 보안 프로그램을 확인합니다.

DLL Load Failed

바이너리·아키텍처 호환 문제

ImportError: DLL load failed

Python 버전, 32·64비트, 외부 런타임과 패키지 호환성을 확인합니다.

13 · Interview

면접 포인트

Python 개발 환경은 무엇으로 구성됩니까?

운영체제, Python 인터프리터, PATH, 프로젝트, 가상환경, 패키지 관리자, IDE와 실행 설정으로 구성됩니다. IDE는 프로젝트에 연결된 인터프리터를 이용해 Python 코드를 실행합니다.

Python 인터프리터와 PyCharm의 차이는 무엇입니까?

Python 인터프리터는 Python 코드를 실제로 읽고 실행하는 프로그램입니다. PyCharm은 코드 작성, 실행, 디버깅을 지원하는 IDE이며 선택된 인터프리터에 실행을 요청합니다.

PATH란 무엇입니까?

운영체제가 터미널에 입력된 명령과 같은 실행 파일을 찾을 때 검색하는 디렉터리 목록입니다.

현재 실행 중인 Python은 어떻게 확인합니까?

sys.executable을 출력하면 현재 코드를 실제로 실행하고 있는 Python 실행 파일 경로를 확인할 수 있습니다.

가상환경은 왜 사용합니까?

프로젝트마다 필요한 패키지와 버전을 다른 프로젝트와 격리하기 위해 사용합니다. 패키지 충돌을 줄이고 실행 환경을 재현하기 쉬워집니다.

가상환경을 활성화하면 무엇이 달라집니까?

현재 Shell에서 가상환경의 실행 디렉터리가 우선 사용됩니다. 이후 python과 패키지 실행 명령이 해당 환경을 가리키게 됩니다.

가상환경인지 어떻게 확인합니까?

sys.prefix와 sys.base_prefix를 비교합니다. 두 값이 다르면 일반적으로 가상환경에서 실행 중입니다.

왜 python -m pip 형식을 사용합니까?

현재 python 명령이 가리키는 인터프리터의 pip를 실행한다는 의미가 명확하기 때문입니다. 여러 Python 환경에서 잘못된 위치에 패키지를 설치하는 실수를 줄일 수 있습니다.

패키지를 설치했는데 import하지 못하는 이유는 무엇입니까?

패키지를 설치한 Python과 코드를 실행하는 Python이 다를 수 있습니다. Terminal, PyCharm, Jupyter에서 각각 sys.executable을 확인해야 합니다.

Eclipse에서 Python은 무엇이 실행합니까?

Eclipse 자체가 Python 코드를 실행하는 것이 아니라 PyDev가 프로젝트에 설정된 Python Interpreter를 호출합니다.

Jupyter Kernel은 무엇입니까?

Notebook 셀의 코드를 실제로 실행하는 Python 환경입니다. 선택한 Kernel에 따라 Python 버전과 설치 패키지가 달라질 수 있습니다.

가상환경을 Git에 커밋하지 않는 이유는 무엇입니까?

가상환경에는 실행 파일, 설치 패키지와 절대경로 정보가 포함될 수 있어 크고 다른 컴퓨터로 옮기기 어렵습니다. 대신 생성 명령과 패키지 목록을 저장해 다시 만듭니다.

IDE와 Terminal의 결과가 다른 이유는 무엇입니까?

IDE의 프로젝트 Interpreter와 Terminal에서 선택된 Python이 다를 수 있기 때문입니다. 두 환경의 sys.executable을 비교해야 합니다.

헷갈리기 쉬운 개념

설치와 환경 구축
설치는 Python을 준비하는 것이고, 환경 구축은 터미널·프로젝트·IDE와 연결하는 전체 과정입니다.
Python과 PyCharm
Python은 코드 실행 환경이고, PyCharm은 개발을 돕는 IDE입니다.
Python 경로와 Scripts 경로
Python 경로에는 인터프리터가 있고, Scripts에는 pip와 패키지 CLI가 저장될 수 있습니다.
전역 Python과 가상환경
전역 Python은 여러 작업이 공유하지만, 가상환경은 특정 프로젝트에 분리됩니다.
pip와 python -m pip
후자는 어느 Python의 pip를 실행하는지 더 명확하게 표현합니다.
PyCharm Run과 Terminal
두 영역이 반드시 동일한 인터프리터를 사용하는 것은 아닙니다.
Jupyter와 Kernel
Jupyter 화면이 아니라 선택된 Kernel이 실제 Python 코드를 실행합니다.
