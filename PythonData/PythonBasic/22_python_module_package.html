01 · Core Concept

모듈은 코드와 이름 공간의 단위이고, 패키지는 그 모듈을 계층적으로 조직하는 특별한 모듈이다

초보자에게 모듈은 보통 하나의 .py 파일입니다. 그러나 핵심은 파일 확장자보다 독립된 전역 이름 공간과 재사용 가능한 코드 단위라는 점입니다. 패키지는 하위 모듈을 찾는 __path__를 가진 특별한 모듈이고, 일반 패키지는 보통 __init__.py를 사용합니다. import는 코드를 현재 파일에 복사하지 않습니다. 모듈 객체를 준비한 뒤 현재 이름 공간에 모듈 또는 내부 객체를 연결합니다.

03 · Syntax & Rules

문법을 외우기 전에 어떤 이름이 만들어지는지 확인한다

MODULE

import math
math.sqrt(81)

현재 이름: math

MODULE ALIAS

import math as m
m.sqrt(81)

현재 이름: m

DIRECT NAME

from math import sqrt
sqrt(81)

현재 이름: sqrt

NAME ALIAS

from math import sqrt as root
root(81)

현재 이름: root

SUBMODULE

import shop.pricing
shop.pricing.add_tax(10000)

현재 이름: shop

AVOID

from calculator import *

여러 이름이 들어와 출처와 충돌을 추적하기 어렵습니다.

import 형식 비교

문법 현재 공간의 이름 사용 예 특징
import math math math.sqrt(9) 출처가 가장 분명함
import math as m m m.sqrt(9) 모듈 별칭 사용
from math import sqrt sqrt sqrt(9) 짧지만 이름 충돌 가능
from math import sqrt as root root root(9) 가져온 이름에 별칭
from math import * 여러 공개 이름 sqrt(9) 일반 프로그램에서는 피함

일반 패키지와 네임스페이스 패키지

REGULAR PACKAGE

shop/
├─ __init__.py
└─ pricing.py

처음 import할 때 __init__.py가 실행되고 패키지 이름 공간을 구성합니다.

NAMESPACE PACKAGE

location_a/shop/tools/
location_b/shop/data/

__init__.py 없이 여러 위치의 부분을 하나의 패키지 이름 아래 구성할 수 있는 고급 기능입니다.

__init__.py와 __all__의 역할은 다르다

ACTUAL RE-EXPORT

# shop/__init__.py
from .pricing import add_tax

add_tax 함수 객체를 shop.add_tax에 실제로 연결합니다.

WILDCARD PUBLIC LIST

__all__ = ["add_tax"]

from shop import *가 가져올 이름 목록을 지정합니다. 접근 제한은 아닙니다.

절대 import와 상대 import

ABSOLUTE IMPORT

from shop.pricing import add_tax

최상위 패키지 이름부터 작성하므로 출처가 분명합니다.

RELATIVE IMPORT

from .pricing import add_tax
from ..common import formatter

.은 현재 패키지, ..은 부모 패키지를 뜻합니다.

문법 주의

import .pricing은 올바른 문법이 아닙니다. 상대 import는 from . import pricing 또는 from .pricing import add_tax 형태로 작성합니다.

sys.modules와 __pycache__

구분 sys.modules __pycache__
위치 현재 프로세스 메모리 디스크 폴더
내용 이미 불러온 모듈 객체 컴파일된 .pyc 바이트코드
수명 프로세스 종료 시 사라짐 프로그램 종료 후에도 남을 수 있음
핵심 질문 이번 실행에서 이미 import했는가? 소스 컴파일 결과를 재사용할 수 있는가?

shop/validator.py

print(f"[validator] {__name__}")


def is_valid_price(price):
    return (
        isinstance(price, (int, float))
        and not isinstance(price, bool)
        and price >= 0
    )

shop/receipt.py

from .pricing import add_tax
from .validator import is_valid_price

print(f"[receipt] {__name__}")


def make_receipt(product, price):
    if not is_valid_price(price):
        raise ValueError(
            "가격은 0 이상의 숫자여야 합니다."
        )

    return f"{product}: {add_tax(price):,}원"

shop/__init__.py

print(f"[shop] {__name__}")

__all__ = ["make_receipt"]

08 · Interview Points

정의만 말하지 말고 탐색·실행·바인딩 순서로 설명한다

Q. 모듈과 패키지의 차이는 무엇인가요?

A. 모듈은 코드와 독립된 전역 이름 공간의 단위입니다. 패키지는 하위 모듈과 하위 패키지를 담을 수 있도록 __path__를 가진 특별한 모듈입니다.

Q. import module과 from module import name의 차이는 무엇인가요?

A. 전자는 모듈 객체를 현재 이름에 연결해 module.name으로 사용하고, 후자는 모듈을 먼저 준비한 뒤 특정 객체를 현재 이름에 직접 연결합니다.

Q. import한 모듈은 매번 실행되나요?

A. 일반적으로 같은 프로세스에서는 최초 import 뒤 sys.modules의 모듈 객체를 재사용합니다. 새 프로세스에서는 다시 실행됩니다.

Q. sys.modules와 __pycache__는 어떻게 다른가요?

A. 전자는 현재 프로세스의 모듈 객체 캐시이고, 후자는 디스크에 저장되는 컴파일 바이트코드 캐시입니다.

Q. __init__.py의 역할은 무엇인가요?

A. 일반 패키지를 구성하고 패키지 최초 import 시 초기화 코드를 실행하며, 패키지에서 제공할 공개 API를 다시 구성할 수 있습니다.

Q. Python 3.3 이상에서도 __init__.py가 필요한가요?

A. 네임스페이스 패키지는 없어도 되지만 일반적인 애플리케이션 패키지에서는 구조와 초기화, 공개 API를 명확히 하기 위해 사용합니다.

Q. __all__은 무엇인가요?

A. from module_or_package import *가 가져올 이름 목록입니다. 접근을 막는 private 또는 보안 기능은 아닙니다.

Q. import package가 모든 하위 모듈을 가져오나요?

A. 아닙니다. 필요한 하위 모듈을 직접 import하거나 __init__.py에서 명시적으로 연결해야 합니다.

Q. 절대 import와 상대 import의 차이는 무엇인가요?

A. 절대 import는 최상위 패키지부터 작성하고, 상대 import는 현재 패키지를 기준으로 .과 ..을 사용합니다.

Q. 상대 import가 있는 파일을 직접 실행하면 왜 실패하나요?

A. 파일이 최상위 __main__으로 실행되어 부모 패키지 문맥을 알 수 없기 때문입니다. 프로젝트 루트에서 python -m package.module로 실행합니다.

Q. 순환 import는 왜 발생하며 어떻게 해결하나요?

A. 서로 import하는 모듈 중 하나가 아직 초기화되지 않은 이름을 요청할 때 발생합니다. 공통 코드를 분리하고 의존 방향을 단방향으로 정리합니다.

Q. 실무에서 import *를 피하는 이유는 무엇인가요?

A. 이름의 출처와 충돌을 추적하기 어렵고 자동 완성, 정적 분석, 코드 검토가 불리해지기 때문입니다.

09 · Final Check

문법 암기가 아니라 파일·메모리·실행 환경을 함께 추적했는지 확인한다

  • 모듈과 패키지를 한 문장으로 구분할 수 있다.
  • 설치 이름과 import 이름이 다를 수 있음을 설명할 수 있다.
  • 다섯 가지 import 형식이 만드는 이름을 구분할 수 있다.
  • from import도 모듈 최상위 코드를 먼저 실행한다는 것을 안다.
  • import 시스템이 sys.modules를 먼저 확인한다는 것을 안다.
  • sys.modules와 __pycache__를 구분한다.
  • __init__.py의 초기화와 공개 API 역할을 설명할 수 있다.
  • 일반 패키지와 네임스페이스 패키지를 구분할 수 있다.
  • __all__이 접근 제한 기능이 아님을 안다.
  • import package가 모든 하위 모듈을 자동으로 불러오지 않음을 안다.
  • 절대 import와 상대 import를 올바른 문법으로 작성할 수 있다.
  • 상대 import 모듈을 python -m으로 실행할 수 있다.
  • __name__과 __main__의 관계를 설명할 수 있다.
  • 모듈 이름 충돌과 순환 import를 진단할 수 있다.
  • Jupyter의 import 캐시와 커널 재시작 시점을 안다.
  • DB·웹·분석·시각화 코드의 import 시점 부작용을 제거할 수 있다.

MEMORY · 오늘의 암기 포인트

import를 설명하는 여섯 문장

  1. 모듈은 코드와 독립된 전역 이름 공간의 단위다.
  2. 패키지는 하위 모듈을 가질 수 있는 특별한 모듈이다.
  3. import는 복사가 아니라 탐색·실행·이름 연결 과정이다.

  5. __all__은 import * 목록이지 보안 기능이 아니다.
  6. 상대 import 모듈은 프로젝트 루트에서 python -m으로 실행한다.
