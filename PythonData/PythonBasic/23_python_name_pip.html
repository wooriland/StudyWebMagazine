01 · Core Concept

__name__은 실행 역할을 알려 주고, pip는 선택된 Python 환경의 의존성을 관리한다

파일의 코드 내용만 보고는 그 파일이 독립 프로그램인지 재사용 모듈인지 정해지지 않습니다. 실행 방법에 따라 Python이 __name__을 정하고, 개발자는 그 값을 조건으로 직접 실행할 코드만 선택합니다. 한편 requests, pandas처럼 표준 라이브러리에 없는 기능은 보통 PyPI에 배포된 패키지를 pip로 설치합니다. 여기서 가장 중요한 기준은 내가 지금 실행할 Python과 pip가 연결된 환경이 같은가입니다.

01

__name__

Python이 모듈에 자동으로 넣는 특별한 전역 변수입니다. 실행 역할에 따라 문자열 값이 달라집니다.

02

"__main__"

현재 최상위 실행 환경에 붙는 특별한 모듈 이름입니다. 예약 함수 이름이 아니라 문자열입니다.

03

메인 가드

if __name__ == "__main__": 조건으로 직접 실행할 때만 아래 블록을 실행합니다.

04

main()

프로그램 시작 절차를 모으는 관례적 함수 이름입니다. Python 예약어는 아닙니다.

05

PyPI

Python 배포 패키지를 게시하고 찾는 공개 저장소입니다. 등록 자체가 품질과 안전을 보증하지는 않습니다.

06

pip

배포 패키지와 필요한 의존성을 내려받아 현재 Python 환경에 설치·조회·삭제하는 도구입니다.

07

가상환경

프로젝트마다 인터프리터와 설치 패키지 경계를 분리하여 버전 충돌을 줄이는 독립 환경입니다.

08

site-packages

해당 환경의 외부 Python 패키지가 설치되는 대표 경로입니다. 환경마다 위치가 다릅니다.

같은 파일도 실행 방법에 따라 역할이 달라진다

실행 상황 파일 내부 __name__ 메인 가드 의미
python app.py "__main__" 참 이 파일이 최상위 프로그램
import app "app" 거짓 다른 파일이 재사용하는 모듈
import shop.app "shop.app" 거짓 패키지 안의 모듈
python -m shop.app "__main__" 참 패키지 문맥을 유지한 최상위 실행
REPL·Jupyter 셀 일반적으로 "__main__" 참 현재 대화형 최상위 환경

설치 이름과 import 이름은 같지 않을 수 있다

beautifulsoup4pip 설치→bs4Python import
scikit-learnpip 설치→sklearnPython import
Pillowpip 설치→PILPython import
opencv-pythonpip 설치→cv2Python import
두 개의 중심 문장

메인 가드는 파일 전체를 보호하지 않고 들여쓰기된 블록만 제어합니다.

python -m pip는 현재 선택한 Python으로 pip를 실행하여 설치 환경의 혼동을 줄입니다.

03 · Syntax & Rules

메인 가드는 정확하게 쓰고, 패키지 명령은 선택한 Python을 기준으로 실행한다

EXACT MAIN GUARD

def main():
    print("프로그램을 시작합니다.")


if __name__ == "__main__":
    main()

한 글자씩 확인

  • __name__: 앞뒤 밑줄 두 개
  • ==: 값을 비교하는 연산자
  • "__main__": 따옴표가 있는 문자열
  • :: 조건식 끝의 콜론
  • main(): 가드 안에 들여쓰기

main, __main__, __main__.py 구분

표현 정체 역할 예
main 관례적인 함수 이름 프로그램 시작 절차를 묶음 def main():
"__main__" 특별한 모듈 이름 문자열 현재 최상위 실행 환경 표시 __name__ == "__main__"
__main__.py 특별한 파일 이름 패키지를 -m으로 실행할 진입점 python -m report_app

EXAMPLE 02

입력과 계산을 분리한 main()

재사용할 함수는 가드 밖에서 정의하고, 사용자 입력은 진입점에서만 수행합니다.

def calculate_total(price, quantity):
    return price * quantity


def main():
    price = int(input("단가: "))
    quantity = int(input("수량: "))
    print(f"합계: {calculate_total(price, quantity):,}원")


if __name__ == "__main__":
    main()
import 결과

다른 테스트 파일이 calculate_total()을 import해도 input()은 실행되지 않습니다.

06 · Mistakes & Errors

오류 메시지를 문법·이름·실행 위치·환경·호환성 순서로 읽는다

SyntaxError

메인 가드 끝의 콜론 누락, 따옴표 불일치, Python 프롬프트에서 pip 명령을 입력했는지 확인합니다.

NameError

__main__에 따옴표가 없으면 변수로 해석합니다. 정확히 "__main__" 문자열을 비교합니다.

ModuleNotFoundError

미설치뿐 아니라 다른 Python에 설치, 잘못된 커널, 다른 import 이름, 프로젝트 경로 문제를 함께 의심합니다.

No module named pip

선택한 Python에 pip가 준비되지 않았습니다. 해당 Python의 ensurepip 사용 가능 여부를 확인합니다.

No matching distribution

패키지명, 버전 조건, Python 버전, 운영체제·CPU용 배포 파일 호환성을 점검합니다.

PermissionError

시스템 환경에 쓰려고 할 수 있습니다. 관리자 권한보다 프로젝트 가상환경 사용을 우선합니다.

externally-managed-environment

운영체제가 관리하는 Python입니다. 시스템 설치를 강제하지 말고 venv를 만듭니다.

의존성 충돌 경고

패키지들이 요구하는 버전 범위가 맞지 않습니다. python -m pip check와 새 환경으로 원인을 좁힙니다.

AttributeError

프로젝트의 requests.py, pandas.py가 외부 패키지를 가렸거나 순환 import 중일 수 있습니다.

ImportError

모듈은 찾았지만 요청한 이름을 가져올 수 없습니다. API 변경, 버전 차이, 순환 import를 확인합니다.

KeyError

패키지 오류로 단정하지 말고 설정 딕셔너리·JSON·DataFrame에 요청한 키나 열이 실제 있는지 확인합니다.

업그레이드 후 실행 실패

08 · Interview Points

정의만 말하지 말고 실행 상황과 환경 경계를 함께 설명한다

Q1. __name__은 무엇인가요?

Python이 각 모듈에 자동으로 제공하는 특별한 전역 변수입니다. 직접 실행된 최상위 모듈에서는 "__main__", import된 모듈에서는 정규 모듈 이름이 들어갑니다.

Q2. 메인 가드는 왜 사용하나요?

함수와 클래스는 import로 재사용할 수 있게 두면서, 사용자 입력·DB 연결·HTTP 요청 같은 프로그램 시작 코드는 직접 실행할 때만 호출하기 위해 사용합니다.

Q3. 메인 가드가 import의 모든 실행을 막나요?

아닙니다. 조건문에 들여쓰기된 블록만 건너뜁니다. 가드 밖 최상위 대입·함수 정의·출력·함수 호출은 import 시 실행됩니다.

Q4. main()은 필수인가요?

필수 문법도 예약 함수도 아닙니다. 시작 절차를 함수로 묶어 읽기·테스트·재사용을 쉽게 만드는 관례입니다.

Q5. python file.py와 python -m package.module의 차이는?

앞은 파일 경로를 직접 실행하고, 뒤는 import 시스템으로 모듈을 찾아 패키지 문맥을 유지한 채 최상위 모듈로 실행합니다.

Q6. PyPI와 pip의 차이는?

PyPI는 배포 패키지를 게시하고 찾는 저장소이고, pip는 패키지를 내려받아 현재 Python 환경에 설치·관리하는 도구입니다.

Q7. 왜 pip보다 python -m pip를 권하나요?

명령 앞의 Python으로 pip 모듈을 실행하므로 여러 Python이 설치된 환경에서 설치 대상을 더 명확히 맞출 수 있습니다.

Q8. 가상환경이 필요한 이유는?

프로젝트마다 패키지와 버전 경계를 분리하여 서로 다른 요구사항의 충돌을 줄이고, 설치 범위와 재현성을 관리하기 위해서입니다.

Q9. 배포 패키지 이름과 import 이름이 다른 예는?

beautifulsoup4 → bs4, scikit-learn → sklearn, Pillow → PIL, opencv-python → cv2가 있습니다.

Q10. site-packages는 무엇인가요?

선택한 Python 환경의 외부 패키지가 설치되는 대표 디렉터리입니다. 시스템·사용자·가상환경마다 다른 경로를 가질 수 있습니다.

Q11. 설치했는데 import가 안 되면 무엇부터 보나요?

sys.executable, python -m pip --version, pip show의 Location, IDE·Notebook 커널, 설치 이름과 import 이름을 순서대로 확인합니다.

Q12. pip freeze는 무엇을 출력하나요?

현재 환경에 설치된 패키지 버전을 요구사항 형식으로 출력합니다. 직접·간접 의존성이 함께 포함될 수 있어 환경 스냅샷 성격이 강합니다.

Q13. pip uninstall은 하위 의존성도 모두 삭제하나요?

보통 지정한 배포 패키지를 제거하며, 함께 설치된 모든 하위 의존성을 자동으로 정리한다고 가정하면 안 됩니다.

Q14. PyPI 패키지는 모두 안전한가요?

아닙니다. 공개 저장소 등록은 안전성 보증이 아니므로 정확한 이름, 게시자, 공식 링크, 최근 릴리스, 호환성, 라이선스를 확인합니다.

실행 환경을 만들었으면 실패하는 순간을 처리한다

프로그램 진입점과 패키지 환경을 정확히 구성해도 파일, 네트워크, DB, 데이터 변환은 실패할 수 있습니다. 다음 단원에서는 예외 발생 지점을 좁히고, 종류에 맞게 처리하며, 자원을 반드시 정리하는 방법을 배웁니다.

main에서 실행 시작 ↓ 외부 패키지 함수 호출 ↓ 파일·HTTP·DB 실패 ↓ try·except로 복구 ↓ finally로 자원 정리 
def main():
    try:
        rows = collect_data()
    except RequestException as error:
        print(f"수집 실패: {error}")
    else:
        save_rows(rows)
    finally:
        close_resources()

if __name__ == "__main__":
    main()

연결 포인트: 다음 단원에서 try·except·else·finally·raise를 배우며 실행 실패를 제어합니다.
