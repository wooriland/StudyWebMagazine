01 · Core Concept

반복 제어문은 다음 실행 위치를 바꾼다

반복문은 기본적으로 현재 회차의 코드를 끝까지 실행한 뒤 다음 값을 가져옵니다. 그러나 모든 데이터를 끝까지 처리할 필요는 없습니다. 현재 값만 제외해야 할 때는 continue, 반복 작업 전체가 더 이상 필요하지 않을 때는 break를 사용합니다.

01

정상 실행

현재 회차의 코드를 끝까지 실행하고 다음 값을 가져옵니다.

process(item)
02

현재 회차 생략

남은 코드를 실행하지 않고 다음 반복으로 이동합니다.

continue
03

반복 전체 종료

가장 가까운 반복문을 끝내고 반복문 다음 줄로 이동합니다.

break
04

상태 변경

while에서는 다음 조건 판단 전에 상태가 바뀌어야 합니다.

count += 1
종료 조건 → 생략 조건 → 정상 처리 권장 읽기 순서 
for item in items:
    if stop_condition(item):
        break

    if skip_condition(item):
        continue

    process(item)
문장 역할 빠져나가는 범위 현재 문장 아래 코드
break 반복 종료 가장 가까운 반복문 하나 실행하지 않음
continue 현재 회차 생략 다음 반복으로 이동 현재 회차에서 실행하지 않음
pass 아무 작업도 하지 않음 이동하지 않음 계속 실행
return 함수 종료 현재 함수 전체 실행하지 않음
한 문장으로 구분하기

원하는 결과를 찾았다면 break, 현재 데이터만 잘못되었다면 continue, 빈 코드 블록만 필요하다면 pass, 함수의 결과가 결정되었다면 return을 검토합니다.

03 · Exact Rules

for와 while의 이동 규칙을 정확히 구분한다

break

가장 가까운 반복문 종료

다음 값을 가져오지 않고 반복문 다음 코드로 이동합니다.

continue

다음 회차 준비

for는 다음 값을 가져오고 while은 조건식을 다시 계산합니다.

pass

흐름을 바꾸지 않음

아무 작업도 하지 않은 뒤 같은 회차의 다음 코드를 계속 실행합니다.

FOR + CONTINUE

다음 항목을 요청한다

현재 회차 생략 → 다음 값 → 반복 변수 할당 
for word in ["Python", "", "DB"]:
    if word == "":
        continue
    print(word)
결과Python / DB

WHILE + CONTINUE

조건식으로 돌아간다

현재 회차 생략 → 조건 재평가 → True이면 반복 
number = 0

while number < 5:
    number += 1
    if number == 3:
        continue
    print(number)
결과1 / 2 / 4 / 5

CRITICAL TRAP

continue가 상태 변경을 건너뛰면 무한 반복된다

잘못된 위치

number = 0

while number < 5:
    if number == 2:
        continue
    number += 1

number가 2에서 바뀌지 않습니다.

안전한 위치

number = 0

while number < 5:
    number += 1
    if number == 2:
        continue

상태를 먼저 바꾼 뒤 현재 회차를 생략합니다.

LOOP ELSE

반복문의 else는 “break가 없었다”는 뜻이다

for가 항목을 끝까지 사용하거나 while의 조건이 False가 되어 정상 종료되면 else가 실행됩니다. break로 종료되면 실행되지 않습니다.

정상 종료→else 실행 break 종료→else 생략 continue만 사용→break가 없으면 else 실행 
numbers = [10, 20, 30]
target = 99

for number in numbers:
    if number == target:
        print("찾았습니다.")
        break
else:
    print("찾지 못했습니다.")

NESTED LOOP

중첩 반복 전체를 끝내려면 제어 범위를 한 단계씩 처리한다

found = False

for row in range(1, 4):
    for column in range(1, 4):
        if row == 2 and column == 2:
            found = True
            break

    if found:
        break
안쪽에서 목표 발견 → found = True → 안쪽 break → 바깥쪽도 break

LAZY ITERATION

필요한 결과를 찾으면 남은 범위를 사용하지 않는다

for number in range(1_000_000_000):
    if number == 3:
        break
    print(number)
사용한 값0, 1, 2, 3
남은 범위반복에서 사용하지 않음

04 · Infinite Loop

while True에는 출구와 안전장치가 필요하다

∞

무한 반복은 문법 오류가 아니다

조건이 계속 참이면 Python은 요청받은 대로 반복합니다. 오류 메시지가 없더라도 종료 조건이 없다면 논리 오류일 수 있습니다.

INTENTIONAL

의도적인 무한 반복

while True:
    command = input("명령(q: 종료): ")

    if command == "q":
        break

    print("실행:", command)

입력값이 종료 조건 역할을 합니다.

ACCIDENTAL

의도하지 않은 무한 반복

number = 1

while number <= 5:
    print(number)

number가 바뀌지 않아 조건이 계속 참입니다.

Truthy를 잘못 이해해도 끝나지 않는다

while False: 실행하지 않음

False는 bool 자료형의 거짓값입니다.

while "False": 계속 실행

비어 있지 않은 문자열은 Truthy입니다.

07 · Mistakes & Errors

문법 오류와 논리 오류를 분리해서 읽는다

범위 착각break

프로그램 전체가 아니라 가장 가까운 반복문만 끝냅니다.

pass 오해pass

현재 회차를 건너뛰지 않고 다음 코드를 실행합니다.

갱신 생략continue

while의 상태 변경을 건너뛰면 무한 반복됩니다.

도달 불가break 아래

제어문 아래에 필요한 저장·출력 코드를 놓지 않습니다.

Truthy 착각"False"

비어 있지 않은 문자열은 참으로 판정됩니다.

else 착각loop else

조건의 거짓 분기가 아니라 break 없는 종료입니다.

원본 변경remove()

반복 중 목록 구조를 바꾸면 아직 처리하지 않은 값을 건너뛸 수 있습니다.

무제한 재시도while True

상한·대기·timeout이 없으면 자원을 낭비할 수 있습니다.

빈 대상for item in []

반복 변수가 한 번도 만들어지지 않을 수 있습니다.

선택자 단정if not items

빈 결과가 마지막 페이지인지 구조 변경인지 확인해야 합니다.

대표 오류 메시지

SyntaxError 'break' outside loop

break를 적용할 for 또는 while이 없습니다.

SyntaxError 'continue' not properly in loop

continue가 반복문 내부에 올바르게 배치되지 않았습니다.

SyntaxError expected ':'

for, while, if 끝의 콜론을 확인합니다.

IndentationError expected an indented block

반복문과 조건문 내부의 들여쓰기 깊이를 맞춥니다.

TypeError NoneType and int

09 · Interview Point

질문에는 이동 범위와 종료 조건을 포함해 답한다

Q1 break와 continue의 차이는 무엇인가요?

break는 가장 가까운 반복문을 종료하고, continue는 현재 회차의 남은 코드만 생략한 뒤 다음 반복으로 이동합니다.

Q2 pass와 continue는 어떻게 다른가요?

pass는 흐름을 바꾸지 않는 빈 문장이라 다음 코드가 실행됩니다. continue는 현재 회차의 나머지 코드를 실행하지 않습니다.

Q3 중첩 반복문에서 break는 어디까지 종료하나요?

break를 직접 포함한 가장 가까운 반복문 하나만 종료합니다. 전체를 끝내려면 플래그, 바깥쪽 break, 함수의 return 등을 설계합니다.

Q4 반복문의 else는 언제 실행되나요?

for가 항목을 모두 사용하거나 while 조건이 거짓이 되어 break 없이 정상 종료될 때 실행됩니다.

Q5 while True는 잘못된 코드인가요?

메뉴, 서버, 스케줄러처럼 종료 시점을 내부에서 결정할 때 의도적으로 사용합니다. 다만 출구, 대기, 재시도 한도, 타임아웃과 자원 정리가 필요합니다.

Q6 while의 continue가 위험할 수 있는 이유는?

조건을 바꾸는 증감식이나 상태 변경을 건너뛰면 조건이 계속 참으로 남아 무한 반복될 수 있기 때문입니다.

Q7 break와 return의 차이는?

break는 반복문 하나만 끝내지만 return은 현재 함수 전체를 종료하고 호출 위치로 결과를 돌려줍니다.

Q8 DB의 fetchone() 반복은 어떻게 끝내나요?

더 이상 행이 없을 때 반환되는 None을 확인하고 break합니다. None 검사 전에 행 인덱스에 접근하지 않습니다.

Q9 크롤링에서 404와 429를 같은 방식으로 처리하면 안 되는 이유는?

404는 페이지가 없다는 뜻이라 종료 조건일 수 있지만, 429는 요청이 너무 많다는 뜻이므로 대기와 제한된 재시도가 필요합니다.

Q10 선택자 결과가 비면 바로 종료해도 되나요?

아닙니다. 마지막 페이지뿐 아니라 선택자 변경, 차단 화면, 로그인, 동적 렌더링 때문일 수 있어 상태 코드와 응답 HTML을 함께 확인합니다.

Q11 분석에서 결측치를 continue로 처리해도 되나요?

흐름 학습이나 복잡한 행 단위 규칙에는 사용할 수 있습니다. 큰 DataFrame에서는 불리언 필터와 dropna()를 우선 검토하고 구조 변화를 확인합니다.

Q12 range()와 break를 함께 쓰면 어떤 장점이 있나요?

목표를 찾은 뒤 남은 범위를 반복할 필요가 없어 불필요한 회차와 연산을 줄일 수 있습니다.

NOTE 01

오늘의 암기 포인트

  1. break는 가장 가까운 반복문을 끝냅니다.
  2. continue는 현재 회차의 남은 코드를 생략합니다.
  3. pass는 아무 작업도 하지 않고 다음 코드를 실행합니다.
  4. return은 현재 함수 전체를 끝냅니다.
  5. for의 continue는 다음 값을 가져옵니다.
  6. while의 continue는 조건식을 다시 계산합니다.
  7. 반복문의 else는 break 없이 끝날 때 실행됩니다.
  8. while True에는 출구와 안전장치가 필요합니다.
